前面几篇都假设一件事：一条链路，两端。

一端发，一端收，中间没有别人。

现实里最常见的场景不是这样。

```text
一间办公室里，二十台电脑接在同一台交换机上。
一个教室里，三十个手机连在同一个 AP 上。
一根同轴电缆上，挂着十几台老式终端。
```

这时候多了一个问题，而且这个问题是前面所有协议都没管过的：

```text
同一时刻，谁可以先发？
```

这就是介质访问控制（Medium Access Control, MAC）。

## 1. 一根线，多台机器

假设一条 1 km 长的同轴电缆，两端各挂一台机器。

A 开始发数据，信号以 2×10^8 m/s 向前跑。

跑到 B 那里需要 5 μs。

在这 5 μs 里，B 完全不知道线上已经有信号了——信号还没到。

如果 B 在这 5 μs 内也决定发送，两路信号就会在电缆中间撞上。

撞上之后，两路信号叠加，谁也听不清。

```text
A ──────►              ◄────── B
         ╲    ╱
          ╲  ╱
           ╳   ← 冲突，两边的数据都废了
          ╱  ╲
         ╱    ╲
```

这叫冲突（collision）。

冲突不是"两台机器同时发"这么简单，而是"两台机器在彼此的传播时延窗口内发"。

**这个窗口的长度，决定了整个 MAC 层的设计。**

因为它意味着：光靠"听"是不够的。

你在发之前听了，线上确实安静；但你听到的安静是 5 μs 之前的安静，这 5 μs 里可能已经有人开始发了。

这个时间差，是后面所有冲突概率的根源。

## 2. 介质访问控制要解决什么

一句话：**在共享介质上，协调多个站点对信道的使用。**

拆开是三个子问题。

```text
① 什么时候可以发？（判决）
② 怎么知道发失败了？（检测）
③ 失败了怎么办？（恢复）
```

三种思路，对应三个流派。

```text
信道划分：把信道切成几份，每人一份，各发各的，永不冲突
随机访问：不划分，想发就发，撞了再说
轮询访问：排队，按顺序来，谁也不许抢
```

三种思路的取舍很清楚。

```text
信道划分：无冲突，但站点不发时资源照样被占着 → 轻负载浪费
随机访问：轻负载时延迟极低，但重负载时冲突爆炸
轮询访问：重负载时效率高，但轻负载时轮询本身是开销
```

**没有一种方案在所有负载下都赢。**

这是这一篇最重要的一句话。

408 的所有选择题，本质上都在问"在这个场景下，哪种方案更合适"。

## 3. 信道划分：把一根线切成几份

四种切法。

**频分多址（FDMA）。**

把频带切成若干互不重叠的子频带，每个站固定占一段。

```text
频率
 ↑
 │  ███ 站1  ███ 站2  ███ 站3  ███ 站4
 │  ███     ███     ███     ███
 └──────────────────────────────────► 时间
    每段频带被一个站长期占用
```

**时分多址（TDMA）。**

时间切成周期性的帧，每帧再切成时隙，每个站固定占一个时隙。

```text
时间
 ──────────────────────────────────────►
 │ 站1 │ 站2 │ 站3 │ 站4 │ 站1 │ 站2 │ ...
 └─────┴─────┴─────┴─────┴─────┴─────┘
   一个 TDMA 帧，每站一个时隙
```

**波分多址（WDM）。**

光纤里按波长分，一根纤里跑几十上百个波长。

本质上是频分，只是频段在光域。

```text
一根光纤
  λ1  ▓▓▓▓▓▓▓▓▓▓  ← 100 Gbps
  λ2  ▒▒▒▒▒▒▒▒▒▒  ← 100 Gbps
  λ3  ░░░░░░░░░░  ← 100 Gbps
  ...
  80 个波长合起来 8 Tbps
```

**码分多址（CDMA）。**

这个特殊，放到第 4 节单独讲。

前三种有两个共同点，都要记住。

```text
共同点一：静态划分。每个站分到的资源是固定的。
共同点二：站不发数据时，那段资源就空着，别人也不能用。
```

这就是"轻负载浪费"的来源。

一条 1 Gbps 的 FDMA 链路，10 个站各分 100 Mbps。

如果只有 1 个站在发，它也只能用 100 Mbps，另外 900 Mbps 全闲着。

改进版叫统计时分复用（STDM）。

```text
不固定分配时隙，谁有数据谁上，按需分配
时隙里带上站号，接收方按站号分流
```

这其实就是"信道划分"往"随机访问"走了一步。

再往前一步，就是 ALOHA。

顺带记两个工程细节，考试偶尔会问。

```text
FDMA 的代价：相邻频带之间要留保护频带，这段带宽不能用
TDMA 的代价：时隙之间要留保护时间，防止前后两个站的信号重叠
```

保护带和保护时间都不传数据。

所以"划分得越细，浪费越多"——分给 100 个站，保护带就要 100 份。

这也是为什么划分方式适合"站点数量固定、流量稳定"的场合。

## 4. CDMA：把"同时"变成"正交"

码分多址（Code Division Multiple Access）的思路和前三种完全不同。

前三种是"分资源"：分频率、分时间、分波长。

CDMA 是"不分资源"：大家同时、同频、一起发。

凭什么不冲突？

凭每个站有一套自己的码片序列（chip sequence），彼此正交。

```text
每个站有一个 m 位的码片序列，m 通常是 8、64、128
码片序列里的每一位叫一个码片（chip）
发送 1  → 发自己的码片序列
发送 0  → 发码片序列的反码
没数据  → 不发（或者发全 0）
```

正交的定义：

```text
两个不同站的码片序列，内积为 0
任何一个站的码片序列，与自己的内积为 m
```

内积就是"对应位相乘再相加"。

```text
S · T = (1/m) × Σ (Si × Ti)
```

有的教材把 1/m 写在外面，有的写在内积定义里。

两种算法都对，只要最后除回去。

因为正交，多个站同时发的时候，信号在线性叠加。

接收方拿到的是叠加后的混合信号。

它用谁的码片去做内积，就只能解出谁的数据。

**别人的信号在做内积时会被"平均"成 0，等于不存在。**

这就是 CDMA 的全部魔法。

一个自然的问题：m 位码片，最多能支持几个站？

答案是 m 个。

因为 m 维空间里，最多只有 m 个互相正交的向量。

```text
m = 8  → 最多 8 个站
m = 64 → 最多 64 个站
```

工程上用的就是沃尔什码（Walsh code），按哈达玛矩阵生成，天然两两正交。

代价是：站数越多，码片越长，发一个比特要占更多的带宽。

```text
m = 64，每比特发 64 个码片
码片速率 1 Mcps → 数据速率只剩 15.6 kbps
```

所以 CDMA 是"用带宽换并发"。

它和 FDMA 的关键差别是：FDMA 分频率，必须留保护频带；CDMA 分码型，不需要留空隙。

**这就是 CDMA 频谱效率更高的原因——它没有"缝"要填。**

## 5. CDMA 算一遍：两个内积

取两个站的码片序列，长度 m = 8。

```text
A 站：(-1, -1, -1, +1, +1, -1, +1, +1)
B 站：(-1, -1, +1, -1, +1, +1, +1, -1)
```

先验证正交。

```text
          A      B      A×B
第1位    -1     -1      +1
第2位    -1     -1      +1
第3位    -1     +1      -1
第4位    +1     -1      -1
第5位    +1     +1      +1
第6位    -1     +1      -1
第7位    +1     +1      +1
第8位    +1     -1      -1
                      ─────
              求和 =    0
```

```text
A · B = 0     → 正交 ✓
```

再算 A 与自己的内积。

```text
A · A = (+1) + (+1) + (+1) + (+1) + (+1) + (+1) + (+1) + (+1) = 8
```

等于 m，符合定义。

现在让 A 发 1，B 发 0。

```text
A 发 1  →  发 A 的码片：  (-1, -1, -1, +1, +1, -1, +1, +1)
B 发 0  →  发 B 的反码：  (+1, +1, -1, +1, -1, -1, -1, +1)
```

两路信号在空中叠加：

```text
        A       -B      叠加后 S
第1位  -1      +1        0
第2位  -1      +1        0
第3位  -1      -1       -2
第4位  +1      +1       +2
第5位  +1      -1        0
第6位  -1      -1       -2
第7位  +1      -1        0
第8位  +1      +1       +2
```

接收方收到的就是 S = (0, 0, -2, +2, 0, -2, 0, +2)。

它要用 A 的码片去解 A 的数据：

```text
S · A = (0)(-1) + (0)(-1) + (-2)(-1) + (2)(+1)
      + (0)(+1) + (-2)(-1) + (0)(+1) + (2)(+1)
      = 0 + 0 + 2 + 2 + 0 + 2 + 0 + 2
      = 8

8 / m = 8 / 8 = +1  →  A 发的是 1 ✓
```

再用 B 的码片解 B 的数据：

```text
S · B = (0)(-1) + (0)(-1) + (-2)(+1) + (2)(-1)
      + (0)(+1) + (-2)(+1) + (0)(+1) + (2)(-1)
      = 0 + 0 - 2 - 2 + 0 - 2 + 0 - 2
      = -8

-8 / m = -8 / 8 = -1  →  B 发的是 0 ✓
```

两个都解对了。

**注意叠加信号 S 里有 0 有 ±2，看起来乱成一团，但内积一算就干净了。**

这就是"正交"的实际含义：混合可以还原，因为各个分量在彼此的"坐标系"里投影为 0。

再补一句工程上的事。

现实里码片不会完美同步，也不会完美正交，所以会有"多址干扰"。

3G 系统的容量就是被这个干扰限制住的——用户越多，互相的残余投影越大，信噪比越差。

**CDMA 不是"无限容量"，它是"用计算复杂度换频率效率"。**

## 6. 随机访问：不划分，撞了再说

不划分资源，谁有数据谁就发。

如果撞了，就都失败，各自随机等一段时间再重发。

这个思路的好处是显而易见的：

```text
只有一个站要发的时候，它可以用满整个信道，延迟极低。
```

坏处也是显而易见的：

```text
两个站同时要发的时候，两边的数据都废了，信道时间被浪费。
```

所以随机访问的全部设计，都在回答一个问题：

```text
怎么让"撞"的概率尽量小，同时不让"等"的时间太长？
```

按"听不听"和"什么时候听"来分，有三代。

```text
第一代 ALOHA：完全不听，想发就发
第二代 CSMA：发之前先听
第三代 CSMA/CD：边发边听，撞了立刻停
```

一条演进线索：**越来越早知道冲突已经发生。**

```text
ALOHA：冲突发生后，等超时才知道
CSMA：发之前听一下，能避免一部分冲突
CSMA/CD：发的同时听，冲突发生后几个比特就能发现
```

知道得越早，浪费的带宽越少。

## 7. 纯 ALOHA：18.4% 的天花板

1970 年代，夏威夷大学。

几个岛之间用无线电连网，这就是 ALOHA 网。

规则简单到不能再简单：

```text
有帧就发。
发完等确认。
超时没确认，随机等一段时间，再发。
```

不需要监听，不需要同步，不需要协商。

代价呢？

假设所有站的总负载是 G——意思是"每个帧时内，平均产生 G 个帧"。

G = 0.5 表示：一个帧的发送时间里，平均有半个帧在等着发。

一个帧要成功，必须满足：它发送的这段时间里，没有别人开始发。

而 ALOHA 的危险区间是两倍帧时：

```text
        ┌──────── 帧时 T ────────┐
   ─────┼────────────────────────┼─────
        │◄──── 危险区间 2T ──────►│
        │                        │
   别人可能在这个窗口的任意位置开始发，
   只要和我的发送时间有重叠，就撞了。
```

为什么是 2T？

因为别人可以在我的帧开始之前 T 的时间内开始发（他的帧还没发完），也可以在我的帧开始之后 T 内开始发（我的帧还没发完）。

所以危险窗口 = 2T。

在这 2T 内没有任何一个帧开始的概率，是泊松分布的零项：

```text
P(没有别人开始) = e^(-2G)
```

所以成功发送的比率是：

```text
S = G · e^(-2G)
```

求最大值，对 G 求导：

```text
dS/dG = e^(-2G) - 2G·e^(-2G) = 0
→ G = 0.5
→ S = 0.5 × e^(-1) = 0.5 × 0.3679 = 0.1839
```

**18.4%。**

> **反直觉的点在这里。**
>
> ALOHA 的理论上限只有 18.4%——"想发就发"的代价，是八成以上的信道时间浪费在冲突上。
>
> 而且这个 18.4% 是"最好情况"，实际系统通常更低。

把这个数代进一条具体的链路。

```text
信道 1 Mbps，帧长 1000 bit → 帧时 T = 1 ms
信道满负荷 = 1000 帧/秒

G = 0.5 时，总负载 = 500 帧/秒
S = 0.184 → 成功 = 184 帧/秒
吞吐量 = 184 × 1000 bit = 184 kbps
```

**一条 1 Mbps 的线，只能跑出 184 kbps。**

而且注意那个荒谬的地方：负载越高，成功率越低。

```text
G = 0.5  → S = 18.4%（最优）
G = 1.0  → S = 1 × e^(-2) = 13.5%
G = 2.0  → S = 2 × e^(-4) = 3.7%
```

负载加到 2，吞吐量掉到 3.7%。

这就是"拥塞崩溃"的原型：越想发，越发不出去。

ALOHA 今天还在用，而且用在你意想不到的地方。

```text
RFID 标签：几百个标签同时回应读卡器，防冲突协议就是 ALOHA 的变种
卫星寻呼：早期铱星系统的上行信道
LoRaWAN：物联网的入网流程里有它的影子
```

它们选择 ALOHA 的理由都一样：

```text
站点的数据量极小（几字节），而且极度突发。
为这么点数据去搞同步、搞监听，成本远高于冲突的代价。
```

**在误码和冲突的成本低于协调的成本时，"不听就发"反而是最优解。**

这条判据比公式本身更有用。

## 8. 时隙 ALOHA：36.8%

把时间切成等长的时隙，时隙长度等于一个帧时。

所有站必须在时隙的起点才能开始发。

```text
时隙：  │  1  │  2  │  3  │  4  │  5  │
       ↑     ↑     ↑     ↑     ↑
       只能在这些点上开始发
```

这一改，危险区间从 2T 缩到了 T。

```text
纯 ALOHA：别人可以在我的帧开始前后各 T 内开始 → 危险区间 2T
时隙 ALOHA：别人只能在时隙起点开始 → 危险区间只有 T（我这一个时隙）
```

因为大家的发送起点被对齐了，不会出现"我发到一半，你插进来"的情况。

所以：

```text
S = G · e^(-G)
```

求最大值：

```text
dS/dG = e^(-G) - G·e^(-G) = 0
→ G = 1
→ S = 1 × e^(-1) = 0.3679
```

**36.8%。**

正好是纯 ALOHA 的两倍。

```text
纯 ALOHA  ：G = 0.5 → S = 18.4%
时隙 ALOHA：G = 1.0 → S = 36.8%
```

多出来的这 18.4 个百分点，是白拿的吗？

不是。

代价是要全网同步。

每个站都得知道"时隙什么时候开始"，这需要一个同步机制（比如从信道上提取时钟，或者用 GPS）。

在一个跨海的无线电网络里，这个代价不小。

**这就是"用同步换效率"的经典交易。**

同样的交易在别处也能看到。

```text
TDMA 要全网同步：不同步，时隙就错位，两个站会挤进同一个时隙
FDMA 不要同步：各发各的频带，谁也撞不到谁
```

所以 FDMA 的设备比 TDMA 简单，代价是频谱利用率低一点。

**同步是"用精度换效率"，这个交易在网络里到处都是。**

## 9. CSMA：先听再发，以及三种坚持策略

ALOHA 最大的问题是"不听"。

CSMA（Carrier Sense Multiple Access）加了一个动作：

```text
发之前，先听。
信道忙，就等；信道闲，就发。
```

这个"听"叫载波监听。

但听完了怎么处理，有三种策略。

**1-坚持（1-persistent）。**

```text
听：信道忙 → 一直听，听到空闲，立刻发（概率 = 1）
```

"坚持"的意思是"坚持监听"，不是"坚持发送"。

问题是：如果两个站都在等，信道一空闲，两个同时发。

**冲突概率最高。**

**非坚持（non-persistent）。**

```text
听：信道忙 → 随机等一段时间，再来听
```

不傻等，退一步。

好处是多个等待者不会在同一时刻涌上来，冲突少。

坏处是信道可能空闲了一小段，而所有等待者都还在"随机等"里，没人发。

**信道利用率反而可能下降。**

**p-坚持（p-persistent）。**

这是给时隙信道设计的。

```text
听：信道空闲 → 以概率 p 发送，以概率 1-p 推迟到下一个时隙再听
    信道忙   → 等到下一个时隙再听
```

p 是一个可以调的参数。

```text
p = 1  → 退化成 1-坚持
p 很小 → 退化成非坚持（很少立刻发）
```

所以 p-坚持是一个"连续的旋钮"，1-坚持和非坚持是它的两个端点。

三种策略的冲突概率排序：

```text
1-坚持 > p-坚持 > 非坚持
```

但信道利用率不是这个顺序：

```text
1-坚持在轻负载时最好（几乎不浪费空闲），重负载时最差（冲突爆炸）
非坚持在重负载时好，轻负载时浪费空闲
p-坚持折中
```

这张"负载—效率"的曲线，是 408 里最爱考的一张图。

还有一件事必须提醒。

**载波监听不能消除冲突。**

因为监听有传播时延。

```text
A 在 t=0 开始发
B 在 t=4 μs 决定发，此时 A 的信号还在路上（需要 5 μs 才到 B）
B 听到信道空闲 → 发
t=5 μs 时，两路信号在中间撞上
```

这个"听了但没听到"的窗口，长度是端到端传播时延 τ。

它决定了冲突不可避免，也决定了 CSMA/CD 为什么要规定最小帧长。

那是第 09 篇的事。

CSMA 还有一个改进：边发边听。

```text
CSMA/CD：Collision Detection，冲突检测。
         一边发，一边听。发现冲突，立刻停止，发一个干扰信号，然后退避。
```

这个"立刻停"很重要。

不检测的话，一帧 1500 字节要发 12 ms，撞了也要发完才知道，12 ms 白费。

检测的话，几个比特的时间就能发现，浪费极小。

有线以太网用这一套。

无线不行。

```text
CSMA/CA：Collision Avoidance，冲突避免。
         不能边发边听（自己发的信号会盖住别人的），
         所以改成"尽量避免冲突"：先预约，再发，收方回 ACK。
```

为什么无线不能边发边听？

```text
① 自己发射的功率比收到的信号强几个数量级，听不见别人
② 隐藏终端：A 和 C 都能到 B，但 A 和 C 互相听不到
```

这两条原因，第 10 篇会展开。

这里只要记住一句：

```text
有线能"检测"，无线只能"避免"。
```

## 10. 轮询访问：令牌与轮询

第三种思路：不抢，排队。

**令牌传递（token passing）。**

一个叫"令牌"的特殊帧在环上转。

```text
      ┌──────► 站1 ──────┐
      │                   ▼
     站4                 站2
      ▲                   │
      └────── 站3 ◄───────┘
              令牌 →
```

谁拿到令牌，谁就有权发。

发完了把令牌传给下一个。

```text
优点：无冲突，重负载时效率高，时延有上界
缺点：令牌本身要维护（丢了要重新生成，重了要去重），
      一个站故障可能拖垮整个环
```

令牌环网（802.5）和 FDDI 用的就是这个。

令牌有个麻烦：它是个"有状态"的东西，状态会丢，也会重。

```text
令牌丢了 → 全网停摆，谁也不敢发
           → 解决：每个站设一个超时计时器，超时就重新生成令牌
令牌重了 → 两个站同时以为自己有令牌，冲突
           → 解决：选一个"监控站"，看到两个令牌就删掉一个
```

这两条机制让令牌环协议的复杂度直接翻倍。

**它输给以太网，不是因为性能差，是因为"要维护一个状态"。**

以太网什么状态都不维护——撞了就退避，没撞就发完。

一个需要"监控站"的协议，在工程上永远比一个"谁都不用管"的协议难部署。

**这是网络史上反复出现的一条规律：无状态打败有状态。**

**轮询（polling）。**

有一个主站，依次问每个从站"你有数据吗"。

```text
主站 → 从站1：有数据吗？
从站1 → 主站：没有
主站 → 从站2：有数据吗？
从站2 → 主站：有，给你
主站 → 从站3：有数据吗？
```

主站是仲裁者，从站不能抢。

```text
优点：完全无冲突，可以实现优先级
缺点：主站是单点故障；轮询本身有开销；
      从站有数据也得等轮到自己
```

蓝牙的微微网（piconet）就是这个模型。

802.11 的 PCF（点协调功能）也是，只是实际部署里很少用。

工业现场总线里，轮询至今还是主流——因为"确定性"比"平均效率"重要。

**在一条生产线上，"最坏情况下 10 ms 内一定送到"比"平均 2 ms"值钱得多。**

## 11. 各自适合什么场景

把三类方案摆到一张表里。

| 方案 | 冲突 | 轻负载效率 | 重负载效率 | 典型场景 |
|---|---|---|---|---|
| FDMA / TDMA / WDM | 无 | 低（资源空占） | 高 | 卫星、蜂窝、光纤骨干 |
| CDMA | 无（靠正交） | 中 | 中（受多址干扰限制） | 3G 移动通信 |
| 纯 ALOHA | 严重 | 低（上限 18.4%） | 极低 | 早期卫星、射频标签 |
| 时隙 ALOHA | 有（上限 36.8%） | 中 | 低 | 需要同步的卫星信道 |
| CSMA | 有 | 高 | 中（冲突增多） | 早期以太网、无线 |
| CSMA/CD | 有（可快速检测） | 高 | 高 | 共享式以太网 |
| CSMA/CA | 有（尽量避免） | 中 | 中 | 802.11 无线局域网 |
| 令牌 / 轮询 | 无 | 低（开销） | 高 | 令牌环、蓝牙、工业总线 |

一句话总结这个表的用法：

```text
负载轻、突发性强 → 随机访问
负载重、流量稳定 → 信道划分或轮询
无线、有隐藏终端 → CSMA/CA
```

再补一个反直觉的观察。

**以太网今天已经不需要 CSMA/CD 了。**

因为交换机是全线速、全双工的，每个端口只连一台设备，冲突域消失了。

```console
$ ethtool eth0 | grep -i duplex
	Duplex: Full
```

全双工意味着收发各走一对线，同时进行，不会冲突。

所以现代以太网里，CSMA/CD 是一段"只在半双工模式下才会启用"的历史包袱。

但它仍然是 408 的重点——因为它是最小帧长、冲突窗口这些概念的来源。

## 12. 容易混淆的点

**第一，介质访问控制 ≠ 流量控制。**

MAC 管"谁能发"，流量控制管"发多快"。

两者都在链路层，但解决的是完全不同的问题。

**第二，"坚持"不是"坚持发送"。**

1-坚持的意思是"坚持监听，一空闲就发"。

不是"不管怎样都要发"。

**第三，CDMA 的正交是码片正交，不是频率正交。**

它同时同频，靠码片序列的内积为 0 来区分。

这也是它比 FDMA 频谱效率高的原因——不需要保护频带。

**第四，时隙 ALOHA 需要全网同步，纯 ALOHA 不需要。**

所以时隙 ALOHA 的 36.8% 不是"免费翻倍"。

考试里问"时隙 ALOHA 比纯 ALOHA 好在哪里、代价是什么"，两个都要答。

**第五，18.4% 和 36.8% 是"最大值"，不是"典型值"。**

它们出现在 G = 0.5 和 G = 1 这两个最优点上。

负载偏离最优点，吞吐率都更低。

**第六，ALOHA 的 S = G·e^(-2G) 里的 2 是"危险区间是两倍帧时"。**

时隙 ALOHA 的 S = G·e^(-G) 里的 1，是"危险区间只有一个时隙"。

这个 2 和 1 的来源，比公式本身更值得记。

**第七，令牌环的"无冲突"不是"无开销"。**

令牌本身的传递、维护、故障恢复都要花时间。

## 13. 408 怎么考

三种题型。

```text
一、算 ALOHA 吞吐率：给 G 求 S，或问最大值出现在哪个 G
二、判断坚持策略：给场景描述，问用的是哪种
三、码分多址计算：给码片序列，算内积、解数据
```

下面是自拟题，三问串起来。

**题目。**

一条 1 Mbps 的共享信道，帧长 1000 bit。

（1）纯 ALOHA 在 G = 0.5 时的吞吐率是多少？换算成每秒成功传输的帧数。

（2）时隙 ALOHA 在 G = 0.5 时呢？它的最优点在哪里？

（3）两个站的码片序列：
A = (-1, -1, -1, +1, +1, -1, +1, +1)
B = (-1, -1, +1, -1, +1, +1, +1, -1)
若接收方解调出的叠加信号是 S = (0, 0, -2, +2, 0, -2, 0, +2)，求 A、B 各自发了什么。

**解答（1）。**

```text
S = G · e^(-2G) = 0.5 × e^(-1) = 0.5 × 0.368 = 0.184
```

吞吐率 18.4%。

帧时 T = 1000 bit / 10^6 b/s = 1 ms，信道满负荷 1000 帧/s。

```text
成功帧数 = 0.184 × 1000 = 184 帧/s
吞吐量   = 184 × 1000 bit = 184 kbps
```

**解答（2）。**

```text
S = G · e^(-G) = 0.5 × e^(-0.5) = 0.5 × 0.6065 = 0.303
```

30.3%，对应的成功帧数是 303 帧/s。

最优点在 G = 1：

```text
S = 1 × e^(-1) = 0.368 → 36.8%
```

注意这一问的两个数别混：G = 0.5 时是 30.3%，最优是 36.8%。

**解答（3）。**

先算 A 解自己：

```text
S · A = (0)(-1) + (0)(-1) + (-2)(-1) + (+2)(+1)
      + (0)(+1) + (-2)(-1) + (0)(+1) + (+2)(+1)
      = 0 + 0 + 2 + 2 + 0 + 2 + 0 + 2
      = 8

8 / 8 = +1  →  A 发 1
```

再算 B：

```text
S · B = (0)(-1) + (0)(-1) + (-2)(+1) + (+2)(-1)
      + (0)(+1) + (-2)(+1) + (0)(+1) + (+2)(-1)
      = 0 + 0 - 2 - 2 + 0 - 2 + 0 - 2
      = -8

-8 / 8 = -1  →  B 发 0
```

答案：A 发 1，B 发 0。

**再补一道判断策略的题。**

"某协议规定：站点发送前先监听，若信道忙则持续监听，一旦空闲立即发送。"

答：1-坚持 CSMA。

如果换成"若信道忙则放弃本次监听，随机延迟后重新监听"，就是非坚持。

如果换成"空闲时以概率 p 发送"，就是 p-坚持。

三种描述的差别只在"忙的时候怎么办"和"闲的时候发不发满"。

## 14. 真实网络里长什么样

**看以太网的冲突计数。**

```console
$ ip -s link show eth0
2: eth0: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 state UP
    link/ether 52:54:00:12:34:56 brd ff:ff:ff:ff:ff:ff
    RX:  bytes packets errors dropped  missed   mcast
      8347291   61205      0       3       0     118
    TX:  bytes packets errors dropped carrier collsns
      1029384   12044      0       0       0       0
                                   ↑
                              collsns = 冲突次数
```

`collsns` 恒为 0，说明这是全双工链路，没有冲突域。

如果这个数在涨，说明网卡工作在半双工模式，或者接了集线器。

**看双工模式。**

```console
$ ethtool eth0 | grep -Ei 'speed|duplex'
	Speed: 1000Mb/s
	Duplex: Full
```

`Full` 就意味着 CSMA/CD 不会启用。

**看无线侧的"冲突避免"。**

802.11 的每个单播数据帧都要回一个 ACK。

在抓包里能看到这个一来一回：

```text
No.  Time      Source             Destination        Info
1    0.000000  52:54:00:12:34:56  ff:ff:ff:ff:ff:ff  ARP Request
2    0.000412  52:54:00:12:34:56  52:54:00:aa:bb:cc  802.11 Data
3    0.000580  52:54:00:aa:bb:cc  52:54:00:12:34:56  802.11 Ack
```

因为无线不能"边发边听"，发送方只能靠"有没有收到 ACK"来判断这一帧是否成功。

**这个 ACK 就是 CSMA/CA 的核心，它的存在本身就是"不能检测冲突"的证据。**

如果没收到 ACK，发送方会退避，重试，几次之后才放弃。

**看频分的样子。**

有线电视就是最直观的 FDMA：一根同轴电缆里跑着几十个频道，每个频道一段频带。

```console
$ dvb-fe-tool --freq 474000000
```

每个频率对应一个频道，互不干扰。

**看码分的遗迹。**

3G 手机用的就是 CDMA。

今天 4G/5G 换成了 OFDMA（正交频分多址），名字里还留着"正交"两个字，但正交的对象从"码片"变成了"子载波"。

**同一个数学工具，换了一个维度用。**

这一段是简化示意。

真实的 5G 物理层还有大规模 MIMO、波束成形、动态时隙配比，比这一篇的模型复杂得多。

但"多址"这个问题的结构，从 ALOHA 到今天没有变过：

```text
谁先发？撞了怎么办？怎么知道自己撞了？
```

## 15. 小结

三类方案，一条判据。

```text
信道划分：分资源，无冲突，轻负载浪费
随机访问：抢资源，有冲突，轻负载高效
轮询访问：排队，无冲突，有开销
```

三组必须记住的数：

```text
纯 ALOHA  ：S = G·e^(-2G)，最大 18.4%（G = 0.5）
时隙 ALOHA：S = G·e^(-G) ，最大 36.8%（G = 1）
CDMA      ：正交码片，内积为 0，自己与自己为 m
```

一句必须记住的分工：

```text
有线能检测冲突 → CSMA/CD
无线不能检测   → CSMA/CA
```

一个必须记住的反直觉点：

```text
ALOHA 的理论上限只有 18.4%。
"想发就发"的代价，是八成以上的信道时间浪费在冲突上。
```

补一个经常被忽略的对照：

```text
18.4% 是纯 ALOHA 的上限，36.8% 是时隙 ALOHA 的上限。
两者差一倍，差的是"有没有全网同步"。
```

所以"要不要同步"这件事，在 MAC 层能值 18 个百分点的信道效率。

还有一个更深的观察，值得留在最后：

```text
所有 MAC 方案都在同一个权衡上做选择：
"空闲时的浪费" 与 "冲突时的浪费"，哪个更贵。
```

下一篇把 CSMA/CD 单独拆开。

```text
计算机网络系统讲解 09：以太网与 CSMA/CD
```

那一篇会回答：

```text
为什么以太网帧最短是 64 字节？
冲突窗口 2τ 和最小帧长是什么关系？
为什么 10 Mbps 时代的以太网跨不过 2500 米？
```

从下一篇开始，"冲突"会变成一个可以用米和比特算出来的距离。
