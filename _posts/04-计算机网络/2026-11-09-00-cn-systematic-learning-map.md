在浏览器里敲一个地址，回车。

半秒后，页面出来了。

这半秒里发生了什么？

```text
浏览器把 URL 拆开，问 DNS：www.example.com 是多少？
DNS 回：93.184.216.34。

浏览器让 TCP 去连这个 IP 的 443 端口。

TCP 发三次握手，连上了。

浏览器把 HTTP 请求塞进去。

IP 层给这段数据加上地址，决定下一跳。

链路层把它封成帧，交给网卡。

网卡变成电信号，发上光纤。

……

对面的服务器一层层拆开，读到你的请求。
```

五层。

每一层只关心自己那一格。

这一篇只做一件事：

```text
把这张地图画出来，
让后面 24 篇里的每个知识点，
都有地方可放。
```

## 1. 为什么网络知识显得散

翻开任何一本教材，目录大概是这样：

```text
概述
物理层
数据链路层
网络层
传输层
应用层
```

六章。

每一章内部又有十几个协议、七八个公式。

于是学起来很像背电话号码：

```text
CSMA/CD 的最小帧长要背
CRC 的生成多项式要背
TCP 的四个计时器要背
```

背完就忘，忘完再背。

**问题不在协议多。**

**问题在于，你不知道它们在"一次通信"里各管哪一段。**

## 2. 一条主线：分层、封装、协议

整套网络，可以压成三句话。

```text
分层：把"一次通信"拆成五件互不干扰的事。
封装：每一层只加自己的首部，不管里面装的是什么。
协议：同一层的两个实体，按约定好的格式对话。
```

画出来：

```text
    发送方                          接收方
  ┌─────────┐                    ┌─────────┐
  │ 应用层   │◄──── 应用层协议 ───►│ 应用层   │
  ├─────────┤                    ├─────────┤
  │ 传输层   │◄──── 传输层协议 ───►│ 传输层   │
  ├─────────┤                    ├─────────┤
  │ 网络层   │◄──── 网络层协议 ───►│ 网络层   │
  ├─────────┤                    ├─────────┤
  │ 链路层   │◄──── 链路层协议 ───►│ 链路层   │
  ├─────────┤                    ├─────────┤
  │ 物理层   │◄──── 比特流 ──────►│ 物理层   │
  └─────────┘                    └─────────┘
```

同层对话，靠的是"逻辑上"的协议。

实际数据是一层层往下交，再一层层往上拆。

```text
应用数据
  │ + TCP 首部
  ▼
TCP 报文段
  │ + IP 首部
  ▼
IP 数据报
  │ + 帧首部 + 帧尾部
  ▼
帧
  │ 变成比特
  ▼
电信号 / 光信号
```

**这就是封装（encapsulation）。**

**反直觉的点在这里：**

```text
网络不是"一条链路把数据送到"，
而是"每一跳都拆到网络层，再重新封装"。
```

路由器不关心你的 TCP 端口，它只看 IP 首部。

交换机连 IP 都不看，它只看 MAC。

这就是分层最实际的价值：**每一层只处理自己需要的那几位。**

### 2.1 一次封装，长度怎么算

拿一个具体的数走一遍。

浏览器要发 1000 字节的 HTTP 响应体。

```text
TCP 首部    20 B   （不含选项）
IP 首部     20 B   （不含选项）
以太网首部  14 B   （目的 MAC 6 + 源 MAC 6 + 类型 2）
以太网尾部   4 B   （FCS）
```

从上往下一路加：

```text
应用数据          1000 B
+ TCP 首部          20 B  → 1020 B   报文段
+ IP 首部           20 B  → 1040 B   数据报
+ 以太网首尾         18 B  → 1058 B   帧
```

所以链路上真正传的是 **1058 字节**。

有效载荷只有 1000 字节，效率：

```text
1000 / 1058 ≈ 94.5%
```

这就是为什么 408 会问"首部开销是多少"。

也是为什么小包很浪费：发 1 字节的数据，也要背 58 字节的首部。

**记住这三个数：20、20、18。**

TCP 20、IP 20、以太网 18（14 头 + 4 尾）。

几乎每道"算帧长/算开销"的题，都从这里开始。

## 3. 五层地图

```text
┌────────────────────────────────────────────┐
│ 应用层  HTTP  DNS  FTP  SMTP   —— 给人用的   │
├────────────────────────────────────────────┤
│ 传输层  TCP  UDP              —— 进程到进程   │
├────────────────────────────────────────────┤
│ 网络层  IP  ICMP  ARP 路由    —— 主机到主机   │
├────────────────────────────────────────────┤
│ 链路层  以太网  PPP  802.11    —— 一跳之内    │
├────────────────────────────────────────────┤
│ 物理层  编码 调制 介质         —— 比特到信号   │
└────────────────────────────────────────────┘
```

一句话记住每一层的"边界"：

```text
物理层：一个比特怎么变成信号
链路层：一段链路上怎么把帧送过去
网络层：从源主机到目的主机怎么走
传输层：到哪两个进程
应用层：这些字节是什么意思
```

## 4. 第 1 层：物理层

它只回答一个问题：

```text
0 和 1，怎么变成电、光、电磁波？
```

考点其实不多，但公式很硬：

```text
奈奎斯特：无噪声时，极限速率 = 2W log2(V)
香农：有噪声时，极限速率 = W log2(1 + S/N)
```

还有一堆"编码方式"：

```text
NRZ、曼彻斯特、差分曼彻斯特、4B/5B
```

408 在这一层最爱考两件事：

```text
给带宽和信噪比，算极限速率
给波形图，判断用的是哪种编码
```

## 5. 第 2 层：链路层

它管"一段链路上"的事。

四个功能：

```text
组帧：把比特流切成帧，知道从哪开始、到哪结束
差错控制：传错了能不能发现（或纠正）
流量控制：别把接收方淹没
介质访问控制：多个设备抢一根线，谁先发
```

这一层是 408 的**计算重灾区**：

```text
CRC 求余数
海明码求校验位
停等/GBN/SR 的信道利用率
CSMA/CD 的最小帧长
```

每一个都有固定套路。

后面各有一篇专门练。

## 6. 第 3 层：网络层

它管"从源主机到目的主机"。

核心只有两件事：

```text
转发：收到分组，查表，从哪个口出去
路由：这张表是怎么算出来的
```

围绕 IPv4 有一大串配套：

```text
地址分类、子网划分、CIDR、NAT
ARP（IP → MAC）
DHCP（自动配地址）
ICMP（报错与探测）
```

408 在这一层最爱考：

```text
给一个 IP 和掩码，算子网地址、广播地址、可用主机数
给路由表，判断某个目的地址走哪条
RIP/OSPF 的收敛与选路
```

## 7. 第 4 层：传输层

它把"主机到主机"细化成"进程到进程"。

两个协议，性格完全相反：

```text
UDP：不连接、不保证、首部 8 字节、想快就用它
TCP：连接、可靠、有序、首部 20 字节起
```

TCP 的三个大块，正好是三篇：

```text
连接管理：三次握手、四次挥手、TIME_WAIT
可靠传输：序号、确认、超时重传、快重传
流量与拥塞控制：rwnd、cwnd、慢开始、拥塞避免
```

408 在这一层最爱考：

```text
序号与确认号的计算
拥塞窗口随 RTT 的变化曲线
三次握手为什么不是两次
```

## 8. 第 5 层：应用层

协议最多，但考的其实是"谁连谁、用什么端口"。

```text
DNS   53   域名 → IP
FTP   20/21 控制连接 + 数据连接
SMTP  25   发邮件
POP3  110  收邮件
HTTP  80   网页
HTTPS 443  加密网页
```

408 在这一层最爱考：

```text
DNS 递归查询与迭代查询的区别
FTP 为什么用两条连接
HTTP/1.0 与 1.1 的连接方式
```

## 9. 三张必须能画的图

### 9.1 封装与拆封

```text
发送方                              接收方
应用数据
  │
  ├─ TCP 首部 ──────────────►  拆掉 TCP 首部
  │
  ├─ IP 首部 ───────────────►  拆掉 IP 首部
  │
  ├─ 帧首部 / 帧尾部 ────────►  拆掉帧头帧尾
  │
  └─ 比特 ──────────────────►  还原成帧
```

### 9.2 三次握手

```text
客户端                          服务器
   │  SYN  seq=x        ────────►  │
   │  ◄────────  SYN+ACK seq=y,ack=x+1
   │  ACK  seq=x+1,ack=y+1 ─────►  │
   │                                │
   连接建立，开始传数据
```

### 9.3 滑动窗口

```text
发送方窗口（大小 4）
┌───┬───┬───┬───┬───┬───┬───┐
│ 1 │ 2 │ 3 │ 4 │ 5 │ 6 │ 7 │
└───┴───┴───┴───┴───┴───┴───┘
 已发已确认 │ 已发未确认 │ 可发 │ 不可发
          └──── 窗口 ────┘
```

窗口往右滑，就表示收到了确认。

## 10. 三个必算的量

这一套里，几乎所有计算都从这三个量出发。

### 10.1 发送时延

```text
发送时延 = 数据长度 / 链路速率
```

1000 字节的帧，1 Gbps 链路：

```text
8000 bit / 10^9 bps = 8 μs
```

### 10.2 传播时延

```text
传播时延 = 距离 / 传播速度
```

1 km 光纤，光速约 2×10^8 m/s：

```text
1000 m / 2×10^8 = 5 μs
```

### 10.3 时延带宽积

```text
时延带宽积 = 传播时延 × 带宽
```

```text
5 μs × 1 Gbps = 5000 bit
```

意思是：这条链路上一共"在途"5000 个比特。

**这就是窗口至少要多大，才能把链路填满。**

## 14. 读完应该能回答的五个问题

这套讲解读完，下面五个问题应该能当场答出来。

答不上来的，就是你还没读透的那一层。

**第一问：带宽翻倍，下载为什么不一定快一倍？**

```text
提示：带宽只压缩"发送时延"。
传播时延、处理时延、排队时延都不变。
长肥管道（高带宽 × 高时延）里，瓶颈常常是窗口，不是带宽。
```

（01、19 篇）

**第二问：交换机为什么不隔离广播域？**

```text
提示：交换机按 MAC 转发，广播帧的目的 MAC 是 ff:ff:ff:ff:ff:ff，
它只能泛洪到所有端口。
要切广播域，得靠路由器或 VLAN。
```

（11 篇）

**第三问：TCP 为什么必须三次握手？**

```text
提示：两次握手时，服务器无法区分"新连接"和"迟到的旧 SYN"。
第三次 ACK 让双方都确认：对方的序号我收到了，我的序号对方也收到了。
```

（18 篇）

**第四问：子网里可用主机数为什么要减 2？**

```text
提示：主机号全 0 是网络地址，全 1 是广播地址，这两个都不能分配给主机。
```

（13 篇）

**第五问：无线为什么用 CSMA/CA 而不是 CSMA/CD？**

```text
提示：无线网卡发射时听不到周围的信号，
"边发边听"物理上做不到，只能先约好（RTS/CTS）再发。
```

（10 篇）

五问覆盖五层。

都能答，408 的概念题基本不会丢分。

## 15. 三遍读法

这套 25 篇不要从头到尾硬啃一遍。

分三遍，每遍目的不同。

**第一遍：建立分层观（约 3 小时）**

```text
00 → 01 → 02 → 12 → 17
```

只求一件事：拿到任何一个协议，知道它属于哪一层、管哪一段。

这一遍不要背公式。

**第二遍：啃计算（约 6 小时）**

```text
03 → 06 → 07 → 09 → 13 → 20
```

这六篇是 408 计算的集中地。

每篇的例题先自己做，再看答案；做错的记下"错在哪一步"，而不是"答案是多少"。

**第三遍：冲刺（约 2 小时）**

```text
23 → 24 → 真题
```

23 篇是十类题型的步骤清单。

24 篇是查阅页：哪道题卡住，按「考点 → 篇目索引」回查。

一个提醒：

```text
网络的计算题，错的往往不是公式，是单位。
b 与 B、ms 与 μs、KB 与 Kb，每次动笔前先把单位写出来。
```

## 16. 小结

整套网络，压成一句话：

```text
把一次通信拆成五层，
每层加自己的首部，
同层按协议对话，
逐跳拆封装再重新封装。
```

五层，五个"边界"：

```text
物理层：比特 → 信号
链路层：一段链路
网络层：主机到主机
传输层：进程到进程
应用层：字节的含义
```

三个必算量：

```text
发送时延 = 长度 / 速率
传播时延 = 距离 / 速度
时延带宽积 = 传播时延 × 带宽
```

下一篇正式开始：

```text
计算机网络系统讲解 01：计算机网络概述与性能指标
```

那一篇会回答：

```text
带宽、吞吐量、时延、RTT，到底谁是谁？
为什么"带宽翻倍"不一定让下载快一倍？
利用率为什么不能到 100%？
```

从下一篇开始，你看到的每个协议，都要能放回这张地图上。
