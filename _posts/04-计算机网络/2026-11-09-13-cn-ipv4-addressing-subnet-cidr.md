给一台新机器配网络，你要填三个框。

```text
IP 地址：192.168.1.37
子网掩码：255.255.255.0
默认网关：192.168.1.1
```

三个框，三种东西。

第一个是接口的名字。

第二个是名字的"切法"。

第三个是不知道往哪走时的出口。

大多数人卡在第二个框：掩码为什么要有，填错了会怎样。

## 1. 这个问题解决什么

一篇要解决的问题，可以拆成三件。

```text
一、给每个接口一个全网唯一的标识
二、让路由器能用一张小表覆盖几亿个目的地
三、让私网里的几十亿台设备共用一个公网地址
```

第一件靠地址结构。

第二件靠前缀聚合。

第三件靠 NAT。

这三件事不是三个独立的知识点。

它们是同一个矛盾的三种解法：**地址只有 32 位，而设备比地址多。**

**先把一个容易搞错的前提说清楚：**

> **IP 地址标识的是"接口"，不是"设备"。**
> 一台路由器有三个口，就有三个 IP。
> 一台笔记本同时开有线和无线，也可能有两个 IP。
> 所以"这台机器的 IP 是多少"这句话，本身就不严谨。

这一篇从一根 32 位的二进制串开始，一路算到 NAT 的表项。

算完之后，你应该能对着任何一个 IPv4 地址，三秒内说出：

```text
它属于哪个子网
它的广播地址是多少
它能不能配在接口上
它和另一个地址是不是邻居
```

这四个问题，是地址这一章的全部考点。

也是排障时最常问的四个问题。

## 2. 32 位地址怎么写

IPv4 地址是 32 位。

写成给人看的形式，叫点分十进制（dotted decimal）。

```text
192 . 168 . 1 . 37
 ↑     ↑    ↑   ↑
 8 位  8 位 8 位 8 位
```

四段，每段 8 位，取值范围 0–255。

超过 255 的写法是非法的，256.1.1.1 不是地址。

把十进制翻成二进制，只需要记住八个位权：

```text
位权：128  64  32  16  8  4  2  1

192 = 128 + 64
168 = 128 + 32 + 8
  1 = 1
 37 = 32 + 4 + 1
```

所以：

```text
192.168.1.37
= 11000000 10101000 00000001 00100101
```

反过来也一样，从高位往低位减就行。

这个转换必须练到不用想。

32 位能表示多少个地址？

2^32 = 4 294 967 296，大约 43 亿。

1990 年代觉得够用，因为当时全世界联网的计算机不到 1000 万台。

2011 年 IANA 把最后一批 IPv4 地址分完。

现在这 43 亿个地址，要装下 200 亿台设备。

差出来的部分，靠 NAT 和 IPv6 补。

这也是为什么地址规划要精打细算。

因为 408 的地址题，第一步永远是翻成二进制。

**关键的一点：**

这 32 位里，没有任何一位标着"从这里开始是主机号"。

地址本身不带结构。

结构是另外给的，那就是掩码。

## 3. 分类地址：A、B、C、D、E

最早的方案，把 32 位按"首字节"分成五类。

```text
类别   首字节     首位模式    默认掩码          网络数        每网主机数
A      0–127      0xxxxxxx    255.0.0.0         126           16 777 214
B      128–191    10xxxxxx    255.255.0.0       16 384        65 534
C      192–223    110xxxxx    255.255.255.0     2 097 152     254
D      224–239    1110xxxx    无（组播）         —             —
E      240–255    1111xxxx    保留               —             —
```

这几个数是怎么来的，值得当场推一遍。

A 类第一位固定是 0，剩下 7 位可以变。

2^7 = 128 个网络号。

但全 0 的 0.0.0.0 和 127 开头的回环地址要留出来。

所以可用网络数是 128 − 2 = 126。

主机号占 24 位，2^24 − 2 = 16 777 214。

边界值要记准，因为考题就卡在这几个数上。

```text
127 是 A 类的最后一个（01111111）
128 是 B 类的第一个（10000000）
191 是 B 类的最后一个（10111111）
192 是 C 类的第一个（11000000）
223 是 C 类的最后一个（11011111）
224 是 D 类的第一个（11100000）
```

B 类前两位固定 10，剩 14 位当网络号，2^14 = 16 384。

主机号 16 位，2^16 − 2 = 65 534。

C 类前三位固定 110，剩 21 位，2^21 = 2 097 152。

主机号 8 位，2^8 − 2 = 254。

每一个都减 2。

减的是"主机号全 0"和"主机号全 1"这两个地址。

```text
主机号全 0：代表"这个网络本身"，也就是网络地址
主机号全 1：代表"这个网络里的所有主机"，也就是广播地址
```

这两个地址都不能配给接口。

不是习惯问题，是协议规定它们有别的语义。

分类地址的问题很明显。

一个需要 300 台主机的公司，C 类不够，只能申请 B 类。

一个 B 类有 65 534 个地址，它只用 300 个。

剩下的 65 234 个地址，谁也拿不到。

**分类地址的浪费率可以到 99%。**

这就是子网划分和 CIDR 出现的直接原因。

## 4. 私有地址与必须记住的特殊地址

有三段地址被留出来，专门给私网用。

```text
10.0.0.0/8          10.0.0.0    – 10.255.255.255       （1 个 A 类）
172.16.0.0/12       172.16.0.0  – 172.31.255.255       （16 个 B 类）
192.168.0.0/16      192.168.0.0 – 192.168.255.255      （256 个 C 类）
```

这三段不会出现在公网上。

运营商的路由器见到目的地址是 192.168.x.x 的包，直接丢掉。

所以全世界几亿个家庭可以同时用 192.168.1.1 当网关，不会冲突。

172.16.0.0/12 这一段的边界经常有人记错。

/12 表示前 12 位固定，第三字节的高 4 位也固定。

第三字节只能是 0001 0000 到 0001 1111，也就是 16 到 31。

所以是 172.16 到 172.31，不是 172.0 到 172.255。

还有几个特殊地址，考试常考，实战也常撞见。

```text
0.0.0.0             本机、未配置源地址、默认路由的目的前缀
127.0.0.0/8         回环，127.0.0.1 就是 localhost
169.254.0.0/16      链路本地，DHCP 拿不到地址时自己配一个
255.255.255.255     受限广播，只在本网段内，路由器不转发
224.0.0.0/4         组播，留到第 15 篇
```

**169.254 这一段特别值得记。**

Windows 上看到"仅本地连接"、地址是 169.254.x.x，意思不是"网卡坏了"。

意思是 DHCP 没回应，系统自己随手挑了一个链路本地地址。

同网段的两台机器都落到 169.254，还能互相通信。

但它们都出不了网关。

这是个很实用的排障信号：看到 169.254，先去查 DHCP。

## 5. 最小模型：掩码、借位与一张子网表

掩码（netmask）也是一串 32 位的二进制。

规则只有一条：

```text
掩码里是 1 的位 → 属于网络号
掩码里是 0 的位 → 属于主机号
```

而且 1 必须连续，从最高位开始，中间不能断。

所以 255.0.255.0 不是合法掩码。

有了掩码，三种计算就固定了。

```text
子网地址 = IP AND 掩码          （主机位全部清零）
广播地址 = 子网地址 OR (NOT 掩码) （主机位全部置一）
可用范围 = 子网地址 + 1  到  广播地址 − 1
```

拿一个地址算一遍。

```text
IP：   192.168.1.100    11000000 10101000 00000001 01100100
掩码： 255.255.255.192  11111111 11111111 11111111 11000000
        ───────────────────────────────────────────────────
AND：                   11000000 10101000 00000001 01000000
                        = 192.168.1.64
```

主机位是最后 6 位，全部置一：

```text
01000000 → 01111111 = 127
广播地址 = 192.168.1.127
```

可用范围：

```text
192.168.1.65 – 192.168.1.126
```

一共 126 − 65 + 1 = 62 个。

和 2^6 − 2 = 62 对得上。

**掩码的另一种记法更快：看最后一个非 255 的字节。**

```text
块大小 = 256 − 该字节的掩码值
```

掩码 192 → 块大小 64。

掩码 224 → 块大小 32。

掩码 240 → 块大小 16。

掩码 248 → 块大小 8。

掩码 252 → 块大小 4。

有了块大小，子网地址就是"把 IP 向下取整到块大小的整数倍"。

100 向下取整到 64 的倍数，就是 64。

不用翻二进制，心算就出来了。

**掩码为什么必须连续？**

因为"网络号"这个概念要求高位的 1 连成一片。

如果允许 255.0.255.0 这种中间断开的掩码，那么"前 n 位是网络号"这个说法就不成立了。

路由表也没法用"前缀长度"来压缩。

所以协议规定：掩码是 n 个连续的 1，后面全是 0。

这也意味着掩码只有 33 种可能，从 /0 到 /32。

工程上还会见到掩码的取反形式，叫反掩码或通配符掩码（wildcard mask）。

```text
掩码      255.255.255.0
反掩码    0.0.0.255
```

Cisco 的 ACL 和 OSPF 的 network 命令用反掩码。

```text
OSPF：network 192.168.1.0 0.0.0.255 area 0
```

读法：前 24 位必须匹配，后 8 位随便。

反掩码里是 0 的位表示"必须一样"，是 1 的位表示"不关心"。

正好和掩码相反，别记混。

### 借位：2^n 与 2^m−2

子网划分（subnetting）做的事情：把一个大网络的主机位，借几位出来当子网号。

```text
原来的：  网络号（24 位） | 主机号（8 位）
借 3 位： 网络号（24 位） | 子网号（3 位） | 主机号（5 位）
```

借 n 位，公式是两个。

```text
子网数 = 2^n
每个子网的可用主机数 = 2^m − 2      （m 是剩下的主机位数）
```

C 类地址的完整对照：

```text
借位数   前缀    掩码最后字节   子网数   每子网可用主机
0        /24     0              1        254
1        /25     128            2        126
2        /26     192            4        62
3        /27     224            8        30
4        /28     240            16       14
5        /29     248            32       6
6        /30     252            64       2
```

**这张表里藏着一个反直觉的地方。**

> **借一位，可用主机从 254 掉到 126。**
> 不是 127。
> 因为 254 个地址被切成两半，每半 128 个，
> 每一半还要再各去掉网络地址和广播地址，
> 128 − 2 = 126。
> 两个子网加起来 252 个可用地址，比原来的 254 少了 2 个。

借得越多，丢得越多。

借 6 位变成 /30，64 个子网，每个只剩 2 个可用地址。

一共 128 个可用地址，原来有 254 个。

**一半的地址被网络地址和广播地址吃掉了。**

这就是为什么点到点链路后来用 /31（RFC 3021），两个地址都当主机用，不谈网络地址和广播地址。

但 408 按传统规则算，见到 /30 就是 2 个可用主机。

不要拿 /31 去抬杠。

**顺带回答一个更实际的问题：为什么要划子网？**

三个理由，从弱到强。

```text
一、省地址：一个 B 类切成 256 个 /24，分给 256 个部门
二、控广播：广播帧不出子网，划小了广播域就小了
三、分权限：不同子网之间的访问必须过路由器，可以在那里做策略
```

第三条是今天最常用的理由。

同一个 /24 里的两台机器，防火墙插不上手。

拆成两个 /27，中间放一台路由器或三层交换机，就能写 ACL。

**广播域这一条，在 408 里和第 11 篇的交换机知识直接连着考。**

一个 /24 就是一个广播域。

划成 8 个 /27，就是 8 个广播域。

但前提是这 8 个子网配在路由器的不同接口上（或者 VLAN 不同）。

只在同一台交换机上改掩码，广播域还是一个。

这是很多人绕不过去的弯。

### 借 3 位：一张完整的 C 类子网表

题目：把 192.168.1.0/24 划分成 8 个子网。

借 3 位，前缀变成 /27，掩码 255.255.255.224。

块大小 = 256 − 224 = 32。

八个子网的起点就是 0、32、64、96、128、160、192、224。

| 子网 | 网络地址 | 第一个可用 | 最后一个可用 | 广播地址 |
|---|---|---|---|---|
| 1 | 192.168.1.0 | 192.168.1.1 | 192.168.1.30 | 192.168.1.31 |
| 2 | 192.168.1.32 | 192.168.1.33 | 192.168.1.62 | 192.168.1.63 |
| 3 | 192.168.1.64 | 192.168.1.65 | 192.168.1.94 | 192.168.1.95 |
| 4 | 192.168.1.96 | 192.168.1.97 | 192.168.1.126 | 192.168.1.127 |
| 5 | 192.168.1.128 | 192.168.1.129 | 192.168.1.158 | 192.168.1.159 |
| 6 | 192.168.1.160 | 192.168.1.161 | 192.168.1.190 | 192.168.1.191 |
| 7 | 192.168.1.192 | 192.168.1.193 | 192.168.1.222 | 192.168.1.223 |
| 8 | 192.168.1.224 | 192.168.1.225 | 192.168.1.254 | 192.168.1.255 |

每一行都满足三个关系：

```text
网络地址 = 起点，主机位全 0
广播地址 = 下一个子网的起点 − 1
可用数量 = 30
```

验算第 4 行。

96 的二进制是 01100000，低 5 位全 0，所以是网络地址。

127 是 01111111，低 5 位全 1，所以是广播地址。

126 − 97 + 1 = 30。

**这张表要能默写。**

408 的综合题，给一个地址问"属于哪个子网、广播地址是多少"，考的就是这张表。

用前面那个块大小法验一遍：/27 的块大小是 32，100 向下取整到 96，广播 96 + 31 = 127。

和表里第 4 行一致。

三秒就能出答案。

所以这张表不用死背。

记住"块大小 = 256 − 掩码最后字节"，表自己就能长出来。

## 6. 408 怎么考

地址这一块的题型很固定，五类。

```text
一、给 IP 和掩码，求子网地址、广播地址、可用范围
二、给需求（几个子网、每网几台主机），求掩码
三、判断两个地址是否在同一子网
四、给几条前缀，求聚合结果，或判断能否聚合（第 9 节有例题）
五、给路由表和一个目的地址，求下一跳（第 10 节）
```

这一节先算前三类。

后两类在第 9、10 节各配了一道题。

套路只有一条：**全部翻成二进制，或者用块大小心算。**

下面这道是自拟题，三问，覆盖前三类。

**题目：**

某单位分到 172.16.10.0/24，需要划分成至少 6 个子网，每个子网至少 25 台主机。

（1）子网掩码应该是多少？

（2）172.16.10.100/27 的子网地址、广播地址、可用范围分别是什么？

（3）172.16.10.100 与 172.16.10.200，在 /27 下是否属于同一子网？

**（1）解：**

先定借位数。

```text
借 2 位：2^2 = 4 个子网，不够 6
借 3 位：2^3 = 8 个子网，够
借 4 位：2^4 = 16 个子网，但主机位只剩 4 位
        2^4 − 2 = 14 台，不够 25
```

只有借 3 位同时满足两个条件。

```text
前缀 = 24 + 3 = 27
掩码 = 255.255.255.224
每个子网可用主机 = 2^5 − 2 = 30 台 ≥ 25
```

答案是 255.255.255.224，也就是 /27。

**（2）解：**

块大小 = 256 − 224 = 32。

100 向下取整到 32 的倍数：

```text
32 × 3 = 96 ≤ 100 < 128 = 32 × 4
```

子网地址 = 172.16.10.96。

广播地址 = 96 + 32 − 1 = 172.16.10.127。

可用范围 = 172.16.10.97 – 172.16.10.126。

验算：126 − 97 + 1 = 30，等于 2^5 − 2。对。

用二进制核一遍：

```text
100 = 01100100
掩码 = 11100000
AND  = 01100000 = 96        ✓
```

**（3）解：**

200 的块：

```text
32 × 6 = 192 ≤ 200 < 224 = 32 × 7
```

200 落在子网 172.16.10.192。

100 落在子网 172.16.10.96。

192 ≠ 96，不是同一子网。

**结论：不在同一子网，通信要经过路由器。**

这道题的三个坑：

```text
坑一：只算子网数，忘了算主机数（借 4 位会挂）
坑二：广播地址算成 96 + 32 = 128（多算了一个）
坑三：判断同子网时去比 IP 大小，而不是比子网地址
```

**再补一个常见的变体。**

题目：下列地址中，哪个不能配在主机接口上？

```text
A. 192.168.1.63/26
B. 192.168.1.65/26
C. 192.168.1.190/27
D. 10.0.0.1/8
```

逐个算。

```text
A. /26 块大小 64，63 向下取整 0 → 子网 .0，广播 .63
   63 正是广播地址，不能用
B. 65 落在 .64 子网（64–127），.65 是第一个可用，能用
C. /27 块大小 32，190 向下取整 160 → 子网 .160，广播 .191
   190 在 161–190 之间，是最后一个可用，能用
D. 10.0.0.1 是 10.0.0.0/8 的第一个可用地址，能用
```

答案是 A。

这类题不考概念，就考"广播地址不能配"这条。

**还有一个送分但有人丢的点。**

题目问"该子网可用主机数"，答 2^m。

忘了减 2。

只要题目问的是 IPv4 的普通子网，一律减 2。

只有 /31 的点到点链路是例外，而 408 不出这种题。

## 7. 真实网络里长什么样

Linux 上看地址，用 `ip addr`。

```text
$ ip -4 addr show eth0
2: eth0: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 qdisc fq_codel
    inet 192.168.1.37/24 brd 192.168.1.255 scope global dynamic eth0
       valid_lft 86390sec preferred_lft 86390sec
```

（简化示意）

三个细节值得看。

```text
一、地址写成 192.168.1.37/24，前缀和地址绑在一起显示
二、brd 192.168.1.255 是内核算出来的广播地址
三、dynamic 说明这个地址是 DHCP 拿的，valid_lft 是剩余租期
```

路由表用 `ip route`。

```text
$ ip route
default via 192.168.1.1 dev eth0 proto dhcp metric 100
192.168.1.0/24 dev eth0 proto kernel scope link src 192.168.1.37
```

（简化示意）

两行读法：

```text
第一行：目的 0.0.0.0/0 的包，交给 192.168.1.1，从 eth0 出去
第二行：目的 192.168.1.0/24 的包，直连，不用网关
```

第二行的 `proto kernel` 表示这条是内核根据地址和掩码自动生成的路由。

配了 192.168.1.37/24，内核自动加一条 192.168.1.0/24 直连路由。

这就是"掩码决定了哪些地址是邻居"的实际体现。

想知道某个具体地址走哪条，用 `ip route get`。

```text
$ ip route get 10.1.2.3
10.1.2.3 via 192.168.1.1 dev eth0 src 192.168.1.37 uid 1000
```

（简化示意）

它会把最长前缀匹配的结果直接打出来。

排障时比 `ip route` 翻表快得多。

Windows 上是 `ipconfig /all`，字段叫"子网掩码"和"默认网关"。

Windows 的路由表用 `route print`，输出里有一列"网络目标"和"网络掩码"。

macOS 是 `ifconfig`，掩码写成十六进制 `0xffffff00`（对应 /24）。

想快速算一个网段，用 `ipcalc` 或 `sipcalc`。

```text
$ ipcalc 192.168.1.100/27
Address:   192.168.1.100        11000000.10101000.00000001.011 00100
Netmask:   255.255.255.224 = 27 11111111.11111111.11111111.111 00000
Network:   192.168.1.96/27      11000000.10101000.00000001.011 00000
HostMin:   192.168.1.97
HostMax:   192.168.1.126
Broadcast: 192.168.1.127
Hosts/Net: 30
```

（简化示意）

它把每一位的对齐关系都画出来了。

考试时不能带工具，但平时用它核对答案很有用。

算完自己对一遍，比反复看书有效。

一台家用路由器的 NAT 表，在管理页面上通常叫"连接跟踪"或"会话表"。

Linux 上对应的命令是 `conntrack -L`。

```text
$ conntrack -L
tcp 6 431999 ESTABLISHED src=10.0.0.2 dst=203.0.113.9 sport=5000 dport=80
    src=203.0.113.9 dst=203.0.113.5 sport=80 dport=40001
```

（简化示意）

一行里两组五元组，就是前面那张表的两侧。

看它就知道 NAPT 是不是在工作。

## 8. CIDR：/n 是唯一的长度

CIDR（无类域间路由）把分类地址彻底废掉了。

它的写法是"地址/前缀长度"。

```text
192.168.1.0/24   表示前 24 位是网络号，后 8 位是主机号
10.0.0.0/8       表示前 8 位是网络号
0.0.0.0/0        表示前 0 位是网络号，也就是"所有地址"
```

前缀长度可以是 0 到 32 之间的任何整数。

不再看首字节，不再有 A/B/C 的隐含约定。

**/n 和掩码是同一件事的两种写法。**

```text
前缀     掩码              块大小（最后字节）
/8      255.0.0.0          —
/12     255.240.0.0        —
/16     255.255.0.0        —
/20     255.255.240.0      16
/22     255.255.252.0      4
/24     255.255.255.0      1
/25     255.255.255.128    128
/26     255.255.255.192    64
/27     255.255.255.224    32
/28     255.255.255.240    16
/29     255.255.255.248    8
/30     255.255.255.252    4
```

前缀越长，网络越小，主机越少。

/n 的主机位数是 32 − n，可用主机数是 2^(32−n) − 2。

/24 → 2^8 − 2 = 254。

/22 → 2^10 − 2 = 1022。

/30 → 2^2 − 2 = 2。

CIDR 带来的最大好处不是省地址，是**让路由表能变小**。

举个规模上的对比。

```text
一个运营商有 4096 个连续的 /24
不聚合：4096 条路由
聚合成 /12：1 条路由
```

4096 = 2^12，24 − 12 = 12。

一条 /12 顶 4096 条 /24。

互联网骨干路由表今天大约 90 万条前缀，如果不做聚合，这个数字会是几千万。

**聚合是互联网能路由的前提，不是优化技巧。**

顺手做一个地址规划的小练习。

某公司有 500 台设备，要一段连续地址。

```text
/24 只有 254 个，不够
/23 有 510 个，够
/23 的掩码是 255.255.254.0
```

所以给它 10.10.0.0/23。

范围是 10.10.0.0 到 10.10.1.255。

广播地址 10.10.1.255。

可用 10.10.0.1 到 10.10.1.254，一共 510 个。

如果明年扩到 1200 台，就要 /21（2046 个）。

规划时留一倍余量，是常规做法。

## 9. 路由聚合：4 条 /24 变 /22

假设一个运营商手里有四段连续的 /24。

```text
200.120.0.0/24
200.120.1.0/24
200.120.2.0/24
200.120.3.0/24
```

不聚合，边界路由器要向全世界通告 4 条路由。

聚合，只通告 1 条。

做法是把四个网络号并排写，找共同前缀。

```text
200.120.0.0/24   第三字节 00000000
200.120.1.0/24   第三字节 00000001
200.120.2.0/24   第三字节 00000010
200.120.3.0/24   第三字节 00000011
                          ↑↑↑↑↑↑
                     这 6 位完全相同
```

第三字节的高 6 位都是 000000，只有低 2 位在变。

所以网络前缀是 24 − 2 = 22 位。

```text
聚合结果：200.120.0.0/22
掩码：    255.255.252.0
范围：    200.120.0.0 – 200.120.3.255
广播：    200.120.3.255
可用主机：2^10 − 2 = 1022
```

验算一下范围对不对。

/22 的第三字节低 2 位可以变，取值 00、01、10、11。

正好对应 0、1、2、3。

第四字节 0–255 全可以变。

所以覆盖的是 200.120.0.0 到 200.120.3.255，一共 4 × 256 = 1024 个地址。

1024 − 2 = 1022。

**聚合不是随便四条就能合的。**

三个条件：

```text
一、地址连续
二、数量是 2 的幂
三、起始地址是数量的整数倍（对齐）
```

反例一：200.120.0.0/24、200.120.2.0/24、200.120.3.0/24、200.120.4.0/24。

少了 200.120.1.0/24，不连续。

硬要聚合成 /22 会把 1.0 这段也吃进去，等于替别人的地址做通告。

反例二：200.120.1.0/24、200.120.2.0/24、200.120.3.0/24、200.120.4.0/24。

数量是 4，但起始的 1 不是 4 的倍数。

看第三字节：

```text
1 = 00000001
2 = 00000010
3 = 00000011
4 = 00000100
```

四条共同的高位只有 5 个 0。

能覆盖它们的最小前缀是 /29，范围 0–7。

这意味着要多吃 0、5、6、7 这四段。

**聚合允许"多吃"，但多吃会误导转发。**

把不属于自己的地址通告出去，流量会跑过来然后被丢掉。

所以工程上的规则更严：聚合后的范围必须正好等于原来那些网络的并集。

四条的并集是 1、2、3、4，不是 0–3，也不是 0–7。

这四条无法用一条路由表示。

只能分别通告，或者两两聚合（1 和 2 也不是对齐的 2 的倍数起点，同样不行）。

这就是"对齐"这个条件的实际含义。

**心算判据：**

```text
把起始地址折算成"块内的序号"
如果序号能被块大小整除 → 对齐，可聚合
否则不行
```

0 能被 4 整除，可以。

1 不能被 4 整除，不行。

4 能被 4 整除，所以 4、5、6、7 可以聚合成 200.120.4.0/22。

同样是四条，起点不同，结果不同。

### 408 会这么问：聚合判断

**题目：** 四条路由 172.16.8.0/24、172.16.9.0/24、172.16.10.0/24、172.16.11.0/24，能否聚合成一条？聚合后 172.16.13.7 是否在这个前缀内？

**解：**

三条都满足：

```text
连续：8、9、10、11 中间没有断
数量：4 = 2^2，是 2 的幂
对齐：起始的 8 是 4 的倍数
```

看第三字节：

```text
 8 = 00001000
 9 = 00001001
10 = 00001010
11 = 00001011
        ↑↑↑↑↑↑
    高 6 位相同
```

共同前缀 22 位。

```text
聚合：172.16.8.0/22
掩码：255.255.252.0
范围：172.16.8.0 – 172.16.11.255
```

再判断 172.16.13.7。

第三字节 13 = 00001101。

/22 要求高 6 位是 000010，13 的高 6 位是 000011，不匹配。

**不在前缀内。**

**验算：** 范围是 8 到 11，13 超出。

也可以直接比前缀：000011 ≠ 000010。两条路结论一致。对。

## 10. 最长前缀匹配

路由表里，同一个目的地址可能匹配多条路由。

```text
目的网络          下一跳        出接口
0.0.0.0/0        10.0.0.1     eth0
10.0.0.0/8       10.0.0.2     eth0
10.1.0.0/16      10.0.0.3     eth1
10.1.2.0/24      10.0.0.4     eth1
```

现在要转发一个目的地址是 10.1.2.3 的包。

四条全匹配。

```text
10.1.2.3 的前 8 位是 10        → 匹配 /8
10.1.2.3 的前 16 位是 10.1     → 匹配 /16
10.1.2.3 的前 24 位是 10.1.2   → 匹配 /24
0.0.0.0/0 谁都能匹配           → 匹配 /0
```

规则是：**前缀最长的那条赢。**

所以选 10.1.2.0/24，下一跳 10.0.0.4。

这个机制叫最长前缀匹配（longest prefix match）。

它带来的一个有趣结果：

```text
0.0.0.0/0 就是默认路由
它的前缀长度是 0，永远最短
所以它永远排在最后，当兜底
```

**这也解释了为什么路由表里可以有互相重叠的条目。**

重叠不是错误，是设计。

细节路由放在前面（更长的前缀），汇总路由放在后面（更短的前缀）。

408 查表题的固定三步：

```text
第一步：把目的地址和每条前缀都写成二进制
第二步：逐条比对前 n 位，n 是这条前缀的长度
第三步：在所有匹配的条目里，选 n 最大的那条
```

如果一条都不匹配，包被丢弃，回一个 ICMP 不可达。

如果有一条 /0，那它一定匹配，所以默认路由等于"永不丢包的兜底"。

**顺带说清路由表的三个来源。**

```text
直连路由：配了地址和掩码，内核自动生成，前缀就是那个 /n
静态路由：人手工写的，一条一条加
动态路由：RIP/OSPF/BGP 算出来的，会随拓扑变化
```

三条来源的路由会一起参与最长前缀匹配。

如果前缀长度一样呢？

比管理距离（administrative distance），值小的优先。

Linux 上叫 metric，`ip route` 输出里那个 `metric 100` 就是它。

优先级大致是：直连 0，静态 1，OSPF 110，RIP 120。

这个顺序在第 16 篇讲路由协议时会再出现一次。

**这里有个容易错的判断。**

有人说"目的地址落在 10.0.0.0/8 里，就应该走 /8 那条"。

错了。

如果表里同时有 10.1.0.0/16，而目的地址是 10.1.5.5，那 /16 更长，走 /16。

前缀长度和"地址落在哪个区间"是两件事。

落在区间里只是匹配的前提，不是选择的依据。

包转发时不需要"分类"，也不需要知道 A/B/C。

只看前缀长度。

一台骨干路由器的路由表可能有 90 万条 IPv4 前缀。

最长前缀匹配要在微秒级完成。

硬件做法是把前缀塞进 TCAM，一次比较所有长度。

软件做法是 Patricia trie 或 LC-trie。

这些不在 408 范围内，知道"最长前缀赢"就够了。

## 11. NAT：一个公网地址怎么被复用

NAT（网络地址转换）解决的问题很具体。

私网地址不能上公网，但私网里的设备要访问公网。

解法：在出口把源地址换掉。

最早的 NAT 是一对一：一个私网地址固定换一个公网地址。

这样不省地址。

真正让 IPv4 活到今天的是 NAPT（网络地址端口转换），俗称 NAT 复用。

它把端口也一起换。

家庭路由器里那张表大概长这样。

| 内网侧（私网 IP:端口） | 外网侧（公网 IP:端口） | 目的地址 |
|---|---|---|
| 10.0.0.2:5000 | 203.0.113.5:40001 | 203.0.113.9:80 |
| 10.0.0.3:5000 | 203.0.113.5:40002 | 203.0.113.9:80 |
| 10.0.0.2:5001 | 203.0.113.5:40003 | 198.51.100.7:443 |

注意第一行和第二行。

两台内网主机的源端口都是 5000。

如果只换 IP，两个连接在公网上会撞车。

所以出口把端口也改了：40001 和 40002。

**区分一个连接，靠的是五元组。**

```text
源 IP、源端口、目的 IP、目的端口、协议
```

NAPT 改的是前两个（出方向），回方向反过来查表。

一次完整的走查：

```text
① 10.0.0.2:5000 发 SYN 到 203.0.113.9:80
② 路由器改源地址为 203.0.113.5:40001，记表，发出
③ 服务器回包，目的 203.0.113.5:40001
④ 路由器查表，改回 10.0.0.2:5000，交给内网
```

第 ② 步还要重算 IP 首部校验和，以及 TCP 校验和（因为伪首部里的源地址变了）。

**NAT 的代价，四条。**

```text
一、破坏端到端：外部主机无法主动连进来（表里没有对应项）
二、需要 ALG：FTP 的 PORT 命令、SIP 的 SDP 里带 IP 和端口，必须拆开改
三、可追溯性变差：一个公网 IP 后面是一群人，日志只能记到地址
四、P2P 和游戏联机需要打洞（STUN/TURN），多一层成本和延迟
```

第一条最要命。

这也是为什么"家里架服务器"必须做端口映射。

端口映射的本质，是手工往那张表里插一条静态项。

```text
公网 203.0.113.5:8080  →  内网 10.0.0.2:80   （静态，永不过期）
```

外部访问 203.0.113.5:8080，路由器照表改目的地址，转给内网那台机器。

第二条容易被忽略。

FTP 主动模式下，客户端在 PORT 命令里塞了自己的 IP 和端口。

NAT 不拆这个载荷，服务器就会去连一个私网地址，必然失败。

所以家用路由器里跑 FTP 服务器经常要"关掉 NAT 校验"或者开被动模式。

这不是路由器坏，是协议把地址写在了应用层数据里。

第三条在合规场景是真问题。

一个小区宽带几百户共用一个公网 IP，出了事只能定位到"这一群人"。

运营商级 NAT（CGNAT）把这个规模放大到几千户，问题更明显。

顺带说一个 408 不考但实战会撞的细节：发夹 NAT（hairpin NAT）。

内网主机 A 用公网 IP 访问内网服务器 B，包发到路由器，路由器要把它再转回内网。

很多家用路由器默认不支持，表现是"内网用域名访问不了自己的服务"。

**NAT 与 IPv6 的关系，一句话。**

NAT 是地址不够的补丁，不是设计的一部分。

IPv6 有足够地址，理论上不需要 NAT。

但工程上很多人还是想要 NAT 带来的"默认不被访问"的效果。

这是安全和地址数量的两件事被混在了一起。

## 12. 容易混淆的点

第一组：网络地址、广播地址、网关地址。

```text
网络地址：主机位全 0，不能配给接口，代表"这个网络"
广播地址：主机位全 1，不能配给接口，代表"全体"
网关地址：某个接口的地址，通常是第一个可用地址，但协议没规定必须是它
```

网关不一定是 .1。

完全可以配成 .254。

只是大家习惯了 .1。

第二组：/24 和 255.255.255.0。

两者完全等价，一个是长度写法，一个是掩码写法。

考题里可能混着给，要能互换。

第三组：169.254 和私有地址。

169.254.0.0/16 是链路本地地址，不是 RFC 1918 私有地址。

它不出网卡，连路由器都不给转发。

私有地址至少还能通过 NAT 出去。

第四组：NAT 改了谁。

```text
出方向：改源 IP 和源端口
回方向：改目的 IP 和目的端口
```

目的 IP 和目的端口，在正常转发中不改。

改了的是 ALG，那是特例。

第五组：聚合后的广播地址。

200.120.0.0/22 的广播地址是 200.120.3.255。

不是 200.120.0.255。

0.255 只是一个普通地址（前提是没用 /24）。

这个错在考卷上非常常见。

## 13. 小结

地址这一块，压成五个公式。

```text
子网地址 = IP AND 掩码
广播地址 = 子网地址 + 块大小 − 1
块大小   = 256 − 掩码最后字节
可用主机 = 2^(32−前缀) − 2
聚合前缀 = 共同前缀的长度（连续、2 的幂、对齐）
```

三句话记住三个机制。

```text
子网划分：把主机位借给子网号，借 n 位得 2^n 个子网
CIDR：用 /n 统一表示前缀，聚合让路由表变小
NAT：用端口区分连接，让一个公网地址服务很多内网主机
```

回到开头那三个框。

```text
IP 地址：标识一个接口
子网掩码：画出网络号和主机号的分界线
默认网关：网段外所有目的地的默认下一跳
```

填错任何一个，机器都出不去。

填对了，它也只是"能出去"。

下一篇要回答的是"出去"这两个字的细节：

```text
知道目的 IP 是 8.8.8.8，但网卡的帧要填 MAC 地址，MAC 从哪来？
刚插上网线，一个地址都没有，地址从哪来？
ping 一个地址，对面不回，是谁在告诉你"不可达"？
```

答案分别是 ARP、DHCP、ICMP。

```text
计算机网络系统讲解 14：ARP、DHCP 与 ICMP
```

那一篇的主线是：**IP 包在每一跳都会被拆开重新封装，而 ARP 就是那个"重新封装"时找 MAC 的动作。**
