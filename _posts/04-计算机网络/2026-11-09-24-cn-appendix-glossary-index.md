## 1. 术语表（一）：体系结构与物理层

为什么按层分组，不按字母排？

因为查的时候，你其实知道自己要找的是哪一层的东西：查拥塞窗口一定在传输层，查最小帧长一定在链路层。

按层翻，两步就到；按字母翻，你得先知道它英文怎么拼。

每组三列：中文、英文、一句话。

整个术语表 66 条，按五层分组。

不在这 66 条里的还有 VLAN、STP、PPP、HDLC、TTL、IPv6、组播这些，它们散在 09、11、15 三篇里，因为离开上下文单写一句反而记不住。

每一组的顺序都是"从概念到协议到设备"，跟数据往下走的顺序一致。

体系结构 4 条：

```text
协议        protocol            对等层之间通信的规则集合
服务        service             下层向上层提供的功能，垂直方向
接口        SAP                 上下层之间的交接点，也就是服务访问点
封装        encapsulation       每层给自己的数据加一个首部
```

物理层 6 条：

```text
码元        symbol              一个信号状态，可携带 log2(V) 个比特
波特率      baud                每秒码元数，不是每秒比特数
奈氏准则    Nyquist             无噪声极限：2W log2(V)
香农定理    Shannon             有噪声极限：W log2(1 + S/N)
信噪比      SNR                 信号功率 / 噪声功率，常用 dB
调制        modulation          把比特映射到载波的幅度/频率/相位
```

四种复用也归在物理层：

```text
频分复用    FDM   按频段切，各占一段，同时发
时分复用    TDM   按时间片轮，各占一槽，轮流发
码分复用    CDM   用一组正交码区分用户，同时同频
波分复用    WDM   光纤里的频分复用，按波长分
```

这一组里只写了缩写的，全称补在这里：

```text
SAP   Service Access Point              服务访问点，上下层的交接点
SNR   Signal-to-Noise Ratio             信噪比
FDM   Frequency Division Multiplexing   频分复用
TDM   Time Division Multiplexing        时分复用
CDM   Code Division Multiplexing        码分复用
WDM   Wavelength Division Multiplexing  波分复用
```

（后面每一组术语表后面都跟一张这样的小表，只展开缩略语，不加新内容。）

物理层的四个"极限与换算"必须能秒答：

```text
2W log2(V)          奈氏，无噪声，V 是码元种类
W log2(1 + S/N)     香农，有噪声，S/N 是功率比
dB = 10 log10(S/N)  30 dB = 1000，20 dB = 100，3 dB ≈ 2
1 Gbps = 10^9 b/s   链路速率一律十进制，别写成 1024
```

**这一类最容易错在哪**：把波特率当成比特率。波特率数的是每秒几个码元，比特率数的是每秒几个比特，一个码元携带 log2(V) 个比特，只有 V = 2 时两个数才相等。另一个高频错误是把 dB 直接当倍数用——30 dB 是 1000 倍，不是 30 倍。

## 2. 术语表（二）：数据链路层

链路层 14 条：

```text
组帧        framing           把比特流切成帧，重点是"哪里是边界"
差错控制    error control     检错（CRC、奇偶）或纠错（海明）
CRC         循环冗余校验       模 2 除法求余数，余数附在数据后面
海明码      Hamming code      多位校验位，能定位并纠正 1 位错
滑动窗口    sliding window    允许连续发送而不用等的范围
停等        stop-and-wait     窗口 = 1，发一个等一个
后退 N 帧   GBN               出错后从出错帧起全部重传
选择重传    SR                只重传出错的那一帧
介质访问    MAC               多个站点共用信道时"谁可以发"
CSMA/CD    载波监听多路访问/冲突检测   以太网用的，边发边听
CSMA/CA    冲突避免           无线用的，先约再发，避免撞上
冲突域      collision domain  会互相冲突的范围，交换机每个口一个
广播域      broadcast domain  一个广播帧能到达的范围，路由器每个口一个
交换机      switch            按 MAC 地址转发，分割冲突域
```

这一组的缩略语全称：

```text
CRC     Cyclic Redundancy Check                循环冗余校验
GBN     Go-Back-N                              后退 N 帧
SR      Selective Repeat                       选择重传
MAC     Medium Access Control                  介质访问控制（MAC 地址就是这一层的地址）
CSMA/CD Carrier Sense Multiple Access with Collision Detection   载波监听多路访问/冲突检测
CSMA/CA Carrier Sense Multiple Access with Collision Avoidance  载波监听多路访问/冲突避免
```

两个数要记牢：

```text
以太网帧 64 ~ 1518 B（不含前导码）
最小帧长 = 速率 × 2τ，这是 CSMA/CD 能检测冲突的前提
```

**这一类最容易错在哪**：把 GBN 和 SR 的窗口上限背反。记法不是硬背，是看接收窗口——GBN 的接收窗口只有 1，必须留一个序号去区分"新帧"和"重传帧"，所以上限是 2^n − 1；SR 的接收窗口大于 1，要用一半序号空间分新旧，所以上限是 2^(n−1)。

## 3. 术语表（三）：网络层

网络层 12 条：

```text
转发        forwarding        收到分组，查表，从某个口送出
路由        routing           算出这张表，靠路由协议
子网掩码    netmask           用 1 的个数区分网络号与主机号
CIDR        无类域间路由       用 /n 表示前缀长度，不再分 A/B/C 类
NAT         网络地址转换       私网地址 ↔ 公网地址，改写 IP 和端口
ARP         地址解析协议       IP 地址 → MAC 地址，广播问，单播答
DHCP        动态主机配置       自动下发 IP、掩码、网关、DNS
ICMP        互联网控制报文     差错报告（目的不可达）与探测（ping）
分片        fragmentation     超过 MTU 就切开，靠标识/偏移/标志重组
距离向量    distance vector   只跟邻居交换整张表，RIP 用
链路状态    link state        泛洪拓扑，各自跑 Dijkstra，OSPF 用
自治系统    AS                一个管理域，域内用 IGP，域间用 BGP
```

这一组的缩略语全称：

```text
CIDR  Classless Inter-Domain Routing       无类域间路由
NAT   Network Address Translation          网络地址转换
ARP   Address Resolution Protocol          地址解析协议
DHCP  Dynamic Host Configuration Protocol  动态主机配置协议
ICMP  Internet Control Message Protocol    互联网控制报文协议
AS    Autonomous System                    自治系统
IGP   Interior Gateway Protocol            域内网关协议
BGP   Border Gateway Protocol              域间网关协议
```

三个必算的量：

```text
可用主机数 = 2^(32 − 前缀) − 2
网络地址   = IP AND 掩码
广播地址   = 网络地址 + 2^(32 − 前缀) − 1
```

**这一类最容易错在哪**：把 ARP 和 ICMP 归错层。它们是网络层的配套协议——ARP 解决"同一个广播域里 IP 怎么换成 MAC"，ICMP 负责差错报告和探测（ping 用的就是它）；两者都封装在 IP 分组里，但它们不是传输层协议。

## 4. 术语表（四）：传输层与应用层

传输层 12 条：

```text
复用分用    multiplexing       用端口号把数据交给正确的进程
端口        port              16 位，0–65535，区分进程
UDP         用户数据报协议     无连接、不保证、首部 8 B
TCP         传输控制协议       面向连接、可靠、有序、首部 20 B 起
三次握手    three-way handshake  同步双方初始序号，确认双向可达
四次挥手    four-way close    两个方向各关一次，所以是四次
TIME_WAIT   时间等待状态       主动关闭方等 2MSL，保证最后的 ACK 能重传
拥塞窗口    cwnd              发送方估计的网络容量
接收窗口    rwnd              接收方缓冲区的余量
慢开始      slow start        cwnd 从 1 开始，每个 RTT 翻倍
快重传      fast retransmit   三个重复 ACK 立刻重传，不等超时
MSS         最大报文段长度     一个 TCP 段能带的最大数据字节数
```

这一组的缩略语全称：

```text
UDP   User Datagram Protocol         用户数据报协议
TCP   Transmission Control Protocol  传输控制协议
MSS   Maximum Segment Size           最大报文段长度
cwnd  congestion window              拥塞窗口
rwnd  receive window                 接收窗口
```

应用层 14 条：

```text
C/S         客户/服务器        服务器常驻等，客户端主动连
P2P         对等网络          每个节点既是客户端也是服务器
DNS         域名系统          域名 → IP，端口 53，主要用 UDP
递归查询    recursive query   对方负责给出最终答案（对方跑腿）
迭代查询    iterative query   对方只告诉你下一个该问谁（自己跑腿）
权威服务器  authoritative     真正存着某个区的记录
FTP         文件传输协议       控制 21 + 数据 20，两条连接
SMTP        简单邮件传输协议   发信，端口 25，只能推
POP3        邮局协议第 3 版    收信，端口 110，默认下载后删除
IMAP        互联网消息访问协议 收信，端口 143，服务器保留
MIME        多用途互联网邮件扩展  让 SMTP 能传非 ASCII，base64 编码
HTTP        超文本传输协议     端口 80，请求-响应，无状态
HTTPS       HTTP over TLS     端口 443，加密 + 证书认证
Cookie      客户端状态        服务器下发的小纸条，每次请求自动带上
```

这一组的缩略语全称：

```text
C/S   Client/Server                          客户/服务器
P2P   Peer-to-Peer                           对等网络
DNS   Domain Name System                     域名系统
FTP   File Transfer Protocol                 文件传输协议
SMTP  Simple Mail Transfer Protocol          简单邮件传输协议
POP3  Post Office Protocol version 3         邮局协议第 3 版
IMAP  Internet Message Access Protocol       互联网消息访问协议
MIME  Multipurpose Internet Mail Extensions  多用途互联网邮件扩展
HTTP  HyperText Transfer Protocol            超文本传输协议
HTTPS HTTP over TLS                          HTTP 跑在 TLS 上
```

应用层的端口，一张纸条就能写完：

```text
53  DNS        21/20  FTP 控制/数据     25  SMTP
110 POP3       143    IMAP              80  HTTP
443 HTTPS      67/68  DHCP              161 SNMP
22  SSH        23     Telnet
```

**这一类最容易错在哪**：把 HTTPS 说成"另一个协议"。它是 HTTP over TLS，报文格式和 HTTP 一模一样，只是外面套了一层加密；同理，SFTP 不是"加了密的 FTP"，而是另一套协议。第二个高频错误是把 POP3 与 IMAP 的端口记反——110 是 POP3，143 是 IMAP。

一个提醒：清单里的"路由器结构"和"IP 组播"是低频考点，看一遍有个印象就行，别花太多时间。

高频的是子网、路由、TCP 三件套、应用层端口，加起来能占网络部分的大半。

这两份索引合起来，就是一张"从考点跳到篇目"的反向目录。

复习时的用法：拿真题对一遍，错哪条查哪篇，比从头重读快十倍。

体检表的正确打开方式，是"先做题，再对表"。

不要一上来就看表——表是查漏的，不是学习材料。

做一套真题，把错的题标上考点，然后按考点跳到篇号，重读那一篇的第 6 节。

一晚上能补完三四个漏点，比从头翻一遍六章有用。

清单里那些"看一遍就行"的条目，也别真的跳过。

路由器结构里的"输入端口 → 交换结构 → 输出端口"，IP 组播里的"IGMP 加组"，都是选择题的边角料，认识就能拿分。

**这一类最容易错在哪**：把索引当学习材料，从头读表。这样读到的是一个一个名词，既记不住也串不起来；正确顺序是先做题、再对表，让错题决定你翻哪一行。

还有一个小坑：同一条考点常常挂着两个篇号（比如 CSMA/CD 在 08 和 09，以太网在 09 和 11），顿号分开的两个号不是"选一个读"，而是一个讲原理、一个讲考法。

## 7. 公式速查

抄一遍，比看十遍有用。

抄的时候别只抄公式，把"单位"和"适用条件"一起抄。

比如 `W ≥ (Td + RTT) / Td`，抄的时候在旁边写一句"结果是帧数，要向上取整"。

再比如 `2^k ≥ m + k + 1`，旁边写"右边那个 1 是'没有错'这种情况"。

一页纸抄完，考前一天再抄一遍，两次的差异就是你的漏洞。

**时延与利用率**

```text
发送时延   Td = L(bit) / R(b/s)
传播时延   Tp = 距离 / 传播速度      （光纤约 2×10^8 m/s）
总时延     Td + Tp + 处理 + 排队
RTT        2 × Tp（题目不说排队和处理）
时延带宽积 Tp × R                   （链路上"在途"的比特数）

停等        U = Td / (Td + RTT)
发 N 帧     U = N·Td / (N·Td + RTT)
满负荷窗口  W ≥ (Td + RTT) / Td
```

**极限速率与换算**

```text
奈氏        C = 2W log2(V)           （无噪声，V 是码元种类）
香农        C = W log2(1 + S/N)      （有噪声）
dB          S/N = 10^(dB/10)         （30 dB = 1000）
比特率      Rb = 波特率 × log2(V)
```

**差错控制**

```text
CRC 余数位数  r = 生成多项式的最高次
CRC 编码      数据补 r 个 0，模 2 除，余数附在后面
海明码位数    2^k ≥ m + k + 1        （m 信息位，k 校验位）
海明检错      各组校验和相加 = 出错位的位置
```

**滑动窗口与以太网**

```text
GBN 窗口上限  2^n − 1
SR  窗口上限  2^(n−1)
最小帧长      Lmin = R × 2τ
最大距离      d = (Lmin / R) / 2 × v
退避          第 i 次冲突取 k ∈ {0, …, 2^i − 1}，等 k × 2τ
```

**地址与子网**

```text
子网大小      2^(32 − 前缀)
可用主机数    2^(32 − 前缀) − 2
网络地址      IP AND 掩码
广播地址      网络地址 + 子网大小 − 1
聚合前缀      32 − log2(块大小)
```

**传输层与应用层**

```text
确认号        ack = 对方 seq + 数据长度（SYN/FIN 各占 1）
发送窗口      min(cwnd, rwnd)
慢开始        cwnd 每个 RTT 翻倍
拥塞避免      cwnd 每个 RTT + 1
超时          ssthresh = cwnd/2，cwnd = 1
三个重复 ACK  ssthresh = cwnd/2，cwnd = ssthresh
MIME 膨胀     base64 后 ≈ 原大小 × 4/3
DNS 报文      无缓存迭代解析 8 个（4 问 4 答）
```

**这一类最容易错在哪**：只抄公式，不抄单位。同一行公式，单位配错就差 8 倍（b 与 B）或者 1000 倍（s 与 ms）。抄的时候把"结果是帧数，要向上取整""右边那个 1 是'没有错'这种情况"这类附注一起抄下来，这张纸才有用。

## 8. 20 组最容易混的概念（上）

> **反直觉的点**：这份附录最值钱的不是术语表，是这 20 组对照。408 选择题的失分，八成发生在这 20 组里。

为什么是这 20 组？

因为它们都是"两个词长得像、位置相邻、但答案相反"的组合。

背术语表只能让你"认识"它们，只有并排对照才能让你"分得清"。

前十组：

```text
① 协议 与 服务
   协议：水平的，对等层之间的规则
   服务：垂直的，下层给上层的能力
   混淆点：说"TCP 提供可靠服务"是对的，说"TCP 协议是服务"是错的

② OSI 七层 与 TCP/IP 四层
   OSI：物理、数据链路、网络、传输、会话、表示、应用
   TCP/IP：网络接口、网际、传输、应用
   对应关系：OSI 的上三层 → TCP/IP 的应用层
   混淆点：TCP/IP 没有会话层和表示层，这两件事被并入应用层

③ 发送时延 与 传播时延
   发送时延 = 长度 / 速率，跟"帧多大、链路多快"有关
   传播时延 = 距离 / 速度，跟"线多长、光多快"有关
   混淆点：题目给"1000 km"，用的是传播；给"1000 B"，用的是发送

④ 带宽 与 吞吐量
   带宽：链路的理论最大速率，是"能力"
   吞吐量：实际测到的速率，是"结果"
   混淆点：带宽 1 Gbps，吞吐 938 Mbps，利用率 93.8%，三个数不是一回事

⑤ CSMA/CD 与 CSMA/CA
   CD：有线，边发边听，撞了立刻停、随机退避重传
   CA：无线，先听、随机退避，用 ACK 确认，可选 RTS/CTS 预约
   混淆点：无线不用 CD 是因为"发送时听不到别人"，不是因为"无线更快"

⑥ 冲突域 与 广播域
   冲突域：会互相冲突的范围，交换机每个口一个
   广播域：一个广播帧能到的范围，路由器每个口一个
   混淆点：交换机分割冲突域，不分割广播域；VLAN 才分割广播域

⑦ 集线器、交换机、路由器
   集线器：一层，物理上放大信号，所有口一个冲突域
   交换机：二层，按 MAC 转发，每口一个冲突域
   路由器：三层，按 IP 转发，每口一个广播域
   混淆点：交换机不隔离广播，路由器才隔离

⑧ GBN 与 SR
   GBN：接收窗口 1，出错后从出错帧起重传全部，窗口 ≤ 2^n − 1
   SR ：接收窗口 > 1，只重传出错帧，窗口 ≤ 2^(n−1)
   混淆点：两个上限差一个指数，n = 3 时是 7 和 4

⑨ 子网 与 超网
   子网：从前缀往长里划，借主机位当网络位
   超网：从前缀往短里合，把多个网段合成一个（CIDR 聚合）
   混淆点：子网掩码变长，超网掩码变短

⑩ ARP 与 DNS
   ARP：IP → MAC，同一广播域内，用广播问
   DNS：域名 → IP，跨网络，用 UDP 53 问
   混淆点：ARP 是网络层的配套协议，不是链路层；DNS 是应用层
```

## 9. 20 组最容易混的概念（下）

后十组：

```text
⑪ IPv4 与 IPv6
   IPv4：32 位，首部 20 B 起，有首部校验和，有分片
   IPv6：128 位，首部固定 40 B，取消首部校验和，分片由源端做
   混淆点：IPv6 没有广播，用组播和任播替代

⑫ TCP 与 UDP
   TCP：面向连接、可靠、有序、首部 20 B 起、有流量和拥塞控制
   UDP：无连接、不保证、首部 8 B、想快就用它
   混淆点：UDP 不是"不可靠的 TCP"，它是另一套取舍

⑬ 流量控制 与 拥塞控制
   流量控制：别把接收方淹了，看 rwnd（接收方缓冲）
   拥塞控制：别把网络淹了，看 cwnd（网络容量）
   混淆点：发送窗口 = min(cwnd, rwnd)，两个都要看

⑭ 三次握手 与 四次挥手
   三次：SYN、SYN+ACK、ACK，为了同步双方序号
   四次：FIN、ACK、FIN、ACK，因为 TCP 是全双工，两个方向各关一次
   混淆点：挥手能变成三次（ACK 与 FIN 合并），握手不能变两次

⑮ TIME_WAIT 与 CLOSE_WAIT
   TIME_WAIT：主动关闭方，等 2MSL，保证最后的 ACK 能重传
   CLOSE_WAIT：被动关闭方，收到 FIN 但应用还没 close
   混淆点：TIME_WAIT 多是正常现象，CLOSE_WAIT 堆积是代码 bug

⑯ HTTP 与 HTTPS
   HTTP：80，明文，无状态
   HTTPS：443，HTTP over TLS，加密 + 证书认证
   混淆点：HTTPS 不是新协议，报文格式和 HTTP 一样，只是套了 TLS

⑰ FTP 主动模式 与 被动模式
   主动 PORT：服务器从 20 端口连客户端（客户端在 NAT 后会失败）
   被动 PASV：客户端连服务器随机端口（容易穿 NAT）
   混淆点："数据连接用 20 端口"只在主动模式成立

⑱ 递归查询 与 迭代查询
   递归：对方负责给最终答案（对方跑腿）
   迭代：对方只给"下一个问谁"（自己跑腿）
   混淆点：说的是谁跑腿，不是报文数；两种方式都是 8 个报文

⑲ POP3 与 IMAP
   POP3：110，下载后删除，状态在客户端
   IMAP：143，服务器保留，状态在服务器，多设备同步
   混淆点：一句话记法——POP3 是"取走"，IMAP 是"遥控"

⑳ 单播、组播、广播
   单播：一对一
   组播：一对多（一组），D 类地址 224.0.0.0/4
   广播：一对全部，只在本广播域内
   混淆点：IPv6 没有广播；组播要 IGMP 加组，不是"发出去就有人收"
```

二十组过完，回头再看一遍第 1 到第 4 节的术语表，会发现一大半的概念都在里面出现过。

术语表告诉你"它是什么"，这二十组告诉你"它不是什么"。

选择题考的恰恰是后者。

**这一类最容易错在哪**：只记住"两个词不一样"，没记住"不一样在哪一步"。"发送时延与传播时延"的真正分歧点是"跟长度有关还是跟距离有关"；"递归与迭代"的真正分歧点是"谁跑腿"。抓不住那一个分歧点，考场上题干换个说法，又混回去了。

## 12. 收尾

25 篇，到这里结束。

回头看一眼第 00 篇那张地图：

```text
应用层  给人用的          21、22
传输层  进程到进程        17、18、19、20
网络层  主机到主机        12、13、14、15、16
链路层  一跳之内          05、06、07、08、09、10、11
物理层  比特到信号        03、04
```

每一层都至少有一篇讲模型，有一篇讲考法。

第 00 篇说，学网络最容易犯的错是"背了一堆协议，但不知道它们在一次通信里各管哪一段"。

25 篇下来，这句话应该已经不成立了。

你现在应该能做的，是这一件事：

```text
看到任何一个网络现象，
先问它在哪一层，
再问这一层用什么单位，
最后问这一层的协议在这里负责什么。
```

三个问题问完，答案基本就出来了。

最后一次说那个贯穿全系列的方法：

```text
先说人话，再画帧格式，
最后回到 408 的考法，
和一台真实主机上会发生什么。
```

408 的网络部分不难，它只是要求你在四个地方不出错：单位、对象、边界、方向。

单位是 b 还是 B，对象是发送还是传播，边界在哪一层，方向是谁主动。

这四件事不出错，分就稳了。

全书完。
