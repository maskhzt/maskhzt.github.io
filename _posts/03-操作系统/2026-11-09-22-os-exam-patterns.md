考场最后二十分钟。

一道地址转换题：页面大小 4 KB，32 位地址，两级页表，页表项 4 B。

问：访问虚拟地址 `0x00403A2C`，物理地址是多少？

你知道该拆页号，也知道该查表。

但你在草稿纸上写下 `0x403`，然后犹豫了一下：

"这个 `0x403` 是页号，还是页框号？"

```text
它不是知识点总结——知识点在 01 到 21 篇里
```

为什么需要这张表？

## 3. 题型 1–2：地址转换与页表大小

### 3.1 题型 1：地址转换

**识别信号。**

```text
给出：页面大小、虚拟地址（十六进制）、页表（可能多级）
求：物理地址，或某个页表项的内容
```

**解题步骤。**

```text
① 由页大小算偏移位数 n：4 KB = 2^12 → n = 12
② 虚拟地址右移 n 位 → 页号；低 n 位 → 偏移
③ 多级页表：把页号按"每级页号位数"从高位往低位拆
④ 逐级查表，最后拿到页框号
⑤ 物理地址 = 页框号 × 页大小 + 偏移（等价于页框号 << n | 偏移）
```

**例题。**

> 页面大小 4 KB，32 位地址，页表项 4 B，采用两级页表。
> 已知一级页表第 1 项指向的二级页表在页框 0x2000，
> 该二级页表第 3 项内容为 0x1A2。
> 求虚拟地址 0x00403A2C 对应的物理地址。

解。

```text
页大小 4 KB = 2^12 → 偏移 12 位，页号 20 位
页表项 4 B，一页能放 4 KB / 4 B = 1024 项
→ 每级页号 10 位，两级正好 20 位

0x00403A2C = 0000 0000 0100 0000 0011 1010 0010 1100
              高位 10 位       次 10 位      低 12 位
一级页号 = 1
二级页号 = 3
偏移     = 0xA2C

查表：一级[1] → 二级页表在页框 0x2000
      二级[3] = 0x1A2   ← 这是页框号

物理地址 = 0x1A2 × 0x1000 + 0xA2C
         = 0x1A2000 + 0xA2C
         = 0x1A2A2C
```

验算一遍页号拆分。

```text
0x403A2C >> 12 = 0x403 = 1027
1027 / 1024 = 1 余 3  → 一级页号 1，二级页号 3 ✓
```

如果题目给的是段页式，多一步拆分。

```text
逻辑地址 = 段号 s + 段内偏移 d
段表项 → 该段的页表基址 + 段长
段内偏移 d 再拆成：页号 p + 页内偏移 w
查页表 → 页框号 → 物理地址 = 页框号 × 页大小 + w

注意：段长检查要用 d，不是 p
     越界检查在段这一级做，页这一级只做映射
```

段页式的题，最容易错的是"两次查表"漏了一次。

```text
段表查一次 → 拿到页表基址
页表查一次 → 拿到页框号
两次内存访问只是查表，取数据还要第三次
```

所以段页式一次访存，最坏要 3 次内存访问。

TLB 里存的通常是"段号 + 页号 → 页框号"的合成项，一次命中就能省掉两次。

**易错点。**

```text
① 把页号当页框号：页号是"第几页"，页框号是"内存第几块"，两者不是一个东西
② 忘记页框号要乘页大小：0x1A2 直接加偏移就错了
③ 十六进制移位时数错位：4 KB 是移 12 位，不是 10 位
④ 多级页表从低位开始拆：必须从高位开始，一级页号在高位
⑤ 段页式只查了段表，忘了段内还要查页表
```

### 3.2 题型 2：页表大小与多级页表

**识别信号。**

```text
"该进程的页表占多少空间"
"需要几级页表"
"页表项有多少个"
```

**解题步骤。**

```text
① 页表项数 = 2^(虚拟地址位数 − 偏移位数)
② 页表大小 = 项数 × 每项字节数
③ 每页能放几项 = 页大小 / 每项字节数
④ 每级页号位数 = log2(每页项数)
⑤ 级数 = 页号总位数 / 每级位数（向上取整）
```

**例题。**

> 32 位虚拟地址，页大小 4 KB，页表项 4 B。
> 求：单级页表大小；若采用两级页表，页号怎么拆？
> 若某进程只使用了低 4 MB 地址空间，两级页表实际占用多少？

解。

```text
页号位数 = 32 − 12 = 20 位
页表项数 = 2^20 = 1,048,576
单级页表大小 = 1,048,576 × 4 B = 4,194,304 B = 4 MB

每页放 4 KB / 4 B = 1024 项 → 每级 10 位
两级：10 + 10 = 20 ✓

只用低 4 MB：页号范围 0 ~ 1023，全部落在同一个二级页表里
= 1 个页目录（4 KB）+ 1 个二级页表（4 KB）= 8 KB
```

注意 4 MB 和 8 KB 的对比。

**这就是多级页表存在的唯一理由：稀疏。**

如果地址空间全用满，两级页表总大小是 4 MB + 4 KB，比单级还多一点。

只有当进程只用了很小一片地址空间时，多级页表才省。

再看 64 位的情况，体会一下量级。

```text
48 位虚拟地址，页大小 4 KB，页表项 8 B
页号位数 = 36，项数 = 2^36 ≈ 687 亿
单级页表大小 = 2^36 × 8 B = 512 GB   ← 一个进程的页表比内存还大

每页放 4 KB / 8 B = 512 项 → 每级 9 位
级数 = 36 / 9 = 4 级
```

**易错点。**

```text
① 把"页表项数"当成"页表大小"（差了 4 倍）
② 忘了页目录本身也占一页
③ 稀疏地址空间按全满算，多算几个数量级
④ 页表项 8 B 时每页只能放 512 项，别还按 1024 算
```

## 4. 题型 3–4：EAT 与页面置换

### 4.1 题型 3：有效访问时间 EAT

**识别信号。**

```text
给出 TLB 命中率 / 缺页率，给出各级访问时间
求："平均访问时间""有效访问时间"
```

**解题步骤。**

```text
① 先画两条路径：TLB 命中、TLB 未命中
② 命中 = TLB 时间 + 一次内存
③ 未命中 = TLB 时间 + 一次页表访问 + 一次内存（多级就多几次）
④ EAT = 命中率 × 命中路径 + (1 − 命中率) × 未命中路径
⑤ 有缺页率 p：EAT = 上式 + p × 缺页处理时间
```

**例题。**

> TLB 访问时间 10 ns，内存访问时间 100 ns，TLB 命中率 90%。
> 求不考虑缺页时的 EAT。
> 若缺页率 10^-4，缺页处理时间 10 ms，再求 EAT。

解。

```text
命中路径：10 + 100 = 110 ns
未命中路径：10 + 100（查页表）+ 100（取数据）= 210 ns

EAT = 0.9 × 110 + 0.1 × 210
    = 99 + 21
    = 120 ns

加缺页：
缺页代价 = 10^-4 × 10 ms
        = 10^-4 × 10,000,000 ns
        = 1,000 ns

EAT = 120 + 1,000 = 1120 ns
```

看这个结果。

**缺页率只有万分之一，EAT 却翻了 9 倍。**

1120 ns 里，正常访问只占 120 ns，缺页占了 1000 ns。

这就是"缺页代价极高"的量化版本。

**易错点。**

```text
① 未命中路径只算一次内存（忘了查页表那一次）
② 缺页处理时间的单位：10 ms = 10^7 ns，不是 10^6
③ 把缺页率和命中率混用（TLB 命中率 ≠ 不缺页率）
④ 多级页表时忘了每级都要访问一次内存
```

### 4.2 题型 4：页面置换

**识别信号。**

```text
给引用串、页框数，问"缺页次数"
或问"哪种算法缺页最少""是否存在 Belady 异常"
```

**解题步骤。**

```text
① 把引用串抄成一行，一列一个引用
② 每列画 n 个小格子，写当前页框内容
③ 命中：格子不动（LRU 要更新"最近使用"）
④ 缺页：按算法选牺牲页，替换，计数 +1
⑤ 数完统计缺页次数
```

**例题。**

> 页框数 3，引用串：7 0 1 2 0 3 0 4 2 3 0 3 2 1 2 0 1 7 0 1。
> 求 FIFO、LRU、CLOCK、OPT 的缺页次数。

结果。

```text
FIFO  = 15 次
LRU   = 12 次
CLOCK = 14 次
OPT   =  9 次
```

这个串值得背下来，因为它是 408 最爱用的那一串。

四个数的相对关系也有意义。

```text
OPT（9） < LRU（12） < CLOCK（14） < FIFO（15）
```

CLOCK 是 LRU 的近似，所以夹在中间。

OPT 是理论下界，不能实现，只用来比较。

顺手验证一下 Belady 异常。

```text
引用串：1 2 3 4 1 2 5 1 2 3 4 5
FIFO，3 个页框 → 9 次缺页
FIFO，4 个页框 → 10 次缺页
```

页框多了，缺页反而多了。

这就是 Belady 异常，只有 FIFO 这类"不看历史"的算法会有。

LRU 和 OPT 属于"栈式算法"，不会出现。

再补一个改进型 CLOCK 的考点（也常出现）。

```text
改进 CLOCK：每个页框有两个位，访问位 A 和修改位 M
淘汰顺序（优先级从高到低）：
  A=0, M=0   最近没访问，也没改过     ← 最优牺牲者，不用写回
  A=0, M=1   没访问，但改过           ← 要写回磁盘
  A=1, M=0   访问过，没改             ← 第一轮扫描时把 A 清 0
  A=1, M=1   访问过，也改过           ← 最差
```

改进的地方就一句话：**优先淘汰"干净"的页，省一次写回。**

**易错点。**

```text
① 缺页次数 ≠ 置换次数：前 n 次是"装入"，置换次数 = 缺页次数 − n
② 命中时 LRU 必须更新最近使用时间，忘了就退化成 FIFO
③ CLOCK 的指针只前进不后退，替换后从下一格继续
④ FIFO 的队列在命中时不移动（这是它和 LRU 的关键区别）
```

## 5. 题型 5–7：调度、银行家、PV

### 5.1 题型 5：调度指标

**识别信号。**

```text
给到达时间、运行时间，问"平均周转时间""带权周转""画甘特图"
```

**解题步骤。**

```text
① 画时间轴，按算法排顺序
② 每个进程的完成时间
③ 周转时间 = 完成时间 − 到达时间
④ 带权周转 = 周转时间 / 运行时间
⑤ 平均值 = 总和 / 进程数
```

**例题。**

> 四个进程：

```text
进程   到达时间   运行时间
P1        0          8
P2        1          4
P3        2          2
P4        5          1
```

> 求 FCFS、SJF（非抢占）、RR（时间片 2）的平均周转时间和平均带权周转时间。

解。

```text
FCFS：
  P1 0–8   P2 8–12   P3 12–14   P4 14–15
  周转：8, 11, 12, 10   和 = 41   平均 = 10.25
  带权：1, 2.75, 6, 10  和 = 19.75 平均 ≈ 4.94

SJF（非抢占）：
  t=0 只有 P1，跑完 0–8
  t=8 剩 P2(4) P3(2) P4(1) → P4 8–9, P3 9–11, P2 11–15
  周转：8, 14, 9, 4     和 = 35   平均 = 8.75
  带权：1, 3.5, 4.5, 4  和 = 13   平均 = 3.25

RR（q=2）：
  P1 0–2 | P2 2–4 | P3 4–6 | P1 6–8 | P2 8–10 | P4 10–11 | P1 11–13 | P1 13–15
  完成：P1 15, P2 10, P3 6, P4 11
  周转：15, 9, 4, 6      和 = 34   平均 = 8.5
  带权：1.875, 2.25, 2, 6  和 = 12.125  平均 ≈ 3.03
```

三个结果放在一起，有个反直觉的地方。

**RR 的平均周转（8.5）比 SJF（8.75）还好一点。**

为什么？

因为 P1 太长，非抢占 SJF 在 t=0 只能选它，一占就是 8 个单位。

RR 让 P3、P2 先做完，短作业的周转被压下来了。

SJF 的"最优"是有前提的：**同时到达**。

到达时间一乱，非抢占 SJF 就可能被别的算法超过。

**易错点。**

```text
① "平均周转"和"平均带权周转"是两个答案，别只写一个
② 带权的分母是运行时间，不是周转时间
③ 同时到达时，SJF 退化成"按运行时间排序"，和到达顺序无关
④ RR 里新到进程与时间片到期的顺序：一般新到的先进队列，再放回被抢占的
⑤ 等待时间 = 周转时间 − 运行时间，别和周转混
⑥ MLFQ 的题要画"队列层级"，每级时间片递增，降级规则写清楚
```

多提一句 MLFQ（多级反馈队列）。

它不常出现在计算题里，但常出现在"给场景选算法"里。

```text
识别信号：既要响应快，又要照顾长作业，还要不饿死
三个要点：队列数、每级时间片、降级与升级规则
为什么不会饿死：高优先级队列空了，低优先级的才能跑；
                有的实现会定期把低优先级的提到高优先级
```

408 考 MLFQ 基本只考"它的设计意图"，不考具体的调度顺序。

真要算，就按"逐级降级 + 队列内 RR"老老实实画时间轴。

### 5.2 题型 6：银行家算法

**识别信号。**

```text
给 Max / Allocation / Available 三张表
问"是否存在安全序列""该请求能否满足"
```

**解题步骤。**

```text
① Need = Max − Allocation
② Work = Available，所有进程 Finish = false
③ 找一个 Need ≤ Work 且未完成的进程
④ 假定它完成：Work = Work + Allocation，Finish = true
⑤ 重复直到找不到；全都完成则安全
⑥ 请求题：先查 Request ≤ Need 且 Request ≤ Available，
   试分配后重做一遍安全性检查，不安全就回滚
```

**例题。**

```text
进程   Max        Allocation   Need
      A  B  C     A  B  C     A  B  C
P0    7  5  3     0  1  0     7  4  3
P1    3  2  2     2  0  0     1  2  2
P2    9  0  2     3  0  2     6  0  0
P3    2  2  2     2  1  1     0  1  1
P4    4  3  3     0  0  2     4  3  1

Available = (3, 3, 2)
```

解安全序列。

```text
Work = (3,3,2)
P1 Need (1,2,2) ≤ Work ✓ → Work = (3,3,2)+(2,0,0) = (5,3,2)
P3 Need (0,1,1) ≤ Work ✓ → Work = (7,4,3)
P4 Need (4,3,1) ≤ Work ✓ → Work = (7,4,5)
P0 Need (7,4,3) ≤ Work ✓ → Work = (7,5,5)
P2 Need (6,0,0) ≤ Work ✓ → Work = (10,5,7)

安全序列：P1 → P3 → P4 → P0 → P2
```

再问：P1 请求 (1,0,2)，能否满足？

```text
检查：Request (1,0,2) ≤ Need (1,2,2) ✓
      Request (1,0,2) ≤ Available (3,3,2) ✓

试分配：
  Available = (3,3,2) − (1,0,2) = (2,3,0)
  P1 Allocation = (3,0,2)，Need = (0,2,0)

安全性检查：
  Work = (2,3,0)
  P1 Need (0,2,0) ≤ Work ✓ → Work = (5,3,2)
  P3 → (7,4,3)   P4 → (7,4,5)   P0 → (7,5,5)   P2 → (10,5,7)

仍然安全 → 可以满足
```

**易错点。**

```text
① 只查 Request ≤ Available，忘了 Request ≤ Need
② 试分配后忘了回滚（不安全时要恢复原状）
③ 安全序列不唯一，写出一组就行，但要能验证
④ Work 更新是加 Allocation，不是加 Need
```

### 5.3 题型 7：PV 操作

**识别信号。**

```text
前趋图、缓冲区、生产者消费者、读者写者
"用信号量实现同步""找出程序中的错误"
```

**解题步骤。**

```text
① 数约束边：有几条"必须先后"的边，就有几个同步信号量
② 每条边一个信号量，初值 0
③ 边的起点 V，终点 P
④ 互斥信号量初值 1，只包住临界区
⑤ 检查：P 在前 V 在后 → 初值必须是 0；否则会死锁
```

**例题。**

> 前趋图：S1 → S2，S1 → S3，S2 → S4，S3 → S4。
> 用 PV 操作实现。

解。四条边，四个信号量。

```c
semaphore a = 0, b = 0, c = 0, d = 0;

S1() { 执行 S1;  V(a); V(b); }
S2() { P(a); 执行 S2; V(c); }
S3() { P(b); 执行 S3; V(d); }
S4() { P(c); P(d); 执行 S4; }
```

验证一下。

```text
S2 要等 S1 → P(a) 卡住，S1 做完 V(a) 才放行 ✓
S3 要等 S1 → P(b) ✓
S4 要等 S2 和 S3 → P(c) 和 P(d)，两个都必须 V 过 ✓
初值全 0 → 没有任何进程能抢跑 ✓
```

还有一类"找错"题，给一段有 bug 的 PV 代码，让你改。

按这五步查，基本都能查出来。

```text
① 信号量初值对不对：该 0 的写成 1，或该 1 的写成 0
② P/V 是不是配对的：有几个 P 就该有几个 V
③ 顺序对不对：互斥的 P 必须在同步的 P 之后
④ 临界区范围对不对：包太大效率低，包太小会漏
⑤ 有没有可能死锁：两个进程以相反顺序申请同一组资源
```

第 ③ 步最常考。

```text
错：P(mutex); P(empty);
对：P(empty); P(mutex);

因为先拿锁再等缓冲区，缓冲区满时锁还攥在手里，
生产者进不来，消费者也进不来（它要先拿锁才能取），直接死锁。
```

**易错点。**

```text
① 信号量初值写成 1：那么 P 直接通过，前趋关系失效
② P/V 写反：起点写成 P，终点写成 V，直接死锁
③ 互斥信号量包太大，把整个函数包进去 → 退化成串行
④ 前趋图的边数数错：漏一条就漏一个信号量
⑤ 读者写者里忘记给 count 加互斥，两个读者同时 count++ 会丢
```

## 6. 408 怎么考

408 卷面 150 分，四科分摊。

操作系统这一块，大致是这个形状。

```text
选择题：约 10 题，每题 2 分，共 20 分上下
综合题：1 ~ 2 道，15 ~ 20 分
合计：约 35 分
```

具体分值每年会浮动，但结构稳定。

**选择题的四种问法。**

```text
① 概念辨析：给四个说法，选正确/错误的
   → 靠 23 篇那 20 组对照，不靠计算

② 算一个数：地址、页表大小、缺页次数、寻道距离
   → 靠这一篇的十类套路，通常 1 ~ 2 分钟一题

③ 判断过程：某一步 CPU 参不参与、某个中断谁处理
   → 靠 20/21 篇的流程图

④ 选算法：给定场景选调度算法/置换算法/磁盘算法
   → 靠"算法特性 + 场景关键词"配对
```

**综合题的三种组合。**

```text
组合一：PV 操作 + 前趋图（最高频）
组合二：地址转换 + 页表 + 缺页
组合三：文件系统（inode / 分配 / 位示图）或磁盘调度
```

偶尔会把调度和死锁放在一道题里。

读完题先判断它属于哪个组合，再决定先做哪问。

**判分点在哪。**

```text
① 有过程分：写出公式、列出表格、画出时间轴，即使最后答案错也能拿分
② 有步骤分：PV 题写对信号量初值就有分
③ 有单位分：答案不带单位，有的年份会扣
```

所以考场上有一条铁律：

**宁可多写一行推导，不要只写一个数。**

## 7. 真实系统里长什么样

这十类题，每一类在真实系统里都有对应物。

知道对应物，公式就不容易记错。

```text
题型 1 地址转换   → x86-64 的四级页表：PML4 → PDPT → PD → PT，9/9/9/9/12
题型 2 页表大小   → 大页（2 MB / 1 GB）就是为了砍掉级数、减轻 TLB 压力
题型 3 EAT        → perf stat 里的 dTLB-load-misses；/proc/vmstat 里的 pgmajfault
题型 4 页面置换   → Linux 的"双链 LRU"：active 链和 inactive 链，LRU 的近似
题型 5 调度       → CFS 用 vruntime 排序，不是 RR；SCHED_RR 仍留给实时任务
题型 6 银行家     → 现实中几乎不用，因为要预知 Max；实际靠配额 + OOM killer
题型 7 PV         → 内核里的 spinlock、mutex、completion，都是信号量的变体
题型 8 磁盘       → blk-mq 的调度器；iostat 里的 await 就是"排队 + 服务"时间
题型 9 文件       → ext4 的 inode + extent；df -i 看 inode 用量
题型 10 I/O 时间  → iostat 的 %util；sar 的 tps 和 await
```

举两个能立刻验证的例子。

**页表级数。**

```text
$ cat /proc/cpuinfo | grep "address sizes"
address sizes   : 39 bits physical, 48 bits virtual
```

48 位虚拟地址，4 级页表，每级 9 位，最后 12 位偏移。

9 × 4 + 12 = 48，正好。

**缺页的两种。**

```text
$ grep -E "pgfault|pgmajfault" /proc/vmstat
pgfault 1234567
pgmajfault 89
```

`pgfault` 是次要缺页（页在内存里，只是没建立映射）。

`pgmajfault` 是主要缺页（要去磁盘读）。

EAT 公式里那个"缺页处理 10 ms"，对应的就是 `pgmajfault`。

**磁盘调度。**

```text
$ cat /sys/block/sda/queue/scheduler
[mq-deadline] kyber bfq none
```

`mq-deadline` 会排序，因为机械盘要减少寻道。

NVMe 上默认是 `none`，因为没有磁头。

这正好呼应 19 篇：**算法是为硬件特性服务的，硬件变了，算法就退休。**

## 8. 题型 8–10：磁盘、文件、I/O 时间

### 8.1 题型 8：磁盘调度

**识别信号。**

```text
给磁道号序列、当前磁头位置（可能给移动方向）
问"移动顺序""总寻道距离"
```

**解题步骤。**

```text
① 把磁道号画在数轴上，标出当前位置
② 按算法决定访问顺序
③ 逐段相加绝对差
④ SCAN/C-SCAN 注意是否走到端点（0 或最大磁道）
⑤ LOOK/C-LOOK 只走到最远的请求
```

**例题。**

> 磁头当前在 53，磁道范围 0 ~ 199，请求序列：
> 98, 183, 37, 122, 14, 124, 65, 67。
> 求 FCFS、SSTF、SCAN（向大）、C-SCAN（向大）、LOOK（向大）、C-LOOK（向大）的总寻道距离。

解。

```text
FCFS：53→98→183→37→122→14→124→65→67
      45+85+146+85+108+110+59+2 = 640

SSTF：53→65→67→37→14→98→122→124→183
      12+2+30+23+84+24+2+59 = 236

SCAN（先到 199，再折回）：
      53→65→67→98→122→124→183→199→37→14
      (199−53) + (199−14) = 146 + 185 = 331

C-SCAN（到 199 后回到 0，再从 0 向大扫到最远的请求 37）：
      53→65→67→98→122→124→183→199→0→14→37
      (199−53) + (199−0) + (37−0) = 146 + 199 + 37 = 382

LOOK（只到 183，再折回）：
      (183−53) + (183−14) = 130 + 169 = 299

C-LOOK（到 183，回到最小请求 14，再向大）：
      (183−53) + (183−14) + (37−14) = 130 + 169 + 23 = 322
```

一句话记住 SCAN 和 LOOK 的差别。

```text
SCAN 走到端点（0 或 199）
LOOK 只走到最远的那个请求
所以 LOOK 总是比 SCAN 少走一段"空跑"
```

有时题目不直接给寻道距离，而是问"访问时间"。

这时要把三段加起来。

```text
访问时间 = 寻道时间 + 平均旋转延迟 + 传输时间
平均旋转延迟 = 半圈时间 = 60 / (2 × 转速) 秒
传输时间 = 数据量 / 传输率
```

举个具体的数。

```text
转速 7200 r/min → 一圈 = 60 / 7200 s = 8.33 ms
平均旋转延迟 = 8.33 / 2 ≈ 4.17 ms
```

注意"平均"两个字。

不是等一整圈，是等半圈。

因为磁头停在哪个扇区是随机的，平均要转半圈才能等到目标扇区到磁头下。

**易错点。**

```text
① 忘了题目给的初始方向，SCAN 的答案会完全不同
② SCAN 走到端点 vs LOOK 只到最远请求，两者差一段
③ C-SCAN 的回程要不要算距离：算，回程也是磁头在动
④ 只求和，忘了题目可能问"平均寻道距离"（除以请求数）
```

### 8.2 题型 9：文件系统计算

**识别信号。**

```text
inode 里有 n 个直接指针、m 个间接指针
给块大小、指针大小，问"最大文件多大""访问某块要几次 I/O"
或给磁盘容量，问位示图多大
```

**解题步骤。**

```text
① 每块能放几个指针 = 块大小 / 指针大小
② 直接寻址容量 = 直接指针数 × 块大小
③ 一级间接 = 指针数 × 块大小
④ 二级间接 = 指针数² × 块大小
⑤ 访问次数 = 经过的索引块层数 + 1（数据块本身）
⑥ 位示图大小 = 总块数 / 8 字节
```

**例题。**

> 某文件系统 inode 含 12 个直接指针、1 个一级间接、1 个二级间接。
> 块大小 4 KB，指针 4 B。求最大文件大小。

解。

```text
每块指针数 = 4096 / 4 = 1024

直接：12 × 4 KB = 48 KB
一级间接：1024 × 4 KB = 4 MB
二级间接：1024 × 1024 × 4 KB = 4 GB

最大 = 48 KB + 4 MB + 4 GB
     = 4,299,210,752 B
     ≈ 4.004 GB
```

再问两个。

```text
问：访问文件中的第 5 GB 处的一个字节，需要几次磁盘 I/O？
答：走二级间接 → 读二级索引块 + 读一级索引块 + 读数据块 = 3 次
   （inode 已在内存，不计）

问：磁盘 1 TB，块 4 KB，位示图占多少空间？
答：块数 = 2^40 / 2^12 = 2^28
   位数 = 2^28 bit
   字节 = 2^28 / 8 = 2^25 B = 32 MB
```

**易错点。**

```text
① 指针数算错：4096 / 4 = 1024，不是 4096
② 二级间接忘了平方：是 1024²，不是 2 × 1024
③ 位示图是"一位一块"，不是"一字节一块"
④ 访问次数忘了算数据块本身（只数了索引块）
```

### 8.3 题型 10：I/O 时间与 CPU 占用

**识别信号。**

```text
给传输率、块大小、每次中断的周期数、主频
问"CPU 用于 I/O 的时间""占比"
或给 T / C / M，问单双缓冲
```

**解题步骤。**

```text
① 块数 = 总数据量 / 块大小
② CPU 时间 = 干预次数 × 每次干预周期数 / 主频
③ 传输时间 = 数据量 / 传输率
④ 占比 = CPU 时间 / 传输时间
⑤ 缓冲题：单缓冲 max(C,T)+M，双缓冲 max(C+M,T)
```

**例题。**

> 传输 1 MB 数据，CPU 主频 1 GHz。
> 情形一：程序查询，每字节轮询 100 周期。
> 情形二：中断驱动，每字节 200 周期。
> 情形三：DMA，每 4 KB 一次中断，每次 1000 周期，另有 500 周期初始化。
> 分别求 CPU 用于该 I/O 的时间。

解。

```text
1 MB = 2^20 = 1,048,576 字节，共 256 个 4 KB 块

情形一：1,048,576 × 100 = 104,857,600 周期
        104,857,600 / 10^9 = 0.1049 s ≈ 105 ms

情形二：1,048,576 × 200 = 209,715,200 周期
        209,715,200 / 10^9 = 0.2097 s ≈ 210 ms

情形三：256 × 1000 + 500 = 256,500 周期
        256,500 / 10^9 = 0.2565 ms

比值：105 ms / 0.2565 ms ≈ 409 倍
```

缓冲的算法在 21 篇，这里只留一句。

```text
单缓冲每块 = max(C, T) + M
双缓冲每块 = max(C + M, T)
```

**易错点。**

```text
① 次数算成字节数（DMA 应该按块数）
② 忘了 DMA 的初始化和收尾
③ 分母用错：占比的分母是"数据传输时间"，不是 CPU 时间
④ 单位：μs 与 ms 差 1000 倍，写答案时务必带单位
```

## 9. 五条通用检查

先看这一篇里最值钱的一段话，也是一个反直觉的结论。

> **408 的操作系统综合题，失分最多的不是不会，**
> **而是单位错（KB 与 K、ms 与 s）和"忘了算缺页那一次访问"。**
>
> 这两类错，占了非智力失分的一大半。
> 它们不需要你多懂一点，只需要你在交卷前多看一眼。

五条检查，按这个顺序过。

**检查一：单位。**

```text
1 KB = 1024 B？还是 1000 B？—— 题里通常写 1 KB = 2^10 B
1 MB = 1024 KB
ms 与 s：1 s = 1000 ms
μs 与 ms：1 ms = 1000 μs
ns 与 μs：1 μs = 1000 ns
```

这一步错了，后面全错，而且错得很像"会做"。

**检查二：页大小是不是 2 的幂。**

408 用的页大小基本都是 4 KB，是 2 的幂，可以直接移位。

但一旦题目给的是"1 KB"或"2 KB"，先确认是不是 1024 / 2048。

如果不是 2 的幂（极少见），就不能用移位，得用除法。

**检查三：算不算缺页。**

```text
问"缺页次数"：第一次访问必然缺页，要计入
问"置换次数"：= 缺页次数 − 页框数
问"访问时间"：缺页那一次的磁盘时间要加进去
```

三个问法，三个答案，别混。

**检查四：是不是要"平均"。**

```text
"平均周转时间" = 总周转 / 进程数
"带权周转时间" = 周转 / 运行时间，不带权字的一般是单指某个进程
"平均寻道距离" = 总距离 / 请求数
```

题目少写两个字，答案就差一个除法。

**检查五：有没有"同时到达"。**

```text
同时到达：SJF 退化成按运行时间排序，和到达顺序无关
不同时到达：必须逐个时刻判断"此刻有哪些进程在等"
```

这一条决定调度题的时间轴怎么画。

## 10. 时间分配与答题顺序

180 分钟，150 分。

```text
选择题 40 题（四科合计）  40 分钟以内
综合题 7 道               120 分钟左右
最后检查                  留 10 ~ 15 分钟
```

OS 部分的建议节奏。

```text
选择题 10 题左右          15 分钟内做完
综合题 1 ~ 2 道           25 ~ 30 分钟
```

**答题顺序。**

先做套路最稳的。

```text
① PV 操作题（12 分钟）—— 套路固定，分数好拿
② 地址转换/页表题（10 分钟）—— 步骤固定，只要不慌
③ 文件系统或磁盘题（10 分钟）—— 计算量大但直白
```

为什么先做 PV？

因为它不依赖前面的计算，写对了就是满分，而且能快速进入状态。

为什么地址转换放第二？

因为它一旦卡住，多半是"页号还是页框号"这种一念之差，越急越错。

**卡住了怎么办。**

```text
一道选择题超过 3 分钟 → 标记，跳过
一道综合题某一问卡住 → 写公式、写思路，往下做
最后 15 分钟 → 回来补标记的题
```

**草稿纸怎么用。**

```text
置换题：画 n 行 × m 列的格子，一格一格填
调度题：画一条横向时间轴，标进程名
磁盘题：画一条 0 ~ 199 的数轴，标出磁头位置和方向
```

这些图不是给别人看的，是给"三分钟后回来的自己"看的。

## 11. 把十类题收回一张图

十类题看着散，其实只有三种动作。

```text
换算：把一种表示换成另一种
      地址 → 物理地址、页号 → 页框号、块号 → 柱面/磁头/扇区

累计：把一串小量加起来
      周转时间、寻道距离、缺页次数、CPU 周期

判定：把一个条件和另一个条件比
      Need ≤ Work、Request ≤ Available、页框够不够
```

把三种动作贴回操作系统那张地图。

```text
                ┌─────────────────────────────┐
                │  CPU                        │
                │  题型 5 调度（累计）          │
                │  题型 6 银行家（判定）        │
                │  题型 7 PV（判定 + 累计边数）  │
                └──────────────┬──────────────┘
                               │
                ┌──────────────▼──────────────┐
                │  内存                        │
                │  题型 1 地址转换（换算）      │
                │  题型 2 页表大小（换算 + 累计）│
                │  题型 3 EAT（累计）           │
                │  题型 4 置换（累计 + 判定）    │
                └──────────────┬──────────────┘
                               │
                ┌──────────────▼──────────────┐
                │  磁盘与文件                  │
                │  题型 8 磁盘（累计）          │
                │  题型 9 inode（换算 + 累计）  │
                │  题型 10 I/O 时间（累计）     │
                └─────────────────────────────┘
```

这张图有一个用处。

考场上看到一道没见过的题，先问自己：

```text
它在换什么？（换算）
它在加什么？（累计）
它在比什么？（判定）
```

三个问题里总有一个能对上。

对上了，就知道该调用哪一套步骤。

对不上，说明这道题是概念题，去 23 篇的 20 组对照里找。

## 12. 小结

这一篇没有新知识，只有排序。

十类题型，各有三件套。

```text
识别信号 → 解题步骤 → 易错点
```

三句话带走。

```text
408 的题是有限套路的排列组合，不是无穷题库。
每类题都有固定步骤，慌的时候按步骤走，比凭感觉快。
真正拉开差距的不是难题，是单位、是缺页、是"平均"这两个字。
```

最后再看一眼那条铁律。

> **宁可多写一行推导，不要只写一个数。**

因为阅卷是按步骤给分的。

一个孤独的答案，对了是满分，错了是零分。

一段带公式的推导，错了还能拿一半。

下一篇是最后一篇，也是整套系列的收口。

```text
操作系统系统讲解 23：附录：术语表、考点索引与自检
```

那一篇会给：

```text
按五块分组的 60 条术语
考点到篇目的逐条索引
一张公式速查
20 组最容易混的概念对照
30 条自检题，答案指向篇号
```

到这里，该讲的知识点讲完了。
