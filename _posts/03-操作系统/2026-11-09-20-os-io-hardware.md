一块 1 GB 的文件，从磁盘读进内存。

机械硬盘的持续传输率，算 200 MB/s。

1 GB = 2^30 B，200 MB/s = 200 × 2^20 B/s。

除一下，5.12 秒。

现在换一种读法。

每读一个字节，CPU 先问一次"好了没"。

1 GB 是 1,073,741,824 个字节。

也就是十亿七千万次询问。

按每次询问 100 个时钟周期、主频 3 GHz 算：

```text
1,073,741,824 × 100 = 107,374,182,400 个周期
107,374,182,400 / 3,000,000,000 = 35.8 秒
```

35.8 秒，对 5.12 秒。

慢了 7 倍。

CPU 什么正事都没干，光在问。

所以这一层要回答的问题不是"CPU 能不能搬数据"。

是"CPU 该不该干这件事"。

## 1. 这个问题解决什么

设备侧的速度，跨了六七个数量级。

```text
CPU 寄存器        不到 1 ns
Cache             几 ns
内存              约 100 ns
SSD 随机读        几十 μs
磁盘随机读        几 ms
打印机出纸        几十 ms 到 秒
```

一边是纳秒，一边是毫秒。

差了六个数量级。

如果 CPU 用"我盯着你干"的方式和磁盘打交道，那 CPU 的设计就白费了。

I/O 硬件这一层，解决三件事。

```text
① 怎么连：设备不直接挂在 CPU 上，中间隔一个控制器
② 怎么指挥：CPU 往哪个地址写，才能让设备动起来
③ 谁来搬数据：CPU 搬，还是别人搬
```

这三件事，对应三组考点。

```text
控制器与端口编址  → 选择题里的概念判断
四种控制方式      → 选择题 + 计算题
DMA 的传送过程    → 判断题最爱
```

## 2. 最小模型：一条 I/O 通路

先画一条最窄的通路。

```text
┌──────┐   系统总线    ┌──────────────┐   设备接口   ┌────────┐
│ CPU  │◀────────────▶│  设备控制器   │◀───────────▶│  设备   │
└──┬───┘              │              │              └────────┘
   │                  │ 数据寄存器    │
   │  中断请求线       │ 状态寄存器    │
   └─────────────────▶│ 控制寄存器    │
                      └──────────────┘
```

三根线，各有分工。

```text
系统总线：地址线 + 数据线 + 控制线，CPU 读写控制器寄存器走这里
中断线：控制器 → CPU，单向，告诉 CPU "事办完了"或"出错了"
DMA 请求线：控制器 → CPU 的总线仲裁器，说"我要用总线"
```

关键的一句：

**CPU 从来不直接操作设备，它只操作控制器上的一小片寄存器。**

设备转多快、磁头在哪、纸有没有卡，CPU 一概不知道。

它只知道：往控制寄存器写 1，然后等状态寄存器的某一位变 1。

这个"隔一层"的设计不是偷懒，是被逼的。

磁盘说 SATA 或 NVMe 协议，键盘说 USB HID 协议，显示器说 DP 协议。

每一种协议的电平、时序、帧格式都不一样。

如果让 CPU 直接对接，那 CPU 的引脚数量和指令集都会被设备绑死。

所以中间必须有一层，把"设备协议"翻译成"几个寄存器"。

这一层就是控制器，而寄存器就是这一层的全部对外接口。

## 3. 设备分类：三种分法

三种分法，考的是"按什么分"和"分出来有什么用"。

### 3.1 按信息交换单位：块设备与字符设备

```text
块设备（block device）
  单位：块，常见 512 B 或 4 KB
  可寻址：能直接读"第 n 块"
  速度：高
  典型：磁盘、SSD、U 盘、光盘
  常用控制方式：DMA

字符设备（character device）
  单位：字节 / 字符
  可寻址：只能顺序流，没有"第 n 个字符"的地址
  速度：低或中等
  典型：键盘、鼠标、串口、打印机
  常用控制方式：中断
```

这个划分不是学术分类，是接口分类。

块设备的核心能力是"随机寻址"，所以文件系统能在它上面做分配、做索引。

字符设备的核心特征是"流"，所以它只需要 read/write 两个动作。

注意一个例外：网卡既不是块设备也不是字符设备。

Linux 里它是第三类，network device，没有设备文件，只有 `eth0` 这样的接口名。

408 的问法一般是这样：

```text
"下列设备中，属于块设备的是：A 键盘  B 打印机  C 磁盘  D 鼠标"
"字符设备只能顺序访问，块设备可以随机访问——这句话对吗？"
```

第二句是坑。

字符设备的"不能随机访问"指的是没有块号这种寻址方式，不代表不能 seek 到流的某个位置。

准确的说法是：字符设备以字节为单位、不以块为单位寻址。

### 3.2 按传输速率

```text
低速：键盘、鼠标        几 B/s 到几 KB/s
中速：打印机、扫描仪     几十 KB/s 到几 MB/s
高速：磁盘、SSD、网卡    MB/s 到 GB/s
```

速率决定了值不值得上 DMA。

给键盘配一个 DMA 控制器，初始化的开销比数据本身还大。

### 3.3 按分配方式

```text
独占设备（exclusive）
  一段时间内只能给一个进程用
  例：打印机、磁带机
  缺点：利用率低，容易死锁

共享设备（shared）
  可寻址，可交替给多个进程用
  例：磁盘、网卡
  注意：交替不等于同时，宏观共享、微观串行

虚拟设备（virtual）
  用软件把一台独占设备变成"看起来多台"
  实现手段就是 SPOOLing，21 篇细讲
```

要强调的是，这三条分类线互相正交。

磁盘是"共享的块设备"。

打印机是"独占的字符设备"。

键盘是"独占的字符设备"，也是"低速设备"。

408 喜欢把它们混在一句话里，让你判断哪句错。

## 4. 设备控制器与 I/O 端口

### 4.1 控制器里有什么

控制器是 CPU 和设备之间的翻译官，内部至少有四样东西。

```text
① 数据寄存器：暂存要传的数据，一般带缓冲
② 状态寄存器：告诉 CPU 现在能不能传
③ 控制寄存器：CPU 下命令的地方
④ 地址译码与设备选择：一个控制器可能挂多台设备
```

三个寄存器的读写方向，是个高频考点。

```text
数据寄存器   可读可写
状态寄存器   只读（有的平台读操作会顺带清标志）
控制寄存器   只写
```

状态寄存器里的常见位：

```text
busy      设备正忙
ready     数据已就绪，可以读
error     出错（校验错、缺纸、介质错误）
irq_en    允许发中断
```

控制寄存器里的常见位：

```text
start     启动一次传送
dir       方向：设备 → 内存，还是内存 → 设备
irq_en    这次传完要不要发中断
dma_en    用 DMA 还是用程序搬
```

除了寄存器，控制器里还有差错校验电路（奇偶校验、CRC）和串并转换。

这些不是考点，但它们解释了一件事：**控制器不只是个寄存器堆，它是个小处理器。**

一个控制器挂多台设备时，还需要一个"设备地址寄存器"。

CPU 先往这个寄存器写设备号，再写数据或命令。

控制器内部按设备号做片选，把信号送到对应设备的接口上。

所以"控制器地址"和"设备地址"是两层。

```text
CPU 写端口 0x1F0 → 选中第一个 IDE 控制器
再写设备号 0    → 选中这个控制器上的主盘
再写命令        → 动作才发生
```

408 有时会把"设备地址"和"控制器端口地址"混在选项里，看清主语。

### 4.2 CPU 怎么和控制器说话

两种方式，本质是"控制器的寄存器放在哪个地址空间里"。

```text
方式一：独立编址（port-mapped I/O）
  I/O 端口有自己的一套地址，用专门的 I/O 指令访问
  x86：in al, 0x60   /   out 0x60, al

方式二：统一编址（memory-mapped I/O，MMIO）
  把控制器的寄存器映射到内存地址空间
  用普通的 load/store 访问
  mov eax, [0xFEE00000]
```

### 4.3 统一编址与独立编址

| 对比项 | 统一编址（memory-mapped） | 独立编址（port-mapped） |
|---|---|---|
| 地址空间 | 与内存共用一套 | 单独一套 I/O 地址空间 |
| 访问指令 | 普通访存指令 | 专用 I/O 指令 |
| 指令灵活性 | 高，各种寻址方式都能用 | 低，通常只能寄存器与端口之间传 |
| 对内存空间的影响 | 占用一部分内存地址 | 完全不占用 |
| 访问保护 | 靠页表权限位 / MMU | 靠 I/O 指令的特权级 |
| 译码复杂度 | 与内存统一译码，逻辑较长 | 端口地址位数少，译码简单 |

各自的优点，一句话说完。

```text
统一编址的优点：指令多、寻址灵活、编程方便
统一编址的缺点：吃掉内存地址空间，且用户态能否访问取决于页表配置

独立编址的优点：不占内存空间，I/O 指令天然是特权指令
独立编址的缺点：指令少，一般只能通过累加器搬数据，写起来别扭
```

现实的分布很干脆。

x86 两者都有：老设备用端口（0x60 键盘、0xCF8/0xCFC PCI 配置），新设备几乎全用 MMIO。

ARM 和 RISC-V 基本只有 MMIO，没有 I/O 指令这回事。

## 5. 四种控制方式

四种方式不是四个并列的知识点。

是一条阶梯：CPU 手里的活越来越少。

```text
① 程序查询：CPU 问一次，搬一次
② 中断驱动：设备好了叫 CPU，CPU 搬一次
③ DMA：CPU 只交代首尾，硬件搬一整块
④ 通道：CPU 只发一条指令，通道执行一串命令
```

衡量这条阶梯的尺子只有一把：**CPU 干预的粒度**。

从"每字节"到"每字节"到"每块"到"每组 I/O"。

### 5.1 程序查询

最原始的方式，CPU 亲自盯着。

```c
/* 简化示意：从设备读 n 个字节 */
for (i = 0; i < n; i++) {
    while ((inb(STATUS) & READY) == 0)
        ;                       /* CPU 在这里空转，什么也干不了 */
    buf[i] = inb(DATA);         /* 搬一个字节，走一次总线 */
}
```

两个硬伤。

```text
CPU 忙等：等待期间不能切换去干别的
无法响应：如果设备永远不就绪，CPU 就永远卡在这
```

优点是简单，不需要中断硬件，也不需要 DMA 控制器。

所以它只出现在两种情况：教学示例，和极端简陋的嵌入式板子。

**算一遍 CPU 时间。**

题目：设备传输率 2 MB/s，每传 1 字节轮询一次，每次轮询 100 个周期，主频 1 GHz。传 1 MB 数据。

```text
1 MB = 2^20 B = 1,048,576 字节
轮询次数 = 1,048,576
周期数   = 1,048,576 × 100 = 104,857,600
CPU 时间 = 104,857,600 / 10^9 = 0.1049 s ≈ 105 ms

数据本身的传输时间 = 1 MB / 2 MB/s = 0.5 s
CPU 占用比例 = 104.9 / 500 ≈ 21%
```

注意这 105 ms 里，几乎全是"等"。

CPU 在做事的时间可能不到 1%。

### 5.2 中断驱动

把"问"换成"报"。

```text
CPU 写控制寄存器，发读命令
        │
        ▼
CPU 返回，去跑别的进程          ← 这里开始并行
        │
        ▼
设备准备好一个字节，控制器拉中断线
        │
        ▼
CPU 响应中断：保存现场 → 查中断向量 → 进中断服务程序
        │
        ▼
中断服务程序读数据寄存器，写进内存
        │
        ▼
恢复现场，返回被打断的地方
        │
        ▼
下一个字节，再来一次
```

CPU 干预次数等于数据单位数。

传 1 MB，就是 1,048,576 次中断。

每次中断的成本，远大于轮询一次。

```text
中断响应        几十个周期（关中断、判优先级、取向量）
保存 / 恢复现场  几十到上百个周期（寄存器入栈出栈）
Cache 与流水线   被打断，可能要重新填充
```

按每次 500 个周期算：

```text
1,048,576 × 500 = 524,288,000 个周期
524,288,000 / 10^9 = 0.524 s
```

0.524 秒，比 0.5 秒的传输时间还长。

这就是中断驱动最尴尬的地方。

**它解决了"CPU 空转"，没解决"CPU 搬运"。**

单位太小，中断太密，光保存现场就把好处吃光了。

中断服务程序为什么要写得极短？

因为它运行在关中断或者高优先级的状态下。

它一长，别的中断就被推迟，设备的数据就可能被覆盖。

所以真实的驱动都拆成上下两半。

上半部读走数据、清中断标志，几十行就结束。

下半部慢慢处理，此时中断已经开着。

这套拆分不是软件品味问题，是被"每字节一次中断"的成本逼出来的。

### 5.3 DMA

DMA（direct memory access，直接存储器访问）的核心是一句话：

**数据从设备到内存，不经过 CPU 的寄存器。**

多了一个 DMA 控制器，它替 CPU 干搬运。

一次 DMA 传输分三段，这三段是 408 判断题的原题素材。

```text
Ⅰ 预处理（CPU 干）
   CPU 往 DMA 控制器写：内存起始地址、传送字节数、方向、设备号
   然后启动，CPU 走人

Ⅱ 数据传送（DMA 控制器干）
   DMA 控制器向 CPU 申请总线
   拿到总线后，设备 ↔ 内存直接传
   数据不经过 CPU

Ⅲ 后处理（CPU 干）
   整块传完，DMA 控制器发一次中断
   CPU 校验、唤醒等待的进程、决定下一块怎么办
```

对应的代码长得像这样。

```c
/* 简化示意：启动一次 DMA 传送 */
dma->src  = DEV_DATA;         /* 设备数据寄存器 */
dma->dst  = (uint64_t)buf;    /* 内存起始地址 */
dma->len  = 4096;             /* 字节数 */
dma->ctrl = DMA_READ | DMA_IRQ_EN | DMA_START;

/* 写完之后 CPU 立刻返回，传完才被中断叫回来 */
```

DMA 抢总线的三种做法，也值得记一下。

```text
停止 CPU 访存：DMA 独占总线，整块传完再还
  优点：传得快　缺点：CPU 在此期间完全不能用内存

周期挪用（cycle stealing）：每次偷一个总线周期
  优点：CPU 几乎不受影响　缺点：DMA 传得慢

交替访问：CPU 和 DMA 分时用总线
  优点：折中　缺点：硬件复杂
```

408 常问："周期挪用方式下，CPU 的执行会被打断吗？"

答：不会打断"指令"，但每次访存会被推迟一个周期，所以程序会变慢。

DMA 控制器自己也有寄存器，最少四个。

```text
内存地址寄存器（MAR）：这次要写到内存哪里，每传一次自动加一
字节计数寄存器（DC）：还剩多少字节，减到 0 就结束
控制寄存器：方向、是否中断、总线模式
状态寄存器：完成、出错、总线请求中
```

"自动加一"这个细节很关键。

它意味着一次 DMA 内部，CPU 完全不用管地址怎么变。

地址递增、计数递减，都在 DMA 控制器内部完成。

这也是 DMA 能"连续传一整块"的物理原因。

如果把 DMA 的粒度设成 1 个字节，那它和中断驱动没有区别，只是把中断换成了总线请求。

### 5.4 通道

通道（channel）是加强版的 DMA，本质上是一台小小的 I/O 处理机。

它有自己的一套指令（通道指令，CCW）。

```text
CPU：执行一条 I/O 指令——"启动通道 0"
        │
        ▼
通道 0：从内存里取出通道程序，一条一条执行
   CCW1：读 磁盘 A 的 0 号块 → 内存 0x1000
   CCW2：读 磁盘 A 的 1 号块 → 内存 0x2000
   CCW3：读 磁盘 B 的 5 号块 → 内存 0x3000
   ...
   CCWn：结束，发一次中断
        │
        ▼
CPU：收到一次中断，整组 I/O 全部完成
```

粒度变了。

DMA 一次交代一块，传完要 CPU 再交代下一块。

通道一次交代一串，中间不用管。

```text
CPU 干预次数：每组 I/O 一次
```

通道分三种，考的是"哪种通道配哪种设备"。

```text
字节多路通道
  为多台低速字符设备服务
  按字节交叉：这台一个字节，那台一个字节
  适合：终端、打印机

数组选择通道
  一次只服务一台高速设备，成组传送
  缺点：一台占着，别的等着

数组多路通道
  多台高速设备，按块交叉
  折中了前两者的优点
```

通道为什么只在大中型机上常见？

因为它需要额外的硬件：一台能取指、能译码、能访存的 I/O 处理机。

个人机上，一块 DMA 控制器加几个中断就够了。

设备数量少，CPU 完全忙得过来。

设备数量一多——几百块磁盘、几十台终端——CPU 光是发指令就发不过来。

这时候通道才划算。

所以 408 里"通道"这个词，考的是概念，不是配置。

你只需要知道：它是"能执行通道程序的 I/O 处理机"，CPU 干预次数是每组 I/O 一次。

这一点和 DMA 拉开了整整一个数量级。

### 5.5 四者对比

| 方式 | CPU 干预粒度 | 每次干预做什么 | 数据经 CPU | 中断次数 | 典型设备 |
|---|---|---|---|---|---|
| 程序查询 | 每个字节 | 轮询状态 + 搬一个字节 | 是 | 0（不用中断） | 最简单的板载外设 |
| 中断驱动 | 每个字节 / 字 | 响应中断 + 搬一个字节 | 是 | 每字节一次 | 键盘、串口、鼠标 |
| DMA | 每个数据块 | 初始化 / 收尾 | 否 | 每块一次 | 磁盘、SSD、网卡 |
| 通道 | 每组 I/O | 发一条 I/O 指令 | 否 | 每组一次 | 大型机的一批设备 |

怎么选，有一个很实用的判据。

```text
数据单位很小、又必须及时响应  → 中断
数据单位很大、连续成块        → DMA
设备很多、要成组传            → 通道
简单到不值得配中断硬件        → 查询
```

举个例子就清楚了。

键盘为什么不用 DMA？

因为一次就一个字节，DMA 的初始化开销（写四个寄存器）比数据本身大几十倍。

磁盘为什么不用中断驱动？

因为一块 4 KB，用中断要中断 4096 次，光保存现场就够看一集动画。

## 6. 408 怎么考

题型就三类。

```text
① 概念判断：给定场景，该用哪种控制方式
② 计算：CPU 干预次数、CPU 占用时间、占用比例
③ 过程判断：DMA 的三段里，哪一步 CPU 参与，哪一步不参与
```

**第一类，选方式。**

判据是数据单位的大小和连续性。

```text
键盘输入一个字符            → 中断驱动
磁盘读一个 4 KB 块          → DMA
连续读 100 个块             → DMA（每块一次中断）
同时管 20 台设备的一批传输   → 通道
```

**第二类，算干预次数。**

这是送分题，但要看清"单位"。

```text
程序查询：干预次数 = 字节数（每字节轮询至少一次，实际更多）
中断驱动：干预次数 = 字节数（或字数，看题目给的单位）
DMA：    干预次数 = 块数 + 首尾各一次
通道：    干预次数 = 1（每组 I/O）
```

**第三类，过程判断。**

把 DMA 的三段背下来，这类题不会错。

顺手再记三个判断题的坑。

> 判断题一："程序查询方式下，CPU 与设备不能并行工作。"

对。

因为 CPU 在循环里读状态寄存器，它没法同时去跑别的代码。

不过要注意，设备和 CPU 在微观上其实都在动。

设备在准备数据，CPU 在轮询。

所以更准确的说法是：CPU 不能与设备并行"做有用的事"。

> 判断题二："中断方式下，CPU 与设备可以并行工作。"

也对，但只在"等待期间"。

传输那一个字节的时候，还是 CPU 亲自搬的。

这就是为什么块设备必须用 DMA。

> 判断题三："通道方式下，CPU 不需要执行任何 I/O 指令。"

错。

CPU 要执行一条"启动通道"的 I/O 指令，只是这条指令之后就不用管了。

三条判断题放在一起看，考的全是同一件事：**CPU 在哪个时刻参与。**

现在算一道完整的。

> 自拟题：某磁盘传输率 4 MB/s（1 MB = 2^20 B），块大小 4 KB。
> 采用 DMA 方式，每传完一块发一次中断，中断处理需要 1000 个时钟周期。
> CPU 主频 2 GHz。现要传输 8 MB 数据。
> 求：(1) 中断次数；(2) 中断处理占用的 CPU 时间；(3) 占传输时间的比例。
> 若改为每字节一次中断，中断次数是多少？

解。

```text
(1) 块数 = 8 MB / 4 KB = (8 × 2^20) / (4 × 2^10) = 8 × 2^10 = 2048 块
    中断次数 = 2048 次

(2) CPU 时间 = 2048 × 1000 / (2 × 10^9)
             = 2,048,000 / 2,000,000,000
             = 1.024 × 10^-3 s
             = 1.024 ms

(3) 传输时间 = 8 MB / 4 MB/s = 2 s = 2000 ms
    占比 = 1.024 / 2000 = 0.000512 = 0.0512%
    约 0.05%

(4) 每字节一次：8 MB = 8 × 2^20 = 8,388,608 字节
    中断次数 = 8,388,608 次
    是 DMA 方式的 8,388,608 / 2048 = 4096 倍
```

三个数字，说明一件事。

DMA 把中断次数从 838 万次压到 2048 次，压了 4096 倍。

这就是"粒度"的威力。

四个常见错法。

```text
① 把块数算成字节数（8 MB / 4 KB 算成 2M）
② 忘了 DMA 只在首尾中断，按每字节算了
③ 比例的分母用了 CPU 时间，而不是传输时间
④ 单位混用：KB 当 1000 B，K 当 1024
```

## 7. 真实系统里长什么样

Linux 把这一层抽象得非常薄。

先看设备文件。

```text
$ ls -l /dev/sda /dev/ttyS0
brw-rw---- 1 root disk 8, 0 ... /dev/sda
crw-rw---- 1 root dialout 4, 64 ... /dev/ttyS0
```

第一个字符 `b` 是块设备，`c` 是字符设备。

`8, 0` 是主设备号和次设备号。

```text
主设备号 → 决定用哪个驱动程序
次设备号 → 决定是这个驱动管的第几台设备
```

`/proc/devices` 里能看到所有已注册的主设备号。

再看端口。

x86 上 `inb()` / `outb()` 是内联汇编，直接对应 `in` / `out` 指令。

PCI 配置空间靠 0xCF8 / 0xCFC 两个端口访问，这是独立编址至今还活着的原因。

现代设备几乎全是 MMIO。

PCIe 设备的 BAR（base address register）把自己的寄存器映射到一段物理地址。

驱动 `ioremap()` 之后，用 `readl()` / `writel()` 访问。

从 CPU 的角度看，那就是一次普通的访存。

中断这一层，Linux 分上下半部。

```text
上半部（hardirq）：关中断执行，只做最紧急的事——读状态、清中断、把活推给下半部
下半部：softirq / tasklet / workqueue，开中断执行，做耗时的事
```

PCIe 用 MSI/MSI-X 代替了物理中断线。

所谓"发中断"，其实是设备往一个约定地址写一个约定数据。

中断变成了一个内存写操作。

DMA 在 Linux 里有专门的 API。

```c
/* 一致性映射：CPU 和设备都能访问，通常用于控制结构 */
dma_addr_t h = dma_alloc_coherent(dev, size, &cpu_addr, GFP_KERNEL);

/* 流式映射：一次性传输，用完就解除 */
dma_addr_t d = dma_map_single(dev, buf, len, DMA_TO_DEVICE);
...
dma_unmap_single(dev, d, len, DMA_TO_DEVICE);
```

中间还夹着一层 IOMMU。

它把设备看到的地址再翻译一次，作用相当于"给设备用的 MMU"。

没有 IOMMU，一个乱写地址的网卡能直接改内核内存。

有 IOMMU，它只能改到自己被允许的那几页。

NVMe 是个特别有意思的例子，它把四种方式全用上了。

```text
提交队列、完成队列放在内存里     → DMA
doorbell 寄存器                   → MMIO 写
完成通知                          → MSI-X 中断
高负载时改用轮询（polling queue） → 又回到程序查询
```

最后那条最值得琢磨。

最快的设备，在高负载下反而把中断关掉，让 CPU 主动轮询。

因为每秒上百万次中断，开销比轮询还大。

**技术不是单调进步的，是在两个极端之间找当前最优点。**

还有一个现实细节：中断也不是白来的。

Linux 里能看到的每一行 `cat /proc/interrupts`，背后都是一次真实的硬件拉线。

```text
$ cat /proc/interrupts
           CPU0       CPU1
  16:       1234          0   IO-APIC  16-fasteoi   ehci_hcd
 124:      98213      21543   PCI-MSI 524288-edge  nvme0q0
```

第一列是中断号，后面是每个 CPU 核收到的次数。

多核机器上，中断可以被路由到指定核。

这就是"中断亲和性"（IRQ affinity）。

它和进程亲和性是一回事：把活分给合适的核。

为什么网卡的多队列要绑核？

因为一个包在哪个核上被中断，它的协议栈处理就在哪个核上。

绑错了核，包就要跨核搬一次，Cache 全废。

## 8. 一次完整走查：1 GB 那道题，四种方式各算一遍

回到开头。

1 GB = 1,073,741,824 B，磁盘 200 MB/s，主频 3 GHz。

**程序查询。**

每字节 100 周期。

```text
1,073,741,824 × 100 = 107,374,182,400 周期
107,374,182,400 / 3,000,000,000 = 35.79 s
```

传输本身只要 5.12 秒。

CPU 被拖到 35.79 秒，全程 100% 占用。

**中断驱动。**

每字节 500 周期。

```text
1,073,741,824 × 500 = 536,870,912,000 周期
536,870,912,000 / 3,000,000,000 = 178.96 s
```

比查询还慢。

这个结果反常识，但账很清楚：中断一次的成本是轮询一次的五倍。

所以"中断一定比查询好"是个错误结论。

准确的说法是：

**中断把 CPU 从"必须等"里解放出来，但没有减少单字节的处理成本。**

如果 CPU 有别的活干，中断的吞吐更高。

如果 CPU 没别的活干，中断纯属白烧。

**DMA。**

4 KB 一块，需要 262,144 块。

```text
1 GB / 4 KB = 2^30 / 2^12 = 2^18 = 262,144 块
262,144 × 1000 = 262,144,000 周期
262,144,000 / 3,000,000,000 = 0.0874 s = 87.4 ms
```

传输 5.12 秒，中断开销 87.4 毫秒，占 1.7%。

CPU 剩下 98% 的时间可以跑别的进程。

**通道。**

一条指令、一次中断。

开销在微秒级，可以当成 0。

把四个数字排在一起：

```text
程序查询   35.79 s    CPU 占用 100%
中断驱动  178.96 s    CPU 占用 100%（更糟）
DMA         0.087 s   CPU 占用 1.7%
通道        ~0        CPU 占用 ~0%
```

阶梯的形状就出来了。

真正的分水岭在 DMA 那一级。

因为它改的不是"谁来等"，是"谁来搬"。

## 9. 容易混淆的点

**一、DMA 与中断的区别。**

不是"一个用中断一个不用"。

DMA 也用中断，只是只在整块传完时用一次。

区别在于数据路径。

```text
中断驱动：设备 → 控制器数据寄存器 → CPU 寄存器 → 内存（两次总线传送）
DMA：     设备 → 内存（一次总线传送，CPU 不占）
```

**二、DMA 与通道的区别。**

```text
DMA：一次交代一块（或一段连续数据），传完要 CPU 再交代
通道：一次交代一串（通道程序），中间不用 CPU
```

通道是"能执行程序的 DMA"。

**三、程序查询与中断驱动的区别。**

```text
查询：CPU 主动问 —— 问的时候 CPU 不能干别的
中断：设备主动报 —— 报之前 CPU 可以干别的
```

一个是被动等待，一个是异步通知。

**四、统一编址与独立编址的区别。**

不是"有没有地址"的区别。

两者都有地址，区别是"这套地址和内存地址是不是同一套"。

统一编址用访存指令访问端口。

独立编址用 I/O 指令访问端口。

**五、通道程序与设备驱动程序。**

这两个词很像，但不是一回事。

```text
通道程序：通道执行的指令序列，存在内存里，由通道硬件取指执行
设备驱动程序：CPU 执行的代码，负责填寄存器、处理中断
```

一个是硬件执行的程序，一个是软件。

**六、状态寄存器"只读"的例外。**

有的平台读状态寄存器会清中断标志。

这类"读清"（read-to-clear）寄存器，调试时读一下就把中断弄丢了。

**七、控制器与设备。**

控制器是 CPU 这一侧，设备是另一侧。

一个控制器可以管多台设备，一台设备只接一个控制器。

所以"控制器坏了"和"设备坏了"，在系统里看到的现象完全不同。

前者表现为"整个通道上的设备全没了"，后者只是单台设备报错。

## 10. 反直觉：DMA 绕过的不是 CPU

```text
很多人把 DMA 记成"DMA 绕过 CPU，所以 CPU 完全不参与"。

错。

DMA 绕过的只有一段路：数据搬运。
数据从设备到内存，不经过 CPU 的寄存器。

但一次 DMA 传输有三个时刻，CPU 必须在场：

① 开始之前：谁告诉 DMA 控制器"从哪读、读到哪、读多少"？
   是 CPU，一条一条写寄存器。

② 传输之中：DMA 要抢总线，总线仲裁要把总线让出来。
   这个"让"，是 CPU 一侧的硬件在配合。

③ 结束之后：DMA 发中断，CPU 校验、唤醒进程、决定下一块。
   没有这一步，数据传完了也没人知道。
```

所以准确的说法是：

**DMA 把 CPU 从"搬运工"降级成"工头"。**

工头不用搬砖，但开工和收工都得他签字。

408 里有一道很经典的判断题：

> "DMA 方式下数据不经过 CPU，因此 CPU 完全不干预 I/O 过程。"

前半句对，后半句错。

还有一道变体：

> "DMA 方式下，数据从设备直接送入内存，不需要 CPU 执行任何指令。"

也错。

启动 DMA 的那几条写寄存器指令，就是 CPU 执行的。

## 11. 小结 + 下一篇

四种控制方式，是一条"CPU 放手"的阶梯。

```text
查询 → 中断：CPU 不用等
中断 → DMA：CPU 不用搬
DMA → 通道：CPU 不用一块一块地交代
```

三句话记住这一篇。

```text
CPU 只碰控制器上的寄存器，从不直接碰设备。
控制方式的区别，就看 CPU 干预的粒度。
DMA 省的是"搬运"，不是"指挥"。
```

还有两个数字要能随手算。

```text
查询 / 中断：CPU 时间 = 字节数 × 每次开销 / 主频
DMA：        CPU 时间 = 块数 × 每次中断开销 / 主频
```

粒度差 4096 倍，结果就差 4096 倍。
