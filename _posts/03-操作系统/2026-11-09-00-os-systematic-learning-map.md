先看一个问题。

同一个地址：

```text
0x400000
```

在进程 A 里读出来是 `100`。

在进程 B 里读出来是 `200`。

两块不同的内存，用了同一个地址。

CPU 居然不觉得乱。

为什么？

这一篇不急着回答。

但整套操作系统，几乎都在回答这一类问题：

```text
两个东西看起来是同一个，
为什么实际上不是，
系统又是怎么把它们隔开的。
```

## 1. 操作系统为什么显得散

翻开任何一本教材，目录大概是这样：

```text
概述
进程管理
内存管理
文件管理
I/O 管理
```

五块。

每一块内部又有十几个小标题。

于是学起来像背五本不相干的书：

```text
进程调度算法要背七八个
页面置换算法要背四五个
磁盘调度又要背四五个
```

背完就忘。

忘完再背。

**问题不在算法多。**

**问题在于，你不知道它们各自在解决同一件事的哪一面。**

## 2. 一条主线：操作系统只在做三件事

把五块内容压一下，其实只有三件事。

```text
① 虚拟化：把一份资源，变成很多份"看起来独占"的。
② 抽象：把复杂的硬件，包装成简单的接口。
③ 管理：决定谁在什么时候，用哪一份资源。
```

具体到资源，只有四类。

```text
CPU      → 进程与线程（让你以为自己在独占 CPU）
内存     → 地址空间（让你以为自己有一整块内存）
磁盘     → 文件（让你以为数据是一个个有名字的对象）
设备     → 统一接口（让你以为所有设备都长一个样）
```

前三类，都是"把一个变成多个"。

第四类，是"把很多变成一个"。

而"谁来用、用多久、用多少"，就是调度和分配。

**记住这一句，后面所有算法都只是它的实现细节。**

## 3. 五块地图

```text
┌──────────────────────────────────────────────┐
│ 概述：OS 是什么、怎么和硬件打交道、怎么被调用   │
├──────────────────────────────────────────────┤
│ 进程：CPU 的虚拟化 + 同步 + 死锁               │
├──────────────────────────────────────────────┤
│ 内存：地址空间的虚拟化 + 分页 + 置换            │
├──────────────────────────────────────────────┤
│ 文件：磁盘的抽象 + 目录 + 分配                  │
├──────────────────────────────────────────────┤
│ I/O：设备的统一接口 + 缓冲 + 驱动               │
└──────────────────────────────────────────────┘
```

五块之间不是并列。

是有依赖的：

```text
没有中断和系统调用（概述），进程根本切不出去。
没有进程（PCB、上下文），调度无从谈起。
没有内存隔离（分页），进程之间会互相踩。
没有文件系统，进程的数据存不下来。
没有 I/O 管理，文件系统落不到磁盘上。
```

所以这套讲解的顺序，就是这个依赖顺序。

## 4. 第 1 块：概述——操作系统到底是什么

这一块回答四个问题。

```text
它管什么？（功能）
它凭什么管？（内核态、特权指令）
它怎么被用？（系统调用）
它长什么样？（内核结构、引导、虚拟机）
```

核心工具只有一个：

```text
中断（interrupt）与异常（exception）。
```

因为操作系统是**被动**的。

它不会自己跑起来。

只有三种情况会把它叫醒：

```text
用户程序发起系统调用
硬件发出中断（时钟、键盘、磁盘完成）
程序出错（缺页、除零、非法指令）
```

**反直觉的点在这里：**

```text
操作系统不是一个一直在运行的程序。
它是一个"被叫醒才干活"的代码集合。
```

想通这一点，你才能理解为什么"时钟中断"是抢占式调度的物理基础。

## 5. 第 2 块：进程——CPU 的虚拟化

一个 CPU，多个程序，怎么让每个程序都觉得自己在独占？

靠三样东西。

```text
PCB：记住这个程序做到哪了
调度：决定下一个轮到谁
切换：把旧现场存起来，新现场恢复
```

看起来简单。

难的是第二层：

```text
多个进程要共享数据，怎么保证不出错？
```

于是有了同步与互斥：

```text
临界区、Peterson、硬件指令、信号量、管程
```

再难一层：

```text
几个进程互相等对方手里的资源，怎么办？
```

于是有了死锁：

```text
四个必要条件、预防、避免、检测与解除
```

这一块的算法最多，但它们回答的是两个问题：

```text
谁先跑？（调度）
跑的时候怎么不打架？（同步）
```

408 在这一块最爱考两样：

```text
算平均周转时间（调度）
写 PV 操作（同步）
```

这两样，后面各有一篇专门练。

## 6. 第 3 块：内存——地址空间的虚拟化

回到开头那个问题。

两个进程里都有 `0x400000`。

为什么读到的不一样？

因为 CPU 发出的地址，**不是**内存真正收到的地址。

它先经过一次翻译：

```text
CPU 发虚拟地址
      ↓
MMU 查页表
      ↓
内存收到物理地址
```

画出来：

```text
虚拟地址 0x400000
   │
   ├─ 页号  = 0x400
   └─ 页内偏移 = 0x000
        │
        ▼
   页表[0x400] = 0x1A2
        │
        ▼
物理地址 0x1A2000
```

进程 A 的页表说 `0x400 → 0x1A2`。

进程 B 的页表说 `0x400 → 0x7C5`。

同一个虚拟地址，落到不同物理页。

**这就是"隔离"的全部秘密：不是不让你访问，是让你的地址翻译到别处去。**

这一块的算法，都是围着这张表转：

```text
页表太大 → 多级页表
查表太慢 → TLB
内存不够 → 请求分页、页面置换
换得太频繁 → 抖动、工作集
```

## 7. 第 4 块：文件——磁盘的抽象

磁盘只有块。

块没有名字，没有结构，断电还在。

用户需要的是：

```text
一个名字（/home/notes/todo.md）
一段可以随意读写的字节流
一套权限（谁能读、谁能写）
```

中间这一层，就是文件系统。

它要解决四个问题：

```text
文件怎么组织？（逻辑结构）
文件放哪？（分配方式）
哪些块空着？（空闲空间管理）
怎么找到文件？（目录与 inode）
```

408 在这一块最爱考：

```text
给定磁盘调度算法，算总寻道距离
给定目录和 inode，算访问一个文件要读几次盘
```

## 8. 第 5 块：I/O——把很多变成一个

键盘、磁盘、网卡、打印机，工作原理完全不同。

但程序里看起来都差不多：

```text
open、read、write、close
```

这一层统一，靠的是：

```text
设备控制器
驱动程序
中断 / DMA
缓冲
```

408 在这一块最爱考四件事：

```text
四种控制方式的区别（程序查询、中断、DMA、通道）
单缓冲/双缓冲的时间计算
SPOOLing 为什么能把独占设备变共享
磁盘与 SSD 的差别
```

### 8.1 一次 read()，五块全用上

把五块串起来看一遍。

用户程序写了一句：

```c
read(fd, buf, 4096);
```

这后面发生了什么。

```text
① 系统调用（概述）
   把系统调用号放进寄存器，执行陷入指令。
   CPU 从用户态切到内核态。

② 查文件（文件）
   用 fd 找到进程打开文件表里的表项，
   再找到 inode，确认这个文件允许读、位置在哪。

③ 查页缓存（内存 / 文件）
   要读的块在不在页缓存里？
   在，直接拷贝；不在，发起磁盘 I/O。

④ 发 I/O（I/O）
   构造请求，交给块设备层，
   可能要排队，可能用 DMA 传输。

⑤ 进程阻塞与唤醒（进程）
   数据没到，当前进程从运行变阻塞，
   调度器切到别的进程。
   磁盘中断到达，进程被唤醒，变就绪。

⑥ 回到用户态
   数据从内核缓冲区拷到 buf，
   恢复现场，返回用户态。
```

六步。

每一步都属于不同的章节。

**这就是为什么这套讲解不按教材目录排，而按依赖排。**

因为真题经常这样问：

```text
"read 系统调用执行过程中，可能发生几次缺页？"
"可能发生几次进程切换？"
"数据从磁盘到用户缓冲区，经过几次拷贝？"
```

只会一章，答不全。

## 9. 三张必须能默画的图

整套系统，浓缩成三张图。

### 9.1 进程状态机

```text
        创建
         │
         ▼
    ┌─────────┐  调度   ┌─────────┐  时间片到  ┌─────────┐
    │  就绪   │ ──────▶ │  运行   │ ────────▶ │  就绪   │
    └─────────┘         └────┬────┘           └─────────┘
         ▲                   │ 等待事件
         │                   ▼
         │              ┌─────────┐
         │   事件发生    │  阻塞   │
         └──────────────└─────────┘
```

三个核心状态：就绪、运行、阻塞。

加上创建和终止，是五态。

再加挂起，是七态。

408 爱考的是：**哪些转换是合法的，哪些不可能。**

比如：

```text
阻塞 → 运行     不可能（必须先变就绪）
就绪 → 阻塞     不可能（没在跑，怎么会等事件）
```

### 9.2 地址转换

```text
虚拟地址
 ┌──────────┬────────┐
 │  页号 p  │ 偏移 d │
 └────┬─────┴────────┘
      │
      ▼
   ┌──────┐  命中   ┌──────┐
   │ TLB  │ ───────▶│页框号│
   └──┬───┘          └──┬───┘
      │ 未命中            │
      ▼                   │
   ┌──────┐               │
   │ 页表 │ ──────────────┘
   └──────┘
      │
      ▼
物理地址 = 页框号 × 页大小 + 偏移
```

缺页时，还要多一次磁盘 I/O。

EAT 的计算题，就是在这张图上做加法。

### 9.3 一次系统调用

```text
用户程序
   │  ① 传参、把系统调用号放进寄存器
   ▼
陷入指令（trap）
   │  ② CPU 从用户态切到内核态
   ▼
内核入口：保存现场
   │
   ▼
系统调用处理程序
   │  ③ 干活（读文件、创建进程……）
   ▼
恢复现场、返回用户态
   │
   ▼
用户程序继续
```

这三张图能默画，五块内容就散不了。

## 11. 408 怎么考这张地图

408 的操作系统部分，题型很稳定。

```text
选择题：概念辨析、地址计算、调度指标、置换次数、磁盘寻道
综合题：PV 操作、页表与地址转换、文件系统结构、调度与死锁
```

分值上，进程管理和内存管理是大头。

但这不代表别的可以放弃。

因为选择题里，文件与 I/O 的占比不低，而且**概念题一旦记混就必错**。

一个实用的判断：

```text
能算的题，靠套路，练三遍就稳。
不能算的题，靠对比，把"两个概念差在哪"说清楚就够。
```

这套讲解每一篇的第 6 节都叫「408 怎么考」，就是干这个的。

## 14. 一个入门的小算例

先热一下手。

### 14.1 地址转换

页面大小 4 KB，页表如下：

```text
页号 0 → 页框 5
页号 1 → 页框 2
页号 2 → 页框 8
```

访问虚拟地址 `0x1234`。

```text
页大小 4 KB = 2^12，所以低 12 位是偏移。
0x1234 = 0001 0010 0011 0100
页号   = 0x1
偏移   = 0x234
查表：页号 1 → 页框 2
物理地址 = 2 × 0x1000 + 0x234 = 0x2234
```

三行算完。

但考场上的题会在这三行外面加东西：多级页表、TLB 命中率、缺页、访问权限。

**骨架永远是这三行。**

### 14.2 调度指标

三个进程同时到达，运行时间分别是 1、2、3。

FCFS：

```text
P1: 完成 1，周转 1
P2: 完成 3，周转 3
P3: 完成 6，周转 6
平均周转 = (1+3+6)/3 = 3.33
```

SJF：

```text
P1: 完成 1，周转 1
P2: 完成 3，周转 3
P3: 完成 6，周转 6
```

等一下，这里两者一样？

因为三个进程**同时到达**，且运行时间恰好是 1、2、3。

按短作业优先，顺序也是 1、2、3。

**这就是 408 最爱设的陷阱：同时到达时，SJF 退化成按长度排序，和"到达顺序"无关。**

如果到达时间不同，答案就变了。

## 15. 读完应该能回答的五个问题

这套讲解读完，下面五个问题应该能当场答出来。

答不上来的，就是你还没读透的那一块。

**第一问：为什么 `fork()` 会返回两次？**

```text
提示：返回值是"进程"这个抽象的一部分。
父进程拿到子进程 PID，子进程拿到 0。
同一条指令，两个执行流各走了一遍。
```

（03 篇）

**第二问：同一个虚拟地址，为什么在两个进程里读到不同数据？**

```text
提示：地址要经过页表翻译。
每个进程有自己的页表，页号相同，页框不同。
```

（13、14 篇）

**第三问：时间片设成 1 个时钟 tick，会怎样？**

```text
提示：切换有开销。
时间片越小，切换越频繁，有效算力越低。
但时间片太大，RR 退化成 FCFS。
```

（06 篇）

**第四问：缺页率 0.001，EAT 大概是多少？**

```text
提示：EAT = (1−p)×内存访问 + p×缺页处理。
缺页处理是毫秒级，内存访问是纳秒级。
所以 p 只要不为 0，EAT 就会被缺页项主导。
```

（14 篇）

**第五问：为什么 inode 里没有文件名？**

```text
提示：文件名属于目录项，inode 只描述文件本身。
所以一个 inode 可以有多个名字（硬链接）。
```

（17、18 篇）

五问里，前三问是"机制"，后两问是"计算与结构"。

都能答，408 的概念题基本不会丢分。

## 16. 小结

整套操作系统，可以压成一句话：

```text
把一份资源，虚拟成很多份；
把复杂硬件，抽象成简单接口；
再决定谁在什么时候用哪一份。
```

五块内容，对应四次虚拟化/抽象：

```text
CPU    → 进程
内存   → 地址空间
磁盘   → 文件
设备   → 统一接口
```

四张底牌：

```text
中断、页表、inode、DMA。
```

```text
操作系统系统讲解 01：操作系统是什么：概念、特征、功能与分类
```
