先看一段代码。

```c
int main(void) {
    int fd = open("a.txt", O_RDONLY);
    char buf[16];
    read(fd, buf, 16);
    close(fd);
    return 0;
}
```

四行调用，跨了四次边界。

`open` 要问内核：这个文件在哪、你有没有权限读。

`read` 要问磁盘：那一段字节存放在哪个块上。

`close` 要问内核：这个打开的表项什么时候能释放。

`return` 要问内核：这个进程的 PCB、页表、文件描述符什么时候回收。

进程自己一件事也做不完。

**它每一次"往外伸手"，伸到的就是操作系统。**

## 1. 这个问题解决什么

"操作系统是什么"，是个看着简单、答起来会飘的问题。

因为你在三个场合见到的"操作系统"，根本不是同一个东西。

```text
装机的时候：Ubuntu 24.04、Windows 11、macOS 15
写代码的时候：open / read / write / fork / mmap 这一组接口
考试的时候：资源管理者，管处理机、存储器、设备、文件
```

三个说法都不算错。

但它们指的不是同一个对象。

所以这一篇要干的事，是把这三个说法拆开，再装回一个能用的定义。

拆完你会发现，"操作系统"这个词至少有两层含义：

```text
狭义：内核（kernel）—— 一直待在内存里、能执行特权指令的那部分代码
广义：内核 + 系统程序 + 命令解释器 + 图形界面 —— 你装机时看到的那一整套
```

408 考的是狭义那一层。

你平时说的"装系统"，说的是广义那一层。

**先把这两个口径分开，后面的概念才不会打架。**

## 2. 最小模型：操作系统站在哪一层

整个计算机可以压成三层。

```text
┌───────────────────────────────────────────────┐
│  应用程序                                      │
│  浏览器 / 编译器 / gcc / 你的 a.out            │
├───────────────────────────────────────────────┤
│  操作系统内核                                   │
│  进程管理 / 内存管理 / 文件系统 / 设备驱动      │
├───────────────────────────────────────────────┤
│  硬件                                          │
│  CPU / 内存 / 磁盘 / 网卡 / 键盘               │
└───────────────────────────────────────────────┘
```

三层之间有两个界面。

上面那个界面，叫系统调用（system call）。

下面那个界面，叫特权指令（privileged instruction）和中断（interrupt）。

**操作系统的全部工作，就是在这两个界面之间做翻译。**

### 2.1 视角一：资源管理者

从上往下看，操作系统是一个分配者。

机器上的资源只有四类，每一类都要回答同一个问题：

```text
CPU    → 分给哪个进程、给多久        → 处理机管理
内存   → 分给哪个进程、分多少页      → 存储器管理
磁盘   → 文件放在哪些块上            → 文件管理
设备   → 谁先用打印机、谁先用网卡    → 设备管理
```

四类资源，四种分配策略。

但抽象出来只有三件事：

```text
记录：谁在用、用了多少    → 数据结构（PCB、页表、inode、设备表）
决策：下一个给谁          → 算法（调度、置换、分配）
执行：真的把资源交出去    → 原语、上下文切换、驱动
```

408 里那一堆算法，全都是"决策"这一格的展开。

### 2.2 视角二：用户与硬件的接口

从下往上看，操作系统是一个包装工。

硬件很难用。

磁盘只认"读第几个扇区"，不认"读 a.txt 的第 3 行"。

网卡只认环形缓冲区里的描述符，不认"发一个 HTTP 请求"。

操作系统把每一个硬件都包成一个简单对象：

```text
磁盘  → 文件（有名字、有权限、可以顺序读写）
内存  → 地址空间（从 0 开始、连续、私有）
CPU   → 进程（看起来一直在跑、独占一个 CPU）
设备  → 统一的 open / read / write / close
```

四个包装，对应四块内容。

**这就是 00 篇说的"三次虚拟化加一次统一"。**

### 2.3 一句话定义

```text
操作系统是管理和控制计算机软硬件资源、
合理组织多道程序运行、
并为用户提供方便接口的系统软件。
```

这句话里每个词都有用。

"管理"对应视角一。

"接口"对应视角二。

"多道程序"是它存在的理由——单道程序不需要操作系统调度。

"系统软件"说明它不是硬件，也不是应用。

这句话还漏了一个要点，补一句：

```text
它不只是"管理"，还要"抽象"。
```

只管理不抽象，用户就得自己算磁道号、自己填页表项。

所以更完整的说法是：

```text
操作系统 = 资源管理者（分配与回收）
         + 抽象提供者（把硬件包成对象）
         + 秩序维护者（隔离与保护）
```

三个角色，一个实体。

408 的题，问"A 体现的是哪个角色"时，就按这三格去对。

## 3. 一次完整走查：从敲回车到屏幕出字

定义看完了，走一遍真实流程。

你在终端里敲：

```text
$ ./hello
```

按回车。

屏幕上出现 `hello`。

这中间发生了什么？

```text
① 键盘按下 → 键盘控制器发中断 → CPU 进内核
② 内核把字符放进终端缓冲区 → 唤醒等在 read 上的 shell
③ shell 解析 "./hello" → fork 出一个子进程
④ 子进程 exec：把 hello 的代码段、数据段映射进地址空间
⑤ 第一条指令取指 → 缺页 → 内核从磁盘调入一页
⑥ 调度器选中这个进程 → 上下文切换 → 跳到入口
⑦ 运行到 printf → 库函数攒够一行 → 调 write
⑧ write 是系统调用 → 陷入内核 → 内核把字节写进终端设备
⑨ 进程 exit → 内核回收 PCB、页表、文件描述符
⑩ 父进程 wait 返回 → shell 打印下一个提示符
```

十个步骤，每一格都对应后面某一篇。

```text
① ② 中断与唤醒        → 02 篇
③ ④ 进程创建与地址空间 → 03 篇、13 篇
⑤   缺页              → 14 篇
⑥   调度与切换        → 05、06 篇、03 篇
⑦ ⑧ 系统调用与设备     → 02 篇、20 篇
⑨   资源回收          → 03 篇
⑩   进程同步          → 07、08 篇
```

**注意一个细节：这十步里，没有一步是"操作系统主动发起的"。**

键盘没按，内核就在 `hlt` 里睡觉。

进程不调 `read`，内核不会替它读文件。

时钟不响，内核不会主动去换进程。

数一下这十步里内核被"叫醒"了几次：

```text
① 键盘中断一次
⑦ write 陷入一次（系统调用）
⑤ 缺页异常一次
⑧ 磁盘中断一次
⑥ 时钟中断若干次（时间片）
```

五次。

每一次都不是内核自己想干活，是外面有事情发生了。

这一点在 02 篇会展开，这里先记一句：

> **操作系统不是一个一直在运行的程序，它是一堆"被叫醒才干活"的代码。**

## 4. 四个特征：并发、共享、虚拟、异步

教材把操作系统的特征写成四个词。

四个词都不难背。

难的是：每个词背后到底在说哪件事、举什么例子算举对了。

### 4.1 并发（concurrency）

先给结论：

```text
并发 = 两个或多个事件在同一时间间隔内发生。
```

关键词是"时间间隔"。

不是"同一时刻"。

例子：

你一边用 `gcc` 编译，一边戴着耳机听歌，一边开着浏览器。

三个程序都在"运行"。

但单核 CPU 在任何一个纳秒，只能执行其中一条指令。

它是这样切出来的：

```text
时间 →
CPU:  [gcc][player][browser][gcc][player][browser] ...
```

每段只有几毫秒。

切换得足够快，你就感觉三个都在跑。

**并发是操作系统最核心的 illusion。**

没有并发，后面所有内容都不需要存在：

```text
不用并发 → 不需要调度
不用并发 → 不需要 PCB
不用并发 → 不需要同步互斥
不用并发 → 不需要虚拟内存
```

### 4.2 共享（sharing）

并发之后立刻出现一个问题：

多个进程同时要用同一份资源，怎么办？

资源分两种共享方式。

```text
互斥共享：一个时间段内只允许一个进程用
          例：打印机、摄像头、临界区里的变量

同时共享：一个时间段内允许多个进程"同时"用
          例：磁盘上的只读文件、内存里的共享库
```

"同时共享"加引号，是因为微观上还是交替访问。

两个进程读同一个文件，其实是两次独立的 `read`。

但它们的宏观效果是"同时"的，谁也不影响谁。

**互斥共享的资源，叫临界资源（critical resource）。**

典型例子是一个共享计数器：

```c
// 两个进程都想执行这一段
count = count + 1;
```

这一行在机器上是三条指令：

```text
load  count → 寄存器
add   1
store 寄存器 → count
```

两个进程交替执行，可能都读到旧值，最后一次 `store` 把另一次覆盖掉。

结果少加了一次。

这就是"共享"必须配"互斥"的原因。

这个词后面会反复出现。

注意一个因果方向：

```text
并发是共享的前提（不并发就不用共享）
共享是并发的代价（一共享就要同步）
```

408 喜欢问"为什么多道程序系统必须解决互斥问题"。

答案就在这个循环里。

### 4.3 虚拟（virtual）

虚拟的定义：

```text
把一个物理实体，变成多个逻辑实体。
```

三种虚拟，对应三类资源。

```text
虚拟处理器：一个 CPU → 多个"看起来在跑"的处理器
            手段：时分复用（时间片轮转）

虚拟存储器：少量内存 → 一个很大的地址空间
            手段：空分复用 + 按需调页（内存 + 磁盘）

虚拟设备：  一台打印机 → 多个"独占打印机"的假象
            手段：SPOOLing，先写磁盘队列，再排队输出
```

三个例子里，最容易搞错的是虚拟存储器。

它不是"假的存储器"。

它是"地址空间比物理内存大，缺的页放在磁盘上，用到了再调进来"。

**虚拟的本质是"用时间换空间"或"用空间换独占"，不是凭空造资源。**

### 4.4 异步（asynchronous）

定义：

```text
进程以不可预知的速度向前推进。
```

为什么不可预知？

因为进程走走停停。

停的原因有三个：

```text
等 I/O（读磁盘要几毫秒，CPU 能跑几百万条指令）
等锁（别人占着临界区）
等调度（时间片用完了）
```

例子：

同一个程序跑两次。

第一次磁盘缓存命中，`read` 花了 1 微秒。

第二次缓存没命中，`read` 花了 5 毫秒。

程序逻辑完全一样，执行时间差三个数量级。

**结果一样，路径不一样。**

这就是异步。

异步带来一个麻烦：程序的结果可能依赖于执行的先后顺序。

```text
进程 A 先写 x，进程 B 后读 x  → 读到新值
进程 B 先读 x，进程 A 后写 x  → 读到旧值
```

如果这个顺序会影响最终结果，程序就是错的。

这类错误叫"与时间有关的错误"（race condition）。

07 篇到 10 篇，整整四篇都在处理它。

### 4.5 并发不等于并行

这是 408 出现频率最高的辨析之一。

先给判据：

```text
并发（concurrency）：同一时间段内，多个任务都在推进
并行（parallel）：    同一时刻，多个任务真的各跑各的
```

画在时间轴上：

```text
并发（单核）：
CPU0  [ A ][ B ][ A ][ B ][ A ][ B ]
      └──── 同一时间段 ────┘
      任何一条竖线，只穿过一个任务

并行（双核）：
CPU0  [ A ][ A ][ A ][ A ]
CPU1  [ B ][ B ][ B ][ B ]
      └──── 同一时间段 ────┘
      任何一条竖线，穿过两个任务
```

一句判断：

```text
看有没有"同一时刻"。
有 → 并行（也一定并发）
没有 → 只有并发
```

两个必须记住的结论：

```text
单处理机系统：进程可以并发，不能并行。
多处理机系统：既可以并发，也可以并行。
```

还有一个更细的点：

```text
并发和并行都不是"同时执行同一条指令"。
程序里有数据依赖时，拆成两个线程也不能并行。
```

这一点在 04 篇讲线程时会再回来。

## 5. 容易混淆的点

### 5.1 操作系统 ≠ 内核

狭义的操作系统是内核。

广义的操作系统是"内核 + 系统程序 + 界面"。

408 说"操作系统"时，一般指内核那一层的能力。

所以说"操作系统提供文件系统"是对的。

说"操作系统提供浏览器"是错的，那是应用。

### 5.2 多道程序设计 ≠ 多处理机

两个词只差一个字，含义完全不同。

```text
多道程序设计：内存里同时放多道程序，一个 CPU 交替执行
多处理机：    机器里有两个以上 CPU，可以真并行
```

多道程序设计解决的是"CPU 等 I/O 时空转"。

多处理机解决的是"一个 CPU 算不过来"。

前者提高利用率，后者提高算力。

### 5.3 分时 ≠ 实时

两个系统都强调"快"。

但快的含义相反。

```text
分时：让每个用户觉得"响应很快"，平均响应时间短
实时：让每个任务"必须在截止时间前完成"，最坏情况有保证
```

分时可以偶尔让某个用户等 2 秒。

实时系统里，一个任务晚 2 毫秒可能就是事故。

这个区别在 11 节会展开成一整节。

### 5.4 虚拟 ≠ 不存在

虚拟内存有真实的物理页做后备。

虚拟处理器背后有一个真实的 CPU 在轮转。

虚拟设备背后有一台真实的打印机在排队。

**虚拟是把"一份物理资源"包装成"多份逻辑资源"，不是凭空生成。**

### 5.5 异步 ≠ 无序

异步说的是"推进速度不可预知"。

不是"执行顺序随便"。

如果程序的正确性依赖顺序，就必须用同步机制把顺序钉死。

钉死之后，程序依然是异步执行的，但结果是确定的。

### 5.6 操作系统 ≠ BIOS

开机时先跑的是主板上的固件，不是操作系统。

```text
BIOS / UEFI：固化在主板芯片里，负责自检、找引导设备
操作系统：  被引导程序装进内存之后才开始运行
```

BIOS 不归操作系统管，它比操作系统更早、更底层。

408 把引导过程放在概述里考，就是因为它跨在"硬件"和"操作系统"中间。

02 篇会把这条链路完整走一遍。

## 6. 408 怎么考

这一篇对应 408 概述部分的前两节：概念、特征、功能、分类。

题型很固定。

```text
选择题（绝大多数）：
  四个特征的辨析
  并发与并行的判断
  某系统属于哪一类（批处理 / 分时 / 实时）
  多道程序设计的优点与缺点
  操作系统功能的归属（哪个属于哪个管理）

综合题（很少）：
  基本不单独出，会融进调度题、内存题里
```

三条套路。

**套路一：看到"单处理机"，直接排除并行。**

题干里只要出现"单 CPU"，凡是选项里有"并行执行"的，基本可以划掉。

**套路二：看到目标词，对应系统类型。**

```text
吞吐量 / 单位时间作业数   → 批处理
响应时间 / 交互 / 公平     → 分时
截止时间 / 确定性 / 可靠   → 实时
```

**套路三：多道程序的优缺点成对记。**

```text
优点：CPU 与 I/O 并行、提高利用率、提高吞吐量
缺点：无交互（用户不能干预）、管理复杂、可能饥饿
```

### 6.1 例题一：判断四句话

自拟，按真题风格。

```text
下列关于操作系统的叙述中，正确的是：

A. 单处理机系统中，进程可以并发执行，也可以并行执行
B. 多道程序设计的主要目的是缩短单个作业的周转时间
C. 分时系统的时间片越小，系统开销越小
D. 并发执行的进程，其执行结果可能与执行速度有关
```

逐条看。

A 错。单处理机没有并行的物理条件。

B 错。多道程序设计提高的是吞吐量和资源利用率，单个作业的周转时间可能变长（要排队）。

C 错。时间片越小，切换次数越多，开销越大。

D 对。这就是异步性带来的"与时间有关的错误"。

答案 D。

### 6.3 例题三：功能归属

自拟。

```text
下列功能中，属于存储器管理而不属于文件管理的是：

A. 为文件分配磁盘块
B. 记录哪些内存块空闲
C. 把逻辑地址转换成物理地址
D. 维护目录结构

（多选，选出所有属于存储器管理的项）
```

逐条看。

A 是文件管理，管的是磁盘上的空闲块。

B 是存储器管理，管的是内存的空闲页框。

C 是存储器管理，地址转换是内存管理的核心动作。

D 是文件管理，目录是文件系统的命名结构。

答案 B、C。

这类题不难，但要求你对"五块功能"的边界心里有图。

一个粗糙的判据：

```text
问的是"内存里怎么放"  → 存储器管理
问的是"磁盘上怎么放"  → 文件管理
问的是"设备怎么动"    → 设备管理
问的是"谁先用 CPU"    → 处理机管理
```

### 6.2 例题二：算 CPU 利用率

自拟。

```text
某单处理机系统有两个程序：

程序 A：CPU 计算 60 ms，然后 I/O 40 ms
程序 B：CPU 计算 80 ms，然后 I/O 20 ms

求：
(1) 单道环境下，先 A 后 B，CPU 利用率是多少？
(2) 多道环境下，CPU 利用率是多少？
```

先算单道。

```text
A: 0-60    CPU
   60-100  I/O
B: 100-180 CPU
   180-200 I/O
总时间 = 200 ms
CPU 忙 = 60 + 80 = 140 ms
利用率 = 140 / 200 = 70%
```

再算多道。

A 先算，B 等 CPU。

```text
0-60    A 用 CPU
60-100  A 做 I/O，B 用 CPU
100     A 结束（A 的 I/O 做完了）
100-140 B 继续用 CPU（B 需要 80，已用 40）
140-160 B 做 I/O
160     全部结束
总时间 = 160 ms
CPU 忙 = 60 + 80 = 140 ms
利用率 = 140 / 160 = 87.5%
```

两个数字：70% 和 87.5%。

**注意 A 的完成时间没变（都是 100 ms），变的是总时间。**

这就是多道程序设计的本质：

```text
不是让某个程序跑得更快，
是让别人在它等 I/O 的时候插进来。
```

顺带一个反例：

如果两个程序都是"纯 CPU、无 I/O"，多道不会提高利用率。

CPU 一直是 100%，多道只增加切换开销。

**多道的收益，完全来自 I/O 等待那段空隙。**

## 7. 真实系统里长什么样

课本说"操作系统是资源管理者"。

真实机器上，这个说法要打个折。

### 7.1 Linux 是"单内核 + 模块"

Linux 的内核是一个大的二进制体，所有子系统编在一起。

但它支持动态加载模块：

```text
$ lsmod | head
$ sudo modprobe nf_conntrack
```

`.ko` 文件就是编译好的模块，加载时直接进内核地址空间。

效果上像"模块化"，本质上还是单内核。

因为模块和核心代码跑在同一个地址空间、同一个特权级。

一个驱动写崩了，整个内核崩。

### 7.2 你装的"系统"不等于内核

```text
$ uname -r
6.8.0-45-generic
```

这一行才是内核版本。

你装的 Ubuntu 24.04 是：

```text
内核 + systemd + glibc + apt + GNOME + 一堆用户态程序
```

`systemd` 是 PID 1，但它是一个用户态程序。

GNOME 也是。

**所以"操作系统"的边界，在工程上是模糊的。**

考试按内核算，装机按发行版算。

### 7.3 内核大部分时间在睡觉

在空闲的机器上敲：

```text
$ top
```

会看到 `id` 那一列接近 100%。

CPU 在干什么？

在 idle 循环里执行 `hlt` 指令。

`hlt` 让 CPU 停止执行，直到下一个中断到来。

```text
没有中断 → CPU 不执行任何内核代码
```

这就是 02 篇要讲的"被动性"的物理证据。

### 7.4 容器说明"系统"可以不止一层

Docker 容器里跑 `cat /etc/os-release`，会显示 Debian 或 Alpine。

但容器里没有自己的内核。

```text
容器 = 命名空间（隔离视图）+ cgroups（限制资源）+ 同一个内核
```

一个内核，多个"看起来独立的系统"。

这也是虚拟化的一种，只不过虚拟的是"视图"，不是"硬件"。

## 8. 功能：操作系统到底管哪五件事

回到课本。

操作系统的功能，标准答案是五块。

```text
① 处理机管理
   进程控制、进程同步、进程通信、调度
   → 03、04、05、06、07-11 篇

② 存储器管理
   内存分配与回收、地址映射、内存保护、内存扩充
   → 12-16 篇

③ 设备管理
   缓冲管理、设备分配、设备处理、虚拟设备
   → 20、21 篇

④ 文件管理
   文件存储空间管理、目录管理、文件读写与保护
   → 17、18、19 篇

⑤ 提供接口
   命令接口（命令行）、程序接口（系统调用）、图形界面
   → 02 篇
```

五块不是并列关系。

它们有依赖：

```text
没有处理机管理 → 程序跑不起来
没有存储器管理 → 程序装不进内存
没有设备管理   → 程序读不到数据
没有文件管理   → 数据存不下来
没有接口       → 用户调不动上面四块
```

**记忆锚点：CPU、内存、设备、文件、接口。**

顺序就是从内到外，从快到慢。

## 9. 服务：内核向上递出的九个能力

功能是"它管什么"。

服务是"它给你什么"。

这两张清单经常被混着考。

九项服务，分两组。

面向用户的一组：

```text
① 用户接口
   命令接口（交互式、批处理式）、程序接口（系统调用）、GUI

② 程序执行
   把程序装进内存、分配资源、让它跑完

③ I/O 操作
   读文件、写文件、操作设备，统一成 read / write

④ 文件系统操作
   创建、删除、打开、读写、查找、列目录

⑤ 通信
   同一台机器上的进程之间传数据；跨机器的网络通信
```

面向系统的一组：

```text
⑥ 资源分配
   多个用户、多个作业抢同一批资源时，决定给谁

⑦ 统计
   记录谁用了多少 CPU、多少存储，用于计费或调优

⑧ 错误检测
   检测 CPU 错误、内存错误、I/O 错误、程序异常

⑨ 保护与安全
   防止一个进程访问另一个进程的资源
```

一句区分：

```text
功能 = 管理者视角的动作（我管什么）
服务 = 使用者视角的能力（你能让我干什么）
```

考试里如果问"下列哪项是操作系统提供的服务"，选项里可能有"编译程序""浏览器"。

那些是应用，不是服务。

## 10. 一部发展史：从手工到个人计算机

发展史不是背年份。

是看每个阶段在解决什么矛盾。

```text
① 手工操作阶段
   没有操作系统。用户独占全机。
   矛盾：人机速度差几个数量级，CPU 等人。

② 单道批处理
   内存里一道程序，用监督程序（monitor）把作业串起来。
   解决：减少人工干预。
   矛盾：CPU 还是要等 I/O，因为只有一道。

③ 多道批处理
   内存里放多道程序，一道等 I/O 就换另一道。
   解决：CPU 与 I/O 并行，吞吐量上去了。
   新问题：没有交互，作业交上去就等着。

④ 分时系统
   时间片轮转，多个终端共享一台主机。
   解决：交互性，响应时间。
   代表：CTSS、MULTICS（UNIX 的直系祖先）。
   四个特点：多路性、独立性、及时性、交互性。
   多路性指一台主机连多个终端，独立性指用户之间互不干扰。

⑤ 实时系统
    Hard real-time：错过截止时间就是失败（飞控、刹车）
    Soft real-time：偶尔错过可接受（视频播放）
   解决：确定性，最坏情况有界。

⑥ 网络操作系统
   管理本机资源 + 提供网络通信与资源共享。

⑦ 分布式操作系统
   多台机器，对一个用户像一台。
   和网络 OS 的区别：分布式有单一地址空间、任务可迁移。

⑧ 个人计算机操作系统
   追求界面友好、多媒体、即插即用。
```

一条主线：

```text
手工 → 批处理：为了不让 CPU 等人
批处理 → 分时：为了不让人等 CPU
分时 → 实时：为了不让"必须准时"的任务迟到
```

**每一次演进，都是因为上一阶段有个东西在等。**

## 11. 三种系统的目标为什么互相冲突

这一节是全篇最反直觉的地方。

教材把批处理、分时、实时并列，容易读成"三种做法"。

其实它们是三种**互相冲突的优化目标**。

```text
批处理：单位时间内完成尽可能多的作业   → 吞吐量
分时：  从提交到看到结果尽可能短       → 响应时间
实时：  在截止时间之前完成             → 截止时间
```

为什么冲突？

先看吞吐量和响应时间。

提高吞吐量最有效的办法是"少切换"：

```text
时间片给长一点，进程一次跑久一点，切换次数就少。
```

但时间片一长，排在你前面的进程就把 CPU 占久了。

响应时间立刻变差。

反过来，提高响应时间最有效的办法是"时间片给小"：

```text
时间片从 100 ms 降到 10 ms，等待的进程最多等 10 ms。
```

但切换次数变成 10 倍。

算一下开销。假设一次切换 1 ms：

```text
时间片 100 ms：开销占比 = 1 / (100 + 1) ≈ 0.99%
时间片  10 ms：开销占比 = 1 / (10 + 1)  ≈ 9.09%
时间片   1 ms：开销占比 = 1 / (1 + 1)   = 50%
```

时间片 1 ms 时，一半的 CPU 时间花在切换上。

吞吐量直接腰斩。

**这就是分时系统不敢把时间片设太小的原因。**

再看实时。

实时系统为了保证截止时间，经常主动"浪费"资源：

```text
CPU 明明空着，也不给低优先级任务，
因为要保证高优先级任务一就绪就能立刻拿到 CPU。
```

从吞吐量角度看，这是灾难。

从截止时间角度看，这是必须。

实时的两个关键词：

```text
截止时间（deadline）：这件事必须在某个时刻之前完成
可预测性（determinism）：最坏情况必须能算出来，不能"平均很快"
```

举个具体的：一个视频播放器每 33 ms 必须送出一帧（约 30 帧/秒）。

晚 1 ms 也许还能接受（软实时）。

晚 100 ms 就是卡顿，观众看得见。

再比如刹车控制，采样周期 5 ms，晚 1 ms 可能就是事故（硬实时）。

三者的关系可以画成这样：

```text
        吞吐量高
           ▲
           │  批处理
           │
           │        分时
           │
           │              实时
           └──────────────────────▶ 响应/确定性
```

不存在同时处在右上角的系统。

> **反直觉的点：不存在"各方面都更好"的操作系统。**
> **每选一个目标，就是在明确地牺牲另外两个。**
> **所以"某系统属于哪一类"这道题，本质是问"它把谁放在第一位"。**

这个视角很有用。

后面学调度算法时，你会发现每个算法都在选边站：

```text
FCFS        → 偏吞吐，响应差
SJF         → 偏平均周转，长作业饥饿
时间片轮转   → 偏响应，切换多
多级反馈队列 → 想两头都占，代价是复杂和不可预测
```

## 12. 小结

这一篇的骨架：

```text
一个定义：管理资源 + 提供接口的系统软件
两个视角：资源管理者 / 用户与硬件的接口
四个特征：并发、共享、虚拟、异步
五块功能：处理机、存储器、设备、文件、接口
九项服务：五项目向用户 + 四项目向系统
一条发展线：手工 → 批处理 → 分时 → 实时 → 网络/分布式/个人
一个冲突：吞吐、响应、截止时间，三者不可兼得
```

如果只能记一句话：

```text
操作系统的全部工作，
是在"让多个程序看起来同时在跑"这件事上，
不断地做取舍。
```

下一篇往下钻一层：

```text
操作系统系统讲解 02：内核态、中断与系统调用
```

那一篇回答三个问题：

```text
内核凭什么能管住应用？（特权级）
内核怎么被叫醒？（中断与异常）
应用怎么合法地请求内核？（系统调用）
```

还有一个反直觉的结论：

```text
操作系统不是一直运行的程序，
是被中断叫醒才干活的一堆代码。
```
