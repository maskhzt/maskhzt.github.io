> **读这篇之前，你只需要知道**：二进制是只用 0 和 1 两个数字计数；时钟是一个不停"滴答"的信号，每个滴答电路往前走一步；带宽是"每秒最多能传多少数据"，习惯用字节每秒（B/s）作单位，不是比特每秒。
> **这篇讲什么**：机箱里十几个部件要互相传数据，靠的是同一组公共的线。这一篇讲这组线怎么分成三类、一次能跑多快、几个设备抢的时候谁先用，最后回答开头那个问题——两块一样的硬盘，为什么第二块会变慢。
> **一个类比**：总线像一条公共走廊。所有房间的门都开在走廊上，谁要送东西都得走这条走廊；走廊一次只能过一个人，于是要有"谁先进"的规矩（仲裁），也要有"你什么时候到、我什么时候接"的约定（定时）。走廊越宽，一次过得越多，但越宽越贵，门也越难对齐。


两块 NVMe 固态硬盘插上去。

第一块跑 7000 MB/s，第二块只有 3500 MB/s。

硬盘没坏，主板也没坏。

打开终端看一眼：

```text
$ lspci -vv -s 02:00.0 | grep LnkSta
LnkSta: Speed 16GT/s (ok), Width x4 (downgraded)
```

第一条链路是 x4，第二条也是 x4。

可第二块的速度就是上不去。

因为那 4 条 lane（通道，一条独立的串行收发通路，可以几条拼起来当一条更宽的路用）是从芯片组（主板上那颗负责把各种设备转接起来的芯片）分出来的，和网卡、USB、SATA 挤在同一段上行链路里。

**线是共享的，带宽就是共享的。**

这句话是整个总线这一章的全部内容。

先把这个词钉住。

**总线（bus）**：一组所有部件都接在上面的公共连线；同一时刻，只允许一对部件用它传数据。

共享带来三个问题：

```text
传什么？    数据、地址、控制，各走哪几根线
怎么传？    什么时候采样，谁等谁 —— 定时
谁先传？    几个设备同时想说话 —— 仲裁
```

三条一个个解释：

传什么——所以要把线分成三组：地址总线、数据总线、控制总线。

怎么传——叫**定时（timing）**：约定"谁在第几拍把数据放上线、对方在第几拍采样"。

快慢不同的设备就是靠它对齐的。

谁先传——叫**仲裁（arbitration）**：几个设备同时举手时，由一套电路当场决定"这次让谁先用"。

## 1. 这个问题解决什么

先算一笔账。

假设一台机器有 10 个部件：CPU、主存、硬盘、网卡、显卡、键盘、鼠标、USB 控制器、声卡、显示器。

如果每个部件都要和别的部件直接连线，需要多少条链路？

```text
C(10, 2) = 10 × 9 / 2 = 45 条
```

45 条。

部件增加到 100 个：

```text
C(100, 2) = 100 × 99 / 2 = 4950 条
```

四千九百五十条。

这还只是连线数量，没算每条线要多少根信号线。

总线把这个平方级的连接，压成了线性级：

```text
每个部件挂到同一组线上，N 个部件 → N 个挂接点
```

代价立刻出现：

```text
同一时刻，只能有一对部件在总线上通信
```

这就是总线的本质。

**用"分时共享"换"连接简单"。**

所以总线这一章从头到尾都在处理共享带来的副作用：

```text
速度不一样怎么办   → 定时方式
好几个人抢怎么办   → 仲裁方式
线不够宽怎么办     → 总线宽度与复用
线太长信号变差     → 负载能力、串行化
```

三条根本矛盾：

```text
速度差   CPU 是纳秒级，打印机是毫秒级，差六个数量级
争用     多个主设备想同时用总线
协议     不同厂商、不同年代的设备要能听懂同一套信号
```

再补一段历史，能帮理解"为什么结构越改越复杂"。

```text
第一代  单总线    所有部件挂一条，ISA 总线，8/16 位
第二代  双总线    CPU 与主存单独一条，I/O 走另一条
第三代  三总线    再加 DMA 专用线，高速设备直接访存
第四代  点对点    不再共享，PCIe 用交换网络，一层一层往下挂
```

前三代都在解决同一件事：共享一条线带来的冲突。

第四代干脆不共享了。

每个设备一条独立链路，冲突问题换成了交换网络的成本问题。

所以"总线"这个词，今天更多指"一组约定的传输协议"，而不是"一组物理的公共线"。

但 408 考的是前三代的模型。

因为那是"共享"这个问题最纯粹的样子。

教材给的定义是：

> 总线是能为多个部件分时共享的公共信息传送线路。

两个词要咬住：**分时**、**共享**。

分时，意味着有排队，有仲裁，有等待。

共享，意味着有冲突，有瓶颈，有"谁占比多少"的问题。

## 2. 最小模型：三条线与一次事务

为什么要先看"最小模型"？

因为真实主板上的总线有几十组，直接看框图会晕。

但不管多少组，一组总线只干三件事：说地址、传数据、发控制。

把这三件事抽出来，剩下的都是这三件事的变种和包装。

把机箱里那堆线抽象一下，只剩三组：

```text
        ┌──────────── 系统总线 ────────────┐
        │                                  │
  ┌─────┴─────┐                    ┌───────┴──────┐
  │    CPU    │                    │     主存      │
  └─────┬─────┘                    └───────┬──────┘
        │                                  │
        │  地址线 A0–A31   单向，主设备 → 从设备
        │  数据线 D0–D63   双向
        │  控制线          读/写、中断请求、总线请求/允许、时钟
        │                                  │
  ┌─────┴─────┐                            │
  │  I/O 接口  ├──── 设备                    │
  └───────────┘                            │
```

三组线的分工，一句话一个：

```text
地址线   我说的是谁      单向，宽度决定寻址空间 2^n
数据线   我要传什么      双向，宽度决定一次搬多少
控制线   什么时候传      读、写、中断、仲裁、时钟
```

地址线宽度直接决定寻址空间。

32 根地址线：

```text
2^32 = 4,294,967,296 B = 4 GB
```

这就是 32 位机最多认 4 GB 内存的原因。

（PAE 之类的扩展先不算，那是分页那一层的事，11 篇讲过。）

地址线是单向的：只有主设备能说地址，从设备只能听。

数据线是双向的：读的时候从设备驱动，写的时候主设备驱动。

控制线是混合的：读/写是主设备发，中断请求是设备发，总线请求/允许是双向的一对。

**主设备（master）** 是能发起总线事务的一方。

**从设备（slave）** 是只能被动响应的一方。

CPU 通常是主设备，主存永远是从设备，DMA 控制器也是主设备。

一次总线事务（bus transaction）走四步：

```text
① 请求与仲裁   主设备发 BR（bus request），仲裁器回 BG（bus grant）
② 寻址         主设备把地址放到地址线上，发"地址有效"
③ 传数据       一拍或多拍，每拍传"宽度 / 8"个字节
④ 结束         撤销信号，释放总线
```

"总线周期"（bus cycle）这个词有歧义，408 里两种用法都出现过。

一种是"一拍"：

```text
一个总线周期 = 一个时钟，传一次数据
带宽 = 宽度 / 8 × 频率
```

一种是"一次完整事务"：

```text
一个总线周期 = 从仲裁到结束的一整段
带宽 = 每次事务传的字节数 / 事务耗时
```

看题目给的单位判断用哪个。

如果题目说"总线周期为 50 ns，每个总线周期传送 4 字节"，那它就是第二种。

如果题目说"总线宽度 32 位，总线时钟 100 MHz，每个时钟周期传送一次"，那就是第一种。

## 3. 分类与结构

为什么需要分类？

因为"总线"这个词在三个层级上被同时使用：芯片内部的、主板上的、机器之间的。

三者的速度、协议、成本差着好几个数量级，不先说清"你在讲哪一层"，"这条总线多少位"这句话就没有意义。

总线可以从三个维度分类。

### 3.1 按位置和层次分

```text
片内总线    CPU 芯片内部，寄存器堆到 ALU、Cache 到核的那组线
系统总线    CPU、主存、I/O 之间，分数据/地址/控制三组
通信总线    设备与设备、机器与机器之间，USB、PCIe、以太网
```

片内总线不考计算，但要知道它存在。

CPU 内部那条总线，就是 16 篇讲的"单总线数据通路"。

它和机箱里的系统总线不是一个东西，名字像，位置完全不同。

一个在芯片里，一个在主板上。

通信总线也叫外部总线，特点是距离长、协议重、常常带供电。

USB 就是一个典型：两根差分数据线加两根电源线，四根线解决了供电和数据。

### 3.2 按功能分

数据总线、地址总线、控制总线。

这三组的功能上面讲过，这里补三个常考的细节。

**数据总线宽度通常等于机器字长。**

32 位机的数据总线是 32 位，64 位机是 64 位。

但可以不等：早期 8088 是 16 位字长、8 位数据总线，为了省钱。

**地址总线宽度决定寻址空间，和数据宽度无关。**

32 位地址线配 8 位数据线的机器是存在的。

**地址线和数据线可以复用。**

这叫总线复用（multiplexed bus）。

省线，但每个事务要多一拍：先送地址，再送数据，中间靠 ALE 之类的信号锁存。

408 里出现过"地址/数据复用"的题，算带宽时要把那一拍算进开销。

### 3.3 按传输方式分：并行与串行

```text
并行总线   多位同时传，每位一根线
串行总线   一位一位传，一条线（或一对差分线）
```

直觉上并行快。

实际上从 2000 年以后，几乎所有高速总线都改成了串行。

```text
老 IDE（PATA）   40/80 根线并行，最高 133 MB/s
SATA             2 对差分线，SATA 3.0 = 6 Gb/s ≈ 600 MB/s
老 PCI           32 位并行，33 MHz，132 MB/s
PCIe 3.0 x1      2 对差分线，约 985 MB/s
```

并行输在哪？

```text
① 时钟偏斜（clock skew）：同一拍出发，到达时间对不齐
② 串扰（crosstalk）：线挨得近，互相感应
③ 同步开关噪声：很多位同时翻转，电源抖动
④ 引脚数：每多一位就多一根线、一个引脚、一份成本
```

线越多，频率越上不去。

频率上不去，位宽再大也白搭。

**这是这一篇第一个反直觉的地方：并行不等于快。**

串行靠三件事把并行打趴：

```text
差分信号   两根线传一个比特，靠差值判断，抗干扰强
嵌入时钟   8b/10b、128b/130b 编码，时钟从数据里恢复，不用单独时钟线
多 lane     一条不够就拼几条，带宽按 lane 数线性叠加
```

第三条就是 PCIe x1、x4、x16 的来源。

lane 可以拼，所以串行总线既能"窄"也能"宽"。

并行总线的宽度是焊死的，串行总线的宽度是可扩展的。

### 3.4 单总线结构

最早的结构，一条总线挂所有东西。

```text
        ┌──────┐   ┌──────┐   ┌──────────┐
        │ CPU  │   │ 主存  │   │ I/O 接口  │
        └──┬───┘   └──┬───┘   └────┬─────┘
           │          │            │
           └──────────┼────────────┘
                  ┌───┴───┐
                  │ 单总线 │   一次只能一对通信
                  └───────┘
```

优点三条：

```text
结构简单，一条总线搞定
成本低，线少、接口少
扩充容易，加设备就多挂一个
```

缺点三条，408 就考这三条：

```text
① 带宽瓶颈：CPU 访存和 I/O 传数据抢同一条总线
② 速度被最慢设备拖住：同步定时必须按最慢的设
③ 任何时刻只有一个主设备能发起事务，CPU 和 DMA 会互相等
```

第三条最要命。

CPU 想读内存，DMA 正在传磁盘数据，两者只能排队。

现代 PC 里这条"单总线"其实还在，只不过它被拆成了多层：

```text
CPU ↔ 内存   一条（内存控制器）
CPU ↔ PCIe   一条（直连的 16 或 24 条 lane）
芯片组 ↔ 设备 若干条
```

每一层都是"单总线"的局部版本，层与层之间用桥接。

### 3.5 双总线结构

在 CPU 和主存之间加一条高速的存储总线。

I/O 设备走另一条 I/O 总线。

两条总线用桥（bridge）连起来。

```text
  CPU ══════ 存储总线 ══════ 主存
   │
   │
   └─── I/O 总线 ── I/O 接口 ── 设备
        （桥接器）
```

好处：

```text
CPU 访存不占 I/O 总线，主存带宽独立
I/O 设备再多，也不影响 CPU 取指
```

代价：

```text
I/O 设备与主存交换数据要过桥，走两段
设备 → 桥 → 主存，多一次转发，多一次仲裁
```

DMA 在双总线下还得"借"存储总线。

所以双总线解决了"平时不打架"，没解决"传大数据时还打架"。

### 3.6 三总线结构

把 DMA 总线单独拉出来。

```text
  CPU ══ 主存总线 ══ 主存
   │                   │
   │                   │
   ├── I/O 总线 ── 接口 ─┘
   │
   └── DMA 总线 ── DMA 控制器 ── 高速设备
```

三条总线各有分工：

```text
主存总线   CPU 与主存之间
I/O 总线   CPU 与低速设备之间
DMA 总线   DMA 控制器与主存之间，高速设备专用
```

好处：DMA 传数据不占 CPU 的存储总线，吞吐最高。

代价：线多、成本高、控制复杂，仲裁器要管三条总线。

408 会问：三总线结构里 DMA 走哪条总线？

答案：走 DMA 总线，直接对主存读写，不经过 CPU，也不占主存总线。

三种结构一句话对比：

```text
单总线   便宜、慢、什么都抢
双总线   访存和 I/O 分开，DMA 还要借道
三总线   再加一条 DMA 专用道，最贵最快
```

## 4. 性能指标

为什么非要拆成四个指标？

因为"这条总线快不快"没法比较。

同样是"快"，可能指一次搬得多（宽度大），也可能指一秒搬得勤（频率高）。

这两件事互相拖后腿，所以必须拆成可测的数，再用一个公式合起来。

四个指标，一个公式。

```text
总线宽度   数据线根数，单位 bit
总线频率   时钟频率，单位 MHz 或 GHz
总线周期   一次传输占用的时间，单位 ns
总线带宽   单位时间传输的字节数，单位 B/s
```

带宽公式，408 必背：

```text
带宽 = 总线宽度(bit) / 8 × 总线频率(Hz)
```

为什么除以 8？

因为宽度是"位"，带宽习惯用"字节每秒"。

32 位 = 4 字节，一次搬 4 字节。

**例 1：基本算例。**

某总线数据线 32 位，总线时钟 66 MHz，每个时钟周期传送一次数据。

```text
每拍字节数 = 32 / 8 = 4 B
频率 = 66 × 10^6 Hz
带宽 = 4 × 66 × 10^6 = 264 × 10^6 B/s = 264 MB/s
```

对照一下历史：

```text
32 位 / 33 MHz  → 4 × 33M = 132 MB/s（老 PCI）
32 位 / 66 MHz  → 264 MB/s（PCI 2.1）
64 位 / 100 MHz → 8 × 100M = 800 MB/s
```

**例 2：把地址周期算进去。**

数据线 32 位（4 B），时钟 100 MHz。

一次总线事务 = 1 个地址周期 + 8 个数据周期，共 9 拍。

```text
理想带宽 = 4 B × 100 × 10^6 = 400 MB/s
一次事务传 4 × 8 = 32 B
一次事务耗时 9 拍 = 9 / (100 × 10^6) = 90 ns
实际带宽 = 32 B / 90 ns = 355.6 × 10^6 B/s = 355.6 MB/s
利用率 = 8 / 9 = 88.9%
```

地址周期就像打车前的报地址。

车没动，计价器在跳。

这就是"名义带宽"和"实测带宽"的第一道差。

还有几件事会让带宽再打折。

**总线复用。**

地址和数据共用一组线，每个事务多一拍。

32 位复用总线，传 4 B 要 2 拍（地址一拍、数据一拍），带宽直接砍半。

**DDR。**

DDR（Double Data Rate，双倍数据率）：时钟的上升沿和下降沿各传一次数据，所以同样的时钟频率，传输次数翻倍。

双沿传输，上升沿和下降沿都采数据。

等效传输率是时钟频率的 2 倍。

```text
100 MHz 时钟，DDR → 200 MT/s
```

408 里如果说"DDR 总线，时钟频率 200 MHz"，那传输率是 400 MT/s。

**内存带宽，是这条公式最常见的应用。**

DDR4-3200 双通道：

```text
单通道：3200 MT/s × 8 B = 25.6 GB/s
双通道：25.6 × 2 = 51.2 GB/s
```

注意 3200 是 MT/s，不是 MHz。

DDR 双沿传输，等效频率是时钟频率的 2 倍。

```text
实际时钟 1600 MHz → 等效 3200 MT/s
```

这就是厂商和主板说明书最容易做手脚的地方。

写"内存频率 3200 MHz"其实是 3200 MT/s，时钟只有 1600 MHz。

**负载能力。**

挂的设备越多，线电容越大，边沿越缓，频率只能降。

一条总线上挂 8 个设备和挂 2 个设备，最高频率完全不同。

**传输率（MT/s）和带宽（B/s）不是一回事。**

MT/s 是每秒多少次传输，B/s 是每秒多少字节。

换算时要乘"每次传输的字节数"。

## 5. 定时与仲裁

为什么这两件事必须一起讲？

因为它们是一组线被共享之后的两个必然产物：线只有一组，所以时间上要排队（定时）；设备有好几个，所以话语权要分配（仲裁）。

前者管"节奏"，后者管"顺序"。

真实的总线协议，就是这两个问题的一套组合答案。

总线被共享，就有两个排队问题。

什么时候传 —— 定时。

谁先传 —— 仲裁。

### 5.1 同步定时

所有设备听同一个时钟。

事务占固定拍数，谁都不能改。

```text
CLK    ─┐_┌─┐_┌─┐_┌─┐_┌─
地址   ═X════════════════
数据   ═══════════X══════
        ↑  固定 2 拍，所有设备同节奏
```

优点：

```text
协议最简单：数拍子就行，不用来回确认
速度快：没有握手往返
实现便宜：不需要额外的应答线
```

缺点，两条，都常考：

```text
① 必须按总线上最慢的设备来定拍数
② 时钟偏斜（clock skew）：同一时钟沿到达不同设备的时间不同
```

第一条的杀伤力被低估了。

一个 10 ns 的设备挂上来，2 ns 的设备也得跟着等 10 ns。

整条总线的节奏被最慢的那个拖住。

第二条在频率高时更严重：频率越高，一个时钟周期越短，偏斜占比越大。

适用场景：CPU 与 Cache、CPU 与主存。

速度相近、距离近、设备固定。

**同步定时的判读，是 408 送分题。**

给一张时序图，看三个特征：

```text
① 有独立的 CLK 线          → 不是纯异步
② 数据在固定第 N 拍出现     → 同步
③ 有 WAIT 之类的线被拉低    → 半同步
```

如果题目只给文字：

```text
"各设备按统一的时钟信号工作"        → 同步
"由主设备发出请求，从设备回答后传输" → 异步
"在同步基础上增加一条等待响应信号"   → 半同步
```

一个常被忽略的推论：同步总线的带宽，等于"按最慢设备算出来的带宽"。

```text
总线带宽 400 MB/s，但最慢设备只支持 100 MB/s 的节奏
实际能用到的只有 100 MB/s
```

这也是后面第 10 节"宽度翻倍带宽不一定翻倍"的第三个原因。

### 5.2 异步定时

不用统一时钟，用握手（handshake）。

```text
主设备：REQ  ──────┐         ┌──────
                   └─────────┘
从设备：ACK  ──────────┐   ┌────────
                       └───┘
数据：   ═══════════════════════
                 ↑ 从设备准备好才回 ACK
```

主设备发请求，从设备准备好了回应答。

中间等多久，由从设备决定。

三种互锁方式：

```text
不互锁   主发 REQ 后不等 ACK，过一段时间自己撤
         从收到 REQ 就回 ACK，不等 REQ 撤销
         最快，但可能出错（主设备以为传完了，其实没传）

半互锁   主等 ACK 到了才撤 REQ
         从不等 REQ 撤销就撤 ACK
         折中

全互锁   主等 ACK 才撤 REQ，从等 REQ 撤销才撤 ACK
         最可靠，最慢，四次握手
```

优点：

```text
能兼容任意速度的设备，慢设备自己决定什么时候回
可靠，能发现设备没响应（超时）
总线长度可以更长，不用管时钟偏斜
```

缺点：

```text
每次事务多几个往返，比同步慢
协议复杂，要处理超时和重试
```

408 判断题有一个经典陷阱：

> "异步定时比同步定时快，因为它不需要等时钟。"

错，正好反了。

同步快在"不等"，异步慢在"要等"。

异步换来的不是速度，是灵活性和兼容性。

### 5.3 半同步定时

同步的骨架，加一条 WAIT 线。

```text
CLK    ─┐_┌─┐_┌─┐_┌─┐_┌─
WAIT   ────────┐___________  ← 慢设备拉低
数据   ═════════════X══════
                   ↑ 周期被拉长
```

快设备按固定拍数走完。

慢设备拉低 WAIT，把当前周期拉长，插等待周期（wait state）。

折中方案：

```text
保留了同步的简单（大部分事务不需要握手）
又允许慢设备插入等待（不用为最慢设备牺牲全部）
```

代价是控制逻辑复杂一点，且 WAIT 本身也要同步。

### 5.4 仲裁：谁先上车

三个主设备同时举手，只能一个上。

三根基本信号：

```text
BR（Bus Request）  我要用
BG（Bus Grant）    你可以用
BB（Bus Busy）     有人在用
```

**如果没有仲裁，会怎样？**

两个主设备同时发起写：一个要把数据线拉高（写 1），一个要拉低（写 0）。

结果不是"谁赢"，而是电平卡在中间——从设备读到的是一个不确定值，数据错了还没人报错；同时电流从高电平那一端直接灌进低电平那一端，发热，严重时会烧掉接口芯片。

所以仲裁不是一个"性能优化"，它是共享总线能存在的前提。

#### 链式查询（daisy chain）

```text
仲裁器 ──BG──→ 设备1 ──BG──→ 设备2 ──BG──→ 设备3
   ↑BR──────────────────────────────────────┘
   ↑BB──────────────────────────────────────┘
```

BG 像接力棒，从仲裁器开始逐级往下传。

设备收到 BG，如果自己有请求，就截住，不再往下传，同时置 BB。

线数：**3 根**。

跟挂多少设备完全无关。

优先级：离仲裁器越近越高，固定，不可改。

优点：

```text
线最少，成本最低
加设备不用改仲裁器，把新设备串在链尾就行
```

缺点：

```text
① 对故障敏感：设备 1 坏了，BG 传不下去，后面全瘫
② 优先级固定：链尾的设备可能永远抢不到
③ BG 逐级传递有延迟，设备多时判优慢
```

408 常问"哪种仲裁方式对电路故障最敏感"。

答案：链式查询。

#### 计数器定时查询

```text
仲裁器里有个计数器
计数从 0 开始，数到 i，就把 BG 发给设备 i
设备 i 有请求 → 停，授权
没请求 → 计数 +1，问下一个
```

线数：**⌈log₂N⌉ + 2**。

N 个设备要 log₂N 根设备地址线，加 BR 和 BB 两根。

N = 8：

```text
⌈log₂8⌉ + 2 = 3 + 2 = 5 根
```

优先级：由计数初值决定。

初值从 0 开始，就是 0 号优先；初值从上次的位置开始，就是轮转（round robin）。

比链式公平。

缺点：

```text
每轮要一个一个地问，有计数开销
判优时间随设备数线性增长
线数比链式多
```

#### 独立请求

每个设备一对线，直接送仲裁器。

```text
设备1 ──BR1──→ ┐
设备2 ──BR2──→ ├ 仲裁器 ──BG1/BG2/BG3──→ 各设备
设备3 ──BR3──→ ┘
   ↑BB──────────────────────────────────┘
```

线数：**2N + 1**。

每个设备一根 BR、一根 BG，加一根公共 BB。

N = 8：

```text
2 × 8 + 1 = 17 根
```

优点：

```text
响应最快：所有请求并行送入仲裁器，一个门延迟就出结果
优先级可编程：固定优先级、轮转、公平队列都行
故障隔离好：一个设备坏了不影响别人
```

缺点：

```text
线最多，N 大时线数爆炸
仲裁器最复杂
```

三种方式对比：

| 方式 | 线数 | 优先级 | 判优速度 | 故障敏感 |
|---|---|---|---|---|
| 链式查询 | 3 | 固定，看位置 | 慢，逐级传 | 最敏感 |
| 计数器定时查询 | ⌈log₂N⌉+2 | 可轮转 | 中，逐个问 | 一般 |
| 独立请求 | 2N+1 | 可编程 | 最快，并行 | 不敏感 |

一句话记忆：

```text
链式用线换逻辑，独立请求用线换速度，计数器在中间
```

## 6. 408 怎么考

为什么这一章值得单独列考法？

因为总线的题有个特点：概念和计算混在一起，而且"总线周期"这个词本身有两种用法。

同样一道题，理解成"一拍"还是"一次完整事务"，答案差好几倍。

先把四种问法认出来，就不会在第一步上错。

四种问法：

```text
① 算带宽（给宽度、频率、事务拍数）
② 判断定时方式（给时序图或一段文字描述）
③ 比较仲裁方式（线数、优点、缺点）
④ 算总线周期数和传输时间
```

**例题一：带宽与传输时间。**

某同步总线数据线 64 位，时钟频率 200 MHz，每个时钟周期传送一次数据。

每次总线事务包含 1 个时钟的地址周期和 4 个时钟的数据周期。

求：（1）理想带宽；（2）实际带宽；（3）连续传 1 MB 数据需要多少时间。

解：

```text
每拍字节数 = 64 / 8 = 8 B

（1）理想 = 8 B × 200 × 10^6 = 1.6 × 10^9 B/s = 1.6 GB/s

（2）一次事务传 4 拍 × 8 B = 32 B
    一次事务耗时 5 拍 = 5 / (200 × 10^6) s = 25 ns
    实际 = 32 B / 25 ns = 1.28 × 10^9 B/s = 1.28 GB/s

（3）1 MB = 2^20 B = 1,048,576 B
    时间 = 1,048,576 / (1.28 × 10^9) = 8.192 × 10^-4 s ≈ 819 μs
```

答：理想 1.6 GB/s，实际 1.28 GB/s，传 1 MB 约 819 μs。

三个易错点：

```text
① 64 位当成 64 B，忘记除以 8
② 忘记地址周期，直接拿 1.6 GB/s 去除
③ 1 MB 按 10^6 算（主存语境用 2^20，题目说"1 MB 数据"一般按 2^20）
```

**例题二：总线周期数。**

某总线宽度 32 位，总线周期 50 ns，每个总线周期传送一次数据。

要把 4 KB 数据从内存传到磁盘控制器，需要多少个总线周期？耗时多少？

解：

```text
每周期传 32 / 8 = 4 B
4 KB = 4096 B
周期数 = 4096 / 4 = 1024 个
耗时 = 1024 × 50 ns = 51,200 ns = 51.2 μs
```

答：1024 个总线周期，51.2 μs。

**判断定时方式的信号词。**

```text
"统一时钟""固定时序""按最慢设备设计"  → 同步
"握手""REQ/ACK""不互锁/半互锁/全互锁" → 异步
"WAIT 信号""插入等待周期"             → 半同步（或同步 + 等待）
```

如果题目给了时序图，看两点：

```text
有没有独立时钟线
有没有一根"慢设备可以拉长周期"的线
```

有钟无等待线 → 同步。

无钟有 REQ/ACK → 异步。

有钟有 WAIT → 半同步。

**仲裁题的标准答法。**

问线数：

```text
链式      3
计数器    ⌈log₂N⌉ + 2
独立请求  2N + 1
```

问优先级：

```text
链式      固定，离仲裁器越近越高
计数器    计数初值可编程，能轮转
独立请求  仲裁算法可编程，最灵活
```

问可靠性（从高到低）：

```text
独立请求 > 计数器定时查询 > 链式查询
```

问速度（从快到慢）：

```text
独立请求 > 计数器定时查询 > 链式查询
```

四个问题的答案里，链式查询永远在最后。

它的唯一优势是线少。

## 7. 真实芯片里长什么样

为什么要看真机？

因为教材里的总线图是上个时代的模型：一条线挂所有设备。

真机早就不是这样了。

看一眼 `lspci` 打出来的树，你会立刻明白一件事——现代高速总线根本不共享，所以"仲裁"这个词在新设备里已经消失了。

先看总线的拓扑。

以下是简化示意：

```text
$ lspci -tv
-[0000:00]-+-00.0  Intel Corporation Host Bridge
           +-01.0-[01]----00.0  NVIDIA GA104 [GeForce RTX 3070]
           +-02.0-[02]----00.0  Samsung NVMe SSD Controller
           +-14.0  Intel USB 3.1 xHCI Controller
           +-1c.0-[03]----00.0  Intel Wi-Fi 6 AX201
```

`[01]`、`[02]`、`[03]` 是 PCI 总线号。

PCIe 的寻址是"总线号 + 设备号 + 功能号"，不是内存地址。

这属于 22 篇的 I/O 编址要处理的事。

再看链路的宽度和速率：

```text
$ lspci -vv -s 01:00.0 | grep -E 'LnkCap|LnkSta'
                LnkCap: Port #0, Speed 16GT/s, Width x16
                LnkSta: Speed 16GT/s (ok), Width x8 (downgraded)
```

`LnkCap` 是能力，`LnkSta` 是当前状态。

`downgraded` 就是"降速了"。

原因可能是插槽只焊了 8 条 lane、用了转接卡、或者信号完整性不过关自动协商降级。

算一下这条 x8 链路能跑多少：

```text
PCIe 4.0：每 lane 16 GT/s，128b/130b 编码
单 lane 有效带宽 = 16 × 10^9 × 128/130 / 8 ≈ 1.969 GB/s
x8 单向 = 1.969 × 8 ≈ 15.75 GB/s
x16 单向 = 1.969 × 16 ≈ 31.5 GB/s
```

注意 128/130 这个编码开销。

每 130 个比特里只有 128 个是数据，剩下 2 个是同步头。

```text
16 GT/s → 15.75 Gb/s 有效 → 约 1.97 GB/s
```

这就是"物理层速率"和"应用层带宽"的差。

再看 CPU 这一侧。

以下是简化示意：

```text
$ lscpu | grep -E 'Model name|Socket|Core|Thread|NUMA'
Model name:                       AMD Ryzen 9 7950X 16-Core Processor
Socket(s):                        1
Core(s) per socket:               16
Thread(s) per core:               2
NUMA node(s):                     1
```

16 个核，共享一条通往内存控制器的通道。

每个核都是主设备，都想这个周期访存。

仲裁器在 uncore 里，决定"这拍谁访存"。

这就是单总线结构的味道，只不过它现在叫"环形总线 + 内存控制器仲裁"。

一个关键变化：**现代高速总线是点对点的，不再仲裁。**

PCIe 一条链路只连两个端点。

多设备靠交换（switch）转发，靠路由表，不靠仲裁。

USB 是主机轮询，所有设备围着主机转，也没有总线仲裁。

所以仲裁这个考点，今天活在两个地方：

```text
多核共享内存控制器的访存仲裁
老式系统总线（VME、PCI、AMBA AHB）的硬件仲裁
```

408 考仲裁，考的是思想：线数、优先级、可靠性怎么权衡。

内存那一侧的总线，带宽更大也更难算清。

DDR5-5600 双通道：

```text
5600 MT/s × 8 B × 2 = 89.6 GB/s
```

但 CPU 核心里那 16 个核，通过环形总线共享这 89.6 GB/s。

单核能拿到的，只有几分之一。

这就是"共享总线"在今天最真实的样子：

```text
带宽总量上去了，但每个主设备能分到的，取决于仲裁策略
```

（以上 `lspci`、`lscpu` 输出为简化示意。）

## 8. 常见标准

为什么非要记这三个名字？

因为选择题喜欢问"下列哪个是串行总线""哪个支持热插拔""哪个可以拼 lane"。

这类题不需要推导，只需要认识。

三个标准，各记一句话就够用了。

三个必须知道名字的标准，每个一句话。

**PCIe（Peripheral Component Interconnect Express）**

串行、点对点、差分、多 lane 聚合，全双工。

一条 lane 是两对差分线（一发一收），x16 就是 32 对。

```text
PCIe 3.0  8 GT/s/lane   128b/130b   x16 ≈ 15.75 GB/s
PCIe 4.0  16 GT/s/lane  128b/130b   x16 ≈ 31.5 GB/s
PCIe 5.0  32 GT/s/lane  128b/130b   x16 ≈ 63 GB/s
```

**USB（Universal Serial Bus）**

串行、树形、主机轮询。

所有设备只能被主机问，不能主动发。

```text
USB 2.0  480 Mb/s  半双工
USB 3.2  5 / 10 / 20 Gb/s  全双工（多了两对差分线）
```

USB 的特点不是快，是"一根线搞定供电 + 数据 + 热插拔"。

**SATA（Serial ATA）**

串行、点对点，一条线只连一个盘。

```text
SATA 3.0  6 Gb/s，8b/10b 编码 → 600 MB/s
```

8b/10b 是每 10 位里 8 位数据，开销 20%。

所以 6 Gb/s 只有 4.8 Gb/s 有效，600 MB/s。

三个标准一句话对比：

```text
PCIe 比"宽"——可以拼 lane，从 x1 拼到 x16
USB  比"省"——一根线带供电，还能挂一树设备
SATA 比"稳"——只连一个盘，协议最简单
```

408 只需要记住：三个都是串行，都是点对点（USB 是主机-设备星形）。

## 9. 容易混淆的点

为什么这一节值得单独列？

因为总线这一章的失分，几乎全发生在"名字像、位置不同"上：总线宽度和字长、单总线结构和单总线数据通路、同步和异步。

每一个单独看都不难，难在题干里只写一个词，你得自己判断它落在哪一层。

五组。

**一、总线宽度 / 字长 / 地址线宽度。**

```text
总线宽度   数据线根数，决定一次搬多少
字长       CPU 一次能处理的位数
地址线宽度  决定寻址空间 2^n
```

三者常常相等，因为方便。

32 位机：32 位字长、32 位数据总线、32 位地址线。

但完全可以不等：

```text
8088   16 位字长，8 位数据总线，20 位地址线
现代 PC 64 位字长，64 位数据总线，48 位物理地址线
```

408 会在题干里故意混着说，看到"地址线 20 根"就要立刻想到 1 MB 寻址空间。

**二、总线频率 / 时钟周期 / 传输率。**

```text
100 MHz → 周期 10 ns
DDR → 每周期传两次 → 200 MT/s
```

408 说"总线频率 100 MHz"，就是每秒 1 亿个时钟。

说"数据传输率 200 MT/s"，是每秒 2 亿次传输。

两者差一个"每周期传几次"。

**三、"单总线结构" vs "单总线数据通路"。**

名字几乎一样，位置完全不同。

```text
单总线结构（本篇）    整个系统只有一条总线，在机箱/主板上
单总线数据通路（16 篇）CPU 内部所有寄存器挂一条总线，在芯片里
```

前者的问题是"设备抢总线"。

后者的问题是"一拍只能一个部件输出"。

408 里两个都考，看清楚题目问的是系统结构还是数据通路。

**四、链式查询"线少"不等于"好"。**

线最少（3 根），成本最低。

但它把可靠性、优先级灵活性全输掉了。

设备一坏，后面的全瘫。

**五、同步不一定比异步快。**

同步单次事务快，因为没有握手。

但它被迫按最慢设备设计。

总线上真挂了一个慢设备时，同步的固定拍数被拉到慢设备的速度，反而不如异步让快设备跑满。

```text
全快设备     同步快
有慢设备     异步可能更快
速度差异大   必须异步或半同步
```

## 10. 反直觉：宽度翻倍，带宽不一定翻倍

为什么这一节要专门拆开？

因为公式太好背了，背完很容易变成"宽度 ×2，带宽就 ×2"。

可真实的机器，宽度翻倍往往只拿到 1.6 到 1.9 倍，甚至更少。

差额从哪来，就是这一节要一件事一件事算清的东西。

公式写得很清楚：

```text
带宽 = 宽度 / 8 × 频率
```

宽度 ×2，频率不变，带宽才 ×2。

现实里，宽度翻倍几乎总伴随三件事。

**情形一：频率被拉低。**

```text
方案 A：32 位，100 MHz → 4 × 100M = 400 MB/s
方案 B：64 位，50 MHz  → 8 × 50M  = 400 MB/s
```

一模一样。

加宽意味着线更多、更密，串扰和偏斜变大，频率只能降。

这是并行总线的宿命：宽度和频率不可兼得。

**情形二：每次事务的固定开销不变。**

设一次事务传固定 S 字节，开销 h 拍，宽度 w 字节/拍。

宽度翻倍后，数据拍数减半，但开销拍数不变。

```text
S = 64 B，w = 4 B（32 位），h = 1 拍
拍数 = 64/4 + 1 = 17 拍
每拍 = 64/17 = 3.76 B

S = 64 B，w = 8 B（64 位），h = 1 拍
拍数 = 64/8 + 1 = 9 拍
每拍 = 64/9 = 7.11 B

带宽比 = 7.11 / 3.76 = 1.89，不是 2
```

开销越大，打折越狠。

```text
h = 4 拍：
32 位 → 64/4 + 4 = 20 拍 → 3.2 B/拍
64 位 → 64/8 + 4 = 12 拍 → 5.33 B/拍
比值 = 1.67
```

宽度翻倍，只拿到 1.67 倍。

这就是为什么算带宽时，一定要问"一次事务传多少拍、有几拍是开销"。

**情形三：同步定时按最慢设备设计。**

宽度翻倍后，能挂的设备更多、更杂。

最慢的那个决定全体拍数。

一个 100 ns 的设备挂上来，整条总线都按 100 ns 走。

宽度带来的收益，被等待吃掉了。

**情形四：真实系统里被最窄的那一段卡住。**

`lspci` 里那个 `downgraded` 就是这条。

物理上 16 条 lane，跑起来只有 8 条。

因为上游的 switch 只有 x8，或者插槽只焊了 8 条。

带宽不是由最宽的一段决定，是由最窄的一段决定。

木桶原理，在总线上是字面意义的。

所以正确的心智模型是：

```text
名义带宽 = 宽度 × 频率 / 8     ← 这是上限
实际带宽 = min(每一段链路的能力) / (1 + 开销占比)
```

宽度翻倍，如果频率、开销、瓶颈段任何一项没跟上，你就拿不到 2 倍。

**"参数表上的带宽"和"实测带宽"永远差一截，原因就是这三个折损。**

这也是为什么 PCIe 从 3.0 到 4.0 只是"速率翻倍"，实际 SSD 性能往往只提升六七成。

**情形五：宽度翻倍了，但通道数减半。**

伺服器主板常见这种做法：

```text
2 条 32 位通道 → 8 B/拍 × 2 = 16 B/拍
1 条 64 位通道 → 8 B/拍 × 1 = 8 B/拍
```

宽度翻倍，通道减半，总带宽反而腰斩。

因为总带宽看的是"所有通道加起来每拍能搬多少字节"。

```text
总带宽 = 单通道宽度 / 8 × 单通道频率 × 通道数
```

加通道比加宽度便宜得多。

一条 64 位通道要走 64 根数据线，两条 32 位通道只要各走 32 根。

但两条通道可以并行访问不同的存储体（08 篇的低位交叉）。

所以真实的内存子系统，永远是"多条窄通道"而不是"一条宽通道"。

### 自检三问

**一问：如果去掉总线仲裁，把所有设备直接并联到数据线上，会怎样？**

答：两个主设备同时写，一个写 1 一个写 0，数据线上的电平卡在中间，从设备读到的是不确定值；更糟的是电流从高电平那一端直接灌进低电平那一端，接口容易发热，严重的会烧掉。所以仲裁不是"性能优化"，是共享总线能存在的前提。

**二问：64 位、100 MHz 的总线和 32 位、200 MHz 的总线，哪条快？为什么不能只看宽度？**

答：两条的名义带宽都是 800 MB/s：`8 B × 100 M` 和 `4 B × 200 M`。宽度只决定"一次搬多少"，频率决定"一秒搬几次"，带宽是两者相乘。所以一看到"宽度翻倍"，先要问频率有没有被拉低，再问一次事务里有没有地址拍、等待拍这些不传数据的拍。

**三问：数据线 64 位、时钟 200 MHz、每次事务 = 1 拍地址 + 4 拍数据，连续传 1 MB 要多久？**

答：每拍 8 B，理想带宽 `8 × 200 M = 1.6 GB/s`；一次事务传 `4 × 8 = 32 B`，耗时 5 拍 = 25 ns，实际带宽 `32 B / 25 ns = 1.28 GB/s`；`1 MB = 2^20 B = 1,048,576 B`，时间 `1,048,576 / 1.28×10^9 ≈ 819 μs`。和本篇例题一的数字一致，差别只在有没有把地址拍算进开销。

## 11. 小结 + 下一篇

三句话：

```text
总线是一组分时共享的线，把 O(N²) 的连接压成 O(N)，代价是争用
带宽 = 宽度 / 8 × 频率，这是上限，不是实测值
定时管"什么时候传"，仲裁管"谁先传"
```

三种定时：

```text
同步    统一时钟，快，但要按最慢设备设计
异步    握手，灵活，但慢
半同步  时钟 + WAIT 线，折中
```

三种仲裁：

```text
链式查询       3 根线，最省，最不灵活，最怕故障
计数器定时查询  ⌈log₂N⌉ + 2 根，优先级可轮转
独立请求        2N + 1 根，最快最贵
```

三个标准：

```text
PCIe  串行点对点多 lane，x16 约 15.75 GB/s（3.0）
USB   串行星形，主机轮询
SATA  串行点对点，6 Gb/s → 600 MB/s
```
