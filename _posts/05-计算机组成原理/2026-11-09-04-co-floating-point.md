> **读这篇之前，你只需要知道**：二进制小数是“小数点后每一位依次表示 1/2、1/4、1/8……”，和十进制小数一个道理；科学计数法是把一个数写成“有效数字 × 10 的几次方”，二进制版本就是把 10 换成 2；定点数是小数点位置固定不动的数（详见 [03 篇](/posts/co-fixed-point-arithmetic-alu/)）。
> **这篇讲什么**：0.1 为什么存不进内存、32 位里哪几位管“小数点挪了几格”、哪几位管“有效数字有多长”，以及两个浮点数相加为什么第一步不是加，而是把小数点对齐。
> **一个类比**：浮点数像一张科学计数法的小卡片，上面写着“符号 + 有效数字 + 小数点挪了几格”。尾数是那串有效数字，相当于尺子的刻度有多细；阶码是挪了几格，相当于尺子有多长。刻度越细，量程就越短，两者永远在抢同一块地方。


第 00 篇开头那行代码，值得再看一次。

```python
>>> 0.1 + 0.2
0.30000000000000004
```

已经知道原因了：0.1 的二进制是无限循环小数。

现在把这句话拆到底。

```text
0.1₁₀ = 0.000110011001100110011001100…₂
```

一个 32 位的容器，只能装下前面一段。

装进去的那个东西，已经不是 0.1 了。

```text
0.1 单精度实际存的是 0x3DCCCCCD
它等于 0.100000001490116119384765625
```

差了大约 1.5×10⁻⁹。

不是四舍五入的错，是“存不下”。

**反直觉的点在这里：**

```text
浮点数不是“精度低一点的实数”。
它是“科学计数法 + 有限位”。

两个浮点数之间，还有无穷多个实数。
但能被表示的，只有有限个。
```

这一篇把“有限个”这件事数清楚。

## 1. 定点数的两个不够

先问：既然定点数又简单又快，为什么还要另造一套浮点？
因为“够用”的标准变了。
定点数能表示的那批数，间隔是均匀的，间隔一固定，它就只能在一个很窄的区间里干活。
一旦要同时处理“星系的质量”和“原子的半径”，这套格子就不够用了。

定点数在 03 篇已经算得明明白白。

它的问题是范围。

```text
16 位定点（纯整数）：
  范围 −32768 ~ +32767
  最小间隔 1

想表示 6.02×10²³ 这样的数？装不下。
想表示 1.6×10⁻¹⁹（一个电子电荷）？也装不下。
```

物理常数跨了 40 多个数量级。

定点数一个也接不住。

**第一个不够：范围。**

**第二个不够：精度和范围不能同时要。**

```text
32 位定点：
  都当整数用 → 能到 21 亿，间隔 1，没有小数
  都当小数用 → 精度 2⁻³¹，范围只有 ±2

想“又能算星系质量，又能算原子半径”，定点做不到。
```

解决办法是让小数点浮动。

```text
定点：小数点位置固定，值 = 数 × 2⁰
浮点：小数点位置随数变，值 = 尾数 × 2^阶码
```

一个数拆成两半。

```text
12.375 = 1.100011₂ × 2³
         └──┬──┘    └┬┘
          尾数      阶码
```

尾数管有效数字，阶码管小数点在哪。

范围交给阶码，精度交给尾数。

两者范围差多少个数量级，看一眼就知道这笔买卖值不值。

```text
格式          范围                有效十进制位
32 位定点     ±2.1×10⁹           约 9–10 位（全当整数）
32 位浮点     ±3.4×10³⁸          约 7 位
64 位浮点     ±1.8×10³⁰⁸         约 16 位

浮点用“少两位精度”，换来了“多 29 个数量级的范围”。
```

这套格式不是一开始就统一的。

```text
1970 年代：每家的浮点格式都不一样，同一个程序换台机器结果就变
1985 年：IEEE 754 发布，单精度 1+8+23、双精度 1+11+52 定案
2008 年：加入 half（FP16）和更多舍入规则
2019 年：加入 bfloat16 一类更短格式的规范化讨论

今天 x86、ARM、RISC-V、GPU 用的都是这套编码。
```

**IEEE 754**：美国电气电子工程师协会（IEEE）在 1985 年发布的浮点运算标准。
它规定三件事：位怎么摆、运算怎么做、舍入（rounding，结果末尾多出来的位怎么处理）怎么定。
所以同一段浮点程序，在不同厂家的机器上会得到同一个结果——在它之前，换台机器数字就变。

## 2. 浮点表示：阶码加尾数

先问：小数点既然要浮动，那“浮到哪儿了”这件事记在哪儿？
必须记下来，否则同一个尾数配上不同的阶码，数值就差好几倍甚至几万倍。
于是浮点数被拆成两部分：尾数管“有效数字是什么”，阶码管“小数点挪了几格”。
再单放一位符号表示正负，就是 IEEE 754 里那三个字段。
理解了这三个字段，那张位图就只是给它们分配了具体的位数。

一个浮点数由两部分组成。

```text
尾数（mantissa / significand）：有效数字，决定精度
阶码（exponent）：2 的幂次，决定范围
符号（sign）：正负
```

通用格式。

```text
 ┌───┬────────────┬──────────────────────┐
 │符号│   阶码 E    │       尾数 M          │
 │ 1 │  e 位      │       m 位            │
 └───┴────────────┴──────────────────────┘

值 = (−1)^S × M × 2^E
```

关键认识：**尾数和阶码的位数分配是一场交易。**

```text
尾数多位 → 精度高，范围小
阶码多位 → 范围大，精度低

单精度：8 位阶码 + 23 位尾数  → 范围 ±10^±38，精度 7 位十进制
双精度：11 位阶码 + 52 位尾数 → 范围 ±10^±308，精度 16 位十进制
```

这个交易在 1950 年代就定了形。

今天的 IEEE 754 只是把位数写成了标准。

还有两个细节值得先定下来。

```text
尾数用什么码？  用原码（符号另存，尾数是纯小数 1.xxx）
阶码用什么码？  用移码（IEEE 754 的偏置，可以直接比大小）

为什么尾数不用补码？
  因为浮点主要做乘除和加减，尾数只需要“绝对值 + 符号”。
  原码的乘除规则简单：绝对值相乘，符号异或。
  补码尾数在乘除时还要处理符号位，反而麻烦。
```

这里的**偏置（bias）**要说清：阶码存进机器时，存的不是真实指数 e，而是 e 加上一个固定的数，读的时候再把它减掉。
加这个数的唯一目的，是把“−126 到 +127”这种带负号的区间，平移到“1 到 254”这种全正的区间，好让硬件直接拿无符号比较器比大小。

所以一个浮点数是“两套编码拼起来的”。

```text
符号：1 位，单独放
阶码：k 位移码
尾数：m 位原码（纯小数部分）
```

这也是 408 判断题爱考的点。

```text
“浮点数的阶码用补码表示”          → 错，用移码
“浮点数的尾数用补码表示”          → 错，用原码（IEEE 754 语境）
“浮点数比定点数表示范围大、精度高” → 错，范围大，同位数下精度更低
```

## 3. 规格化：尾数最高位为什么要为 1

先看一个麻烦。

```text
12.375 可以写成：
  1.100011 × 2³
  0.1100011 × 2⁴
  11.00011 × 2²
  110.0011 × 2¹
```

同一个数，无穷多种写法。

不统一就没法比较，也没法做加减。

**如果没有规格化，会怎样？**

上面那四种写法就全都成立，机器没法判断它们其实是同一个数。

比较两个浮点数大小时，就不能先比阶码再比尾数，而要先把小数点对齐再逐位比，比较器复杂度翻几倍。

更糟的是“尾数最高位永远是 1”这个前提没了，隐藏位也就藏不了，等于白丢一位精度。

这一位在单精度里就是 7 位十进制有效数字的最后一位，几百万次累加之后就是看得见的误差。

于是规定：**规格化（normalization）。**

```text
尾数的最高有效位必须是 1。
即尾数形如 1.xxxxxxxx
```

规定之后，每个数只有一种写法。

```text
12.375 → 只能是 1.100011 × 2³
```

好处有三个。

```text
① 表示唯一，比较大小可以先比阶码再比尾数
② 精度最大化，不浪费前导零
③ 隐藏位：既然最高位永远是 1，那就不用存
```

第三条是最妙的。

```text
规格化后尾数一定是 1.xxxx 的形式，
那个开头的 1 是固定的，存它纯属浪费。

于是把它藏起来（hidden bit），
尾数字段里只存小数点后面那几位。

单精度：尾数字段 23 位，实际精度 24 位
双精度：尾数字段 52 位，实际精度 53 位
```

白赚一位精度。

代价是：读的时候必须记得把那个 1 补回去。

```text
尾数字段 100011000…
实际尾数 1.100011000…
         ↑
         这个 1 是补的，不在存储里
```

408 里最常见的失分点就是这个。

```text
“尾数 23 位” → 错，隐含位算上是 24 位
“精度 23 位” → 错，精度是 24 位二进制有效数字
```

还有一类例外：非规格化数。

那个开头的 1 不补，改成补 0。

第 9 节讲。

规格化还有个教材版本的定义，和 IEEE 754 长得不一样。

```text
教材（纯小数形式）： 1/2 ≤ |M| < 1
  M 写成 0.1xxxx 或 1.0xxxx（补码表示负数）
  位数更省，但没有隐藏位

IEEE 754（隐含 1 的形式）： 1 ≤ |M| < 2
  M 写成 1.xxxx，开头的 1 不存
  白赚一位精度

两者是同一个数的两种写法：
  教材：0.1100011 × 2⁴
  IEEE：1.100011  × 2³
        阶码差 1，尾数差一倍
```

408 题干如果写“尾数用补码、含 1 位符号位、纯小数”，那就是教材版本。

如果写“IEEE 754 单精度”，那就是隐含 1 的版本。

两种不能混着算。

读题时先确认一句话：尾数是 0.1xxx 还是 1.xxx。

这一句话决定阶码要不要差 1，决定答案对不对。

## 4. IEEE 754：1+8+23 与 1+11+52

IEEE 754 是目前所有主流机器都遵守的浮点标准。

单精度（binary32）的布局。

```text
 31 30        23 22                              0
┌──┬────────────┬────────────────────────────────┐
│ S│  阶码 E(8)  │          尾数 M(23)             │
└──┴────────────┴────────────────────────────────┘
 1 位    8 位              23 位

值 = (−1)^S × 1.M × 2^(E−127)
偏置（bias）= 127
```

双精度（binary64）的布局。

```text
 63 62          52 51                            0
┌──┬──────────────┬──────────────────────────────┐
│ S│  阶码 E(11)   │         尾数 M(52)            │
└──┴──────────────┴──────────────────────────────┘
 1 位     11 位               52 位

值 = (−1)^S × 1.M × 2^(E−1023)
偏置（bias）= 1023
```

两句话记住。

```text
单精度：1 + 8 + 23 = 32，偏置 127
双精度：1 + 11 + 52 = 64，偏置 1023
```

为什么用移码而不是补码存阶码。

02 篇说过：移码保持大小顺序，浮点比较可以先比阶码。

为什么偏置是 127 而不是 128。

```text
因为阶码字段的 0 和 255 被特殊值占用了：
  E = 0   → 非规格化数，或 ±0
  E = 255 → ±∞，或 NaN

所以规格化数的阶码只能用 1 ~ 254。
对应的真实指数是 1−127 = −126 到 254−127 = +127。

偏置取 127 而不是 128，正好让可用区间对称：
  −126 ~ +127，加起来 254 个值
```

这个不对称是设计出来的，不是巧合。

```text
如果偏置取 128，可用区间是 −127 ~ +126，也能用，
但最小规格化数会小一位，非规格化数的尾巴就短一位。
IEEE 754 选了 127，留出完整的非规格化区间。
```

## 5. 从十进制到 32 位：五步写完一个编码

先问：为什么要死记这五步，而不是记一个公式？
因为公式只给结果，五步给的是过程；408 要你在卷面上把过程写出来，出错时也只有分步才能定位。
这五步每一步都对应一个具体动作：定符号、转二进制、挪小数点、加偏置、去隐藏位。
把动作记成顺序，比背一个长公式可靠得多。

这是本章最该练熟的动作。

例题：把 −12.375 写成单精度 IEEE 754 编码。

**第一步：定符号位。**

```text
−12.375 是负数 → S = 1
```

**第二步：把绝对值转成二进制。**

```text
整数部分 12 = 1100
小数部分 0.375：
  0.375 × 2 = 0.75   取 0
  0.75  × 2 = 1.5    取 1
  0.5   × 2 = 1.0    取 1
  → 0.011

合起来：12.375 = 1100.011₂
```

验算小数部分：0.011₂ = 0.25 + 0.125 = 0.375 ✓

**第三步：规格化，移小数点。**

```text
1100.011
  ↓ 小数点左移 3 位
1.100011 × 2³

尾数 = 1.100011
阶码真值 e = 3
```

**第四步：算阶码字段。**

```text
E = e + 127 = 3 + 127 = 130
130 = 1000 0010₂
```

验算：130 = 128 + 2 = 1000 0010 ✓

**第五步：填尾数，去掉隐藏位。**

```text
尾数 1.100011
去掉隐藏的 1 → 100011
后面补 0 到 23 位：

  100011 0000 0000 0000 0000
  └────┬────┘
   有效 6 位 + 17 个 0 = 23 位
```

拼起来。

```text
S     E          M
1  | 10000010 | 10001100000000000000000

合并成 32 位：
1100 0001 0100 0110 0000 0000 0000 0000
  C    1    4    6    0    0    0    0

结果：0xC1460000
```

反验一遍。

```text
0xC1460000
= 1100 0001 0100 0110 0000 …
  S = 1
  E = 1000 0010 = 130  →  e = 130 − 127 = 3
  M = 1000110…

尾数补隐藏位：1.100011
值 = −1.100011₂ × 2³
   = −(1 + 0.5 + 0.03125 + 0.015625) × 8
   = −1.546875 × 8
   = −12.375 ✓
```

五步走完，一个 32 位编码。

四步是机械的，只有第二步可能出错（小数转二进制）。

练习时把第二步算清楚，剩下的都是填空。

再练一个带无限循环的。

```text
0.1 的单精度编码：

0.1 × 2 = 0.2   0
0.2 × 2 = 0.4   0
0.4 × 2 = 0.8   0
0.8 × 2 = 1.6   1
0.6 × 2 = 1.2   1
0.2 × 2 = 0.4   0   ← 从这里开始循环 0110
…

0.1 = 1.1001100110011… × 2⁻⁴

e = −4，E = −4 + 127 = 123 = 0111 1011
尾数取 23 位：1001 1001 1001 1001 1001 101（最后一位进位）

S=0, E=01111011, M=10011001100110011001101
→ 0x3DCCCCCD
```

这就是那个“存进去了但不是 0.1”的东西。

## 6. 408 怎么考

浮点这一章的题目，一半是编码题，一半是过程题。

```text
选择题：
  给一个十进制数，问单精度编码（十六进制）
  给一个编码，问真值
  问阶码偏置、问隐藏位、问精度位数
  问特殊值的编码（0、∞、NaN）
  问非规格化数的意义
  问浮点加减的步骤顺序
  问对阶的方向

综合题：
  写成完整的浮点加减过程（对阶、加减、规格化、舍入）
  与定点加减合并：给出阶码溢出与尾数溢出的处理
```

五条套路。

```text
① 编码题按五步走：符号、转二进制、规格化、算阶码、填尾数。
② 求真值按反序：拆三段、补隐藏位、算 e、乘回去。
③ 见到“0x…000”结尾的编码，先想它是不是整数或 2 的幂。
④ 浮点加减一定先对阶，对阶一定小阶向大阶。
⑤ 判断溢出看阶码，不看尾数。
```

例题（自拟，408 风格）。

```text
(1) 写出 −12.375 的单精度 IEEE 754 编码（十六进制）。
(2) 求 0x41A00000 对应的十进制真值。
(3) 用 1.1001×2³ 与 1.0100×2¹ 走一遍浮点加法五步，给出结果。
(4) 用双精度算 10¹⁶ + 1.0，结果是多少？为什么？
```

答案与验算。

```text
(1) 见第 5 节：0xC1460000

    S=1, E=130=1000 0010, M=1000110…0
    1100 0001 0100 0110 0000 0000 0000 0000
    = 0xC1460000 ✓

(2) 0x41A00000
    = 0100 0001 1010 0000 0000 0000 0000 0000
      S = 0
      E = 1000 0011 = 131  →  e = 131 − 127 = 4
      M = 010 0000…  →  尾数 1.01₂

    值 = +1.01₂ × 2⁴ = 1.25 × 16 = 20.0

    反验：20 = 10100₂ = 1.01 × 2⁴
          E = 4+127 = 131 = 1000 0011 ✓
          M = 01 后补零 ✓

(3) 12.5 = 1.1001 × 2³，2.5 = 1.0100 × 2¹

    ① 对阶：小阶向大阶看齐
       阶差 = 3 − 1 = 2
       y 的尾数右移 2 位：1.0100 → 0.0101
       y 的阶码改为 3

    ② 尾数相加
       1.1001 + 0.0101 = 1.1110

    ③ 规格化
       1.1110 已规格化（最高位是 1），阶码仍为 3

    ④ 舍入
       本例无位丢失，不需要舍入

    ⑤ 溢出判断
       阶码 3 在 −126 ~ +127 之间，无溢出

    结果：1.1110 × 2³ = 1.875 × 8 = 15.0
    验算：12.5 + 2.5 = 15 ✓

    IEEE 754 编码核对：15 = 1.111 × 2³
      E = 130 = 1000 0010，M = 111 后补零
      → 0x41700000

(4) 10¹⁶ + 1.0 = 10¹⁶

    双精度尾数 52 位 + 隐藏位 = 53 位
    2⁵³ = 9007199254740992 ≈ 9.007×10¹⁵

    10¹⁶ > 2⁵³，此时相邻两个可表示数之间的间隔已经变成 2。
    10¹⁶ 是偶数，正好在格点上。
    10¹⁶ + 1 落在两个格点正中间，按“就近舍入到偶数”规则回到 10¹⁶。

    所以 1.0 被整个吞掉了。
```

第(4)问是这一篇最实用的一题。

```text
累加大量小数时，先加小的、后加大的，结果会更准。
反过来（先加大数），小的会被一个个吞掉。
```

## 7. 真实芯片里长什么样

浮点不是软件模拟的，硬件里有专门的部件。

```text
FPU（floating-point unit）：浮点加减乘除
  x86：x87（80 位扩展精度，历史遗留）+ SSE2（标量 double）
  ARM：AArch64 的标准浮点，VFP / NEON
```

延迟大概是这个量级。

```text
（简化示意，不同微架构差异很大）
单精度加法：3–4 个周期
单精度乘法：4–5 个周期
单精度除法：10–20 个周期
平方根：15–25 个周期
```

除法比加法慢五倍，这是“能乘就别除”的硬件原因。

有一条指令值得单独说：FMA。

```text
FMA（fused multiply-add）：d = a × b + c

普通做法：先算 a×b（舍入一次），再加 c（再舍入一次）
FMA：      中间结果不舍入，只在最后舍入一次
```

两个好处。

```text
① 精度更高：少一次舍入误差
② 性能更好：一条指令做两次运算，峰值 FLOPS 翻倍
```

所以 TOP500 的峰值算力都按 FMA 之后的数字算。

舍入模式是可控的。

先问：为什么舍入还要分模式？
因为“丢掉的那几位”怎么处理，会改变结果的偏向。
一律向上进，累加一百万次就整体偏大；一律向下舍，就整体偏小。
在金融、物理仿真这类要累加海量数据的场合，这种系统性偏差比单次误差更致命。

```text
IEEE 754 定义了 5 种舍入方式，常用四种：
  就近舍入到偶数（round to nearest, ties to even）← 默认
  向零舍入（truncate）
  向正无穷（round up）
  向负无穷（round down）

x86：MXCSR 寄存器里的 RC 字段控制
ARM：FPCR 寄存器里的 RMode 字段控制
```

默认选“就近到偶数”的原因很实际。

```text
它可以避免统计上的偏差。
如果一律“四舍五入”，大量累加会系统性地偏大。
“到偶数”让 .5 的情况一半进一半舍，偏差抵消。
```

IEEE 754 还定义了 5 种浮点异常。

```text
无效运算（invalid）    如 0/0、∞−∞、√负数  → 产生 NaN
除零（divide by zero） 如 1/0             → 产生 ∞
上溢（overflow）       结果超出最大可表示数 → 产生 ∞
下溢（underflow）      结果小于最小规格化数 → 变非规格化数或 0
不精确（inexact）      舍入丢了信息        → 置标志位
```

注意最后一条。

```text
“不精确”在浮点里是常态，不是错误。
0.1 + 0.2 每次都会置不精确标志。
语言默认不报，因为报了就没法用了。
```

非规格化数在硬件里是有代价的。

```text
（简化示意）
多数 x86 / ARM 核心对非规格化数做硬件处理，
但历史上不少实现走“慢路径”：一次运算几十到上百个周期。

这就是某些数值程序里“突然变慢 100 倍”的原因：
中间结果下溢成了非规格化数。
```

机器学习加速器里还有更短的格式。

```text
FP16：1 + 5 + 10，偏置 15，范围 ±65504
bfloat16：1 + 8 + 7，阶码与单精度相同，尾数只剩 7 位
TF32：1 + 8 + 10（NVIDIA 的说法）

它们都是“IEEE 754 的截断版”，不是新标准。
取舍一样：砍尾数保范围，或者砍范围保精度。
```

## 8. 反过来：从 32 位编码求真值

编码求真值，就是五步倒着走。

三步拆字段，两步算回去。

```text
① 拆：S / E / M
② 算阶：e = E − 127
③ 补位：尾数前面补 1.（规格化数）
④ 移位：把小数点按 e 移动
⑤ 转十进制
```

练四个，从易到难。

```text
① 0x3F800000
   0011 1111 1000 0000 …
   S=0, E=0111 1111=127 → e=0, M=0
   值 = 1.0 × 2⁰ = 1.0

② 0x40000000
   S=0, E=1000 0000=128 → e=1, M=0
   值 = 1.0 × 2¹ = 2.0

③ 0xC1200000
   1100 0001 0010 0000 …
   S=1, E=1000 0010=130 → e=3, M=010 0000…
   尾数 1.01₂ = 1.25
   值 = −1.25 × 2³ = −10.0

④ 0x3E99999A
   S=0, E=0111 1101=125 → e=−2, M=00110011001100110011010
   尾数 = 1.00110011001100110011010₂
        = 1 + 0x19999A / 2²³
        = 1 + 1677722 / 8388608
        = 1.2000000476837158
   值 = 1.2000000476837158 × 2⁻² = 0.30000001192092896
```

第④个就是 `0.1f + 0.2f` 的结果。

再补一个更有名的。

```text
0x40490FDB

0100 0000 0100 1001 0000 1111 1101 1011
S = 0
E = 1000 0000 = 128  →  e = 1
M = 10010010000111111011011

尾数 1.10010010000111111011011₂
值 = 1.57079637050628662 × 2 = 3.14159274101257324
```

这是 float 版的 π。

它不等于 3.141592653589793。

```text
double π：3.141592653589793
float  π：3.14159274101257324
差约 8.7×10⁻⁸，正好是单精度 7 位有效数字的极限。
```

所以拿 float 算圆周率到十几位，是白费力气。

对照一下：

```text
单精度：0.1f + 0.2f = 0.30000001192092896
双精度：0.1  + 0.2  = 0.30000000000000004
十进制：            0.3
```

三个都不一样。

尾数位数越多，误差越小，但永远不为零。

这就是“存不下”的定量版本。

## 9. 特殊值：±0、±∞、NaN、非规格化数

先问：为什么非要浪费两个阶码值去造这些“不是数”的东西？
因为现实里的计算会失败：除以零、开负数平方根、上溢、下溢。
如果没有一套约定的表示，程序出错时只能拿到一个乱七八糟的数，还不知道自己错了。
把这些情况编码成特殊值，错误就能沿着计算一路传播，最后被一次检查抓住。

阶码字段的 0 和最大值被留出来了。

```text
E = 0，M = 0    → ±0
E = 0，M ≠ 0    → 非规格化数
E = 255，M = 0   → ±∞
E = 255，M ≠ 0   → NaN
```

单精度的具体编码。

| 值 | 十六进制 | 说明 |
|---|---|---|
| +0 | 0x00000000 | 全 0 |
| −0 | 0x80000000 | 只差符号位 |
| 最小非规格化正数 | 0x00000001 | ≈ 1.4×10⁻⁴⁵ |
| 最小规格化正数 | 0x00800000 | 2⁻¹²⁶ ≈ 1.18×10⁻³⁸ |
| 最大规格化数 | 0x7F7FFFFF | ≈ 3.4028235×10³⁸ |
| +∞ | 0x7F800000 | 阶码全 1，尾数全 0 |
| −∞ | 0xFF800000 | |
| 静默 NaN | 0x7FC00000 | 阶码全 1，尾数最高位 1 |

逐个核对。

```text
最小规格化正数：E = 0000 0001 = 1 → e = 1 − 127 = −126
               M = 0 → 1.0 × 2⁻¹²⁶ ✓
               编码 0000 0001 0000… = 0x00800000 ✓

最大规格化数：E = 1111 1110 = 254 → e = 127
             M = 111…1 (23 个 1) → 1.111…1 = 2 − 2⁻²³
             值 = (2 − 2⁻²³) × 2¹²⁷ ≈ 3.4028235 × 10³⁸ ✓
             编码 0111 1111 0111 1111 … = 0x7F7FFFFF ✓

∞：E = 1111 1111 = 255，M = 0
    编码 0111 1111 1000 0000 … = 0x7F800000 ✓
```

±0 和 NaN 各有讲究。

```text
+0 和 −0 在比较时相等（0.0 == -0.0 为真），
但符号不同，1/+0 = +∞，1/−0 = −∞。
```

```text
NaN 与任何值比较都为假，包括它自己。
所以 x != x 是判断 NaN 的经典写法。

NaN 分静默（quiet）和信号（signaling）两类，
前者传播，后者触发无效运算异常。
```

**非规格化数（denormal / subnormal）是最需要理解的一类。**

```text
E = 0，M ≠ 0
值 = 0.M × 2⁻¹²⁶
   ↑
   隐藏位补 0，不是补 1
```

为什么要专门留这一类。

```text
如果没有非规格化数：
  最小正数是 2⁻¹²⁶ ≈ 1.18×10⁻³⁸
  比它小的数只能直接变成 0
  于是出现“突然掉到零”的断崖（abrupt underflow）

有了非规格化数：
  从 2⁻¹²⁶ 往下平滑地衰减到 2⁻¹⁴⁹ ≈ 1.4×10⁻⁴⁵
  精度逐渐损失，但不会断
  这叫渐进下溢（gradual underflow）
```

代价是精度。

```text
非规格化数的有效位数少于 24 位，
越靠近 2⁻¹⁴⁹，有效位越少，最后只剩 1 位。
```

一句话记住。

```text
非规格化数 = 用精度的损失，换范围的连续。
```

算一个最小非规格化数，把公式用一遍。

```text
0x00000001
S=0, E=0, M=00000000000000000000001

非规格化：值 = 0.M × 2⁻¹²⁶
M = 2⁻²³
值 = 2⁻²³ × 2⁻¹²⁶ = 2⁻¹⁴⁹ ≈ 1.401298×10⁻⁴⁵
```

再算最大的非规格化数。

```text
0x007FFFFF
M = 1 − 2⁻²³
值 = (1 − 2⁻²³) × 2⁻¹²⁶ ≈ 1.1754942×10⁻³⁸
```

它和最小规格化数 2⁻¹²⁶ 只差一点点。

```text
最大非规格化：(1 − 2⁻²³) × 2⁻¹²⁶
最小规格化：  1.0 × 2⁻¹²⁶

两者紧挨着，中间没有缝。
这就是“渐进下溢”的样子：一路衰减到 0，不跳崖。
```

## 10. 浮点加减五步

先问：为什么浮点加法不能像整数那样直接加？
因为两个数的小数点不在同一处。
1.1001 × 2³ 和 1.0100 × 2¹ 直接逐位相加，等于把 12.5 和 2.5 的小数点按错位对齐，加出来的东西没有任何意义。
所以第一步不是加，而是把两个数的小数点搬到同一处。
后面四步，都在收拾这次搬运留下的尾巴。

浮点加减比整数麻烦，因为小数点不在一起。

五步，顺序不能换。

```text
① 对阶：把小阶的尾数右移，阶码补到和大阶一样
② 尾数加减：同定点加减
③ 规格化：结果尾数最高位必须是 1
④ 舍入：处理右移和规格化时丢掉的位
⑤ 溢出判断：看阶码是否超出范围
```

拿 12.5 + 2.5 走一遍。

```text
x = 1.1001 × 2³ = 12.5
y = 1.0100 × 2¹ = 2.5
```

**① 对阶。**

```text
阶差 = 3 − 1 = 2
小阶向大阶看齐 → y 的阶码改成 3，尾数右移 2 位

y：1.0100 × 2¹  →  0.0101 × 2³
        └─右移 2 位─┘
```

**② 尾数加减。**

```text
   1.1001
 + 0.0101
 --------
   1.1110
```

**③ 规格化。**

```text
1.1110 的最高位已经是 1，不需要再动。
阶码保持 3。
```

**④ 舍入。**

```text
本例右移 2 位时没有丢掉非零位（1.0100 → 0.0101，丢的是 00）
无舍入误差。
```

**⑤ 溢出判断。**

```text
阶码 3，落在 −126 ~ +127 之内，无溢出。
```

结果。

```text
1.1110 × 2³ = 1.875 × 8 = 15.0 ✓
```

再走一个会产生舍入的。

```text
1.0000 × 2⁰ + 1.0000 × 2⁻⁴

① 对阶：阶差 4，小阶尾数右移 4 位
   1.0000 → 0.00010000
   若尾数只有 4 位小数，右移后变成 0.0001，末 4 位被挤出

② 相加：1.0000 + 0.0001 = 1.0001

③ 规格化：已规格化

④ 舍入：被挤出的 0000 位是 0，无误差

⑤ 溢出判断：阶码 0，正常

结果 1.0001 × 2⁰ = 1.0625 ✓（1 + 0.0625）
```

注意第①步的设计。

```text
尾数右移时，被挤出去的位不能直接扔。
要保留几位“保护位”（guard bits），
否则连续的舍入误差会累积。
```

真实硬件通常保留 2–3 位保护位。

```text
（简化示意）
运算时尾数用比存储更宽的宽度（比如 26 位而非 24 位），
最后一步才舍入回 24 位。
```

408 里还有一个常被忽略的细节：尾数用什么符号位参与运算。

```text
浮点加减时，尾数通常用双符号位（变形补码）参与运算。
  相加后：
    01 → 正溢出  → 尾数右移一位，阶码加一
    10 → 负溢出  → 尾数右移一位，阶码加一
    00 / 11 → 正常

为什么右移一位就能修好？
  因为尾数溢出只是“整数部分多了一位”，
  右移一位等于小数点左移一位，数值不变，阶码加一补回来。
```

这个动作和第 03 篇的定点溢出判断是一回事。

区别在于：定点溢出是错误，浮点尾数溢出是正常现象，改一改就好。

真正致命的只有阶码溢出。

```text
阶码超出上限 → 上溢（overflow），结果置 ±∞
阶码低于下限 → 下溢（underflow），结果置 0 或非规格化数

尾数怎么进位都不会“错”，阶码一出界就全完了。
```

所以浮点加减的第五步看的是阶码，不是尾数。

这一点和定点加减完全相反。

## 11. 对阶为什么是小阶向大阶看齐

这个方向不是随便定的。

反过来想一次就明白：对阶时，两个尾数必须有一个要动。

```text
若“大阶向小阶看齐”：
  大阶那个数要左移，把小数点往右推。
  左移 = 整数部分变长 = 高位要被挤出尾数宽度。
  一旦挤出的是有效位，数量级就错了。

若“小阶向大阶看齐”：
  小阶那个数要右移，把小数点往左推。
  右移 = 只往低位补零、只丢低位。
  丢的是精度，不是数量级。
```

极端情况下，前一种根本做不到。

```text
一个阶码 e = 127 的数，要向左看齐到 e = −126，
尾数得左移 253 位。
那需要 254 位整数部分，任何硬件都给不出。

反过来，让 e = −126 的数右移到 e = 127，
只是丢掉 253 位低位 —— 那个数本身早就小到可以忽略。
```

所以规则是：

```text
小阶向大阶看齐：右移，丢低位，损失精度
大阶向小阶看齐：左移，丢高位，损失数量级
```

前者可接受，后者不可接受。

这就是“大数吃小数”的由来。

```text
1.000 × 2¹⁰ + 1.000 × 2⁰
若尾数只有 4 位：
  y 右移 10 位 → 0.0000（全丢了）
  结果 = 1.000 × 2¹⁰

小的那个被完全吞掉，一点痕迹不留。
```

第 6 节第(4)问就是这个现象。

```text
10¹⁶ + 1.0 = 10¹⁶
两个数相差 1，但 10¹⁶ 的“格点间隔”是 2，1 不够一格。
```

工程上的对策。

```text
① 排序后从小到大累加
② 用 Kahan 求和（补偿求和）把舍入误差单独存起来
③ 用更高精度累加（float 求和先升到 double）
```

这三条在数值计算里是常识。

在 408 里只需要知道“为什么会吃”。

## 12. 精度与范围不是一回事

先问：为什么这两个词必须分开说？
因为它们由不同字段决定，可以一个很好、另一个很差。
宣传话术只报范围（“能表示到 10 的 38 次方”），不报精度（“到了那个量级，加一等于没加”）。
分不清这两个词，就会写出“用 float 存金额”这种 bug。

这两个词天天被混用。

```text
范围（range）：能表示的最大数和最小数
  由阶码位数决定

精度（precision）：相邻两个可表示数之间的间隔
  由尾数位数决定
```

单精度的两个数字。

```text
范围：1.18×10⁻³⁸ ~ 3.4×10³⁸
精度：约 7 位十进制有效数字（24 位二进制）
```

双精度。

```text
范围：2.2×10⁻³⁰⁸ ~ 1.8×10³⁰⁸
精度：约 16 位十进制有效数字（53 位二进制）
```

关键是：**范围大不代表精度高。**

```text
单精度能表示 3.4×10³⁸，看起来很大。
但在 3.4×10³⁸ 附近，相邻两个可表示数的间隔是
  2¹²⁷ × 2⁻²³ = 2¹⁰⁴ ≈ 2×10³¹

也就是说，在 10³⁸ 量级上加减 10³⁰，结果可能一点不变。
```

一个具体的例子。

```text
单精度：16777216 = 2²⁴ 可以精确表示
       16777217 = 2²⁴ + 1 表示不了
       它会舍入回 16777216

原因：在 [2²⁴, 2²⁵) 区间内，格点间隔是 2。
      奇数全部落在格点之间。
```

对比双精度。

```text
双精度：2⁵³ = 9007199254740992 可以精确表示
       2⁵³ + 1 表示不了

这就是 JavaScript 里 Number.MAX_SAFE_INTEGER = 2⁵³ − 1 的由来。
超过它，整数运算就不再精确。
```

所以“浮点数能表示很大”和“浮点数能精确表示”是两件事。

```text
能表示：范围问题
能精确表示：精度问题
```

这也是为什么金额不能用 float 存。

```text
0.1 存不准，累加 100 次会差出可见的金额。
用整数分（int64）或十进制定点（decimal）才对。
```

## 13. 反直觉点：能表示的只有有限个

数轴上，任意两个实数之间还有无穷多个实数。

浮点数不是。

```text
单精度一共有 2³² 个编码（约 43 亿个），
扣掉 NaN 和 ∞ 占的位置，能表示的有限实数不到 43 亿个。
双精度是 2⁶⁴ 个。
```

43 亿听起来很多。

但和实数比，它是零。

```text
在 [1, 2) 区间内，单精度有 2²³ = 8388608 个值。
在 [2, 4) 区间内，同样只有 2²³ 个值。
在 [2¹²⁷, 2¹²⁸) 内，还是只有 2²³ 个值。

每一段的个数一样多，但跨的区间宽了 2¹²⁷ 倍。
所以越大的数，越稀疏。
```

这就是浮点数的真实形状。

```text
不是均匀的格子，是对数尺度的格子。
靠近 0 的地方密，远离 0 的地方稀。
而且是对称的、分段等密度的。
```

再叠一层：正负两半对称，0 附近还有非规格化数兜底。

```text
单精度的密度分布（示意）：

 0        1        2        4        8   …   2¹²⁷
 ├─┬─┬─┬─┼──┬──┬──┼───┬───┼────┬────┼── … ──┤
  ← 非规格化 → ← 每段 2²³ 个值，段长翻倍 →

越往右，格点越稀。
```

**这就是那个反直觉的点：**

```text
浮点数不是“精度低一点的实数”。
它是一条有限长的、对数刻度的、带孔的数轴。

两个浮点数之间有无限多个实数，
但这些实数一个都表示不了。
```

推论一：浮点加法的结果总会被舍入。

```text
除了极少数情况（两数阶码相同、尾数和不超位），
几乎每一次浮点运算都会丢掉信息。
```

推论二：浮点运算不满足结合律。

```text
(a + b) + c  ≠  a + (b + c)   在某些情况下

经典例子（双精度）：
  (1e16 + 1.0) + 1.0 = 1e16
  1e16 + (1.0 + 1.0) = 1e16 + 2.0 = 1e16 + 2
```

推论三：整数和浮点之间的转换不是免费的。

```text
int → float：可能丢精度（超过 2²⁴ 的奇数）
float → int：可能截断，也可能溢出（未定义）
```

## 14. 容易混淆的点

七组，逐个拆。

```text
① 尾数 23 位 vs 精度 24 位
   存储只有 23 位，隐藏位补 1，实际精度 24 位。
   双精度同理：存 52，精度 53。
```

```text
② 阶码字段 vs 真实指数
   字段 E 是移码，真实指数 e = E − 127（单精度）。
   E = 130 时 e = 3，不是 130。
```

```text
③ 偏置 127 vs 8 位移码的偏置 128
   IEEE 754 单精度的偏置是 127。
   通用的 8 位移码偏置是 128。
   差一个，因为阶码的 0 和 255 被特殊值占用了。
```

```text
④ 规格化的“最高位为 1” vs 非规格化的“最高位为 0”
   规格化：尾数 1.M，隐藏位补 1，阶码 e = E − 127，E ∈ [1, 254]
   非规格化：尾数 0.M，隐藏位补 0，阶码固定 e = −126，E = 0
```

```text
⑤ 尾数溢出 vs 阶码溢出
   尾数相加进位 → 右移一位、阶码加一（这不算溢出）
   阶码超出 [−126, 127] → 才是溢出，向上是 ∞，向下是 0
```

```text
⑥ 舍入 vs 截断
   截断是舍入的一种（向零舍入）。
   IEEE 754 默认是“就近舍入到偶数”，不是截断。
   C 的强制类型转换是截断，和浮点默认舍入不一样。
```

```text
⑦ 精度损失 vs 范围溢出
   0.1 + 0.2 是精度损失，结果还在范围内。
   1e38 × 10 是范围溢出，结果变成 ∞。
   两件事，两种处理。
```

## 15. 小结

这一篇的骨架是“两段式编码”。

**第一层：表示。**

```text
值 = (−1)^S × 1.M × 2^(E − bias)
单精度：1 + 8 + 23，bias = 127
双精度：1 + 11 + 52，bias = 1023
规格化：尾数隐含最高位 1，白赚一位精度
```

**第二层：写编码的五步。**

```text
符号 → 转二进制 → 规格化 → 算阶码（e + bias）→ 填尾数（去隐藏位）
```

**第三层：特殊值。**

```text
E=0, M=0    → ±0
E=0, M≠0    → 非规格化数（渐进下溢）
E=255, M=0  → ±∞
E=255, M≠0  → NaN
```

**第四层：浮点加减五步。**

```text
对阶 → 尾数加减 → 规格化 → 舍入 → 溢出判断
对阶永远是小阶向大阶：右移丢低位可接受，左移丢高位不可接受
```

**第五层：精度与范围。**

```text
范围由阶码位数决定
精度由尾数位数决定
单精度约 7 位十进制，双精度约 16 位
```
