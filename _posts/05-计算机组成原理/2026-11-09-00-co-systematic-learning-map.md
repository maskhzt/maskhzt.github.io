先看一行代码：

```python
>>> 0.1 + 0.2
0.30000000000000004
```

你可能会说：这是 Python 的精度问题。

换个语言，结果一样：

```c
printf("%.17g\n", 0.1 + 0.2);   /* 0.30000000000000004 */
```

不是语言的问题。

是**计算机根本没有 0.1 这个数**。

0.1 的二进制是无限循环小数：

```text
0.1₁₀ = 0.00011001100110011…₂
```

一个 32 位或 64 位的寄存器，只能存前面一段。

存进去的那一刻，它就已经不是 0.1 了。

**反直觉的点在这里：**

```text
计算机不是"算得不准"，
而是"它连你要算的数都存不下"。
```

这一篇从这里出发，画一张地图。

## 1. 为什么组成原理显得难

翻开教材，目录大概是这样：

```text
概述
数据的表示与运算
存储系统
指令系统
中央处理器
总线
输入输出系统
```

七章。

每一章都有硬公式和硬图。

数据通路图能画满一页，流水线时空图像网格纸。

于是学起来很像背电路：

```text
cache 地址怎么划分
流水线加速比怎么算
微指令的格式有哪几种
```

背完就忘。

**问题不在公式多。**

**问题在于，你不知道这些部件是怎么串成"一条指令"的。**

## 2. 一条指令的一生

所有的组成原理，都可以压成同一个问题：

```text
一条指令，从内存里出来，到结果写回，
中间经过了哪些部件？
```

走一遍：

```text
① 取指      PC → 地址 → 读内存 → 指令寄存器 IR
② 译码      IR → 控制器 → 产生控制信号
③ 取操作数  按寻址方式算出地址 → 读寄存器或内存
④ 执行      ALU 运算
⑤ 访存      需要的话，读写内存
⑥ 写回      结果写回寄存器
⑦ 更新 PC   顺序 +1，或跳到目标地址
```

七步。

七步里用到的部件，正好是五块：

```text
数据怎么表示 → ②③④ 全在用
存在哪里     → ①⑤ 在用
指令长什么样 → ① 在用
谁来指挥     → ②④ 在用
怎么连起来   → 全部
```

所以这套讲解不按教材章节排。

按"一条指令经过的部件"排。

## 3. 五块地图

```text
┌──────────────────────────────────────────────┐
│ 数据表示  二进制、补码、浮点、运算              │
├──────────────────────────────────────────────┤
│ 存储系统  主存、Cache、虚拟存储、磁盘           │
├──────────────────────────────────────────────┤
│ 指令系统  格式、寻址、CISC/RISC、机器级代码     │
├──────────────────────────────────────────────┤
│ CPU       数据通路、控制器、中断、流水线        │
├──────────────────────────────────────────────┤
│ 总线与 I/O 怎么连、怎么传、怎么等               │
└──────────────────────────────────────────────┘
```

五块之间不是并列。

是层层支撑：

```text
没有数据表示，ALU 不知道该算什么。
没有存储，指令和数据都没地方放。
没有指令格式，控制器不知道要译什么。
没有数据通路，控制信号不知道往哪发。
没有总线，部件之间连不起来。
```

## 4. 第 1 块：数据表示

这一块只回答一个问题：

```text
一个数，在寄存器里长什么样？
```

四种整数编码：

```text
原码：最高位符号，其余绝对值
反码：负数按位取反
补码：负数取反加一
移码：补码符号位取反
```

为什么要补码？

因为补码把减法变成了加法：

```text
a − b = a + (−b)
```

ALU 里只需要一个加法器，不需要减法器。

浮点数更狠：

```text
符号 1 位 + 阶码 8 位 + 尾数 23 位（单精度）
```

阶码用移码，尾数用原码。

**这一块是 408 的送分题，也是丢分题。**

送分，因为规则固定。

丢分，因为方向容易反，比如补码转真值时忘了"取反加一"的顺序。

## 5. 第 2 块：存储系统

它回答一个问题：

```text
数据放在哪一层，才能又大又快？
```

答案是一个金字塔：

```text
       寄存器    最快、最小、最贵
         ↑
       Cache
         ↑
        主存
         ↑
        磁盘      最慢、最大、最便宜
```

每一层都在做同一件事：

```text
把下一层的一小块，搬到上一层来。
```

于是所有计算都长一个样：

```text
平均访问时间 = 命中时间 + 缺失率 × 缺失代价
```

Cache 考的是"地址怎么切分"。

虚拟存储考的是"页表怎么查"。

磁盘考的是"容量和时间怎么算"。

## 6. 第 3 块：指令系统

它回答一个问题：

```text
CPU 能听懂哪些句子？
```

一条指令 = 操作码 + 地址码。

```text
操作码：做什么
地址码：对谁做
```

扩展操作码是 408 的高频点：

```text
操作码越长，能表示的指令越多，但留给地址码的位越少。
```

寻址方式是另一个高频点：

```text
立即、直接、间接、寄存器、寄存器间接、
变址、基址、相对、堆栈
```

九种，每一种都在回答同一个问题：

```text
操作数到底在哪里？
```

## 7. 第 4 块：CPU

它回答一个问题：

```text
谁在下命令，命令怎么变成电信号？
```

两条路线：

```text
硬布线：用门电路直接产生控制信号，快但难改
微程序：用微指令序列解释机器指令，慢但灵活
```

再往上，是流水线：

```text
把一条指令的七步拆开，
让不同指令的不同步同时进行。
```

流水线一出现，三个敌人就来了：

```text
结构冒险：抢同一个部件
数据冒险：后一条要用前一条的结果
控制冒险：转移指令让取指不确定
```

三个敌人各有对策：

```text
停顿、转发、预测
```

## 8. 第 5 块：总线与 I/O

它回答一个问题：

```text
这么多部件，怎么连？怎么传？怎么等？
```

总线就是一组共享的线：

```text
地址线、数据线、控制线
```

I/O 的三种方式，本质是在回答"谁来搬数据"：

```text
程序查询：CPU 自己搬，还要一直问好了没
中断：设备好了叫 CPU，CPU 再来搬
DMA：设备自己搬，搬完通知 CPU
```

从"CPU 全程参与"到"CPU 只在两头签字"，就是 I/O 的进化史。

## 9. 三张必须能画的图

### 9.1 存储层次

```text
        容量小、速度快、价格高
              ↑
        ┌───────────┐
        │  寄存器    │   < 1 KB
        ├───────────┤
        │  L1 Cache │   32–64 KB
        ├───────────┤
        │  L2 Cache │   256 KB–1 MB
        ├───────────┤
        │  L3 Cache │   几 MB–几十 MB

        ├───────────┤
        │   磁盘     │   TB
        └───────────┘

        容量大、速度慢、价格低
```

              ┌───────┴────────┐

```text

```

理想情况下，每个周期完成一条。

## 10. 三个必算的量

### 10.1 CPI 与 MIPS

```text
CPI = 总时钟周期数 / 指令条数
MIPS = 主频 / (CPI × 10^6)
```

主频 2 GHz、CPI = 2：

```text
MIPS = 2×10^9 / (2×10^6) = 1000
```

### 10.2 平均访问时间

```text
AMAT = 命中时间 + 缺失率 × 缺失代价
```

命中 1 ns、缺失率 5%、缺失代价 100 ns：

```text
AMAT = 1 + 0.05 × 100 = 6 ns
```

一次缺失，抵 100 次命中。

### 10.3 流水线加速比

```text
S = 串行执行时间 / 流水线执行时间
理想情况 S ≈ 流水段数 k
实际 S = n·k / (k + n − 1)
```

n 条指令、k 段：

```text
n = 100，k = 5 → S = 500 / 104 ≈ 4.81
```

永远到不了 5。

### 10.4 三个量串起来的一道题

一台机器：主频 2.5 GHz，程序共 10^8 条指令，平均 CPI = 1.6。

```text
CPU 时间 = 指令数 × CPI / 主频
        = 10^8 × 1.6 / (2.5 × 10^9)
        = 0.064 s
```

MIPS：

```text
MIPS = 主频 / (CPI × 10^6) = 2500 / 1.6 = 1562.5
```

再看存储：L1 命中 1 ns、缺失率 4%、缺失代价 80 ns：

```text
AMAT = 1 + 0.04 × 80 = 4.2 ns
```

一次缺失，等于 80 次命中。

最后看流水线：5 段、100 条指令：

```text
S = (100 × 5) / (5 + 100 − 1) = 500 / 104 ≈ 4.81
```

四个数，四块内容。

408 的综合题，常常就是把它们拼在一道题里。

## 11. 408 怎么考这张地图

408 组成原理部分，题型很稳定：

```text
选择题：补码、IEEE 754、Cache 地址划分、寻址方式、
       流水线冒险、总线带宽、中断与 DMA
综合题：数据通路与控制信号、Cache 计算、流水线时空图、
       指令格式设计
```

一个实用的判断：

```text
能算的，套路固定，练三遍就稳。
不能算的，靠图：把数据通路画出来，控制信号自然就出来了。
```

## 14. 读完应该能回答的五个问题

**第一问：为什么 0.1 + 0.2 ≠ 0.3？**

```text
提示：0.1 的二进制是无限循环小数，存不下。
存进去的是近似值，加出来的自然是近似值。
```

（04 篇）

**第二问：为什么用补码表示负数？**

```text
提示：补码让减法变成加法，ALU 只需要一个加法器。
```

（02、03 篇）

**第三问：Cache 为什么能起作用？**

```text
提示：局部性。程序访问的地址和时间都扎堆。
没有局部性，Cache 只会增加开销。
```

（08、09 篇）

**第四问：流水线为什么达不到 k 倍加速？**

```text
提示：有填充和排空，还有冒险导致的停顿。
理想加速比 k 只在指令无限多且无冒险时成立。
```

（19、20 篇）

**第五问：DMA 和中断到底差在哪？**

```text
提示：中断是"设备好了叫 CPU 来搬"，DMA 是"设备自己搬，搬完叫一声"。
```

（22 篇）

## 15. 小结

整套组成原理，压成一句话：

```text
一条指令，从内存出来，经过数据通路，被控制器指挥着，
在 ALU 里算完，把结果写回去。
```

五块，五个问题：

```text
数据怎么表示
存在哪里
指令长什么样
谁来指挥
怎么连起来
```

三个必算量：

```text
CPI / MIPS
AMAT = 命中时间 + 缺失率 × 缺失代价
S = n·k / (k + n − 1)
```
