一段 C：

```c
int sum(int *a, int n) {
    int s = 0;
    for (int i = 0; i < n; i++)
        s += a[i];
    return s;
}
```

编译出来，没有"数组"，没有"循环"，没有"函数"。

只剩三类东西：

```text
把数据搬来搬去
做加减乘除和比较
根据条件跳转
```

高级语言是给人看的。

机器码是给 CPU 看的。

中间那层翻译，就是这一篇的主题。

**反直觉的点在这里：**

```text
RISC 的指令少，但程序不一定更长。
编译器可以用简单指令的组合，替代一条复杂指令。
流水线又让每条简单指令都更快。
```

指令少，不等于干得少。

一条 x86 的复杂指令，内部可能被拆成好几个微操作。

一条 RISC 的简单指令，可能一个周期就完成。

比"指令条数"，不如比"总周期数"。

这一篇先把 CISC 和 RISC 的账算清，再把 C 的四种结构翻译成汇编。

## 1. 从 C 到机器码，中间发生了什么

一条 C 语句，要经过三步才变成电信号。

```text
C 源码
  ↓ 编译器（compiler）
汇编代码
  ↓ 汇编器（assembler）
机器码
  ↓ 处理器
电信号
```

编译器做的事，比想象中多：

```text
把变量分配到寄存器或栈
把表达式拆成一条条三地址码
把 if/while 变成比较和跳转
把函数调用变成 call/ret 和栈帧
```

用 `gcc -S` 可以停在汇编这一步：

```text
gcc -S -O0 sum.c -o sum.s
```

`-O0` 是关闭优化。

打开 `-O2`，汇编会短很多，因为编译器把能省的都省了。

这一篇主要看 `-O0`。

不是因为它好，而是因为它和 C 的结构一一对应，适合学习。

汇编里只有三类指令：

```text
数据传送：mov、load、store
算术逻辑：add、sub、and、or、cmp
控制转移：jmp、jcc、call、ret
```

所有高级语言结构，最后都落到这三类上。

编译器的内部流程，可以粗分成几步：

```text
词法分析：把源码切成 token
语法分析：建语法树
语义分析：检查类型
中间代码：生成三地址码
优化：删冗余、提公共子表达式
目标代码：选指令、分寄存器、排栈帧
```

对写组成原理的人来说，最关心最后两步。

因为"选指令"决定了用 CISC 还是 RISC 的风格。

"分寄存器"决定了变量在寄存器还是栈上。

"排栈帧"决定了函数调用时栈长什么样。

举个最小的例子：

```c
z = x + y;
```

三地址码大概是：

```text
t1 = x
t2 = y
t3 = t1 + t2
z = t3
```

到 x86 上可能变成：

```text
movl x(%rip), %eax
addl y(%rip), %eax
movl %eax, z(%rip)
```

到 RISC 上可能是：

```text
lw   t0, x
lw   t1, y
add  t2, t0, t1
sw   t2, z
```

同样是加法，CISC 可以直接"内存加寄存器"，RISC 必须先 load。

这就是两种设计哲学最直观的差别。

学汇编，不是为了手写汇编。

是为了能看懂：

```text
编译器把你的 C 变成了什么
一条 C 语句在机器级要做几步
栈帧长什么样
函数调用到底发生了什么
```

看懂这些，408 的机器级表示题就有了底。

也能解释很多"语言层面的怪现象"：

```text
为什么局部变量不初始化是随机值
为什么数组越界不一定报错
为什么递归太深会栈溢出
为什么传大结构体比传指针慢
```

这些问题，在 C 的语法层面找不到答案。

在栈帧和机器码里，一目了然。

## 2. CISC 与 RISC：两种设计哲学

CISC（complex instruction set computer）和 RISC（reduced instruction set computer），是两种指令集设计路线。

### 2.1 CISC：让一条指令多干活

CISC 的思路：

```text
一条指令能做很多事。
指令可以很长。
寻址方式可以很多。
操作数可以直接来自内存。
```

x86 是典型。

一条 `add` 可以直接把内存里的数加到寄存器：

```text
add eax, [ebx+4]
```

取数、加法、写回，一条指令完成。

好处：

```text
代码密度高。
同样功能，指令条数少。
```

坏处：

```text
指令长度不一，译码复杂。
一条指令要做多步，难以流水线。
控制器常用微程序实现。
```

### 2.2 RISC：让每条指令都简单

RISC 的思路：

```text
指令少，格式固定。
只有 load/store 能访问内存。
运算只在寄存器之间进行。
寻址方式少。
```

ARM、MIPS、RISC-V 是典型。

一条 RISC 指令大概长这样：

```text
add x0, x1, x2      ; x0 = x1 + x2
ldr x0, [x1, #8]    ; x0 = M[x1+8]
```

好处：

```text
指令定长，译码简单。
每条指令步骤少，容易流水线。
控制器可以用硬布线，快。
寄存器多，减少访存。
```

坏处：

```text
同样功能，指令条数可能更多。
代码密度可能更低。
```

### 2.3 为什么会分成两派

CISC 的黄金年代是 1970 年代。

那时候内存又贵又慢。

一条指令能多做事，程序就能短一点，访存就少一点。

所以指令集越做越复杂：

```text
一条指令可以取数、运算、写回
一条指令可以处理数组
一条指令可以有多种寻址方式
```

微程序控制也是那个年代的产物。

复杂指令用一串微指令解释，硬件不用做得太复杂。

RISC 的思路在 1980 年代出现。

背景变了：

```text
编译器变强了，能把复杂操作拆成简单指令
寄存器变多了
流水线技术成熟了
```

既然编译器能拆，硬件就不必背那么多复杂指令。

把指令做简单，时钟频率可以更高，流水线可以更深。

于是有了 Berkeley RISC、Stanford MIPS 这些项目。

后来的 ARM、MIPS、RISC-V，都沿着这条路走。

x86 没有推翻自己。

它选择在内部做一次"翻译"：

```text
变长的 x86 指令
  ↓ 前端译码
定长的微操作（micro-ops）
  ↓ 后端执行
乱序、多发射、流水线
```

所以今天的 x86，前端是 CISC，后端更像 RISC。

这也是为什么"x86 一定比 ARM 慢"不成立。

### 2.4 两条路的代价

CISC 把复杂度放在硬件前端。

```text
译码器要处理变长指令
要支持很多寻址方式
要兼容几十年积累的指令
```

RISC 把复杂度放在编译器。

```text
编译器要负责把复杂操作拆开
要负责寄存器分配
要负责指令调度
```

两边都要付出代价，只是付在不同的地方。

```text
CISC：硬件复杂，软件简单
RISC：硬件简单，软件复杂
```

这就是"复杂度守恒"。

没有哪条路免费。

### 2.5 一句话记住两家

```text
CISC：用复杂的指令，换更短的代码。
RISC：用简单的指令，换更高的主频和更好的流水线。
```

x86 是 CISC。

ARM、MIPS、RISC-V 是 RISC。

但现代 x86 内部会把复杂指令拆成微操作（micro-ops），后端执行起来更像 RISC。

所以"CISC 一定慢"是错的。

真正的区别在**指令编码**和**前端译码**，不在绝对性能。

两家也不是非黑即白。

```text
RISC 也有复杂指令：SIMD、加密、原子操作
CISC 也有简单指令：mov、add、jmp
```

分类看的是"整体倾向"，不是"每一条指令"。

408 的选择题，按整体倾向答。

拿一条具体指令抬杠，通常不得分。

## 3. 八个维度对比

把两家放在一张表里：

| 维度 | CISC | RISC |
|---|---|---|
| 指令数量 | 多，几百到上千条 | 少，几十到一百多条 |
| 指令长度 | 变长 | 定长（常见 32 位） |
| 寻址方式 | 多，内存操作数常见 | 少，主要基址 + 偏移 |
| 访存 | 运算指令可直接访存 | 只有 load/store 访存 |
| CPI | 较高，指令步骤多 | 接近 1 |
| 控制器 | 传统上多用微程序 | 传统上多用硬布线 |
| 寄存器 | 较少 | 较多 |
| 流水线 | 难做，需要拆微操作 | 容易做 |

这张表是"传统印象"。

逐行看，每一行背后都有一个因果。

```text
指令数量多 → 译码表大 → 控制器复杂
指令变长 → 取指要先找边界 → 流水线难做
寻址方式多 → 地址计算单元复杂 → 指令周期变长
运算指令能访存 → 一条指令里混了访存 → 流水段不好切
CPI 高 → 同样指令条数要更多周期
微程序 → 一条机器指令要跑多拍微指令
寄存器少 → 更多变量溢出到栈 → 访存变多
```

RISC 的每一行，基本是把左边反过来。

```text
指令少 → 译码简单
定长 → 取指固定，PC 固定加 4
寻址少 → 地址计算快
只有 load/store 访存 → 流水段清晰
CPI 接近 1 → 每个周期都能完成一条
硬布线 → 控制信号直接由门电路产生
寄存器多 → 变量留在寄存器里
```

所以"CISC 和 RISC 的对比"，本质是"复杂度和性能放在哪"的对比。

真实芯片会互相借鉴：

```text
x86 内部拆微操作，前端复杂、后端 RISC 化。
ARM 也加复杂指令，比如 SIMD、加密指令。
```

所以 408 考的是"典型特征"，不是"绝对边界"。

答题时按教材的对比写，不要拿某个具体芯片抬杠。

408 选择题里，看到这些词要小心：

```text
"RISC 一定比 CISC 快"       错
"RISC 的指令数一定少"       对，但要看具体定义
"RISC 一定采用硬布线"       传统上如此，不是绝对
"CISC 一定用微程序"         传统上如此，不是绝对
"RISC 的 CPI 一定等于 1"    理想值，实际大于 1
```

判断题的正确答案，通常是" Typically（通常）"，不是"一定"。

## 4. 选择与循环：cmp + 跳转

高级语言里的 `if`、`while`、`for`，在机器级都变成：

```text
比较
条件跳转
无条件跳转
```

### 4.1 if/else

C：

```c
if (x > y)
    z = x - y;
else
    z = y - x;
```

x86-64 汇编（AT&T 语法）：

```text
    cmpl %esi, %edi      # 比较 x 和 y
    jle  .Lelse          # 若 x <= y，跳到 else
    movl %edi, %eax
    subl %esi, %eax      # z = x - y
    jmp  .Lend
.Lelse:
    movl %esi, %eax
    subl %edi, %eax      # z = y - x
.Lend:
```

读法：

```text
cmp 只设置标志位，不保存结果。
jle 根据标志位决定跳不跳。
then 分支执行完，要 jmp 跳过 else。
```

三个标签，两条跳转。

`if/else` 的本质是"两条路，选一条走"。

### 4.2 循环

C：

```c
for (int i = 0; i < n; i++)
    s += a[i];
```

汇编骨架：

```text
    xorl %eax, %eax        # s = 0
    xorl %ecx, %ecx        # i = 0
.Lloop:
    cmpl %esi, %ecx        # 比较 i 和 n
    jge  .Ldone            # i >= n 就退出
    movslq %ecx, %rdx
    addl (%rdi,%rdx,4), %eax   # s += a[i]
    incl %ecx              # i++
    jmp  .Lloop            # 跳回循环开头
.Ldone:
```

循环的本质：

```text
一个向前的条件跳转（退出）
一个向后的无条件跳转（回到开头）
```

`for` 和 `while` 的差别，只在"判断在循环体前还是后"。

```text
while：先判断，可能一次都不执行
do-while：先执行，至少执行一次
```

编译出来，都是"比较 + 条件跳转 + 跳回"。

### 4.3 条件码

x86 的比较指令不保存结果，只设置标志位。

```text
ZF：结果为零
SF：结果为负
OF：溢出
CF：进位/借位
```

条件跳转读这些标志：

```text
je  / jz    ZF = 1
jne / jnz   ZF = 0
jl          有符号小于
jb          无符号小于
jg          有符号大于
ja          无符号大于
```

有符号和无符号，用的跳转指令不一样。

这是 408 和手写汇编都容易错的地方。

为什么必须分开？

因为同一串位，两种解释不一样。

```text
0xFFFFFFFF
按无符号看：4294967295
按有符号看：−1
```

`0xFFFFFFFF` 和 `1` 比：

```text
无符号：0xFFFFFFFF > 1
有符号：−1 < 1
```

同一个比较，结论相反。

所以硬件要同时给出两组标志：

```text
CF：无符号比较的借位/进位
SF：结果的符号位
OF：有符号溢出
ZF：结果是否为零
```

跳转指令各取所需：

```text
jb  看 CF = 1
jl  看 SF ≠ OF
ja  看 CF = 0 且 ZF = 0
jg  看 ZF = 0 且 SF = OF
```

记不住也没关系。

408 一般不会让你从门电路推标志。

它只要求你知道"有符号和无符号要用不同的跳转"。

## 5. 数组：基址 + 变址

C 里的 `a[i]`，机器级就是：

```text
地址 = a 的首地址 + i × 元素大小
操作数 = M[地址]
```

如果 `int` 是 4 字节：

```text
a[i] 的地址 = a + i × 4
```

x86 的 SIB 寻址正好干这个：

```text
(%rdi,%rsi,4)
```

意思是：

```text
EA = rdi + rsi × 4
```

一条指令完成"基址 + 变址 × 比例"。

### 5.1 二维数组

C 的二维数组按行存放：

```c
int a[3][4];
a[i][j]
```

地址：

```text
a + (i × 4 + j) × 4
```

先算行偏移 `i × 列数`，再加列下标 `j`，最后乘元素大小。

编译器会把它拆成两次乘加。

```text
t = i × 4
t = t + j
addr = a + t × 4
```

举个具体的数。

`a[1][2]` 的偏移：

```text
(1 × 4 + 2) × 4 = 24
```

地址就是 `a + 24`。

如果数组按列存放，公式要换成：

```text
(j × 行数 + i) × 4
```

C 用行优先（row-major）。

Fortran 用列优先（column-major）。

所以同样的 `a[i][j]`，两种语言的地址算法不同。

408 默认 C 的行优先。

### 5.2 指针遍历

```c
for (int *p = a; p < a + n; p++)
    s += *p;
```

汇编里不需要每次乘 4。

指针每次加 4：

```text
addq $4, %rdi
```

为什么是加 4，不是加 1？

因为 `p` 是 `int *`。

`p + 1` 在 C 里的意思是"下一个 int"，地址要加 `sizeof(int)`。

编译器知道 `sizeof(int) = 4`，所以生成 `addq $4`。

如果 `p` 是 `char *`，就加 1。

如果 `p` 是 `double *`，就加 8。

指针的类型，决定了"加一"到底加几个字节。

这就是"指针运算"比"下标运算"快的原因之一。

下标运算每次都要乘元素大小。

指针运算只在初始化时算一次，之后每次加固定值。

编译器通常会把下标循环优化成指针循环。

`-O2` 下，两种写法生成的代码可能一模一样。

### 5.3 结构体的机器级表示

结构体在内存里，就是一段连续的字节。

```c
struct Point {
    int x;
    int y;
};
```

布局：

```text
偏移 0：x，4 字节
偏移 4：y，4 字节
总大小：8 字节
```

访问 `p.y`：

```text
地址 = p 的首地址 + 4
```

汇编里就是：

```text
movl 4(%rdi), %eax
```

结构体本身没有"指令"。

编译器只是把字段访问，翻译成"基址 + 偏移"。

### 5.4 对齐与填充

结构体的大小，不一定等于字段大小之和。

```c
struct S {
    char c;    // 1 字节
    int  i;    // 4 字节
};
```

看起来是 5 字节。

实际 `sizeof(struct S)` 通常是 8。

因为 `int` 要 4 字节对齐。

```text
偏移 0：c
偏移 1 到 3：填充
偏移 4 到 7：i
```

填充不是浪费，是让每个字段的地址满足对齐要求。

408 有时问"结构体占多少字节"。

按"字段大小 + 对齐填充"算，不要简单相加。

## 6. 408 怎么考

这一块的题型：

```text
① 给 C 代码，填汇编或缺哪条指令
② 给函数，算栈帧大小、参数位置
③ 给调用约定，问参数怎么传、谁清理栈
④ 给循环，问执行次数、跳转方向
⑤ 判断 CISC/RISC 特征
```

### 6.1 例题一：if/else 的指令条数

题目：

```c
if (x == 0) y = 1;
else y = 2;
```

对应的 x86 汇编至少有几步？

答：

```text
testl %edi, %edi     ; 测试 x
jne   .Lelse         ; x != 0 跳 else
movl  $1, %eax       ; y = 1
jmp   .Lend
.Lelse:
movl  $2, %eax       ; y = 2
.Lend:
```

共 5 条指令。

如果编译器把 `else` 放在前面，也可以写成 5 条。

关键是：

```text
一个比较
一个条件跳转
两个赋值
一个无条件跳转
```

### 6.2 例题二：栈帧大小

题目：

```c
int f(int a, int b) {
    int x, y, z;
    ...
}
```

32 位 cdecl，函数入口执行：

```text
push ebp
mov  ebp, esp
sub  esp, 12
```

问：栈帧一共占多少字节（含返回地址和旧 ebp）？

算：

```text
返回地址   4 字节
旧 ebp     4 字节
3 个局部变量 12 字节
合计 20 字节
```

答案：20 字节。

布局：

```text
[ebp+12]  b
[ebp+8]   a
[ebp+4]   返回地址
[ebp]     旧 ebp
[ebp-4]   x
[ebp-8]   y
[ebp-12]  z
```

### 6.3 例题三：参数位置

题目：

```c
f(1, 2, 3);
```

32 位 cdecl，调用前 `esp = 0x1000`。

问：进入 `f` 后，参数 1、2、3 分别在哪？

算：

```text
push 3   → esp = 0x0FFC
push 2   → esp = 0x0FF8
push 1   → esp = 0x0FF4
call     → 压入返回地址，esp = 0x0FF0
```

进入函数后：

```text
[esp]     = 返回地址
[esp+4]   = 1
[esp+8]   = 2
[esp+12]  = 3
```

答案：参数 1 在 `[esp+4]`，2 在 `[esp+8]`，3 在 `[esp+12]`。

参数从右往左压，所以第一个参数离返回地址最近。

### 6.4 例题四：循环次数

题目：

```c
for (int i = 0; i < 10; i++)
    s += i;
```

循环体执行几次？条件跳转跳几次？

答：

```text
i = 0 到 9，循环体执行 10 次。
第 11 次判断 i = 10，条件不成立，退出。
```

条件跳转：

```text
前 10 次成立，跳回循环体。
第 11 次不成立，不跳。
```

### 6.5 例题五：同一段循环的 RISC 版本

题目：

```c
s = 0;
for (int i = 0; i < n; i++)
    s += a[i];
```

用 MIPS 风格写出来。

答：

```text
      add  $t0, $zero, $zero   # s = 0
      add  $t1, $zero, $zero   # i = 0
loop:
      slt  $t2, $t1, $a1       # t2 = (i < n)
      beq  $t2, $zero, done    # 若 i >= n，退出
      sll  $t2, $t1, 2         # t2 = i × 4
      add  $t2, $a0, $t2       # t2 = a + i×4
      lw   $t3, 0($t2)         # t3 = a[i]
      add  $t0, $t0, $t3       # s += a[i]
      addi $t1, $t1, 1         # i++
      j    loop
done:
      add  $v0, $t0, $zero     # 返回值 = s
      jr   $ra
```

数一数：

```text
11 条指令
其中只有 lw 一条访存
其余都是寄存器运算
```

x86 版本可能只要 5 到 6 条，因为它的寻址方式能直接算 `a[i]`。

但 x86 的指令更长，译码更复杂。

MIPS 的指令都是 32 位，取指、译码、流水线都简单。

这就是"指令条数"和"指令复杂度"的交换。

408 不会要求你写完整 MIPS 程序。

它要你知道：

```text
RISC 用 load/store 把访存单独拿出来。
数组地址用移位和加法算。
循环用 slt + beq + j。
```

### 6.6 答题模板

```text
第一步：把 C 拆成基本块
第二步：给每个变量分配位置（寄存器或栈）
第三步：把条件变成 cmp + jcc
第四步：把函数调用变成 call + 栈帧
第五步：检查参数顺序和栈平衡
```

## 7. 真实芯片里长什么样

教材里的汇编是"教学方言"。

下面的汇编、ABI 和字节编码，都是简化示意。

真实编译器的输出会更复杂，也会随版本变化。

真实芯片的汇编，要认三样东西：

```text
语法：AT&T 还是 Intel
调用约定：参数放哪、谁清理栈
工具：gcc -S、objdump -d
```

### 7.1 AT&T 与 Intel

一句话：

```text
AT&T：源操作数在前，寄存器带 %，立即数带 $，如 movl $1, %eax
Intel：目的操作数在前，如 mov eax, 1
```

`gcc -S` 默认输出 AT&T。

`objdump -d` 默认也是 AT&T，可以用 `-M intel` 切换。

同一条指令，两种写法：

```text
AT&T：  movl %edi, -4(%rbp)
Intel： mov  DWORD PTR [rbp-4], edi
```

AT&T 的 `movl` 带 `l`，表示 32 位。

Intel 用 `DWORD PTR` 表示 32 位。

读 408 题时，先看题目用的是哪种语法。

两种语法的操作数顺序相反，看反了就会把源和目的弄颠倒。

### 7.2 gcc -S

```text
gcc -S -O0 sum.c -o sum.s
```

打开 `sum.s`，能看到：

```text
pushq %rbp
movq  %rsp, %rbp
movl  %edi, -4(%rbp)
...
```

`-O0` 的代码很啰嗦，每个变量都从栈上读写。

`-O2` 会把变量放进寄存器，循环也会重写。

### 7.3 objdump -d

```text
objdump -d sum
```

输出：

```text
  4005b6:  55                    push   %rbp
  4005b7:  48 89 e5              mov    %rsp,%rbp
  4005ba:  89 7d fc              mov    %edi,-0x4(%rbp)
  4005bd:  8b 45 fc              mov    -0x4(%rbp),%eax
```

左边是机器码字节，右边是汇编。

`55` 是 `push rbp`，一个字节。

`48 89 e5` 是 `mov rsp, rbp`，三个字节。

`89 7d fc` 是 `mov %edi, -4(%rbp)`，三个字节。

`8b 45 fc` 是 `mov -4(%rbp), %eax`，三个字节。

拆开看：

```text
89       操作码：mov r/m32, r32
7d       ModR/M：mod=01，reg=111（edi），r/m=101（rbp+disp8）
fc       位移：−4
```

`7d` 的最高两位 `01` 表示"后面跟 1 字节位移"。

最低三位 `101` 表示基址寄存器是 `rbp`。

中间三位 `111` 表示源寄存器是 `edi`。

一条 3 字节指令，把"操作码、寄存器、偏移"都编进去了。

`ModR/M` 的 `mod` 字段，还决定了位移的长度：

```text
mod = 00：没有位移，或者 r/m 是 RIP 相对
mod = 01：8 位位移
mod = 10：32 位位移
mod = 11：r/m 是寄存器，不是内存
```

所以同样是 `mov`，指令长度可以从 2 字节到 7 字节不等。

这就是变长指令的"变"到底变在哪。

指令长度不一样，这就是变长指令。

### 7.4 System V AMD64 调用约定

Linux、macOS 的 x86-64 用 System V AMD64 ABI。

```text
整型/指针参数：rdi、rsi、rdx、rcx、r8、r9
浮点参数：xmm0 到 xmm7
返回值：rax（浮点用 xmm0）
调用者保存：rax、rcx、rdx、rsi、rdi、r8–r11
被调用者保存：rbx、rbp、r12–r15
栈对齐：call 前 rsp 是 16 的倍数
```

因为 `call` 会压入 8 字节返回地址，所以函数入口处：

```text
rsp ≡ 8 (mod 16)
```

函数里如果要调用别人，得先把栈调整到 16 字节对齐。

这就是为什么 `main` 里经常看到：

```text
subq $8, %rsp
```

不是为了放变量，是为了对齐。

对齐的规则，一句话：

```text
call 指令执行前，rsp 必须是 16 的倍数。
```

如果不对齐，`movaps` 这类 SSE 指令会直接崩。

所以编译器会在序言里补一个 `subq $8` 或者 `push` 一个用不上的寄存器。

还有一个细节：叶子函数（不再调用别人）可以用"红区"（red zone）。

```text
rsp 往下 128 字节，信号处理不会碰。
叶子函数可以直接用，不用调整 rsp。
```

这是 x86-64 特有的优化。

408 不考红区，但看到 `-128(%rsp)` 不用惊讶。

ARM64 的约定更简单：

```text
x0–x7 传参
x0 返回
bl 调用
ret 返回
```

## 8. 过程调用：call、ret 与栈帧

函数调用，机器级只做两件事：

```text
把返回地址保存起来
跳到被调用函数的入口
```

### 8.1 call 和 ret

```text
call f：
  把下一条指令的地址压栈
  跳到 f 的入口

ret：
  从栈顶弹出返回地址
  跳回去
```

返回地址是"调用指令的下一条指令"。

不是当前指令，也不是函数入口。

### 8.2 栈帧

函数执行时，栈上的一块区域叫栈帧（stack frame）。

```text
高地址
+------------------+
| 调用者的栈帧      |
+------------------+
| 参数 7 以上       |  ← 调用者压入
+------------------+
| 返回地址          |  ← call 压入
+------------------+
| 保存的旧 rbp      |  ← push rbp
+------------------+  ← rbp
| 局部变量          |
| ...              |
+------------------+  ← rsp
低地址
```

栈向低地址增长。

所以"栈顶"在低地址，"栈底"在高地址。

把 32 位 cdecl 的偏移写全：

```text
[ebp+12]   第二个参数
[ebp+8]    第一个参数
[ebp+4]    返回地址
[ebp]      调用者的旧 ebp
[ebp-4]    第一个局部变量
[ebp-8]    第二个局部变量
...
```

为什么参数在正偏移？

因为参数是调用者压进去的，位置比返回地址高。

为什么局部变量在负偏移？

因为局部变量是函数自己 `sub esp, N` 留出来的，位置比 `ebp` 低。

记住这个布局，408 的栈帧题就能直接填。

32 位和 64 位的偏移差 4 字节：

```text
32 位：返回地址在 [ebp+4]，参数从 [ebp+8] 开始
64 位：返回地址在 [rbp+8]，参数从 [rbp+16] 开始
```

因为 64 位的指针和返回地址都是 8 字节。

题目给的是 32 位还是 64 位，先看清楚。

### 8.3 函数序言和尾声

序言（prologue）：

```text
pushq %rbp
movq  %rsp, %rbp
subq  $N, %rsp
```

三步：

```text
保存调用者的 rbp
建立当前函数的帧指针
给局部变量留空间
```

举个具体的：

```text
pushq %rbp          ; rsp -= 8，存入旧 rbp
movq  %rsp, %rbp    ; rbp = rsp
subq  $32, %rsp     ; rsp -= 32，留 32 字节局部变量区
```

执行完，帧长：

```text
返回地址 8 + 旧 rbp 8 + 局部变量 32 = 48 字节
```

`subq $32` 的 32，是编译器算出来的局部变量总大小，再按 16 字节对齐。

为什么按 16 字节对齐？

```text
SSE 指令一次搬 16 字节，地址必须 16 字节对齐。
函数调用时，ABI 要求 rsp 16 字节对齐。
```

所以局部变量区经常比实际需要的大一点。

```text
3 个 int 只要 12 字节
编译器可能留 16 字节
```

多出来的 4 字节不是浪费，是对齐的填充。

408 算栈帧大小时，按题目给的 `sub` 数值算，不要自己按变量个数猜。

尾声（epilogue）：

```text
movq %rbp, %rsp
popq %rbp
ret
```

或者用一条：

```text
leave
ret
```

`leave` 等价于：

```text
movq %rbp, %rsp
popq %rbp
```

### 8.4 为什么要有帧指针

`rbp` 不是必需的。

编译器可以用 `rsp` 加偏移访问局部变量。

但 `rbp` 让栈帧布局固定：

```text
参数在 rbp + 正偏移
返回地址在 rbp + 8
局部变量在 rbp - 负偏移
```

调试器、backtrace、栈展开，都靠它。

`-O2` 常开 `-fomit-frame-pointer`，把 `rbp` 省出来当通用寄存器。

代价是栈回溯变难。

## 9. 参数传递与返回值

参数怎么传，取决于调用约定。

### 9.1 寄存器传参 vs 栈传参

```text
寄存器传参：快，但寄存器数量有限
栈传参：慢，但数量不限
```

x86-64 前 6 个整型参数用寄存器。

第 7 个开始放栈上。

32 位 cdecl 全部用栈。

寄存器传参还有一个副作用：寄存器归谁管。

```text
调用者保存：rax、rcx、rdx、rsi、rdi、r8–r11
被调用者保存：rbx、rbp、r12–r15
```

"调用者保存"的意思是：

```text
被调用函数可以随便改这些寄存器。
调用者如果还要用，得自己先存起来。
```

"被调用者保存"的意思是：

```text
被调用函数要用这些寄存器，必须先存旧值，返回前恢复。
```

所以函数序言里经常看到：

```text
pushq %rbx
...
popq %rbx
```

不是为了参数，是为了遵守约定。

### 9.2 值传递与地址传递

C 只有值传递。

```c
void f(int x);
void g(int *p);
```

`f` 拿到的是副本。

`g` 拿到的是地址，可以通过地址改原变量。

机器级看：

```text
值传递：把值复制到参数位置
地址传递：把地址复制到参数位置
```

两者都是"复制"，区别在复制的是什么。

### 9.3 返回值

整型返回值放 `rax`。

浮点返回值放 `xmm0`。

较大的结构体，调用者分配一块空间，把地址作为隐藏参数传进去。

```text
rdi = 返回空间的地址
其他参数往后挪一位
```

返回值的机器级动作：

```text
被调用函数把结果放进 eax/rax
执行 ret
调用者从 eax/rax 读结果
```

所以 `call` 之后，调用者通常马上用 `eax`：

```text
call sum
movl %eax, %edi     # 把返回值当参数传给下一个函数
```

### 9.4 谁清理栈

```text
cdecl：调用者清理
stdcall：被调用者清理
x86-64 System V：调用者清理（参数大多在寄存器，栈上很少）
```

408 常考 cdecl：

```text
调用前 push 参数
调用后 add esp, N
```

N 是参数总字节数。

举个例子：

```c
f(1, 2, 3);
```

三个 `int`，每个 4 字节：

```text
push $3
push $2
push $1
call f
add  $12, %esp     # 3 × 4 = 12
```

如果是 `stdcall`，`add $12, %esp` 就由 `f` 自己在 `ret` 前做。

```text
被调用者的 ret 指令带一个立即数：ret $12
```

两种约定不能混用。

混用会导致栈指针错位，程序直接崩。

## 10. 一段 C 代码的汇编骨架

把开头的 `sum` 完整翻译一遍。

C：

```c
int sum(int *a, int n) {
    int s = 0;
    for (int i = 0; i < n; i++)
        s += a[i];
    return s;
}
```

x86-64（AT&T，`-O0` 风格，简化示意）：

```text
sum:
    pushq %rbp
    movq  %rsp, %rbp
    subq  $32, %rsp           # 留 32 字节局部变量区
    movq  %rdi, -24(%rbp)     # 保存 a
    movl  %esi, -28(%rbp)     # 保存 n
    movl  $0, -4(%rbp)        # s = 0
    movl  $0, -8(%rbp)        # i = 0
    jmp   .L2
.L3:
    movl  -8(%rbp), %eax      # eax = i
    cltq                      # 符号扩展到 rax
    leaq  0(,%rax,4), %rdx    # rdx = i × 4
    movq  -24(%rbp), %rax     # rax = a
    addq  %rdx, %rax          # rax = a + i×4
    movl  (%rax), %eax        # eax = a[i]
    addl  %eax, -4(%rbp)      # s += a[i]
    addl  $1, -8(%rbp)        # i++
.L2:
    movl  -8(%rbp), %eax
    cmpl  -28(%rbp), %eax     # 比较 i 和 n
    jl    .L3                 # i < n 就循环
    movl  -4(%rbp), %eax      # 返回值 = s
    movq  %rbp, %rsp          # 恢复 rsp
    popq  %rbp
    ret
```

逐段读：

```text
push/mov/sub      建立栈帧
movq/movl         把参数存到栈上
movl $0           初始化 s 和 i
jmp .L2           先跳到条件判断
.L3               循环体
leaq/addq/movl    算地址、取 a[i]
addl              累加
addl $1            i++
.L2              条件判断
jl .L3            成立就跳回循环体
movl -4(%rbp)     把 s 放进 eax
movq rbp,rsp      恢复 rsp
popq/ret          恢复 rbp、返回
```

这段代码里，C 的四个结构都能找到对应：

```text
变量分配 → 栈上的 -4、-8、-24、-28
for 循环 → .L2 判断 + .L3 循环体 + jl 跳回
数组访问 → leaq + addq + movl
函数返回 → eax + ret
```

这段 `-O0` 代码有几个刻意的地方：

```text
参数 a、n 先存回栈，再反复从栈读
s 和 i 也放在栈上，每次加法都要读内存
数组地址每次重新算：i → rax → rdx → rax → 地址
```

这些在 `-O0` 下都是真的。

不是编译器笨，是它故意不优化，方便调试。

`-O2` 会把它压缩很多：

```text
参数留在寄存器
s 和 i 也留在寄存器
循环只保留比较、取数、加法、自增、跳转
```

一个可能的 `-O2` 版本：

```text
sum:
    xorl  %eax, %eax          # s = 0
    testl %esi, %esi          # n <= 0 ?
    jle   .Ldone
    movslq %esi, %rsi
    leaq  (%rdi,%rsi,4), %rdx # rdx = a + n×4，尾指针
.Lloop:
    addl  (%rdi), %eax        # s += *p
    addq  $4, %rdi            # p++
    cmpq  %rdx, %rdi          # p != end ?
    jne   .Lloop
.Ldone:
    ret
```

对比一下：

```text
-O0：约 20 条指令，反复访存
-O2：约 8 条指令，全部在寄存器里
```

指令条数少了，不是因为指令集变了。

是因为编译器把能省的都省了。

408 给汇编题时，通常会说明是"未优化"还是"优化后"。

没说明时，按题目给的代码读，不要自己脑补优化。

但骨架不变。

## 11. 容易混淆的点

**第一，CISC 不等于慢，RISC 不等于快。**

x86 内部拆微操作，性能照样很高。

**第二，RISC 指令少，不等于程序短。**

编译器可能用更多条简单指令，换更低的 CPI。

**第三，`call` 不等于 `jmp`。**

`call` 要压返回地址，`jmp` 不压。

**第四，返回地址不是旧 rbp。**

`[rbp]` 是旧 rbp，`[rbp+4]`（32 位）或 `[rbp+8]`（64 位）才是返回地址。

**第五，栈向低地址增长。**

`push` 让 `rsp` 减小，`pop` 让 `rsp` 增大。

**第六，AT&T 和 Intel 的操作数顺序相反。**

AT&T 是"源在前"，Intel 是"目的在前"。

**第七，`cmp` 不保存结果。**

它只设置标志位，结果要另外算。

**第八，`lea` 不访存。**

它只算地址，把地址放进寄存器。

**第九，参数不一定在栈上。**

x86-64 前 6 个参数在寄存器。

**第十，`-O0` 和 `-O2` 的代码可能完全不同。**

考试按题目给的汇编读，不要拿编译器的优化结果抬杠。

这十个点，前五个是概念，后五个是读汇编的细节。

概念题错在"绝对化"。

细节题错在"看反源和目的"。

读汇编时，养成一个习惯：

```text
先看语法（AT&T 还是 Intel）
再看方向（谁写到谁）
最后看栈（rsp/rbp 怎么动）
```

三步走完，大部分汇编题就不会读错。

## 12. 小结

CISC 与 RISC：

```text
CISC：指令复杂、变长、寻址多、代码密度高
RISC：指令简单、定长、load/store、流水线友好
```

高级语言四种结构：

```text
if/else → cmp + 条件跳转 + 无条件跳转
循环    → 条件跳转退出 + 无条件跳转回去
数组    → 基址 + 变址 × 元素大小
函数    → call/ret + 栈帧
```

栈帧：

```text
参数、返回地址、旧 rbp、局部变量、保存的寄存器
```

调用约定：

```text
x86-64：rdi、rsi、rdx、rcx、r8、r9 传参，rax 返回
ARM64：x0–x7 传参，x0 返回
```

把一次函数调用压成时序：

```text
调用者：准备参数 → call
被调用者：push rbp → mov rbp,rsp → sub rsp,N
         → 执行函数体
         → mov rsp,rbp → pop rbp → ret
调用者：从 eax/rax 取返回值
```

七步。

每一步在栈上留下什么，都能在上面的栈帧图里找到。

栈指针 `rsp` 一共动了四次：`call`、`push rbp`、`sub rsp`、`leave`。

帧指针 `rbp` 动了两次：建立和恢复。

记住这两个次数，栈帧题就不会数错。

返回地址永远在旧 `rbp` 的上面，参数又在返回地址的上面。

从 `rbp` 往上数，先返回地址，再参数。

从 `rbp` 往下数，全是局部变量和保存的寄存器。

反直觉点再重复一次：

```text
RISC 的指令少，程序不一定更长。
编译器用简单指令组合出复杂操作，
流水线让每条指令都更快。
```

下一篇进入 CPU 内部：

```text
取指、译码、执行，到底用了哪些部件？
一条 ADD 指令，数据在总线上怎么走？
为什么单总线取指要四个周期？
```

从"指令长什么样"，走到"指令怎么被执行"。
