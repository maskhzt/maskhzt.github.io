先算一个最小的题。

一根地址线，能区分几个单元？

```text
1 根 → 2 个（0 和 1）
2 根 → 4 个（00、01、10、11）
n 根 → 2^n 个
```

所以容量和地址线是这么挂钩的：

```text
1 KB  = 2^10  →  10 根地址线
1 MB  = 2^20  →  20 根
1 GB  = 2^30  →  30 根
4 GB  = 2^32  →  32 根
```

一栋 40 亿个房间的楼，门牌号只要 32 位。

这是组成原理里最便宜的一条公式，也是最容易被忽略的一条。

**反直觉的点先放这里：**

```text
DRAM 的地址线只有一半，不是"白省了 10 根线"。

它是拿"送两次地址"换了"一半引脚"。
省下来的引脚，代价记在延迟和时序复杂度上。
```

## 1. 存储器在系统里排第几

先看一张图，这张图你以后会看到很多次：

```text
        寄存器       < 1 KB      0.3 ns
          ↑
        L1 Cache     32–64 KB    1 ns
          ↑
        L2 Cache     256 KB–2 MB 4 ns
          ↑
        L3 Cache     8–32 MB     15 ns
          ↑
         主存        GB 级        80 ns
          ↑
         磁盘        TB 级        100 μs
```

差距有多夸张？

```text
寄存器到主存：差 200 倍以上
主存到磁盘：差 1000 倍以上
```

如果 CPU 直接从磁盘取一条指令，一条指令要等 0.1 毫秒。

3 GHz 的 CPU，这 0.1 毫秒里能执行 30 万条指令。

所以存储必须分层。

分层能成立，靠的是下一章要讲的局部性（locality）。

这里先记住一句话：

```text
上一层是下一层的"常用缓存"。
```

于是所有的层次都能用同一个式子衡量：

```text
平均访问时间 = 命中时间 + 缺失率 × 缺失代价
```

代入主存的数：

```text
Cache 命中 1 ns，缺失率 5%，缺失代价 80 ns
AMAT = 1 + 0.05 × 80 = 5 ns
```

从 80 ns 降到 5 ns，只靠 95% 的命中率。

这也说明 Cache 的关键不是"有没有"，是"命中率有多高"。

命中率掉到 50%，AMAT 就变成 41 ns，几乎白建。

## 2. 最小模型：单元、字、编址

存储器有四个必须分清的概念，408 每年都在这里设陷阱。

```text
存储元    一个能存 1 位的地方（触发器或电容）
存储单元  若干个存储元组成的整体，一个地址对应一个
存储字    一个存储单元里的 0/1 串
存储字长  这个串有多少位
```

举个具体的：

```text
某存储器：1M × 8 位
1M   = 2^20，一共 2^20 个存储单元
8 位 = 每个单元存 8 个二进制位
总容量 = 2^20 × 8 bit = 1 MB
```

**注意这里的两个"字"。**

```text
存储字长是 8 位：这是芯片自身的宽度
机器字长是 32 位：这是 CPU 运算的宽度
```

它们不相等，很正常。

一条 32 位指令，要从 4 个字节拼起来。

**存储元到底长什么样？**

两种主流结构，画出来差别一目了然。

```text
SRAM 的 6T 存储元                DRAM 的 1T1C 存储元

     Vdd                           字线（Word Line）
      │                                │
   ┌──┴──┐                          ┌─┴─┐
   │ P1  │ P2                       │ T │  ← 一个晶体管
   └──┬──┘                          └─┬─┘
      ├──────┬──── Q                 │
   ┌──┴──┐ ┌─┴──┐                 ┌──┴──┐
   │ N1  │ │ N2 │                 │  C  │  ← 一个电容
   └──┬──┘ └─┬──┘                 └──┬──┘
      │      │                       │
      └──────┴─── 位线                 地
```

数一下差别：

```text
SRAM：6 个晶体管，双稳态，只要通电就一直保持
DRAM：1 个晶体管 + 1 个电容，靠电荷存 1
```

双稳态的意思是：两个反相器首尾相接，互为输入。

```text
写 1 之后，正反馈把自己锁在 1
写 0 之后，正反馈把自己锁在 0
```

只要不断电，这个环就一直转，数据一直在。

不需要刷新，读多少次都不变。

DRAM 就惨了：电荷会通过晶体管漏掉。

```text
典型保持时间：几十毫秒
```

几十毫秒不刷新，数据就变成随机的 0 或 1。

所以必须隔一段时间重写一次，这就是刷新的全部原因。

**一个 6T 对 1T1C，差了 6 倍面积。**

这就是为什么 Cache 只有几十 MB，主存能有几十 GB。

**编址单位是第三个坑。**

```text
按字节编址：1 个地址 = 1 个字节
按字编址：  1 个地址 = 1 个字（字长可能是 16、32、64 位）
```

同一个 4 GB 空间：

```text
按字节编址 → 4G 个地址 → 32 根地址线
按 32 位字编址 → 1G 个地址 → 30 根地址线
```

差了整整两根线，选择题就爱问这个。

## 3. 一次完整走查：CPU 读一个字节

从 CPU 发出地址，到数据回到数据总线，中间发生了什么？

```text
① CPU 把地址 A 送到地址总线
② 地址译码器判断这一字节在哪个芯片、哪个区
③ 片选信号 CS 有效，选中该芯片
④ 芯片内部把地址拆成行地址、列地址
⑤ 行地址先送进去（RAS），整行读进行缓冲
⑥ 列地址后送进去（CAS），从行缓冲里挑出那一列
⑦ 数据经读出放大器放大，送上数据总线
⑧ CPU 锁存数据
```

第⑤⑥步就是 DRAM 的全部秘密，下面会展开。

第⑦步的"读出放大器"值得单独提一句：

DRAM 的电容只有几十飞法，读出来的电压差不到 0.1 伏。

必须先放大，才能变成数字 0 和 1。

放大完，这个值顺便被写回原处。

这叫**破坏性读出**（destructive read）与**再生**（regeneration）。

所以 DRAM 读一次，其实做了一次"读 + 重写"。

**行缓冲是理解 DRAM 性能的关键。**

一行被 RAS 选进来之后，整行（比如 1024 位）都在行缓冲里。

接下来只要访问的是这一行，就不用再开行。

```text
行命中（row hit）：  换列不换行 → 只送 CAS，快
行缺失（row miss）： 换行 → 先预充电关闭旧行，再开新行，慢
```

代价差多少？

```text
行命中   → CL（十几到二十几个时钟）
行缺失   → tRP + tRCD + CL（多出几十个时钟）
```

这组时序参数，就是内存条标签上那些数字背后的东西。

```text
tRCD   行地址到列地址的延迟，开一行要多久
CL     CAS 延迟，列地址送出到数据出来
tRP    预充电时间，关一行要多久
```

**所以顺序访问比随机访问快，是物理决定的。**

不只是"缓存友好"这种软件层面的说法。

DRAM 自己就更喜欢"同一行的连续列"。

这也解释了 DDR5 为什么要拆子通道、加 bank group：

```text
一个 bank 在开行的时候，别的 bank 可以读
把"必须等的那些时钟"填满
```

## 4. 拆开看

### 4.1 按存储介质分

```text
半导体存储器    内存、Cache、SSD 的闪存，主流
磁表面存储器    硬盘、磁带
光存储器        光盘
```

408 只考半导体，另外两类知道有就行。

### 4.2 按存取方式分

这是最容易被问倒的一维。

```text
随机存取（RAM）    存取时间与位置无关，内存
顺序存取（SAM）    只能按顺序找，磁带
直接存取（DAM）    先找道，再等旋转，磁盘
相联存取（CAM）    按内容找，TLB、Cache 的标记比较
```

关键区别在"存取时间跟不跟地址有关"：

```text
RAM：地址 0 和地址 100 万，一样快
SAM：地址 0 和地址 100 万，差 100 万步
```

**这一维和"易失性"是两回事。**

ROM 是随机存取，但非易失。

磁盘是直接存取，也非易失。

两个维度交叉，别混着记。

再说一句"相联存取"。

它不按地址找，按内容找。

```text
输入：一段数据（比如 32 位的标记）
输出：有没有匹配的，在哪
```

Cache 的标记比较、TLB 的查找，都是这个模式。

硬件上要并行比较很多项，所以面积贵，但一次就出结果。

这就是"相联"两个字的物理含义。

### 4.3 按易失性分

```text
易失（volatile）    断电就没了：SRAM、DRAM
非易失（non-volatile）  断电还在：ROM、Flash、磁盘
```

内存条断电丢数据，是 DRAM 的物理性质决定的，不是设计缺陷。

### 4.4 层次结构与两个指标

层次结构只有一条规则：

```text
上一层装下一层的"最近用过的部分"。
```

每一层都在回答同一个问题：

```text
怎样用便宜的大容量，伪装成贵的小容量？
```

层次结构有三个性质，考选择题时会用到：

```text
① 上一层的内容是下一层的子集（包含性）
② 上一层更小、更快、更贵（单位容量）
③ 上一层由硬件管理，最下面一层由操作系统管理
```

第③条是个分界线。

```text
Cache 的替换、写回，全硬件自动，程序看不见
主存到磁盘的换页，靠操作系统的页表
```

**为什么不能全用 SRAM？**

算一笔账。

```text
SRAM 每 MB 的成本，大约是 DRAM 的几十倍
16 GB 全用 SRAM → 成本高到不可接受，芯片面积也放不下
```

反过来，全用 DRAM 也不行：

```text
DRAM 的延迟 80 ns，3 GHz CPU 一个周期 0.33 ns
一次访存要等 240 个周期
```

所以必须夹一层 Cache，把 80 ns 的访问变成 1 ns 的命中。

这就是第 09、10 篇要展开的内容。

三个性能指标要分清：

```text
存取时间 Ta   从发出读命令到数据稳定，一次的事
存储周期 Tmc  两次独立访问之间的最小间隔，Ta + 恢复时间
带宽          单位时间能传多少数据
```

**为什么 DRAM 的 Tmc > Ta？**

因为读完要再生，再生完才能接受下一次访问。

```text
SRAM：Tmc ≈ Ta（触发器不需要恢复）
DRAM：Tmc > Ta（电容要重写，要等）
```

带宽的算法：

```text
带宽 = 数据线宽度 / 存储周期
```

例：数据线 8 位，存储周期 50 ns。

```text
带宽 = 1 B / 50 ns = 20 MB/s
```

### 4.5 SRAM 与 DRAM

| 项目 | SRAM | DRAM |
|---|---|---|
| 存储原理 | 双稳态触发器 | 电容电荷 |
| 是否刷新 | 不需要 | 需要，定期刷新 |
| 读出 | 非破坏性 | 破坏性，需再生 |
| 速度快慢 | 快（1 ns 级） | 慢（几十 ns） |
| 集成度 | 低 | 高 |
| 功耗 | 静态功耗大，动态小 | 静态小，刷新耗电 |
| 成本 | 贵 | 便宜 |
| 用途 | Cache、寄存器堆 | 主存 |

**为什么 SRAM 快但集成度低？**

一个 SRAM 存储元要 6 个晶体管（6T）。

一个 DRAM 存储元只要 1 个晶体管 + 1 个电容（1T1C）。

```text
同样面积，DRAM 能放 6 倍以上的单元
```

代价是电容会漏电。

漏电就要刷新，刷新就要占时间。

**这一条链子要能背下来：**

```text
电容会漏电 → 必须刷新 → 有刷新开销 → 所以 DRAM 慢
触发器不漏电 → 不用刷新 → 没有开销 → 所以 SRAM 快
```

**功耗这一行容易记反。**

```text
SRAM：静态功耗大（6 个管子里的电流一直在流），动态功耗小
DRAM：静态功耗小（不访问时几乎不耗），但有刷新功耗
```

所以手机待机时把内存切到自刷新模式（self-refresh），只花很少的电。

这也解释了为什么"待机功耗"里，内存占的比重不低。

**为什么 DRAM 不需要"恢复时间"以外的东西，而 SRAM 需要 6 个管子？**

因为 SRAM 要"双稳态"。

```text
双稳态 = 两条交叉耦合的反馈路径
反馈 = 至少 4 个晶体管（2 个 PMOS + 2 个 NMOS）
加上两个访问管 = 6 个
```

DRAM 不需要反馈。

它只需要"把电荷存在一个坑里，用的时候能读出来"。

```text
1 个访问管 + 1 个电容 = 最小结构
```

代价就是那个坑会漏。

### 4.6 行列地址复用

先看做不复用的情况。

一个 1M 位的芯片，需要 20 根地址线：

```text
2^20 = 1M
20 根地址线 → 20 个引脚
```

芯片封装上，每一个引脚都是钱和面积。

而且引脚多了，封装就大，走线就密，可靠性就降。

DRAM 的解法：**把地址拆成两半，分两次送。**

```text
第一次：送行地址（row），锁存在行地址缓冲里
第二次：送列地址（column），锁存在列地址缓冲里
```

```text
┌──────────────────────────────────────┐
│  DRAM 芯片内部                        │
│                                      │
│  行地址 10 根 ──→ 行译码 ──→ 选中一行  │
│                              ↓        │
│                        行缓冲（1 行）  │
│                              ↓        │
│  列地址 10 根 ──→ 列译码 ──→ 选中一列  │
│                              ↓        │
│                          读出放大器    │
│                              ↓        │
│                          数据 8 位     │
└──────────────────────────────────────┘
```

于是 1M 个单元，只要 10 根地址线。

```text
不复用：20 根地址线
复用后：10 根地址线 + RAS + CAS
```

**省了 10 根，多花了一次送地址的时间。**

这就是开头那个反直觉点的全部内容。

**算一遍：**

```text
芯片容量 64M × 8
64M = 2^26
不复用需要 26 根地址线
复用后需要 13 根地址线（A0–A12）+ RAS + CAS
```

13 根线，选 2^13 = 8192 行，再选 2^13 = 8192 列。

```text
8192 × 8192 = 2^26 = 64M   ✓
```

行列相等是常见设计，不是必须。

128 × 128、256 × 64 都行，只要乘积对得上。

### 4.7 三种刷新方式

刷新的对象是"行"。

```text
一次刷新 = 把一整行读出来，放大，再写回去
```

所以刷新的次数只跟行数有关，跟列数、位宽都无关。

**这是刷新计算题的第一条常识。**

设一个芯片：阵列 128 行 × 128 列，存取周期 0.5 μs，刷新周期 2 ms。

（刷新周期 2 ms 的意思是：2 ms 内必须把 128 行全部刷一遍。）

**方式一：集中刷新。**

在 2 ms 的最后，集中刷 128 行。

```text
刷新时间 = 128 × 0.5 μs = 64 μs
占比 = 64 μs / 2000 μs = 3.2%
```

这 64 μs 里，CPU 不能访存。

叫"死区"（dead time）。

```text
死区 = 64 μs，每 2 ms 来一次
```

**方式二：分散刷新。**

每个存取周期后面跟一次刷新。

```text
系统存取周期 = 0.5 μs（读写）+ 0.5 μs（刷新）= 1 μs
刷新一遍 128 行 = 128 μs
开销 = 0.5 / 1 = 50%
```

没有死区，但速度掉一半。

```text
优点：访问均匀，无死区
缺点：每个周期都变长，带宽减半
```

**方式三：异步刷新。**

把 128 次刷新均匀摊到 2 ms 里。

```text
刷新间隔 = 2 ms / 128 = 15.625 μs
每次占 0.5 μs
开销 = 0.5 / 15.625 = 3.2%
```

死区被切成 128 个 0.5 μs 的小块，每次只有一小段不可用。

```text
开销和集中刷新一样，但延迟感受好得多
```

三种方式排一起：

```text
               有无死区    刷新开销    实现复杂度
集中刷新        有，整块    3.2%        最简单
分散刷新        无          50%         简单
异步刷新        有，很碎    3.2%        稍复杂
```

**注意集中和异步的开销是同一个数。**

因为都是 128 × 0.5 μs 的总刷新区，只是切法不同。

改变的是"什么时候不能访存"，不改"总共要刷多久"。

**刷新周期这个参数从哪来？**

不是算出来的，是由工艺决定的。

```text
早期 DRAM：2 ms
现代 DRAM：64 ms
```

数据手册写多少就是多少，题目一定给。

真正要算的是"在这个周期内，怎么把 N 行刷完"。

**还有一条常被忽略的约束：刷新不能被无限推迟。**

```text
某一行在刷新周期内一次都没被刷 → 数据丢失
```

所以"集中刷新"虽然简单，但它是把风险堆到最后。

如果这期间来了一个 DMA 大批量传输，刷新就可能被挤掉。

异步刷新没有这个问题，因为它给每一行都排了固定的位置。

这也解释了为什么真实的内存控制器用异步的思路：

```text
一个刷新计数器，每 15.6 μs 加一，按行号依次刷
```

### 4.8 ROM 家族

ROM 名字里有"只读"，但现在的 ROM 大都能写。

```text
MROM   掩膜 ROM，出厂就写好，改不了
PROM   一次可编程，烧断熔丝，写完就定
EPROM  紫外线擦除，擦一次要十几分钟
EEPROM 电可擦除，按字节擦写，慢
Flash  电可擦除，按块擦写，快，SSD 和 U 盘都用它
```

记忆线索：

```text
从 MROM 到 Flash，一条线：可写性越来越强，擦写粒度越来越大
```

Flash 有个必须知道的限制：

```text
写之前必须先擦，擦除的粒度是块（几百 KB），不是字节
```

所以 SSD 的写放大、垃圾回收、寿命问题，根源都在这句话上。

**ROM 在系统里干什么？**

存 BIOS/UEFI、存固件、存微程序。

它非易失、随机读、可以原地执行（execute in place）。

### 4.9 破坏性读出与再生

DRAM 读一个单元，电容上的电荷被分掉了。

读完这一位就变了，必须马上写回。

```text
读 → 放大 → 写回
```

这一套动作，硬件自动做，时序上算在存取时间里。

后果有两个：

```text
① 读和写一样"贵"，不能靠"只读不写"省时间
② 刷新和读操作共用同一条通路，所以要排队
```

SRAM 没这个问题，读多少次都不变。

**这条性质在真实系统里有个直接后果。**

DRAM 的读操作，其实是一次"读 + 写"。

```text
读一行 → 放大 → 整行写回
```

所以：

```text
① 读和写的时序差不多，不能指望"只读更快"
② 读操作也消耗写回的能量，这是 DRAM 功耗的大头之一
③ 刷新和读共用同一条通路，必须排队
```

第三点解释了一个现象：内存压力大的时候，刷新会被推迟，延迟抖动会变大。

工控和车载系统里，这种抖动是要专门度量并留余量的。

## 5. 容易混淆的点

**第一，存取时间和存储周期不是一回事。**

```text
存取时间 Ta：一次读要多久
存储周期 Tmc：两次读之间要隔多久
```

DRAM 的 Tmc 明显大于 Ta，因为要再生。

**第二，刷新按行，不按列，不按字节。**

```text
刷新次数 = 行数
刷新一遍的时间 = 行数 × 存取周期
```

跟位宽、列数、容量都无关。

**第三，地址线数量看的是"单元数"，不是"总位数"。**

```text
1M × 8 位：地址线 20 根（2^20 个单元），数据线 8 根
```

不是 23 根。

**第四，复用后的地址线是"一半"，不是"少两根"。**

```text
n 位地址，复用后 = n/2 根
```

因为行、列各占一半。

**第五，ROM 不是"不能写"，是"写得慢、写得少"。**

EEPROM 能按字节写，只是要几十毫秒。

**第六，编址单位影响地址线数量。**

同一容量，按字编址比按字节编址少 log₂(字长/8) 根线。

**第七，刷新不是"重写全部内容"，是"按行重写"。**

```text
一行的所有列，一次全部放大重写
所以刷新一次的开销是一个存取周期，不是一行有多少位那么多
```

**第八，DRAM 的地址线是"分时复用"，不是"只接一半"。**

```text
行地址和列地址走同一组引脚
靠 RAS、CAS 两个信号区分"现在送的是谁"
```

所以引脚少了，但一次访问要发两个地址。

时间成本在这里，不在引脚上。

## 6. 408 怎么考

题型固定在三类：

```text
选择题：SRAM/DRAM 特性对比、刷新次数、地址线根数、容量换算
计算题：给阵列尺寸和刷新周期，求刷新开销或死区
综合题：给主存容量和编址方式，求地址线、芯片数（下一篇）
```

### 例题 1：地址线根数

某 DRAM 芯片容量为 64M × 8 位，采用行列地址复用，求地址线根数和数据线根数。

解：

```text
64M = 2^26
地址线（不复用）= 26 根
复用后 = 26 / 2 = 13 根
数据线 = 8 根
```

答案：地址线 13 根（外加 RAS、CAS 各 1 根），数据线 8 根。

验算：2^13 × 2^13 = 2^26 = 64M ✓。

### 例题 2：刷新开销

某 DRAM 芯片内部为 128 × 128 阵列，存取周期 0.5 μs，刷新周期 2 ms。

求：(1) 集中刷新的死区与占比；(2) 分散刷新的开销；(3) 异步刷新的刷新间隔。

解：

```text
行数 = 128

(1) 集中刷新
    死区 = 128 × 0.5 μs = 64 μs
    占比 = 64 / 2000 = 3.2%

(2) 分散刷新
    系统周期 = 0.5 + 0.5 = 1 μs
    开销 = 0.5 / 1 = 50%

(3) 异步刷新
    间隔 = 2000 μs / 128 = 15.625 μs
```

验算：15.625 × 128 = 2000 μs = 2 ms ✓。

### 例题 3：带宽

某存储器数据线 16 位，存储周期 40 ns，求带宽。

解：

```text
一次传 16 位 = 2 B
带宽 = 2 B / 40 ns = 2 / (40 × 10⁻⁹) = 5 × 10^7 B/s = 50 MB/s
```

验算：50 MB/s × 40 ns = 2 B ✓。

### 例题 4：编址方式与地址线

某机主存容量 4 GB，分别求按字节编址、按 32 位字编址时的地址线根数。

解：

```text
按字节编址：4 GB = 2^32 B → 2^32 个地址 → 32 根
按字编址：  4 GB / 4 B = 2^30 个字 → 30 根
```

答案：32 根 与 30 根。

差 2 根，正好是 log₂4。

### 例题 5：综合——容量、刷新、带宽一次算完

某 DRAM 芯片容量 16M × 8 位，内部阵列 4096 行 × 4096 列，存取周期 100 ns，刷新周期 64 ms。

求：(1) 复用后的地址线根数；(2) 异步刷新间隔；(3) 集中刷新的死区占比；(4) 带宽。

解：

```text
(1) 16M = 2^24 → 24 根地址线 → 复用后 12 根

(2) 64 ms / 4096 = 15.625 μs

(3) 死区 = 4096 × 100 ns = 409.6 μs
    占比 = 409.6 μs / 64000 μs = 0.64%

(4) 带宽 = 8 位 / 100 ns = 1 B / 100 ns = 10 MB/s
```

验算：

```text
(1) 2^12 × 2^12 = 2^24 = 16M   ✓
(2) 15.625 μs × 4096 = 64000 μs = 64 ms   ✓
(3) 4096 × 100 = 409600 ns = 409.6 μs   ✓
(4) 1 B / 100 × 10⁻⁹ s = 10^7 B/s = 10 MB/s   ✓
```

四个小问共用一组数据，各考一个公式。

408 的综合题常这么出：不给新数据，逼你把同一组数字用三遍。

## 7. 真实芯片里长什么样

（以下为简化示意，实际时序和参数复杂得多。）

**DDR4 的地址结构。**

一颗 8 Gbit 的 DDR4 颗粒，内部是这么分的：

```text
bank 数       16（4 个 bank group × 4 个 bank）
行地址        16 位 → 65536 行
列地址        10 位 → 1024 列
位宽          8 位（x8 颗粒）
```

验算容量：

```text
16 × 65536 × 1024 × 8
= 2^4 × 2^16 × 2^10 × 2^3
= 2^33 bit
= 8 Gbit   ✓
```

**为什么要分 bank？**

因为同一个 bank 里的行操作要串行（先关旧行，再开新行）。

不同 bank 之间可以流水：

```text
bank0 开行 → bank1 开行 → bank0 读 → bank1 读
```

这就是内存控制器调度（bank interleaving）的物理基础。

**DDR5 改了什么？**

```text
bank 数从 16 提到 32（8 个 bank group × 4 个 bank）
通道从 1 个 64 位拆成 2 个 32 位子通道
突发长度从 BL8 变成 BL16
```

一次访问的字节数没变：

```text
DDR4：64 位 × 8 = 64 B
DDR5：32 位 × 16 = 64 B
```

正好一个 Cache 行。

**这不是巧合，是协商结果。**

CPU 的 Cache 行是 64 B，内存就按 64 B 一次给你。

**怎么在 Linux 上看真实参数：**

```text
$ sudo dmidecode -t memory
Memory Device
        Total Width: 64 bits
        Size: 16 GB
        Type: DDR4
        Speed: 3200 MT/s
        Configured Memory Speed: 3200 MT/s
        Rank: 2
        Bank Locator: P0 CHANNEL A
```

读法：

```text
Type: DDR4            代际
Speed: 3200 MT/s      等效频率（不是时钟频率，时钟是 1600 MHz）
Rank: 2               这一条由 2 组颗粒并排放
Total Width: 64 bits  单通道 64 位
```

`dmidecode` 给出的是"内存条"级参数。

它不会告诉你行地址几位、bank 几个，那些在颗粒手册里。

**为什么 3200 MT/s 的时钟是 1600 MHz？**

因为 DDR 是双沿传输（Double Data Rate）。

```text
时钟 1600 MHz，上升沿传一次，下降沿传一次
等效 3200 MT/s
```

算带宽：

```text
3200 MT/s × 8 B（64 位）= 25600 MB/s ≈ 25.6 GB/s
```

双通道就翻倍，约 51.2 GB/s。

## 8. 容量、地址线、编址的三条换算

这三条必须闭着眼睛能写出来。

```text
① 单元数 = 2^(地址线根数)
② 容量 = 单元数 × 存储字长
③ 编址单位决定"一个地址管几个字节"
```

反过来用：

```text
地址线根数 = log₂(单元数)
```

再看几个常见数字，背下来省时间：

```text
2^10 = 1 K      2^20 = 1 M
2^11 = 2 K      2^21 = 2 M
2^12 = 4 K      2^22 = 4 M
2^13 = 8 K      2^23 = 8 M
2^14 = 16 K     2^24 = 16 M
2^15 = 32 K     2^25 = 32 M
2^16 = 64 K     2^26 = 64 M
```

有了这张表，64M 立刻能反推 26 根线、复用后 13 根。

再练四个小换算，吃饭时就能想：

```text
8K × 8 位   → 8K = 2^13 → 13 根地址线，8 根数据线，容量 8 KB
32K × 4 位  → 32K = 2^15 → 15 根地址线，4 根数据线，容量 16 KB
1M × 1 位   → 1M = 2^20 → 20 根地址线，1 根数据线，容量 128 KB
16M × 8 位  → 16M = 2^24 → 24 根地址线，复用后 12 根
```

第三个例子最容易被骗。

```text
1M × 1 位的容量 = 2^20 bit = 2^20 / 8 B = 128 KB
```

不是 1 MB。

"1M"是单元数，"× 1 位"是每个单元 1 位。

容量看的是乘积，不是单元数。

**最后一条容易忽略：地址范围也是容量。**

```text
地址 00000H – 7FFFFH
```

这个范围有多少个地址？

```text
7FFFFH + 1 = 80000H = 2^19 = 524288 = 512 K
```

所以这段地址对应的容量是 512 KB（按字节编址）。

408 给地址范围求容量，就是这个套路：

```text
容量 = 末地址 − 首地址 + 1
```

加那个 1 千万别忘。

0000H 到 0000H 是 1 个字节，不是 0 个。

## 9. 一张表把这一章压成六行

```text
① 容量 = 2^n × 字长，n 是地址线根数
② SRAM 用触发器，不刷新，快，贵，做 Cache
③ DRAM 用电容，要刷新，慢，便宜，做主存
④ DRAM 行列复用：地址线减半，代价是送两次地址
⑤ 刷新按行：刷新次数 = 行数，与列数无关
⑥ 集中/分散/异步，差别在"什么时候刷"，不在"刷多久"
```

六行里，④ 和 ⑥ 最容易背成"结论"。

要多问一句"为什么"：

```text
④ 为什么减半？因为行列分时复用同一组引脚。
⑥ 为什么开销一样？因为总刷新区的大小不变，只是切法变了。
```

能答上这两个"为什么"，这段知识才算长在自己身上。

408 的存储题，从来不是考"你背了几条特性"。

它考的是"给你一组数，能不能推出另一组数"。

## 10. 五道自测题

先别翻答案，用一分钟过一遍。

做错哪道，就回去看对应的那一节。

**题 1：** 一个 DRAM 芯片，行地址 12 位、列地址 12 位、数据线 4 位，容量是多少？

```text
单元数 = 2^12 × 2^12 = 2^24 = 16 M
容量 = 16 M × 4 位 = 64 Mbit
```

**题 2：** 刷新周期 8 ms，芯片有 512 行，异步刷新的间隔是多少？

```text
8 ms / 512 = 15.625 μs
```

**题 3：** SRAM 会不会有"读后数据被破坏"的问题？

```text
不会。触发器读多少遍都不变，是非破坏性读出。
DRAM 才会，所以读完必须再生，Tmc > Ta。
```

**题 4：** 地址 2000H 到 3FFFH 这一段，按字节编址有多少容量？

```text
3FFFH − 2000H + 1 = 1FFFH + 1 = 2000H = 2^13 = 8192 B = 8 KB
```

**题 5：** 一个存储器的地址线 14 根、数据线 4 根，容量是 64 KB 吗？

```text
不是。单元数 = 2^14 = 16K，容量 = 16K × 4 位 = 64 Kbit = 8 KB。
```

"K 个单元"和"KB"是两个东西，中间差着"位宽 / 8"。

## 11. 这一篇给下一章留了什么

三件事，下一章直接用：

```text
① 一片芯片的容量有限，要凑出大主存 → 扩展
② 地址线只有那么多根，要选出芯片 → 译码
③ 一次只能读写一个单元，要提速 → 多模块交叉
```

三件事正好对应 07、07、08 三篇。

第①件事的算式先给出来，下一篇直接用：

```text
芯片数 = 总容量 / 单片容量
```

但这一个式子里藏着两种完全不同的拼法。

一种是"字不够长"，一种是"字数不够多"。

```text
位扩展：拼字长，所有芯片同时工作
字扩展：拼字数，同一时刻只有一片工作
```

这两种拼法的地址线接法完全不同，下一篇的主角。

## 12. 小结

存储器这一块，先把层次和芯片分开：

```text
层次：寄存器 / Cache / 主存 / 辅存，越往下越大越慢越便宜
芯片：SRAM 快而贵，DRAM 慢而便宜，ROM 非易失
```

四个数必须记住：

```text
容量 = 2^n × 字长
1 KB = 2^10，1 MB = 2^20，1 GB = 2^30
DRAM 复用后地址线 = n/2
刷新次数 = 行数
```

一句话总结 SRAM 和 DRAM：

```text
SRAM 用 6 个晶体管买"不用管"，
DRAM 用 1 管 1 容买"便宜"，然后一辈子还刷新这笔债。
```

读书时容易记住"SRAM 快、DRAM 便宜"。

写题时真正拉开差距的，是下面这句：

```text
所有 DRAM 的麻烦，都来自那个会漏电的电容；
所有 SRAM 的优点和缺点，都来自那 6 个管子。
```

忘了某条特性时，回到这句话推一遍，基本都能推出来。
