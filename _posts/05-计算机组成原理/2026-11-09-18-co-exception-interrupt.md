一条指令正走到执行阶段，忽然停住了。

原因可能有三类。

```text
除数是 0
要访问的页不在内存
网卡收到一个包，或者定时器又响了一次
```

第一类，CPU 自己算出了错。

第二类，CPU 访存时发现目标不在。

第三类，完全来自 CPU 外部。

三件事的共同点是：

```text
当前程序必须停下，跳到另一段代码去处理，处理完再回来。
```

区别在于"谁引起的"、"什么时候引起"、"回来时从哪条指令继续"。

这三个问题的答案，就是异常与中断的全部分类。

**先放一句反直觉的话在这里：**

```text
中断不是"打断后重来"，而是"打断后精确恢复"。
```

保存的不只是 PC。

还有程序状态字（PSW）、通用寄存器、有时候还有浮点状态。

少保存一个，回来就错。

## 1. 三个场景：CPU 为什么会跳走

**场景一：除零。**

```asm
DIV R1, R2      ; R2 = 0
```

除法指令在 ALU 里执行，除数检查发现为 0。

结果无法产生。

CPU 必须放弃这条指令，转而报告给操作系统。

**场景二：缺页。**

```asm
LOAD R1, 0(R2)  ; R2 指向的页不在物理内存
```

指令本身没毛病，地址也合法。

问题是那一页还在磁盘上。

CPU 在访存阶段发现页表项无效，触发缺页。

操作系统要把页从磁盘读进来、更新页表，然后**重新执行这条 LOAD**。

**场景三：时钟中断。**

```text
每 1 ms，定时器向 CPU 发一次中断请求。
```

当前程序完全是好的。

没有出错，没有缺页，只是时间片用完了。

操作系统要抢占它，换另一个进程。

三种场景，三种处理方式：

```text
除零      报告错误，可能终止进程
缺页      补好数据，重新执行当前指令
时钟中断  与当前指令无关，回来后执行下一条
```

注意第三种的"回来后执行下一条"。

它和第一种、第二种完全不同。

## 2. 最小模型：异常与中断的分类

先分最大的两类。

```text
异常（exception，内中断）：由 CPU 内部在执行指令过程中检测到
中断（interrupt，外中断）：由 CPU 外部的设备或时钟提出请求
```

异常再分三种，按"处理完之后能不能回来、从哪回来"分。

**故障（fault）**

```text
在执行指令的过程中检测到，但处理完之后可以重新执行这条指令。
典型：缺页、除数为零、访问越界。
返回地址：当前指令。
```

**陷入（trap）**

```text
由程序主动触发，是有意的，不是错误。
典型：系统调用、调试断点、单步。
返回地址：下一条指令。
```

**终止（abort）**

```text
硬件出了严重问题，程序无法继续。
典型：存储器校验错、总线错误、控制器故障。
返回地址：没有，进程被终止。
```

三类的对照：

| 类型 | 英文 | 引起原因 | 典型例子 | 返回地址 |
|---|---|---|---|---|
| 故障 | fault | 指令执行中检测到错误 | 缺页、除零 | 当前指令 |
| 陷入 | trap | 程序主动请求 | 系统调用、断点 | 下一条指令 |
| 终止 | abort | 硬件严重故障 | 校验错、总线错 | 不返回 |

中断再分两种。

**可屏蔽中断（maskable interrupt，INTR）**

```text
CPU 可以通过中断允许标志（IF）或屏蔽字禁止它。
典型：键盘、网卡、磁盘、定时器。
```

**不可屏蔽中断（non-maskable interrupt，NMI）**

```text
CPU 不能屏蔽，必须响应。
典型：电源故障、内存校验错、看门狗超时。
```

一句话区分：

```text
可屏蔽中断是"可以等一下"的事。
不可屏蔽中断是"现在必须处理"的事。
```

中断存在的三个理由：

```text
① 实时处理：设备随时可能就绪，CPU 不能一直等
② 故障处理：硬件出错要立刻知道
③ 进程切换：时间片轮转靠时钟中断
```

没有中断，CPU 只能轮询（polling）。

大量时间花在"问好了没"上。

这是第 22 篇 I/O 方式的起点。

## 3. 中断响应过程：五步

一次中断，从请求到进入服务程序，分五步。

前四步由硬件自动完成，合称**中断隐指令**（interrupt hidden instruction）。

它不是一条真正的指令，用户看不见，也不占指令集。

```text
① 关中断            IF ← 0，禁止新的中断进来
② 保存断点          PC（和 PSW）压栈，或存入专用寄存器
③ 识别中断源        判优 + 取向量，或软件轮询
④ 转中断服务程序    向量地址 → PC
```

接着是软件部分：

```text
⑤ 保存现场          通用寄存器、状态寄存器入栈
⑥ 开中断            允许更高级的中断嵌套
⑦ 执行中断服务      真正干活
⑧ 恢复现场、开中断、中断返回（IRET）
```

顺序不能乱。

尤其第①步和第②步。

```text
如果先保存断点、后关中断：
保存过程中如果又来一个中断，断点会被覆盖，原程序回不去。
所以必须"先关门，再记账"。
```

第④步之后，PC 已经指向服务程序。

但此时通用寄存器还是被打断程序的现场。

所以第⑤步必须紧接着做。

否则服务程序一用寄存器，现场就没了。

完整流程画成一条线：

```text
          请求
           │
           ▼
   ┌───────────────┐
   │ ① 关中断       │  硬件
   │ ② 保存 PC/PSW  │  硬件（中断隐指令）
   │ ③ 识别中断源   │  硬件
   │ ④ 转服务程序   │  硬件
   ├───────────────┤
   │ ⑤ 保存现场     │  软件
   │ ⑥ 开中断       │  软件
   │ ⑦ 执行服务     │  软件
   │ ⑧ 恢复并返回   │  软件
   └───────────────┘
           │
           ▼
       继续原程序
```

一句话记：

```text
关中断、存断点、找源头、转服务。
```

这四个动作，是 408 顺序题的标准答案骨架。

### 3.1 断点落在哪里

中断看起来是"随时"来的，但 CPU 只在一个地方响应它：指令边界。

```text
一条指令执行完之后，CPU 检查有没有中断请求。
有，就进入响应流程；没有，就取下一条指令。
```

所以：

```text
中断请求是异步的，中断响应是同步的。
```

断点因此总是落在两条指令之间。

三种断点位置，对应三种返回地址：

```text
响应在指令 i 执行完之后   → 断点是 i+1 的地址
异常发生在指令 i 执行之中 → 断点是 i 的地址（fault）
陷入由指令 i 主动触发     → 断点是 i+1 的地址（trap）
```

为什么 fault 的断点是 i 自己？

因为 i 没有执行成功，必须重来。

为什么 trap 的断点是 i+1？

因为 i 已经完成了它的使命，比如把系统调用号放进了寄存器，不需要重来。

这一小节，就是 408 里所有"断点地址"题的逻辑来源。

## 4. 中断源识别与中断向量表

第③步"识别中断源"，有两种做法。

**向量中断（vectored interrupt）**

```text
每个中断源有一个固定的中断类型号（向量号）。
CPU 用向量号去查中断向量表，得到服务程序入口地址。
```

查表方式（简化示意）：

```text
向量表基址（IDTR / VBAR 之类）+ 向量号 × 表项大小 = 表项地址
表项内容：服务程序入口地址（或一条跳转指令）
```

**轮询（polling）**

```text
CPU 依次查询每个设备的"请求"标志位。
谁先被查到，谁先服务。
```

两者对比：

```text
向量中断：硬件判优，快，硬件复杂
轮询：      软件判优，慢，硬件简单
```

中断向量表（interrupt vector table）的本质，是一张**地址表**。

```text
下标：中断类型号
内容：该类型中断的服务程序入口地址
```

一道小计算：

```text
中断向量表每项 4 字节，表基址 0x00001000。
中断类型号为 0x21。
服务程序入口地址存放在：0x00001000 + 0x21 × 4 = 0x00001084
```

算的时候注意两点：

```text
乘的是表项大小，不是向量号本身
表基址要加上，别只算偏移
```

第③步还有一件事：**判优**。

多个中断源同时请求，谁先响应？

```text
硬件判优：并行优先级编码器、菊花链（daisy chain）
软件判优：轮询顺序就是优先级
```

优先级通常固定写在硬件里，改不了。

能改的是"能不能打断"，那是屏蔽字的事。

## 5. 多重中断：屏蔽字、优先级与嵌套

**多重中断**（multiple interrupt）指一个中断服务程序还没执行完，又被另一个更高级的中断打断。

要支持它，需要三样东西：

```text
① 中断优先级：同时请求时谁先响应
② 中断屏蔽字：执行某个服务程序时，允许谁打断
③ 开中断：服务程序里要主动开中断，否则嵌套不了
```

**中断屏蔽字**（interrupt mask word）是一个寄存器。

```text
每一位对应一个中断源。
1 表示屏蔽（禁止该源打断当前程序），0 表示允许。
```

注意区分两个概念：

```text
响应优先级：硬件排队器决定，多个请求同时到达时谁先被响应，固定
处理优先级：屏蔽字决定，谁能打断谁，可编程
```

408 里有一类题，专门考"用屏蔽字改变处理次序"。

比如本来优先级 A > B > C > D，通过设置屏蔽字，可以让 C 先被处理完，再处理 A。

因为 A 的屏蔽字里把 C 屏蔽了。

**完整嵌套**（full nesting）的规则：

```text
执行第 i 级服务程序时，屏蔽字屏蔽"自己及所有更低级"，不屏蔽"更高级"。
于是更高级的可以随时打断，同级的不能互相打断。
```

现在手算一次。

### 5.1 走查：四个中断源的嵌套轨迹

题目（自拟）：

```text
4 个中断源 A、B、C、D，硬件优先级 A > B > C > D。
每个服务程序需要 2 个时间单位。
主程序 t=0 开始执行，初始为开中断。
请求到达时刻：D 在 t=1，C 在 t=2，B 在 t=3，A 在 t=4。
采用完全嵌套。
求：CPU 的执行轨迹与各服务程序的完成时刻。
```

一步一步走。

```text
t=1  D 请求，无中断在执行 → 响应 D，D 执行 1 个单位（t=1..3）
     D 的屏蔽字：屏蔽 D，不屏蔽 A、B、C → 0001
```

```text
t=2  C 请求，C 高于 D，D 未屏蔽 C → 嵌套，响应 C（t=2..4）
     D 已执行 1 个单位，还剩 1 个
     C 的屏蔽字：屏蔽 C、D → 0011
```

```text
t=3  B 请求，B 高于 C，C 未屏蔽 B → 嵌套，响应 B（t=3..5）
     C 已执行 1 个单位，还剩 1 个
     B 的屏蔽字：屏蔽 B、C、D → 0111
```

```text
t=4  A 请求，A 高于 B，B 未屏蔽 A → 嵌套，响应 A（t=4..6）
     B 已执行 1 个单位，还剩 1 个
     A 的屏蔽字：屏蔽 A、B、C、D → 1111
```

```text
t=6  A 完成，返回 B，B 再执行 1 个单位（t=6..7）
t=7  B 完成，返回 C，C 再执行 1 个单位（t=7..8）
t=8  C 完成，返回 D，D 再执行 1 个单位（t=8..9）
t=9  D 完成，返回主程序
```

执行轨迹：

```text
D → C → B → A → B → C → D
```

完成时刻：

```text
A 在 t=6
B 在 t=7
C 在 t=8
D 在 t=9
```

画成时间轴：

```text
t=1  ┬─ 主程序被打断，D 开始（第 1 段）
t=2  ├─ C 打断 D，D 挂起（第 1 段只跑了 1 个单位）
t=3  ├─ B 打断 C，C 挂起
t=4  ├─ A 打断 B，B 挂起
t=6  ├─ A 完成，B 继续（第 2 段）
t=7  ├─ B 完成，C 继续（第 2 段）
t=8  ├─ C 完成，D 继续（第 2 段）
t=9  └─ D 完成，回主程序
```

（简化示意：每一行是一个时间点，缩进表示嵌套的层次。）

看这张图能读出两条规律：

```text
进入的顺序是 D、C、B、A（从低到高，越晚来的优先级越高，越先抢到 CPU）
退出的顺序是 A、B、C、D（从高到低，像栈）
```

所以多重中断的现场，本质是一个**栈**。

后进先出。

### 5.2 反例：全部屏蔽会怎样

把条件改成：

```text
所有服务程序的屏蔽字都是 1111（不允许任何嵌套）。
```

重走一遍：

```text
t=1  D 请求 → 响应 D（t=1..3）
t=2  C 请求 → 被 D 屏蔽，等待
t=3  B 请求；D 完成，等待中的有 C、B → 按优先级选 B（t=3..5）
t=4  A 请求 → 被 B 屏蔽，等待
t=5  B 完成，等待中的有 C、A → 按优先级选 A（t=5..7）
t=7  A 完成 → 只剩 C，响应 C（t=7..9）
t=9  C 完成
```

执行轨迹变成：

```text
D → B → A → C
```

完成时刻：

```text
A 在 t=7
C 在 t=9
```

对比两种结果：

```text
完全嵌套：D C B A B C D，A 最早完成（t=6）
全屏蔽：  D B A C，      A 反而晚完成（t=7）
```

这说明一件事：

```text
允许嵌套，不是让高级中断"等得更久"，而是让它"插得更快"。
```

A 在两种情况下都是 t=4 到达。

允许嵌套时，它立刻抢到了 CPU。

全屏蔽时，它要等 B 执行完。

这就是多重中断存在的意义。

## 6. 408 怎么考

题型四类：

```text
① 判断某个事件是异常还是中断，是哪种异常
② 排出中断响应过程的顺序
③ 屏蔽字设计与执行轨迹
④ 中断向量表地址计算
```

### 6.1 例题一：判断类型

题目（自拟）：下列事件各属于哪一类？

```text
(a) 执行 DIV 指令时除数为 0
(b) 程序执行 syscall 进入内核
(c) 内存条出现校验错，数据不可信
(d) 键盘按下一个键
(e) 访问的页不在物理内存
(f) 电源电压跌落
```

答案：

```text
(a) 故障 fault，返回当前指令
(b) 陷入 trap，返回下一条指令
(c) 终止 abort，不返回
(d) 可屏蔽中断 INTR，返回下一条指令
(e) 故障 fault，补页后重新执行当前指令
(f) 不可屏蔽中断 NMI，返回下一条指令
```

判断的两个抓手：

```text
先看来源：CPU 内部 → 异常；CPU 外部 → 中断
再看返回：当前指令 → fault；下一条 → trap 或中断；不返回 → abort
```

一个易错点：

```text
"除零"很多人答成 abort。
abort 是硬件坏到没法继续，除零是软件错误，操作系统还能处理，属于 fault。
```

### 6.2 例题二：屏蔽字与执行轨迹

用 5.1 的条件，改问法：

```text
4 个中断源 A、B、C、D，优先级 A > B > C > D。
请求时刻：D 在 t=1，C 在 t=2，B 在 t=3，A 在 t=4。
采用完全嵌套，服务程序各需 2 个时间单位。
(1) 写出执行轨迹
(2) 求 A、D 的完成时刻
(3) 如果 A 在 t=8 才到达，执行轨迹会变成什么？
```

(1)(2) 的答案上面已经算过：

```text
轨迹：D → C → B → A → B → C → D
A 完成于 t=6，D 完成于 t=9
```

(3) 重新走：

```text
t=1  D 响应（t=1..3）
t=2  C 嵌套（t=2..4），D 剩 1 个单位
t=3  B 嵌套（t=3..5），C 剩 1 个单位
t=5  B 完成 → 返回 C，C 执行 t=5..6
t=6  C 完成 → 返回 D，D 执行 t=6..7
t=7  D 完成 → 回到主程序
t=8  A 到达 → 无中断在执行 → 响应 A（t=8..10）
```

轨迹：

```text
D → C → B → C → D → A
```

A 完成于 t=10。

注意 t=5 到 t=7 这段。

```text
D 和 C 是被打断的，它们剩下的部分按"后进先出"的顺序补完。
先补 C（更晚进入），再补 D（更早进入）。
```

验证一个不变量：

```text
每个服务程序的总执行时间都是 2 个单位。
D：t=1..2 加 t=6..7，共 2 ✓
C：t=2..3 加 t=5..6，共 2 ✓
B：t=3..5，共 2 ✓
```

这道题的判分点只有三个：

```text
① 谁能打断谁（屏蔽字 + 优先级）
② 被打断的剩余部分什么时候补
③ 完成时刻用"最后一段的结束时间"
```

### 6.3 例题三：向量表地址

题目（自拟）：

```text
中断向量表基址为 0x00002000，每项 8 字节，共 256 项。
(1) 类型号为 0x0E 的中断，其入口地址存在哪个单元？
(2) 该表共占多少字节？能容纳多少个中断类型？
```

(1)

```text
0x00002000 + 0x0E × 8 = 0x00002000 + 0x70 = 0x00002070
```

(2)

```text
256 × 8 = 2048 字节 = 2 KB
能容纳 256 个中断类型（类型号 0x00 ~ 0xFF）
```

验算 (1)：

```text
0x0E = 14
14 × 8 = 112 = 0x70 ✓
0x2000 + 0x70 = 0x2070 ✓
```

这里最容易错的是"表项大小"。

```text
实模式下每项 4 字节（段:偏移）
保护模式下每项 8 字节（门描述符）
题目给多少就用多少，不要凭印象。
```

### 6.4 例题四：中断开销

题目（自拟）：

```text
某 CPU 主频 1 GHz。
一次中断的响应加现场保存、恢复，共需 500 个时钟周期。
某设备每秒产生 2000 次中断。
求：中断开销占 CPU 时间的百分比。
```

单次开销：

```text
500 ÷ (1 × 10^9) s = 500 ns
```

每秒总开销：

```text
2000 × 500 ns = 1 000 000 ns = 1 ms
```

占比：

```text
1 ms ÷ 1000 ms = 0.1%
```

再问一句：

```text
如果换成每秒 50 万次中断的高速网卡，占比多少？
```

```text
5 × 10^5 × 500 ns = 2.5 × 10^8 ns = 250 ms
250 ms ÷ 1000 ms = 25%
```

四分之一的 CPU 时间花在中断上。

这就解释了为什么高速网络要用轮询（polling）或者中断合并（interrupt coalescing）。

```text
中断不是越多越好。
每次中断都有固定开销，频率高到一定程度，开销会吃掉收益。
```

## 7. 真实芯片里长什么样

**x86：IDT 与 APIC。**

x86 保护模式用中断描述符表（interrupt descriptor table，IDT）统一管理异常和中断。

```text
IDT 最多 256 项，每项 8 字节（门描述符）。
表基址存在 IDTR 寄存器里。
0 ~ 31 号由 Intel 保留给异常，32 ~ 255 给外部中断和软件中断。
```

几个具体的向量号：

```text
0    除零（#DE）
13   通用保护错（#GP）
14   缺页（#PF）
```

外部中断走本地 APIC（advanced programmable interrupt controller）。

不可屏蔽中断 NMI 走独立引脚，不受 IF 控制。

系统调用有两代做法：

```text
老办法：int 0x80，走中断门
x86-64：syscall 指令，入口地址存在 MSR LSTAR 里
```

缺页异常 #PF 的处理，正好是 fault 的标准例子：

```text
操作系统在 #PF 处理程序里把页调入、改页表，
然后执行 IRET 回到出错的那条指令，重新执行。
```

这就是"返回当前指令"的现实版本。

再补一个常被问的细节：中断门与陷阱门。

```text
中断门（interrupt gate）：进入时自动关中断（IF ← 0）
陷阱门（trap gate）：进入时不关中断
```

硬件中断用中断门，系统调用一般用陷阱门。

两者的区别只在"进门时关不关中断"，其他都一样。

（简化示意：x86-64 上还有 IST 等机制专门处理 NMI 与双重故障。）

在 Linux 上可以直接看到这些计数：

```text
/proc/interrupts   每个 IRQ 在每个 CPU 上的中断次数
vmstat 的 in 列    每秒中断次数
```

（简化示意：现代 x86 还有 APIC 虚拟化、中断重映射等，向量号分配也更复杂。）

**ARM：异常等级与 VBAR。**

ARMv8 把异常分成同步异常和异步异常。

```text
同步异常：由当前指令直接引起，如 SVC、缺页、对齐错误
异步异常：与当前指令无关，如 IRQ、FIQ、SError
```

特权级分四层：

```text
EL0 用户程序
EL1 操作系统内核
EL2 虚拟化监控
EL3 安全监控
```

向量表基址放在 VBAR_EL1 这类寄存器里。

```text
向量表按"异常来源 × 异常类型"组织成 4 × 4 项。
系统调用用 SVC #0 指令，同步异常进入 EL1。
返回用 ERET，从 ELR_EL1 恢复 PC，从 SPSR_EL1 恢复 PSTATE。
```

中断控制器叫 GIC（generic interrupt controller），负责分发与优先级。

（简化示意：GIC 的版本与分组、SError 的触发源，各实现差异很大。）

**两家的共同点：**

```text
都有一个"向量表 + 基址寄存器"的结构。
都有"保存 PC + 保存状态 + 换特权级"这三件事。
都把"返回地址取当前还是取下一条"写死在异常类型里。
```

## 8. 反直觉：不是"重来"，是"精确恢复"

回到那句话：

```text
中断不是"打断后重来"，而是"打断后精确恢复"。
```

为什么强调"精确"？

先看一个只保存 PC 的例子。

```asm
ADD R1, R2, R3     ; 结果 ZF = 1（为零）
BEQ  target        ; 若 ZF = 1 则跳转
```

假设 `ADD` 执行完、`BEQ` 还没执行时来了中断。

只保存 PC（指向 `BEQ`）就跳走了。

服务程序里执行了 `SUB`，把 ZF 改成了 0。

返回后恢复 PC，执行 `BEQ`。

ZF 已经不是 1 了。

**跳错了。**

所以必须保存程序状态字（PSW / EFLAGS / PSTATE）。

它里面装着：

```text
条件码：ZF、CF、OF、SF
中断允许位：IF
方向位、特权级、跟踪位
```

少保存一个条件码，回来就可能走错分支。

再看现场寄存器。

```text
被打断的程序，R1 里可能存着循环计数器。
服务程序如果不保存 R1 就随便用，回来计数器就变了。
```

所以第⑤步"保存现场"，保存的是：

```text
通用寄存器
状态寄存器
必要时还有浮点/SIMD 寄存器、MMU 上下文（页表基址）
```

"精确"还有第二层意思：叫**精确异常**（precise exception）。

```text
发生异常时，异常指令之前的所有指令都已完成。
异常指令之后的所有指令都还没产生任何效果。
```

为什么难？

因为流水线里同时有好几条指令在飞。

分支预测可能已经把后面的指令执行了一部分。

要保证"后面的指令没有效果"，就得把它们冲刷掉（flush）。

这就是第 19 篇要讲的流水线冲刷。

所以"精确恢复"这四个字，背后是一整套机制：

```text
保存 PC        → 知道回到哪
保存 PSW       → 知道回到什么状态
保存现场       → 知道回到什么数据
精确异常       → 保证回来时机器状态是干净的
```

少一样，都叫"不精确"。

不精确中断的后果，比"算错一个数"严重得多。

它会让程序在**不可复现的状态**下出错。

## 9. 异常与中断的区别

把前面的内容压成一张表：

| 对比项 | 异常（内中断） | 中断（外中断） |
|---|---|---|
| 来源 | CPU 内部，指令执行引起 | CPU 外部，设备或时钟提出 |
| 与当前指令的关系 | 同步，由当前指令直接引起 | 异步，与当前指令无关 |
| 产生时机 | 指令执行过程中 | 任意时刻 |
| 是否可屏蔽 | 一般不可屏蔽（除零不能屏蔽） | 可屏蔽或不可屏蔽 |
| 返回地址 | fault 返回当前指令，trap 返回下一条 | 返回下一条指令 |
| 典型例子 | 缺页、除零、系统调用、断点 | 键盘、网卡、定时器 |
| 处理者 | 操作系统（异常处理程序） | 操作系统（中断服务程序） |

记住三行就够：

```text
异常是"自己出错/自己请求"，中断是"外面叫你"。
异常和指令同步，中断和指令异步。
异常一般不可屏蔽，中断分可屏蔽与不可屏蔽。
```

## 10. 容易混淆的点

**第一，中断响应和中断处理不是一回事。**

```text
中断响应：硬件自动完成，关中断、存断点、找源头、转服务
中断处理：软件完成，保存现场、执行服务、恢复、返回
```

题目问"中断响应过程"，答四步，不要答成八步。

**第二，中断隐指令不是指令。**

```text
它是硬件在响应中断时自动完成的一系列操作。
不在指令系统里，程序员写不出来。
```

**第三，屏蔽字和优先级是两个机制。**

```text
优先级：多个请求同时到达，谁先被响应（硬件定）
屏蔽字：正在执行的服务程序，允许谁打断（软件定）
```

屏蔽字不能改变"同时到达时的响应顺序"，但能改变"实际处理完成的顺序"。

**第四，关中断和屏蔽字不是一回事。**

```text
关中断：IF ← 0，屏蔽所有可屏蔽中断，全局
屏蔽字：只屏蔽指定源，局部
```

NMI 两者都挡不住。

**第五，fault 和 trap 的返回地址差一条指令。**

```text
fault：返回当前指令，重新执行
trap： 返回下一条指令，继续往下走
```

除零、缺页是 fault，系统调用、断点是 trap。

**第六，缺页是异常，不是中断。**

虽然它由"访存"引起，看起来像外部事件，但它是 CPU 在执行指令时检测到的。

**第七，中断向量、向量表、向量地址是三个东西。**

```text
向量（类型号）：一个编号，如 14
向量表：存入口地址的数组
向量地址：表项的地址，基址 + 向量 × 表项大小
```

**第八，保存断点是硬件的活，保存现场是软件的活。**

问"中断响应时保存了什么"，答案是 PC 和 PSW。

问"中断服务程序开头做了什么"，答案是保存通用寄存器。

**第九，不可屏蔽中断也能被"延迟"。**

NMI 不能被 IF 屏蔽，但 CPU 可以在执行关键指令时短暂延迟响应。

"不可屏蔽"不等于"零延迟"。

**第十，单重中断与多重中断的差别只在一处。**

```text
单重中断：服务程序里不开中断，执行期间不响应任何新请求
多重中断：服务程序里开中断，允许更高级的请求打断
```

两者的硬件基础完全相同。

区别只在软件有没有执行"开中断"这一步。

**第十一，中断服务程序里也可能出现异常。**

中断处理过程中如果发生缺页，CPU 会先处理缺页异常，再回来继续中断服务。

这叫"中断嵌套异常"。

所以"当前在中断服务程序里"并不等于"不会再被打断"。

## 11. 小结

异常与中断，压成一张分类图：

```text
异常（内）  故障 fault    缺页、除零       返回当前指令
            陷入 trap     系统调用、断点    返回下一条
            终止 abort    校验错、总线错    不返回

中断（外）  可屏蔽 INTR   键盘、网卡、时钟  可被 IF/屏蔽字禁止
            不可屏蔽 NMI  电源、看门狗      必须响应
```

中断响应的四步，顺序不能乱：

```text
① 关中断
② 保存断点（PC、PSW）
③ 识别中断源（判优、取向量）
④ 转中断服务程序
```

多重中断的两个机制：

```text
优先级：谁先被响应
屏蔽字：谁能打断谁
```

一个必会的计算：

```text
完全嵌套的执行轨迹，进入从低到高，退出从高到低。
被打断的服务程序，剩余部分按"后进先出"补完。
```

最后是那句反直觉的话：

```text
中断不是重来，是精确恢复。
PC 决定回到哪，PSW 决定回到什么状态，现场决定回到什么数据，精确异常决定回来时机器干不干净。
```

下一篇讲流水线。

一条指令被拆成五段，五条指令同时在飞。

于是"精确异常"变难了：异常发生时，后面那几条已经跑了一半的指令怎么办？

还有更常见的麻烦：后一条指令要用前一条的结果，可结果还没算出来。
