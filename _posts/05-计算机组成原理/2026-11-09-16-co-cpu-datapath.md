单总线 CPU，取一条指令，要四个时钟周期。

```text
T0: PC → MAR
T1: M(MAR) → MDR
T2: MDR → IR
T3: PC + 1 → PC
```

四个微操作，四拍。

为什么不能一拍做完？

因为四个操作都要用同一条内部总线。

同一时刻，总线上只能有一个数据在跑。

PC 的值上了总线，MAR 才能收。

MAR 把地址送到内存，内存才能把指令送回 MDR。

MDR 上了总线，IR 才能收。

每一步都得排队。

**反直觉的点在这里：**

```text
单总线慢，不是因为线少。
是因为"一次只能有一个数据上总线"。
```

哪怕把总线从 16 位加宽到 64 位，取指还是四拍。

加宽只是让一次搬的位数变多，没有让"排队"消失。

要减少拍数，得加总线、加专用通路，让多个数据同时走。

这一篇把 CPU 拆开，重点写微操作序列。

## 1. CPU 里有哪些部件

先看一张单总线 CPU 的结构图。

```text
        +-----+   +-----+   +------+   +------+
        | PC  |   | IR  |   |  R0  |   |  R1  | ...
        +--+--+   +--+--+   +--+---+   +--+---+
           |         |         |          |
        +--+---------+---------+----------+--+
        |              内部总线                |
        +--+---------+---------+----------+--+
           |         |         |          |
        +--+--+   +--+--+   +--+--+    +--+--+
        | MAR |   | MDR |   |  A  |    |  B  |
        +--+--+   +--+--+   +--+--+    +--+--+
           |         |          \          /
           |         |         +------------+
           |         |         |    ALU     |
           |         |         +-----+------+
           |         |               |
        +--+---------+--+         +--+--+
        |     主存       |         |  Z  |
        +----------------+         +-----+
```

部件分三组。

**第一组：程序员能看见的。**

```text
PC：程序计数器，存下一条指令的地址
通用寄存器 R0、R1…：存操作数
PSW：程序状态字，存标志位
```

**第二组：程序员看不见的。**

```text
IR：指令寄存器，存当前指令
MAR：存储器地址寄存器，驱动地址总线
MDR：存储器数据寄存器，缓冲数据总线
```

**第三组：干活的。**

```text
ALU：算术逻辑单元
A、B：ALU 的两个输入锁存器
Z：ALU 的输出锁存器
控制器：译码、发控制信号
```

每个部件的职责，可以用一句话说清：

```text
PC    → 下一步去哪取指令
IR    → 当前这条指令长什么样
MAR   → 要访问哪个内存单元
MDR   → 读出来或写进去的数据
PSW   → 上一次运算的结果状态
ALU   → 做加减与逻辑运算
控制器 → 根据 IR 和 PSW，决定下一步发什么信号
```

为什么要有 MAR 和 MDR？

因为 CPU 和内存之间隔着系统总线。

CPU 不能直接把 PC 接到地址总线上。

它要先把地址放进 MAR，再由 MAR 驱动地址总线。

数据也一样，先放进 MDR，再决定送去哪里。

MAR 和 MDR 是"缓冲"和"隔离"。

它们让 CPU 内部的时序，和内存的时序解耦。

CPU 很快，内存很慢。

如果 PC 直接连地址总线，内存还没准备好，PC 可能已经变了。

所以先把地址锁进 MAR，让它稳定地挂在地址总线上。

数据也一样，先锁进 MDR，等 CPU 需要时再取。

这就是"寄存器隔离"的作用。

从程序员的角度看，部件分两类：

```text
可见：PC、通用寄存器、PSW
不可见：IR、MAR、MDR、A、B、Z
```

可见的，汇编语言能直接操作。

不可见的，由硬件自动管理，指令里看不到。

408 有时问"哪些寄存器对程序员透明"。

答案就是不可见的那一组。

PSW 要单独说一句。

它不是"一个"寄存器，而是一组标志位的集合。

```text
ZF：结果为零
SF：结果为负
CF：进位/借位
OF：有符号溢出
IF：中断允许
```

ALU 每次运算完，都会更新这些位。

条件跳转、中断响应，都要读它。

408 有时把 PSW 画在 ALU 旁边，有时画在控制器旁边。

位置不同，作用一样：保存"上一次运算的状态"。

## 2. 指令周期的四个阶段

一条指令从出生到退休，分四个阶段。

```text
取指（fetch）
间址（indirect）
执行（execute）
中断（interrupt）
```

不是每条指令都走四段。

```text
取指：每条指令都有
间址：只有间接寻址的指令才有
执行：每条指令都有
中断：有中断请求、且允许中断时才走
```

所以一条指令周期，可能是：

```text
取指 + 执行
取指 + 间址 + 执行
取指 + 执行 + 中断
取指 + 间址 + 执行 + 中断
```

四个阶段的关系：

```text
取指 → 译码 → 间址? → 执行 → 中断?
```

译码不算独立阶段，它夹在取指和执行之间。

控制器拿到 IR 里的操作码，才知道执行阶段该发什么信号。

### 2.1 三个"周期"

408 喜欢考这三个词的区别。

```text
时钟周期：CPU 的主频倒数，最小时间单位
机器周期：完成一个基本操作的时间，通常几个时钟周期
指令周期：一条指令从取指到执行完的时间
```

关系：

```text
指令周期 = 若干个机器周期
机器周期 = 若干个时钟周期
```

一条指令可能包含：

```text
取指周期（一个机器周期）
间址周期（一个机器周期）
执行周期（一个机器周期）
中断周期（一个机器周期）
```

每个机器周期里，又有若干个时钟周期，每个时钟周期完成一个微操作。

微操作是"不能再分的最小操作"。

```text
PC → MAR        一个微操作
M(MAR) → MDR    一个微操作
MDR → IR        一个微操作
```

一个微操作，通常一个时钟周期。

所以"取指四个微操作"，就是"取指四个时钟周期"。

译码为什么不单列一个阶段？

因为译码和取指的最后一步重叠。

IR 收到指令的同时，控制器就开始译码。

译码本身不访存，也不改数据，只是把操作码变成控制信号。

所以教材把它算在取指周期的末尾，或者算在执行周期的开头。

指令周期的长短，不是固定的。

```text
最短：取指 + 执行
最长：取指 + 间址 + 执行 + 中断
```

同一台机器，不同指令的周期数可以差很多。

408 算 CPI 时，要把每种指令的周期数按比例加权。

不能拿一条指令的周期数当整台机器的 CPI。

取指周期是唯一不能省的阶段。

```text
没有取指，CPU 不知道要执行什么。
```

所以算周期数时，取指是"固定开销"。

```text
总周期 = 指令条数 × 取指拍数 + 各指令执行拍数之和
```

这个式子，就是例题一用的算法。

执行拍数按指令类型加权，不能直接取平均。

因为不同指令的执行拍数，可能差好几倍。

把这两件事分开算，CPI 就不会错。

### 2.2 一笔具体的周期账

一条 `ADD R1, R2`，单总线：

```text
取指：4 拍
执行：3 拍
合计：7 拍
```

主频 1 GHz，一个时钟周期 1 ns。

```text
一条 ADD 要 7 ns
```

1000 条 ADD：

```text
7 × 1000 = 7000 拍 = 7000 ns = 7 μs
```

如果把取指从 4 拍压到 3 拍：

```text
每条 6 拍
1000 条 6000 拍 = 6 μs
```

快了 14%。

这就是"微操作少一拍"在程序层面的放大效应。

单条指令省 1 ns，看起来不多。

一百万条指令，就省 1 ms。

所以数据通路的优化，永远值得做。

## 3. 单总线数据通路

单总线结构，所有部件都挂在同一条内部总线上。

```text
PC、IR、通用寄存器、MAR、MDR、A、B、Z
        ↓
     内部总线
```

任何两个部件之间传数据，都要经过这条总线。

### 3.1 一次只能有一个发送方

总线是共享的。

如果 PC 和 R1 同时把数据放上总线，总线上的电平就乱了。

所以每个部件到总线之间，要有一个三态门。

```text
控制信号为 1：门打开，部件把数据放上总线
控制信号为 0：门关闭，部件与总线隔离
```

同一时刻，只能有一个发送方。

但可以有多个接收方。

```text
一个源，多个目的：可以
多个源，一个目的：不行
```

这就是"单总线一次只能传一个数据"的原因。

### 3.2 数据通路的两种走法

第一种：寄存器到寄存器。

```text
R1 → A
```

R1 把数据放上总线，A 从总线收。

第二种：寄存器到内存。

```text
R1 → MDR → M(MAR)
```

先 R1 到 MDR，再由 MDR 写到内存。

注意 MAR 要提前准备好地址。

### 3.3 ALU 的位置

ALU 不直接挂在总线上。

它的输入是 A、B 两个锁存器，输出是 Z。

```text
总线 → A
总线 → B
A、B → ALU → Z
Z → 总线
```

为什么要加 A、B、Z？

因为 ALU 是组合逻辑，输入一变，输出就跟着变。

如果直接把总线接到 ALU 输入，总线上的值一撤，输出就没了。

所以要先用 A、B 锁住输入，等 ALU 稳定，再把结果锁进 Z。

这也是为什么一次加法要三拍：

```text
T0: R1 → A
T1: R2 → B
T2: A + B → Z → R1
```

如果 ALU 有专用通路，能省掉中间的锁存，但单总线结构省不掉。

一个微操作，在时间上分三段：

```text
驱动：源寄存器打开三态门，把数据放上总线
传播：数据沿总线走到目的寄存器
锁存：目的寄存器在时钟边沿收下数据
```

三段走完，才能开始下一拍。

所以总线不能太长，挂的部件不能太多。

线越长，传播越慢，时钟周期就得越长。

这也是为什么真实 CPU 用短的总线、分层的互连，而不是一根线挂所有部件。

三态门还有个好处：可以把不用的部件"断开"。

```text
不用的寄存器，三态门关闭，对总线没有影响。
```

如果不用三态门，多个寄存器直接连在一起，输出会互相打架。

## 4. 取指周期的微操作

取指周期，做四件事。

```text
T0: PC → MAR
T1: M(MAR) → MDR
T2: MDR → IR
T3: PC + 1 → PC
```

逐拍看。

**T0：PC → MAR**

```text
PC 把下一条指令的地址放上总线
MAR 从总线收下
```

控制信号：

```text
PCout = 1
MARin = 1
```

**T1：M(MAR) → MDR**

```text
MAR 把地址送到地址总线
内存读出数据
数据送到数据总线
MDR 收下
```

控制信号：

```text
MEMR = 1（读）
MDRin = 1
```

**T2：MDR → IR**

```text
MDR 把指令放上内部总线
IR 收下
```

控制信号：

```text
MDRout = 1
IRin = 1
```

**T3：PC + 1 → PC**

```text
PC 加 1，指向下一条指令
```

控制信号：

```text
PCinc = 1
```

注意：PC + 1 用的是专用增量器，不占内部总线。

如果机器没有专用增量器，要用 ALU 加 1，那就得拆成两拍：

```text
T3: PC → A
T4: A + 1 → PC
```

取指就变成五拍。

408 题目如果没有特别说明，按四拍算。

有的机器把 PC + 1 放在 T1 并行：

```text
T0: PC → MAR
T1: M(MAR) → MDR, PC + 1 → PC
T2: MDR → IR
```

三拍就够。

前提是 PC 有独立的增量器，且 PC 的输出和 MAR 的输入不冲突。

有的机器更激进，把取指和译码重叠：

```text
T2: MDR → IR, 同时开始译码
```

译码不占用总线，可以和传输并行。

但 408 的微操作题，通常按"一个微操作一拍"来算。

除非题目给了时序图，否则不要自己合并。

### 4.1 取指的时序图

```text
时钟      T0      T1      T2      T3
        ┌──┐    ┌──┐    ┌──┐    ┌──┐
CLK     │  │    │  │    │  │    │  │
        ┘  └────┘  └────┘  └────┘  └──
PCout   ────────
MARin   ────────
MEMR            ────────
MDRin           ────────
MDRout                  ────────
IRin                    ────────
PCinc                           ────────
```

一条指令的取指，就这样占满四个时钟周期。

## 5. 执行阶段的微操作

执行阶段做什么，取决于操作码。

### 5.1 寄存器加法 ADD R1, R2

```text
T0: R1 → A
T1: R2 → B
T2: A + B → R1
```

三拍。

```text
T0：R1out=1，Ain=1
T1：R2out=1，Bin=1
T2：ALUop=ADD，Zout=1，R1in=1
```

为什么不能两拍？

因为 A 和 B 都要从同一条总线收数。

R1 上总线时，R2 不能同时上。

所以至少要两拍把两个操作数送进 ALU。

第三拍把结果写回。

为什么结果要经过 Z 再到 R1？

因为 ALU 的输出是组合逻辑，不稳定。

先把结果锁进 Z，下一拍再由 Z 驱动总线写回。

如果省掉 Z，直接把 ALU 输出接到总线，结果可能在传播中抖动。

单总线结构里，Z 是"结果缓冲"。

有的教材把 Z 画成 ALU 的一部分，有的单独画。

名字不同，作用一样。

### 5.2 寄存器间接加法 ADD R1, (R2)

```text
T0: R2 → MAR
T1: M(MAR) → MDR
T2: MDR → B
T3: R1 → A
T4: A + B → R1
```

五拍。

前三拍取操作数，后两拍做加法。

```text
T0：R2out=1，MARin=1
T1：MEMR=1，MDRin=1
T2：MDRout=1，Bin=1
T3：R1out=1，Ain=1
T4：ALUop=ADD，Zout=1，R1in=1
```

顺序可以换：

```text
T2: R1 → A
T3: MDR → B
T4: A + B → R1
```

只要两个操作数都进了 A、B，顺序不影响结果。

408 答题时，两种都算对，但要注意和题目给的图一致。

### 5.3 直接寻址取数 LOAD R1, X

```text
T0: X → MAR
T1: M(MAR) → MDR
T2: MDR → R1
```

三拍。

```text
T0：Ad(IR) → MAR
T1：MEMR=1，MDRin=1
T2：MDRout=1，R1in=1
```

`X` 是形式地址，直接从 IR 的地址字段送进 MAR。

### 5.4 直接寻址存数 STORE R1, X

```text
T0: X → MAR
T1: R1 → MDR
T2: MDR → M(MAR)
```

三拍。

```text
T0：Ad(IR) → MAR
T1：R1out=1，MDRin=1
T2：MEMW=1
```

注意写内存时，数据已经在 MDR 里，MAR 里是地址。

`MEMW` 一有效，内存就把 MDR 的内容写进 MAR 指向的单元。

### 5.5 无条件跳转 JMP X

```text
T0: X → PC
```

一拍。

```text
T0：Ad(IR) → PC
```

跳转指令不改数据，只改 PC。

### 5.6 条件跳转 JZ X

```text
T0: 测试 PSW 的 Z 标志
T1: 若 Z = 1，X → PC
```

两拍。

第一拍不一定占总线，可能只是控制器读 PSW。

第二拍才决定要不要改 PC。

如果条件不成立，PC 保持原值。

### 5.7 一张微操作速查表

```text
ADD R1, R2      R1→A, R2→B, ALU→R1                 3 拍
ADD R1, (R2)    R2→MAR, M→MDR, MDR→B, R1→A, ALU→R1  5 拍
LOAD R1, X      X→MAR, M→MDR, MDR→R1                3 拍
STORE R1, X     X→MAR, R1→MDR, MDR→M                3 拍
JMP X           X→PC                                1 拍
JZ X            测 PSW, 条件成立时 X→PC              2 拍
```

这七行，覆盖了 408 数据通路题的大部分执行阶段。

微操作的顺序，不是唯一的。

```text
ADD R1, (R2)
可以先 R2→MAR，也可以先 R1→A。
只要两个操作数最终都进了 A、B，结果一样。
```

但有些顺序不能换。

```text
STORE 必须先 X→MAR，再 R1→MDR。
因为写内存时，地址和数据要同时准备好。
```

答题时，按"数据依赖"排顺序：

```text
先算地址，再访存
先取操作数，再运算
先算结果，再写回
```

这三条，比背具体顺序有用。

## 6. 408 怎么考

这一块的题型：

```text
① 给数据通路图，填微操作序列
② 给指令，问需要几个时钟周期
③ 给微操作，问需要哪些控制信号
④ 给指令序列，算总周期数和 CPI
⑤ 比较单总线、多总线的取指拍数
```

### 6.1 例题一：算总周期数和 CPI

题目：

```text
某单总线 CPU，取指 4 拍。
执行阶段：
ADD R1, R2       3 拍
LOAD R1, X       3 拍
STORE R1, X      3 拍
JMP X            1 拍

程序共 100 条指令：
50 条 ADD，30 条 LOAD，15 条 STORE，5 条 JMP。
求总时钟周期数和 CPI。
```

算：

```text
取指：100 × 4 = 400
ADD：50 × 3 = 150
LOAD：30 × 3 = 90
STORE：15 × 3 = 45
JMP：5 × 1 = 5
```

总周期：

```text
400 + 150 + 90 + 45 + 5 = 690
```

CPI：

```text
690 / 100 = 6.9
```

答案：690 拍，CPI = 6.9。

注意 CPI 是"平均每条指令多少拍"，不是"执行阶段多少拍"。

取指也算在里面。

### 6.2 例题二：填微操作

题目：

```text
补全 ADD R1, (R2) 的微操作序列：
T0: ______
T1: ______
T2: ______
T3: ______
T4: ______
```

答：

```text
T0: R2 → MAR
T1: M(MAR) → MDR
T2: MDR → B
T3: R1 → A
T4: A + B → R1
```

验算：

```text
R2 里是操作数的地址
M[MAR] 取出操作数
MDR → B 把操作数送进 ALU
R1 → A 把被加数送进 ALU
A + B → R1 完成加法并写回
```

五拍，逻辑闭环。

### 6.3 例题三：间址的代价

题目：

```text
ADD R1, @X 采用间接寻址。
取指 4 拍，间址 3 拍，执行 5 拍。
求一条指令总共几拍？
```

算：

```text
4 + 3 + 5 = 12 拍
```

答案：12 拍。

对比直接寻址的 `ADD R1, X`：

```text
取指 4 拍
执行：X→MAR, M→MDR, MDR→B, R1→A, ALU→R1 = 5 拍
合计 9 拍
```

间接多 3 拍。

这 3 拍，就是"多一次访存"的代价。

### 6.4 例题四：数据通路填空

题目：

```text
某指令执行阶段要完成 R1 ← R1 + M[R2]。
数据通路有：PC、IR、MAR、MDR、R1、R2、A、B、Z、ALU、总线。
问 T0 到 T4 各由哪个部件驱动总线、哪个部件接收？
```

答：

```text
T0: R2 驱动，MAR 接收
T1: 内存驱动，MDR 接收（MEMR）
T2: MDR 驱动，B 接收
T3: R1 驱动，A 接收
T4: Z 驱动，R1 接收（ALUop=ADD）
```

关键：

```text
一个微操作里，只能有一个驱动方。
接收方可以有一个或多个。
```

如果同一拍写了两个驱动方，答案就错了。

### 6.5 例题五：写控制信号

题目：

```text
取指周期的四个微操作：
T0: PC → MAR
T1: M(MAR) → MDR
T2: MDR → IR
T3: PC + 1 → PC

写出每一拍的控制信号。
```

答：

```text
T0: PCout = 1, MARin = 1
T1: MEMR = 1, MDRin = 1
T2: MDRout = 1, IRin = 1
T3: PCinc = 1
```

如果 T3 用 ALU 加 1：

```text
T3: PCout = 1, Ain = 1
T4: ALUop = INC, Zout = 1, PCin = 1
```

取指变成五拍。

这类题的关键：

```text
先确定数据从哪来、到哪去
再确定谁 out、谁 in
最后确定内存是读还是写
```

### 6.6 答题模板

```text
第一步：画数据通路，标出每个部件的入/出
第二步：按"取操作数 → 运算 → 写回"拆微操作
第三步：每一拍只让一个部件驱动总线
第四步：写控制信号（谁 out、谁 in、ALU 做什么、内存读还是写）
第五步：数拍数，检查有没有可以合并的
```

## 7. 真实芯片里长什么样

教材里的单总线 CPU，是为了把微操作讲清楚。

真实 CPU 早就不是这个结构。

### 7.1 取指不是四拍

现代 x86 或 ARM64，一个周期可以取 16 字节甚至更多。

```text
L1 指令 Cache → 取指单元 → 指令队列 → 译码
```

取指单元一次拿一整块，不是一次拿一条。

因为指令 Cache 和 CPU 之间是专用通路，不跟数据访问抢总线。

### 7.2 多条总线、多个端口

真实 CPU 内部：

```text
寄存器文件有多个读端口、多个写端口
ALU 有专用输入通路
load/store 单元有单独的地址通路
PC 有专用加法器
```

所以一个周期里，可以同时：

```text
读两个寄存器
算一个地址
取一条指令
写一个结果
```

单总线做不到，因为它一次只能传一个数据。

真实 CPU 的寄存器文件，端口数是硬指标。

```text
2 读 1 写：能同时读两个操作数、写一个结果
4 读 2 写：能支撑更宽的发射
```

端口越多，面积越大，功耗越高。

所以 CPU 设计不是"端口越多越好"，而是在发射宽度和成本之间找平衡。

### 7.3 微操作变成了微指令

x86 的复杂指令，前端会拆成微操作（micro-ops）。

```text
一条 add [mem], eax
  ↓
load 微操作
add 微操作
store 微操作
```

后端把微操作放进乱序调度器，能并行就并行。

ARM64 的指令简单，通常一条指令对应一个或几个微操作。

### 7.4 流水线

真实 CPU 把取指、译码、执行、访存、写回拆成流水段。

```text
IF → ID → EX → MEM → WB
```

不同指令的不同阶段，可以同时进行。

单总线 CPU 一条指令要好几拍，而且下一拍才能开始下一条。

流水线把"排队"变成了"重叠"。

这就是第 19、20 篇的主题。

教材里的单总线结构，是这些真实结构的简化示意。

微操作的思想没变：

```text
每条指令，都能拆成一串"谁把什么送到哪里"。
```

这句话，是这一篇最值钱的一句。

不管数据通路是单总线、多总线还是专用通路，微操作的写法都一样：

```text
源 → 目的
```

差别只在"能不能同一拍做多个"。

单总线：一拍一个。

多总线：一拍多个。

专用通路：固定路径不占拍。

把这句话记住，408 的数据通路题就能拆。

## 8. 间址周期与中断周期

取指和执行之间，可能夹一个间址周期。

执行之后，可能夹一个中断周期。

### 8.1 间址周期

```text
T0: Ad(IR) → MAR
T1: M(MAR) → MDR
T2: MDR → Ad(IR)
```

三拍。

作用：

```text
把 IR 里的形式地址，换成内存里的有效地址。
```

执行阶段再用 `Ad(IR)` 当 EA。

注意：

```text
T2 写回的是 IR 的地址字段，不是 IR 的全部。
```

有些教材写成 `MDR → Y`，Y 是地址暂存器。

本质一样：把有效地址存起来，供执行阶段用。

### 8.2 中断周期

中断响应时，要做五件事。

```text
T0: SP − 1 → SP
T1: SP → MAR
T2: PC → MDR
T3: MDR → M(MAR)
T4: 向量地址 → PC
```

逐拍：

```text
T0：栈指针减 1，准备放返回地址
T1：把 SP 送到 MAR
T2：把当前 PC 送到 MDR
T3：把 PC 写进栈
T4：把中断向量地址送进 PC
```

这样，中断处理程序执行完，可以从栈里取回原 PC，继续执行。

如果要保存 PSW，还要多两次访存：

```text
PSW → MDR
MDR → M(MAR)
```

408 题目通常只要求写保存 PC 的五拍。

中断周期做的事，相当于执行了一条"隐指令"。

这条隐指令没有操作码，不是程序员写的。

它由硬件在中断响应时自动执行。

```text
保存断点（PC）
保存现场（PSW）
转入中断处理程序
```

所以有人叫它"中断隐指令"。

它和普通指令的区别：

```text
普通指令：从内存取，由 IR 译码
中断隐指令：由硬件直接产生，不经过取指
```

这也是为什么中断周期的微操作，和普通指令长得不一样。

### 8.3 中断周期为什么不一定有

```text
没有中断请求：没有中断周期
有中断请求但关中断：没有中断周期
有中断请求且开中断：当前指令执行完，进入中断周期
```

所以指令周期可能是：

```text
取指 + 执行
取指 + 间址 + 执行
取指 + 执行 + 中断
取指 + 间址 + 执行 + 中断
```

四种组合。

## 9. 多总线与专用通路

单总线的瓶颈，是"一次只能一个数据上总线"。

解决办法有两个：

```text
加总线：让多个数据同时走不同的总线
加专用通路：让某些固定的传输不经过总线
```

### 9.1 双总线

```text
总线 A：寄存器 → ALU 输入 A
总线 B：寄存器 → ALU 输入 B
ALU 输出：专用写出通路 → 寄存器
```

两个操作数可以同时上总线。

`ADD R1, R2` 从三拍变成：

```text
T0: R1 → A, R2 → B    （两条总线同时）
T1: A + B → R1
```

两拍。

### 9.2 三总线

再加一条输出总线。

```text
T0: R1 → A, R2 → B
T1: A + B → R1
```

还是两拍，但取指可以更快。

取指：

```text
T0: PC → MAR
T1: M(MAR) → MDR
T2: MDR → IR
```

PC+1 用专用增量器，和 T1 并行。

三拍，甚至两拍。

三种结构的取指拍数，可以排个序：

```text
单总线：T0 PC→MAR, T1 M→MDR, T2 MDR→IR, T3 PC+1    4 拍
双总线：T0 PC→MAR, T1 M→MDR, T2 MDR→IR, PC+1 并行   3 拍
三总线：T0 PC→MAR, T1 M→MDR 与 MDR→IR 部分重叠      2 到 3 拍
```

拍数不是唯一指标。

多一条总线，芯片面积、引脚、功耗都要涨。

所以真实 CPU 不会无限加总线。

它会在关键路径上加专线，其他地方继续共享。

### 9.3 专用通路

有些传输是固定的，可以拉专线。

```text
PC → MAR：取指专用
PC → 增量器 → PC：PC+1 专用
MAR → 地址总线：专用
MDR ↔ 数据总线：专用
```

专线不占内部总线，可以和其他传输并行。

代价是线更多、引脚更多、芯片更贵。

### 9.4 为什么快

```text
单总线：一个数据排队，四个微操作四拍
多总线：多个数据并行，同样的微操作两拍
专用通路：固定传输不排队，取指可以更快
```

快的本质，不是"线更多"，是"并行度更高"。

```text
单总线：串行
多总线：部分并行
专用通路：把固定路径从共享路径里拿出来
```

这就是数据通路设计的核心：

```text
找出可以并行的传输，给它们独立的路径。
```

但并行不是免费的。

```text
多一条总线，多一组驱动器、接收器、仲裁逻辑
多一个端口，寄存器文件面积增大
多一条专线，布线资源和功耗增加
```

所以真实 CPU 的做法是"关键路径专用，非关键路径共享"。

```text
PC→MAR、PC+1：专用，因为每拍都要用
ALU 输入：专用，因为运算最频繁
普通寄存器传输：共享总线，够用就行
```

这就是为什么真实 CPU 的内部互连，看起来像一张网，而不是一根线。

## 10. 控制信号从哪来

微操作序列写好了，谁来发信号？

控制器。

### 10.1 控制信号的来源

控制器从 IR 拿到操作码，从 PSW 拿到标志，从时序部件拿到节拍。

```text
IR 的操作码 → 译码 → 知道当前是什么指令
PSW 的标志 → 知道条件是否成立
节拍发生器 → 知道现在是 T0、T1 还是 T2
```

三者一组合，就能产生每一拍的控制信号。

```text
控制信号 = f(操作码, 标志, 节拍)
```

控制信号有两种有效电平。

```text
高电平有效：1 表示打开
低电平有效：0 表示打开
```

教材里通常画成高电平有效。

真实芯片里，低电平有效很常见，因为抗干扰更好。

做题时看题目给的图，图上标了小圆圈就是低电平有效。

### 10.2 硬布线与微程序

两种实现：

```text
硬布线：用门电路直接产生控制信号
微程序：把控制信号存在控制存储器里，一条微指令对应一拍
```

硬布线：

```text
快，但设计复杂，改指令要改电路。
```

微程序：

```text
慢一点，但灵活，改指令只要改微程序。
```

### 10.3 取指的控制信号

以取指为例：

```text
T0: PCout, MARin
T1: MEMR, MDRin
T2: MDRout, IRin
T3: PCinc
```

这些信号，就是控制器在四个节拍里依次发出的。

408 的数据通路填空题，经常让你补这些信号。

```text
谁 out：谁把数据放上总线
谁 in：谁从总线接收
MEMR/MEMW：内存读还是写
ALUop：ALU 做什么运算
```

### 10.4 RISC 与 CISC 的控制

```text
RISC：指令少、格式固定，硬布线容易做
CISC：指令多、格式复杂，传统上用微程序
```

现代 CPU 常常混合：

```text
前端用微码处理复杂指令
后端用硬布线处理简单微操作
```

### 10.5 控制信号与时钟的关系

控制信号不是一直有效的。

它只在某个时钟周期里有效。

```text
T0 有效：PCout、MARin
T1 有效：MEMR、MDRin
T2 有效：MDRout、IRin
T3 有效：PCinc
```

到了下一拍，上一拍的信号必须撤销。

否则会出现两个部件同时驱动总线。

时序上，控制信号要在时钟边沿之前稳定。

```text
建立时间：信号先到，等时钟边沿
保持时间：时钟边沿之后，信号再保持一会儿
```

这两个时间不够，寄存器可能锁到错误的值。

408 不考建立/保持时间。

但它会问"某一拍哪些信号有效"。

按微操作序列逐拍写，就不会错。

第 17 篇会专门讲控制器。

## 11. 容易混淆的点

**第一，时钟周期 ≠ 机器周期 ≠ 指令周期。**

时钟周期最小，机器周期包含若干时钟周期，指令周期包含若干机器周期。

**第二，单总线 ≠ 单周期。**

单总线是说只有一条内部总线。

单周期是说一条指令一个周期完成。

两者不是一回事。

**第三，MAR 和 MDR 不是 PC 和 IR。**

MAR/MDR 面向内存，PC/IR 面向指令。

**第四，微操作 ≠ 微指令。**

微操作是一个动作，比如 `PC → MAR`。

微指令是一组微命令的集合，可能包含多个微操作。

**第五，取指四拍，不是说指令周期四拍。**

取指只是指令周期的一段。

执行、间址、中断还要加拍。

**第六，中断周期不一定有。**

要看有没有中断请求、是否开中断。

**第七，PC+1 的时机不固定。**

有专用增量器，可以在 T1 并行。

没有专用增量器，要单独占一拍，甚至两拍。

**第八，数据通路 ≠ 控制器。**

数据通路是"路"，控制器是"红绿灯"。

路再好，没有信号也走不了。

**第九，总线宽度 ≠ 总线数量。**

加宽总线，一次搬更多位。

加总线，一次搬更多个数据。

两者解决的不是同一个问题。

这九个点，前四个是概念，后五个是算拍数时的细节。

概念题错在"把总线数量和周期数混为一谈"。

细节题错在"PC+1 到底算不算一拍"。

做微操作题，先问自己三个问题：

```text
这一拍谁驱动总线？
这一拍谁接收？
这一拍内存读还是写？
```

三个问题都答上来，控制信号自然就出来了。

## 12. 小结

CPU 的部件：

```text
PC、IR、MAR、MDR、通用寄存器、PSW、ALU、控制器
```

指令周期的四个阶段：

```text
取指 → 间址? → 执行 → 中断?
```

单总线取指四拍：

```text
T0: PC → MAR
T1: M(MAR) → MDR
T2: MDR → IR
T3: PC + 1 → PC
```

执行阶段的三条主线：

```text
ADD R1, R2      R1→A, R2→B, ALU→R1        3 拍
LOAD R1, X      X→MAR, M→MDR, MDR→R1      3 拍
STORE R1, X     X→MAR, R1→MDR, MDR→M        3 拍
```

间接寻址多三拍：

```text
Ad(IR)→MAR, M→MDR, MDR→Ad(IR)
```

多总线为什么快：

```text
不是线多，是并行度高。
同一拍可以有多个数据同时走不同的路。
```

控制信号：

```text
控制信号 = f(操作码, 标志, 节拍)
硬布线快，微程序灵活。
```

反直觉点再重复一次：

```text
单总线慢，不是因为线少。
是因为一次只能有一个数据上总线。
取指四拍，是数据在排队。
```

```text
微地址怎么形成？
```
