`MOV R1, 0x2000`

这个 `0x2000`，是操作数，还是操作数的地址？

两种读法都成立。

如果这是直接寻址，`0x2000` 是地址，操作数在内存的 `0x2000` 单元里。

如果这是立即寻址，`0x2000` 就是操作数本身。

同一串二进制，含义完全不同。

决定含义的，不是位数，是**寻址方式**。

**反直觉的点在这里：**

```text
间接寻址要访存两次，比直接寻址慢一倍。
但它让"指针"成为可能。
一次寻址拿到的不是操作数，而是操作数的地址。
```

C 语言里的 `int *p`、链表、树、函数指针，底层都靠这一层"地址的地址"。

灵活性是拿速度换的。

这一篇把九种寻址方式拆开，每一种都算三个量：

```text
有效地址 EA 怎么来
要访存几次
能寻多大的范围
```

## 1. 指令里的"地址"是什么

指令里的地址字段，叫**形式地址**（formal address），记作 A。

它不一定等于真正的内存地址。

真正的地址叫**有效地址**（effective address），记作 EA。

操作数可能在三个地方：

```text
指令里：立即数
寄存器里：寄存器操作数
内存里：需要算出 EA，再访存
```

寻址方式，就是"从形式地址 A 算出操作数位置"的规则。

```text
A ──寻址方式──> EA 或 寄存器编号 或 操作数本身
```

三种结果：

```text
立即寻址：A 就是操作数，没有 EA
寄存器寻址：A 是寄存器编号，没有内存 EA
其他方式：A 参与算出 EA，再去内存取操作数
```

所以"寻址"这个词，有时候找的是操作数，有时候找的是操作数的地址。

408 题干里经常混着说。

看到"操作数地址"，先问：它要的是 EA，还是 EA 里的内容？

## 2. 九种寻址方式总览

九种方式，先用一张表压住。

表中的"访存次数"只算**取操作数**，不含取指。

取指那一次，所有指令都要花，单独另算。

| 方式 | 有效地址 EA | 访存次数 | 寻址范围 | 速度 |
|---|---|---|---|---|
| 立即寻址 | 无（A 即操作数） | 0 | 由 A 的位数决定 | 最快 |
| 直接寻址 | EA = A | 1 | 2^m（m 为地址字段位数） | 快 |
| 间接寻址 | EA = M[A] | 2 | 2^n（n 为存储字长） | 慢 |
| 寄存器寻址 | 无（操作数在 Ri） | 0 | 由寄存器位数决定 | 最快 |
| 寄存器间接 | EA = (Ri) | 1 | 2^n（n 为寄存器位数） | 较快 |
| 变址寻址 | EA = (IX) + A | 1 | 由 IX 位数与 A 共同决定 | 较慢 |
| 基址寻址 | EA = (BR) + A | 1 | 由 BR 位数与 A 共同决定 | 较慢 |
| 相对寻址 | EA = (PC) + A | 1（转移指令 0） | PC ± 2^(m−1) | 较慢 |
| 堆栈寻址 | EA = (SP) | 1 | 由 SP 位数决定 | 较慢 |

九种方式，可以按"操作数在哪"分成三组：

```text
操作数在指令里：立即
操作数在寄存器里：寄存器
操作数在内存里：直接、间接、寄存器间接、变址、基址、相对、堆栈
```

内存组里，差别只在"EA 怎么算"。

```text
直接：EA 就是 A
间接：EA 是 M[A]
寄存器间接：EA 是 (Ri)
变址：EA 是 (IX) + A
基址：EA 是 (BR) + A
相对：EA 是 (PC) + A
堆栈：EA 是 (SP)
```

记住这张"EA 来源表"，比背九段定义有用。

这张表有三处容易读错。

第一处，访存次数不含取指。

一条指令执行完，取指至少访存一次。

表里写"0 次"的，是说取操作数不用再访存，不是说整条指令不访存。

第二处，速度排序不是绝对的。

寄存器寻址最快，是因为它不访存。

但如果寄存器文件端口不够，或者要等前一条指令写回，寄存器也可能变慢。

408 按"访存次数越少越快"来排就够。

第三处，寻址范围的单位不同。

立即寻址的范围是"数值范围"。

直接寻址的范围是"内存单元数"。

寄存器寻址的范围是"寄存器个数"。

三种"范围"不是一回事，题目问哪个就答哪个。

## 3. 立即、直接、间接

### 3.1 立即寻址

操作数直接写在指令里。

```text
MOV R1, #0x1234
```

`#` 是立即数的记号。

`0x1234` 就是操作数，不需要访存。

优点：

```text
快。
取指的时候操作数就到手了。
```

缺点：

```text
操作数的大小受地址字段位数限制。
8 位字段只能表示 0 到 255。
```

立即数通常是有符号的，也可能是无符号的，看指令怎么定义。

408 里问"立即寻址的寻址范围"，答的是"立即数的表示范围"，不是内存地址范围。

这是个小坑。

### 3.2 直接寻址

地址字段直接给出内存地址。

```text
MOV R1, 0x2000
```

EA = 0x2000。

操作数 = M[0x2000]。

访存一次。

优点：

```text
简单。
算出 EA 不需要任何寄存器参与。
```

缺点：

```text
寻址范围被地址字段卡死。
地址字段 12 位，只能访问 4K 个单元。
```

而且地址写死在指令里，程序一搬家，指令就得改。

这就是"位置相关"。

### 3.3 间接寻址

地址字段给出的，是"地址的地址"。

```text
MOV R1, @0x2000
```

`@` 表示间接。

EA = M[0x2000]。

操作数 = M[EA] = M[M[0x2000]]。

访存两次：

```text
第一次：读 M[0x2000]，拿到 EA
第二次：读 M[EA]，拿到操作数
```

优点：

```text
寻址范围不再受地址字段限制，而是受存储字长限制。
地址字段 12 位，但 M[0x2000] 里可以存 16 位地址，寻址范围变成 64K。
```

更大的优点是指针：

```text
指令里写的是指针变量 p 的地址。
M[p 的地址] 里存的是 p 的值，也就是目标地址。
再访存一次，才拿到目标。
```

链表节点里存 `next` 指针，就是这种结构。

缺点：

```text
慢。
两次访存。
```

如果间接再套间接，就是多级间接，访存次数继续加。

实际机器很少用多级间接，太慢。

**这里就是本篇的反直觉点。**

直接寻址一次访存就能拿到操作数，为什么还要留一个更慢的间接寻址？

因为直接寻址把地址写死在指令里。

指令一旦编译好，地址就不能变。

可程序运行时，目标地址经常要变：

```text
链表的下一个节点在哪，编译时不知道。
函数指针指向哪个函数，运行时才知道。
```

间接寻址把"目标地址"放进内存单元。

指令里写的是这个内存单元的地址，固定不变。

内存单元里的内容可以随时改。

于是同一条指令，可以访问不同的目标。

```text
直接寻址：指令 → 操作数
间接寻址：指令 → 指针 → 操作数
```

多出来的一次访存，买的是"地址可变"。

这就是拿速度换灵活。

### 3.4 多级间接

间接寻址还能再套一层。

```text
MOV R1, @@0x2000
```

```text
EA1 = M[0x2000]
EA2 = M[EA1]
操作数 = M[EA2]
```

访存三次。

每多一级间接，就多一次访存。

多级间接在理论上很灵活，实际机器很少用。

原因很直接：

```text
内存访问本来就慢，多一级就多等一个访存周期。
编译器宁愿把多级指针拆成几条指令，也不愿让一条指令在硬件里连续访存三次。
```

所以 408 里遇到多级间接，按"每级一次访存"数就行。

真正常用的，是"一级间接"和"寄存器间接"。

## 4. 寄存器与寄存器间接

### 4.1 寄存器寻址

操作数在寄存器里。

```text
ADD R1, R2
```

`R2` 是寄存器编号，不是内存地址。

EA 不存在，访存 0 次。

优点：

```text
最快。
寄存器在 CPU 内部，不需要走内存。
指令也短，因为寄存器编号只需要几位。
```

缺点：

```text
寄存器数量有限。
寄存器编号 3 位，只能编 8 个寄存器。
```

寄存器寻址的"寻址范围"，问的是寄存器的数量，不是内存大小。

### 4.2 寄存器间接寻址

寄存器里存的是操作数的地址。

```text
MOV R1, (R2)
```

EA = (R2)，也就是 R2 的内容。

操作数 = M[R2]。

访存一次。

它和间接寻址的区别：

```text
间接寻址：指针在内存里，先访存取指针，再访存取操作数 → 2 次
寄存器间接：指针在寄存器里，直接拿寄存器内容当 EA → 1 次
```

所以寄存器间接是"间接寻址的快速版"。

C 语言里的指针变量，编译器通常放在寄存器里。

```c
int x = *p;
```

编译出来大概是：

```text
LOAD R1, (R2)    ; R2 里是 p 的值
```

链表遍历、数组指针、函数指针，底层都可能是寄存器间接。

它的寻址范围由寄存器位数决定。

32 位寄存器 → 4G 个单元。

64 位寄存器 → 更大。

### 4.3 寄存器编号的位数账

寄存器寻址的指令为什么短？

因为寄存器编号比内存地址短得多。

```text
8 个寄存器 → 3 位编号
16 个寄存器 → 4 位编号
32 个寄存器 → 5 位编号
```

内存地址动辄 16 位、32 位。

所以同一条 `ADD`，操作数在寄存器里，地址字段只要 5 位；操作数在内存里，地址字段要 32 位。

一条 32 位指令，装不下两个 32 位内存地址。

这就是 RISC 的设计逻辑：

```text
让大多数运算都在寄存器之间进行。
只有 load/store 才访问内存。
```

寄存器多了，编号变长，但换来的是一次访存都不用。

这笔账，RISC 算得很清楚。

## 5. 变址、基址、相对、堆栈

这四种都在算 `寄存器 + A`，但寄存器的角色不同。

### 5.1 变址寻址

```text
EA = (IX) + A
```

`IX` 是变址寄存器（index register）。

`A` 是形式地址，通常放数组的首地址。

`IX` 放下标。

```text
a[i] 的地址 = a 的首地址 + i × 元素大小
```

如果元素是 4 字节：

```text
EA = (IX) + A，其中 IX = i × 4
```

优点：

```text
适合数组和循环。
A 不变，IX 每次加一个元素大小。
一条指令可以反复用。
```

访存一次。

变址寄存器的内容由用户程序改变。

这就是"变址"两个字的来源：**下标在变**。

### 5.2 基址寻址

```text
EA = (BR) + A
```

`BR` 是基址寄存器（base register）。

`BR` 放一个基地址，通常是程序或数据段的起点。

`A` 是偏移量。

```text
程序搬家后，只要改 BR，所有指令里的 A 都不用改。
```

优点：

```text
支持重定位。
支持多道程序：每个程序有自己的基址。
```

访存一次。

基址寄存器的内容通常由操作系统设置，程序运行期间不变。

这就是"基址"两个字的来源：**基准地址不动**。

### 5.3 相对寻址

```text
EA = (PC) + A
```

`PC` 是程序计数器。

`A` 是带符号的偏移量。

```text
A > 0：向前跳
A < 0：向后跳
```

用在转移指令里：

```text
JMP +0x10
```

优点：

```text
位置无关。
整段代码搬到别的地方，相对距离不变，跳转仍然正确。
```

访存一次（如果用它取操作数）。

如果用于转移指令，只算目标地址，不取操作数。

相对寻址的寻址范围是 `PC ± 2^(m−1)`，m 是偏移量位数。

这里有一个必须说清的约定：

```text
相对寻址的 EA，到底是"当前指令地址 + A"，还是"下一条指令地址 + A"？
```

两种约定都存在。

取指完成后，PC 通常已经指向下一条指令。

所以很多机器用"下一条指令地址 + A"。

408 题目一般会明确说"PC 取指后指向下一条指令"。

如果没有说，就按题目给的 PC 值算，不要自己猜。

### 5.4 堆栈寻址

```text
EA = (SP)
```

`SP` 是堆栈指针（stack pointer）。

栈顶就是 SP 指向的单元。

两种操作：

```text
PUSH X：先 (SP) − 1 → SP，再 X → M[SP]
POP  X：先 M[SP] → X，再 (SP) + 1 → SP
```

这是"栈向低地址增长"的约定。

有的机器相反，栈向高地址增长。

408 通常默认向低地址增长，SP 指向栈顶。

堆栈寻址的特点：

```text
操作数地址隐含在 SP 里，指令不需要地址字段。
所以堆栈指令很短。
```

访存一次。

函数调用、局部变量、表达式求值，都靠它。

栈向低地址增长时，PUSH 先减 SP 再写，POP 先读再增 SP。

栈向高地址增长时，顺序相反。

408 做题前先看题目给的图，图上 SP 箭头指向哪，就按哪种约定。

两种约定都合法，混着用就会算错地址。

### 5.5 四种方式怎么选

四种方式都在算 `寄存器 + A`，但用途分得很清。

```text
变址：数组遍历。
IX 是下标，A 是首地址。
基址：程序重定位。
BR 是段基址，A 是段内偏移。
相对：转移指令。
PC 是当前指令附近，A 是相对距离。
堆栈：函数调用。
SP 是栈顶，地址隐含。
```

一个记忆顺序：

```text
数组找变址，
搬家找基址，
跳转找相对，
调用找堆栈。
```

408 选择题里，场景和方式是配对的。

看到"数组"、"循环"、"下标"，选变址。

看到"重定位"、"多道程序"、"段"，选基址。

看到"转移"、"跳转"、"位置无关"，选相对。

看到"函数调用"、"局部变量"、"后进先出"，选堆栈。

看到"指针"、"链表"，选间接或寄存器间接。

看到"常数"，选立即。

## 6. 408 怎么考

寻址方式这一块，408 的题型：

```text
① 给指令和寄存器/内存初值，算 EA 和操作数
② 问某种方式访存几次
③ 给场景，选最合适的寻址方式
④ 算寻址范围
⑤ 判断基址与变址的区别
```

### 6.1 例题一：算 EA 和访存次数

题目：

```text
指令 ADD R1, @0x2000，采用间接寻址。
M[0x2000] = 0x3000，M[0x3000] = 0x1234。
求 EA、操作数、取操作数的访存次数。
若把取指也算进去，总访存几次？
```

解：

```text
EA = M[0x2000] = 0x3000
操作数 = M[0x3000] = 0x1234
取操作数访存 2 次
加上取指 1 次，总共 3 次
```

答案：EA = 0x3000，操作数 = 0x1234，2 次；含取指 3 次。

### 6.2 例题二：选寻址方式

题目：

```text
下列场景，各选一种最合适的寻址方式：
(1) 访问数组 a[i]
(2) 循环体末尾跳回循环开头
(3) 遍历链表 node = node->next
(4) 指令里使用常数 3.14
(5) 多道程序重定位
```

答：

```text
(1) 变址寻址：首地址 + 下标
(2) 相对寻址：向后跳，位置无关
(3) 寄存器间接寻址：指针在寄存器里
(4) 立即寻址：常数直接编码
(5) 基址寻址：改基址寄存器即可搬家
```

### 6.3 例题三：寻址范围

题目：

```text
某机地址码 16 位，按字节编址，直接寻址的寻址范围是多少？
若改用寄存器间接寻址，寄存器 32 位，寻址范围是多少？
```

解：

```text
直接寻址：2^16 = 65536 个字节 = 64 KB
寄存器间接：2^32 = 4G 个字节 = 4 GB
```

答案：64 KB；4 GB。

### 6.4 例题四：相对寻址的 EA

题目：

```text
某指令位于地址 0x1000，长度 4 字节，
采用相对寻址，偏移量 A = +0x0010。
取指后 PC 指向下一条指令。
求转移目标地址。
```

解：

```text
取指后 PC = 0x1000 + 4 = 0x1004
EA = 0x1004 + 0x0010 = 0x1014
```

答案：0x1014。

如果题目约定 PC 仍指向当前指令：

```text
EA = 0x1000 + 0x0010 = 0x1010
```

两者差 4，正好是一条指令的长度。

所以做这类题，先看题目怎么定义 PC。

### 6.5 答题模板

```text
第一步：看清是哪种寻址方式
第二步：写出 EA 公式
第三步：把寄存器/内存值代进去
第四步：数访存次数（先只算操作数，再看要不要加取指）
第五步：检查范围单位（字节还是字）
```

## 7. 真实芯片里长什么样

教材里的九种方式，在真实芯片里被压缩成几种"地址计算模式"。

下面这些结构都是简化示意。

真实的译码器和地址生成单元，比这复杂得多。

### 7.1 x86：基址 + 变址 × 比例 + 位移

x86 的内存操作数，可以写成：

```text
段基址 + 基址寄存器 + 变址寄存器 × 比例 + 位移
```

比例只能是 1、2、4、8。

`SIB` 字节就是干这个的：

```text
scale（2 位）：1、2、4、8
index（3 位）：变址寄存器
base（3 位）：基址寄存器
```

一条指令：

```text
mov (%rax,%rbx,4), %ecx
```

意思是：

```text
EA = rax + rbx × 4
```

这正好对应"基址 + 变址"。

`objdump -d` 里看：

```text
  4004d0:  8b 05 2e 00 00 00     mov    0x2e(%rip),%eax
  4004d6:  8b 0c 98              mov    (%rax,%rbx,4),%ecx
```

第一条是 RIP 相对寻址：

```text
EA = RIP + 0x2e
```

第二条是基址 + 变址 × 4：

```text
EA = rax + rbx × 4
```

x86-64 默认用 RIP 相对寻址，就是为了位置无关代码（PIC）。

### 7.2 ARM64：基址 + 偏移，或基址 + 变址

ARM64 的加载/存储指令：

```text
ldr w0, [x1, #4]          ; EA = x1 + 4
ldr w0, [x1, x2, lsl #2]  ; EA = x1 + x2 × 4
```

第一种是基址 + 立即数偏移。

第二种是基址 + 变址，还带移位。

PC 相对：

```text
adr x0, label             ; EA = PC + 偏移
```

### 7.3 真实芯片的取舍

```text
x86：寻址方式多，指令长，但一条指令能干很多事
ARM64：寻址方式少，指令定长，靠多条指令组合
RISC-V：更少，只有基址 + 偏移
```

教材里的九种，是把这些模式拆开讲。

真实芯片不会九种都支持。

但"立即、寄存器、基址 + 偏移、PC 相对"这四类，几乎所有芯片都有。

### 7.4 为什么 RISC 只留"基址 + 偏移"

RISC 的加载/存储指令，通常只有一种内存地址形式：

```text
EA = 基址寄存器 + 立即数偏移
```

数组下标怎么办？

不用专门的变址寻址，而是用两条指令算地址：

```text
slli t0, i, 2      ; t0 = i × 4
add  t0, a0, t0    ; t0 = a 的首地址 + i×4
lw   t1, 0(t0)     ; 从 t0 取数
```

这样指令格式简单，译码简单，流水线好做。

代价是指令条数多了。

x86 选择另一条路：

```text
一条 mov 就能完成"基址 + 变址×4 + 位移"
```

指令条数少，但指令长，译码复杂。

两条路都能走通。

408 不要求你站队，只要求你知道：

```text
寻址方式多 → 单条指令能干更多事 → 指令更长、译码更复杂
寻址方式少 → 单条指令更简单 → 指令更短、条数更多
```

## 8. 一段指令序列：算 EA 和操作数

给一组初值：

```text
R1 = 0x0100
R2 = 0x2000
IX = 0x0004
BR = 0x3000
SP = 0x8000
取指后 PC = 0x1010

M[0x2000] = 0x00AA
M[0x00AA] = 0x1357
M[0x0008] = 0xBEEF
M[0x3100] = 0x2468
M[0x8000] = 0x0F0F
```

八条指令，逐条算。

```text
① MOV R1, #0x1234
② MOV R1, 0x2000
③ MOV R1, @0x2000
④ MOV R1, (R2)
⑤ MOV R1, 0x0004(IX)
⑥ MOV R1, 0x0100(BR)
⑦ JMP +0x0010
⑧ POP R1
```

逐条：

```text
① 立即寻址：操作数 = 0x1234，无 EA，访存 0 次
② 直接寻址：EA = 0x2000，操作数 = 0x00AA，访存 1 次
③ 间接寻址：EA = M[0x2000] = 0x00AA，操作数 = M[0x00AA] = 0x1357，访存 2 次
④ 寄存器间接：EA = R2 = 0x2000，操作数 = 0x00AA，访存 1 次
⑤ 变址：EA = IX + 4 = 0x0008，操作数 = 0xBEEF，访存 1 次
⑥ 基址：EA = BR + 0x0100 = 0x3100，操作数 = 0x2468，访存 1 次
⑦ 相对：EA = PC + 0x0010 = 0x1020，这是转移目标，不取操作数
⑧ 堆栈：EA = SP = 0x8000，操作数 = 0x0F0F，访存 1 次；之后 SP = 0x8002
```

汇总：

| 指令 | 方式 | EA | 操作数 | 取操作数访存 |
|---|---|---|---|---|
| ① | 立即 | 无 | 0x1234 | 0 |
| ② | 直接 | 0x2000 | 0x00AA | 1 |
| ③ | 间接 | 0x00AA | 0x1357 | 2 |
| ④ | 寄存器间接 | 0x2000 | 0x00AA | 1 |
| ⑤ | 变址 | 0x0008 | 0xBEEF | 1 |
| ⑥ | 基址 | 0x3100 | 0x2468 | 1 |
| ⑦ | 相对 | 0x1020 | 无（转移目标） | 0 |
| ⑧ | 堆栈 | 0x8000 | 0x0F0F | 1 |

这里最容易错的是 ③。

`@0x2000` 不是"地址 0x2000 里的操作数"这么简单，它要读两次。

第一次读 `0x2000`，得到 `0x00AA`。

第二次读 `0x00AA`，才得到 `0x1357`。

如果题目问"操作数地址"，答案是 `0x00AA`，不是 `0x2000`。

如果题目问"指令里的形式地址"，答案是 `0x2000`。

三个地址要分清：

```text
形式地址 A：指令里写的，0x2000
有效地址 EA：算出来的，0x00AA
操作数：内存里的，0x1357
```

## 9. 基址与变址的区别

这是 408 最爱考的一组对比。

两者公式几乎一样：

```text
变址：EA = (IX) + A
基址：EA = (BR) + A
```

区别不在公式，在**谁在变、谁设置、为什么变**。

```text
变址寄存器 IX：用户程序改变，A 是数组首地址，IX 是下标
基址寄存器 BR：操作系统设置，A 是偏移量，BR 是段起点
```

用一句话记：

```text
变址面向数组：A 不动，IX 动。
基址面向段：BR 不动，A 动。
```

再展开一点：

```text
变址：A 是"首地址"，IX 是"第几个元素"
基址：BR 是"段基址"，A 是"段内偏移"
```

用途也不同：

```text
变址：数组遍历、向量运算、循环
基址：程序重定位、多道程序、段式存储
```

判断谁在变，有个简单办法：

```text
看循环一次之后，哪个寄存器变了。
变的是变址，不变的是基址。
```

不过这个办法只看现象。

更准确的是看语义：

```text
变址寄存器提供"下标"，形式地址提供"基"。
基址寄存器提供"基"，形式地址提供"偏移"。
```

x86 的 `(%rax,%rbx,4)` 把两者放在一条指令里：

```text
rax 是基址，rbx 是变址，4 是比例
```

所以 x86 一条指令就能算 `a[i]` 的地址。

ARM64 的 `[x1, x2, lsl #2]` 也一样。

## 10. 寻址方式对指令长度的影响

寻址方式越多，指令越长。

原因很简单：

```text
每种寻址方式需要一个编码。
8 种方式要 3 位，16 种方式要 4 位。
```

这几位叫"寻址特征位"，要占指令字长。

一个 16 位指令的例子：

```text
操作码 4 位，一地址，地址码 8 位。
如果只有 1 种寻址方式：4 + 8 = 12 位，还剩 4 位。
如果有 8 种寻址方式：4 + 3 + 8 = 15 位，只剩 1 位。
```

多一种方式，地址码就得让位。

极端情况下：

```text
指令字长 16 位，操作码 4 位，二地址。
每个地址 8 种方式 → 每个地址 3 位寻址特征。
4 + 2 × (a + 3) = 16
2a + 6 = 12
a = 3
```

每个地址码只剩 3 位，寻址范围只有 8 个单元。

这就是"寻址方式丰富"的代价。

反过来，寄存器寻址为什么指令短？

```text
寄存器编号只需要几位。
8 个寄存器 → 3 位。
内存地址可能要 16 位、32 位。
```

所以同一台机器上：

```text
寄存器指令短，内存指令长。
立即数指令也长，因为要放下整个操作数。
```

408 有时问"为什么 RISC 的指令定长，还能支持多种寻址"。

答案是：

```text
RISC 把复杂寻址拆成多条简单指令。
一条指令只做"基址 + 偏移"。
数组下标用移位和加法单独算。
```

这就是"用指令条数换指令长度"。

### 10.1 寻址方式背后的硬件

每种寻址方式，都要有硬件支持。

```text
立即寻址：不需要地址生成，直接取指令里的字段
寄存器寻址：不需要地址生成，直接读寄存器堆
直接寻址：地址字段直接送 MAR，不需要加法
间接寻址：要访存，地址来自 MDR
变址/基址：要一个加法器，算 IX+A 或 BR+A
相对寻址：要一个加法器，算 PC+A
堆栈：要一个能自动加减的 SP
```

负责算地址的部件，叫地址生成单元（AGU，address generation unit）。

```text
AGU = 加法器 + 移位器 + 一些选择器
```

x86 的 AGU 能算：

```text
base + index × scale + displacement
```

一条指令里完成，所以寻址方式多，AGU 也复杂。

RISC 的 AGU 通常只算：

```text
base + offset
```

简单，快，面积小。

408 不会让你画 AGU。

但它会问"哪种寻址方式需要几次访存、需不需要加法"。

知道背后的硬件，这类题就不用死记。

### 10.2 装不满的账

再算一个具体的账。

```text
某机指令字长 16 位，操作码 5 位，二地址指令。
有 4 种寻址方式，每个地址都要 2 位寻址特征。
每个地址码还剩几位？
```

算：

```text
5 + 2 × (a + 2) = 16
5 + 2a + 4 = 16
2a = 7
a = 3.5
```

不能刚好装满。

这说明：

```text
5 位操作码 + 2 个地址 + 4 种寻址方式，
按刚好用满 16 位算，没有整数解。
```

要么把操作码减到 4 位：

```text
4 + 2 × (a + 2) = 16
2a = 8
a = 4
```

每个地址 4 位，寻址范围 16 个单元。

要么把寻址方式减到 2 种：

```text
5 + 2 × (a + 1) = 16
2a = 9
a = 4.5
```

还是不行。

按"刚好用满 16 位"算，除不尽。

实际设计可以取 `a = 4`：

```text
5 + 2 × (4 + 1) = 15
```

五个地址位只用四个，剩下 1 位空着。

指令格式允许留空位，只是浪费。

所以题目里说的"装不下"，准确意思是"不能刚好装满"。

408 题目一般会要求"尽可能利用"，那就得调整某一项，直到刚好 16 位。

这就是格式设计里的凑数。

可见 16 位指令里，二地址 + 寻址特征 + 操作码，三者很难同时宽松。

这就是为什么早期的 16 位机器，二地址指令往往只有很短的地址码。

## 11. 一道综合题：把九种方式串起来

题目：

```text
某机指令字长 16 位，地址码 8 位，有 4 种寻址方式。
(1) 操作码最多几位？最多几条指令？
(2) 直接寻址的寻址范围是多少个单元？
(3) 若采用寄存器间接寻址，寄存器 16 位，寻址范围是多少？
(4) 指令 ADD R1, @0x20 从取指到取到操作数，共访存几次？
```

逐问算。

第一问：

```text
4 种寻址方式 → 2 位寻址特征
操作码 = 16 − 8 − 2 = 6 位
指令条数上限 = 2^6 = 64 条
```

第二问：

```text
直接寻址 EA = A，A 是 8 位
2^8 = 256 个编址单位
```

第三问：

```text
寄存器间接 EA = (Ri)，Ri 是 16 位
2^16 = 65536 个编址单位 = 64K
```

第四问：

```text
取指 1 次
间接寻址取操作数 2 次
总共 3 次
```

答案：

```text
(1) 6 位，64 条
(2) 256 个单元
(3) 64K 个单元
(4) 3 次
```

这道题把"格式、范围、访存"三件事串在一条指令上。

如果把第 (4) 问改成 `ADD R1, (R2)`：

```text
取指 1 次
寄存器间接取操作数 1 次
总共 2 次
```

改成 `ADD R1, @0x20`：

```text
取指 1 次
间接取操作数 2 次
总共 3 次
```

同样是"从内存取一个数"，寻址方式不同，访存次数就差一次。

408 的综合题，经常就是这个结构：

```text
先给指令格式，让你算操作码和寻址范围
再给一条具体指令，让你算 EA 和访存次数
最后问流水线或数据通路，那是 16 篇以后的事
```

## 12. 容易混淆的八个点

**第一，EA 不是操作数。**

EA 是地址，操作数是 EA 指向的内容。

间接寻址里，EA 和操作数还隔着一层。

**第二，间接寻址 ≠ 寄存器间接寻址。**

间接的指针在内存里，访存两次。

寄存器间接的指针在寄存器里，访存一次。

**第三，变址 ≠ 基址。**

变址的 IX 由用户改，面向数组。

基址的 BR 由系统设，面向重定位。

**第四，相对寻址的 PC 值要看题目约定。**

是当前指令地址，还是下一条指令地址，差一条指令长度。

**第五，访存次数含不含取指，要看清题目。**

只问"取操作数"，就不算取指。

问"整个指令执行过程"，就要加取指。

**第六，立即寻址的"范围"是数值范围，不是地址范围。**

8 位立即数能表示 0 到 255，或者 −128 到 127，看有没有符号。

**第七，堆栈的 SP 指向哪里，要看约定。**

多数教材让 SP 指向栈顶，栈向低地址增长。

**第八，直接寻址的范围由地址字段决定，不由机器字长决定。**

地址字段 12 位就是 4K，哪怕机器是 64 位。

## 13. 小结

九种寻址方式，压成三句话：

```text
操作数在指令里：立即
操作数在寄存器里：寄存器
操作数在内存里：先算 EA，再访存
```

EA 的七种来源：

```text
直接：A
间接：M[A]
寄存器间接：(Ri)
变址：(IX) + A
基址：(BR) + A
相对：(PC) + A
堆栈：(SP)
```

三个量：

```text
访存次数：立即/寄存器 0 次，间接 2 次，其余 1 次
寻址范围：看地址字段、寄存器位数或存储字长
速度：寄存器/立即 > 直接 > 寄存器间接/变址/基址/相对 > 间接
```

基址与变址：

```text
变址：A 不动，IX 动，面向数组
基址：BR 不动，A 动，面向重定位
```

九种方式不是九条孤立规则。

它们共用同一个骨架：

```text
形式地址 + 寄存器或内存的内容 → 有效地址
```

记住骨架，再记每种方式"加了谁"，就不会混。

反直觉点再重复一次：

```text
间接寻址慢，是因为它多了一次访存。
但它让地址可以放在内存里，随时改变。
指针、链表、函数指针，都建立在这一层"地址的地址"上。
```

```text
指令少了，程序会不会变长？
复杂指令和简单指令，谁更快？
一段 C 代码，编译出来到底长什么样？
```
