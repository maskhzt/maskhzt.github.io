键盘上敲一个字符。

CPU 那边发生了什么？

它怎么知道有人按了键？按键的信息放在哪？

谁把它读进来的？

三个问题，指向同一层东西：**I/O 接口**。

再换个角度。

读一个 4 KB 的块，从磁盘到内存。

数据最终在内存里，这一点没变。

变的是"谁搬的"：

```text
程序查询    CPU 自己搬，还要一直问"好了没"
中断        设备好了叫 CPU，CPU 再来搬
DMA         设备自己搬，搬完通知 CPU
```

三种方式，CPU 花的时间差了几百倍。

差在哪？

```text
不在"搬"的速度，在"搬"的粒度
```

逐字节搬，还是整块搬。

这就是这一篇的主线。

## 1. 这个问题解决什么

CPU 和设备的差距，比人和蜗牛的差距还大。

```text
CPU 执行一条指令      约 1 ns
L1 Cache 命中         约 1 ns
主存访问              约 100 ns
SSD 随机读            几十 μs
机械硬盘随机读        几 ms
打印机出纸            几十 ms 到几秒
```

一头是纳秒，一头是毫秒。

差六个数量级。

如果 CPU 用"我盯着你干完"的方式和硬盘打交道，那 CPU 的设计就白费了。

三个不匹配，I/O 接口要全部处理掉：

```text
速度不匹配   CPU 快，设备慢，需要缓冲和状态
格式不匹配   设备可能是串行比特流，CPU 要的是并行字
时序不匹配   设备随时可能就绪，CPU 有自己的节奏
```

所以接口（interface）干三件事：

```text
① 地址译码与选中   这么多设备，CPU 说"我要 3 号"，得有人举手
② 数据缓冲与格式转换  串并转换、电平转换、字节装配
③ 状态报告与控制    好了没？出错没？开始/停止
```

一句话：

**接口是 CPU 和设备之间的翻译官兼门卫。**

翻译：把设备的串行比特流翻成 CPU 能读的并行字。

门卫：只有被点名的设备才能上总线。

接口还能再分两类。

**按数据传输方式分：**

```text
串行接口   一位一位传，线少、距离远，要做串并转换（USB、SATA）
并行接口   多位同时传，线多、距离近（老式打印机口、IDE）
```

这和 21 篇的"串行 vs 并行"是同一件事，只是发生在设备这一侧。

**按设备类型分：**

```text
字符设备   以字节流为单位，不能随机定位（键盘、串口、打印机）
块设备     以块为单位，可以随机访问任意块（磁盘、SSD、U 盘）
```

块设备才有 DMA 的必要。

字符设备一次就一个字节，用中断就够了。

408 的 I/O 这一章，考点全在"CPU 以什么方式参与"上。

因为总线（21 篇）解决了"怎么连"，接口解决了"连上之后怎么说话"。

## 2. 最小模型：接口里的三个寄存器

一个 I/O 接口，最小配置是三个寄存器加一个地址译码器。

```text
                ┌──────────────────────────┐
  数据总线 ═════╡ 数据寄存器 DR             ╡──── 数据 ──── 设备
  地址总线 ────→╡ 地址译码 / 控制逻辑        ╡
  控制总线 ────→╡ 状态寄存器 SR             ╡←─── 状态 ──── 设备
                │ 控制寄存器 CR             ╡──── 命令 ───→ 设备
                └──────────────────────────┘
                        I/O 接口
```

三个寄存器，三个作用：

```text
数据寄存器 DR   存一个字节/字，双向，CPU 和设备各写各的
状态寄存器 SR   设备告诉 CPU "我好了""我错了""我还在忙"
控制寄存器 CR   CPU 告诉设备 "开始""停止""允许中断"
```

状态寄存器里通常有这几位：

```text
READY / BUSY   就绪 / 忙
ERROR          出错（缺纸、校验错、超时）
IRQ ENABLE     中断允许
```

控制寄存器里通常有这几位：

```text
START          启动一次传输
DIR            方向：读设备还是写设备
INT ENABLE     是否允许发中断
RESET          复位
```

**端口（port）就是这些寄存器各自的地址。**

一个接口通常占好几个端口：

```text
基地址 + 0   数据端口
基地址 + 1   状态端口
基地址 + 2   控制端口
```

408 里问"一个 I/O 接口有几个端口"，答案看它有几个可被 CPU 访问的寄存器。

三个寄存器就是三个端口。

实际系统里怎么分配这些地址？

```text
独立编址（x86）：0x3F8 – 0x3FF  COM1 串口，8 个端口
                 0x1F0 – 0x1F7  IDE 主通道
                 0x60 – 0x64    键盘控制器
统一编址（MMIO）：0xFEE0_0000 起，本地 APIC
                 显卡 BAR 通常在 0xE000_0000 以上
```

一个经验规律：

```text
端口少、功能固定、要极快 → 独立编址（小端口号）
寄存器多、要大块映射、要复用现成驱动 → 统一编址（MMIO）
```

现代设备寄存器越来越多（一个 NVMe 控制器有几十个寄存器），独立编址那 64K 个端口根本不够分。

所以除了历史遗留的几个，全走 MMIO。

有的接口把状态和控制合并成一个寄存器（读是状态、写是控制），那就两个端口。

数据通路是这样的：

```text
写（CPU → 设备）：
  CPU 把数据放数据总线 → 接口的 DR 锁存 → 设备从 DR 取走

读（设备 → CPU）：
  设备把数据放 DR → 置 READY → CPU 读 DR → 清 READY
```

注意最后一步"清 READY"。

很多接口是"读清"（read-to-clear）的：读一次数据端口，READY 自动清掉。

如果 CPU 读了两次，第二次读到的是旧数据或者无效数据。

这是写驱动时最容易踩的坑之一。

## 3. 端口编址：统一 vs 独立

CPU 要访问一个端口，就得有个地址。

两种做法。

### 3.1 统一编址（memory-mapped I/O）

把端口放进主存的地址空间里。

I/O 端口和内存单元共用一套地址。

访问端口就像访问内存，用普通的 load/store 指令。

```text
地址空间：
0x0000_0000 ─────────────┐
                         │  主存
0x7FFF_FFFF ─────────────┤
                         │
0xFEE0_0000 ─────────────┤  设备寄存器（MMIO）
0xFEE0_0FFF ─────────────┘
```

优点：

```text
指令多：任何访存指令都能用，寻址方式全都能用
编程灵活：可以用指针指向设备寄存器，C 语言里就是普通的 *(volatile int *)
不需要额外的控制线：M/IO 那条线可以省掉
```

缺点：

```text
占用主存地址空间
不能靠地址线区分内存和设备，只能靠高位译码
可能被 Cache 缓存 —— 必须标记为不可缓存（uncached）
```

最后一条是真问题。

设备寄存器的值会自己变（比如状态位），Cache 一缓存，CPU 读到的是旧值。

所以 MMIO 区域必须在页表里标成 uncached。

（11 篇讲页表时提过这个标志位。）

### 3.2 独立编址（isolated I/O / port-mapped I/O）

I/O 端口单独一套地址空间。

用专门的 I/O 指令访问。

x86 的 `in` 和 `out` 就是这种。

```text
主存地址空间    0x0000_0000 – 0xFFFF_FFFF
I/O 地址空间    0x0000 – 0xFFFF（16 位，64K 个端口）
```

优点：

```text
不占主存地址空间
程序不容易误访问（要写 in/out 才行）
译码简单：地址线一到，配上 M/IO 信号就分开了
不会被 Cache 缓存（I/O 访问根本不走 Cache）
```

缺点：

```text
指令少：只有 in/out 两条，寻址方式也受限
需要额外的控制线区分内存访问和 I/O 访问
```

### 3.3 怎么判断题目在说哪一种

三个信号：

```text
"用访存指令访问 I/O"        → 统一编址
"用 in/out 或专门的 I/O 指令" → 独立编址
"地址空间与主存分开"         → 独立编址
```

408 还会问一个更细的：

> 统一编址和独立编址，哪种方式下 CPU 访问 I/O 更快？

答案：硬件速度差别不大。

差别在软件：统一编址可以用更丰富的寻址方式（变址、基址、间接），写起来更灵活。

但统一编址要处理 Cache 一致性，实际系统里通常更慢一点。

**真实世界是混着用的。**

x86 两套都有：

```text
0xCF8 / 0xCFC     PCI 配置空间端口，用 in/out 访问（独立编址）
0xFEE0_0000 起    本地 APIC 寄存器，MMIO（统一编址）
显卡的 BAR        全部 MMIO
```

现代设备几乎全是 MMIO。

独立编址活下来的地方，只剩几个历史遗留的配置端口。

## 4. 程序查询与中断

CPU 参与 I/O 的方式，本质是"用多大的粒度去管"。

从最细的开始。

### 4.1 程序查询（programmed I/O / polling）

流程：

```text
① CPU 读状态端口
② 判断 READY 位
③ 没就绪 → 回到 ①（循环）
④ 就绪 → 读/写数据端口
⑤ 修改内存地址和计数器，回到 ①
```

这叫**忙等（busy-wait）**。

CPU 的时间全花在"问"上。

**算例一：程序查询的 CPU 占用率。**

某设备传输率 2 MB/s（这里 MB = 10^6 B）。

CPU 主频 500 MHz。

每次查询状态加传送一个字节，共需 100 个时钟周期。

求 CPU 用于 I/O 的时间占比。

解：

```text
每字节时间 = 1 / (2 × 10^6) s = 0.5 μs
主频 500 MHz → 一个时钟周期 = 2 ns
每字节可用周期数 = 0.5 μs / 2 ns = 250 个

CPU 花在 I/O 上的周期 = 100 个
占比 = 100 / 250 = 40%
```

答：40%。

这里有个隐含假设：CPU 恰好在设备就绪时查询到，每字节只查询一次。

如果设备更慢、CPU 查询更快，CPU 会空转更多次，占用率还是 100%（因为它在死循环里等）。

换个数据看趋势。

设备传输率降到 100 KB/s（每字节 10 μs）：

```text
每字节可用周期 = 10 μs / 2 ns = 5000 个
占比 = 100 / 5000 = 2%
```

设备越慢，查询占比越低。

设备越快，查询占比越高，直到 CPU 被彻底占死。

```text
2 MB/s   → 40%
4 MB/s   → 80%
5 MB/s   → 100%（超过就丢数据）
```

**算例二：要传的数据量固定，算总时间。**

传 1 MB 数据，设备 2 MB/s，每次查询传送 1 B。

```text
字节数 = 2^20 = 1,048,576
每字节 CPU 时间 = 100 周期 = 200 ns
CPU 总时间 = 1,048,576 × 200 ns = 209.7 ms
传输本身耗时 = 1 MB / 2 MB/s = 524.3 ms
CPU 占用 = 209.7 / 524.3 = 40% ✓
```

注意这 209.7 ms 里，CPU 一个字节一个字节地搬，什么别的都干不了。

程序查询的两个改进：

```text
多设备轮询：一个循环里查 8 个设备，提高利用率
定时轮询：用定时器每隔一段时间查一次，不用死循环
```

多设备轮询的账是这样算的。

8 台设备，每台每 100 μs 就绪一次，每台查询加传送 50 个周期（100 ns @ 500 MHz）。

```text
一次大循环：8 台 × 50 周期 = 400 周期 = 800 ns
循环周期必须 ≤ 100 μs，否则会漏数据
一个循环里 CPU 花 800 ns
占用 = 800 ns / 100 μs = 0.8%
```

看起来只有 0.8%，很划算。

但代价是：

```text
CPU 必须每 100 μs 回来一趟，中间不能有长指令序列
如果某台设备突然变快，轮询周期就得跟着缩短
8 台还好，800 台就没法轮了
```

所以轮询的设备数一多就撑不住：复杂度随设备数线性增长，中断不会。

但根本问题没解决：**CPU 和 I/O 是串行的。**

CPU 必须"在场"，才能接到数据。

### 4.2 中断方式（interrupt-driven I/O）

设备就绪，主动发中断请求。

CPU 不用等，去干别的。

中断来了再处理。

流程：

```text
① CPU 启动设备（写控制寄存器），然后继续执行主程序
② 设备就绪，拉中断请求线
③ CPU 执行完当前指令，检查到中断
④ 保存现场（PC、PSW、通用寄存器）
⑤ 跳转到中断服务程序（ISR），读数据寄存器，存内存
⑥ 恢复现场，返回主程序
```

关键区别：

```text
查询：CPU 主动问，问之前不知道好了没
中断：设备主动说，CPU 只在被叫时到场
```

**算例三：中断次数与开销。**

同一台设备，2 MB/s。

改成中断方式，每次中断传 4 B（一个字）。

每次中断的总开销算 200 个时钟周期：

```text
响应与判优           20 周期
保存现场             60 周期
ISR 决策与搬运        80 周期
恢复现场             40 周期
合计                200 周期
```

主频 500 MHz（5 × 10^8 周期/秒）。

```text
每秒中断次数 = 2 × 10^6 / 4 = 5 × 10^5 次
每秒 CPU 周期 = 5 × 10^5 × 200 = 1 × 10^8 周期
占用率 = 1 × 10^8 / (5 × 10^8) = 20%
```

答：20%。

从 40% 降到 20%。

但如果每次只传 1 B：

```text
每秒中断 = 2 × 10^6 次
每秒 CPU 周期 = 2 × 10^6 × 200 = 4 × 10^8
占用率 = 4 × 10^8 / 5 × 10^8 = 80%
```

80%，比查询还糟。

**这就是中断的死穴：中断次数正比于传输次数。**

传得快、传得碎，中断就淹没 CPU。

算数据量固定的版本：

传 1 MB，每次 4 B：

```text
中断次数 = 1,048,576 / 4 = 262,144 次
CPU 开销 = 262,144 × 200 = 52,428,800 周期
时间 = 52,428,800 / (5 × 10^8) = 104.9 ms
```

对比查询的 209.7 ms，省了一半。

但 104.9 ms 里，CPU 全在做中断处理。

还有一笔隐藏成本，408 不考但真实存在：

```text
每次中断都要保存/恢复现场
流水线被冲掉，Cache 被污染（18 篇）
中断太密时，CPU 可能永远在执行 ISR，主程序得不到执行
```

这叫**中断活锁（livelock）**。

真实系统的解法是"中断合并"：攒够一批再中断一次。

而"攒一批"这件事，DMA 直接做到了极致。

## 5. DMA：让设备自己搬

DMA（Direct Memory Access，直接存储器访问）的核心一句话：

**数据从设备到内存，不经过 CPU 的寄存器。**

CPU 只负责在开头交代任务，在结尾收个尾。

### 5.1 DMA 的三种工作方式

DMA 要访存，就会和 CPU 抢内存。

三种抢法。

**一、停止 CPU 访存（成块传送）**

DMA 传一整块时，CPU 交出总线，停下来。

```text
CPU:  ──运行──|  停  |──运行──
DMA:          |传 4 KB|
```

优点：控制最简单，DMA 想什么时候传就什么时候传，速度最快。

缺点：CPU 在这一整块传输期间完全停摆。

传 4 KB，设备 2 MB/s：

```text
4 KB = 4096 B，2 × 10^6 B/s
传输时间 = 4096 / 2 × 10^6 = 2.048 ms
CPU 停 2 ms
```

2 ms 足够现代 CPU 执行几百万条指令。

所以这种方式只适合"块很大、传输很快"的场合，或者 CPU 本来就没活干。

**二、周期挪用（cycle stealing，周期窃取）**

DMA 每次只偷一个存储周期（或总线周期）。

CPU 慢一拍，但不停止。

```text
CPU:  ─X─X─X─X─X─X─X─X─   （被偷走的周期标记为 X）
DMA:    ↑   ↑   ↑   ↑
```

优点：CPU 不会被长时间打断，效率高。

缺点：控制复杂，DMA 每次都要发总线请求、等仲裁。

而且 CPU 的访存被推迟，实际执行时间会变长。

408 最常考的就是这种方式。

```text
"周期挪用" = 每次偷一个周期
"停止 CPU 访存" = 一次偷一整块
```

**三、DMA 与 CPU 交替访存**

把时间切成片，一半给 CPU，一半给 DMA。

```text
周期 1  3  5  7  → CPU 访存
周期 2  4  6  8  → DMA 访存
```

优点：不需要总线请求线，时序固定，控制简单。

缺点：CPU 和 DMA 各自只能用一半的访存带宽，利用率低。

内存的带宽被硬切了一半，谁都不够用。

```text
三种方式一句话：
停止 CPU    一次偷一大块，CPU 停
周期挪用    一次偷一拍，CPU 慢一点
交替访存    时间对半分，谁都不痛快
```

三种方式的时序差别，画出来最清楚。

```text
停止 CPU 访存：
CPU:  ████|        |████         ← 中间整段停摆
DMA:      |▓▓▓▓▓▓▓▓|             ← 一整块连续传
总线:      ←── DMA 独占 ──→

周期挪用：
CPU:  ██▓██▓██▓██▓               ← 每几拍被偷一拍，慢但不死
DMA:    ↑  ↑  ↑  ↑               ← 每次偷一个存储周期
总线:  交替，仲裁器一拍一拍地给

交替访存：
CPU:  █░█░█░█░                   ← 固定半分
DMA:   ░█░█░█░█                   ← 另一半
总线:  时间对半分，不需要请求线
```

三种方式的 CPU 停顿时间，一眼可见：

```text
停止 CPU   最长（整块传输期间）
周期挪用   最短（每拍延迟一点）
交替访存   固定（一半时间不能用）
```

408 常问一句：

> 周期挪用方式下，CPU 是否停止执行程序？

不停止，只是每次访存被推迟。

### 5.2 DMA 控制器的结构

```text
        ┌─────────────────────────────────┐
        │          DMA 控制器              │
        │                                 │
  ──────┼──→ 地址寄存器 AR   当前内存地址  │
  ──────┼──→ 字计数器 WC     还剩多少字节  │
  ──────┼──↔ 数据缓冲寄存器 DR             │
  ──────┼──→ 控制/状态逻辑 + 中断机构      │
        │                                 │
        └───────┬──────────────┬──────────┘
                │DMA 请求 HRQ   │DMA 响应 HLDA
                ↓               ↑
            总线仲裁器         CPU
```

四个部件：

```text
地址寄存器 AR   这次传到哪了，每传一个字节 +1（或 +4）
字计数器 WC     还剩多少，每传一个 -1，减到 0 就结束
数据缓冲 DR     暂存一个字节/字，做速度匹配
控制/状态逻辑   发 DMA 请求（HRQ），收响应（HLDA），结束时发中断
```

HRQ / HLDA 就是 21 篇里的 BR / BG。

DMA 控制器也是一个主设备，也要参与总线仲裁。

### 5.3 DMA 的传输过程

三段：

```text
① 预处理（CPU 做）
   CPU 写 AR（内存起始地址）
   CPU 写 WC（传输字节数）
   CPU 写控制寄存器（方向、是否中断）
   CPU 置 START 位
   然后 CPU 就走了，去执行别的程序

② 数据传送（DMA 硬件做）
   设备发 DMA 请求（DREQ）
   DMA 控制器向总线仲裁器发 HRQ
   拿到总线（HLDA）后，用掉一个存储周期：
     - 读：设备 → DR → 内存[AR]
     - 写：内存[AR] → DR → 设备
   AR ← AR + 1，WC ← WC − 1
   重复，直到 WC = 0

③ 后处理（CPU 做）
   WC = 0，DMA 控制器发中断
   CPU 进 ISR：校验数据、清标志、唤醒等待的进程、
   决定下一块从哪读
```

注意第 ① 步和第 ③ 步。

这两步，CPU 一定在场。

这就是后面"反直觉"那一节的伏笔。

### 5.4 DMA 与中断的区别

五条，408 最爱考。

```text
① 数据是否经过 CPU
   中断：经过。ISR 用寄存器一条一条搬
   DMA：不经过。设备 ↔ 内存 直连，CPU 寄存器完全不参与

② CPU 干预的粒度
   中断：每个字节/字一次（程序级）
   DMA：一整块一次（硬件级）

③ 响应时机
   中断：一条指令执行结束后才响应
   DMA：一个存储周期结束后就能挪用（更快）

④ 优先级
   DMA 通常高于中断。DMA 请求不会被关中断屏蔽，
   因为它抢的是总线/存储周期，不是 CPU 的执行流

⑤ 适用对象
   中断：低速、随机、需要 CPU 判断的设备（键盘、鼠标、串口）
   DMA：高速、成块、不需要 CPU 逐字节看的设备（磁盘、网卡、显卡）
```

一句话区分：

```text
中断是"设备叫 CPU 来搬"
DMA 是"设备自己搬，搬完叫一声"
```

### 5.5 通道与 I/O 处理机

再往上还有一层。

**通道（channel）** 是一台小 CPU，有自己的指令系统（通道指令），能执行通道程序。

一条"启动 I/O"指令，就能让通道自己完成一整批 I/O，包括多台设备、多个数据块。

**I/O 处理机（IOP, I/O processor）** 比通道更强，是一台完整的外围处理机，能脱离主机独立工作。

四层阶梯：

```text
程序查询   CPU 问、CPU 搬
中断       CPU 不问，但 CPU 搬
DMA        CPU 不搬，只交代和收尾（一块）
通道       CPU 只交代一次，管一整批（多块、多设备）
```

## 6. 408 怎么考

三类题：

```text
① 算 CPU 占用率 / 时间（给传输率、每次开销、主频）
② 判断该用哪种方式（给设备特性、数据量、实时性要求）
③ 描述 DMA 传输过程 / 比较 DMA 与中断
```

**例题一：CPU 占用率。**

某设备传输率 1 MB/s（10^6 B/s），CPU 主频 1 GHz。

（1）用程序查询，每次查询加传送共 200 个周期，每字节查询一次，求占用率。

（2）用中断，每次中断传 2 B，每次中断开销 300 个周期，求占用率。

（3）用 DMA，每块 8 KB，每次 DMA 的初始化加收尾共 500 个周期，求占用率。

解：

```text
每字节时间 = 1 / 10^6 s = 1 μs
主频 1 GHz → 周期 1 ns
每字节可用周期 = 1 μs / 1 ns = 1000 个

（1）占用 = 200 / 1000 = 20%

（2）每秒中断次数 = 10^6 / 2 = 5 × 10^5 次
    每秒 CPU 周期 = 5 × 10^5 × 300 = 1.5 × 10^8
    占用 = 1.5 × 10^8 / 10^9 = 15%

（3）每秒 DMA 次数 = 10^6 / 8192 ≈ 122.07 次
    每秒 CPU 周期 = 122.07 × 500 ≈ 61,035
    占用 = 61,035 / 10^9 ≈ 0.0061%
```

答：20%、15%、约 0.006%。

三种方式的数量级差在这里看得很清楚。

从 20% 到 0.006%，差了三千多倍。

**例题二：判断该用哪种方式。**

题干通常长这样：

> 某设备每秒产生 100 个数据，每个数据 1 B，CPU 每次处理需 50 个周期，主频 100 MHz。
> 应采用哪种 I/O 方式？

解：

```text
每秒 100 次，每次间隔 10 ms
每次中断开销按 50 周期算 = 50 / (100 × 10^6) = 0.5 μs
占用 = 0.5 μs / 10 ms = 0.005%
```

这种设备（低速、稀疏）用中断最合适。

查询也行，但白白占着 CPU（0.005% 也够低了，实际用查询也常见）。

如果是"每秒 10^6 次、每次 4 KB"，那就必须 DMA。

判断口诀：

```text
频率低、数据少、要 CPU 判断  → 中断
频率高、数据成块、CPU 不用看  → DMA
设备极慢、CPU 闲着也是闲着    → 查询也行（最便宜）
多设备、大批量、要卸载 CPU    → 通道
```

**例题三：DMA 传输过程。**

问：DMA 控制器在传输过程中，什么时候会用到 CPU？

答三条：

```text
① 传输前：CPU 写地址寄存器、字计数器、控制寄存器，启动
② 传输中：CPU 不参与数据搬运，但 DMA 抢总线时，
           CPU 一侧的仲裁逻辑要配合让出总线
③ 传输后：DMA 发中断，CPU 执行 ISR 做校验和收尾
```

答"CPU 完全不参与"是错的。

答"数据经过 CPU"也是错的。

## 7. 真实芯片里长什么样

先看设备是怎么被枚举出来的。

以下是简化示意：

```text
$ lsusb
Bus 002 Device 001: ID 1d6b:0003 Linux Foundation 3.0 root hub
Bus 001 Device 004: ID 046d:c52b Logitech, Inc. Unifying Receiver
Bus 001 Device 005: ID 0781:5581 SanDisk Corp. Ultra Fit
Bus 001 Device 001: ID 1d6b:0002 Linux Foundation 2.0 root hub
```

`Bus 002 Device 001` 是总线号加设备号。

USB 的寻址是"总线 → 设备 → 端点（endpoint）"。

每个设备有若干端点，每个端点有自己的方向（IN / OUT）和类型（控制、批量、中断、等时）。

```text
端点 0        控制端点，枚举时用
批量端点      U 盘、网卡，大块数据
中断端点      键盘、鼠标，小数据、有周期保证
等时端点      摄像头、声卡，要带宽保证、允许丢
```

"中断端点"这个名字容易误解。

USB 的"中断传输"不是设备主动打断主机。

是主机按固定周期来问："你有数据吗？"

**本质还是轮询，只是协议层叫 interrupt。**

这一点在 408 里不会考，但在真实系统里必须知道。

因为 USB 是主机轮询的总线（21 篇），设备根本没有资格主动发。

真正的"设备主动"是 PCIe 的 MSI/MSI-X。

所谓"发中断"，其实是设备往一个约定地址写一个值。

中断变成了一个内存写操作。

再看 I/O 的"忙"是怎么体现的。

以下是简化示意：

```text
$ vmstat 1
procs -----------memory---------- ---swap-- -----io---- --system-- ------cpu-----
 r  b   swpd   free   buff  cache   si   so    bi    bo   in    cs us sy id wa st
 1  0      0 812345  12034 902345    0    0    12    48  812  1204 12  3 84  1  0
 0  2      0 801234  12034 902345    0    0  4096 16384 1024  2103  2  5 43 50  0
```

最后一列 `wa`（iowait）是 CPU 空闲、但有未完成的 I/O 的时间占比。

第二行 `wa = 50`，意思是这一秒 CPU 有一半时间是"闲着等 I/O"。

再看磁盘侧：

以下是简化示意：

```text
$ iostat -x 1
Device   r/s     w/s     rkB/s    wkB/s  await  %util
nvme0n1  120.0   340.0   4800.0  17600.0   0.42   12.3
sda        2.0    18.0    128.0    576.0   8.90   45.6
```

`await` 是平均 I/O 等待时间（毫秒），`%util` 是设备忙碌时间占比。

`sda` 的 `%util` 45.6%、`await` 8.9 ms，说明这个盘已经在排队了。

这三个数字放在一起看，能推出 I/O 用的是哪种方式：

```text
vmstat 的 in 很高，说明中断次数多 → 逐包/逐块中断
iostat 的 %util 高但 CPU 的 sy 低 → 数据搬运没占 CPU，大概率是 DMA
vmstat 的 wa 高、us 低 → CPU 在等 I/O，不是在搬数据
```

现代 NVMe 盘，一个 4 KB 读大概是这样的：

```text
① 驱动把命令写进提交队列（在内存里）——MMIO 写 doorbell
② 盘自己从内存读命令（DMA 读）
③ 盘把数据写进内存（DMA 写）
④ 盘往完成队列写一个条目（DMA 写）
⑤ 盘发 MSI-X 中断
⑥ 驱动在 ISR 里看完成队列，唤醒进程
```

CPU 全程没碰数据。

它只写了几个 doorbell、处理了一次中断。

这就是 DMA 在真实系统里的样子。

（以上 `lsusb`、`vmstat`、`iostat` 输出为简化示意。）

## 8. 四种方式对比

| 方式 | CPU 干预粒度 | 数据路径 | CPU 占用 | 适用设备 |
|---|---|---|---|---|
| 程序查询 | 每字节，且要忙等 | 设备 → CPU → 内存 | 最高 | 极慢、偶发设备 |
| 中断 | 每字节/字一次 | 设备 → CPU → 内存 | 中到高 | 低速、随机设备 |
| DMA | 每块一次 | 设备 → 内存（直连） | 极低 | 高速块设备 |
| 通道 | 每批一次 | 设备 → 内存（通道管） | 最低 | 大型机多设备 |

四个层次的本质：

```text
查询 → 中断：CPU 不用等
中断 → DMA：CPU 不用搬
DMA → 通道：CPU 不用一块一块地交代
```

一个容易漏的点：

四种方式都需要 CPU **初始化**。

```text
查询：CPU 写控制寄存器启动，然后自己开始轮询
中断：CPU 写控制寄存器启动，开中断
DMA：CPU 写 AR、WC、控制寄存器，启动
通道：CPU 执行一条"启动 I/O"指令
```

区别只在"启动之后 CPU 还管多少"。

## 9. 容易混淆的点

五组。

**一、接口 vs 端口 vs 设备。**

```text
设备    打印机、硬盘、键盘本体
接口    主板/芯片里那块电路，管地址译码、缓冲、状态
端口    接口里可被 CPU 访问的寄存器的地址
```

一个接口可以有多个端口。

一台设备接一个接口，一个接口可以带多台同类设备（比如一个 USB 控制器带多个设备）。

**二、统一编址 vs 独立编址的"优点"。**

统一编址的优点在"指令和寻址方式多"。

独立编址的优点在"不占地址空间、不会被缓存、译码简单"。

408 常把两者的优点对调，让你判断。

记法：

```text
统一编址 = 蹭内存的指令集，灵活但占地方
独立编址 = 自己一套，干净但指令少
```

**三、中断方式下"CPU 不等待"≠"CPU 不参与"。**

中断省掉的是"等"。

搬运还是 CPU 干的，一个字节一条指令。

所以中断方式下 CPU 的占用率仍然正比于传输率。

**四、DMA 的"周期挪用" vs "停止 CPU 访存"。**

```text
周期挪用   每传一个字节/字，偷一个存储周期
停止 CPU   传一整块期间，CPU 完全不访存
```

408 会问"周期挪用方式下，CPU 是否停止执行程序"。

不停止，只是每次访存被推迟一个周期。

**五、通道 vs DMA。**

```text
DMA   一个控制器管一条数据流，CPU 每块交代一次
通道  一台小 CPU 执行通道程序，CPU 每批交代一次
```

通道能自己控制多台设备、执行多条通道指令、处理状态。

DMA 只会"搬 N 个字节"。

**六、DMA 的三种方式，别混成一种。**

```text
停止 CPU 访存   一次让一整块，CPU 停
周期挪用        一次让一个存储周期，CPU 慢一拍
交替访存        时间对半，谁也不占谁
```

题目说"周期挪用"就是第二种，CPU 不停止；

说"CPU 暂停执行"就是第一种。

## 10. 反直觉：DMA 没让 CPU 完全闲着

很多人的记忆是：

```text
"DMA 绕过 CPU，所以 CPU 完全不参与。"
```

错。

DMA 绕过的只有一段路：**数据搬运**。

数据从设备到内存，确实不经过 CPU 的寄存器。

但一次 DMA 传输有三个时刻，CPU 必须在场。

```text
① 开始之前
   谁告诉 DMA 控制器"从哪读、读到哪、读多少"？
   是 CPU，一条一条写寄存器（AR、WC、控制字）。
   这几条指令就是 CPU 执行的。

② 传输之中
   DMA 要抢总线，总线仲裁要把总线让出来。
   这个"让"，是 CPU 一侧的硬件在配合。
   周期挪用方式下，CPU 每个被偷走的周期都要停顿一下。

③ 结束之后
   DMA 发中断，CPU 校验数据、清标志、唤醒进程、
   决定下一块从哪读。
   没有这一步，数据传完了也没人知道。
```

所以准确的说法是：

**DMA 把 CPU 从"搬运工"降级成"工头"。**

工头不用搬砖，但开工和收工都得他签字。

这个区别在算占用率时体现得很清楚。

回到例题一：

```text
中断方式   每字节 300 周期，占用 15%
DMA 方式   每块 500 周期，占用 0.006%
```

DMA 的 0.006% 不是 0。

它对应的是"每 8 KB 一次交代 + 一次中断"，不是"什么都不用做"。

还有一层更隐蔽的成本：**缓存一致性。**

DMA 直接写内存，不经过 CPU 的 Cache。

如果那块内存刚被 CPU 读过，Cache 里是旧值。

```text
DMA 写内存 → 内存变成新值 → Cache 里还是旧值 → CPU 读到旧的
```

所以 DMA 传输前后要处理：

```text
传之前：把 Cache 里脏的数据写回（flush）
传之后：把对应 Cache 行作废（invalidate）
```

或者干脆用"一致性映射"（coherent mapping），让硬件保证。

这件事在 x86 上是 IOMMU 和硬件一致性协议在做。

在 ARM 上，很多平台要驱动手动 `dma_sync_*`。

**所以"CPU 完全不参与"这句话，错得比你想象的更彻底。**

DMA 省的是搬运的指令，不是省掉 CPU 的存在。

408 里有两道经典判断题，两句都错：

> "DMA 方式下数据不经过 CPU，因此 CPU 完全不干预 I/O 过程。"

前半句对，后半句错。

> "DMA 方式下数据从设备直接送入内存，不需要 CPU 执行任何指令。"

错。启动 DMA 的那几条写寄存器指令，就是 CPU 执行的。

## 11. 小结 + 下一篇

四层阶梯：

```text
查询 → 中断：CPU 不用等
中断 → DMA：CPU 不用搬
DMA → 通道：CPU 不用一块一块交代
```

三句话：

```text
接口是三个寄存器：数据、状态、控制，各有一个端口地址
统一编址蹭内存指令，独立编址自己一套，x86 两套都有
DMA 省的是搬运，不是指挥
```

两个能随手算的量：

```text
查询/中断：CPU 时间 = 传输次数 × 每次开销 / 主频
DMA：      CPU 时间 = 块数 × 每次开销 / 主频
```

传输次数和块数差多少，CPU 时间就差多少。

```text
1 MB，每次 4 B   → 262,144 次
1 MB，每块 4 KB  → 256 次
比值 1024
```

粒度就是这一章的全部。
