> **读这篇之前，你只需要知道**：位是一个 0 或 1，八位叫一个字节；十六进制是二进制的缩写，四位二进制正好写成一位十六进制（0–9 之后用 A–F 补足）；“逢几进一”的规则叫进制，人习惯十进制，机器只认二进制。
> **这篇讲什么**：同一串 0/1 为什么可以有五种都正确的读法，电脑偏偏选了其中一种（补码）来存负数，还因此多表示出一个 −128；顺带讲清 BCD、ASCII、校验位这三种“给人看、给传输用”的编码。
> **一个类比**：把 0/1 串想成一张只写了数字的纸条。纸条本身没有含义，是你拿哪本字典去查它，才决定它读作什么：查《无符号字典》是 204，查《补码字典》是 −52。这篇就是把这几本字典的编法摊开，让你随手能查。


看一个字节。

```text
0xCC = 1100 1100
```

这一个字节，至少有五种正确的读法。

```text
当无符号数读：   204
当补码读：      −52
当原码读：      −76
当反码读：      −51
当移码读（偏置 128）：76
```

全都对。

因为它到底是多少，取决于你用哪套约定去看它。

**一个 0/1 串本身没有含义，含义是编码给的。**

这一篇就把这几套约定摊开。

摊到你能随手写出四种编码为止。

## 1. 一个字节的两种读法

先问一句：为什么负数会有四种存法？
因为电路里根本没有“负号”这个东西，它只认高电平和低电平，也就是 1 和 0。
所以“负数”必须由人来约定：拿哪一位当符号、剩下的位放什么。
约定不同，同一串 0/1 就读出不同的数。
这是整篇所有混乱的源头，也是所有考点的源头。

先从最小的分歧开始。

```text
无符号数（unsigned）：全部 8 位都算数值
  1100 1100 = 128 + 64 + 8 + 4 = 204

有符号数（signed）：最高位当符号位
  最高位 1 表示负数
```

只要允许负数，问题立刻来了：负数怎么存。

四种方案的名字先各给一句话，后面逐节拆开：
原码（sign-magnitude）：最高位当符号（0 表示正、1 表示负），其余位放绝对值。
反码（ones' complement）：负数的数值位逐位取反，符号位保留不动。
补码（two's complement）：负数按“逐位取反再加一”算出来，今天所有主流机器都用它。
移码（biased）：把真值统一加上一个固定的偏置数，让所有编码都变成非负。

```text
有四种主流答案：
  原码  sign-magnitude
  反码  ones' complement
  补码  two's complement
  移码  biased
```

四种答案，四种不同的 0/1 排布。

后面几节逐个拆。

先交代一句为什么是 8 位。

```text
早期机器字长五花八门：6 位、9 位、12 位、36 位都有。
1964 年 IBM System/360 把 8 位定为一个字节（byte），
之后小型机、微机全部跟上，8 位就成了事实标准。

8 位的两个好处：
  ① 刚好装下 7 位 ASCII 码，再留 1 位做校验或扩展
  ② 是 2 的幂，切成十六进制正好两位一组，读写都方便
```

所以"一个字节"既是硬件的宽度，也是编码的宽度。

两者从 1960 年代起就绑在一起了。

先看更基础的一层：进制。

## 2. 进制转换：二、八、十、十六

先问：机器只认二进制，为什么还要学八进制和十六进制？
因为人读长串 0/1 会出错：让你数清 110011001100 里有几个 1，你得一位一位点过去。
写成 0xCCC 一眼就能看清，而它和二进制之间只是“四位一组”的机械对应，不需要算。
转换是人和机器之间的翻译工作，两边都得熟。

计算机用二进制，人用十进制，写代码用十六进制，权限位用八进制。

四种进制在一台机器上同时存在。

转换只有两个方向。

**十进制转任意进制：除基取余，倒着读。**

```text
173 转二进制：
173 ÷ 2 = 86 余 1   ← 最低位
 86 ÷ 2 = 43 余 0
 43 ÷ 2 = 21 余 1
 21 ÷ 2 = 10 余 1
 10 ÷ 2 =  5 余 0
  5 ÷ 2 =  2 余 1
  2 ÷ 2 =  1 余 0
  1 ÷ 2 =  0 余 1   ← 最高位

倒着读：1010 1101
```

验算一遍：128 + 32 + 8 + 4 + 1 = 173。

对。

**小数部分：乘基取整，顺着读。**

```text
0.6875 转二进制：
0.6875 × 2 = 1.375  取整 1  ← 最高小数位
0.375  × 2 = 0.75   取整 0
0.75   × 2 = 1.5    取整 1
0.5    × 2 = 1.0    取整 1  ← 最低小数位

顺着读：0.1011

验算：0.5 + 0.125 + 0.0625 = 0.6875 ✓
```

不是所有小数都这么听话。

```text
0.1 × 2 = 0.2  取 0
0.2 × 2 = 0.4  取 0
0.4 × 2 = 0.8  取 0
0.8 × 2 = 1.6  取 1
0.6 × 2 = 1.2  取 1
0.2 × 2 = 0.4  取 0   ← 循环了
...
0.1₁₀ = 0.0001100110011…₂
```

永远转不完。

这就是第 00 篇那个 `0.1 + 0.2` 的根。

**二、八、十六之间：按位分组，不用算。**

```text
八进制 ↔ 二进制：3 位一组
十六进制 ↔ 二进制：4 位一组

1010 1101
  ↓ 3 位一组（从右往左）
10 101 101  → 2 5 5  → 255₈

1010 1101
  ↓ 4 位一组（从右往左）
1010 1101  → A  D    → 0xAD
```

反向也一样。

```text
0x2C6
= 0010 1100 0110
   ↓ 3 位一组补零
001 011 000 110 → 1 3 0 6 → 1306₈

十进制核一遍：2×256 + 12×16 + 6 = 512 + 192 + 6 = 710
八进制核一遍：1×512 + 3×64 + 0×8 + 6 = 512 + 192 + 6 = 710 ✓
```

分组法一定要会。

408 里所有“写出十六进制编码”的题，都是靠四位一组完成的。

用十进制绕一圈，慢十倍还容易错。

顺带回答一个基础问题：为什么机器偏爱二进制。

```text
① 物理上容易做：通/断、高/低、有磁/无磁，只有两个稳定状态
② 抗干扰：两个状态隔得远，阈值判断不容易错
③ 运算规则最简单：加法和乘法表各只有 4 条
④ 和布尔代数直接对应：0/1 就是假/真，逻辑门就是开关
```

历史上有过十进制机器。

```text
ENIAC 用十进制计数器（10 个电子管一组），庞大、难维护。
也有过三进制机器（苏联 Setun，1958），
理论上三进制更省“位”，但器件生态跟不上。

最后赢的是二进制，原因不是它最节省，
而是它最容易在电路上稳定实现。
```

三进制的那个论点值得记住。

```text
若用 r 进制，表示 n 个数需要的“位数 × 每位的状态数”正比于 r/ln r。
r = e ≈ 2.718 时最小。
所以 3 进制理论上最优，2 进制几乎打平，10 进制差得多。
```

工程上没选 3，是因为做三个稳定状态的器件太贵。

## 3. BCD 与 ASCII

二进制算得快，但人不习惯读。

于是有了两种“给人看”的编码。

**BCD（binary-coded decimal）：用 4 位二进制表示 1 位十进制。**

```text
47₁₀
  = 0100 0111   （压缩 BCD，8 位存两位十进制）
  = 0x47
```

注意 `0x47` 这个写法。

它的值不是 47，是 71。

BCD 的巧合就在这里：十六进制看起来像十进制，值却不一样。

```text
8421 码：就是最朴素的 BCD，权值是 8/4/2/1
余 3 码：每位加 3
  47 → 0100 0111 → +0011 0011 → 0111 1010
```

BCD 有什么用。

```text
财务计算：0.1 + 0.2 必须是 0.3，不能是 0.30000000000000004
显示器驱动：要把 0–9 直接送七段数码管
```

BCD 的加法不能直接借用二进制加法器，要做“加 6 修正”。

这是 408 的一个细节考点。

```text
47 + 38 = 85

  0100 0111   (47 的 BCD)
+ 0011 1000   (38 的 BCD)
-----------
  0111 1111   = 0x7F

低 4 位是 F，不是合法的 BCD 数字（每 4 位只允许 0–9）。
为什么：7 + 8 = 15，二进制加法在第 4 位内完成了，
但 BCD 每 4 位只装 10 个数，多出来的 6 个编码是空的。

修正：某 4 位的结果 > 9（或产生了进位），就给它加 6
  1111 + 0110 = 1 0101  →  低 4 位得 5，向高 4 位进 1
高 4 位：7 + 0 = 7，再加进位 1 = 8

结果 1000 0101 = 0x85 = 85 ✓
```

加 6 的道理，就在这里。

```text
4 位能表示 16 个数，BCD 只用 10 个，跳过 6 个。
所以每一位“溢出”的时候，要补回这 6 个空档。
```

同样的修正也出现在十进制调整指令里。

```text
x86：DAA / DAS（加/减后的十进制调整）
ARM：没有等价指令，BCD 运算要靠软件或十进制扩展
```

**ASCII：用 7 位（实际存 8 位）表示字符。**

ASCII 是 American Standard Code for Information Interchange 的缩写，即美国信息交换标准代码。
它给 128 个常用字符各编了一个 7 位的号码：数字、大小写字母、标点、以及一批控制字符。
7 位只够 128 个字符，装不下汉字，所以后来各国又各自往下扩展。

```text
'0' = 0x30 = 48 = 0011 0000
'1' = 0x31 = 49
'9' = 0x39 = 57
'A' = 0x41 = 65
'Z' = 0x5A = 90
'a' = 0x61 = 97
'z' = 0x7A = 122
```

三个必须记住的差值。

```text
'9' − '0' = 9        数字字符连续排列
'a' − 'A' = 0x20 = 32  大小写只差第 5 位
'0' 与 BCD 值 0 差 0x30  数字字符 = BCD 码值 + 0x30
```

最后一条是实用的：想把 BCD 转成 ASCII，加 0x30；反过来减 0x30。

```text
BCD 0x47  → ASCII '4''7' → 0x34 0x37
ASCII 0x34 0x37 → 减 0x30 → 0x04 0x07 → 拼成 0x47
```

408 考得不多，但“ASCII 码占 1 字节、最高位常用作校验位或扩展”这句话会出现在选择题里。

ASCII 有个很好用的性质：大小写只差一位。

```text
'A' = 0100 0001 = 0x41
'a' = 0110 0001 = 0x61
         ↑
      只差 bit5（0x20）

转小写 = 或上 0x20
转大写 = 与上 0xDF
判大小写 = 看 bit5
```

超过 127 的部分，各家自己填。

```text
1963 年：ASCII 定 7 位，128 个字符
扩展 ASCII：用满 8 位，256 个字符，但各国不兼容
中文：GB2312 / GBK 是双字节，UTF-8 是变长（汉字 3 字节）
```

408 只考标准 ASCII 的 7 位那一段。

## 4. 校验码：奇偶与二维奇偶

数据在传输和存储时会翻位。

一个 0 变成 1，这叫一个错误。

检测错误最便宜的办法是加一位校验位。

```text
奇校验：数据位 + 校验位 中，1 的总个数为奇数
偶校验：数据位 + 校验位 中，1 的总个数为偶数
```

算一个。

```text
数据 1011 0011
1 的个数 = 5（奇数）

偶校验：校验位补 1 → 总共 6 个 1，偶数 ✓
奇校验：校验位补 0 → 总共 5 个 1，奇数 ✓
```

奇偶校验的能力边界必须说清。

```text
能检出：奇数个位出错
检不出：偶数个位出错
不能定位：知道错了，不知道哪一位错
```

改进办法是二维奇偶校验。

```text
把数据排成矩阵，每行一个校验位，每列一个校验位。

        列校验
  d11 d12 d13 d14 | r1
  d21 d22 d23 d24 | r2
  d31 d32 d33 d34 | r3
  ---------------------
  c1  c2  c3  c4  | 总校验

某一位翻转 → 它所在的行和列校验同时出错
→ 行号 + 列号 → 直接定位到那一位，并且可以纠正
```

一句话总结：一维奇偶只能查错，二维奇偶能纠一位错。

更强的方案是汉明码（Hamming code），能纠一位、检两位。

第 06 篇讲主存芯片时会再遇到它。

这里先算一个最小的例子，因为 408 会问。

```text
4 位数据 1011，加 3 位校验位，凑成 7 位。

校验位放在 2 的幂次位置上：第 1、2、4 位
数据位放在其余位置：第 3、5、6、7 位

位置   1   2   3   4   5   6   7
内容  p1  p2  d1  p4  d2  d3  d4
数据       1       0   1   1

按偶校验定三个 p：
  p1 管 1,3,5,7 → p1 + 1 + 0 + 1 为偶数  → p1 = 0
  p2 管 2,3,6,7 → p2 + 1 + 1 + 1 为偶数  → p2 = 1
  p4 管 4,5,6,7 → p4 + 0 + 1 + 1 为偶数  → p4 = 0

码字：0 1 1 0 0 1 1 = 0110011
```

怎么纠错。

```text
若第 5 位翻转（0 → 1），码字变成 0110111

  组 1（1,3,5,7）= 0+1+1+1 = 3，奇数 ✗
  组 2（2,3,6,7）= 1+1+1+1 = 4，偶数 ✓
  组 4（4,5,6,7）= 0+1+1+1 = 3，奇数 ✗

出错位置 = 1 + 4 = 5
把第 5 位再翻回来即可。
```

三个校验组的“对错”拼起来，正好就是出错位的二进制编号。

```text
组 4 组 2 组 1
 ✗    ✓    ✗    →  101 = 5
```

这就是汉明码的全部设计思想：让校验结果自己报出地址。

**如果没有校验位，会怎样？**

内存里一个 0 因为电压抖动或宇宙射线翻成了 1，程序读到的就是另一个数。

这个数可能刚好是金额的小数位，也可能刚好是条指令的操作码。

整台机器没有任何机制发现这件事，只会安静地算出一个错的结果。

校验位的作用，就是让这种错误至少在“读出来”的那一刻被察觉，而不是等三天后账目对不上再回头查。

代价只是一点带宽或一点空间：8 位数据配 1 位校验，多花 12.5%。

## 5. 机器数与真值

回到最开头那个字节。

先统一两个词，后面每道题都要用到它们。
机器数（machine number）：机器里真正存着的那串 0/1，比如 1100 1100。
真值（true value）：这串 0/1 按某套编码翻译出来、带正负号的十进制数，比如 −52。
一个机器数能对应好几个真值，取决于你按哪套编码去读它。
所以读题第一步永远不是算，而是确认“题目说的机器数用哪种编码”。

```text
机器数（machine number）：在机器里存的 0/1 串，比如 1100 1100
真值（true value）：      它用带符号的十进制表示的那个数，比如 −52
```

同一个机器数，换一套编码解释，真值就换一个。

```text
0xCC = 1100 1100

无符号：      204
补码：        −52
原码：        −76      （符号位 1，数值位 100 1100 = 76）
反码：        −51      （数值位取反 011 0011 = 51）
移码（偏置 128）：76
```

五种读法，五种答案。

这就是“机器数没有含义”的实证。

再看一个更阴的例子。

```text
0x9A = 1001 1010

当补码读：−102
  按权展开：−128 + 16 + 8 + 2 = −102 ✓
  取反加一：0110 0101 + 1 = 0110 0110 = 102 → −102 ✓

当原码读：−26
  符号位 1，数值位 001 1010 = 26 → −26
```

注意：`0x9A` 是 −26 的原码，也是 −102 的补码。

同一串 0/1，两个真值，都对。

所以做题第一件事永远是看清题目说“按补码解释”还是“按原码解释”。

## 6. 408 怎么考

这一章是 408 数据表示部分的送分题，也是丢分题。

```text
选择题：
  给一个真值，问补码/移码是多少
  给一个补码，问真值是多少
  问 n 位补码/原码的表示范围
  问补码 0 的表示是否唯一
  问符号扩展补什么
  问 −128 有没有原码

综合题：
  与加法器、溢出判断合并出题（03 篇）
  与 IEEE 754 阶码结合出题（04 篇）
```

三条套路。

```text
① 先判符号，再算数值。负数的补码是“取反加一”，顺序不能反。
② 求补码对应的真值，优先用按权展开，最快也最不容易错。
③ 见到范围题，先写 −2^(n−1) ~ 2^(n−1)−1，再代 n。
```

例题（自拟，408 风格）。

```text
某机字长 8 位（含 1 位符号位）。

(1) 写出十进制数 −52 的原码、反码、补码、8 位移码（用十六进制表示）。
(2) 补码 1110 0110 的真值是多少？
(3) 8 位补码能表示的最小负数是多少？它有对应的原码吗？
(4) 把 (1) 得到的 8 位补码符号扩展到 16 位。
```

答案与验算。

```text
(1) 52 = 0011 0100
    原码：符号位 1 + 011 0100  → 1011 0100 = 0xB4
    反码：原码数值位取反        → 1100 1011 = 0xCB
    补码：反码加一              → 1100 1100 = 0xCC
    移码：补码符号位取反        → 0100 1100 = 0x4C

    移码交叉验算：−52 + 128 = 76 = 0x4C ✓

(2) 1110 0110
    按权展开：−128 + 64 + 32 + 4 + 2 = −26
    取反加一核：0001 1001 + 1 = 0001 1010 = 26 → −26 ✓
    真值 = −26

(3) 最小负数 = −2^(8−1) = −128 = 1000 0000
    没有对应的原码。
    因为原码表示 −128 需要符号位 1 加数值位 1000 0000，共 9 位。

(4) 符号扩展：负数补 1
    1100 1100 → 1111 1111 1100 1100 = 0xFFCC

    验算：0xFFCC 无符号是 65484，按 16 位补码解释
          65484 − 65536 = −52 ✓
```

四问四个答案：0xB4 / 0xCB / 0xCC / 0x4C；−26；−128 且无原码；0xFFCC。

再补一个选择题级别的判断。

```text
“8 位补码能表示的整数个数是 256 个”        → 对（−128 … 127）
“8 位原码能表示的整数个数是 256 个”        → 错（只有 255 个，±0 重复）
“补码中 0 的表示唯一”                     → 对（0000 0000）
“补码中 −128 的相反数是 128，可以表示”     → 错（−(−128) 溢出）
```

最后一条很实用：C 语言里对 `INT_MIN` 取负是未定义行为，原因就在这里。

再补一道 16 位的，专练“套公式”。

```text
某机字长 16 位，补码表示。

(1) 表示范围是多少？
(2) −1 的补码，十六进制是什么？
(3) 补码 0x8000 的真值是多少？
(4) 补码 0xFFFF 的真值是多少？

(1) −2¹⁵ ~ 2¹⁵−1，即 −32768 ~ +32767
(2) 负数全 1：0xFFFF
(3) 最低那个负数：−32768
(4) 全 1 = −1
```

四问都在考同一个动作。

```text
见到全 0 → 0
见到全 1 → −1
见到 1 后全 0 → 最小负数
其余 → 按权展开
```

这四个特殊模式，值得单独背下来。

## 7. 真实芯片里长什么样

真实机器只认补码。

```text
x86-64、ARM A64、RISC-V：整数一律补码。
没有哪台主流机器用原码做整数运算。
原码只在教材和浮点尾数里出现。
```

原因在 03 篇会展开：补码让减法变成加法，ALU 只需要一个加法器。

有符号和无符号在硬件上共生。

```text
同一套加减法器，同一批位。
差别只在这几处：
  右移：sar（算术，补符号位） vs shr（逻辑，补 0）
  比较：有符号用 SF≠OF，无符号用 CF
  除法：idiv vs div
  扩展：符号扩展 vs 零扩展
```

乘法也一样：x86 的 `imul` 和 `mul` 走同一套阵列乘法器，只在最后判断结果的高半部分是不是符号扩展。

浮点阶码用的是移码。

```text
IEEE 754 单精度阶码 8 位，偏置 127
  存的是 e + 127，不是 e 本身
双精度阶码 11 位，偏置 1023
```

为什么阶码用移码而不是补码。

```text
移码保持大小顺序：把 0/1 串当无符号数比较，大小关系就是真值的大小关系。
补码不行：补码的 1111 1111 是无符号最大，真值却是 −1。

浮点比较时，先比阶码。
阶码能用整数比较器直接比，硬件省一大块。
```

字符编码在芯片里更靠外。

```text
ASCII 是 UTF-8 的子集，UTF-8 是变长编码：
  ASCII 字符 1 字节
  拉丁/希腊字母 2 字节
  汉字 3 字节
  少数符号 4 字节
```

所以“一个汉字占 2 字节”这句话只在 GBK 里对，在 UTF-8 里是 3 字节。

校验码在内存侧用的是 ECC。

```text
（简化示意）
普通内存条：64 位数据
ECC 内存条：64 位数据 + 8 位校验位 = 72 位
  用汉明码之类的方案，能纠正 1 位错、检出 2 位错
```

这就是服务器内存贵一截的原因：多的那 8 颗颗粒不是容量，是可靠性。

## 8. 原码与反码

先问：机器又不用原码，为什么还要学它？
因为原码最接近人的直觉，是理解后面两种编码的起点。
补码那条“取反加一”的规则，本质是在给原码的两个缺陷打补丁；不知道缺陷是什么，规则就只能死记。
而且 408 会让你把同一个数写成四种编码，原码是第一步。

**原码：最高位符号，其余位是绝对值。**

```text
+52 → 0 011 0100
−52 → 1 011 0100

n 位原码范围：−(2^(n−1) − 1) ~ +(2^(n−1) − 1)
8 位：−127 ~ +127
```

直观，好读，人一眼就能看懂。

但它有两个致命缺陷。

```text
① 0 有两种写法
   +0 = 0000 0000
   −0 = 1000 0000
   硬件要判两次零，浪费一个编码。

② 加法器不能直接用
   原码做加法要先比绝对值、再定符号、可能还要做减法。
   电路复杂度翻倍。
```

第②条值得展开，因为它就是补码存在的理由。

```text
原码加法要分四种情况：

  同号相加 → 绝对值相加，符号照抄          （简单）
  异号相加 → 比较绝对值，大减小，符号取大的 （复杂）

举例：
  (+5) + (−3)：|5| > |3|，符号取正，5 − 3 = +2
  (+5) + (−7)：|5| < |7|，符号取负，7 − 5 = −2

要做出这三步（比较、相减、定符号），
硬件需要一条比较器、一条减法路径、一套符号选择逻辑。
```

同样的四种情况，补码只用一个加法器就全接住了。

```text
  0000 0101   (+5)
+ 1111 1101   (−3)
-----------
  0000 0010 = +2 ✓

  0000 0101   (+5)
+ 1111 1001   (−7)
-----------
  1111 1110 = −2 ✓
```

这就是“一个加法器替代四条路径”的实际含义。

**反码：负数按位取反（符号位不动）。**

```text
+52 → 0 011 0100
−52 → 1 100 1011   （数值位 011 0100 取反 = 100 1011）

n 位反码范围：同原码，−127 ~ +127
```

反码解决了一部分问题。

```text
反码的加法：符号位直接参与运算，进位回卷到最低位（循环进位）
  7 + (−5)：
    0000 0111
  + 1111 1010   (−5 的反码)
  -----------
    1 0000 0001
    进位回卷 +1
  -----------
    0000 0010 = 2 ✓
```

能算了，但还是要处理循环进位。

而且零还是两个。

```text
+0 = 0000 0000
−0 = 1111 1111
```

反码是通向补码的中间站。

它值一提，是因为 408 会让你写它，也可能拿它当干扰项。

真正常用的是下一节。

## 9. 补码：取反加一背后的模运算

补码的定义只有一句。

```text
正数的补码 = 它自己
负数的补码 = 对应正数按位取反，末位加一
```

例子。

```text
+52 → 0011 0100
−52 → 取反 1100 1011，加一 1100 1100 = 0xCC
```

一步一步手算 −52 的补码，每一步都说清为什么：

```text
① 先写 +52 的二进制：
   52 = 32 + 16 + 4
   权重 128 64 32 16 8 4 2 1 里，32、16、4 这三位是 1
   → 0011 0100

② 8 位全部取反（含符号位）：
   0011 0100 → 1100 1011
   取反就是每一位 0 变 1、1 变 0

③ 末位加一：
   1100 1011 + 1 = 1100 1100
   只加最低位，有进位就照常往左传

④ 检查：
   符号位是 1，确实是负数
   按权展开验算：−128 + 64 + 8 + 4 = −52 ✓
```

四步里只有第③步容易出错：加一加的是最低位，不是符号位。

记住“取反加一”，能做题。

但不知道为什么，遇到 “[−x]补 怎么求” 就容易乱。

底层是模运算。

```text
8 位寄存器的模是 2^8 = 256。
在模 256 的意义下，−52 和 204 是同一个数：
  −52 ≡ 204 (mod 256)
  204 = 1100 1100
所以 −52 的补码就是 204 的二进制。

验算：−52 + 256 = 204 ✓
换句话说，204 就是 −52 在模 256 下的另一个名字。
```

这个“另一个名字”的说法，能解释很多看起来别扭的地方。

```text
减法 3 − 5：相当于 3 + (−5) = 3 + 251 = 254 ≡ −2 (mod 256)
结果 1111 1110，读作补码就是 −2 ✓
```

这个视角解释了三件事。

```text
① 为什么减法能变加法
   A − B = A + (256 − B) = A + [−B]补，溢出位自然丢掉。
   硬件不需要减法器，只需要加法器 + 取反 + 进位输入 1。

② 为什么 [−x]补 是“全部位取反加一”
   x + (~x) = 1111 1111 = 255
   x + (~x) + 1 = 256 ≡ 0 (mod 256)
   所以 (~x) + 1 就是 −x。

③ 为什么补码的 0 唯一
   0000 0000 取反加一还是 0000 0000。
```

性质要背住这几条。

```text
[x]补 + [y]补 = [x + y]补     （mod 2^n，符号位参与运算）
[x − y]补 = [x]补 + [−y]补
[−y]补：把 [y]补 全部位（含符号位）取反，末位加一

算术右移一位 = 除以 2 向下取整（补符号位）
算术左移一位 = 乘以 2（可能溢出）
```

算一遍。

```text
7 + (−5)：
   0000 0111   (7)
 + 1111 1011   (−5)
 -----------
 1 0000 0010
 丢掉最高进位 → 0000 0010 = 2 ✓

5 − 7：
   0000 0101   (5)
 + 1111 1001   (−7)
 -----------
   1111 1110 = −2 ✓
```

两个都对。

注意那个“丢掉最高进位”。

在模 256 里，它是理所应当的，不是特殊处理。

## 10. 补码的表示范围

这是 408 最爱考的一行。

```text
n 位补码的范围：
  −2^(n−1)  ~  2^(n−1) − 1

n = 8：  −128 ~ +127
n = 16： −32768 ~ +32767
n = 32： −2147483648 ~ +2147483647
n = 64： −9223372036854775808 ~ +9223372036854775807
```

四种编码的范围对照。

| 编码 | 8 位范围 | 不同值的个数 | 零的写法 |
|---|---|---|---|
| 原码 | −127 ~ +127 | 255 | 2 种（±0） |
| 反码 | −127 ~ +127 | 255 | 2 种（±0） |
| 补码 | −128 ~ +127 | 256 | 1 种 |
| 移码 | −128 ~ +127 | 256 | 1 种 |

规律一眼可见。

```text
原码、反码：对称，缺一个值，因为零占了两份
补码、移码：不对称，负数比正数多一个
```

不对称是有代价的。

```text
最小的负数 −128，它的相反数 128 表示不出来。
所以 −(−128) 会溢出。

C 里对 INT_MIN 取负、取绝对值，都是未定义行为。
x86 上 `neg` 一个 0x80000000 会得到 0x80000000，并置 OF = 1。
```

为什么是这个范围，用按权展开看最清楚。

```text
把补码看成有权重的二进制数：
  最高位权重 = −2^(n−1)
  其余位权重 = +2^(n−2) … +2^0

8 位：
  1000 0000 = −128 + 0 = −128       ← 最小
  1111 1111 = −128 + 127 = −1
  0000 0000 = 0
  0111 1111 = 0 + 127 = +127        ← 最大
```

按权展开这个方法，比“取反加一”快得多。

408 那种“给一个补码求真值”的题，用它两秒钟出结果。

代入几个 n 看一遍。

```text
n = 4：  −2³ ~ 2³−1    =  −8 ~ +7         共 16 个
n = 8：  −2⁷ ~ 2⁷−1    =  −128 ~ +127     共 256 个
n = 16： −2¹⁵ ~ 2¹⁵−1   =  −32768 ~ +32767 共 65536 个
n = 32： −2³¹ ~ 2³¹−1   =  −2147483648 ~ +2147483647
```

这几个数在代码里有名字。

```text
INT8_MIN  = −128
INT16_MIN = −32768
INT32_MIN = −2147483648
INT64_MIN = −9223372036854775808
```

C 里要写 `-2147483647 - 1` 才能安全表示 INT32_MIN。

因为字面量 `2147483648` 已经超出 int 的范围，会先被当成更大的类型。

这是范围不对称带来的第一个实际麻烦。

## 11. 移码与符号扩展

先问：已经有了补码，为什么还要再造一个移码？
因为补码有一处致命的不方便：把 0/1 串当无符号数比大小时，顺序是错的。
补码的 1111 1111 当无符号读是 255（最大），真值却是 −1。
浮点数比较大小要先比阶码，如果阶码用补码，每次比较都得先看符号位、再修正结论。
移码把这个麻烦一次消掉：编码的大小顺序，就是真值的大小顺序。

**移码：把真值加上一个偏置，让所有数都变成非负。**

```text
[n 位移码] = 真值 + 2^(n−1)

8 位例子（偏置 128）：
  −128 → 0     = 0000 0000
  −52  → 76    = 0100 1100
  0    → 128   = 1000 0000
  +127 → 255   = 1111 1111
```

它和补码只差一步。

```text
移码 = 补码的符号位取反
补码 = 移码的符号位取反

−52：补码 1100 1100 → 移码 0100 1100 ✓
```

移码的用途很窄，但很关键：浮点数的阶码。

```text
IEEE 754 单精度：阶码 8 位，偏置 127
IEEE 754 双精度：阶码 11 位，偏置 1023
```

为什么阶码非用移码不可。

```text
因为浮点比较要先比阶码。
移码把真值映射成无符号顺序，硬件用整数比较器直接比就行。
补码不行，符号位会让无符号比较的结果反过来。
```

演示一下“顺序对不对”。

```text
三个数：−1、0、+1

补码：  1111 1111、0000 0000、0000 0001
        当无符号比：255 > 0 < 1     ✗ 顺序乱了

移码：  0111 1111、1000 0000、1000 0001
        当无符号比：127 < 128 < 129  ✓ 顺序正确
```

一行比较器就能解决的事，不值得为它加符号判断逻辑。

**符号扩展：把 n 位有符号数变宽，补符号位。**

```text
8 位 −52：1100 1100

扩展到 16 位（补 1）：1111 1111 1100 1100 = 0xFFCC
扩展到 32 位（补 1）：1111 … 1111 1100 1100 = 0xFFFFFFCC

8 位 +52：0011 0100
扩展到 16 位（补 0）：0000 0000 0011 0100 = 0x0034
```

规则一句话。

```text
有符号数：补符号位（正数补 0，负数补 1）
无符号数：补 0（零扩展，zero extension）
```

为什么补符号位对。

```text
用按权展开验：8 位 1100 1100 = −128 + 76 = −52
16 位 1111 1111 1100 1100
  = −32768 + 16384 + 8192 + 4096 + 2048 + 1024 + 512 + 256 + 128 + 64 + 8 + 4
  = −32768 + 32716 = −52 ✓
```

新的高 8 位（bit15 ~ bit8）合起来是 −32768 + 32512 = −256。
低 8 位是 0xCC = 204。
−256 + 204 = −52 ✓

补 0 就错了：`0000 0000 1100 1100` = 204，符号都变了。

408 会把这个错项放进去：`把 8 位补码扩展成 16 位时，高 8 位补 0` —— 错。

## 12. 四种编码对照：给一个数写四遍

把前面几节合成一张表。

| 真值 | 原码 | 反码 | 补码 | 移码（偏置 128） |
|---|---|---|---|---|
| +52 | 0x34 | 0x34 | 0x34 | 0xB4 |
| −52 | 0xB4 | 0xCB | 0xCC | 0x4C |
| 0 | 0x00 | 0x00 | 0x00 | 0x80 |
| −1 | 0x81 | 0xFE | 0xFF | 0x7F |
| −128 | 无 | 无 | 0x80 | 0x00 |
| +127 | 0x7F | 0x7F | 0x7F | 0xFF |

逐个验算（8 位）。

```text
+52：52 = 0011 0100，四种编码正数全相同 = 0x34
     移码 = 52 + 128 = 180 = 0xB4 ✓

−52：原码 0xB4，反码 0xCB，补码 0xCC，移码 0x4C ✓

0：  原码 0x00（+0），补码 0x00，移码 = 0 + 128 = 128 = 0x80 ✓

−1： 原码 1000 0001 = 0x81
     反码 1111 1110 = 0xFE
     补码 1111 1111 = 0xFF
     移码 = −1 + 128 = 127 = 0x7F ✓
     核：补码 0xFF 符号位取反 = 0x7F ✓

−128：补码 1000 0000 = 0x80，移码 = 0x00
      原码/反码不存在

+127：四种编码（除移码）= 0111 1111 = 0x7F
      移码 = 127 + 128 = 255 = 0xFF ✓
```

手工写四种编码的标准流程。

```text
第一步：算出该数的绝对值二进制（8 位）
第二步：符号位定 0 或 1，得原码
第三步：若为负数，数值位取反 → 反码
第四步：反码加一 → 补码
第五步：补码符号位取反 → 移码
```

五步，四行结果。

考试时按这个顺序写，不会乱。

再练一个，专挑容易翻车的 −100。

```text
x = −100

100 = 0110 0100

原码：符号位 1，数值位 110 0100  → 1110 0100 = 0xE4
反码：数值位取反                 → 1001 1011 = 0x9B
补码：反码加一                   → 1001 1100 = 0x9C
移码：补码符号位取反             → 0001 1100 = 0x1C

验算移码：−100 + 128 = 28 = 0x1C ✓
验算补码：按权展开 1001 1100
  = −128 + 16 + 8 + 4 = −100 ✓
```

三个地方最容易错。

```text
① 反码取反时不包含符号位
   1110 0100 的数值位是 110 0100，
   取反成 001 1011，拼上符号位 1 → 1001 1011 ✓
   若把符号位也取反，得到 0001 1011 = +27，全错。

② 补码加一时要向数值位加，不进符号位
   1001 1011 + 1 = 1001 1100（低 7 位加了 1）

③ 移码是“补码符号位取反”，不是“补码取反”
   0x9C → 0x1C，只翻最高位。
```

## 13. 反直觉点：−128 是 0 让出来的

现在回答最开头那个问题。

为什么 8 位补码能到 −128，8 位原码只能到 −127。

答案不是“补码更先进”。

答案是**数了一遍数**。

```text
8 位一共 256 种 0/1 组合。
这 256 种组合能表示多少个不同的整数，取决于编码怎么分配。
```

原码的分配方式。

```text
 0 000 0000  →  +0
 1 000 0000  →  −0     ← 同一个数，占了两个编码
 0 111 1111  →  +127
 1 111 1111  →  −127

正数区：0 ~ 127，共 128 个编码
负数区：−127 ~ −0，共 128 个编码，其中两个编码都表示 0
→ 实际能表示的不同整数 = 128 + 127 = 255 个
```

256 个编码，只装下 255 个数。

浪费的那一个，就是 −0。

补码的分配方式。

```text
补码里 0 只有一种写法：0000 0000。
原来分配给 −0 的那个编码 1000 0000，空出来了。

空出来的编码给谁？
顺着数轴的下一格：−128。

于是：
  0000 0000 ~ 0111 1111  →  0 ~ +127
  1000 0000 ~ 1111 1111  →  −128 ~ −1
  共 128 + 128 = 256 个，一个不浪费
```

**这就是那个反直觉的点：**

```text
补码多出来的 −128，
不是因为它“能表示更大的负数”，
而是因为“0 不再需要两种写法”，腾出了一个编码。

−128 是 −0 让出来的位置。
```

这个视角能顺手解释一串现象。

```text
① 补码范围为什么不对称：−128 ~ +127，负数多一个。
② 为什么 −(−128) 会溢出：它的相反数 +128 没有编码。
③ 为什么原码要浪费一个编码：因为它坚持保留“符号 + 绝对值”的对称性。
④ 为什么移码也是 −128 ~ +127：移码就是补码符号位取反，一一对应。
```

还有一个推论。

```text
n 位补码能表示 2^n 个不同的整数，范围是 −2^(n−1) ~ 2^(n−1)−1。
n 位原码只能表示 2^n − 1 个不同的整数。
所以浮点尾数用原码时，表示范围会小一点点（实际可忽略，因为尾数只要精度）。
```

一片编码位置，一行范围公式。

背后是一次会计。

把账再算细一点。

```text
8 位编码总数                       256

原码：正数 128 个（0 ~ +127）
      负数 128 个（−0 ~ −127）
      但 −0 就是 0，重复 → 有效值 255 个

补码：正数 128 个（0 ~ +127）
      负数 128 个（−128 ~ −1）
      无重复 → 有效值 256 个

多出来的那一个，正是 1000 0000
——它在原码里是 −0，在补码里是 −128。
```

同一串 0/1，两种身份。

中间隔着的就是那句“0 只需要一种写法”。

## 14. 容易混淆的点

七组，逐个拆。

```text
① 取反 vs 取反加一
   [−x]补 = [x]补 全部位取反 + 1
   只取反不加以，得到的是 [−x]反，不是补码。
   差的那一个 1，就是模运算里 256 − 255 = 1。
```

```text
② 负数补码转真值：取反加一 vs 减一再取反
   两种做法都对，结果一样。
   1110 0110 → 取反加一 = 0001 1010 = 26 → −26
   1110 0110 → 减一 = 1110 0101，取反 = 0001 1010 = 26 → −26
   推荐用按权展开，一步到位：−128+64+32+4+2 = −26
```

```text
③ 符号扩展 vs 零扩展
   有符号 → 补符号位
   无符号 → 补 0
   弄反了，正数没事，负数全错。
```

```text
④ 移码偏置是 2^(n−1) 还是 2^(n−1)−1
   通用的 n 位移码偏置是 2^(n−1)，8 位就是 128。
   IEEE 754 单精度的 127 是规格化数的偏置，不是 8 位移码的通用偏置。
   两个数差 1，别混。
```

这一条要特别小心。

```text
通用移码：真值 + 128，范围 0000 0000 ~ 1111 1111 对应 −128 ~ +127
IEEE 754：阶码字段 = e + 127，e 的实际范围 −126 ~ +127
          0000 0000 和 1111 1111 被特殊值占用（非规格化数、∞/NaN）
```

```text
⑤ 反码的两个零
   +0 = 0000 0000，−0 = 1111 1111
   补码只有一个 0：0000 0000
```

```text
⑥ 原码的 −0 与补码的 −128 是同一个编码
   1000 0000
   在原码里表示 −0（数值上等于 0）
   在补码里表示 −128
   同一串 0/1，两个完全不同的真值。
```

```text
⑦ BCD 的 0x47 与十六进制的 0x47
   BCD 0x47 = 十进制 47
   十六进制 0x47 = 十进制 71
   差 24，因为 BCD 的 4 位一节只用了 10 个编码。
```

```text
⑧ “补码求相反数”与“补码求负数编码”是同一件事
   [−x]补 = 把 [x]补 全部位取反加一
   注意是全部位，包括符号位；而“求负数补码”时符号位外的取反不翻符号。
   两者不矛盾：
     知道 +52 求 −52 → 可以用全部位取反加一，也可以先写原码再转
     结果都是 0xCC
```

```text
⑨ 补码的符号位参与运算，原码的符号位不参与
   补码：把符号位当普通位一起加，进位丢掉
   原码：符号位单独处理，只对数值位做算术
   这是两种编码最本质的区别，也是补码省硬件的根源。
```

## 15. 小结

这一篇的骨架是四层。

**第一层：进位制。**

```text
十进制 ↔ 二进制：除基取余 / 按权展开
二 ↔ 八：3 位一组
二 ↔ 十六：4 位一组
小数部分：乘基取整，可能无限循环（0.1 就是）
```

**第二层：人机之间的编码。**

```text
BCD：4 位存 1 位十进制，0x47 表示 47
ASCII：'0' = 0x30，'a' − 'A' = 0x20
校验：奇偶查一位错，二维奇偶能定位，汉明码能纠错
```

**第三层：机器数与真值。**

```text
同一个 0xCC：无符号 204、补码 −52、原码 −76、反码 −51、移码 76
机器数没有含义，含义由编码约定给出。
```

**第四层：四种定点编码。**

```text
原码：符号 + 绝对值，范围 −127 ~ +127，两个零
反码：负数按位取反，范围同上，两个零
补码：取反加一，范围 −128 ~ +127，一个零
移码：补码符号位取反，范围 −128 ~ +127，用作阶码

n 位补码范围：−2^(n−1) ~ 2^(n−1) − 1
```

一句必须带走的话。

```text
补码多出来的 −128，是 −0 让出来的位置。
```
