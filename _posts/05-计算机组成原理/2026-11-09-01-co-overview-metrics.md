两台机器摆在桌上。

```text
机器 A：主频 3.0 GHz，跑同一段程序用 1.8 秒
机器 B：主频 2.4 GHz，跑同一段程序用 1.2 秒
```

主频高的那台，慢了 50%。

广告不会告诉你这件事。

广告只会说 GHz。

**主频是心跳，不是速度。**

心跳快，可能每一步都很小。

心跳慢，可能一步顶别人两步。

这一篇把“快”这个字拆开，拆到能算为止。

## 1. 三种「快」：响应时间、吞吐量、执行时间

日常说“这台机器快”，至少混了三个概念。

```text
响应时间（response time）
  一个任务从提交到完成，花了多久。
  打游戏看帧率、点开软件看转圈，都是它。

吞吐量（throughput）
  单位时间内完成了多少任务。
  服务器看 QPS，编译器看每小时编译多少个文件。

CPU 执行时间（CPU time）
  程序真正占着 CPU 的那段时间。
  不含等 I/O、不含被操作系统换出。
```

408 里说“性能”，多数场合指第三个。

原因很实际：前两个跟操作系统、磁盘、网络都有关系，只有 CPU 时间能被一条公式算出来。

三者还会互相打架。

```text
流水线加深 → 吞吐量上升，单条指令的延迟反而变大。
多核         → 吞吐量翻倍，单线程响应时间几乎不变。
Cache 变大   → 平均响应时间下降，芯片面积和功耗上升。
```

所以“哪个快”必须先问一句：比的是什么。

举个例子，把区别摆具体。

```text
一个 Web 服务，单个请求处理 5 ms。

单核串行跑：        吞吐量约 200 请求/秒，响应时间 5 ms
流水线重叠三段：    吞吐量约 300 请求/秒，响应时间可能变 5.6 ms
加到四个核：        吞吐量约 800 请求/秒，单请求还是 5 ms
```

要吞吐量就加核，要低延迟就抬单核频率、加大 Cache。

这也是为什么跑分软件要分开看。

```text
单核分   → 衡量响应时间
多核分   → 衡量吞吐量
两者经常不同向变化，甚至互相拖后腿。
```

这篇后面所有公式，比的都是 CPU 执行时间。

## 2. 主频、时钟周期与 CPI

CPU 里有一个时钟，像节拍器。

```text
时钟周期 T：一个节拍的长度，单位 ns
主频 f = 1 / T：每秒多少个节拍，单位 GHz
```

换算要背下来，不然后面所有题都会差三个数量级。

```text
1 GHz  → T = 1 ns
2 GHz  → T = 0.5 ns
2.5 GHz → T = 0.4 ns
3 GHz  → T ≈ 0.333 ns
4 GHz  → T = 0.25 ns
```

一个节拍里，CPU 干不完一条指令。

一条指令要拆成取指、译码、执行、访存、写回几步，每步占一个或几个节拍。

于是有了 CPI。

```text
CPI（cycles per instruction）
  平均执行一条指令需要多少个时钟周期。
  CPI = 程序总时钟周期数 / 程序指令条数
```

CPI 是个平均值，不同类型的指令 CPI 不同。

```text
一条整数加法：1 个周期
一次 L1 命中读内存：4 个周期
一次 L2 命中：12 个周期
一次主存访问：200 个周期上下
一次分支预测失败：15 个周期上下
```

程序里各类指令混着来，平均 CPI 要按比例加权。

```text
CPI = Σ ( 第 i 类指令的 CPI × 第 i 类指令占比 )
```

举个能算的。

```text
某程序指令分布：
  ALU 类      60%   CPI = 1
  取数/存数类  30%   CPI = 4
  转移类      10%   CPI = 2

CPI = 0.6×1 + 0.3×4 + 0.1×2
    = 0.6 + 1.2 + 0.2
    = 2.0
```

平均一条指令 2 个节拍。

CPI 的倒数是 IPC。

```text
IPC（instructions per cycle）= 1 / CPI
```

上面那个例子 IPC = 0.5，意思是平均每个节拍退休半条指令。

现代超标量处理器一个节拍能发射 4 条、6 条指令，理想 IPC 大于 1，CPI 小于 1。

所以看到“CPI = 0.25”别惊讶，那是 4 发射机器的理想值。

## 3. CPU 执行时间 = 指令数 × CPI × 时钟周期

这是整章最重要的一行。

```text
CPU 执行时间 = 指令条数 × CPI × 时钟周期
             = 指令条数 × CPI / 主频
```

三个因子，缺一不可。

```text
指令条数 N   由程序、编译器、指令集决定
CPI          由指令集、微结构、Cache、流水线决定
时钟周期 T   由工艺、电路、流水级数决定
```

这三个量不是独立的。

改一个，另外两个常常跟着动。

```text
主频拉高     → 流水级切得更细 → 分支预测失败代价按周期算变大 → CPI 上升
CPI 降低     → 通常靠更复杂的硬件 → 关键路径变长 → 主频上不去
指令数减少   → 用更复杂的指令（CISC 风格）→ 单条指令 CPI 变大
```

所以优化性能从来不是调一个旋钮。

拿一组具体数走一遍。

```text
原始：N = 1×10^9 条，CPI = 2.0，f = 2 GHz
T = 1×10^9 × 2.0 / 2×10^9 = 1.00 秒
```

三种优化，三种结果。

```text
优化 A：主频提到 2.5 GHz，但 CPI 涨到 2.4
T = 1×10^9 × 2.4 / 2.5×10^9 = 0.96 秒     提升 4%

优化 B：CPI 降到 1.5，主频不变
T = 1×10^9 × 1.5 / 2×10^9 = 0.75 秒       提升 25%

优化 C：指令数降 20%，但 CPI 涨到 2.5
T = 0.8×10^9 × 2.5 / 2×10^9 = 1.00 秒     提升 0%
```

优化 A 就是真实世界里“堆频率”的典型收益：个位数。

优化 C 就是“编译优化反而变慢”的典型原因：指令少了，CPI 涨了，正好抵消。

这三个数都验算过：0.8 × 2.5 = 2.0，除以 2 正好 1.0。

一秒不多，一秒不少。

## 4. MIPS、MFLOPS 与字长

三个因子之外，还有一批“每秒多少”的指标。

```text
MIPS（million instructions per second）
  MIPS = 指令条数 / (执行时间 × 10^6)
       = 主频(MHz) / CPI
       = 主频(GHz) × 1000 / CPI
```

用上一节的数：主频 2 GHz、CPI 2.0。

```text
MIPS = 2000 / 2.0 = 1000
```

每秒十亿条指令。

MIPS 有三个硬伤。

```text
① 不同指令集的“一条指令”干的活不一样，不能横比。
② 只看条数，不看每条指令有多复杂。
③ 不反映浮点能力，也不反映 I/O 能力。
```

所以又有了 MFLOPS。

```text
MFLOPS = 浮点运算次数 / (执行时间 × 10^6)
GFLOPS = 1000 MFLOPS
TFLOPS = 1000 GFLOPS
```

注意分子是“浮点运算次数”，不是“指令条数”。

一条向量指令可能一次做 8 次浮点乘法，那要算 8 次。

```text
某程序 0.25 秒内完成 2×10^8 次浮点运算
MFLOPS = 2×10^8 / (0.25 × 10^6) = 800
```

字长是另一个常被问错的量。

```text
机器字长：CPU 一次能处理的二进制位数
          = 通用寄存器宽度 = ALU 位宽，常见 32 / 64

指令字长：一条指令占的二进制位数，可以等于、大于、小于机器字长
存储字长：一个存储单元存多少位
```

三者可以不一样。

x86 的机器字长早就 64 位了，指令字长还是变长的，从 1 字节到 15 字节都有。

MIPS32 机器字长 32 位，指令字长也固定 32 位。

字长决定了两件事。

```text
① 一次运算能处理的数据范围 → 影响整数表示范围与浮点精度
② 地址空间的宽度 → 32 位地址最多寻址 2^32 B = 4 GB
```

最后一行是 408 的高频点：按字节编址、地址线 32 根，主存最大 4 GB。

想上 4 GB 以上，地址线就得加宽，这就是 64 位取代 32 位的直接原因之一。

拿一道具体的来算。

```text
按字节编址，地址线 32 根：
  可寻址单元数 = 2³² = 4G 个
  每单元 1 B  →  主存最大 4 GB

按字编址，字长 32 位（4 B），地址线仍是 32 根：
  可寻址单元数 = 2³² = 4G 个
  每单元 4 B  →  主存最大 16 GB
```

同样的地址位数，编址单位一变，容量差四倍。

408 的坑就在这一句：题目写“按字节编址”还是“按字编址”。

## 5. 冯·诺依曼结构：五大部件

先把发展史压成一句话。

```text
1946 年 ENIAC 用电子管做算术，靠插线板编程；
1945 年冯·诺依曼在 EDVAC 报告里提出“存储程序”，
计算机从此把程序和数据一起放进存储器，并按地址自动执行。
```

之后四代，换的都是器件。

```text
第一代  电子管        1946–1957
第二代  晶体管        1958–1964
第三代  中小规模集成电路 1965–1971
第四代  大规模/超大规模集成电路 1972 至今
```

器件换了四茬，结构没换。

冯·诺依曼结构到今天还是主流，原因就在下面这五个部件。

```text
        ┌──────────────────────────────────────┐
        │            存储器（Memory）            │
        │        指令和数据都存在这里            │
        └───┬──────────────┬──────────────┬────┘
            │              │              │
       ┌────┴────┐    ┌────┴────┐    ┌────┴────┐
       │ 运算器   │    │ 控制器   │    │  输入    │
       │  ALU    │←──→│   CU    │←───│  设备    │
       └────┬────┘    └────┬────┘    └─────────┘
            │              │
            │         ┌────┴────┐
            └────────→│  输出    │
                      │  设备    │
                      └─────────┘
```

五大部件：运算器、控制器、存储器、输入设备、输出设备。

现代机器把运算器和控制器做在一块芯片上，合称 CPU。

输入输出合称 I/O。

408 常考的那五条特点，逐条落地。

```text
① 计算机由五大部件组成。
② 指令和数据以同等地位存于存储器，可按地址访问。
③ 指令和数据都用二进制表示。
④ 指令由操作码和地址码组成，操作码表示做什么，地址码表示对谁做。
⑤ 指令在存储器内按顺序存放，通常顺序执行，特定条件下可跳转。
```

注意第②条里的“同等地位”四个字。

它不是修辞，是物理事实。

在存储器眼里，指令和数据都是一串 0 和 1，没有标签区分。

区分只发生在 CPU 取指的那一瞬间：PC 指过去读出来的，就当指令用。

五条特点里，第②条和第④条最容易被出成干扰项。

```text
“指令和数据一样，都以二进制形式存放在存储器中”   → 对
“指令和数据分两个存储区域分别存放”               → 错（那是哈佛结构）
“指令由操作码和地址码组成”                       → 对
“指令在存储器中按执行顺序连续存放”               → 对
“CPU 能自动区分取出的是指令还是数据”             → 对，但区分靠时序，不靠标记
```

最后一条要小心措辞。

硬件里没有“这是指令位”这种标记。

区分永远发生在时序上：取指周期从 PC 指向的单元读出来的，算指令；执行周期按地址读出来的，算数据。

这一点带来一个著名的性能问题：冯·诺依曼瓶颈。

```text
CPU 和存储器之间只有一条通路。
取指令要占用它，取数据也要占用它。
两者不能同时进行。
```

CPU 越快，这条通路越像瓶颈。

后面第 08 篇讲的 Cache、第 11 篇讲的虚拟存储，本质都在给这条通路减压。

## 6. 408 怎么考

这章的题型很固定。

```text
选择题：
  给主频和 CPI，问 MIPS
  给指令分布和各类 CPI，问平均 CPI 或执行时间
  判断冯·诺依曼结构的特点（哪一条不对）
  问“字长”指什么、32 位地址空间多大

综合题：
  偶尔与流水线、Cache 合并出题，单独出大题的概率低
```

三条套路。

```text
① 见到“主频翻倍”，先找 CPI 有没有跟着变。
② 见到“平均 CPI”，一定先乘占比再求和，别直接算术平均。
③ 见到“每秒多少条指令”，检查分母是 10^6 还是 10^9。
```

例题（自拟，408 风格）。

```text
某计算机主频 2 GHz。某程序共 1×10^9 条指令：
  ALU 类占 60%，CPI = 1
  取数/存数类占 30%，CPI = 4
  转移类占 10%，CPI = 2

(1) 求平均 CPI、MIPS、程序执行时间。
(2) 编译器优化后指令数减少 20%，CPI 升到 2.5，
    主频不变，执行时间变成多少？变快了吗？
(3) 若要在 (2) 的基础上再快一倍，主频要到多少？
```

答案与验算。

```text
(1) CPI = 0.6×1 + 0.3×4 + 0.1×2
        = 0.6 + 1.2 + 0.2 = 2.0

    MIPS = 2000 / 2.0 = 1000

    T = 1×10^9 × 2.0 / 2×10^9 = 1.00 秒

(2) N = 0.8×10^9，CPI = 2.5
    T = 0.8×10^9 × 2.5 / 2×10^9 = 1.00 秒
    没变快——指令少了 20%，CPI 涨了 25%，正好打平。

(3) 需要的周期数 = 0.8×10^9 × 2.5 = 2×10^9 个
    T = 2×10^9 / f = 0.5 秒
    → f = 4 GHz
```

三个数交叉验算过。

第(2)问周期数 2×10^9 个，第(3)问要半秒跑完，4 GHz 正好一秒 40 亿个周期。

还有两个常考的判断题。

```text
“主频越高，程序执行越快”          → 错，CPI 可能同步变大
“指令和数据在存储器中形式上无区别”  → 对，靠 PC 区分
```

再补一道最小的计算题，专门练单位。

```text
某机主频 3 GHz，CPI = 1.5。

MIPS = 3000 / 1.5 = 2000

执行 10⁶ 条指令的时间：
  周期数 = 10⁶ × 1.5 = 1.5×10⁶ 个
  T = 1.5×10⁶ / 3×10⁹ = 0.5×10⁻³ s = 0.5 ms
```

单位换算错了，答案就错十倍。

```text
主频用 GHz → MIPS 公式里要用 ×1000 换成 MHz
时间用秒算，最后再换 ms 或 μs
1 ms = 1000 μs = 10⁶ ns
```

## 7. 真实芯片里长什么样

真实的 x86 和 ARM 芯片，CPI 早就不接近 1 了，有的还小于 1。

```text
（简化示意，不展开具体型号微结构）
现代高性能核心：每周期取指 4–6 条，译码 4–6 条，
                发射 4–8 个微操作，退休 4–8 条
→ 理想 IPC 可以是 3–5，即 CPI 约 0.2–0.35
```

这就是为什么“主频 3 GHz 的老架构”能打“主频 4 GHz 的新架构”。

也解释了第 1 节那两台机器的差距：CPI 差一倍，主频差 25%，结果慢 50%。

x86 和 ARM 在这一点上走了两条路。

```text
x86：指令变长（1–15 字节），译码复杂，前端压力大，
     靠微操作缓存（uop cache）把热点指令缓存起来降低取指开销。

ARM：A64 指令定长 4 字节，译码简单，
     取指单元规整，适合低功耗宽发射。
```

浮点能力看 FPU 和 SIMD。

```text
SSE：128 位，一条指令 4 个单精度
AVX2：256 位，一条指令 8 个单精度
AVX-512：512 位，一条指令 16 个单精度
ARM NEON：128 位，4 个单精度
ARM SVE/SVE2：向量长度可变（128–2048 位）
```

一条 AVX-512 乘法指令，理论峰值就是标量的 16 倍。

这就是 MFLOPS 和 GFLOPS 这两个指标存在的意义：它们衡量的往往不是标量代码，而是向量化之后的吞吐。

还有一个绕不过去的事实：频率墙。

```text
2005 年前后，桌面 CPU 主频停在 3–5 GHz 区间，
再往上提，功耗按频率的三次方级别上涨，散热顶不住。
之后性能增长主要靠：多核、SIMD 加宽、IPC 提升、专用加速器。
```

这也是 408 那套“三因子”模型的现实意义。

主频这条路走不通了，就只能去动指令数和 CPI。

有个对照数字能说明问题。

```text
2000 年：Pentium 4 冲到 3.8 GHz，功耗约 115 W
2006 年：Core 2 回到 2.4 GHz，单线程反而更快
今天：桌面 CPU 睿频 5~6 GHz，同频性能是 2000 年的十几倍
```

二十多年里，频率涨了不到一倍。

性能涨了十几倍。

涨的都不是主频，是 CPI 和指令数。

## 8. 存储程序：指令和数据同等存储

“存储程序”这四个字，展开是三条约定。

```text
① 程序（指令序列）和数据都存在同一个存储器里。
② 两者都用二进制表示，形式上没有区别。
③ 靠地址区分，靠 PC 顺序取指，靠跳转指令改变顺序。
```

这三条带来的好处，是计算机变成通用机器。

```text
换一个程序，不用改电路。
程序可以被加载、被编译、被复制、被分发。
编译器可以把高级语言翻译成指令序列，因为指令就是数据。
```

代价也很直接。

```text
指令和数据混在一起，靠 PC 判断谁是代码。
一旦 PC 被改坏（缓冲区溢出把返回地址覆盖成攻击者构造的地址），
CPU 就会把数据当指令执行。
```

这就是缓冲区溢出攻击的物理基础。

现代系统把这三条约定用到了极致。

```text
程序存成文件、加载进内存就能跑    —— 存储程序
编译器把高级语言翻成指令序列      —— 指令即数据
JIT 在运行时生成机器码再跳过去执行 —— 数据变成指令
固件把程序烧进 ROM               —— 还是存储程序，只是存储器换成了只读的
```

反向的利用也存在。

```text
任何“能写内存、又能改 PC”的漏洞，都能升级成“执行任意代码”。
硬件级的对策是 NX 位（不可执行页）和 W^X（可写与可执行互斥）。
```

这些机制的存在本身，就说明冯·诺依曼结构默认不区分代码和数据。

“代码区可写”这个麻烦，也是哈佛结构在某些场合重新流行的原因。

```text
冯·诺依曼结构：指令和数据共用一个存储空间、一组总线
哈佛结构：    指令存储器与数据存储器分开，两组总线

现代 CPU 的实际做法：
  L1 层拆成 L1-I（指令）和 L1-D（数据），哈佛式；
  往下的 L2、L3、主存又合并，冯·诺依曼式。
  这叫“改进型哈佛结构”。
```

408 选择题常问“以下哪个不是冯·诺依曼结构的特点”。

选项里塞“指令和数据分开存储”就是标准错项。

## 9. 从以运算器为中心到以存储器为中心

最早的机器，运算器是交通枢纽。

```text
早期（以运算器为中心）

  输入设备 ──→ 运算器 ──→ 存储器
                 ↑  ↓
              控制器

所有数据都要经过运算器中转，
I/O 的数据也得先进运算器，再写进存储器。
```

现代机器把枢纽换成了存储器。

```text
现代（以存储器为中心）

  输入设备 ──┐
             ├──→ 存储器 ←──→ CPU（运算器 + 控制器）
  输出设备 ──┘

I/O 与存储器之间可以直接搬数据，不经过运算器。
```

为什么改。

```text
① I/O 数据量远大于计算量，让运算器当中转站是浪费。
② 运算器成了瓶颈，所有流量都挤在一条路上。
③ 存储器变成共享中心，各部件通过总线并列连接。
```

这个变化直接长出了后面的 DMA。

第 22 篇会讲：DMA 就是“I/O 和存储器直接搬，CPU 只在两头签字”。

能这么干，前提就是存储器已经是中心了。

## 10. 硬件、软件与固件

硬件是看得见的部件，软件是看不见的指令序列。

中间还有一层，叫固件。

```text
硬件（hardware）
  运算器、控制器、存储器、总线、外设。
  改变它要动电路板。

固件（firmware）
  固化在 ROM / Flash 里的程序。
  介于硬件与软件之间：形式是软件，位置是硬件。
  主板 BIOS/UEFI、微程序控制器里的微程序，都属于固件。

软件（software）
  系统软件：操作系统、编译器、数据库、驱动程序
  应用软件：浏览器、编辑器、你写的程序
```

固件这一层在 408 里有明确落点：微程序。

第 17 篇会讲，微程序控制器把一条机器指令拆成一串微指令，存在控制存储器里。

那串微指令是“程序”，但它固化在 ROM 里，所以是固件。

软硬件还有一个重要性质：逻辑等价。

```text
同一个功能，可以用硬件实现，也可以用软件实现。

乘法：
  硬件实现：专用乘法器电路，一个周期出结果，面积大
  软件实现：移位 + 加法循环，几十个周期，面积为零

浮点：
  硬件实现：FPU，快
  软件实现：软件浮点库，慢几十倍
```

所以“这条指令该用硬件做还是软件做”是个工程权衡。

固件这一层在嵌入式里更明显。

```text
一个 8 位单片机，没有操作系统，程序直接烧在 Flash 里。
上电复位后，PC 指向 Flash 的起始地址，开始取指。
那里的“程序”既是软件也是固件：形式是代码，载体是芯片。
```

所以“软硬件分界”是一条会移动的线。

```text
早期：乘法是软件（移位加法循环）
后来：乘法是硬件（阵列乘法器）
再后来：AES 加密从软件库变成 AES-NI 指令
现在：矩阵乘法正在从软件库变成 NPU 的硬件指令

每次迁移的判断标准都一样：
这个操作够不够常用、够不够影响性能、值不值得占面积。
```

RISC 的选择是：只把常用的放硬件，其余交给编译器组合。

CISC 的选择是：能放硬件就放硬件，指令越复杂越好。

第 15 篇专门讲这条分岔。

## 11. 五级层次结构

从最底下往上数，一台机器是五层摞起来的。

```text
  M4  高级语言机器级     C / Python / Java
        ↑ 编译程序翻译
  M3  汇编语言机器级     汇编指令
        ↑ 汇编程序翻译
  M2  操作系统机器级     系统调用、作业控制
        ↑ 系统调用/部分由硬件与微程序实现
  M1  机器语言机器级     机器指令（实际机器）
        ↑ 微指令解释
  M0  微程序机器级       微指令（微程序控制器）
```

两条规律。

```text
① 上层是虚拟机器，下层是实际机器。
   你写 Python 时面对的那台“机器”，硬件里并不存在。
② 每层都在做“翻译”或“解释”。
   编译是整体翻译一次，解释是逐条翻译。
```

408 常考的一个细节：实际机器是哪一层。

```text
M1（机器语言级）被称为实际机器，因为它的指令由硬件直接执行。
M0（微程序级）是更底层的实现，用微指令解释 M1 的指令。
```

再一个细节：操作系统的位置。

```text
M2 在 M1 之上，M3 之下。
它既要用 M1 的指令实现，又要给 M3、M4 提供接口。
```

还有一个常见误解：把 M0 和 M1 混为一谈。

```text
M1 的指令（add r1, r2）是“机器指令”，程序员可见。
M0 的指令（“打开 ALU 的 A 端口”）是“微指令”，对程序员不可见。

一条机器指令 = 一串微指令。
有的机器干脆没有 M0（硬布线控制器），这时 M1 就是最底层。
```

层次结构的意义，是每一层都能独立替换。

```text
换一个 CPU（换 M1/M0）→ 上面的程序不用改，因为有指令集这层接口
换一个编译器（换 M4→M1 的翻译）→ 硬件不用改
换一个操作系统（换 M2）→ 应用程序不用改
```

把这条链反过来看，就是“一条指令的一生”。

```text
你写的 a = b + c
  → 编译器生成 add 指令（M4 → M3 → M1）
  → CPU 用微指令解释 add（M1 → M0）
  → 微指令驱动数据通路，ALU 做加法（M0 → 硬件）
```

五层，一条加法。

下一篇开始，我们就在最底下那两层里刨。

## 12. 反直觉点：主频翻倍、CPI 也翻倍

前面第 3 节的公式，到这里该显灵了。

假设有一台机器，主频从 2 GHz 提到 4 GHz。

因为流水级切得更细，CPI 从 2.0 涨到 4.0。

指令条数不变。

```text
改造前：T = N × 2.0 / 2×10^9 = N × 1.0×10^-9
改造后：T = N × 4.0 / 4×10^9 = N × 1.0×10^-9
```

一模一样。

主频翻了一倍，程序一个纳秒都没快。

```text
CPU 执行时间 = 指令数 × CPI × 时钟周期
              ↑        ↑        ↑
            主频只影响最后一个因子
```

为什么主频涨了，CPI 会跟着涨。

```text
① 流水级变细，级数变多。
   分支预测失败的清空代价按“周期数”计，级数越多，代价越大。

② 内存墙。
   主频涨一倍，DRAM 的绝对延迟（约 60–100 ns）几乎不变，
   折算成周期数就翻倍：
     2 GHz：80 ns = 160 个周期
     4 GHz：80 ns = 320 个周期
   一次 Cache 缺失，在 4 GHz 机器上要多花一倍周期。

③ 流水级之间的锁存器开销占比上升。
   每级实际干活的时间被切短，锁存器、时钟偏斜的固定开销不缩。
```

这就是 2005 年之后主频停住的原因。

继续提频率，CPI 涨得比频率还快，净收益变成负的。

于是产业转向了另外两个因子。

```text
降 CPI：更宽的发射、更好的分支预测、更大的 Cache、乱序执行
降指令数：SIMD 向量化、专用指令、更强的编译器
```

**记住这个反直觉的结论：**

```text
性能是三个因子的乘积，不是主频的独角戏。
单看 GHz 判断快慢，和单看马力判断车速一样不靠谱。
```

## 13. 容易混淆的点

五组，逐个拆。

```text
① 主频 vs 时钟周期
   主频 2 GHz → 周期 0.5 ns。
   GHz 变大，ns 变小，方向相反，别写反。
```

```text
② CPI vs IPC
   CPI = 周期数 / 指令数，越小越好。
   IPC = 指令数 / 周期数 = 1/CPI，越大越好。
   超标量机器 IPC 可以大于 1，此时 CPI 小于 1。
```

```text
③ MIPS vs MFLOPS
   MIPS 数指令条数，适合整数与通用代码。
   MFLOPS 数浮点运算次数，适合科学计算。
   一条向量指令算 16 次浮点，只算 1 条指令、16 次运算。
```

```text
④ 机器字长 vs 指令字长 vs 存储字长
   机器字长：ALU 与寄存器的宽度
   指令字长：一条指令的位数
   存储字长：一个存储单元的位数
   三者可以不同。x86-64 机器字长 64 位，指令字长 8–120 位（1–15 字节）。
```

```text
⑤ 吞吐量 vs 响应时间
   吞吐量：单位时间完成多少任务
   响应时间：单个任务花多久
   流水线、多核提升吞吐量，未必改善单任务响应时间。
```

还有一组容易忘的：冯·诺依曼 vs 哈佛。

```text
冯·诺依曼：指令和数据同一存储空间，同一组总线
哈佛：      指令和数据分开存储，分开的总线
现代 CPU：  L1 分开（哈佛式），L2 以下合并（冯·诺依曼式）
```

## 14. 小结

这一篇立了三根柱子。

**第一根：结构。**

```text
冯·诺依曼五大部件：运算器、控制器、存储器、输入、输出
存储程序三条约定的核心：指令和数据同等存储、按地址访问
结构演进的主线：以运算器为中心 → 以存储器为中心
```

**第二根：层次。**

```text
M0 微程序 → M1 机器语言 → M2 操作系统 → M3 汇编 → M4 高级语言
每层都在翻译或解释，上层是虚拟机器，下层是实际机器
```

**第三根：性能。**

```text
CPU 执行时间 = 指令数 × CPI × 时钟周期 = 指令数 × CPI / 主频
CPI = Σ(各类 CPI × 占比)
IPC = 1 / CPI
MIPS = 主频(MHz) / CPI
MFLOPS = 浮点运算次数 / (时间 × 10^6)
```

一个必须带走的判断。

```text
看到“主频”两个字，先问 CPI。
看到“每秒多少”，先问是条数还是运算次数。
看到“字长”，先问是机器字长还是指令字长。
```
