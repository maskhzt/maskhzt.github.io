> **读这篇之前，你只需要知道**：内存断电就丢数据，外存（磁盘、固态盘）断电还在；B 是字节，1 KB 在磁盘容量里按 1000 字节算、在内存里按 1024 字节算（第 9 节会讲为什么）；毫秒是千分之一秒。
> **这篇讲什么**：机械盘读一个字节为什么要先"走过去、等它转过来"，容量和时间怎么算，地址怎么排；固态盘为什么读得快、写得慢，以及它为什么会写坏。
> **一个类比**：机械盘像一个巨大的圆形仓库，取货要先走到那一排货架（寻道），再等传送带把那一格转到面前（旋转延迟），最后才把箱子搬下来（传输）；固态盘像一排储物柜，没有传送带，直接开格子，但格子擦一次就少一次寿命。


一块 7200 转的机械盘，参数写着"持续传输率 200 MB/s"。

同一个盘，跑 4 KiB 随机读，只能跑出 300 KB/s。

```text
顺序读：200 MB/s
随机读：80 IOPS × 4 KiB = 320 KB/s
```

差 600 倍。

这里的 IOPS（input/output operations per second，每秒输入输出次数）指"这块盘一秒钟能完成多少次独立的读写请求"。

机械盘（HDD，hard disk drive，硬盘）靠盘片旋转、磁头读写；SSD（solid state drive，固态硬盘）用闪存芯片存数据，没有盘片、没有磁头、没有会转的部件。

直觉会说：磁头慢。

错。

磁头飞在盘面上方几纳米，盘片每秒转 120 圈，磁头下面每秒掠过 200 MB 的数据。

磁头一点都不慢。

**慢的是"找位置"。**

```text
一次 4 KiB 随机读的时间账（7200 转，平均寻道 8.5 ms）：
寻道      8.5 ms    ← 67%
旋转延迟  4.17 ms   ← 33%
传输      0.02 ms   ← 0.16%
```

先认三个词：**寻道（seek）**是把磁头挪到目标磁道；**旋转延迟（rotational latency）**是等盘片把目标扇区转到磁头下面；**传输（transfer）**才是真正读字节。

99.8% 的时间花在"把磁头挪到正确的位置"和"等盘片转到正确的角度"。

真正读数据的时间，占千分之一。

这就是磁盘性能的第一原理：

```text
顺序访问，一次寻道摊到几 MB 上，寻道成本可以忽略。
随机访问，一次寻道只摊到 4 KiB 上，成本被放大一千倍。
```

所有磁盘优化——柱面优先、扇区交错、预读、日志结构化——都在对付这一件事。

这篇从盘片结构讲到 SSD，最后算清楚那 600 倍是怎么来的。

## 1. 这个问题解决什么

存储层次走到最底层，就剩两个选择：磁盘和 SSD。

它们解决同一个问题：**断电之后数据还在**。

寄存器、Cache、主存都是易失的（volatile），断电就没了。

为什么非要非易失？因为内存靠电容存数据，断电后电荷漏光，内容就没了；外存把数据变成磁化方向或电荷陷阱，断电也不变。

外存是非易失的（non-volatile）。

408 的存储系统这一章，外存考三件事：

```text
① 容量怎么算      盘面数 × 磁道数 × 扇区数 × 扇区大小
② 时间怎么算      寻道 + 旋转延迟 + 传输
③ 地址怎么排      柱面、盘面、扇区，为什么柱面优先
```

这三件事都是能算的，而且套路固定。

加上 SSD 之后，多了一组新概念：

```text
闪存的页与块、擦除、FTL 地址映射、写放大、磨损均衡
```

这组概念和磁盘的 CHS 地址是两套体系，但考法一样：给你参数，让你算。

先看最小结构。

## 2. 最小模型：一个扇区怎么被读到

为什么从"一个扇区"开始？因为容量、时间、地址三笔账，最后都落在这一个小格子上。

先看它在物理上长在哪，再看读它要经过哪几步。

### 2.1 磁盘的物理结构

```text
              ┌─────────── 主轴 ───────────┐
              │                            │
        ┌─────┴─────┐  ┌───────────┐  ┌────┴──────┐
        │  盘片 0    │  │  盘片 1    │  │  盘片 2    │
        └─────┬─────┘  └─────┬─────┘  └─────┬─────┘
              │              │              │
           磁头臂          磁头臂          磁头臂
              │              │              │
         ┌────┴──────────────┴──────────────┴────┐
         │            音圈马达（一起动）           │
         └───────────────────────────────────────┘
```

四层套娃：

```text
盘片（platter）：一片圆形的铝合金或玻璃，两面都涂磁性材料
盘面（surface）：一个盘片有两个面，每面一个磁头
磁道（track）  ：每个盘面上的一圈同心圆
扇区（sector）：磁道上切出来的一小段，传统 512 B
```

再加上两个跨盘面的概念：

```text
柱面（cylinder）：所有盘面上半径相同的磁道，摞起来是一个圆柱面
磁头（head）    ：每个盘面一个，所有磁头装在同一个臂上，一起移动
```

为什么盘片要双面记录？因为两面的磁性材料、马达、外壳成本一样，多用一个面几乎不增加成本，容量直接翻倍。

关键在最后一句：

```text
所有磁头是刚性连在一起的，同时移动。
所以"换盘面"不需要寻道，只有"换柱面"才需要。
```

这一句就是"柱面优先"的全部理由。

还有一个物理细节值得知道：

```text
磁头飞行高度只有几纳米，比一粒灰尘小两个数量级。
磁头一旦碰到盘面，就是"划盘"，那一片磁道永久报废。
```

所以机械盘怕震动，笔记本里要加跌落保护（APS）。

SSD 没有这个顾虑，这是它在移动设备上取代机械盘的第一个原因。

### 2.2 一次读的四个阶段

```text
① 寻道（seek）    磁头臂移动到目标磁道        平均 8–9 ms（机械动作）
② 旋转延迟（rotational latency）
                  等盘片转到目标扇区          平均半圈，7200 转时 4.17 ms
③ 传输（transfer）读扇区数据                  扇区数 × 512 B / 传输率
④ 控制器开销      排队、校验、DMA 搬运          通常忽略或并入 ③
```

前两个是机械动作，第三个是电子动作。

```text
机械：毫秒级
电子：微秒级
```

差三个数量级，所以优化永远先优化寻道。

### 2.3 一个扇区长什么样

```text
┌────────┬──────────┬──────────┬─────────┬────────┐
│ 间隙   │ 地址标识  │  数据 512 B │  ECC    │ 间隙   │
│(gap)   │(ID)      │            │(校验)   │(gap)   │
└────────┴──────────┴──────────┴─────────┴────────┘
```

扇区之间留间隙，是为了磁头切换和转速波动留余量。

408 一般只考"每道多少扇区""每扇区多少字节"，间隙不考。

## 3. 一次完整走查：容量与存取时间

这一节用一块参数规整的"教材盘"，把三个公式各算一遍。

算完你会看到：真正读数据的时间只占百分之一，剩下全是在等机械动作。

设定一块"教材盘"（数字规整，方便手算）：

```text
盘片数        4        → 盘面数 8（双面记录）
每面磁道数    10,000
每道扇区数    500
每扇区字节数  512 B
转速          7200 r/min
平均寻道时间  8 ms
```

### 3.1 容量

```text
容量 = 盘面数 × 磁道数 × 扇区数 × 扇区大小
     = 8 × 10,000 × 500 × 512 B
     = 20,480,000,000 B
     = 20.48 GB（十进制）
```

逐层验算：

```text
总磁道数 = 8 面 × 10,000 道 = 80,000 道
总扇区数 = 80,000 × 500    = 40,000,000 个
总字节数 = 40,000,000 × 512 = 20,480,000,000 B
```

换算成 GiB：

```text
20,480,000,000 / 2^30 = 19.07 GiB
```

标称 20.48 GB，系统里显示 19.07 GiB。

这就是"买回来少了一截"的来源，第 9 节细说。

### 3.2 旋转延迟

```text
转速 7200 r/min = 7200 / 60 = 120 r/s
转一圈 = 1 / 120 s = 8.333 ms
平均旋转延迟 = 半圈 = 4.167 ms
```

记住 8.33 和 4.17 这两个数，7200 转的题全靠它们。

### 3.3 传输时间

一个磁道 500 个扇区，转一圈 8.333 ms。

```text
单扇区传输时间 = 8.333 ms / 500 = 16.67 μs
传输率 = 500 × 512 B / 8.333 ms = 30.72 MB/s
```

验算：

```text
256,000 B / 0.0083333 s = 30,720,000 B/s = 30.72 MB/s   ✓
```

### 3.4 读一个扇区要多久

```text
T = 寻道 + 旋转延迟 + 传输
  = 8 ms + 4.167 ms + 0.01667 ms
  = 12.18 ms
```

读 4 KiB（8 个连续扇区）：

```text
T = 8 + 4.167 + 8 × 0.01667
  = 8 + 4.167 + 0.1333
  = 12.30 ms
```

算一下这三个数各占多少：

```text
寻道      8.000 ms   65.0%
旋转延迟  4.167 ms   33.9%
传输      0.133 ms    1.1%
```

一个 4 KiB 的读，99% 的时间在等机械动作。

### 3.5 顺序 vs 随机

顺序读 500 个扇区（一整道）：

```text
T = 8 + 4.167 + 500 × 0.01667
  = 8 + 4.167 + 8.333
  = 20.5 ms
数据量 = 500 × 512 B = 256,000 B
有效带宽 = 256,000 / 0.0205 = 12.5 MB/s
```

还是不高，因为这道只有 256 KB，寻道占了 40%。

有效带宽等于数据量除以总时间。寻道和旋转是固定开销，数据量越大，摊到每个字节上就越少，带宽越接近峰值。

如果连着读 100 个柱面（800 道）：

```text
数据量 = 800 × 256 KB = 204.8 MB
传输   = 800 × 8.333 ms = 6667 ms
寻道   = 100 次相邻柱面寻道，每次约 1 ms = 100 ms
旋转   = 4.167 ms
总时间 = 6771 ms
有效带宽 = 204.8 MB / 6.771 s = 30.2 MB/s
```

接近峰值 30.72 MB/s。

再看随机读 1000 个 4 KiB 块：

```text
每个 12.30 ms
1000 个 = 12.3 s
数据量 = 1000 × 4 KiB = 4 MB
有效带宽 = 4 MB / 12.3 s = 325 KB/s
```

```text
顺序 30.2 MB/s vs 随机 0.325 MB/s
差 93 倍
```

教材盘只有 30 MB/s，所以差 93 倍。

真实盘 200 MB/s，随机仍是 80 IOPS 左右，差 600 倍。

这就是开篇那个数字的来历。

## 4. 拆开看：地址、SSD、RAID

前面把一块盘当成整体算时间，这一节拆到内部：地址怎么排、固态盘怎么存、多块盘怎么拼。

三件事都在回答同一个问题：怎么让"定位"这一次性成本摊到更多数据上。

### 4.1 磁盘地址：为什么柱面优先

磁盘的物理地址是三维的：

```text
（柱面号，盘面号，扇区号）
```

逻辑块号怎么排成三维地址，有两种方案。

**柱面优先（cylinder-major）**：

```text
逻辑块号 = 柱面号 × (盘面数 × 每道扇区数)
         + 盘面号 × 每道扇区数
         + 扇区号
```

**盘面优先（surface-major）**：

```text
逻辑块号 = 盘面号 × (柱面数 × 每道扇区数)
         + 柱面号 × 每道扇区数
         + 扇区号
```

哪个好？看"连续的逻辑块要不要寻道"。

```text
柱面优先：同一柱面的所有磁道排在一起
        连续块先换盘面（磁头切换，0 寻道），再换柱面（1 次寻道）
        → 一个柱面的数据 = 8 × 500 = 4000 个扇区，只寻道 1 次

盘面优先：同一盘面的所有磁道排在一起
        连续块先换柱面（每次都要寻道）
        → 每 500 个扇区就要寻道 1 次
```

同一份数据，柱面优先的寻道次数是盘面优先的 1/8。

所以真实磁盘都用柱面优先。

这一条对文件系统同样重要：把同一个文件放在相邻柱面，顺序读时就只需要很少几次寻道。

```text
文件系统尽量把文件放在同一柱面内，
就是为了让大文件顺序读时只寻道一次。
```

手算一个地址转换。

```text
参数：8 盘面，10,000 磁道，500 扇区/道
逻辑块号 1,234,567，求（柱面，盘面，扇区）

每柱面扇区数 = 8 × 500 = 4000
柱面号 = 1,234,567 / 4000 = 308 余 2,567
盘面号 = 2,567 / 500    = 5   余 67
扇区号 = 67
```

验算：

```text
308 × 4000 = 1,232,000
5 × 500    =     2,500
67         =        67
合计         = 1,234,567   ✓
```

所以逻辑块 1,234,567 在柱面 308、盘面 5、扇区 67。

这三个数读成人话就是：第 308 层同心圆、第 5 个磁头、圆周上的第 67 段。

换个顺序理解：先定半径（柱面），再定用哪个面（盘面），最后定角度（扇区）。

三个数都在范围内：

```text
柱面 308 < 10,000    ✓
盘面 5   < 8         ✓
扇区 67  < 500       ✓
```

408 的套路就是这样：给你"逻辑块号"和三个维度，让你做除法取余。

注意顺序：先除每柱面的扇区数，商是柱面，余数再除每道扇区数。

除反了，答案就错。

### 4.2 传输率与扇区大小

传输率有两个口径：

```text
峰值传输率（内部传输率）= 每道字节数 × 每秒转数
                        = 500 × 512 × 120 = 30.72 MB/s

接口传输率（外部传输率）= SATA 6 Gb/s = 600 MB/s 量级
```

两个数差 20 倍。

说明瓶颈在盘片，不在接口。

```text
SATA 3.0 接口 6 Gb/s ≈ 600 MB/s，一块 7200 转盘的实际持续传输只有 150–200 MB/s
```

扇区大小也在变：

```text
512 B：传统扇区，用了三十年
4 KiB：Advanced Format，2010 年后普及
512e：物理 4 KiB，逻辑报 512 B（兼容老系统）
4Kn ：物理、逻辑都是 4 KiB
```

为什么改 4 KiB？

```text
每个扇区的 ECC 和间隙是固定开销。
512 B 扇区，ECC 占约 50 B → 开销 10%
4 KiB 扇区，ECC 占约 100 B → 开销 2.4%
同样面积多存 8% 的数据
```

代价是老系统要对齐到 4 KiB，否则每次写都要读-改-写整块。

408 只考 512 B。

### 4.3 SSD：页、块、擦除

SSD 里是 NAND 闪存，结构是两层：

```text
块（block）  ：擦除的最小单位，常见 128–512 个页
页（page）   ：读写的最小单位，常见 4 KiB
```

关键的物理限制：

```text
读：以页为单位，可以随便读
写：以页为单位，但只能写"擦干净"的页
擦：以块为单位，一次擦掉一整块
```

三个动作的粒度不一样，这是 SSD 一切复杂性的来源。

为什么非要这样设计？因为闪存单元被写过之后，再写就必须先擦回初始状态；而擦除会清掉整块，做不到只擦一个页。

```text
          ┌──────── 块（1 MiB = 256 页）────────┐
页号   0    1    2    3   ...  253  254  255
      ┌────┬────┬────┬────┬───┬────┬────┬────┐
      │ 4K │ 4K │ 4K │ 4K │...│ 4K │ 4K │ 4K │
      └────┴────┴────┴────┴───┴────┴────┴────┘
       ↑ 读/写单位                    ↑ 擦除单位是整个块
```

想改第 3 页的一个字节？

```text
不能原地改。
只能：写到一个新的空页 → 把旧页标记为无效
```

这叫异地更新（out-of-place update）。

后果有两个：

```text
① 需要一个映射表，记录"逻辑页 → 物理页"的最新位置  → FTL
② 无效页越积越多，需要回收（GC），回收要搬有效页  → 写放大
```

再来一个数字：擦除的代价。

```text
页读取     25–50 μs
页编程     200–500 μs     ← 写比读慢一个数量级
块擦除     1.5–3 ms       ← 比写又慢一个数量级
```

所以 SSD 读快、写慢、擦更慢。

这也解释了"SSD 用久了会变慢"：

```text
空闲页多时，写直接落到空页，快
空闲页少时，每次写都要先 GC（搬页 + 擦块），慢
```

TRIM 指令就是给操作系统一个机会，告诉 SSD"这些页不要了"，让它提前回收。

### 4.4 FTL、写放大、磨损均衡

**FTL（flash translation layer）** 是 SSD 控制器里的固件层。

它维护一张映射表：

```text
逻辑块地址 LBA → 物理页号 PPN
```

主机读写的是 LBA，FTL 翻译成物理页。

这张表有多大？

```text
512 GB 盘，4 KiB 页 → 1.25 亿个页
每项 4 B → 500 MB
```

500 MB 的表，装不进控制器的小 SRAM。

所以真实 SSD 用分级映射：

```text
块级映射：逻辑块 → 物理块（粗粒度，表小）
页级映射：块内的页偏移（细粒度，只维护当前块）
混合映射：热数据用页级，冷数据用块级
```

而且表本身要缓存在 DRAM 里，这也是 SSD 上那小块 DRAM 的用途。

断电时表要能重建（扫描全盘太慢），所以还有一份快照存在闪存里。

为什么表放 DRAM、快照放闪存？因为读表要快，DRAM 合适；DRAM 掉电会丢，快照就是给掉电准备的，不用扫全盘就能恢复。

**写放大（write amplification）**：

```text
写放大 WA = 写进闪存的数据量 / 主机请求写入的数据量
```

为什么会有放大？

回收一个块时，块里还有有效页，必须先搬走。

算一笔账（简化示意）：

```text
一个块 = 256 页
GC 时块内还有 192 页有效，64 页已无效
要回收：搬 192 页到新块 + 擦除
主机当初写进这个块的净数据：只有那 64 页（被覆盖的）

闪存实际写入 = 64（新数据）+ 192（搬移）= 256 页
WA = 256 / 64 = 4
```

写放大 4 意味着：主机写 1 GB，闪存实际写 4 GB。

寿命直接除以 4。

哪些情况写放大高？

```text
随机小写：块内有效页分散，回收时搬得多
盘快满  ：空闲块少，GC 频繁触发
小文件多：每次写都动一个块
```

哪些情况低？

```text
顺序大块写：整块写完再回收，块内几乎全无效，搬 0 页 → WA ≈ 1
```

所以 SSD 的性能和寿命都偏爱顺序写。

**磨损均衡（wear leveling）**：

闪存块有寿命，TLC（triple-level cell，每个存储单元存 3 个比特）大约 1000–3000 次擦写（P/E cycles，program/erase，编程与擦除）。

如果一个块被反复擦，它会先坏。

磨损均衡就是把擦除次数摊平：

```text
动态磨损均衡：新数据优先写到擦除次数少的块
静态磨损均衡：定期把冷数据从"擦得少"的块搬出来，
              让这个块也参与轮换
```

静态均衡很重要，因为操作系统里大量数据是"写完就不动"的（比如系统文件）。

只做动态均衡，那些存放冷数据的块永远不被擦，寿命白白浪费。

**如果没有磨损均衡会怎样**：文件系统的超级块、日志区、目录这些"天天改、位置又不变"的数据，会反复落在同一批块上。

那几十个块先被擦穿，整盘跟着报废，尽管其余 99% 的块几乎没被擦过。

磨损均衡就是把"写得最多的地址"摊到"擦得最少的块"上，让全盘一起老。

寿命怎么算？

```text
512 GB TLC，每块 3000 次 P/E，写放大 3

总可写入 = 512 GB × 3000 / 3 = 512 TB
```

验算：

```text
512 × 10^9 × 3000 = 1.536 × 10^15 B
1.536 × 10^15 / 3 = 5.12 × 10^14 B = 512 TB   ✓
```

如果每天写 50 GB：

```text
512 TB / 50 GB/天 = 10,240 天 ≈ 28 年
```

厂商标的 TBW（total bytes written）就是这个数的保守版。

比如 1 TB 盘标 600 TBW，对应 600 次全盘写入。

### 4.5 RAID 0/1/5

一块盘会坏，所以要多块。

RAID 是在多块盘上做冗余和并行。

**RAID 0（条带）**：

```text
数据切成块，轮流写到 N 块盘上
容量 = N 块盘之和（100%）
读性能 ≈ N 倍
可靠性 = 最差（一块坏，全毁）
```

**RAID 1（镜像）**：

```text
同样数据写两份
容量 = 50%
读性能可翻倍（两个副本并行读）
可靠性 = 可容忍坏一块（每对）
```

**RAID 5（条带 + 分布式校验）**：

```text
数据和奇偶校验轮流分布在 N 块盘上
容量 = (N−1)/N
可容忍坏 1 块（用校验重建）
小写有"读-改-写"惩罚：改一个块要读旧数据 + 读旧校验 + 写新数据 + 写新校验 = 4 次 I/O
```

一句话总结：

```text
RAID 0 要速度不要命，RAID 1 要命不要容量，RAID 5 折中但要算校验。
```

RAID 5 的写惩罚是它最大的问题：

```text
一次逻辑写 → 4 次物理 I/O
随机写性能只有单盘的 1/4
```

所以数据库多用 RAID 10（镜像 + 条带）。

### 4.6 SSD 的内部并行与 OP 预留

SSD 不是一块大闪存，是很多块小闪存并联。

```text
通道（channel）→ 芯片（die）→ 平面（plane）→ 块 → 页

8 通道 × 4 die × 2 plane = 64 个 plane
64 个 plane 可以同时读写
```

算一下带宽：

```text
一个 plane 写一页 4 KiB 用 200 μs → 20 MB/s
64 个 plane 并行 → 1.28 GB/s
```

SSD 能跑到 GB/s，不是因为单个闪存快，是因为并行。

队列深度（QD）就是把并行度用起来的手段：

为什么提高队列深度能提升 IOPS？因为 SSD 内部有很多闪存芯片，深度 1 时只有一个芯片在忙，其余都在等。

```text
QD = 1  → 一次只有一个 plane 在忙 → 几十 K IOPS
QD = 32 → 64 个 plane 填满 → 几十万 IOPS
```

第 7 节 fio 那两个数（QD1 一万四、QD32 三十一万）就是这么来的。

**OP（over-provisioning，预留空间）**：

```text
标称 512 GB 的盘，闪存实际容量更大
消费级 OP 约 7%  → 原始约 550 GB
企业级 OP 约 28% → 原始约 711 GB
```

预留的部分不暴露给主机，专供 GC 周转。

```text
OP 越大 → 空闲块越多 → GC 越少触发 → 写放大越低 → 寿命越长
```

一个直观对比：

```text
OP 7% ：空闲块紧张，GC 频繁，WA 可能 3–4
OP 28%：空闲块充裕，GC 从容，WA 可能 1.5–2
```

所以企业级 SSD 标称容量小、寿命长、价格贵，不是骗钱。

主机也能自己留 OP：

```text
分区只用 90%，剩下的 10% 就是"手工 OP"
```

这带来一条反直觉的建议：

```text
SSD 不要写满。
写满 → 没有空闲块 → 每次写都要先 GC → 速度断崖式下跌。
一般留 10%–20% 不用。
```

机械盘没有这个问题，写满只是碎片多。

固态盘写满，是物理意义上的没地方周转。

## 5. 容易混淆的点

下面这些词，差一个限定就换了一个意思，代入公式就会错。

**盘片数和盘面数不是一回事。**

```text
4 个盘片，双面记录 → 8 个盘面 → 8 个磁头
题目说"4 个盘片"，容量要按 8 个面算
题目说"4 个盘面"，那就是 2 个盘片
```

这是容量题最常见的失分点。

**磁道数指每面的磁道数，不是总数。**

```text
总磁道数 = 盘面数 × 每面磁道数
```

**转速和时间的关系是倒数，不是正比。**

```text
7200 r/min → 120 r/s → 8.333 ms/圈
15000 r/min → 250 r/s → 4 ms/圈
```

转得快，一圈时间短，平均旋转延迟小。

**平均旋转延迟是半圈，不是一圈。**

因为目标扇区在圆周上均匀分布，平均要转半圈才能碰上。

```text
也有教材按 1/3 圈算（考虑扇区有宽度），408 用半圈
```

**传输时间按"扇区数 × 每扇区字节 / 传输率"算，不是按整块算。**

题目给的传输率可能是"每道字节数 / 每圈时间"，也可能是接口带宽。

看清楚单位。

**寻道时间是平均值，不是最大值。**

题目一般给"平均寻道时间"。

如果给的是"相邻磁道寻道 1 ms"，那连续访问同柱面时寻道接近 0。

**SSD 没有"寻道时间"和"旋转延迟"。**

它的延迟是电子的：请求排队 + 闪存读 + 控制器处理。

所以 SSD 的随机性能比机械盘高四五个数量级。

**SSD 的"块"和文件系统的"块"不是一回事。**

```text
闪存块：擦除单位，1 MiB 量级，硬件概念
文件系统块：分配单位，4 KiB 量级，软件概念
```

**写放大不是"写得慢"，是"写得比要写的多"。**

慢是结果，放大是原因。

**RAID 不是备份。**

删库、勒索病毒、控制器损坏，RAID 一样救不了。

### 反直觉的点：随机慢不是因为磁头慢

把开篇的账算完整。

一块真实 7200 转盘（不是教材盘）：

```text
持续传输率    200 MB/s
平均寻道      8.5 ms
转速          7200 r/min → 8.333 ms/圈
```

顺序读 1 MB：

```text
传输 = 1 MB / 200 MB/s = 5 ms
寻道 + 旋转 = 8.5 + 4.17 = 12.67 ms
总时间 = 17.67 ms
有效带宽 = 1 MB / 17.67 ms = 56.6 MB/s
```

读 100 MB：

```text
传输 = 500 ms
寻道 + 旋转 = 12.67 ms
总时间 = 512.67 ms
有效带宽 = 100 MB / 0.5127 s = 195 MB/s
```

接近峰值 200 MB/s。

随机读 4 KiB：

```text
传输 = 4 KiB / 200 MB/s = 0.02 ms
寻道 + 旋转 = 12.67 ms
总时间 = 12.69 ms
有效带宽 = 4 KiB / 12.69 ms = 322 KB/s
IOPS = 1 / 0.01269 = 78.8
```

对比：

```text
顺序 195 MB/s
随机 0.322 MB/s
比值 = 604
```

604 倍，接近三个数量级。

拆开看这 604 倍是怎么来的：

```text
顺序读：12.67 ms 的定位成本摊到 100 MB → 每 MB 只摊 0.127 ms
随机读：12.69 ms 摊到 4 KiB = 0.0039 MB → 每 MB 要摊 3,248 ms
摊销比 = 3248 / 0.127 ≈ 25,600 倍
```

为什么带宽只差 604 倍，不是 25,600 倍？

因为顺序读的带宽被传输率封顶了。

```text
200 MB/s 是盘片能扫过的上限。
再怎么摊，顺序读也不会超过 200 MB/s。
而随机读的 322 KB/s 离天花板还有 600 倍空间。
```

如果盘片的传输率是 20 GB/s，那带宽比就会接近 25,600 倍。

```text
所以"随机慢多少倍"取决于两个数：
定位成本 / 传输率。
传输率越高，随机和顺序的差距越大。
```

这也解释了为什么 SSD 上"随机 vs 顺序"的差距反而小：SSD 没有寻道，定位成本几乎为 0。

更直白的说法：

```text
磁头找一次位置要 12.7 ms。
顺序读：这 12.7 ms 换来 100 MB。
随机读：这 12.7 ms 换来 4 KiB。
同样的 12.7 ms，一个换 100 MB，一个换 4 KB，差 25600 倍。
```

磁头本身呢？

```text
磁头下方每秒掠过 200 MB，等于每微秒 200 B。
4 KiB 数据，磁头只需要 20 μs 就扫过去了。
```

20 μs 对 12,690 μs。

磁头的贡献是千分之一。

所以"磁盘随机慢"这句话要改：

```text
不是磁盘慢，是"定位"慢。
数据本身读得飞快，找到它要十几毫秒。
```

这也解释了为什么数据库要把随机 I/O 变成顺序 I/O：

```text
B+ 树：把随机写攒在内存里，一次顺序刷盘
日志结构：所有写都追加到末尾，永远顺序
预读：猜你接下来要读相邻的块，提前搬进 Cache
```

它们都在做同一件事：让那 12.7 ms 摊到更多数据上。

## 6. 408 怎么考

外存的题，四种问法：

```text
① 给盘面、磁道、扇区、扇区大小 → 算容量
② 给转速、寻道时间 → 算平均存取时间、传输率
③ 给逻辑块号 → 转成（柱面，盘面，扇区）
④ SSD 的写放大、寿命
```

外存计算题也有固定顺序：先统一单位（GB 还是 GiB），再算容量，再算三段时间和有效带宽，最后检查该向上取整还是四舍五入。

### 例题一：容量与地址

```text
某磁盘：6 个盘片（双面记录），每面 20,000 磁道，
每道 400 个扇区，每扇区 512 B。
(1) 磁盘容量是多少字节？合多少 GB？
(2) 逻辑块号 5,000,000 对应的（柱面，盘面，扇区）是什么？
(3) 若要存 40 GB 数据，需要多少块这样的盘？（不考虑冗余）
```

解：

```text
(1) 盘面数 = 6 × 2 = 12
    容量 = 12 × 20,000 × 400 × 512
         = 12 × 20,000 = 240,000 道
         240,000 × 400 = 96,000,000 扇区
         96,000,000 × 512 = 49,152,000,000 B
         ≈ 49.15 GB
```

```text
(2) 每柱面扇区数 = 12 × 400 = 4,800
    柱面 = 5,000,000 / 4,800 = 1041 余 3,200
    盘面 = 3,200 / 400       = 8    余 0
    扇区 = 0
    答案：（1041, 8, 0）
```

验算：

```text
1041 × 4800 = 4,996,800
8 × 400     =     3,200
0           =         0
合计          = 5,000,000        ✓
```

```text
(3) 40 GB / 49.15 GB = 0.814 → 需要 1 块
```

第 (3) 问如果按"要存 100 GB"：

```text
100 / 49.15 = 2.03 → 需要 3 块
```

**注意向上取整，不是四舍五入。**

### 例题二：平均存取时间

```text
某磁盘转速 7200 r/min，平均寻道时间 8 ms，
每道 500 个扇区，每扇区 512 B。
(1) 平均旋转延迟是多少？
(2) 读取一个扇区的平均存取时间是多少？
(3) 读取 10 个连续扇区的平均存取时间是多少？
(4) 传输率是多少？
```

解：

```text
(1) 7200 / 60 = 120 r/s
    一圈 = 1/120 s = 8.333 ms
    平均旋转延迟 = 8.333 / 2 = 4.167 ms

(2) 单扇区传输 = 8.333 / 500 = 0.01667 ms
    T = 8 + 4.167 + 0.01667 = 12.18 ms

(3) T = 8 + 4.167 + 10 × 0.01667
      = 8 + 4.167 + 0.1667
      = 12.33 ms

(4) 传输率 = 500 × 512 B / 8.333 ms
           = 256,000 / 0.0083333
           = 30,720,000 B/s = 30.72 MB/s
```

第 (2) 和 (3) 只差 0.15 ms：

```text
读 1 个扇区 12.18 ms
读 10 个扇区 12.33 ms
多了 9 个扇区，只多了 1.2% 的时间
```

这就是"一次寻道要摊到更多数据上"的定量版。

### 例题三：多大块才划算

```text
承接例题二。若要求有效带宽达到峰值传输率的一半（15.36 MB/s），
一次连续读至少要读多少字节？
```

解：

```text
设读 n 个扇区，数据 D = n × 512 B
时间 T = 8 + 4.167 + n × 0.01667 ms

要求 D / T ≥ 15.36 MB/s

试 n = 500（一整道）：
D = 256,000 B，T = 8 + 4.167 + 8.333 = 20.5 ms
带宽 = 256,000 / 0.0205 = 12.5 MB/s     不够

试 n = 1500（三道）：
D = 768,000 B
T = 8 + 4.167 + 1500 × 0.01667 = 8 + 4.167 + 25 = 37.17 ms
带宽 = 768,000 / 0.03717 = 20.7 MB/s    够了

试 n = 1000：
D = 512,000 B
T = 8 + 4.167 + 16.67 = 28.84 ms
带宽 = 512,000 / 0.02884 = 17.75 MB/s   够了

试 n = 800：
D = 409,600 B
T = 8 + 4.167 + 13.33 = 25.5 ms
带宽 = 409,600 / 0.0255 = 16.06 MB/s   刚好够

试 n = 700：
D = 358,400 B
T = 8 + 4.167 + 11.67 = 23.84 ms
带宽 = 358,400 / 0.02384 = 15.03 MB/s   不够
```

答案：约 800 个扇区，即 400 KB 左右。

```text
这个数就是"顺序访问的最小有效粒度"。
小于它，寻道成本压不住。
```

这解释了为什么文件系统的预读窗口通常是 128 KB–1 MB。

### 例题四：SSD 寿命

```text
某 SSD 容量 1 TB，TLC 闪存，每块可擦写 3000 次，
实测写放大为 2.5。
(1) 总可写入量（TBW）是多少？
(2) 若每天写 100 GB，能用多少年？
(3) 写放大升到 5，寿命变成多少？
```

解：

```text
(1) TBW = 1 TB × 3000 / 2.5 = 1200 TB

(2) 1200 TB / 100 GB/天 = 12,000 天 ≈ 32.9 年

(3) TBW = 1 TB × 3000 / 5 = 600 TB
    寿命减半
```

验算第 (1) 问：

```text
1 × 10^12 × 3000 = 3 × 10^15 B
3 × 10^15 / 2.5 = 1.2 × 10^15 B = 1200 TB   ✓
```

第 (2) 问：

```text
1.2 × 10^15 / 100 × 10^9 = 12,000 天
12,000 / 365 = 32.9 年                      ✓
```

这道题的结论：

```text
写放大翻倍，寿命减半。
所以 SSD 固件拼命优化 GC，就是为了压 WA。
```

### 例题五：RAID 5 的容量与代价

```text
5 块 4 TB 硬盘组成 RAID 5，单盘持续传输 180 MB/s。
(1) 可用容量是多少？
(2) 读一个 4 KiB 块需要几次磁盘 I/O？写呢？
(3) 一块盘坏了，重建要读多少数据？按 180 MB/s 算要多久？
(4) 若改成 RAID 10，5 块盘能用几块？容量多少？
```

解：

```text
(1) 容量 = (N − 1) × 单盘容量 = 4 × 4 TB = 16 TB

(2) 读：1 次（数据在某一块盘上，直接读）
    写：4 次
      读旧数据 + 读旧校验 + 写新数据 + 写新校验
      这叫写惩罚，只有"部分条带写"才发生

(3) 重建 = 读其余 4 块的全部数据 = 16 TB
    时间 = 16 × 10^12 / (180 × 10^6)
         = 88,889 s ≈ 24.7 小时

(4) RAID 10 要求偶数块，5 块只能用 4 块做两组镜像
    容量 = 2 × 4 TB = 8 TB
    （剩下一块只能当热备，或者干脆上 6 块）
```

第 (3) 问的数字值得警惕：

```text
重建要 24.7 小时，这段时间阵列处于"无冗余"状态。
再坏一块，数据全没。
```

所以大容量盘的 RAID 5 重建风险很高，业界转向 RAID 6 或 RAID 10。

第 (2) 问的"4 次 I/O"也有前提：

```text
只有"部分条带写"才要 4 次。
一次写满整个条带（所有盘都写），校验可以直接算出来，不用读旧值。
```

这就是为什么数据库的日志写（顺序、大块）比随机小写快得多。

### 例题六：三种 RAID 的取舍

```text
有 4 块 2 TB 硬盘，分别组 RAID 0、RAID 1、RAID 5。
(1) 三种方案的可用容量各是多少？
(2) 各自能容忍几块盘故障？
(3) 若随机写性能以单盘为 1，三种方案大约是多少？
```

解：

```text
(1) RAID 0：4 × 2 = 8 TB
    RAID 1：2 组镜像 → 2 × 2 = 4 TB
    RAID 5：(4 − 1) × 2 = 6 TB

(2) RAID 0：0 块（坏一块全毁）
    RAID 1：每组坏 1 块，但不能是同组的 2 块
    RAID 5：1 块

(3) RAID 0：4（四块并行写）
    RAID 1：2（两组镜像并行）
    RAID 5：约 1（4 次 I/O 换 1 次逻辑写，写惩罚吃掉并行度）
```

第 (3) 问最容易被忽略：

```text
RAID 5 的顺序读能到 3 倍（数据分布在 3 块上）
但随机写只有 1 倍甚至更低，因为每次写要读旧数据、读旧校验。
```

所以"RAID 5 读写都变快"是错的。

读快、顺序写快、随机写慢，这才是 RAID 5 的真实画像。

## 7. 真实芯片里长什么样

理论算出来的 12 ms、80 IOPS，真盘上是不是这个数？

下面这些命令把盘自己报的参数和实测值读出来，可以拿来对答案。

先看系统里有几块盘、哪些是机械盘：

```bash
$ lsblk -d -o NAME,ROTA,SIZE,MODEL
NAME    ROTA  SIZE MODEL
sda        1  3.6T ST4000DM004-2CV104
nvme0n1    0  931G Samsung SSD 980 PRO 1TB
```

`ROTA`（rotational）就是"是否旋转"：

```text
ROTA = 1 → 机械盘
ROTA = 0 → SSD
```

为什么 ROTA 能一眼判断？因为机械盘必须旋转，固态盘没有马达，这个值直接暴露了有没有机械结构。

这个值来自：

```bash
$ cat /sys/block/sda/queue/rotational
1
$ cat /sys/block/nvme0n1/queue/rotational
0
```

再看扇区大小：

```bash
$ cat /sys/block/sda/queue/logical_block_size
512
$ cat /sys/block/sda/queue/physical_block_size
4096
```

`logical` 512、`physical` 4096，这就是一块 512e 盘：

```text
对外报 512 B 扇区（兼容老系统）
内部按 4 KiB 管理
如果分区没对齐到 4 KiB，每次写都要读-改-写
```

机械盘的详细参数，`smartctl` 直接给：

```bash
$ sudo smartctl -a /dev/sda
Model Family:     Seagate Barracuda 3.5
Device Model:     ST4000DM004-2CV104
Rotation Rate:    5400 rpm
Sector Sizes:     512 bytes logical, 4096 bytes physical
```

`Rotation Rate` 这一行，就是算旋转延迟要用的转速。

注意这块是 5400 转，不是 7200：

```text
5400 r/min → 90 r/s → 11.11 ms/圈 → 平均旋转 5.56 ms
```

SSD 的 `smartctl` 输出更长，信息更有意思：

```bash
$ sudo smartctl -a /dev/nvme0n1
Model Number:                       Samsung SSD 980 PRO 1TB
Rotation Rate:                      Solid State Device
Firmware Version:                   5B2QGXA7
...
SMART/Health Information:
Percentage Used:                    3%
Data Units Written:                 45,231,908 [23.1 TB]
Power On Hours:                     4,120
Unsafe Shutdowns:                   37
```

三行值得算一下：

```text
Data Units Written 的单位是 1000 × 512 B = 512,000 B
45,231,908 × 512,000 B = 2.32 × 10^13 B = 23.1 TB
```

这 23.1 TB 是"主机写入量"，不是"闪存写入量"。

```text
闪存实际写入 = 主机写入 × 写放大
如果 WA = 2，闪存已经写了 46 TB
```

`Percentage Used` 3% 就是厂商按 TBW 算的消耗：

```text
600 TBW × 3% = 18 TB
和 23.1 TB 不完全对得上，因为厂商的 TBW 是保守估计
```

`Unsafe Shutdowns` 37 次，对应 37 次掉电。

SSD 掉电可能导致映射表没刷完，所以固件要有掉电保护（电容或日志）。

传输性能，用 `fio` 或 `hdparm` 量：

```bash
$ sudo hdparm -t --direct /dev/sda
 Timing O_DIRECT disk reads: 512 MB in  3.21 seconds = 159.50 MB/sec
```

159.5 MB/s，和标称的 190 MB/s 差不多。

随机 4K 就看 `fio`：

```bash
$ sudo fio --name=randread --filename=/dev/sda --direct=1 \
>          --bs=4k --iodepth=1 --runtime=10 --rw=randread
  read: IOPS=84, BW=336KiB/s
```

84 IOPS，336 KiB/s。

和前面算的 78.8 IOPS、322 KB/s 对得上。

```text
理论算一次 12.69 ms → 78.8 IOPS
实测 84 IOPS → 11.9 ms
差的 0.8 ms 是控制器和排队的开销，或者盘片密度比假设的高一点
```

同一条命令换成 NVMe：

```bash
$ sudo fio --name=randread --filename=/dev/nvme0n1 --direct=1 \
>          --bs=4k --iodepth=1 --rw=randread
  read: IOPS=14.2k, BW=55.5MiB/s
```

14,200 IOPS，比机械盘高 169 倍。

队列深度拉到 32，能到 31 万 IOPS（1211 MiB/s）。

SSD 的并行度来自内部多个闪存通道，深度 1 只用得上一个通道。

最后看一眼 TRIM 有没有开：

```bash
$ cat /sys/block/nvme0n1/queue/discard_max_bytes
2199023255552
```

非 0 就说明支持 discard（TRIM）。

这个数 2 TB 是单次 discard 的上限。

## 8. 磁盘与 SSD 对比

前面两套东西分开讲，放到一张表里才看得清：它们不是"新的取代旧的"，而是各守一段。

表格的读法是看"哪一列赢在哪一行"，不是看谁赢得多。

| 维度 | 机械硬盘 HDD | 固态硬盘 SSD |
|---|---|---|
| 存储介质 | 磁性涂层，机械读写 | NAND 闪存，电子读写 |
| 随机 4K 读 | 80–100 IOPS | 1 万–50 万 IOPS |
| 顺序读 | 150–200 MB/s | 500 MB/s（SATA）–7 GB/s（NVMe） |
| 随机读延迟 | 约 12 ms | 约 50–100 μs |
| 最小读写单位 | 扇区 512 B / 4 KiB | 页 4 KiB |
| 最小擦除单位 | 无（可覆盖写） | 块 1–4 MiB |
| 写前是否要擦 | 不需要 | 必须，且以块为单位 |
| 寿命限制 | 机械磨损，数年 | 擦写次数，1000–3000 P/E |
| 震动敏感 | 是（磁头会撞盘） | 否 |
| 每 GB 价格 | 低 | 高（但差距在缩小） |
| 容量上限 | 20 TB+ | 8 TB+（消费级 4 TB） |
| 典型用途 | 冷数据、备份、监控 | 系统盘、数据库、热数据 |

看这张表的方式：

```text
SSD 在延迟、IOPS、抗震上全面胜出，且高 4–5 个数量级。
HDD 只剩下两个优势：每 GB 价格、单盘容量。
```

所以现在的做法是分层：

```text
SSD 放热数据（系统、数据库、索引）
HDD 放冷数据（归档、备份、日志）
```

这就是存储层次在"外存"这一层的复制：

```text
寄存器 → Cache → 主存 → SSD → HDD → 磁带
                         ↑      ↑
                      热数据   冷数据
```

每一层都在做同一件事：把下一层的一小块搬到上一层。

## 9. 容量为什么总是对不上

买回来的盘"少了 10%"，这件事每年都要被问一次。

它不是质量问题，是两个单位制在同一个数字上打架。

买一块"4 TB"的硬盘，装到 Windows 里显示 3.63 TB。

买一块"512 GB"的 SSD，显示 476 GB。

不是厂商缺斤短两，是两个单位制。

```text
厂商标称：十进制 1 TB = 10^12 B = 1,000,000,000,000 B
系统显示：二进制 1 TiB = 2^40 B = 1,099,511,627,776 B
```

算一下：

```text
4 × 10^12 / 2^40 = 3.638 TiB
512 × 10^9 / 2^30 = 476.8 GiB
```

所以"4 TB"的盘显示 3.63，"512 GB"的盘显示 476。

差多少？

```text
2^40 / 10^12 = 1.0995 → 差 10%
2^30 / 10^9  = 1.0737 → 差 7.4%
```

容量越大，差得越多。

```text
1 TB → 差 9.95%
4 TB → 差 9.95%
```

比例固定，约 10%。

为什么厂商坚持十进制？因为容量本来就是按扇区个数算出来的，用 10 的幂更自然，数字也更大。

这 10% 在 408 里也要小心：

```text
主存容量题：1 KB = 1024 B，1 MB = 1024 KB
磁盘容量题：1 KB = 1000 B，1 MB = 1000 KB（厂商标称）
```

题目一般会说清，但看到"某磁盘 1 GB"时，先判断它指的是 10^9 还是 2^30。

一个实用判断：

```text
用"盘面数 × 磁道数 × 扇区数 × 512"算出来的字节数，
是十进制口径（因为扇区数就是物理个数）。
换算成 GB 时除以 10^9，不要除以 2^30。
```

写"20.48 GB"和写"19.07 GiB"都对，但别把两者混着写。

## 10. 小结

三个公式：

```text
容量 = 盘面数 × 每面磁道数 × 每道扇区数 × 扇区大小

平均存取时间 = 平均寻道 + 平均旋转延迟 + 传输时间
             = 寻道 + (60 / 转速) / 2 + 扇区数 × 扇区大小 / 传输率

逻辑块号 → （柱面，盘面，扇区）
  柱面 = 块号 / (盘面数 × 每道扇区数)
  盘面 = 余数 / 每道扇区数
  扇区 = 再余数
```

两个数字要背：

```text
7200 r/min → 一圈 8.33 ms → 平均旋转 4.17 ms
5400 r/min → 一圈 11.11 ms → 平均旋转 5.56 ms
```

反直觉的点再重复一次：

```text
磁盘随机读写慢，不是因为磁头慢，
是因为寻道那十几毫秒要摊到 4 KiB 上。
数据本身只占千分之一的时间。
```

SSD 那一侧的一句话：

```text
闪存不能原地改，只能异地写；
异地写要 GC，GC 要搬页，搬页就是写放大；
写放大吃寿命，所以要磨损均衡。
```
