> **读这篇之前，你只需要知道**：线性表是排成一排的元素，每个元素只有一个后继；递归是一个函数调用自己，写递归必须有一个"不再递归"的出口；指针是一个格子的门牌号，空指针写作 `NULL`。
> **这篇讲什么**：树把"一个后继"放宽成"多个后继"，代价是不能再用下标算位置；二叉树再把"多个"收窄成"最多两个"，收窄之后冒出五条能算的性质，以及一种能直接用数组存的特例。
> **一个类比**：家族族谱。一个人可以有若干子女，子女又有各自的子女。想快速找到"某人的父亲"很容易，想快速找到"某人的第三个孩子"就得先翻一遍——存法决定了哪个方向便宜。


给你一棵二叉树，不画出来。

只告诉你：它有 12 个度为 2 的结点。

问：它有几个叶子？

答案是 13。

**形状完全不知道，答案却是唯一的。**

这就是树的性质的力量——它不用你把树画出来，就能算出一些必然成立的数。

**反直觉的点在这里：**

`n0 = n2 + 1` 和树的形状一点关系都没有。

一棵歪到天边的单支树，和一棵完美对称的满二叉树，只要度为 2 的结点数相同，叶子数就相同。

度数分布决定了叶子数，形状不决定。

## 1. 树：从"一对多"开始

**如果只有线性表，凡是"一个上级管多个下级"的关系，都只能靠额外的表去查。**

文件目录、公司组织架构、语法树、家谱，全是这种关系。

线性表存不了，因为它规定每个元素只有一个后继。

树的定义放宽了这一条：

```text
树（tree）是 n（n >= 0）个结点的有限集合。
n = 0 时叫空树。
n > 0 时：
  有且仅有一个特定的结点，叫根（root）。
  其余结点分成若干个互不相交的有限集，每个集合本身又是一棵树，
  叫根的子树（subtree）。
```

这是一个递归定义。

"子树本身又是一棵树"——所以树的很多算法天然是递归的。

画出来：

```text
            A
          / | \
         B  C  D
        / \     \
       E   F     G

A 是根。
B、C、D 是 A 的三棵子树的根。
E、F 是 B 的孩子。G 是 D 的孩子。
```

树和线性表的关系，一句话说清：

```text
线性表：每个结点最多一个前驱、最多一个后继。
树：    每个结点最多一个前驱（根没有）、可以有多个后继。
```

**"最多一个前驱"这一条没放宽。**

所以树里不存在"两个父亲"的结点，也不存在环。

这两条保证了树可以被递归地拆开，也保证了从根到任何结点只有一条路径。

最后这句很重要：**路径唯一**。

它是一切树上算法的前提——不用考虑"走哪条路更短"。

树在计算机里出现得极频繁。

```text
文件系统目录        每个目录可以有多个子目录
公司的组织架构      一个人管若干下属
编译器的语法树      一个表达式由子表达式组成
网页的 DOM          一个元素包含若干子元素
数据库的 B+ 树      一个索引结点指向几百个子结点
决策树、行为树      每个判断分出若干分支
```

这些例子的共同点：**同一层内部是排成一队的，层与层之间是一对多的。**

所以树的处理方式几乎总是"先处理当前结点，再对每个孩子递归"。

递归在这里不是炫技，是因为定义本身就是递归的。

**定义怎么写，代码就怎么写。**

这是树这一章最省力的地方：把定义抄成代码，基本就是对的。

## 2. 术语：度、层次、深度、森林

**如果不把这些词的定义钉死，题目里"树的度为 3"和"结点 A 的度为 3"会被当成同一件事。**

先列定义。

```text
结点的度（degree）：该结点拥有的子树个数。
树的度：树内所有结点度的最大值。
叶子（leaf）：度为 0 的结点，也叫终端结点。
分支结点：度不为 0 的结点，也叫非终端结点。
孩子（child）：结点的子树的根。
双亲（parent）：孩子的上层结点。
兄弟（sibling）：同一个双亲的结点。
堂兄弟：双亲在同一层的结点。
层次（level）：根为第 1 层，根的孩子为第 2 层，依次往下。
深度（depth）/ 高度（height）：结点的最大层次，也叫树的高度。
有序树 / 无序树：子树有左右次序之分 / 没有。
森林（forest）：m（m >= 0）棵互不相交的树的集合。
```

森林（forest）这个词看起来多余，其实很关键。

**把一棵树的根删掉，它的所有子树就构成一个森林。**

反过来，给一个森林加一个虚拟的根，就成了一棵树。

这个"加根/删根"的操作，是后面树与森林转换的基础。

### 三条能算的性质

树的性质不多，但每一条都能出题。

```text
性质一：树中结点数 = 所有结点的度数之和 + 1。
```

为什么？每条边贡献一个"度"，而 n 个结点的树有 n−1 条边。

一条边从双亲连到孩子，在孩子身上记一个度。

所以度数之和等于边数，等于 n − 1。

```text
性质二：度为 m 的树中，第 i 层最多有 m^(i-1) 个结点。
```

第 1 层只有根，1 个。

第 2 层最多 m 个（每个结点最多 m 个孩子）。

第 3 层最多 m² 个。

```text
性质三：高度为 h 的 m 叉树，最多有 (m^h − 1) / (m − 1) 个结点。
```

就是把性质二从第 1 层加到第 h 层，一个等比数列求和。

m = 2 时，`(2^h − 1) / 1 = 2^h − 1`，正好是后面二叉树的性质。

手算一道。

```text
一棵度为 3 的树，有 5 个度为 3 的结点、3 个度为 2 的结点、2 个度为 1 的结点。
求叶子结点个数。
```

```text
设叶子数为 n0。

结点总数 n = n0 + 2 + 3 + 5 = n0 + 10

度数之和 = 2×1 + 3×2 + 5×3 = 2 + 6 + 15 = 23
由性质一：n = 23 + 1 = 24

所以 n0 + 10 = 24，n0 = 14。
```

验算：叶子 14 个，总度数 23，总边数 23，结点数 24。

24 个结点、23 条边，正好是一棵树。

**这类题只有一招：把所有度数的贡献加起来，用"度数和 = 结点数 − 1"列一个方程。**

树还有两条容易忽略的补充定义。

```text
路径：从一个结点往下走到另一个结点，经过的结点序列。
      树中任意两个结点之间，路径唯一。
路径长度：路径上边的条数。
```

路径唯一这条性质，在图上就不成立。

图里两点之间可能有多条路径，所以图才有最短路径问题。

树没有这个问题，因为树里没有环。

**没有环，是树和图的根本区别。**

一棵有 n 个结点的树，恰好有 n−1 条边。

再加一条边，必然成环，就不再是树了。

这个数字关系后面会反复用到，也是很多题的突破口。

## 3. 树的存储：三种表示法

**如果只按"逻辑关系"存，不选一种明确的物理结构，代码根本写不出来。**

树的存储有三种主流表示法，各有各的便宜和贵。

### 3.1 双亲表示法

每个结点只记自己的双亲在哪。

```c
#define MAXSIZE 100

typedef struct {
    int data;        /* 数据 */
    int parent;      /* 双亲在数组中的下标，根为 -1 */
} PTNode;

typedef struct {
    PTNode nodes[MAXSIZE];
    int    n;        /* 结点个数 */
} PTree;
```

```text
下标:   0    1    2    3    4    5
data:   A    B    C    D    E    F
parent: -1   0    0    0    1    1

找 A 的孩子？扫一遍数组，看谁的 parent 是 0 → B、C、D
找 E 的双亲？O(1)，直接读 parent[4] = 1 → B
```

优点：找双亲 O(1)，实现极简。

缺点：找孩子要扫全表，O(n)。

**这正是"存法决定哪个操作便宜"的典型例子。**

### 3.2 孩子表示法

每个结点挂一条链表，链上全是它的孩子。

```c
typedef struct CNode {
    int child;              /* 孩子在数组中的下标 */
    struct CNode *next;     /* 下一个孩子 */
} CNode;

typedef struct {
    int data;
    CNode *firstchild;
} CTNode;

typedef struct {
    CTNode nodes[MAXSIZE];
    int n;
} CTree;
```

```text
0: A ──► [1] ──► [2] ──► [3]
1: B ──► [4] ──► [5]
2: C ──► ^
3: D ──► ^
4: E ──► ^
5: F ──► ^
```

优点：找孩子快，有几个孩子就遍历几个。

缺点：找双亲要扫全表。

**双亲和孩子的成本永远是一对反向的取舍。**

### 3.3 孩子兄弟表示法

这个最重要，因为它把一棵树变成了二叉树。

```c
typedef struct CSNode {
    int data;
    struct CSNode *firstchild;   /* 第一个孩子 */
    struct CSNode *nextsibling;  /* 右边的下一个兄弟 */
} CSNode, *CSTree;
```

规则只有一句：**左指针指第一个孩子，右指针指下一个兄弟。**

```text
原树：
        A
      / | \
     B  C  D
    / \
   E   F

孩子兄弟表示：
        A
       /
      B
     / \
    E   C
     \   \
      F   D
```

看到的是一棵二叉树，其实是原来那棵树。

**这就是"树转二叉树"的全部内容。**

它叫"二叉链表表示法"，也叫"左孩子右兄弟表示法"。

好处是：任何树都能用二叉树的存储结构存下来，一套代码通吃。

代价是：原来的"兄弟"关系变成了"右孩子"，看图时容易看错。

08 篇会专门讲这个转换的细节和遍历对应关系。

双亲表示法有个常见的改进：顺手把第一个孩子也记下来。

```c
typedef struct {
    int data;
    int parent;      /* 双亲下标 */
    int firstchild;  /* 第一个孩子下标 */
} PTNode2;
```

这样找双亲还是 O(1)，找第一个孩子也变成 O(1)。

想找第二个孩子，就得扫一遍全表，找"parent 相同且下标更大"的那个。

**这是很典型的折中：把最常用的操作做到 O(1)，其余保持 O(n)。**

数据结构里没有所有操作都快的结构，只有常用操作快的结构。

## 4. 二叉树：为什么限制两个孩子

**如果不限制孩子的个数，每个结点都要存一个变长的孩子列表，空间和代码都会变复杂。**

二叉树（binary tree）的定义：

```text
每个结点至多有两棵子树，且子树有左右之分，次序不能颠倒。
```

两个要点，缺一不可。

```text
要点一：至多两棵。可以 0 棵、1 棵、2 棵。
要点二：左右有序。左子树和右子树交换，就是另一棵二叉树。
```

第二条最容易忽略。

```text
    A              A
   /                \
  B                  B

这是两棵不同的二叉树。
```

如果左右不分，它们就是同一棵。

二叉树不是"度为 2 的树"。

这五个字是 408 的经典陷阱：

```text
二叉树的度可以小于 2（有叶子，有只有一个孩子的结点）。
度为 2 的树要求每个结点恰好有 2 个孩子，那是另一种东西。
```

二叉树还有五种基本形态：

```text
1. 空二叉树
2. 只有根
3. 只有左子树
4. 只有右子树
5. 左右子树都有
```

### 二叉树的性质

五条，全部要能默写。

```text
性质一：第 i 层最多有 2^(i-1) 个结点。
性质二：深度为 h 的二叉树最多有 2^h − 1 个结点（满二叉树）。
性质三：n0 = n2 + 1。                     ← 最重要
性质四：n 个结点的完全二叉树深度为 ⌊log2 n⌋ + 1。
性质五：完全二叉树按层编号后，结点 i 的左孩子是 2i，右孩子是 2i+1，双亲是 ⌊i/2⌋。
```

性质一、二是性质三的特殊情况，性质四、五专属于完全二叉树，下一节讲。

五种形态画出来是这样。

```text
(1) 空树      (2) 只有根    (3) 只有左子树  (4) 只有右子树  (5) 左右都有

   （无）         A             A               A             A
                               /                 \           / \
                              B                   B         B   C
```

(1) 和 (2) 经常被混。

空树是一个合法的二叉树，结点数是 0、高度是 0。

只有根的树结点数是 1、高度是 1。

408 问"空二叉树的高度是多少"，标准答案是 0。

**这一分很容易丢，因为它考的是定义而不是计算。**

还有一个容易忽略的点：**二叉树的子树仍然是二叉树。**

所以这个概念是自相似的，任何一棵子树的左右孩子关系，和整棵树完全一样。

递归算法能写得那么短，就是因为这个自相似性。

**每一层的问题，长得和总问题一模一样。**

## 5. 满二叉树与完全二叉树

**如果不定义"完全"，"用数组存二叉树"这件事就没有明确的适用边界。**

两个概念必须分清。

```text
满二叉树（full binary tree）：
  每一层的结点数都达到最大。深度 h 时有 2^h − 1 个结点。
  也就是：每个分支结点都有两个孩子。

完全二叉树（complete binary tree）：
  除最后一层外，每一层都满。
  最后一层的结点全部集中在左边，中间不能有空。
```

画出来对比。

```text
满二叉树（h=3，7 个结点）        完全二叉树（h=3，6 个结点）

        A                              A
      /   \                          /   \
     B     C                        B     C
    / \   / \                      / \   /
   D   E F   G                    D   E F

每个分支结点都有两个孩子。        最后一层的 F 靠左，右边空着。
```

再看一个**不是**完全二叉树的例子。

```text
        A
      /   \
     B     C
    / \     \
   D   E     F

F 在最后一层的右边，中间空了一个位置 → 不是完全二叉树。
```

判据只有一句：

```text
从上到下、从左到右编号 1, 2, 3, …，
如果编号能连续排到 n 而不出现空洞，就是完全二叉树。
```

满二叉树一定是完全二叉树，反之不成立。

**这个包含关系是单向的，别记反。**

完全二叉树为什么重要？

因为它的编号是连续的，可以用数组直接存，一个格子都不浪费。

普通二叉树没有这个性质——单支树要浪费一半以上的数组。

两个概念的结点数关系，可以精确写出来。

```text
深度 h 的满二叉树：结点数恰好 2^h − 1，叶子数 2^(h-1)。
深度 h 的完全二叉树：结点数在 [2^(h-1), 2^h − 1] 之间。
```

最后这条区间很实用。

拿 h = 10 试：结点数在 [512, 1023] 之间。

所以"一棵完全二叉树有 1000 个结点，高度是多少"，只需要看 1000 落在哪个区间。

```text
2^9 = 512 <= 1000 <= 1023 = 2^10 − 1
→ 高度是 10
```

反过来，"高度 10 的完全二叉树最少有多少个结点"，答案是 512。

**这两个方向的换算，是 408 里出现频率最高的完全二叉树题。**

## 6. n0 = n2 + 1：推导与手算

**如果不知道这个式子，凡是"给度数求叶子"的题都只能靠猜。**

先把式子写出来：

```text
对任何一棵非空二叉树：n0 = n2 + 1
```

n0 是叶子数（度为 0），n2 是度为 2 的结点数。

### 推导

只需要两个等式。

```text
等式一（按结点数）：
  n = n0 + n1 + n2

等式二（按边数）：
  树的边数 = n − 1
  另一方面，每条边由一个"孩子"贡献，而度为 i 的结点贡献 i 个孩子，
  所以边数 = 0×n0 + 1×n1 + 2×n2 = n1 + 2n2

联立：
  n0 + n1 + n2 − 1 = n1 + 2n2
  n0 − 1 = n2
  n0 = n2 + 1
```

推导里 **n1 被消掉了**。

这就是为什么叶子数只取决于 n2，和有没有单孩子结点无关。

```text
n1 可以是 0, 1, 2, …，随便多少，都不影响 n0 − n2 = 1。
```

**这是这一节最该记住的一句话。**

### 手算一：给度数求叶子

```text
一棵二叉树有 30 个结点，其中 5 个结点只有一个孩子。
求叶子数和度为 2 的结点数。
```

```text
n = 30，n1 = 5
n0 + n2 = 30 − 5 = 25
n0 = n2 + 1

代入：n2 + 1 + n2 = 25
      2n2 = 24
      n2 = 12
      n0 = 13
```

验算：13 + 5 + 12 = 30 ✔，13 = 12 + 1 ✔。

### 手算二：完全二叉树的三个量

```text
一棵完全二叉树有 1000 个结点，求它的高度、叶子数、度为 1 的结点数。
```

```text
高度：h = ⌊log2 1000⌋ + 1
      2^9 = 512 <= 1000 < 1024 = 2^10
      ⌊log2 1000⌋ = 9
      h = 10

叶子数：n0 = ⌈n / 2⌉ = ⌈1000 / 2⌉ = 500
      （完全二叉树的叶子只出现在最后两层，且 n0 = ⌈n/2⌉）

度为 1 的结点：n 为偶数时恰有 1 个，n 为奇数时为 0
      1000 是偶数 → n1 = 1

验证：n2 = n0 − 1 = 499
      n0 + n1 + n2 = 500 + 1 + 499 = 1000 ✔
```

三个量互相印证，说明没有算错。

**这类题的检查方法就是：算完之后用 n0 + n1 + n2 = n 回代一遍。**

### 手算三：767 个结点

```text
一棵完全二叉树有 767 个结点，求叶子数。
```

```text
767 是奇数 → n1 = 0
n0 + n2 = 767
n0 = n2 + 1

2n2 + 1 = 767
n2 = 383
n0 = 384
```

或者直接用 `n0 = ⌈767/2⌉ = 384`。

两条路答案一样，说明公式和推导是一致的。

## 7. 完全二叉树的编号性质

**如果编号不连续，用下标推父子关系这件事就无从谈起。**

完全二叉树按"从上到下、从左到右"编号，从 1 开始。

```text
              1
           /     \
          2       3
         / \     /
        4   5   6
       / \
      7   8
```

编号和位置的关系，四条：

```text
结点 i 的双亲：⌊i / 2⌋          （i = 1 时没有双亲）
结点 i 的左孩子：2i              （2i > n 时没有左孩子）
结点 i 的右孩子：2i + 1          （2i + 1 > n 时没有右孩子）
结点 i 所在层次：⌊log2 i⌋ + 1
```

这四条之所以成立，是因为编号本身就是"按层铺开"的顺序。

第 k 层有 2^(k-1) 个位置，编号从 2^(k-1) 到 2^k − 1。

所以 `i` 的二进制位数，就等于它所在的层数。

```text
i = 5，二进制 101，3 位 → 第 3 层。验证：⌊log2 5⌋ + 1 = 2 + 1 = 3 ✔
i = 8，二进制 1000，4 位 → 第 4 层。验证：⌊log2 8⌋ + 1 = 3 + 1 = 4 ✔
```

四条推论，考试常用：

```text
推论一：n 个结点的完全二叉树，叶子数 = ⌈n/2⌉，编号从 ⌊n/2⌋ + 1 到 n。
推论二：n 为偶数时恰有 1 个度为 1 的结点（编号 n/2），n 为奇数时为 0。
推论三：编号 i 是叶子 ⟺ 2i > n。
推论四：高度 h 的完全二叉树，结点数在 [2^(h-1), 2^h − 1] 之间。
```

手算一道，把编号性质用起来。

```text
完全二叉树有 1000 个结点。
问：(1) 编号 500 的结点有没有孩子？(2) 叶子结点的编号范围？
```

```text
(1) 左孩子编号 2 × 500 = 1000 <= 1000 → 有左孩子（编号 1000）。
    右孩子编号 1001 > 1000 → 没有右孩子。
    所以结点 500 只有左孩子，度为 1。

(2) 叶子 ⟺ 2i > 1000 ⟺ i > 500
    所以叶子编号是 501 到 1000，共 500 个。

和 n0 = ⌈1000/2⌉ = 500 一致。
```

注意 (1) 的结论：结点 500 正是那唯一一个度为 1 的结点。

`n/2 = 500`，正好对上推论二。

**这三条结论互相咬合，任一条算错，其余两条就对不上。**

## 8. 顺序存储：完全二叉树的特权

**如果用数组存一棵普通二叉树，最坏情况下要浪费一半以上的空间。**

顺序存储（sequential storage）就是用一个一维数组，按编号把结点放进去。

```c
#define MAXSIZE 100

typedef struct {
    int  data[MAXSIZE];   /* data[0] 不用，从 1 开始 */
    int  n;               /* 结点个数 */
} SqBiTree;
```

完全二叉树：

```text
        A(1)
      /      \
   B(2)      C(3)
   /  \      /
D(4) E(5)  F(6)

数组：[ _ | A | B | C | D | E | F ]
下标：   0   1   2   3   4   5   6

6 个结点，占用下标 1..6，一个格子都没浪费。
```

普通二叉树：

```text
        A(1)
      /      \
   B(2)      C(3)
     \         \
     D(5)      E(7)      ← 按完全二叉树的编号规则硬套

数组：[ _ | A | B | C | _ | D | _ | E ]
下标：   0   1   2   3   4   5   6   7

4 个结点，占了 8 个格子，浪费 4 个。
```

最坏情况是单支树。

```text
A
 \
  B
   \
    C
     \
      D

深度 4，需要 2^4 − 1 = 15 个格子，只存了 4 个结点。
利用率 4/15 ≈ 27%。
```

所以结论很明确：

```text
完全二叉树 → 顺序存储，零浪费，父子关系靠下标算，O(1)。
一般二叉树 → 链式存储，要多少结点分配多少。
```

**这正是"结构约束换存储效率"的一个干净例子。**

完全二叉树这个约束，就是为顺序存储量身定做的。

顺序存储的三个后果，值得列清楚。

```text
好处一：父子关系靠下标算，O(1)，不用存指针。
好处二：内存连续，遍历时缓存命中率高，实际跑得快。
坏处一：非完全二叉树会浪费大量空间，单支树时利用率可以低到百分之几。
坏处二：插入删除一个结点要整体搬动，O(n)。
坏处三：容量固定，结点数一变就要重新分配。
```

所以它只适合两种场景：

```text
完全二叉树，而且建成之后不再增删结点。
堆（heap）——它本身就必须是完全二叉树，用数组存是最优解。
```

堆排序、优先队列、哈夫曼编码的合并过程，底层全是"用数组存的完全二叉树"。

**这就是完全二叉树值得单独一节的理由：它有明确的工程用途，不只是一个考试定义。**

## 9. 二叉链表与三叉链表

**如果不给每个结点留两个指针，二叉树的"左右"就没地方记。**

链式存储最常用的是二叉链表（binary linked list）。

```c
typedef struct BiTNode {
    int  data;
    struct BiTNode *lchild;
    struct BiTNode *rchild;
} BiTNode, *BiTree;
```

```text
        ┌──────┬──────┬──────┐
        │lchild│ data │rchild│
        └──────┴──────┴──────┘
```

画一棵树。

```text
        A
      /   \
     B     C
    / \   /
   D   E F
```

```text
        A
       / \
      B   C
     / \  /
    D  E F

每个指针要么指向一个结点，要么是 NULL。
A 的左指针 → B，右指针 → C
B 的左指针 → D，右指针 → E
C 的左指针 → F，右指针 → NULL
D、E、F 的左右指针都是 NULL
```

### n+1 个空指针

数一数：n 个结点，2n 个指针域。

其中有多少个非空？每条边让一个指针非空，树有 n−1 条边。

所以空指针有：

```text
2n − (n − 1) = n + 1 个
```

**这个 n+1 是线索二叉树存在的全部理由。**

那么多空指针闲着，不如让它们指向"遍历时的前驱和后继"。

08 篇讲线索化，就是干这件事。

### 三叉链表

如果经常要找双亲，二叉链表就得从头搜。

三叉链表加一个 `parent` 指针。

```c
typedef struct TriTNode {
    int  data;
    struct TriTNode *lchild;
    struct TriTNode *rchild;
    struct TriTNode *parent;    /* 指向双亲 */
} TriTNode, *TriTree;
```

代价是多 n 个指针的空间，好处是找双亲 O(1)。

**还是那个取舍：多存一点，换一个操作变快。**

### 静态链表

如果不想用指针（考试环境、嵌入式），可以用数组模拟。

```c
typedef struct {
    int data;
    int lchild;      /* 存下标，-1 表示空 */
    int rchild;
} SNode;

SNode tree[MAXSIZE];
```

申请结点就是"从数组里取一个空闲下标"，释放就是"把下标还回去"。

好处是不用 `malloc`，坏处是要自己管理空闲下标。

408 里出现过这种问法：给一个静态链表数组，问某结点的左孩子是谁。

**解法就是把它当二叉链表看，只是把指针换成了下标。**

建树最常用的办法是"按先序序列递归建"。

```c
/* 按先序序列建树，'#' 表示空 */
BiTree CreateBiTree(void) {
    char ch = getchar();
    if (ch == '#') return NULL;

    BiTree T = (BiTree)malloc(sizeof(BiTNode));
    T->data   = ch;
    T->lchild = CreateBiTree();     /* 递归建左子树 */
    T->rchild = CreateBiTree();     /* 递归建右子树 */
    return T;
}
```

输入 `AB#D##C##` 得到的是：

```text
        A
       / \
      B   C
       \
        D
```

为什么这个序列能唯一建出树？

因为 `#` 把"空"也写进了序列，信息不再缺失。

**这正是"先序 + 后序不能还原"的反面：只要把空位置也记下来，一个序列就够了。**

这也是序列化的基本思路：把树写成一个字符串，读回来还能还原成一模一样的树。

## 10. 由先序加中序还原二叉树

**如果只会遍历不会还原，遇到"给两个序列画树"的题就只能干看着。**

先把三种遍历的规则钉死（08 篇细讲，这里只用来还原）。

```text
先序（preorder）：根 → 左 → 右
中序（inorder） ：左 → 根 → 右
后序（postorder）：左 → 右 → 根
```

还原的钥匙只有一条：

```text
先序的第一个元素，一定是根。
在中序里找到这个根，左边是左子树的中序，右边是右子树的中序。
中序分出的左右两段的长度，也就决定了先序里哪一段是左子树、哪一段是右子树。
```

递归地对每一段用这一条，树就唯一确定了。

**为什么唯一？** 因为"根"被先序钉死了，"左右怎么分"被中序钉死了，两者合起来信息完备。

### 手算：8 个结点的例子

```text
先序：A B D G C E H F
中序：D G B A E H C F
```

第一步，找根。

```text
先序第一个是 A → 根是 A。

在中序里找 A：
  中序：D G B  |  A  |  E H C F
        左子树      根     右子树

左子树有 3 个结点：D G B
右子树有 4 个结点：E H C F
```

第二步，切先序。

```text
先序去掉 A 之后：B D G | C E H F
                 前 3 个    后 4 个
左子树的先序：B D G
右子树的先序：C E H F
```

第三步，处理左子树。

```text
左子树先序 B D G → 根是 B
左子树中序 D G B → B 在最后，所以左子树没有右孩子，D G 全在 B 的左边

  B 的中序：D G | B | （空）
  B 的先序：D G

继续：根是 D
  D 的中序：D | （空）→ D 没有左孩子，G 在右边

  D 的先序：D G → 剩下的 G 是 D 的右孩子

左子树结构：
     B
    /
   D
    \
     G
```

第四步，处理右子树。

```text
右子树先序 C E H F → 根是 C
右子树中序 E H C F → C 在中间

  C 的中序：E H | C | F
  左子树 2 个结点：E H
  右子树 1 个结点：F

C 的先序：E H | F
左子树先序 E H，中序 E H
  → 根 E，E 没有左孩子，H 是 E 的右孩子

右子树只有一个 F，直接挂上。

右子树结构：
       C
      / \
     E   F
      \
       H
```

第五步，拼起来。

```text
              A
            /   \
           B     C
          /     / \
         D     E   F
          \     \
           G     H
```

第六步，验算。

```text
先序：A B D G C E H F      ✔ 对上了
中序：D G B A E H C F      ✔ 对上了
后序：G D B H E F C A      （顺便得出，可以用来出下一道题）
层序：A B C D E F G H
```

**还原完必须回代验算一次。**

只验先序不够，两个序列都对上，才算真的对了。

### 哪些组合能唯一确定

```text
先序 + 中序   → 能唯一确定
后序 + 中序   → 能唯一确定（后序的最后一个元素是根）
层序 + 中序   → 能唯一确定（层序的第一个元素是根）
先序 + 后序   → 不能唯一确定
```

最后一条是高频考点。

```text
先序 A B，后序 B A：
    A           A
   /             \
  B               B
两棵树先序都是 AB，后序都是 BA。分不出来。
```

原因：先序和后序都只能告诉你"谁是根"，但都不能告诉你"左右怎么分"。

中序的作用就是提供这个"分界点"。

**所以"先序 + 后序"永远不够，必须有一个中序。**

后序 + 中序的还原，只需要改一个观察点。

```text
先序的第一个元素是根。
后序的最后一个元素是根。
```

其余步骤一模一样：在中序里找到根，分出左右两段，再按长度切分后序。

举个例子。

```text
后序：D E B F C A
中序：D B E A F C
```

```text
后序最后一个是 A → 根 A。
中序：D B E | A | F C

左子树 3 个结点，右子树 2 个结点。
后序去掉 A：D E B | F C
            前 3 个  后 2 个

左子树：后序 D E B，中序 D B E
  根 B（后序最后）。中序 D | B | E
  左 D，右 E。

右子树：后序 F C，中序 F C
  根 C。中序 F | C → C 没有右孩子，F 是左孩子。

        A
       / \
      B   C
     / \ /
    D  E F
```

验算：先序 `A B D E C F`，中序 `D B E A F C`，后序 `D E B F C A`，全对。

**注意根的位置：先序在最前，后序在最后。**

除了这一处，两种还原的流程完全一样。

## 11. 408 怎么考

**如果不熟悉这四类题型，性质题会耗掉大量时间。**

```text
1. 给结点数或度数分布，求 n0、n1、n2、高度。
2. 完全二叉树的编号推断：某结点有无孩子、叶子范围、双亲是谁。
3. 由两个遍历序列还原二叉树，或判断某组合能否唯一确定。
4. 存储结构判断：顺序存储要多少空间、二叉链表有多少空指针。
```

### 例题一：给 n1 求 n0

```text
一棵二叉树有 20 个叶子，问度为 2 的结点有多少个？度为 1 的结点可能有多少个？
```

```text
n0 = 20
n0 = n2 + 1  →  n2 = 19

n1 无法确定，可以是 0, 1, 2, ...
n = 20 + n1 + 19 = 39 + n1

所以只能确定 n2 = 19，n1 任意。
```

这道题专门用来打"以为能算出 n1"的人。

**n1 是自由的，这是 n0 = n2 + 1 推导过程里被消掉的那个变量。**

### 例题二：完全二叉树编号

```text
一棵完全二叉树有 1001 个结点，求：
(1) 高度  (2) 叶子数  (3) 编号 500 的结点的双亲编号  (4) 最后一个分支结点的编号
```

```text
(1) 2^9 = 512 <= 1001 < 1024 = 2^10
    h = ⌊log2 1001⌋ + 1 = 9 + 1 = 10

(2) n0 = ⌈1001 / 2⌉ = 501
    验证：1001 是奇数 → n1 = 0
          n0 + n2 = 1001，n0 = n2 + 1
          2n2 + 1 = 1001 → n2 = 500, n0 = 501 ✔

(3) ⌊500 / 2⌋ = 250

(4) 最后一个分支结点 = ⌊n / 2⌋ = ⌊1001 / 2⌋ = 500
    验证：结点 500 的左孩子是 1000，右孩子是 1001，都有 → 是分支结点。
          结点 501 的左孩子是 1002 > 1001 → 是叶子。
```

### 例题三：先序 + 中序还原

```text
先序：A B C D E F
中序：C B A E D F
画出二叉树并写出后序。
```

```text
根 A。中序：C B | A | E D F

左子树：先序 B C，中序 C B
  根 B，中序 C | B → B 无右孩子，C 是 B 的左孩子

右子树：先序 D E F，中序 E D F
  根 D，中序 E | D | F
  左子树 E（单个），右子树 F（单个）

        A
       / \
      B   D
     /   / \
    C   E   F

后序：C B E F D A
```

验算后序：左子树 C B → `C B`；右子树 `E F D`；最后 `A`。

合起来 `C B E F D A` ✔

### 例题四：空指针个数

```text
一棵二叉树有 15 个结点，用二叉链表存储。问有多少个空指针域？
```

```text
空指针 = n + 1 = 15 + 1 = 16

验证：2n = 30 个指针域，非空的等于边数 = n − 1 = 14
      30 − 14 = 16 ✔
```

顺带一句：这 16 个空指针，正好可以拿来做线索化。

### 例题五：判断这样的二叉树是否存在

```text
一棵二叉树有 5 个结点，其中 2 个是叶子。这样的二叉树存在吗？
```

```text
n0 = 2 → n2 = n0 − 1 = 1
n1 = 5 − 2 − 1 = 2

n1 = 2 是允许的。存在，例如：

      A
     / \
    B   C
   /     \
  D       E

n0 = 2（D、E），n1 = 2（B、C），n2 = 1（A）
```

再问一个。

```text
一棵二叉树有 5 个结点，其中 3 个是叶子。存在吗？
```

```text
n0 = 3 → n2 = 2
n1 = 5 − 3 − 2 = 0

自洽。存在，例如：

        A
       / \
      B   C
     / \
    D   E

n0 = 3（C、D、E），n2 = 2（A、B），n1 = 0
```

判据只有一条：

```text
由 n0 定出 n2 = n0 − 1，
再要求 n1 = n − n0 − n2 >= 0。
```

不满足，就不存在。

**这类题看起来在考构造，其实在考 n0 = n2 + 1 加一个非负约束。**

## 12. 常见错误与真实系统

**如果不把这些坑过一遍，性质题会算得很顺但答案全错。**

```text
错误一：把"二叉树"当成"度为 2 的树"。
        二叉树的度可以是 0 或 1。

错误二：忽略左右子树的次序。
        左孩子和右孩子交换，是另一棵二叉树。

错误三：以为 n0 = n2 + 1 只对完全二叉树成立。
        它对所有非空二叉树成立。

错误四：以为可以同时算出 n1。
        n1 自由，只能由其他条件给出。

错误五：完全二叉树的高度公式写成 ⌈log2 n⌉。
        应为 ⌊log2 n⌋ + 1。n = 8 时：⌊3⌋+1 = 4 ✔，⌈3⌉ = 3 ✘。

错误六：以为"满二叉树"和"完全二叉树"可以互换。
        满的一定是完全的，完全的不一定是满的。
```

真实系统里，树到处都是。

```text
文件系统：目录树。每个目录的孩子个数不固定，用孩子兄弟表示法正好。
编译器的语法树：抽象语法树（AST），每个结点孩子数不同，多用"孩子列表"。
数据库索引：B+ 树是"多叉平衡树"，一个结点存几百个键。
DOM：浏览器的文档对象模型，就是一棵树。
决策树、行为树、渲染树：名字里带 tree 的，模型基本都是树。
```

有意思的是，工业界很少直接用"二叉树"存数据。

因为二叉树的一个结点只能有两个孩子，树会很高，访问一次要跳很多层。

真实系统更偏爱多叉树（B 树、B+ 树），一个结点塞满一个磁盘页或一个缓存行。

**二叉树的价值在"思想"和"教学"：**

```text
它的性质清晰、能算、能验证。
平衡二叉树、堆、哈夫曼树、二叉搜索树，全是二叉树的变种。
理解了二叉树，多叉树只是"每个结点多几个孩子指针"。
```

08 篇会把遍历、线索化和树/森林的转换讲完，那一篇是二叉树真正开始有用的时候。

### 自检三问

**第一问：一棵二叉树有 100 个结点，其中 30 个是叶子，求度为 2 的结点数。**

答：29。

由 `n0 = n2 + 1`，`n2 = n0 − 1 = 29`。

顺带：`n1 = 100 − 30 − 29 = 41`，可以用 `n0 + n1 + n2 = n` 回代验证。

**第二问：完全二叉树有 1000 个结点，编号 500 的结点有几个孩子？**

答：一个，只有左孩子。

左孩子编号 `2 × 500 = 1000`，存在；右孩子编号 `1001 > 1000`，不存在。

**第三问：给出先序 `AB` 和后序 `BA`，能否唯一确定这棵二叉树？**

答：不能。

它可能是 `A` 带左孩子 `B`，也可能是 `A` 带右孩子 `B`。

必须再给一个中序才能定下来。

## 13. 小结

这一篇的骨架是三组数。

```text
二叉树五条性质：
  第 i 层最多 2^(i-1) 个
  深度 h 最多 2^h − 1 个
  n0 = n2 + 1
  n 个结点的完全二叉树高 ⌊log2 n⌋ + 1
  完全二叉树：左孩子 2i，右孩子 2i+1，双亲 ⌊i/2⌋
```

```text
三个必须能算的量：
  n0 = ⌈n/2⌉            （完全二叉树）
  n1 = n % 2            （完全二叉树，0 或 1）
  空指针 = n + 1        （二叉链表）
```

```text
三种树的存储：
  双亲表示法：找双亲 O(1)，找孩子 O(n)
  孩子表示法：找孩子快，找双亲 O(n)
  孩子兄弟表示法：把树变成二叉树，左孩子右兄弟
```

```text
二叉树之所以值得单独研究，
是因为"最多两个孩子"这个约束，
把一棵形状自由的树，变成了一组可以精确计算的数。
```
