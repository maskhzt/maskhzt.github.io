> **读这篇之前，你只需要知道**：二叉树每个结点最多两个孩子，左右有序；`n` 个结点的二叉链表有 `n+1` 个空指针；递归是一个函数调用自己，必须有一个"不再递归"的出口。
> **这篇讲什么**：遍历是按某种顺序把树里的结点各访问一次；三种遍历的差别只在"根"被访问的时机；线索化是把空指针改造成"下一步该去哪"的指针；树和森林则靠"左孩子右兄弟"整棵搬进二叉树。
> **一个类比**：绕着一栋楼走一圈。你可以先看门牌再看房间（先序），也可以先看完左边所有房间再回头看门牌（中序），还可以最后才回来看门牌（后序）。走的是同一条路，只是"什么时候记录这一站"不同。


三种遍历的代码，骨架完全一样。

```c
void PreOrder(BiTree T)  { if (T) { visit(T); PreOrder(T->lchild); PreOrder(T->rchild); } }
void InOrder(BiTree T)   { if (T) { InOrder(T->lchild); visit(T); InOrder(T->rchild); } }
void PostOrder(BiTree T) { if (T) { PostOrder(T->lchild); PostOrder(T->rchild); visit(T); } }
```

三行，交换一下位置，就是三种遍历。

**反直觉的点在这里：**

先序、中序、后序不是三种算法。

它们是**同一段代码**里 `visit(T)` 这一行的三个位置。

左右子树的相对顺序从来没变过——永远是先左后右。

变的只有一件事：根什么时候被访问。

所以"中序"这个名字有误导性。

它不是"中间那个"，它是"根在中间"。

## 1. 遍历：把一棵树压成一串

**如果不定义遍历，树就只是一堆指针，无法比较、无法输出、无法存进文件。**

遍历（traversal）的定义：

```text
按某种确定的次序，把树中每个结点访问一次，且只访问一次。
```

两个要求：每个结点都访问到，每个结点只访问一次。

后者常被忽略，但它是"遍历"和"随便走走"的区别。

遍历为什么重要？

因为树是非线性的，但几乎所有的下游操作都要求线性：

```text
输出：屏幕是一行一行写的，必须有顺序。
比较：判断两棵树是否相同，得按同一顺序比。
存储：写进文件是一串字节，必须有顺序。
复制：深拷贝要按某个顺序逐个创建结点。
```

**遍历就是把非线性结构"压平"成线性序列的那道工序。**

压平之后，很多树上的问题就变成了序列上的问题。

比如"判断两棵树是否相同"，按先序压平再逐位比较就行。

比如"求树的深度"，遍历一遍，记下最大层数就行。

### 遍历的三种顺序从哪来

一棵二叉树有三部分：

```text
根（N）、左子树（L）、右子树（R）
```

遍历这三部分，共有 6 种排列：

```text
NLR  LNR  LRN  NRL  RNL  RLN
```

前三种是"先左后右"，后三种是"先右后左"。

数据结构只取前三种，并且规定左右不能换：

```text
NLR → 先序遍历（preorder）
LNR → 中序遍历（inorder）
LRN → 后序遍历（postorder）
```

后三种被丢掉，因为"先右后左"只是把镜像树遍历了一遍，信息量重复。

**所以遍历只有三种，这是设计选择，不是数学必然。**

压平的代价，也要说清楚。

一趟遍历只输出一个序列，序列里没有任何层级信息。

```text
        A                 A
       /                   \
      B                     B

两棵不同的树，先序都是 A B。
```

所以遍历序列是有损的。

要还原，必须两个序列配合：一个给根，一个给边界。

**记住这个不对称：树到序列很方便，序列到树需要额外信息。**

## 2. 三种递归遍历

**如果只背名字不理解"根在哪"，序列一定会写错。**

递归代码只有一行不同。

```c
typedef struct BiTNode {
    int  data;
    struct BiTNode *lchild, *rchild;
} BiTNode, *BiTree;

void visit(BiTNode *p) { printf("%c ", p->data); }

/* 先序：根 → 左 → 右 */
void PreOrder(BiTree T) {
    if (T == NULL) return;
    visit(T);
    PreOrder(T->lchild);
    PreOrder(T->rchild);
}

/* 中序：左 → 根 → 右 */
void InOrder(BiTree T) {
    if (T == NULL) return;
    InOrder(T->lchild);
    visit(T);
    InOrder(T->rchild);
}

/* 后序：左 → 右 → 根 */
void PostOrder(BiTree T) {
    if (T == NULL) return;
    PostOrder(T->lchild);
    PostOrder(T->rchild);
    visit(T);
}
```

三段的差别只在 `visit(T)` 的位置。

**第一行、中间行、最后一行——就这三种。**

递归的执行过程，本质是"沿着左链一路往下，然后在回来的路上做不同的事"。

```text
先序：往下走的时候访问。
中序：从左子树回来的时候访问。
后序：从左、右子树都回来之后访问。
```

用这棵树走一遍。

```text
              A
            /   \
           B     C
          / \   /
         D   E F
```

```text
先序：A → 左(B) → 左(D) → 右(E) → 右(C) → 左(F)
      结果：A B D E C F

中序：左(D) → B → 右(E) → A → 左(F) → C
      结果：D B E A F C

后序：左(D) → 右(E) → B → 左(F) → C → A
      结果：D E B F C A
```

验算的技巧：**中序序列里，根一定在左右子树中间；先序第一个、后序最后一个一定是根。**

三条检查一起做，错不了。

### 递归的三个要素

写树的算法，永远问三个问题：

```text
1. 出口是什么？——T == NULL 时返回。
2. 本层做什么？——visit(T)，或者更新某个全局量。
3. 交给下一层做什么？——对 lchild 和 rchild 递归。
```

把这三个问题答完，代码就写完了。

**树的算法之所以短，是因为"下一层的问题和本层长得一样"。**

这就是 07 篇说的自相似性。

## 3. 非递归遍历：为什么要用栈

**如果面试或考试要求"不用递归"，你就必须知道递归替我们保存了什么。**

递归函数被调用时，系统在栈上保存三样东西：

```text
返回地址（回到哪一行继续执行）
局部变量（T 是谁）
参数
```

对二叉树来说，最需要保存的是"**回来的时候该访问谁**"。

一路往左下走的时候，沿途的结点都得记下来，因为它们的"根"还没访问。

```text
        A
       /
      B
     /
    C

中序：先走到 C，访问 C，回来访问 B，再回来访问 A。
      回来的顺序是 C → B → A，正好是"先进后出"。
```

先进后出，就是栈。

所以中序的非递归写法是：

```c
void InOrder2(BiTree T) {
    BiTNode *stack[MAXSIZE];
    int top = 0;
    BiTNode *p = T;

    while (p != NULL || top > 0) {
        if (p != NULL) {
            stack[top++] = p;      /* 沿途压栈，等回来再访问 */
            p = p->lchild;         /* 一路向左 */
        } else {
            p = stack[--top];      /* 弹出：左边走完了，该访问它了 */
            visit(p);
            p = p->rchild;         /* 转向右子树 */
        }
    }
}
```

三句话概括：

```text
能往左就往左，边走边压栈。
走不动了，弹一个出来访问。
访问完，转向它的右子树。
```

这段代码比递归长，但它的好处是**栈的大小可控**。

递归的栈深度等于树高。

一棵退化成链的二叉树（单支树），树高等于结点数，递归会栈溢出。

非递归版本可以用固定大小的数组或者显式扩容，可控。

### 先序的非递归

先序只要把 `visit` 挪到"压栈之后"。

```c
void PreOrder2(BiTree T) {
    BiTNode *stack[MAXSIZE];
    int top = 0;
    BiTNode *p = T;

    while (p != NULL || top > 0) {
        if (p != NULL) {
            visit(p);              /* 一到这里就访问 */
            stack[top++] = p;
            p = p->lchild;
        } else {
            p = stack[--top];
            p = p->rchild;
        }
    }
}
```

### 后序的非递归最难

因为后序要求"左右都访问完，才访问根"。

从栈里弹出一个结点时，你分不清"我是从左子树回来的，还是从右子树回来的"。

三个常见解法：

```text
解法一：加一个 last 指针，记住上一个访问的结点。
解法二：每个结点入栈两次，第二次弹出时才访问。
解法三：按"根右左"的先序走一遍，把结果反过来。
```

解法三最简单，也最适合考场上写。

```c
/* 后序 = 根右左 的逆序 */
void PostOrder2(BiTree T) {
    BiTNode *s1[MAXSIZE], *s2[MAXSIZE];
    int t1 = 0, t2 = 0;

    if (T) s1[t1++] = T;
    while (t1 > 0) {
        BiTNode *p = s1[--t1];
        s2[t2++] = p;                  /* 存到第二个栈 */
        if (p->lchild) s1[t1++] = p->lchild;
        if (p->rchild) s1[t1++] = p->rchild;
    }
    while (t2 > 0) visit(s2[--t2]);    /* 倒着输出 */
}
```

**"正着走、倒着出"这个技巧，在树和图里都很常用。**

后序非递归的 last 指针解法也值得看一眼，因为它最直观。

```c
void PostOrder3(BiTree T) {
    BiTNode *stack[MAXSIZE];
    int top = 0;
    BiTNode *p = T, *last = NULL;

    while (p != NULL || top > 0) {
        while (p != NULL) { stack[top++] = p; p = p->lchild; }

        p = stack[top - 1];                  /* 看栈顶，先不弹 */
        if (p->rchild != NULL && p->rchild != last) {
            p = p->rchild;                   /* 右子树还没走，转过去 */
        } else {
            visit(p);                        /* 左右都走完了 */
            last = p;
            top--;                           /* 这时才真正弹出 */
            p = NULL;                        /* 强制下一轮继续弹栈 */
        }
    }
}
```

`last` 的作用是回答那个问题：刚才是从左子树回来的，还是从右子树回来的？

```text
p->rchild == last  → 右子树刚访问完 → 该访问 p 了
p->rchild != last  → 右子树还没走   → 转过去
```

**这个"记住上一步"的技巧，在树的迭代算法里到处都是。**

## 4. 层序遍历：为什么要用队列

**如果只用栈，你永远走不出"一条路走到黑"的模式。**

先序、中序、后序都是深度优先——先钻到底，再回头。

层序遍历（level order）是广度优先——一层一层往下扫。

```text
              A
            /   \
           B     C
          / \   /
         D   E F

层序：A B C D E F
```

它要的是"先来先服务"，所以用队列。

```c
void LevelOrder(BiTree T) {
    BiTNode *queue[MAXSIZE];
    int front = 0, rear = 0;

    if (T == NULL) return;
    queue[rear++] = T;                 /* 根入队 */

    while (front != rear) {
        BiTNode *p = queue[front++];   /* 队头出队 */
        visit(p);

        if (p->lchild) queue[rear++] = p->lchild;
        if (p->rchild) queue[rear++] = p->rchild;
    }
}
```

四步，循环往复：

```text
出队一个，访问它。
把它的左孩子入队。
把它的右孩子入队。
队列空了就结束。
```

注意 `rear` 要用取模，否则数组会越界。

这里为了看清逻辑，用了足够大的数组和简单的自增。

层序遍历有一个直接用途：**求树的高度**。

```c
int TreeHeight(BiTree T) {
    if (T == NULL) return 0;

    BiTNode *queue[MAXSIZE];
    int front = 0, rear = 0, level = 0, levelEnd;

    queue[rear++] = T;

    while (front != rear) {
        levelEnd = rear;               /* 本层的最后一个位置 */
        while (front < levelEnd) {     /* 只处理本层 */
            BiTNode *p = queue[front++];
            if (p->lchild) queue[rear++] = p->lchild;
            if (p->rchild) queue[rear++] = p->rchild;
        }
        ++level;
    }
    return level;
}
```

**核心技巧是"记住本层的边界"。**

不加 `levelEnd`，你就分不清"刚出队的是第几层"。

这个"分层"的技巧，在图 BFS 求最短路径时会再出现一次。

## 5. 由遍历序列还原二叉树

**如果不知道哪两个序列能定树，考场上会拿"先序 + 后序"去硬凑，凑半天发现不唯一。**

07 篇已经讲过先序 + 中序的还原，这里把它系统化，并补上后序的变式。

四种组合的结论：

```text
先序 + 中序   → 唯一
后序 + 中序   → 唯一
层序 + 中序   → 唯一
先序 + 后序   → 不唯一
```

原因一句话：

```text
先序、后序、层序都能确定"谁是根"。
只有中序能确定"根的左边有几个、右边有几个"。
```

既然根和分界都要，就**必须有一个中序**。

### 手算：6 个结点的还原

```text
先序：A B D E C F
中序：D B E A C F
```

```text
第一步：先序第一个是 A → 根 A
        中序：D B E | A | C F
              左 3 个      右 2 个

第二步：切先序
        去掉 A：B D E | C F
                前 3    后 2
        左子树先序 B D E，右子树先序 C F

第三步：左子树
        先序 B D E → 根 B
        中序 D B E → D | B | E
        左 D（单个），右 E（单个）

第四步：右子树
        先序 C F → 根 C
        中序 C F → C 在第一位 → C 没有左孩子，F 在右边
        所以 F 是 C 的右孩子

第五步：拼起来

              A
            /   \
           B     C
          / \     \
         D   E     F
```

```text
第六步：验算
        先序：A B D E C F   ✔
        中序：D B E A C F   ✔
        后序：D E B F C A   （顺便得出）
        层序：A B C D E F
```

**还原完必须验算两个序列，只验一个不够。**

### 层序 + 中序的还原

层序的用法和后序不同：它不是"第一个/最后一个"，而是"**在剩下的元素里，第一个出现的**"。

```text
层序：A B C D E F
中序：D B E A C F
```

```text
层序第一个 A → 根 A
中序：D B E | A | C F

左子树的结点集合 = {D, B, E}
在层序里按顺序找这些结点，第一个是 B → 左子树的根是 B
右子树的结点集合 = {C, F}
在层序里第一个是 C → 右子树的根是 C

继续递归，规律一样：
  对每个子树，在层序里"第一个属于这个子树的结点"就是它的根。
```

这就是层序还原的核心：**层序提供"谁先被访问"，中序提供"边界在哪"。**

还原还可以写成统一的递归函数，参数就是两个区间。

```c
/* pre[pl..pr] 是先序，in[il..ir] 是中序 */
BiTree Build(int *pre, int pl, int pr, int *in, int il, int ir) {
    if (pl > pr) return NULL;

    int root = pre[pl];                  /* 先序的第一个是根 */
    int k = il;
    while (in[k] != root) k++;           /* 在中序里定位 */
    int leftLen = k - il;                /* 左子树结点数 */

    BiTree T = (BiTree)malloc(sizeof(BiTNode));
    T->data   = root;
    T->lchild = Build(pre, pl + 1, pl + leftLen, in, il, k - 1);
    T->rchild = Build(pre, pl + leftLen + 1, pr, in, k + 1, ir);
    return T;
}
```

四个下标范围要把准：

```text
先序左子树：pl+1         到 pl+leftLen
先序右子树：pl+leftLen+1 到 pr
中序左子树：il           到 k-1
中序右子树：k+1          到 ir
```

`leftLen` 是枢纽——它把先序里"哪些属于左子树"切出来。

**所有由两个序列还原的题，本质都是这一件事：用中序确定长度，用长度切另一个序列。**

## 6. 线索：把空指针利用起来

**如果不做线索化，中序遍历的非递归版本就得自己维护一个栈。**

而那个栈，本质上存的是"我下一步该去哪"。

07 篇算过一个数：`n` 个结点的二叉链表，有 `n+1` 个空指针。

```text
2n 个指针域，n−1 个非空，剩下的 n+1 个全是 NULL。
```

这些 NULL 什么信息也没有，纯浪费。

线索（thread）的想法很直接：

```text
既然空着，就让它们指向"遍历时的前驱和后继"。
```

改造后的结点长这样：

```c
typedef struct ThreadNode {
    int  data;
    struct ThreadNode *lchild, *rchild;
    int  ltag, rtag;              /* 标志位：0 表示指向孩子，1 表示指向线索 */
} ThreadNode, *ThreadTree;
```

标志位的含义，必须记死：

```text
ltag = 0：lchild 指向左孩子
ltag = 1：lchild 指向前驱（线索）

rtag = 0：rchild 指向右孩子
rtag = 1：rchild 指向后继（线索）
```

**0 是"真的孩子"，1 是"假的，其实是线索"。**

这个记法可以用一句话辅助：0 像字母 O，是"原装"；1 像字母 I，是"接上去的"。

### 线索二叉树有几种

按线索化的顺序分三种：

```text
中序线索二叉树：空指针指向中序序列里的前驱/后继。最常用。
先序线索二叉树：按先序。
后序线索二叉树：按后序。
```

中序最常用，因为中序线索树上找前驱和后继都不需要额外的父指针。

这一点下一节会算。

**关键认知：线索化不改变树的形状，也不改变遍历的结果。**

它改变的是"能不能不用栈、不用递归，直接走到下一个结点"。

```text
普通二叉树：从结点 A 想找它的中序后继，必须从根重新走一遍，O(n)。
中序线索树：O(1) 或 O(h)，绝大多数情况 O(1)。
```

**这就是线索的价值：把"重新找路"变成"顺着线走"。**

## 7. 中序线索化的过程与代码

**如果只记住了 tag 的含义，不知道 tag 是怎么填的，手算题一定错。**

线索化就是一次中序遍历。

在遍历过程中，把空指针改成线索，把标志位改成 1。

```c
ThreadNode *pre = NULL;        /* 全局：上一个访问的结点 */

void InThread(ThreadTree p) {
    if (p == NULL) return;

    InThread(p->lchild);       /* 递归左子树 */

    if (p->lchild == NULL) {   /* 左空 → 指向前驱 */
        p->lchild = pre;
        p->ltag = 1;
    }
    if (pre != NULL && pre->rchild == NULL) {   /* 前驱的右空 → 指向后继 */
        pre->rchild = p;
        pre->rtag = 1;
    }
    pre = p;                   /* 更新 pre */

    InThread(p->rchild);       /* 递归右子树 */
}
```

三个要点。

```text
要点一：`pre` 必须是全局变量（或者用二级指针），因为递归里要跨层传递。
要点二：改前驱的右指针时，改的是 `pre` 的，不是 `p` 的。
        原因：访问到 p 时，p 的后继还不知道是谁。
要点三：最后要把 pre 的 rchild 收尾（它是最右下的结点，后继为空）。
```

第三点常被漏。

```c
void CreateInThread(ThreadTree T) {
    pre = NULL;
    if (T != NULL) {
        InThread(T);
        if (pre->rchild == NULL)     /* 处理最后一个结点 */
            pre->rtag = 1;
    }
}
```

### 手算：把每个 tag 填出来

用这棵树。

```text
              A
            /   \
           B     C
          / \   /
         D   E F
```

先写出中序序列。

```text
中序：D B E A F C
```

逐个结点填表。

```text
结点   左指针            ltag   右指针            rtag
-------------------------------------------------------
D      NULL（无前驱）      1     → B（后继）        1
B      → D（左孩子）       0     → E（右孩子）      0
E      → B（前驱）         1     NULL？不对 ——>      1
F      → A（前驱）         1     → C（后继）        1
C      → F（左孩子）       0     NULL（无后继）      1
A      → B（左孩子）       0     → C（右孩子）      0
```

上面故意留了一处要看清楚的地方：**E 有没有孩子？**

```text
看原树：E 是 B 的右孩子，E 没有孩子。
所以 E 的左右指针都是空的：
  E.lchild = NULL → ltag = 1 → 指向前驱 B（中序里 E 前面是 B）
  E.rchild = NULL → rtag = 1 → 指向后继 A（中序里 E 后面是 A）
```

整理成完整正确的表：

```text
结点   lchild        ltag   rchild        rtag   说明
--------------------------------------------------------------
D      NULL           1     B              1     中序第一个，无前驱
B      D              0     E              0     两个孩子都在
E      B              1     A              1     叶子，前后都是线索
A      B              0     C              0     两个孩子都在
F      A              1     C              1     叶子，前后都是线索
C      F              0     NULL           1     中序最后一个，无后继
```

三条自检：

```text
1. 线索数（tag=1 的指针）应该等于空指针数 = n+1 = 7。
   数一数：D 两个、E 两个、F 两个、C 一个 = 7 ✔

2. 第一个结点（D）的 ltag 必为 1 且 lchild 为 NULL。
3. 最后一个结点（C）的 rtag 必为 1 且 rchild 为 NULL。
```

**第 1 条是最硬的检查：线索总数一定等于 n+1。**

算出来不是 n+1，就是填错了。

## 8. 线索树上找前驱与后继

**如果没有这套规则，线索树就只是"多了两个标志位"，一点用也没有。**

中序线索树上找后继，分两种情况。

```text
情况一：rtag == 1
        后继就是 rchild，一步到位。

情况二：rtag == 0
        说明 rchild 是右孩子，右子树还在。
        中序里，右子树的最左下结点就是后继。
        所以：从 rchild 出发，一路往左走，直到某个结点的 ltag == 1。
```

```c
ThreadNode *InOrderNext(ThreadNode *p) {
    if (p->rtag == 1) return p->rchild;      /* 线索，直接给 */

    ThreadNode *q = p->rchild;               /* 右子树中最左下的结点 */
    while (q->ltag == 0) q = q->lchild;
    return q;
}
```

找前驱是镜像的。

```text
情况一：ltag == 1 → 前驱是 lchild。
情况二：ltag == 0 → 前驱是左子树中最右下的结点。
```

```c
ThreadNode *InOrderPrev(ThreadNode *p) {
    if (p->ltag == 1) return p->lchild;

    ThreadNode *q = p->lchild;               /* 左子树中最右下的结点 */
    while (q->rtag == 0) q = q->rchild;
    return q;
}
```

### 手算验证

用上一节那棵线索树。

```text
问一：A 的中序后继是谁？
      A.rtag = 0 → 走右子树，从 C 出发往左找
      C 的 ltag = 0，往左走到 F
      F 的 ltag = 1，停
      后继是 F。

      查中序序列：D B E A F C，A 后面确实是 F ✔

问二：A 的中序前驱是谁？
      A.ltag = 0 → 走左子树，从 B 出发往右找
      B 的 rtag = 0，往右走到 E
      E 的 rtag = 1，停
      前驱是 E。

      查中序序列，A 前面确实是 E ✔

问三：E 的后继是谁？
      E.rtag = 1 → 直接是 rchild = A ✔

问四：C 的后继是谁？
      C.rtag = 1 且 rchild = NULL → 没有后继（C 是中序最后一个）✔
```

有了 `InOrderNext`，中序遍历就不需要栈了。

```c
void InOrderThread(ThreadTree T) {
    ThreadNode *p = T;
    if (p == NULL) return;

    while (p->ltag == 0) p = p->lchild;    /* 找到中序第一个结点 */

    while (p != NULL) {
        visit(p);
        p = InOrderNext(p);                /* 顺着线索走 */
    }
}
```

**两段代码，一个栈都没用。**

这就是线索二叉树存在的全部意义。

### 先序和后序的线索

先序线索找后继，规则不同：

```text
ltag == 0 → 后继是 lchild（先序里根后面就是左子树）
ltag == 1 且 rtag == 0 → 后继是 rchild
ltag == 1 且 rtag == 1 → 后继是 rchild（线索）
```

注意后两种情况可以合并成"后继是 rchild"。

```text
先序后继：有左孩子就是左孩子，否则就是 rchild。
```

后序线索最麻烦。

```text
后序序列是"左 右 根"，找后继需要知道"我是不是右孩子"。
线索本身给不出这个信息，所以后序线索树必须带 parent 指针。
```

**这也是为什么中序线索最常用：它不需要额外的父指针。**

408 考线索，99% 考中序。

先序线索找后继，手算一遍就清楚了。

```text
              A
            /   \
           B     C
          / \   /
         D   E F

先序：A B D E C F
```

```text
问：D 的先序后继是谁？
      D.ltag = 1（没有左孩子），D.rtag = 1（没有右孩子）
      → 后继是 rchild，也就是线索指向的 E
      查序列 A B D E C F，D 后面是 E ✔

问：B 的先序后继是谁？
      B.ltag = 0（有左孩子 D）
      → 有左孩子，后继就是左孩子 D
      查序列，B 后面是 D ✔

问：E 的先序后继是谁？
      E.ltag = 1，E.rtag = 1
      → 后继是 rchild 线索，指向 C
      查序列，E 后面是 C ✔
```

规律很好记：

```text
先序是"根 左 右"，所以：
有左孩子就去左孩子；
没有左孩子就去右孩子（不管是真孩子还是线索）。
```

和找中序后继对比一下：中序要"往左下钻到底"，先序只需一步。

**三种线索树的找法各不相同，因为线索只回答"该顺序下的下一个是谁"。**

顺序一变，答案就变。

## 9. 树、森林与二叉树的转换

**如果不做转换，就得给树和森林各写一套遍历、一套存储，代码量翻倍。**

07 篇提过孩子兄弟表示法：左指针指第一个孩子，右指针指下一个兄弟。

这一节把它变成一套完整的转换规则。

先把森林这个词再钉一次：

```text
森林（forest）：m（m >= 0）棵互不相交的树的集合。
把一棵树的根删掉，它的所有子树就构成一个森林。
给一个森林加一个虚拟的根，就成了一棵树。
```

树、森林、二叉树三者之间，可以两两互转，而且可逆。

**可逆这件事很关键：它意味着只需要维护一套二叉树代码。**

### 树转二叉树

三条规则，按顺序做：

```text
规则一：每个结点，把它的第一个孩子变成它的左孩子。
规则二：把它的其余孩子，依次变成前一个孩子的右孩子（也就是右兄弟链）。
规则三：原来的"兄弟"关系，全部变成"右孩子"关系。
```

举个例子。

```text
原树：
         A
       / | \
      B  C  D
     / \     |
    E   F    G
```

```text
第一步：A 的第一个孩子是 B → A 的左孩子是 B
第二步：B、C、D 是兄弟 → 依次挂成右链：B 的右孩子是 C，C 的右孩子是 D
第三步：B 的第一个孩子是 E → B 的左孩子是 E
        E、F 是兄弟 → E 的右孩子是 F
第四步：D 的第一个孩子是 G → D 的左孩子是 G

结果：
        A
       /
      B
     / \
    E   C
     \   \
      F   D
         /
        G
```

检查一下规则有没有用错：

```text
A 没有兄弟 → A 没有右孩子 ✔（树转成的二叉树，根一定没有右子树）
B 的右孩子是 C（兄弟）✔
C 的右孩子是 D（兄弟）✔
E 的右孩子是 F（兄弟）✔
G 没有兄弟、没有孩子 → G 是叶子 ✔
D 的左孩子是 G（G 是 D 的第一个孩子），D 的右指针为空 ✔
```

注意 G 挂在 D 的**左边**。

孩子关系走左指针，兄弟关系走右指针，这两条线不能混。

**"树转成的二叉树，根没有右子树"——这一条是树和森林的分界线。**

树的根只有一个，没有兄弟，所以右指针空。

森林有多棵树的根，它们互为兄弟，所以右指针不空。

### 森林转二叉树

规则只有一句：**把每棵树的根当成兄弟。**

```text
森林：
  T1:  A         T2:  X
      / \             |
     B   C            Y

第一步：各棵树内部按"树转二叉树"处理
第二步：把 T1 的根 A 和 T2 的根 X 当成兄弟 → A 的右孩子是 X

结果：
        A
       / \
      B   X
       \   \
        C   Y
```

验算：

```text
A 没有右孩子吗？有，右孩子是 X（另一棵树的根）。
所以"根有右子树"说明这是森林转来的，不是单棵树。
```

**这条判据反过来用，就是二叉树转森林的依据。**

```text
二叉树转树：根的右子树为空 → 是一棵树转来的。
二叉树转森林：根的右子树不为空 → 断开右链，每一条链是一棵树。
```

### 二叉树转回树/森林

规则是上面三条的逆操作：

```text
规则一：若结点是双亲的左孩子，把它的右链上所有结点，都变成双亲的孩子。
规则二：断开所有"右孩子"连线。
规则三：剩下的连线就是原来的树。
```

拿上面那棵二叉树试。

```text
        A
       /
      B
     / \
    E   C
     \   \
      F   D
         /
        G

B 是 A 的左孩子 → B 的右链（B → C → D）都变成 A 的孩子
E 是 B 的左孩子 → E 的右链（E → F）都变成 B 的孩子
G 是 D 的左孩子 → G 的右链只有它自己 → G 是 D 的孩子

断掉右链，得到：
         A
       / | \
      B  C  D
     / \     |
    E   F    G
```

和原树一致。

**转换是双向的、可逆的，这一点很重要。**

它意味着：任何树和森林，都可以用同一套二叉树的代码去处理。

## 10. 树与森林的遍历

**如果不把遍历对应起来，你会在"树的先根遍历"和"二叉树的先序遍历"之间反复怀疑自己。**

树的遍历只有两种（因为没有"中"这个概念——孩子不分左右）。

```text
先根遍历：先访问根，再依次先根遍历每棵子树。
后根遍历：先依次后根遍历每棵子树，最后访问根。
```

森林的遍历也是两种：

```text
先序遍历：依次先序遍历每棵树。
中序遍历（也叫后序遍历）：依次后序遍历每棵树。
```

**对应关系是这一节的全部考点：**

```text
树的先根遍历  ==  对应二叉树的先序遍历
树的后根遍历  ==  对应二叉树的中序遍历

森林的先序遍历 ==  对应二叉树的先序遍历
森林的中序遍历 ==  对应二叉树的中序遍历
```

### 手算验证

还用 9.1 节那棵树。

```text
原树：
         A
       / | \
      B  C  D
     / \     |
    E   F    G

树的先根遍历：A → B → E → F → C → D → G
  （A 先访问；然后第一棵子树 B：B 先访问，再 E，再 F；然后 C；然后 D，再 G）

树的后根遍历：E → F → B → C → G → D → A
  （B 的子树：E、F 都完成后访问 B；D 的子树 G 完成后访问 D；最后 A）
```

对应的二叉树：

```text
        A
       /
      B
     / \
    E   C
     \   \
      F   D
         /
        G
```

```text
二叉树先序：A → B → E → F → C → D → G      ✔ 和树的先根遍历一样
二叉树中序：E → F → B → C → G → D → A      ✔ 和树的后根遍历一样
```

完全对上。

**为什么？**

因为"左孩子"就是"第一个孩子"，"右孩子"就是"下一个兄弟"。

```text
先序：根 → 左（第一个孩子）→ 右（下一个兄弟）
      正好是"先自己，再孩子，再兄弟"，和先根遍历一个意思。

中序：左（第一个孩子及其后代）→ 根 → 右（兄弟）
      先处理完自己的所有孩子，再处理自己，再处理兄弟。
      这正是后根遍历的顺序。
```

**理解了这两行，对应关系就不用背了。**

森林的遍历，用两棵树手算一遍。

```text
森林：
  T1:  A           T2:  X
      / \               |
     B   C              Y

先序遍历森林：A B C X Y
  （先序 T1：A B C；再先序 T2：X Y）

中序遍历森林：B C A Y X
  （中序 T1：B C A；再中序 T2：Y X）
```

转成二叉树。

```text
        A
       / \
      B   X
       \   /
        C Y
```

这里有一个极易犯的错。

```text
X 是第二棵树的根，它挂在 A 的右边（作为"兄弟"）。
但 X 自己是有孩子的：Y 是 X 的第一个孩子。

孩子关系走左指针，兄弟关系走右指针。
所以 X 的左孩子是 Y，X 的右孩子（下一个兄弟）是空。
```

验算二叉树中序。

```text
中序：B C A Y X
  B 没有左孩子 → B
  B 的右孩子 C → C（C 没有孩子）→ 得 B C
  根 A
  右子树：先中序 X 的左子树 Y → Y，再 X → 得 Y X
  总数：B C A Y X ✔
```

和森林的中序遍历完全一致。

**记住这条判据：右链上是兄弟，左指针下是孩子。**

## 11. 408 怎么考

**如果不熟这五类题型，遍历题会做但线索题一定丢分。**

### 例题一：写三种序列

```text
              A
            /   \
           B     C
          / \     \
         D   E     F
            /
           G
写出先序、中序、后序、层序。
```

```text
先序：A B D E G C F
中序：D B G E A C F
后序：D G E B F C A
层序：A B C D E F G
```

逐个验算：

```text
先序：A，然后左子树（B，然后 D，然后 E 的左 G）→ A B D E G，
      然后右子树（C，无左，右 F）→ C F
      得 A B D E G C F ✔

中序：左子树的中序 = D B G E
      （D、B、G、E：B 的左 D，B 的右 E，E 的左 G）
      根 A，右子树中序 = C F
      得 D B G E A C F ✔

后序：左子树后序 = D G E B，右子树后序 = F C
      最后 A
      得 D G E B F C A ✔
```

### 例题二：线索数

```text
一棵二叉树有 20 个结点，做中序线索化。问有多少个线索（tag=1 的指针）？
```

```text
线索数 = 空指针数 = n + 1 = 21

验证：2n = 40 个指针域，非空的等于边数 = 19
      40 − 19 = 21 ✔
```

### 例题三：找中序后继

```text
接上题那棵树，问：结点 C 的中序后继是谁？结点 E 的中序前驱是谁？
```

```text
中序序列：D B G E A C F

C 的后继是 F。
推理：C.rtag = 0（有右孩子 F），所以走右子树最左下 → F 没有左孩子 → F。

E 的前驱是 G。
推理：E.ltag = 0（有左孩子 G），走左子树最右下 → G 没有右孩子 → G。
      查序列，E 前面确实是 G ✔
```

### 例题四：树转二叉树并写遍历

```text
         A
       / | \
      B  C  D
     /
    E

转成二叉树，写出二叉树的先序和中序。
```

```text
转换：
  A 的左孩子 = B（第一个孩子），B 的右孩子 = C，C 的右孩子 = D
  B 的左孩子 = E（第一个孩子）

        A
       /
      B
     / \
    E   C
         \
          D

二叉树先序：A B E C D
二叉树中序：E B C D A

对应的树：
  树的先根遍历 = A B E C D ✔
  树的后根遍历 = E B C D A ✔
```

验算树的后根遍历：

```text
B 的子树：E 完成 → 访问 B → E B
C：C
D：D
最后 A
得 E B C D A ✔
```

### 例题五：遍历的应用

```text
写一个函数，统计二叉树中度为 1 的结点个数。
```

```c
int CountOneChild(BiTree T) {
    if (T == NULL) return 0;

    int self = 0;
    if ((T->lchild == NULL) != (T->rchild == NULL))   /* 恰好一个为空 */
        self = 1;

    return self + CountOneChild(T->lchild) + CountOneChild(T->rchild);
}
```

```text
核心写法：本层的贡献 + 左子树的贡献 + 右子树的贡献。

这个模板可以套到几乎所有"统计"类题目上：
  求结点总数 → self = 1
  求叶子数   → self = （左右都空）
  求深度     → 返回 1 + max(左, 右)
  判断相等   → 返回 左 && 右 && 数据相等
```

**"本层 + 左 + 右"是树上的万能递归模板。**

## 12. 常见错误与真实系统

**如果不把这些坑走一遍，遍历序列能写对，但线索和转换会连环错。**

```text
错误一：把中序写成"先左再右再根"。
        那是后序。中序是"左 根 右"。

错误二：以为中序就是"中间层"。
        中序说的是"根在中间"，和层数无关。

错误三：非递归中序里忘了判 p != NULL || top > 0。
        只判一个条件，循环会提前退出或死循环。

错误四：线索化时改错了对象。
        要改 pre 的右指针，不是 p 的。

错误五：以为线索化会让遍历变快。
        它省的是栈空间和"重新找路"的开销，
        单次访问的复杂度还是 O(1)，整体还是 O(n)。

错误六：认为"先序 + 后序"能唯一确定二叉树。
        不能。必须有一个中序。

错误七：树转二叉树后，以为根可以有右子树。
        单棵树转来的二叉树，根一定没有右子树。
```

真实系统里，遍历的变体比教科书多得多。

```text
文件系统的遍历：
  find 命令默认是深度优先（先序）。
  du 统计目录大小必须先算完子目录，是后序。

编译器的语法树：
  求值用后序（先算子表达式，再算运算符）。
  类型检查用先序或中序（先确定上下文，再检查内部）。

JSON / XML 的序列化：
  本质是先序遍历，遇到空孩子写一个占位符。

DOM 的事件传播：
  捕获阶段是先序（从外到内），冒泡阶段是后序（从内到外）。
```

线索二叉树在工业界用得不多，但它的思想到处都是。

```text
"把空指针利用起来" → 这就是所有"指针标记"技巧的源头。
"顺着线索 O(1) 找后继" → 迭代器（iterator）的本质。
```

C++ 的 `std::map` 迭代器 `++it` 是 O(1) 摊还，靠的就是在红黑树结点里多存一个父指针，或者用线索化的思路。

**"下一个是谁"这个问题，一旦能 O(1) 回答，整棵树的遍历就变成了一个链表扫描。**

这是线索化真正的启发。

### 自检三问

**第一问：一棵二叉树有 100 个结点，中序线索化后有多少个线索？**

答：101 个。

线索数 = 空指针数 = n + 1。

**第二问：中序线索树里，结点 p 的 rtag = 0，它的中序后继在哪？**

答：在右子树的最左下角。

从 `p->rchild` 出发，一路往左走，直到某个结点的 `ltag == 1`，那个结点就是后继。

如果 `rtag == 1`，后继就是 `p->rchild` 本身。

**第三问：树的先根遍历对应二叉树的哪种遍历？为什么？**

答：对应先序遍历。

因为"左孩子"就是"第一个孩子"，"右孩子"就是"下一个兄弟"。

先序的顺序是"根 → 左 → 右"，翻译过来就是"自己 → 第一个孩子 → 下一个兄弟"，正好是先根遍历。

同理，树的后根遍历对应二叉树的中序。

## 13. 小结

这一篇的四块内容，各自压成一句。

```text
遍历：三种顺序只差 visit 的位置，左右永远是先左后右。
非递归：递归帮我们压栈，所以非递归要自己压。层序用队列。
线索：n+1 个空指针改成前驱/后继，中序线索找后继 O(1) 且不需要父指针。
转换：左孩子右兄弟；树的先根 = 二叉树的先序，树的后根 = 二叉树的中序。
```

三个必须记住的数：

```text
空指针数 = n + 1 = 线索数
线索树遍历的空间 = O(1)（不需要栈）
树高 = 递归栈的最大深度
```

三个必须能默写的规则：

```text
线索化：ltag/rtag = 0 指孩子，1 指线索
中序后继：rtag=1 取 rchild；否则取右子树最左下
树转二叉树：第一个孩子变左孩子，其余兄弟变右孩子
```

到这里，二叉树这条线走完了。

```text
定义 → 性质 → 存储 → 遍历 → 线索 → 转换
```

每一个环节都在解决上一环留下的问题：

```text
形状自由 → 用性质把它算清楚
指针浪费 → 用线索把空指针用起来
孩子个数不定 → 用左孩子右兄弟统一成二叉树
```
