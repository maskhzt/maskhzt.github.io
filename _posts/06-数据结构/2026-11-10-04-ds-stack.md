> **读这篇之前，你只需要知道**：线性表是排成一排、有先后次序的一组元素；插入和删除可以发生在任意位置；数组是一段连续内存，下标从 0 开始。
> **这篇讲什么**：把插入删除限制在同一端，只允许"后进先出"，看这种自我限制能换来什么，以及它为什么能解决括号、表达式和函数调用三类问题。
> **一个类比**：一摞盘子，只能从最上面拿、也只能往最上面放；想拿最底下那个，必须先把上面的全搬走。

你打开一个网页，点进第二个，再点进第三个。

按三次"后退"。

依次回到第二个、第一个、空白页。

三次"撤销"也一样：

```text
输入 A → 输入 B → 输入 C
撤销 → 撤销 → 撤销
依次撤掉 C、B、A
```

最后进来的，最先出去。

浏览器没有"前进到最早那个页面"的按钮，编辑器也不会先撤销你打的第一个字。

这不是巧合。

**有一类问题，天生要求"记住最近的"，而"最近的"必须最先被处理。**

这类问题需要一种专门的结构。

它的规则简单到只有一句：

```text
只允许在一端插入，也只允许在同一端删除。
```

这一篇讲它，以及它为什么能解决三大类问题。

## 1. 没有"后进先出"，会怎样

先看一个具体场景。

你要检查一段代码里的括号是否配对：

```c
int f(int a[10]) {
    if (a[0] > 0) {
        return (a[0] + a[1]) * 2;
    }
    return 0;
}
```

人眼一扫就知道配不配对。

可程序怎么判断？

它从左往右读，读到 `(` 时，不知道哪个 `)` 才是它的搭档。

中间可能又冒出新的 `(`。

```text
( ( ( ) ) )
```

第 3 个左括号，必须和第 1 个右括号配对。

第 2 个左括号，配第 2 个右括号。

**最后打开的那个，最先关闭。**

如果用一个"先进先出"的队列来记左括号：

```text
先记第 1 个 (，再记第 2 个，再记第 3 个
遇到右括号时，取队头配对
```

对 `((()))`，队列也会报"成功"。

答案碰巧对，但它给出的配对关系是错的：它让第 1 个 `(` 配了第 1 个 `)`，而真正的嵌套要求第 1 个 `(` 配最后一个 `)`。

换成 `([)]`，问题就藏不住了。

```text
队列：记 (，记 [
遇 )：队头是 (，类型对得上，配对成功，队列剩 [
遇 ]：队头是 [，类型也对得上，配对成功
```

队列说"配对成功"。

可 `([)]` 明明是错的：`(` 里面套的是 `[`，`[` 还没关，怎么能先关 `(`？

**队列只看"最早打开的"和"类型相同"，看不到"最近打开的"，所以它判断不了嵌套。**

栈能。

栈只记"最近打开的"，遇到右括号时，栈顶正好是那个应该被关闭的左括号。

这就是"后进先出"的价值。

**不是所有"排队"都该先进先出；有些问题，必须后进先出。**

生活里的栈到处都是。

```text
一摞盘子：只能从最上面拿。
弹匣：最后压进去的子弹，最先打出去。
羽毛球筒：先放进去的球，最后才拿得到。
电梯：最后进来的人，往往最先出去（如果他站在门口）。
```

它们的共同点：

```text
只有一个开口。
进去和出来，走同一个口。
```

只要满足这两条，"后进先出"就是必然结果，不是谁规定的。

**栈不是被设计出来的，是被"一个口"这个物理约束逼出来的。**

## 2. 栈的定义：一条被限制的线性表

如果没有"只能在一端操作"这条限制，栈就退化成普通线性表。

先把词钉死。

**栈（stack）：只允许在一端进行插入和删除操作的线性表。**

那一端叫栈顶（top）。

另一端叫栈底（bottom）。

插入叫入栈（push），也叫压栈。

删除叫出栈（pop），也叫弹栈。

```text
        栈顶
         ↓
      ┌─────┐
      │  30 │  ← 最后进来，最先出去
      ├─────┤
      │  20 │
      ├─────┤
      │  10 │  ← 最早进来，最后出去
      └─────┘
        栈底
```

规则一句话：

```text
后进先出（last in first out，LIFO）。
```

注意栈仍然是线性表。

它的逻辑结构还是"一对一"。

只是运算被限制了：只能在表尾插入删除，不能在中间或表头操作。

**所以栈是"操作受限的线性表"，不是另一种逻辑结构。**

408 选择题常问："栈是线性表吗？"

答案：是，是操作受限的线性表。

还有一句话要记：

```text
栈的插入和删除都只在栈顶进行，所以栈底是固定的。
```

第一个入栈的元素，一定在栈底，也一定最后出栈。

这带来一个直接推论：

```text
入栈序列是 a1, a2, ..., an，出栈序列的最后一个元素一定是 a1。
```

用 ADT 的写法，栈的"合同"是这样：

```text
ADT Stack {
    数据对象：D = { a_i | a_i ∈ ElemSet, i = 1, 2, ..., n, n ≥ 0 }
    数据关系：R = { <a_{i-1}, a_i> | a_{i-1}, a_i ∈ D, i = 2, ..., n }
    基本操作：
        InitStack(&S)
        DestroyStack(&S)
        StackEmpty(S)
        StackLength(S)
        GetTop(S, &e)
        Push(&S, e)
        Pop(&S, &e)
    约定：插入和删除只能在表尾（栈顶）进行。
}
```

和 [01 篇](/posts/ds-intro-complexity/)讲的线性表 ADT 比，只多了最后那条"约定"。

**数据结构没变，变的是"允许哪些操作"——这就是"操作受限"四个字的含义。**

## 3. 栈的基本操作

如果没有统一的接口，换一种实现就要重写所有调用代码。

不管顺序栈还是链栈，对外都提供同一组操作。

```text
InitStack(&S)      初始化，构造空栈
DestroyStack(&S)   销毁
StackEmpty(S)      判空
StackLength(S)     求元素个数
GetTop(S, &x)      读栈顶，不出栈
Push(&S, x)        入栈
Pop(&S, &x)        出栈，用 x 带回
```

六个操作里，最容易被忽略的是 `GetTop`。

它只读不删。

```text
GetTop 之后，栈里元素个数不变。
Pop 之后，少一个。
```

408 代码题里，如果只是"看一眼栈顶"，用 `GetTop`，别用 `Pop`。

用 `Pop` 再 `Push` 回去，逻辑上等价，但多两次操作，还容易在中间出错。

**能读就别改，这是写栈代码的基本纪律。**

六个操作的复杂度不都一样。

```text
顺序栈：
  Push / Pop / GetTop：O(1)
  StackLength：O(1)，因为 top 就知道个数（top + 1）
  StackEmpty：O(1)

链栈：
  Push / Pop / GetTop：O(1)
  StackLength：O(n)，要走一遍
  StackEmpty：O(1)
```

顺序栈的 `StackLength` 不用另外存一个 length。

`top + 1` 就是元素个数（约定 A）。

**一个 top，同时表达了"栈顶在哪"和"有几个元素"。**

链栈没这个便利，想要 O(1) 求长度，得额外加一个计数变量。

## 4. 顺序栈：用数组加一个 top

没有 top，你根本不知道下一个元素该放哪。

顺序栈（sequential stack）：用一段连续内存存元素，再用一个整数 `top` 记栈顶位置。

```c
#define MAXSIZE 100

typedef int ElemType;

typedef struct {
    ElemType data[MAXSIZE];   /* 连续存储区 */
    int      top;             /* 栈顶指针，这里存的是下标 */
} SqStack;
```

`top` 叫"指针"，但它存的是数组下标，不是内存地址。

这是 408 的用词习惯，别被"指针"两个字带偏。

为什么用下标而不是真指针？

下标更好算边界。

```text
判空：top == -1
判满：top == MAXSIZE - 1
```

如果存真地址，判满就要写成 `top == base + MAXSIZE - 1`，还得额外记一个 base。

下标是"第几格"，地址是"门牌号"。

用"第几格"判断"还有没有格子"，比用门牌号直观。

真用指针也行，C 里可以这么写：

```c
typedef struct {
    ElemType data[MAXSIZE];
    ElemType *top;      /* 指向栈顶元素的下一个位置 */
} PtrStack;
```

这时 `top - data` 才是元素个数。

两种写法本质相同，408 统一用下标，因为计算简单。

**考试时看到"栈顶指针"，先确认它存的是下标还是地址，再套公式。**

`top` 有两种约定，必须先说清用哪种。

**约定 A：top 指向栈顶元素。**

```text
初始化：top = -1
空栈：  top == -1
满栈：  top == MAXSIZE - 1
入栈：  data[++top] = x
出栈：  x = data[top--]
```

**约定 B：top 指向栈顶元素的下一个空位。**

```text
初始化：top = 0
空栈：  top == 0
满栈：  top == MAXSIZE
入栈：  data[top++] = x
出栈：  x = data[--top]
```

两种都对，只是差一个偏移。

这篇的代码统一用约定 A，因为"top 就是栈顶下标"更直观。

看到别人的代码，先看初始化是 −1 还是 0，再判断用的是哪种。

**这是读栈代码的第一步，也是考试最容易设陷阱的地方。**

约定 A 的完整实现：

```c
void InitStack(SqStack *S) {
    S->top = -1;
}

int StackEmpty(SqStack S) {
    return S.top == -1;
}

int Push(SqStack *S, ElemType x) {
    if (S->top == MAXSIZE - 1)     /* 栈满 */
        return 0;
    S->data[++S->top] = x;         /* 先加下标，再存 */
    return 1;
}

int Pop(SqStack *S, ElemType *x) {
    if (S->top == -1)              /* 栈空 */
        return 0;
    *x = S->data[S->top--];        /* 先取，再减下标 */
    return 1;
}

int GetTop(SqStack S, ElemType *x) {
    if (S.top == -1)
        return 0;
    *x = S.data[S.top];            /* 只读，不改 top */
    return 1;
}
```

走一遍。

```text
初始：top = -1，空栈

Push 10：data[0]=10，top=0
Push 20：data[1]=20，top=1
Push 30：data[2]=30，top=2

GetTop：返回 data[2]=30，top 仍是 2

Pop：*x=30，top=1
Pop：*x=20，top=0
Pop：*x=10，top=-1

再 Pop：top == -1，返回 0，下溢
```

注意 `++S->top` 和 `S->top++` 的区别。

`++top` 是"先加再用"，用于入栈。

`top--` 是"先用再减"，用于出栈。

写反了，第一个元素就存到 `data[-1]` 或者读错位置。

**这两个自增自减的位置，是顺序栈代码最常见的错。**

## 5. 栈空与栈满：四个条件要分清

不判空不判满，程序迟早越界。

栈的边界条件比顺序表多，因为有两头。

```text
栈空：不能出栈，不能读栈顶。
栈满：不能入栈。
```

对应两个错误名字。

```text
下溢（underflow）：栈空时还想出栈。
上溢（overflow）：栈满时还想入栈。
```

顺序栈两种都会发生。

链栈只会下溢，不会上溢（除非内存耗尽）。

上溢和下溢的后果不一样。

```text
顺序栈上溢：数组写越界，可能改掉相邻变量，程序不崩但数据错。
顺序栈下溢：读到没写过的内存，或者返回一个垃圾值。
```

所以 Push 前必须判满，Pop 前必须判空。

这不是"防御性编程"，是顺序栈能正确工作的前提。

C 不做下标检查，`data[MAXSIZE]` 写进去不会报错，只会悄悄破坏别的东西。

**顺序栈的每个操作，都是一次"先判边界，再动数据"的固定套路。**

四个条件对照：

| 约定 | 空栈 | 满栈 | 入栈 | 出栈 |
|---|---|---|---|---|
| A：top 指栈顶 | top == −1 | top == MAXSIZE−1 | data[++top]=x | x=data[top−−] |
| B：top 指空位 | top == 0 | top == MAXSIZE | data[top++]=x | x=data[−−top] |

记的时候只记一句话：

```text
top 指哪，空和满就跟着指到哪。
```

约定 A 里 top 指栈顶，空栈就是"没有栈顶"，用 −1 表示。

满栈就是栈顶顶到了数组最后一格，MAXSIZE−1。

约定 B 里 top 指空位，空栈就是"第一个空位在 0"，满栈就是"空位在数组外面"，MAXSIZE。

**不要死背，画一个只有 2 格的栈，把空和满各走一遍，条件自然就出来了。**

## 6. 共享栈：两个栈共用一个数组

一个数组，只用一个栈，可能浪费。

两个栈，一个从左边长，一个从右边长，共用一个数组，叫共享栈（shared stack）。

```text
┌────┬────┬────┬────┬────┬────┬────┐
│ 10 │ 20 │    │    │    │ 90 │ 80 │
└────┴────┴────┴────┴────┴────┴────┘
  ↑                    ↑
 top0                top1
```

左边栈的栈顶从 −1 往右走。

右边栈的栈顶从 MAXSIZE 往左走。

```c
typedef struct {
    ElemType data[MAXSIZE];
    int top0;    /* 左栈顶，初始 -1 */
    int top1;    /* 右栈顶，初始 MAXSIZE */
} ShStack;
```

判空、判满：

```text
左栈空：top0 == -1
右栈空：top1 == MAXSIZE
整个栈满：top1 - top0 == 1
```

为什么满的条件是 `top1 - top0 == 1`？

因为两个栈顶相邻时，中间已经没有空位。

画出来：

```text
top0 = 3，top1 = 4

下标： 0    1    2    3    4    5
      [10] [20] [30] [40] [  ] [  ]
                  ↑    ↑
                top0  top1

top1 - top0 = 1，满
```

再入栈任何一个，就会越界。

共享栈的好处：

```text
两个栈各自最多能用 MAXSIZE，但不会互相挤占。
只有两个栈的元素总数达到 MAXSIZE 时才上溢。
```

入栈代码要区分往哪边放。

```c
/* which = 0 表示左栈，which = 1 表示右栈 */
int PushShared(ShStack *S, int which, ElemType x) {
    if (S->top1 - S->top0 == 1)    /* 整个栈满 */
        return 0;

    if (which == 0)
        S->data[++S->top0] = x;    /* 左栈：往右长 */
    else
        S->data[--S->top1] = x;    /* 右栈：往左长 */
    return 1;
}

int PopShared(ShStack *S, int which, ElemType *x) {
    if (which == 0) {
        if (S->top0 == -1) return 0;
        *x = S->data[S->top0--];
    } else {
        if (S->top1 == MAXSIZE) return 0;
        *x = S->data[S->top1++];
    }
    return 1;
}
```

左栈入栈是 `++top0`，右栈入栈是 `--top1`。

一个加，一个减，方向相反，但都朝中间走。

单栈各自开一半，各 50 格。

共享栈合起来 100 格，一个栈可以长到 99，只要另一个只用 1 格。

**这是"按需分配"的雏形：空间不预先切死，谁需要谁用。**

代价是：两个栈的元素总数超过 MAXSIZE 时，即使单个栈还有"名义上的空间"，也会上溢。

408 考共享栈，基本只考"满的条件"。

记住 `top1 - top0 == 1`，比背文字快。

## 7. 链栈：头插法的天然应用

顺序栈的容量是写死的。

链栈（linked stack）用单链表实现，随用随申请。

栈顶放在哪一头？

放在表头。

因为单链表在表头插入删除都是 O(1)。

```c
typedef struct StackNode {
    ElemType data;
    struct StackNode *next;
} StackNode, *LinkStack;
```

链栈通常不带头结点。

栈顶指针就是链表头指针。

```text
top → [30|·] → [20|·] → [10|^]
```

为什么栈顶一定要放在表头？

放在表尾行不行？

不行。

单链表在表尾插入是 O(n)，因为要先走到尾。

在表尾删除也是 O(n)，因为要找到尾的前驱。

而栈的 Push 和 Pop 必须 O(1)。

放在表头，两个操作都只动第一个结点，都是 O(1)。

**"栈顶放表头"不是习惯，是唯一能保证 O(1) 的选择。**

顺序栈和链栈的对比：

```text
顺序栈：容量固定，可能上溢，访问快，实现简单。
链栈：容量随需，只有内存上限，每个结点多一个指针。
```

408 代码题里，顺序栈更常用，因为题目通常给了 MAXSIZE。

如果题目强调"栈可能很大、事先不知道数量"，才选链栈。

入栈就是头插。

出栈就是删首结点。

```c
void InitStack(LinkStack *S) {
    *S = NULL;
}

int Push(LinkStack *S, ElemType x) {
    StackNode *s = (StackNode *)malloc(sizeof(StackNode));
    if (s == NULL) return 0;

    s->data = x;
    s->next = *S;      /* 新结点指向原栈顶 */
    *S = s;            /* 栈顶改指新结点 */
    return 1;
}

int Pop(LinkStack *S, ElemType *x) {
    if (*S == NULL) return 0;   /* 栈空 */

    StackNode *q = *S;
    *x = q->data;
    *S = q->next;       /* 栈顶下移 */
    free(q);
    return 1;
}
```

对照 [03 篇](/posts/ds-linked-list/)的头插法：

```text
Push  = 头插
Pop   = 删首结点
```

一模一样。

**栈的链式实现，本质就是"只允许在表头操作的单链表"。**

链栈的优点：

```text
不会上溢，除非内存真的用完。
多个栈共享内存时，按需申请，不会浪费。
```

缺点：

```text
每个结点多一个指针，空间开销大。
频繁 malloc/free，比数组慢。
```

408 代码题如果没规定，顺序栈更好写，也更不容易出错。

## 8. 括号匹配：一次完整走查

回到开头的问题。

算法只有三条规则。

```text
遇左括号：入栈。
遇右括号：看栈顶。
  栈空 → 不匹配。
  栈顶是同类左括号 → 弹出，继续。
  栈顶是异类左括号 → 不匹配。
扫完整个串：栈空 → 匹配；栈非空 → 不匹配。
```

先走一个正确的：`{[()]}`。

```text
读 {：入栈       栈：[{]
读 [：入栈       栈：[{ []
读 (：入栈       栈：[{ [ (]
读 )：栈顶是 (   弹出，栈：[{ []
读 ]：栈顶是 [   弹出，栈：[{]
读 }：栈顶是 {   弹出，栈：[]
结束：栈空 → 匹配成功
```

再走一个错误的：`([)]`。

```text
读 (：入栈       栈：[(]
读 [：入栈       栈：[( []
读 )：栈顶是 [   异类 → 不匹配，失败
```

再看两种"扫完了但不匹配"的。

`((()`：

```text
读 ( ( (：栈：[( ( (]
结束：栈非空（3 个左括号没关）→ 不匹配
```

`())`：

```text
读 (：栈：[(]
读 )：弹出，栈：[]
读 )：栈空 → 不匹配
```

四种情况覆盖了所有失败模式：

```text
右括号多余     → 栈空时遇到右括号
左右类型不符   → 栈顶不是对应的左括号
左括号多余     → 扫完栈非空
顺序错误       → 上面第二条的变体
```

有人会想：只数左括号和右括号的个数，相等不就行了？

不行。

`([)]` 里左括号 2 个，右括号 2 个，个数相等，但它不合法。

计数器只知道"总数差多少"，不知道"最近打开的是哪个"。

```text
计数器：能判"多没多"，不能判"配没配"。
栈：既能判多没多，又能判顺序对不对。
```

如果只有一种括号，计数器确实够用。

但只要有多种括号，或者要求"嵌套顺序正确"，就必须用栈。

**这就是"记住最近的"比"记住总数"多出来的信息量。**

C 实现：

```c
int BracketMatch(char *s) {
    SqStack S;
    InitStack(&S);

    for (int i = 0; s[i] != '\0'; i++) {
        char c = s[i];

        if (c == '(' || c == '[' || c == '{') {
            Push(&S, c);
        } else if (c == ')' || c == ']' || c == '}') {
            if (StackEmpty(S)) return 0;   /* 右括号多余 */

            ElemType t;
            Pop(&S, &t);

            if ((c == ')' && t != '(') ||
                (c == ']' && t != '[') ||
                (c == '}' && t != '{'))
                return 0;                  /* 类型不匹配 */
        }
        /* 其他字符直接跳过 */
    }
    return StackEmpty(S);                  /* 左括号是否多余 */
}
```

注意最后一行。

它同时处理了"匹配成功"和"左括号多余"两种情况：

```text
栈空 → 返回 1
栈非空 → 返回 0
```

**一个返回值，两种含义，写起来短，读起来要小心。**

408 还可能问"匹配过程中栈的最大深度"。

对 `{[()]}`，深度依次是 1、2、3、2、1、0，最大 3。

栈深就是"当前嵌套了几层括号"。

## 9. 中缀转后缀：为什么要换一种写法

如果直接让程序算中缀，它要同时处理优先级和括号，很容易写错。

人写表达式用中缀：`A + B * C`。

运算符在中间。

计算机不喜欢中缀，因为要处理优先级和括号。

```text
先算 B*C，再算 A+...
括号改变顺序：(A+B)*C
```

后缀表达式（postfix）把运算符放在操作数后面：

```text
A + B        →  A B +
A + B * C    →  A B C * +
(A + B) * C  →  A B + C *
```

后缀也叫逆波兰表达式（reverse Polish notation，RPN）。

它的好处：

```text
没有括号。
没有优先级。
从左到右扫一遍，遇到运算符就算。
```

**所有"先算谁"的信息，都被编码进了操作数和运算符的先后顺序里。**

中缀转后缀，用手算的规则：

```text
1. 遇操作数：直接输出。
2. 遇左括号：入栈。
3. 遇右括号：弹栈并输出，直到弹出左括号；左括号丢弃。
4. 遇运算符：
   弹出栈顶所有优先级 >= 它的运算符并输出；
   然后把它入栈。
5. 扫完：弹出栈里剩余运算符。
```

优先级：

```text
* /  高于  + -
同级运算符，左结合（从左往右算）。
```

结合性要用例子说清。

`A - B - C` 按左结合，等于 `(A - B) - C`。

转后缀：

```text
A B C - -
```

计算顺序是"先 A−B，再减 C"。

如果是右结合，就会变成 `A - (B - C)`，结果完全不同。

`A ^ B ^ C`（^ 表示乘方）是右结合，等于 `A ^ (B ^ C)`。

转后缀：

```text
A B C ^ ^
```

**408 只考 + − * /，全是左结合，不会遇到右结合。**

但知道有这回事，遇到 `^` 或赋值运算符时不会想当然。

还有前缀表达式（prefix），运算符在操作数前面：

```text
A + B        →  + A B
(A + B) * C  →  * + A B C
```

前缀也叫波兰表达式。

中缀转前缀的规则和中缀转后缀对称，只是从右往左扫。

408 主要考后缀，前缀知道定义即可。

走一个完整的：`A + B * C - D / E`。

```text
读 A：输出 A               输出：A
读 +：栈空，入栈            栈：[+]
读 B：输出 B               输出：A B
读 *：栈顶 + 优先级低，不弹；* 入栈   栈：[+ *]
读 C：输出 C               输出：A B C
读 -：栈顶 * 优先级高，弹出；栈顶 + 同级，弹出；
      - 入栈                输出：A B C * +   栈：[-]
读 D：输出 D               输出：A B C * + D
读 /：栈顶 - 优先级低，不弹；/ 入栈   栈：[- /]
读 E：输出 E               输出：A B C * + D E
扫完：弹出 /，再弹出 -      输出：A B C * + D E / -
```

最终后缀：`A B C * + D E / -`。

验证一下：原式是 `(A + (B*C)) - (D/E)`。

后缀里先 `B C *`，再 `A ... +`，再 `D E /`，最后 `-`，顺序对。

再走一个带括号的：`(A + B) * C - D`。

```text
读 (：入栈                 栈：[(]
读 A：输出 A               输出：A
读 +：栈顶是 (，不弹；入栈   栈：[( +]
读 B：输出 B               输出：A B
读 )：弹到 ( 为止，输出 +，丢弃 (   输出：A B +   栈：[]
读 *：栈空，入栈            栈：[*]
读 C：输出 C               输出：A B + C
读 -：栈顶 * 优先级高，弹出；- 入栈  输出：A B + C *   栈：[-]
读 D：输出 D               输出：A B + C * D
扫完：弹出 -                输出：A B + C * D -
```

结果：`A B + C * D -`。

**手算时把"输出"和"栈"两列并排写，一步一行，比心算可靠。**

## 10. 后缀表达式求值：一个栈就够

如果后缀不配一个栈，运算符就找不到它的两个操作数。

后缀求值比中缀简单得多。

规则：

```text
遇操作数：入栈。
遇运算符：弹出两个操作数，先弹出的是右操作数，后弹出的是左操作数；
         计算，把结果入栈。
最后栈里剩一个数，就是答案。
```

为什么先弹出的是右操作数？

因为栈是后进先出。

表达式 `A B -` 里，先入 A，再入 B。

遇到 `-` 时，栈顶是 B，所以先弹出 B（右操作数），再弹出 A（左操作数）。

计算 `A - B`。

**顺序反了，减法和除法就会算错，这是后缀求值最大的坑。**

走一个：`3 4 2 * +`。

```text
读 3：入栈        栈：[3]
读 4：入栈        栈：[3 4]
读 2：入栈        栈：[3 4 2]
读 *：弹 2（右），弹 4（左），4*2=8，入栈   栈：[3 8]
读 +：弹 8（右），弹 3（左），3+8=11，入栈  栈：[11]
结束：答案 11
```

原式是 `3 + 4*2 = 11`，对。

再走一个带减法和除法的：`A B C * + D E / -`，取 A=6、B=4、C=2、D=8、E=2。

```text
读 6：栈：[6]
读 4：栈：[6 4]
读 2：栈：[6 4 2]
读 *：4*2=8，栈：[6 8]
读 +：6+8=14，栈：[14]
读 8：栈：[14 8]
读 2：栈：[14 8 2]
读 /：8/2=4，栈：[14 4]
读 -：14-4=10，栈：[10]
答案 10
```

再手算一个完整的中缀转后缀再求值：`(3 + 4) * 5 - 6 / 2`。

先转后缀：

```text
读 (：栈：[(]
读 3：输出 3
读 +：栈：[( +]
读 4：输出 3 4
读 )：弹出 +，输出 3 4 +，栈：[]
读 *：栈：[*]
读 5：输出 3 4 + 5
读 -：弹出 *，输出 3 4 + 5 *，栈：[-]
读 6：输出 3 4 + 5 * 6
读 /：栈：[- /]
读 2：输出 3 4 + 5 * 6 2
扫完：弹出 /，再弹出 -
后缀：3 4 + 5 * 6 2 / -
```

再求值：

```text
3 4 + → 7
7 5 * → 35
6 2 / → 3
35 3 - → 32
```

答案 32。

原式 `(3+4)*5 - 6/2 = 35 - 3 = 32`，对。

**转后缀和求值，各用一个栈，各扫一遍，都是 O(n)。**

计算机其实也能直接算中缀。

用两个栈：

```text
操作数栈：存数字
运算符栈：存运算符
```

规则：

```text
遇数字：入操作数栈。
遇左括号：入运算符栈。
遇右括号：弹运算符，算一次，结果入操作数栈，直到弹出左括号。
遇运算符：当运算符栈顶优先级 >= 当前运算符时，先弹出来算；
         算完再入栈。
扫完：把运算符栈弹空，每次弹出一个就算一次。
```

这就是很多计算器的实现方式。

但 408 更爱考"先转后缀再求值"，因为两个阶段可以分别出题。

**会手算转后缀，再会手算后缀求值，中缀求值自然就会了。**

## 11. 递归与栈：函数调用本身就是栈

如果没有调用栈，函数返回时根本不知道回哪。

递归（recursion）：一个函数直接或间接调用自己。

```c
int fact(int n) {
    if (n <= 1) return 1;      /* 递归出口 */
    return n * fact(n - 1);    /* 递归调用 */
}
```

`fact(4)` 的执行过程：

```text
fact(4) = 4 * fact(3)
              fact(3) = 3 * fact(2)
                            fact(2) = 2 * fact(1)
                                          fact(1) = 1
返回：1 → 2 → 6 → 24
```

看起来像"先一路往下，再一路往上"。

往下时，每一层的 `n` 和"返回到哪里"都要记住。

往上时，按相反顺序一层层恢复。

**这个"记住现场、按相反顺序恢复"的过程，正是栈。**

程序运行时有一块内存叫调用栈（call stack）。

每次函数调用，压入一个栈帧（stack frame）。

栈帧里存：

```text
参数
返回地址（函数执行完回到哪一行）
局部变量
```

函数返回时，弹出栈帧，恢复上一层现场。

```text
fact(4) 调用 fact(3)：压栈
fact(3) 调用 fact(2)：压栈
fact(2) 调用 fact(1)：压栈
fact(1) 返回：弹栈
fact(2) 返回：弹栈
fact(3) 返回：弹栈
```

递归深度是 n，调用栈就有 n 层。

空间复杂度 O(n)。

**反直觉的点在这里：递归函数里一行循环都没有，空间复杂度却可能是 O(n)。**

空间不是花在"代码"上，是花在"每一层调用都要记住现场"上。

**这就是为什么递归不是"免费"的：每一层都要占一块栈空间。**

栈空间有多大？

Linux 默认一个线程的栈大约 8 MB。

线程（thread）：程序里独立执行的一条执行流，每个线程有自己的调用栈。

每层栈帧假设 64 字节，8 MB 能放约 13 万层。

递归 10 万层可能没事，20 万层就栈溢出（stack overflow）。

```text
Segmentation fault
```

很多时候就是递归太深。

没有栈会怎样？

函数调用无法返回。

你必须手动记住"从哪来、回哪去、局部变量是什么"。

早期的某些语言真的这么干过，代码里全是显式的"返回地址表"。

**栈是"函数调用"这个机制在硬件和编译器里的落地方式。**

递归都能改成非递归。

办法就是：自己开一个栈，模拟系统调用栈。

比如二叉树的中序遍历：

```c
/* 非递归中序：用栈保存"回去的路径"（BiTree 是二叉树结点指针，后面树的一篇会定义） */
void InOrder(BiTree T) {
    SqStack S;
    InitStack(&S);
    BiTree p = T;

    while (p != NULL || !StackEmpty(S)) {
        if (p != NULL) {
            Push(&S, p);      /* 一路向左，沿途入栈 */
            p = p->left;
        } else {
            Pop(&S, &p);      /* 左边走不动了，弹一个访问 */
            visit(p);
            p = p->right;     /* 转向右子树 */
        }
    }
}
```

栈里存的是"还没访问完的祖先结点"。

**递归转非递归，本质是把"系统帮你压的栈"改成"你自己压的栈"。**

递归转非递归，一般分三步。

```text
第一步：找出递归的"现场"是什么（哪些变量要跨层保存）。
第二步：定义一个栈，栈里存的就是这些现场。
第三步：用循环模拟"压栈—处理—弹栈"的过程。
```

有些递归可以更简单。

比如尾递归（tail recursion）：递归调用是函数的最后一步，返回后不再做别的计算。

```c
int fact(int n, int acc) {     /* 尾递归版本 */
    if (n <= 1) return acc;
    return fact(n - 1, acc * n);
}
```

这种递归，编译器可以优化成循环，不占额外栈空间。

但 C 标准不保证一定优化，写代码时别依赖它。

**408 只要求会算递归的栈深和执行过程，不要求手写尾递归优化。**

## 12. 出栈序列：哪些可能，哪些不可能

如果不判断合法性，你会以为所有排列都能出栈。

给定入栈序列 `1, 2, 3`，元素依次入栈。

但入栈和出栈可以交替进行。

问：可能的出栈序列有哪些？

先枚举。

```text
123：1 进 1 出，2 进 2 出，3 进 3 出
132：1 进 1 出，2 进 3 进 3 出 2 出
213：1 进 2 进 2 出 1 出 3 进 3 出
231：1 进 2 进 2 出 3 进 3 出 1 出
321：1 进 2 进 3 进 3 出 2 出 1 出
```

一共 5 种。

`312` 行不行？

```text
要 3 先出：1、2、3 都入栈，栈是 [1, 2, 3]，3 在顶
3 出，栈：[1, 2]
下一个要 1 出，可栈顶是 2，1 被压在下面
只能先出 2，再出 1
所以 312 不可能
```

**规律：出栈序列里，如果某个较大的数先出，那么比它小的、还在栈里的数，必须按从大到小的顺序出。**

312 里 3 先出，剩下的 1、2 必须按 2、1 出，不能按 1、2 出。

n 个元素，可能的出栈序列总数是卡特兰数（Catalan number）：

```text
C_n = (1/(n+1)) × C(2n, n)
```

代 n = 3：

```text
C_3 = (1/4) × C(6,3) = (1/4) × 20 = 5
```

代 n = 4：

```text
C_4 = (1/5) × C(8,4) = (1/5) × 70 = 14
```

代 n = 5：

```text
C_5 = (1/6) × C(10,5) = (1/6) × 252 = 42
```

为什么是卡特兰数？

因为每一个合法出栈序列，对应一种"n 个元素入栈、出栈的合法括号序列"。

入栈看成左括号，出栈看成右括号。

任何时刻，出栈次数不能超过入栈次数。

这个条件的方案数，就是卡特兰数。

**所以"出栈序列计数"和"n 对括号的合法排列数"是同一个问题。**

408 判断某个序列是否合法，不用套公式。

直接模拟：

```text
按出栈序列的顺序，依次检查。
要出的元素如果就在栈顶，弹出。
如果不在栈顶，把还没入栈的元素依次入栈，直到它出现在栈顶。
如果入栈入到没得入，它还没出现，就非法。
```

模拟 `4, 3, 5, 1, 2`，入栈 1..5：

```text
要 4：入 1,2,3,4，4 在顶，弹出    栈：[1,2,3]
要 3：3 在顶，弹出                栈：[1,2]
要 5：入 5，5 在顶，弹出          栈：[1,2]
要 1：栈顶是 2，不是 1；没得入    非法
```

所以 `4,3,5,1,2` 不合法。

再模拟 `2,3,4,1,5`：

```text
要 2：入 1,2，弹出 2       栈：[1]
要 3：入 3，弹出 3         栈：[1]
要 4：入 4，弹出 4         栈：[1]
要 1：1 在顶，弹出         栈：[]
要 5：入 5，弹出 5         栈：[]
合法
```

**模拟法比重背规律可靠，考场上画个栈，一步步走，不会错。**

写成代码也不长。

```c
/* 入栈序列固定为 1..n，判断 out[0..n-1] 是否为合法出栈序列 */
int ValidPopOrder(int out[], int n) {
    int stack[100];
    int top = -1;
    int next = 1;              /* 下一个待入栈的数 */

    for (int k = 0; k < n; k++) {
        while (top == -1 || stack[top] != out[k]) {
            if (next > n)      /* 没得入栈，还没等到 out[k] */
                return 0;
            stack[++top] = next++;
        }
        top--;                 /* 栈顶正是 out[k]，弹出 */
    }
    return 1;
}
```

走 `2,3,4,1,5`：

```text
k=0，要 2：入 1、2，栈顶是 2，弹出
k=1，要 3：入 3，弹出
k=2，要 4：入 4，弹出
k=3，要 1：栈顶是 1，弹出
k=4，要 5：入 5，弹出
全部通过，合法
```

走 `4,3,5,1,2`：

```text
k=0，要 4：入 1、2、3、4，弹出 4
k=1，要 3：栈顶是 3，弹出
k=2，要 5：入 5，弹出
k=3，要 1：栈顶是 2，不等；next 已经到 6，没得入 → 返回 0
```

非法。

**这段代码的时间复杂度是 O(n)：每个元素最多入栈一次、出栈一次。**

## 13. 408 怎么考这一章

栈在 408 里分值稳定，题型集中。

**题型一：判断出栈序列是否合法。**

例题（自拟）：入栈序列 `1,2,3,4,5`，判断 `3,2,5,4,1` 是否合法。

```text
要 3：入 1,2,3，弹出 3      栈：[1,2]
要 2：2 在顶，弹出          栈：[1]
要 5：入 4,5，弹出 5        栈：[1,4]
要 4：4 在顶，弹出          栈：[1]
要 1：1 在顶，弹出          栈：[]
合法
```

答案：合法。

**题型二：中缀转后缀。**

例题（自拟）：`A + B * (C - D) - E / F`。

```text
A          输出 A
+          栈：[+]
B          输出 A B
*          栈：[+ *]
(          栈：[+ * (]
C          输出 A B C
-          栈顶 ( 不弹；栈：[+ * ( -]
D          输出 A B C D
)          弹出 -，输出 ... -，丢弃 (；栈：[+ *]
-          弹出 *、+，输出 * +；- 入栈；栈：[-]
E          输出 ... E
/          栈：[- /]
F          输出 ... F
扫完       弹出 /、-
```

后缀：`A B C D - * + E F / -`。

**题型三：后缀表达式求值。**

例题（自拟）：`8 2 3 * + 4 -`。

```text
8 入栈              [8]
2 入栈              [8 2]
3 入栈              [8 2 3]
*：2*3=6            [8 6]
+：8+6=14           [14]
4 入栈              [14 4]
-：14-4=10          [10]
答案 10
```

**题型四：栈的深度与容量。**

例题（自拟）：`{[()]}` 匹配过程中，栈的最大深度是多少？

```text
{  → 1
[  → 2
(  → 3
)  → 2
]  → 1
}  → 0
```

最大深度 3。

如果栈的容量只有 2，这个串在第 3 个括号时就上溢了。

再问一个反向问题：要让 `{[()]}` 匹配成功，栈的容量至少多大？

```text
最大深度是 3，所以容量至少 3。
容量 2 会在读第 3 个左括号时上溢。
```

**"栈的容量"和"栈的最大深度"是同一个数，一个问配置，一个问过程。**

**题型五：递归与栈。**

例题（自拟）：`fact(5)` 的递归调用栈最深有几层？

```text
fact(5) → fact(4) → fact(3) → fact(2) → fact(1)
```

5 层。

返回时逐层弹出。

时间 O(n)，空间 O(n)。

五个题型里，前两个出现频率最高。

## 14. 容易混淆的点

```text
1. 栈是线性表
   栈是操作受限的线性表，逻辑结构仍是线性。
   它不是"另一种逻辑结构"。

2. top 的两种约定
   指向栈顶元素：初始 -1，满 MAXSIZE-1。
   指向栈顶下一个空位：初始 0，满 MAXSIZE。
   读代码先看初始化。

3. 栈空与栈满
   顺序栈两个都要判。
   链栈只判空，不判满。

4. 共享栈的满条件
   top1 - top0 == 1。
   不是 top0 == top1，也不是 top0 + top1 == MAXSIZE。

5. 出栈序列
   最后一个出栈的，一定是最先入栈的。
   判断合法性用模拟，别硬套公式。

6. 中缀转后缀的优先级
   * / 高于 + -。
   同级左结合。
   左括号入栈后，优先级最低，只有右括号能把它请出来。

7. 后缀求值的操作数顺序
   先弹出的是右操作数。
   减法和除法顺序反了，答案就错。

8. 递归的空间复杂度
   递归深度 n，空间 O(n)。
   不是 O(1)，因为每层都占栈帧。
```

还有一个容易忽略的：

```text
9. 栈和队列的区别
   栈：后进先出，同一端进出。
   队列：先进先出，一端进、另一端出。
   两者都是操作受限的线性表。
```

最后一个容易想当然的：

```text
10. 栈的操作都是 O(1)，不代表栈能解决所有问题
    O(1) 说的是单次 Push/Pop。
    用栈扫描整个表达式仍是 O(n)。
    栈是工具，不是复杂度本身。
```

### 自检三问

2. 顺序栈用"top 指向栈顶元素"的约定，空栈、满栈、入栈、出栈四个条件分别是什么？换成"top 指向空位"又变成什么？

## 15. 小结

把这一篇压成几句话。

```text
栈 = 只在栈顶插入删除的线性表
规则 = 后进先出（LIFO）
```

两种实现：

```text
顺序栈：数组 + top，会上溢
链栈：单链表 + 头插，只有内存耗尽才失败
共享栈：两头往中间长，top1 - top0 == 1 时满
```

三个核心判断：

```text
空栈：top == -1（约定 A）
满栈：top == MAXSIZE - 1（约定 A）
栈深：匹配过程中栈里最多几个元素
```

三大应用：

```text
括号匹配：遇左入栈，遇右比对栈顶
中缀转后缀：操作数直出，运算符按优先级进出栈
后缀求值：遇数入栈，遇符弹两个算完再入栈
```

递归的本质：

```text
函数调用 = 压栈帧
函数返回 = 弹栈帧
递归深度 = 栈的深度
```

出栈序列：

```text
n 个元素有 C(2n,n)/(n+1) 种合法序列
判断合法性用模拟，不用背公式
```

栈的下一站，是把"同一端进出"改成"一端进、另一端出"：

```text
同样是一端进、另一端出，
为什么队列在操作系统里到处都是？
循环队列的队空队满，为什么要少用一个格子？
```

```text

```

那一篇会回答：

```text

```
