## 2. 术语表：绪论

这一块的词最少，但每个词后面都挂着一整门课。

逻辑结构决定"能怎么用"，存储结构决定"要花多少时间"。

两个词分不清，后面每一篇都会读得别扭。

- **数据（data）**：所有能输入计算机并被处理的符号集合。
- **数据元素（data element）**：数据的基本单位，一条完整记录。
- **数据结构（data structure）**：数据元素之间关系的整体，含逻辑结构、存储结构和操作。
- **逻辑结构（logical structure）**：元素之间"看起来"的关系：集合、线性、树、图。
- **存储结构（storage structure）**：逻辑结构在内存里的落地方式：顺序、链式、索引、散列。
- **抽象数据类型（abstract data type，ADT）**：数据对象加一组操作，只讲能做什么，不讲怎么实现。
- **时间复杂度（time complexity）**：基本操作次数随规模增长的量级。
- **空间复杂度（space complexity）**：除输入外，额外占用的空间随规模增长的量级。

## 3. 术语表：线性表

这一块的词成对出现：顺序对链式，头指针对头结点。

少看一半，等于两个都没记住。

顺序表和链表的区别，本质上只有一个：地址是算出来的，还是顺着指针找出来的。

- **线性表（linear list）**：n 个同类型元素排成的有限序列。
- **顺序表（sequential list）**：用连续内存存线性表，靠下标算地址。
- **链表（linked list）**：结点分散存放，靠指针串起来。
- **双链表（doubly linked list）**：每个结点存前驱和后继两个指针。
- **循环链表（circular linked list）**：尾结点指针指回头结点，形成环。
- **静态链表（static linked list）**：用数组模拟链表，靠数组下标代替指针。
- **头结点（head node）**：第一个元素之前附加的结点，用来统一插入删除操作。
- **头指针（head pointer）**：指向链表第一个结点的指针，是链表的入口。

## 4. 术语表：栈、队列与数组

这一块考的是"边界"：栈顶在哪、队满没满、矩阵压成一维后下标怎么算。

栈和队列的题，八成错在边界：栈空、栈满、队空、队满。

- **栈（stack）**：只允许在一端插入和删除的线性表，后进先出。
- **栈顶（top）**：允许操作的那一端。
- **顺序栈（sequential stack）**：用数组加一个 top 指针实现的栈。
- **链栈（linked stack）**：用单链表实现的栈，栈顶在表头。
- **队列（queue）**：只允许一端进、另一端出的线性表，先进先出。
- **循环队列（circular queue）**：把数组首尾相接，解决假溢出。
- **假溢出（false overflow）**：队尾指针到数组末尾、前面还有空位却无法入队。
- **压缩存储（compressed storage）**：多个相同元素只存一份，特殊矩阵常用。
- **稀疏矩阵（sparse matrix）**：非零元素很少的矩阵，用三元组或十字链表存。

## 5. 术语表：串

这一块只有一个主角：怎么在长串里快速找到一个短串。

串这一块只有一个东西要背：next。剩下的都是它的推论。

- **串（string）**：零个或多个字符组成的有限序列。
- **空串（empty string）**：长度为 0 的串。
- **子串（substring）**：串中连续的一段。
- **模式匹配（pattern matching）**：在主串里找模式串第一次出现的位置。
- **next 数组（next array）**：失配时模式串该回退到的位置。
- **nextval（nextval array）**：next 的优化版，跳过相同字符的无效比较。

## 6. 术语表：树与二叉树

这一块的词最多，也最容易混。

满和完全是两回事，深度和高度是两回事，树和森林只差一次转换。

树这一块的题，几乎都能用两条性质解决：n0 = n2 + 1，和"左孩子右兄弟"。

- **树（tree）**：n 个结点的有限集，一个根，其余分成若干不相交的子树。
- **结点的度（degree）**：结点拥有的子树个数。
- **叶子（leaf）**：度为 0 的结点。
- **深度 / 高度（depth / height）**：从根往下数的层数 / 从下往上数的层数。
- **二叉树（binary tree）**：每个结点最多两个孩子的树，左右有序。
- **满二叉树（full binary tree）**：每一层都满的二叉树。
- **完全二叉树（complete binary tree）**：只有最后一层可以不满，且结点靠左。
- **线索二叉树（threaded binary tree）**：用空指针存前驱后继，把树变成可顺序遍历的链表。
- **哈夫曼树（Huffman tree）**：带权路径长度最小的二叉树。
- **带权路径长度（weighted path length，WPL）**：每个叶子的权值乘它的深度，再求和。
- **并查集（union-find）**：只支持"合并两个集合"和"查元素属于哪个集合"的树形结构。

## 7. 术语表：图

这一块的词分两组：一组描述形状（连通、度、生成树），一组描述算法（最小生成树、拓扑、关键路径）。

图的题也分两类：画图题（遍历、生成树）和算表题（最短路、关键路径）。

- **图（graph）**：顶点和边的集合。
- **度 / 入度 / 出度（degree / in-degree / out-degree）**：与顶点相连的边数 / 指向它的边数 / 从它出发的边数。
- **连通图（connected graph）**：任意两个顶点之间都有路径。
- **生成树（spanning tree）**：包含全部 n 个顶点、只有 n−1 条边的连通子图。
- **邻接矩阵（adjacency matrix）**：n×n 矩阵，a[i][j] 表示边是否存在或权值。
- **邻接表（adjacency list）**：每个顶点挂一条边表，只存存在的边。
- **最小生成树（minimum spanning tree，MST）**：权值之和最小的生成树。
- **拓扑排序（topological sort）**：把 AOV 网的顶点排成线性序列，边都从前指向后。
- **关键路径（critical path）**：AOE 网中长度最长的路径，决定整个工期。

## 8. 术语表：查找

这一块的词绕着一个量转：平均要比较几次。

顺序、折半、分块、散列，差别只在"用什么办法把比较次数压下来"。

- **查找（search）**：在数据集合里找满足条件的元素。
- **平均查找长度（average search length，ASL）**：找到元素平均要比较的次数。
- **折半查找（binary search）**：有序表上每次取中间，砍掉一半。
- **判定树（decision tree）**：把折半查找的比较过程画成二叉树，第几层就比几次。
- **分块查找（block search）**：块间有序、块内无序，先查索引表再查块。
- **B 树（B-tree）**：多路平衡查找树，一个结点存多个关键字和多个孩子。
- **B+ 树（B+ tree）**：B 树的变体，只有叶子存记录，叶子之间用链表串起来。
- **散列表（hash table）**：用散列函数直接算出存储位置的表。
- **装填因子（load factor）**：表中记录数与表长之比，记作 α。

## 9. 术语表：排序

这一块的词要按"比较 / 移动 / 稳定 / 空间"四个维度记，只记名字没用。

排序的题问来问去就四件事：第几趟、稳不稳、比几次、占多少空间。

- **排序（sorting）**：把记录按关键字排成有序序列。
- **稳定性（stability）**：关键字相同的记录，排序前后相对次序不变。
- **内排序（internal sorting）**：数据全在内存里排。
- **外排序（external sorting）**：数据太大，要借助外存分段排，再归并。
- **希尔排序（Shell sort）**：按增量分组做插入排序，增量逐步缩小到 1。
- **快速排序（quick sort）**：选一个枢轴划分，左右两半递归。
- **堆（heap）**：完全二叉树，每个结点都不小于（或不大于）它的孩子。
- **归并排序（merge sort）**：两两合并有序段，直到整体有序。
- **基数排序（radix sort）**：按位从低到高分配再收集，不比较关键字。
- **多路归并（multiway merge）**：一次合并 k 个有序段，减少归并趟数。

## 10. 公式速查

按"考前扫一眼"的顺序排。

公式不用全背，背记不住的那几个就行。

考前扫一遍，圈出每次都要想三秒的，那才是你的漏洞。

**复杂度。**

```text
T(n) = T(n−1) + 1      → O(n)
T(n) = T(n−1) + n      → O(n²)
T(n) = 2T(n−1) + 1     → O(2ⁿ)
T(n) = T(n/2) + 1      → O(log n)
T(n) = T(n/2) + n      → O(n)
T(n) = 2T(n/2) + n     → O(n log n)
```

**查找。**

```text
顺序查找 ASL = (n+1)/2
折半查找 最多比较 ⌈log2(n+1)⌉ 次
分块查找 ASL = (b+1)/2 + (s+1)/2   （b 为块数，s 为块长）
散列装填因子 α = 表中记录数 / 表长
线性探测成功 ASL ≈ (1/2)(1 + 1/(1−α))
链地址成功 ASL ≈ 1 + α/2
```

**二叉树。**

```text
n0 = n2 + 1
n  = n0 + n1 + n2
第 i 层最多 2^(i−1) 个结点
高度 h 最多 2^h − 1 个结点
完全二叉树高度 = ⌈log2(n+1)⌉
完全二叉树 n0 = ⌈n/2⌉
编号 i（1 起）：左 2i，右 2i+1，父 ⌊i/2⌋
```

**哈夫曼。**

```text
WPL = Σ(权值 × 深度) = 所有合并值之和
n 个叶子 → 共 2n−1 个结点，合并 n−1 次
```

**B 树。**

```text
m 阶：关键字 [⌈m/2⌉−1, m−1]，孩子 [⌈m/2⌉, m]
最小高度 h ≥ log_m(n+1)
最大高度 h ≤ log_{⌈m/2⌉}((n+1)/2) + 1
```

**排序。**

```text
冒泡 / 直接插入 / 简单选择：最坏比较 n(n−1)/2 次
归并：⌈log2 n⌉ 趟，额外空间 O(n)
堆：建堆 O(n)，排序 n−1 趟，每趟 O(log n)
快速：平均 O(n log n)，最坏 O(n²)，额外空间 O(log n)
基数：d 趟，每趟 O(n + r)
```

**图。**

```text
生成树边数 = n − 1
Prim：O(n²)；Kruskal：O(e log e)
Dijkstra：O(n²)；Floyd：O(n³)
```

**栈。**

```text
n 个元素出栈序列数 = C(2n, n) / (n+1)
```

## 11. 20 组最容易混的概念

这一类题失分，通常不是不知道这两个概念，而是"两个都记得，选项里一放就选反"。

出题人只改一个词，两句话读起来一样顺，意思正好相反。

对付它的办法只有一个：每组都用"一句话说出 A 是 X、B 是 Y"的方式过一遍。

说不出来，就是没分清。

二十组里，最常被做成选择题的是这五组。

```text
3   满二叉树 / 完全二叉树：考结点数、叶子数、编号
5   Prim / Kruskal：考选边顺序、适用图
9   B 树 / B+ 树：考叶子存不存记录、范围查询
10  开放定址 / 链地址：考装填因子、删除
11  稳定 / 不稳定：考排序算法归类
```

这五组，每组都值得单独抄一遍。

五组的共同点是：两边的名字你都认识，区别却只在半句话里。

**1. 顺序表 vs 链表。**

顺序表一段连续内存，随机访问 O(1)，插入删除要搬元素，平均搬一半。

链表靠指针串，访问第 i 个要 O(n)，已知位置插入删除 O(1)。

顺序表怕搬家，链表怕找位置。

**2. 栈 vs 队列。**

栈只在一端进出，后进先出，典型用途是括号匹配、表达式求值、递归、DFS。

队列一端进另一端出，先进先出，典型用途是 BFS、缓冲、调度。

一个像弹夹，一个像排队。

**3. 满二叉树 vs 完全二叉树。**

满二叉树每一层都满，结点数一定是 2^h − 1。

完全二叉树只允许最后一层不满，而且结点靠左排。

满一定完全，完全不一定满。

**4. 树 vs 森林。**

树只有一个根，森林是若干棵互不相交的树。

森林加一个虚拟根就是树，树删掉根就是森林。

树转二叉树用"左孩子右兄弟"，森林转二叉树把各棵树的根当兄弟串起来。

**5. Prim vs Kruskal。**

Prim 从点集长出去，每次选"树内连树外"的最小边，O(n²)，适合稠密图。

Kruskal 全局挑最小边，用并查集判环，O(e log e)，适合稀疏图。

两者求出的权值相同，形态可能不同。

**6. Dijkstra vs Floyd。**

Dijkstra 单源，贪心，每轮锁定一个最近点，不能有负权，O(n²)。

Floyd 多源，动态规划，k 在外层，允许负权但不能有负环，O(n³)。

一个一次算一行，一个一次算一张表。

**7. BFS vs DFS。**

BFS 用队列，一层一层推，能求无权图的最短路径。

DFS 用栈或递归，一条路走到黑，能求连通分量、判环。

邻接表下都是 O(n+e)，邻接矩阵下都是 O(n²)。

**8. 折半查找 vs 分块查找。**

折半要求全表有序且顺序存储，O(log n)，插入删除要维持有序。

分块只要求块间有序、块内无序，先查索引再查块，√n 量级。

折半更快，分块更好维护。

**9. B 树 vs B+ 树。**

B 树每个结点都存关键字和记录，查找可能在内部结点就结束。

B+ 树只有叶子存记录，内部结点只当索引，叶子用链表串起来。

B+ 树每次查找都走到叶子，路径等长，范围查询只要顺着叶子链扫。

**10. 开放定址 vs 链地址。**

开放定址冲突时在表内另找空位，装填因子不能高，删除要留标记。

链地址把同地址的记录挂成链表，装填因子可以大于 1，删除方便。

开放定址省指针、缓存友好；链地址抗冲突、实现简单。

**11. 稳定 vs 不稳定。**

稳定：关键字相同的记录，排完相对次序不变。

稳定：插入类、冒泡、归并、基数。

不稳定：简单选择、希尔、快速、堆。

口诀"快选希堆不稳定"。

**12. 内排序 vs 外排序。**

内排序数据全在内存，看比较次数和移动次数。

外排序数据在磁盘，看 I/O 次数，靠多路归并、败者树、置换选择。

外排序的瓶颈是磁盘，不是 CPU。

**13. 逻辑结构 vs 存储结构。**

逻辑结构是"看起来什么关系"：集合、线性、树、图。

存储结构是"内存里怎么摆"：顺序、链式、索引、散列。

同一个逻辑结构可以有多种存储：线性表可以是顺序表，也可以是链表。

**14. 头指针 vs 头结点。**

头指针是指向第一个结点的指针，丢了它整个链表就丢了。

头结点是第一个元素之前附加的结点，数据域通常空着。

有头结点，在表头插入删除不用特判；没有，代码里要多一个 if。

**15. 邻接矩阵 vs 邻接表。**

邻接矩阵 n×n，判断两点是否相邻 O(1)，空间 O(n²)，适合稠密图。

邻接表只存存在的边，空间 O(n+e)，找邻居快，判断两点相邻要扫链表。

无向图的邻接矩阵对称，邻接表每条边存两次。

**16. AOV vs AOE。**

AOV 顶点表示活动，边表示先后约束，求拓扑序，判"能不能排完"。

AOE 边表示活动，权是持续时间，顶点表示事件，求关键路径，算"最短要多久"。

一个管顺序，一个管工期。

**17. 深度 vs 高度。**

深度从根往下数，根在第 1 层。

高度从叶子往上数，树的高度等于最大层数。

数值往往一样，起点不一样；题目说"高度为 h"时先确认根算第几层。

**18. 大根堆 vs 小根堆。**

大根堆每个结点不小于孩子，堆顶是最大值，升序排序用它。

小根堆每个结点不大于孩子，堆顶是最小值，优先队列取最小用它。

建堆都是 O(n)，插入删除都是 O(log n)。

**19. 朴素匹配 vs KMP。**

朴素匹配失配后主串指针回退，最坏 O(nm)。

KMP 主串指针不回退，靠 next 跳模式串，O(n+m)。

KMP 的代价是先花 O(m) 求 next。

**20. 顺序查找 vs 折半查找。**

顺序查找不要求有序，O(n)，ASL = (n+1)/2。

折半查找要求有序且顺序存储，O(log n)。

链表不能折半，因为算不出中间位置。

二十组过完，如果只能记住一句：

**两个概念的区别，永远落在"谁更快、谁更省、谁更稳"三件事上。**

## 14. 收尾：带走一句话

整套 23 篇，如果要压成一句。

```text
数据结构，是用"多存一点结构"换"少做一点操作"。
```

再展开一点。

```text
顺序表   → 用连续的空间，换 O(1) 的随机访问
链表     → 用指针的空间，换 O(1) 的插入删除
散列表   → 用一张表的空间，换 O(1) 的查找
B+ 树    → 用多一层索引，换更少的磁盘 I/O
```

四次交换，四种结构。

但每一次交换都有代价，代价就写在复杂度里。

```text
顺序表换来了随机访问，代价是插入删除要搬家
链表换来了插入删除，代价是查找要顺着走
散列表换来了平均 O(1)，代价是最坏情况和额外空间
B+ 树换来了稳定的 I/O 次数，代价是插入删除要分裂合并
```

408 考的是这些取舍。

这也是为什么这门课不背"最优解"。

没有最优，只有"在这个场景下最不坏"。

写代码时用的是这些取舍。

读源码时看到的，还是这些取舍。

如果这套系列只让你记住一件事，那应该是这句：

**遇到任何一个数据结构问题，先问"它用哪种结构，换来了哪个操作，代价是什么"。**

答得出这个问题，剩下的都是细节。
