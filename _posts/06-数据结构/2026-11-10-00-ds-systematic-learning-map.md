先看一个问题。

你有 100 万条名字，要判断"张三"在不在里面。

最笨的办法：从头到尾看一遍。

平均要看 50 万次。

如果这些名字事先按拼音排好序呢？

每次看中间那个，比一下大小，砍掉一半。

50 万 → 25 万 → 12.5 万 → ……

**20 次就够了。**

同样的数据，同样的电脑，差了 2.5 万倍。

**反直觉的点在这里：**

```text
让程序变快的，往往不是更快的电脑，
而是换一种"存法"。
```

数据结构这门课，研究的就是"怎么存"以及"存法带来的代价"。

## 1. 数据结构到底在研究什么

三个词：

```text
数据：一堆要处理的东西（名字、分数、路口、网页）。
结构：这些东西之间有什么关系（排成一排？分成层？连成网？）。
操作：你要对它做什么（查、插、删、遍历、排序）。
```

数据结构 = **数据 + 关系 + 操作 + 代价**。

注意最后那个"代价"。

同一个问题，用数组和用链表，代码都能写出来。

但一个插入快、查询慢，另一个反过来。

这门课不教你"唯一正确的写法"。

它教你**在什么场景下选哪种，以及为什么**。

## 2. 在往下读之前：六个常识

在读正文之前，先认识六个词。

**1. 数据元素**

你要处理的一个整体，比如一条学生记录。

**2. 下标**

一排格子的编号，从 0 开始。

`a[0]` 是第一个，`a[1]` 是第二个。

**3. 内存**

一排带编号的格子，每个格子放一个字节。

数组就是"连续的一段格子"。

**4. 指针**

一个格子的地址（门牌号）。

通过指针能"找到"另一个格子。

**5. 递归**

一个函数自己调用自己。

比如"算 n 的阶乘"= n × "算 n−1 的阶乘"。

**6. 复杂度**

不是"跑几秒"，而是"数据量翻倍时，工作量翻几倍"。

翻一倍叫 O(n)，翻两倍叫 O(n²)。

这六个词就是整套讲解的地基。

后面每出现一个新词，都会像这样先解释，再使用。

## 3. 五种逻辑结构

逻辑结构 = 数据之间"看起来"是什么关系，和内存怎么摆无关。

```text
集合：元素之间没有关系，只是"都在一个筐里"。
线性：排成一排，每个元素有唯一的前驱和后继（数组、链表、栈、队列）。
树：一对多，一个上级管若干下级（目录、家族树）。
图：多对多，谁都能连谁（地图、社交网络）。
```

还有一类特殊的：

```text
散列：不算关系，靠一个函数直接算出位置（哈希表）。
```

408 考的，就是这五类。

## 4. 四种物理存储

逻辑结构是"想法"，存储结构是"落地"。

```text
顺序存储：用一段连续的内存，靠下标算位置。
链式存储：每个元素单独放，靠指针串起来。
索引存储：额外建一张"目录表"，先查目录再找数据。
散列存储：用哈希函数直接算出地址。
```

一句话记住区别：

```text
顺序存储靠"算"（下标 × 元素大小 + 基址）。
链式存储靠"找"（顺着指针一个个走）。
```

**这就是数组查询快、链表插入快的根本原因。**

画出来：

```text
顺序存储（数组）
┌────┬────┬────┬────┐
│ 10 │ 20 │ 30 │ 40 │   地址连续，a[i] 一步到位
└────┴────┴────┴────┘

链式存储（链表）
┌────┬──┐   ┌────┬──┐   ┌────┬──┐
│ 10 │──┼──►│ 20 │──┼──►│ 30 │╳ │   地址分散，只能顺着走
└────┴──┘   └────┴──┘   └────┴──┘
```

## 5. 复杂度：为什么必须学会估

复杂度不是"跑多快"，是"数据变多时，代价怎么涨"。

常见的几档：

```text
O(1)      常数     查数组第 i 个
O(log n)  对数     折半查找、平衡树
O(n)      线性     遍历一遍
O(n log n)        归并排序、堆排序
O(n²)     平方     冒泡、直接插入（最坏）
O(2ⁿ)     指数     暴力枚举子集
```

一个直观的对比：

```text
n = 100 万时
O(log n) ≈ 20 次
O(n)     = 100 万次
O(n²)    = 1 万亿次
```

**所以 408 的算法题，第一步永远是问复杂度。**

## 6. 三张必须能画的图

### 6.1 数组与链表

```text
数组：随机访问 O(1)，插入删除 O(n)（要搬家）
链表：随机访问 O(n)（要走过去），插入删除 O(1)（改指针）
```

### 6.2 二叉树与遍历

```text
        A
      /   \
     B     C
    / \   /
   D   E F

先序：A B D E C F   （根 → 左 → 右）
中序：D B E A F C   （左 → 根 → 右）
后序：D E B F C A   （左 → 右 → 根）
层序：A B C D E F   （一层一层）
```

### 6.3 图的两种遍历

```text
      A ─── B
      │     │
      C ─── D

BFS（队列）：A → B → C → D
DFS（栈/递归）：A → B → D → C
```

## 7. 三个必算的量

### 7.1 平均查找长度 ASL

```text
ASL = Σ（第 i 个元素被查到的概率 × 找到它要比较的次数）
```

等概率时，就是"每个元素比较次数之和 ÷ 元素个数"。

顺序查找 n 个元素：ASL = (1+2+…+n)/n = (n+1)/2。

### 7.2 时间复杂度

数"基本操作执行了多少次"，保留最高阶、丢掉系数。

```text
3n² + 5n + 7  →  O(n²)
```

### 7.3 排序的比较次数与趟数

```text
冒泡：n−1 趟，最坏比较 n(n−1)/2 次
快速：平均 O(n log n)，最坏 O(n²)（已有序且取端点为基准）
归并：始终 O(n log n)，但要额外 O(n) 空间
```

## 11. 五个应该能回答的问题

**第一问：数组下标为什么从 0 开始？**

```text
提示：a[i] 的地址 = 基址 + i × 元素大小。
从 0 开始，i 正好是"偏移几个元素"，不用减 1。
```

（02 篇）

**第二问：链表插入是 O(1)，为什么查找前驱还是 O(n)？**

```text
提示：插入本身只改指针，但你得先"走到"那个位置。
```

（03 篇）

**第三问：KMP 为什么能跳过？**

```text
提示：它利用"已匹配部分的前缀等于后缀"这个信息，
不回退主串指针。
```

（06 篇）

**第四问：为什么快排最坏是 O(n²)？**

```text
提示：每次选的基准都是最大或最小，划分极不均匀。
```

（18 篇）

**第五问：散列表查找是 O(1) 吗？**

```text
提示：平均是 O(1)，但冲突多、装填因子高时会退化。
```

（17 篇）

## 12. 小结

数据结构这门课，压成一句话：

```text
选一种存法，让它最常用的那个操作最便宜。
```

五种逻辑结构：

```text
集合、线性、树、图、散列
```

两种主要存法：

```text
顺序（靠算）、链式（靠找）
```

三个必算量：

```text
ASL、复杂度、趟数/比较次数
```

下一篇正式开始：

```text
数据结构系统讲解 01：绪论：数据结构、抽象数据类型与复杂度
```

那一篇会回答：

```text
数据结构和数据类型差在哪？

O(1) 和 O(log n) 差多少？
```

从下一篇开始，每看到一个结构，都要问一句：**它最贵的操作是什么？**
