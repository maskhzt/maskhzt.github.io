> **读这篇之前，你只需要知道**：线性表是"排成一排"的一串元素，每个元素有唯一的前驱和后继；顺序存储是把元素放在一段连续的内存里，靠下标算地址；指针是一个格子的门牌号。
> **这篇讲什么**：队列只准一头进一头出，用数组实现时会撞上"假溢出"，解法是把数组接成一个圈；数组本身则是一个能把地址直接算出来的结构，正因为能算，才有"压缩存储"这种把矩阵塞进一维数组的技巧。
> **一个类比**：一根传送带，货从一端上、另一端下。传送带长度固定，转满一圈就得从头再来；如果只在直线段上跑，跑到底就停住，前面明明还有空位也用不上。


键盘上敲十个字符，程序只读走三个。

剩下七个去哪了？

在缓冲区里排队等着。

缓冲区（buffer）就是一个队列。

先敲进去的先被读走，后敲的排在后面。

没有这个队列，只有两种下场：

要么后来的字符把前面的覆盖掉，要么程序干脆把字符丢掉。

**反直觉的地方在这里：**

队列用数组实现，最贵的操作不是入队，也不是出队——这两个都是 O(1)。

最贵的是"判断它到底满了没有"。

为了这一个判断，人们发明了至少三种方案，而 408 每年都在这个点上出选择题。

## 1. 排队这件事：队列约束了什么

**没有队列，打印机就只能靠抢。**

三个任务同时要打印，谁先拿到设备？没有规矩，就是随机。

队列给出的规矩只有一条：**先来的先走**。

队列（queue）的定义很窄：

```text
只允许在一端插入，在另一端删除的线性表。
插入的那一端叫队尾（rear）。
删除的那一端叫队头（front）。
```

窄，是它的全部价值。

栈允许你在同一端又进又出，所以它能做"撤销"。

队列不给你这个自由，所以它能做"排队"。

两种结构都是线性表，差别只在"允许在哪动"。

```text
栈：  进 ─┐
          ├─ 同一端        后进先出 LIFO
      出 ─┘

队列：进 ──────►  [ ][ ][ ][ ]  ──────► 出
      队尾                              队头
                                先进先出 FIFO
```

队列的基本操作有五个：

```text
InitQueue(&Q)      初始化，造一个空队列
QueueEmpty(Q)      判空
EnQueue(&Q, x)     入队，放到队尾
DeQueue(&Q, &x)    出队，从队头取走
GetHead(Q, &x)     只看队头，不取走
```

五个操作里，四个都是 O(1)。

这就是队列在设计上的全部追求：**任何单个操作都不能跟队列长度有关**。

后面所有的麻烦，都来自这句"不能跟长度有关"。

因为一旦允许 O(n)，判满可以用"数一遍元素个数"来解决，就什么都不用发明了。

这个差别决定了两者的用途完全不重叠。

栈适合处理最近发生的事：函数返回、括号匹配、撤销。

队列适合处理最早发生的事：打印任务、进程调度、消息投递。

一句话：栈记住的是刚刚，队列记住的是先后。

还有一种结构叫优先队列（priority queue）。

它不按来的先后出队，按优先级出队。

严格说它不是队列，是堆。

后面排序那一篇会再见到它。

队列的操作构成一个抽象数据类型（abstract data type, ADT）。

ADT 只规定能做什么，不规定怎么存。

用数组存是队列，用链表存也是队列。

后面两节讨论的顺序队列和链式队列，就是同一个 ADT 的两种落地方式。

## 2. 顺序队列：最小模型

**如果不记录队头在哪，出队就得把整个数组往前搬一格。**

那就成了 O(n)。

所以顺序队列（sequential queue）必须用两个下标记住位置。

```c
#define MAXQSIZE 8

typedef struct {
    int  data[MAXQSIZE];
    int  front;   /* 队头元素的下标 */
    int  rear;    /* 队尾元素下一个位置的下标 */
} SqQueue;
```

约定很关键，先钉死：

```text
front 指向"当前队头元素"。
rear  指向"下一个可以放元素的位置"。
```

于是：

```text
空队列：front == rear
入队：  Q.data[Q.rear] = x;  Q.rear++
出队：  x = Q.data[Q.front]; Q.front++
```

入队出队各一行，都是 O(1)。

看起来完美。

跑一遍就露馅了。

```c
int EnQueue(SqQueue *Q, int x) {
    if (Q->rear == MAXQSIZE) return 0;   /* 上溢出 */
    Q->data[Q->rear++] = x;
    return 1;
}

int DeQueue(SqQueue *Q, int *x) {
    if (Q->front == Q->rear) return 0;   /* 下溢：空队 */
    *x = Q->data[Q->front++];
    return 1;
}
```

问题在 `Q->rear == MAXQSIZE` 这个判断上。

它判的不是"队列满"，它判的是"数组用完了"。

这两件事在队列里不是一回事。

这两个函数里藏着两个术语。

队满还往里塞，叫上溢（overflow）。

队空还往外取，叫下溢（underflow）。

上溢是真错误，必须处理；下溢往往只是暂时没数据，可以等。

很多教材把两者笼统叫溢出，408 会专门拿这个区分出题。

还有一处约定值得说清：为什么 `rear` 指向下一个空位，而不是当前队尾？

因为入队最自然的写法是先写再移，`data[rear++] = x` 一行就够。

如果 `rear` 指向当前队尾，入队就得写成 `data[++rear] = x`，初始值还要设成 −1，空队列的判据也跟着变复杂。

两种约定都能用，混用就是灾难。

做题时先看题干怎么定义，再动手。

## 3. 假溢出：明明有空位却进不来

**没有"循环"这个概念，数组前部空出来的格子永远用不上。**

举个例子，`MAXQSIZE = 8`：

```text
初始        front=0, rear=0
入 A~G      front=0, rear=7        存了 7 个

┌────┬────┬────┬────┬────┬────┬────┬────┐
│ A  │ B  │ C  │ D  │ E  │ F  │ G  │    │
└────┴────┴────┴────┴────┴────┴────┴────┘
  ↑front                              ↑rear

出 A、B     front=2, rear=7        还剩 5 个

┌────┬────┬────┬────┬────┬────┬────┬────┐
│    │    │ C  │ D  │ E  │ F  │ G  │    │
└────┴────┴────┴────┴────┴────┴────┴────┘
              ↑front                  ↑rear
```

现在数组前面空了 2 格，后面还剩 1 格。

再入队一个 H，`rear` 变成 8。

再入队 I，`Q->rear == MAXQSIZE` 成立，返回失败。

可队列里只有 6 个元素，数组有 8 格。

**这就是假溢出（false overflow）。**

真溢出是"元素个数超过了容量"，假溢出是"指针走到头了，但前面有空位"。

区别很大：真溢出必须扩容或拒绝，假溢出只是走路的方式不对。

两条解法摆在面前：

```text
方案一：出队时把后面所有元素往前搬一格。O(n)，每次出队都搬，废掉。
方案二：让 rear 走到 8 之后回到 0。O(1)，不用搬。
```

方案二就是循环队列。

假溢出的本质是：数组用完和队列满，不是一回事。

数组用完，说的是物理下标走到头了。

队列满，说的是元素个数到了容量。

在直线数组上，这两个条件被绑在一起，所以看起来一样。

一旦把数组首尾接上，它们就分开了：元素个数可以等于容量，而下标永远不越界。

这中间有个取舍值得记住。

如果不允许回绕，唯一能做的就是出队时把后面的元素整体前移。

那是 O(n)，而且每次出队都要搬，队列就废了。

所以循环不是优化，是必需。

## 4. 循环队列：把数组接成一个圈

**如果不把数组首尾接上，假溢出只能用搬迁来绕，一搬就退化成 O(n)。**

循环队列（circular queue）做的事，只是把下标算术换掉：

```text
rear++  变成  rear = (rear + 1) % MAXQSIZE
front++ 变成  front = (front + 1) % MAXQSIZE
```

数组没变，还是一段连续内存。

变的是"下标怎么走"：走到末尾就回到开头。

```text
        ┌───────────────────────────┐
        │                           │
        ▼                           │
   ┌────┬────┬────┬────┬────┬────┬──┴─┬────┐
   │ 0  │ 1  │ 2  │ 3  │ 4  │ 5  │ 6  │ 7  │
   └────┴────┴────┴────┴────┴────┴────┴────┘
```

代价是：不能再靠 `rear == MAXQSIZE` 判满了。

因为 `rear` 永远在 0 到 7 之间打转。

```c
#define MAXQSIZE 8

typedef struct {
    int data[MAXQSIZE];
    int front;
    int rear;
} SqQueue;

void InitQueue(SqQueue *Q) {
    Q->front = Q->rear = 0;
}

int QueueLength(SqQueue Q) {
    return (Q.rear - Q.front + MAXQSIZE) % MAXQSIZE;
}
```

`QueueLength` 里那个 `+ MAXQSIZE` 是必须的。

因为 C 的取模对负数返回负数，`rear - front` 一旦为负，不加上一个周期就会得到错误的长度。

这是 408 选择题的常客，也是真实代码里的常见 bug。

现在问题集中到一点：**`front == rear` 到底是空还是满？**

取模在这里的作用，是把一条直线折成一个圆。

`(rear + 1) % MAXQSIZE` 的取值永远落在 0 到 MAXQSIZE−1 之间。

这就是环的全部含义：不是内存真的弯了，是下标算出来会回绕。

真实系统里还有一个加速技巧。

把 MAXQSIZE 取成 2 的幂，`% MAXQSIZE` 就能换成 `& (MAXQSIZE - 1)`。

因为对 2 的幂取模，等价于只取二进制的低位。

一个取模指令在早期 CPU 上要几十个周期，位与只要一个周期。

这就是缓冲区容量总是 2 的幂的来由。

还要提醒一点：循环队列不能像普通数组那样从头 `for` 到尾。

遍历必须从 `front` 开始走 `count` 步，每一步取模。

直接写 `for (i = 0; i < MAXQSIZE; i++)` 会把已经出队的垃圾一起打出来。

## 5. 手算：判空判满的三种方案

**如果只用 front 和 rear 两个下标，空和满的判据会撞车。**

因为空队列是 `front == rear`。

转一圈装满之后，`rear` 又追上 `front`，还是 `front == rear`。

同一个条件，两种含义。必须引入额外信息。

三种主流方案：

```text
方案一：牺牲一个存储单元。少存一个，用位置差区分。
方案二：加一个计数器 count。用元素个数区分。
方案三：加一个标志位 tag。记录最近一次是入队还是出队。
```

### 5.1 方案一：牺牲一个单元

规定：**队尾指针的下一个位置就是队头，就算满。**

```c
int QueueFull(SqQueue Q)  { return (Q.rear + 1) % MAXQSIZE == Q.front; }
int QueueEmpty(SqQueue Q) { return Q.front == Q.rear; }
```

容量从 8 变成 7。

用这 7 的容量，把前面那个例子重算一遍。

```text
MAXQSIZE = 8，实际最多存 7 个

操作             front  rear   队列内容（按逻辑顺序）        判定
------------------------------------------------------------------
初始              0      0     空                          空
入 A              0      1     A
入 B              0      2     A B
入 C              0      3     A B C
入 D              0      4     A B C D
入 E              0      5     A B C D E
入 F              0      6     A B C D E F
入 G              0      7     A B C D E F G
入 H              0      7     拒绝： (7+1)%8 = 0 == front   满
出队 → A          1      7     B C D E F G
出队 → B          2      7     C D E F G
入 H              2      0     C D E F G H                 rear 绕回 0
入 I              2      1     C D E F G H I               rear = 1
入 J              2      1     拒绝： (1+1)%8 = 2 == front   满
```

停止时的数组长这样：

```text
下标    0    1    2    3    4    5    6    7
      ┌────┬────┬────┬────┬────┬────┬────┬────┐
      │ I  │    │ C  │ D  │ E  │ F  │ G  │ H  │
      └────┴────┴────┴────┴────┴────┴────┴────┘
              ↑    ↑front
              └── rear（下一个可写位置，此格空闲）

元素个数 = (1 - 2 + 8) % 8 = 7       恰好等于容量上限
队头元素 = data[2] = C
队尾元素 = data[(rear - 1 + 8) % 8] = data[0] = I
```

注意队尾元素的下标算法：`rear` 指向的是**下一个可写位置**，所以真正的队尾要往前退一格，且退的时候也要取模。

这一步错，队尾元素就永远读成 0 或者越界。

### 5.2 方案二：加计数器

```c
typedef struct {
    int data[MAXQSIZE];
    int front, rear;
    int count;              /* 当前元素个数 */
} SqQueue2;

int QueueFull(SqQueue2 Q)  { return Q.count == MAXQSIZE; }
int QueueEmpty(SqQueue2 Q) { return Q.count == 0; }
```

一个 `count` 字段，两个判断都变直白，而且**容量不再损失**。

同样的操作序列，能多存一个：

```text
MAXQSIZE = 8，实际最多存 8 个

入 A~G      front=0 rear=7 count=7
入 H        front=0 rear=0 count=8    (写下标 7，rear 绕回 0)
入 I        拒绝：count == 8，满
出 A、B     front=2 rear=0 count=6
入 I        front=2 rear=1 count=7    (写下标 0)
```

代价是每次入队出队都要维护 `count`。

入队 `count++`，出队 `count--`。

在多线程环境里，这个额外的共享变量是实打实的成本——它让"读 front/rear 判断状态"变成了"必须原子地读改写 count"。

### 5.3 方案三：加标志位

```c
typedef struct {
    int data[MAXQSIZE];
    int front, rear;
    int tag;                /* 0：上次是出队；1：上次是入队 */
} SqQueue3;

int QueueEmpty(SqQueue3 Q) { return Q.front == Q.rear && Q.tag == 0; }
int QueueFull(SqQueue3 Q)  { return Q.front == Q.rear && Q.tag == 1; }
```

道理是：指针相等时，只有两种可能。

上一次操作是出队 → 队列被取空了 → 空。

上一次操作是入队 → 入队把 rear 追上了 front → 满。

一个 bit 就够，容量也不损失。

### 5.4 三种方案对比

| 方案 | 判空 | 判满 | 容量 | 额外状态 |
|---|---|---|---|---|
| 牺牲一个单元 | `front == rear` | `(rear+1)%M == front` | M−1 | 无 |
| 计数器 | `count == 0` | `count == M` | M | 一个整数 |
| 标志位 | `front==rear && tag==0` | `front==rear && tag==1` | M | 一个 bit |

408 最常考第一种。

因为它不需要额外字段，只用两个下标就能推出全部结论，出题方便。

代价是"最多存 M−1 个"这句话必须记牢——问"容量为 8 的循环队列最多存几个"，答 7，不是 8。

三种判据写成完整的 C 代码，差别一目了然。

```c
/* 方案一：牺牲一个单元 */
int Empty1(SqQueue  Q) { return Q.front == Q.rear; }
int Full1 (SqQueue  Q) { return (Q.rear + 1) % MAXQSIZE == Q.front; }

/* 方案二：计数器 */
int Empty2(SqQueue2 Q) { return Q.count == 0; }
int Full2 (SqQueue2 Q) { return Q.count == MAXQSIZE; }

/* 方案三：标志位 */
int Empty3(SqQueue3 Q) { return Q.front == Q.rear && Q.tag == 0; }
int Full3 (SqQueue3 Q) { return Q.front == Q.rear && Q.tag == 1; }
```

注意方案二和方案三里，`front` 和 `rear` 的推进方式完全没变。

变的只是多维护一个变量，用这个变量去区分撞车的两种情形。

这也是数据结构里常见的一种设计手法：主结构不动，加一个辅助量把歧义消掉。

三种方案在 408 里的出现比例大概是 7 : 2 : 1。

牺牲一个单元是绝对主力，因为它只用两个变量，题干最短。

另外两种必须认得——题干一旦出现 `count` 或 `tag` 字段，判据就完全不同了。

## 6. 链式队列与双端队列

**如果元素个数事先不知道，顺序队列就只能靠"估一个够大的 MAXQSIZE"。**

估小了溢出，估大了浪费。

链式队列（linked queue）用指针解决这个问题。

```c
typedef struct LNode {
    int data;
    struct LNode *next;
} LNode, *LinkQueuePtr;

typedef struct {
    LinkQueuePtr front;     /* 队头指针，指向头结点；front->next 才是第一个元素 */
    LinkQueuePtr rear;      /* 队尾指针，指向最后一个元素 */
} LinkQueue;

void InitQueue(LinkQueue *Q) {
    Q->front = Q->rear = (LinkQueuePtr)malloc(sizeof(LNode));
    Q->front->next = NULL;      /* 头结点的 next 为空，表示队列空 */
}
```

头结点在这里很重要。

没有头结点，出队到队列变空时，`rear` 会变成野指针。

有了头结点，空队列就是 `front == rear == 头结点`，出队永远只动 `front->next`。

```text
空队列：
  ┌────────┐
  │ 头结点 │  next = NULL
  └────────┘
   ↑front
   ↑rear

入队 A、B 之后：
  ┌────────┐    ┌───┐    ┌───┐
  │ 头结点 │──► │ A │──► │ B │  next = NULL
  └────────┘    └───┘    └───┘
   ↑front                 ↑rear
```

```c
int EnQueue(LinkQueue *Q, int x) {
    LinkQueuePtr p = (LinkQueuePtr)malloc(sizeof(LNode));
    if (!p) return 0;
    p->data = x;
    p->next = NULL;

    Q->rear->next = p;      /* 挂到队尾后面 */
    Q->rear = p;            /* 尾指针后移 */
    return 1;
}

int DeQueue(LinkQueue *Q, int *x) {
    if (Q->front == Q->rear) return 0;      /* 空 */

    LinkQueuePtr p = Q->front->next;        /* 真正的队头元素 */
    *x = p->data;
    Q->front->next = p->next;

    if (Q->rear == p)                       /* 取走的正是最后一个 */
        Q->rear = Q->front;                 /* 尾指针退回，否则悬空 */
    free(p);
    return 1;
}
```

`if (Q->rear == p)` 这一行是链式队列最容易漏的地方。

漏了它，队列被取空之后 `rear` 还指着已经 `free` 掉的内存，下一次入队就往野指针上挂。

### 双端队列

双端队列（double-ended queue, deque）是队列的放宽版：

```text
两端都可以插入，两端都可以删除。
```

限制其中一端，得到两个变体：

```text
输入受限双端队列：只允许在一端插入，两端都能删除。
输出受限双端队列：两端都能插入，只允许在一端删除。
```

408 喜欢考"某个输出序列能不能由给定输入序列得到"。

举个能验证的例子：输入序列 1, 2, 3, 4 依次插入，用**输入受限**双端队列（只能从左端插入，两端都能删），能否得到 4, 2, 3, 1？

```text
不能。

要第一个输出 4，必须先把 1,2,3,4 全部从左端插入：
        左端 →  4  3  2  1  ← 右端
删除 4（左端），剩下  3  2  1
要第二个输出 2：左端是 3，右端是 1，2 卡在中间，取不到。
```

而 4, 1, 2, 3 是可以的：

```text
左端删 4 → 剩 3 2 1
右端删 1 → 剩 3 2
右端删 2 → 剩 3
右端删 3
```

这就是双端队列题的全部解法：**永远盯着"目标序列的下一个元素在不在两端"**。

顺序队列和链式队列怎么选？

顺序队列不花指针，内存连续，缓存友好，但容量固定。

链式队列每次入队都要 `malloc`，有分配开销，但长度不限。

一个粗略的判据：

元素个数上限明确、波动不大，用顺序队列。

元素个数说不准、或者要长期运行，用链式队列。

真实系统里还有第三条路：预先分配一块大数组，满了就整体翻倍扩容。

扩容时把旧数据搬到新数组，均摊下来每次入队还是 O(1)。

多数语言标准库里的队列都是这个实现。

还有一句话要记住：双端队列题不需要真的模拟。

把目标序列从两端往里对，看每一步要的元素在不在两端。

对不上就是不可能。

这比画十步 deque 快得多，也更不容易错。

## 7. 数组：地址为什么能算出来

**如果地址不能算，访问第 100 万个元素就得从头走 100 万步。**

数组（array）的全部力量，来自一个乘法。

一维数组：

```text
LOC(a[i]) = LOC(a[0]) + i × L          L 是每个元素占的字节数
```

二维数组要先把"行和列"摊平成一维。

两种摊法，就要记两个公式。

**行优先（row-major）**：先存完一整行，再存下一行。

```text
LOC(a[i][j]) = LOC(a[0][0]) + (i × n + j) × L        n 是列数
```

**列优先（column-major）**：先存完一整列，再存下一列。

```text
LOC(a[i][j]) = LOC(a[0][0]) + (j × m + i) × L        m 是行数
```

手算一道。

```text
二维数组 A[0..8][0..9]，每个元素占 3 字节，
A[0][0] 的地址是 1000。
求 A[5][6] 的地址（行优先 / 列优先各算一遍）。
```

```text
行数 m = 9，列数 n = 10。

行优先：
  在 A[5][6] 之前有 5 整行 = 5 × 10 = 50 个元素，
  第 5 行里前面有 6 个元素，
  共 50 + 6 = 56 个元素。
  地址 = 1000 + 56 × 3 = 1000 + 168 = 1168

列优先：
  在 A[5][6] 之前有 6 整列 = 6 × 9 = 54 个元素，
  第 6 列里前面有 5 个元素，
  共 54 + 5 = 59 个元素。
  地址 = 1000 + 59 × 3 = 1000 + 177 = 1177
```

两个答案差 9 个字节，正好是"3 行 × 3 字节"。

因为行优先和列优先的差别，就是把"走完一行"换成"走完一列"。

**这就是数组能随机访问的全部秘密：地址是一个算术式，不是一个查找过程。**

链表做不到，因为链表的下一个元素在哪，只能顺着指针去读。

数组还有两个别的结构没有的性质。

一是元素个数固定。定义之后不能插入一个，只能改。

二是元素类型相同，每个元素占的字节数一样。

第二条是随机访问的前提。

如果每个元素大小不同，`i × L` 这个式子就写不出来。

三维以上同理，只是多套一层。

`A[d1][d2][d3]` 行优先的偏移是 `(i × d2 + j) × d3 + k`。

记法只有一条：从最外层往里，每进一层就乘上那一维的长度。

这就是行优先的递归定义。

## 8. 对称矩阵：一半的元素是多余的

**如果不压缩，一个 1000 阶对称矩阵要占 100 万个元素的位置，其中 49.5 万个是重复的。**

对称矩阵（symmetric matrix）的定义：

```text
n 阶方阵 A，满足 a[i][j] == a[j][i] 对所有 i, j 成立。
```

也就是沿主对角线翻折，两边一样。

真正独立的信息只有下三角（或上三角）加对角线。

```text
元素个数 = 1 + 2 + 3 + ... + n = n(n+1)/2
```

n = 1000 时：1000 × 1001 / 2 = 500500。

从 100 万降到 50 万，省了一半。

压缩存储（compressed storage）要做的事，就是建一个长度为 `n(n+1)/2` 的一维数组 B，把下三角按行优先塞进去，再给出一个公式，把 `(i, j)` 算成 B 的下标 `k`。

```text
只存下三角（含对角线），行优先：

第 0 行：a[0][0]                       1 个
第 1 行：a[1][0] a[1][1]               2 个
第 2 行：a[2][0] a[2][1] a[2][2]       3 个
...
第 i 行之前共有 1 + 2 + ... + i = i(i+1)/2 个元素
第 i 行内，a[i][j] 前面有 j 个元素
```

于是：

```text
i >= j 时：  k = i(i+1)/2 + j
i <  j 时：  k = j(j+1)/2 + i          （利用对称性，翻到下三角去取）
```

手算一道，验证到底。

```text
10 阶对称矩阵 A（下标 0..9），只存下三角，行优先放入 B[0..54]。
求 A[8][5] 和 A[5][8] 在 B 中的下标。
```

```text
B 的长度 = 10 × 11 / 2 = 55，下标范围 0..54。

A[8][5]：i=8 >= j=5，直接算
  k = 8×9/2 + 5 = 36 + 5 = 41

A[5][8]：i=5 < j=8，翻成 A[8][5]
  k = 8×9/2 + 5 = 41

两个落在同一格，符合对称性。
```

再验一次边界：

```text
A[0][0] → k = 0              B 的第一个
A[9][9] → 9×10/2 + 9 = 54    B 的最后一个
A[9][0] → 9×10/2 + 0 = 45    第 9 行的第一个
```

三个都对，公式就是对的。

如果题目改成"只存上三角"，公式对称地反过来：

```text
i <= j 时：k = j(j+1)/2 + i
i >  j 时：k = i(i+1)/2 + j
```

看清楚题目存的是哪一半，比记公式更重要。

为什么 408 特别爱考这一节？

因为它一次考三件事：元素个数、映射公式、以及 `i < j` 时会不会翻折。

第三件最容易漏。

题目给 `A[5][8]`，直接代 `i(i+1)/2 + j` 得 `5×6/2 + 8 = 23`，就错了。

下三角里根本没有 `A[5][8]` 这个位置。

看到 `i < j`，第一反应必须是翻过去。

压缩的效果可以用存储密度衡量。

存储密度 = 数据本身占的空间 ÷ 实际占用的空间。

不压缩时，对称矩阵的存储密度趋近二分之一。

压缩之后接近一。

## 9. 三角矩阵与三对角矩阵

**如果不给常数区一个位置，上三角矩阵里那一片 0 还得各占一格。**

上三角矩阵：主对角线以下全是常数 c（通常是 0）。

```text
┌─────────────┐
│ a  a  a  a  │
│ c  a  a  a  │        下三角全是 c
│ c  c  a  a  │
│ c  c  c  a  │
└─────────────┘
```

存储时，上三角的 `n(n+1)/2` 个元素照常按行优先放。

常数区只留**一个**位置，放在 B 的最后。

```text
B 的长度 = n(n+1)/2 + 1
```

映射公式：

```text
i <= j 时：k = i(2n - i + 1)/2 + (j - i)
i >  j 时：k = n(n+1)/2              （常数区，就在最后一个格子）
```

`i(2n - i + 1)/2` 这一坨是"第 i 行之前有多少个上三角元素"：第 0 行有 n 个，第 1 行有 n−1 个……前 i 行共 `n + (n-1) + ... + (n-i+1)` 个。

下三角矩阵同理，只是把常数区挪到另一边。

### 三对角矩阵

三对角矩阵（tridiagonal matrix）只有一个条件：

```text
|i - j| <= 1 的位置可能非零，其余全是 0。
```

画出来是一条带子：

```text
┌───────────────────┐
│ a  a  ·  ·  ·  ·  │
│ a  a  a  ·  ·  ·  │
│ ·  a  a  a  ·  ·  │
│ ·  ·  a  a  a  ·  │
│ ·  ·  ·  a  a  a  │
│ ·  ·  ·  ·  a  a  │
└───────────────────┘
```

元素个数：

```text
第 0 行 2 个，最后一行 2 个，中间每行 3 个。
共 2 + 3(n-2) + 2 = 3n - 2 个。
```

映射公式（按行优先，下标从 0 开始）：

```text
k = 2i + j        （当 |i - j| <= 1）
```

验一遍 n = 10：

```text
总元素 3×10 - 2 = 28 个，下标 0..27。

A[0][1] → 2×0 + 1 = 1        第 0 行：a[0][0] 在 0，a[0][1] 在 1
A[1][0] → 2×1 + 0 = 2        ✔ 接在第 0 行后面
A[1][2] → 2×1 + 2 = 4
A[8][7] → 2×8 + 7 = 23       ✔ 第 8 行第 1 个（前面 8 行共 2 + 3×7 = 23 个）
A[8][9] → 2×8 + 9 = 25
A[9][8] → 2×9 + 8 = 26
A[9][9] → 2×9 + 9 = 27       ✔ 最后一个
```

全对。

现在反过来算：给一个 k，求 `(i, j)`。

```text
由 k = 2i + j，且 j 只能是 i-1、i、i+1：
  i = (k + 1) / 2     向下取整
  j = k - 2i
```

拿 k = 23 试：`i = 24/2 = 12`？不对。

重算：`k = 2i + j`，j ∈ {i−1, i, i+1}，所以 `3i − 1 <= k <= 3i + 1`。

由此 `i = ⌊(k + 1) / 3⌋`。

k = 23：`i = ⌊24/3⌋ = 8`，`j = 23 − 16 = 7`。

正好是 A[8][7]。

这个"由 k 反求 i, j"是 408 里区分度最高的一种问法，很多人只背了正推公式就卡在这儿。

三对角是最常见的带状矩阵（band matrix）。

一般地，若只有 `|i - j| <= b` 的位置可能非零，就叫半带宽为 b 的带状矩阵。

元素个数 = `(2b + 1)n - b(b + 1)`。

b = 1 时得 `3n - 2`，和三对角对上。

b = 2 时（五对角）得 `5n - 6`。

n = 10 时，五对角有 44 个元素。

408 只考 b = 1，但知道这个通式，遇到变形题不会慌。

## 10. 稀疏矩阵：三元组与十字链表

**如果不记"非零元素在哪"，稀疏矩阵按二维数组存，99% 的空间都在放 0。**

稀疏矩阵（sparse matrix）的定义不严格，但有一条常用的界：

```text
非零元素个数远少于总元素个数，通常认为非零元素占比小于 5%。
```

严格说，"稀疏"是"非零元素随机分布"的意思。

一个 1000×1000 的矩阵，如果只有三对角上有值，它并不稀疏——因为非零元素有规律，可以按公式存。

真正的稀疏矩阵，非零元素的位置是散的，只能一个个记下来。

### 三元组表

最直接的表示：把每个非零元素记成 `(行下标, 列下标, 值)`。

```c
#define MAXSIZE 1000

typedef struct {
    int i, j;          /* 行、列下标 */
    int e;             /* 值 */
} Triple;

typedef struct {
    Triple data[MAXSIZE + 1];   /* data[0] 闲置或存总信息 */
    int    mu, nu, tu;          /* 行数、列数、非零元素个数 */
} TSMatrix;
```

存下来之后，随机存取的能力没了。

要取 `a[3][4]`，必须扫一遍三元组表。

这就是压缩存储的代价：**空间省了，随机访问丢了。**

### 快速转置

转置是稀疏矩阵最常考的操作。

朴素转置：对 B 的每一列扫一遍 A 的三元组表，O(nu × tu)。

快速转置（fast transpose）：先数清楚 A 的每一列有几个非零元素，直接算出它们在 B 里该放哪。

需要两个辅助数组：

```text
num[col]：A 中第 col 列的非零元素个数
cpot[col]：A 中第 col 列的第一个非零元素，在 B.data 中的位置
```

```c
int FastTranspose(TSMatrix A, TSMatrix *B) {
    int num[100] = {0}, cpot[100];
    int col, t, p, q;

    B->mu = A.nu;  B->nu = A.mu;  B->tu = A.tu;
    if (A.tu == 0) return 1;

    for (t = 1; t <= A.tu; t++)
        num[A.data[t].j]++;              /* 数每列有多少个 */

    cpot[1] = 1;
    for (col = 2; col <= A.nu; col++)
        cpot[col] = cpot[col - 1] + num[col - 1];

    for (p = 1; p <= A.tu; p++) {        /* 扫一遍 A 就够了 */
        col = A.data[p].j;
        q = cpot[col];
        B->data[q].i = A.data[p].j;
        B->data[q].j = A.data[p].i;
        B->data[q].e = A.data[p].e;
        cpot[col]++;
    }
    return 1;
}
```

复杂度从 O(nu × tu) 降到 O(nu + tu)。

手算一遍。

```text
A 是 4 行 5 列，非零元素 4 个（用 1 起的下标）：
  (1,2,12)  (2,4,-7)  (3,1,3)  (4,3,9)

求 B = Aᵀ 的三元组表。
```

```text
num：  col=1: 1 个      col=2: 1 个    col=3: 1 个   col=4: 1 个   col=5: 0 个
cpot： 1 → 1
       2 → 1 + 1 = 2
       3 → 2 + 1 = 3
       4 → 3 + 1 = 4
       5 → 4 + 0 = 5

按 A 的三元组顺序扫：

p=1  (1,2,12)  col=2  q=cpot[2]=2  → B[2]=(2,1,12)   cpot[2]=3
p=2  (2,4,-7)  col=4  q=cpot[4]=4  → B[4]=(4,2,-7)   cpot[4]=5
p=3  (3,1,3)   col=1  q=cpot[1]=1  → B[1]=(1,3,3)    cpot[1]=2
p=4  (4,3,9)   col=3  q=cpot[3]=3  → B[3]=(3,4,9)    cpot[3]=4

B = (1,3,3)  (2,1,12)  (3,4,9)  (4,2,-7)
```

B 的三元组按行号递增，正确。

**这个算法之所以叫"快速"，是因为它只扫了 A 一遍。**

`cpot` 提前算好了"每一列该从哪个位置开始写"，所以每个元素一步到位，不用回头移动。

### 十字链表

三元组表有个硬伤：插入、删除一个非零元素要移动大量数据。

十字链表（orthogonal linked list）用两个方向的链表解决。

```c
typedef struct OLNode {
    int i, j, e;
    struct OLNode *right;      /* 同一行右边的下一个非零元素 */
    struct OLNode *down;       /* 同一列下边的下一个非零元素 */
} OLNode, *OLink;
```

每个非零元素同时挂在两条链上：

```text
行链表：把所有 "第 i 行" 的元素从左到右串起来。
列链表：把所有 "第 j 列" 的元素从上到下串起来。
```

```text
        col 1      col 2      col 3
row 1    [3] ─────────────► [12]
          │                   │
          ▼                   ▼
row 2                        [-7]
          │                   │
          ▼                   ▼
row 3    [9]
```

好处是插入和删除都是 O(1)（找到位置后只改指针）。

坏处是每个元素多两个指针，指针的开销可能比数据本身还大。

所以：**非零元素少而稳定，用三元组；要频繁插入删除，用十字链表。**

三元组表还有个变体：行逻辑链接顺序表。

它额外维护一个 `rpos[row]` 数组，记下每一行第一个非零元素在三元组表里的位置。

这样按行访问就不用每次从头扫。

代价只是多一个长度为行数的辅助数组。

这是用小索引换大扫描的典型套路，和后面 B+ 树的思路一脉相承。

还要提醒一句：矩阵稀疏与否，和阶数无关，和分布有关。

10×10 的矩阵有 40 个非零元素，占比 40%，不稀疏。

1000×1000 的矩阵若非零元素全挤在对角线附近，也不该按稀疏矩阵处理。

判断标准是分布有没有规律，不是个数多少。

## 11. 408 怎么考

**如果不背判满条件和下标公式，这类题只能靠现场推，一推就超时。**

题型就四类：

```text
1. 循环队列：给 front/rear，求元素个数；或给操作序列，问满不满。
2. 数组地址：给行列优先、元素大小、首地址，求某个元素的地址。
3. 压缩矩阵：给压缩方案，求 (i,j) 对应的 k；或反过来由 k 求 (i,j)。
4. 稀疏矩阵：快速转置的 num/cpot 计算，或三元组表长度。
```

### 例题一：循环队列

```text
循环队列存放在数组 Q[0..9] 中，front 指向队头元素，
rear 指向队尾元素的下一个位置，采用"牺牲一个单元"的方式判满。

(1) 该队列最多能存多少个元素？
(2) 若 front = 3，rear = 8，队列中有几个元素？
(3) 若 front = 8，rear = 2，队列中有几个元素？
(4) 若 front = 8，rear = 7，此时能否入队？
```

```text
(1) MAXQSIZE = 10，牺牲一个单元，最多 9 个。

(2) (8 - 3 + 10) % 10 = 15 % 10 = 5 个。

(3) (2 - 8 + 10) % 10 = 4 % 10 = 4 个。
    rear 已经绕过数组末尾，所以必须加一个周期。

(4) 判满：(7 + 1) % 10 = 8 == front → 满，不能入队。
    注意此时元素个数 (7 - 8 + 10) % 10 = 9，正好是容量上限。
```

### 例题二：数组地址

```text
二维数组 A[1..6][1..8]，每个元素占 4 字节，
按列优先存储，A[1][1] 的地址是 2000。
求 A[4][6] 的地址。
```

```text
行下标 1..6 共 6 行，列下标 1..8 共 8 列。

列优先：在 A[4][6] 之前有 5 整列（第 1..5 列），
每列 6 个元素，共 5 × 6 = 30 个；
第 6 列里，A[4] 之前有 3 个元素（A[1], A[2], A[3]）。
总偏移 = 30 + 3 = 33 个元素。

地址 = 2000 + 33 × 4 = 2000 + 132 = 2132
```

小心下标的起点。

如果题目改成 `A[0..5][0..7]`，同一个 `(4,6)` 的偏移就变成 `6 × 6 + 4 = 40`，答案完全不同。

**先画一个 2×3 的小数组数一遍，比背公式稳。**

### 例题三：压缩矩阵反求

```text
将 10 阶对称矩阵 A 的下三角（含对角线）按行优先存入一维数组 B，
B 的下标从 0 开始。若 A[i][j]（i >= j）存放在 B[32] 中，
求 i 与 j 的关系。
```

```text
由 k = i(i+1)/2 + j = 32。

试 i = 7： 7×8/2 = 28，j = 32 - 28 = 4，且 j <= i ✔
试 i = 8： 8×9/2 = 36 > 32，不可能。

所以 i = 7，j = 4。
```

### 例题四：容量与个数

```text
一个循环队列的容量为 MAXQSIZE，用计数器方式管理。
队空时 front = rear = 0。
经过 12 次入队、5 次出队后，front、rear、count 各是多少？
```

```text
入队 12 次，rear 前进 12：rear = 12 % MAXQSIZE。
出队 5 次，front 前进 5：front = 5。
count = 12 - 5 = 7。

若 MAXQSIZE = 8：
  rear = 12 % 8 = 4
  front = 5
  count = 7    （正好等于容量，队列是满的）
  验证：(4 - 5 + 8) % 8 = 7 ✔
```

### 例题五：快速转置的 cpot

```text
稀疏矩阵 A 是 6 行 7 列，各列非零元素个数为：
第 0 列 2 个，第 1 列 0 个，第 2 列 3 个，第 3 列 1 个，
第 4 列 0 个，第 5 列 2 个，第 6 列 0 个。
三元组表下标从 1 开始，求 cpot 数组。
```

```text
num  = [2, 0, 3, 1, 0, 2, 0]

cpot[0] = 1
cpot[1] = cpot[0] + num[0] = 1 + 2 = 3
cpot[2] = cpot[1] + num[1] = 3 + 0 = 3
cpot[3] = cpot[2] + num[2] = 3 + 3 = 6
cpot[4] = cpot[3] + num[3] = 6 + 1 = 7
cpot[5] = cpot[4] + num[4] = 7 + 0 = 7
cpot[6] = cpot[5] + num[5] = 7 + 2 = 9

校验：非零元素总数 = 2+0+3+1+0+2+0 = 8 个，
B 用到下标 1..8，下一个空位正好是 9。
```

注意 `cpot` 里有相等的情况（`cpot[1] == cpot[2]`，`cpot[4] == cpot[5]`）。

那不是算错，是因为中间有空的列。

## 12. 常见错误与真实系统

**如果不看真实代码，"循环队列"就只是考试模型，你会在工程里重新踩一遍同样的坑。**

四个高频错误：

```text
错误一：把 MAXQSIZE 当成最大元素个数。
        牺牲一个单元时，最多存 MAXQSIZE - 1 个。
        问"容量为 10 的循环队列最多存几个"，答 9。

错误二：求长度时忘了加 MAXQSIZE。
        C 语言里 (rear - front) 为负时，取模结果还是负的。

错误三：队尾元素写成 data[rear]。
        rear 指向的是"下一个空位"，队尾元素是 data[(rear-1+M)%M]。

错误四：链式队列出队到空时忘了重置 rear。
        队列空了，rear 还指着刚 free 的结点，下一次入队就写野指针。
```

真实系统里，这个结构叫**环形缓冲区（ring buffer）**。

Linux 内核的 `kfifo` 就是它，实现上用了"容量取 2 的幂 + 位与代替取模"这个技巧：

```c
/* 简化示意，不是内核原文 */
#define kfifo_put(fifo, val)  do {                      \
    unsigned int __ret;                                  \
    if (kfifo_is_full(fifo)) { __ret = 0; break; }        \
    fifo->buffer[fifo->in & (fifo->size - 1)] = (val);    \
    fifo->in++;                                           \
} while (0)
```

`in & (size - 1)` 和 `in % size` 等价，条件是 size 必须是 2 的幂。

位与只要一个指令周期，取模在早期 CPU 上要几十个周期。

这就是"容量取 2 的幂"这条设计规矩的真正来由——不是为了对齐，是为了让取模变便宜。

音频、视频的采集卡，网卡的收发队列，日志的写入缓冲，基本都是这个形状。

```text
生产者在一端写，消费者在另一端读。
满了就丢（实时音视频）或者阻塞（日志）。
空了就等。
```

数据库的连接池、线程池的任务队列，用的是同一套下标算术，只是把"满"的处理换成了"扩容"或"阻塞"。

一个常被忽略的事实：队列满了该怎么办，比队列本身更重要。

实时音视频丢最旧的帧，因为旧帧已经没有价值。

日志系统丢日志或者落盘，因为阻塞业务比丢日志更糟。

线程池阻塞生产者，因为任务不能丢。

同一个环形缓冲区，三种满的策略，对应三种完全不同的系统行为。

所以看一个系统的队列设计，先问它的丢弃策略。

答不上来，说明这个设计还没想清楚。

### 自检三问

**第一问：容量为 8 的循环队列，用"牺牲一个单元"判满，最多存几个？**

答：7 个。

判满条件是 `(rear + 1) % 8 == front`，所以 `rear` 永远不能和 `front` 重合，能用的格子少一个。

**第二问：front = 6，rear = 2，MAXQSIZE = 10，队列里有几个元素？**

答：`(2 - 6 + 10) % 10 = 6` 个。

不加 `+ 10` 会得到 `-4`，这是错答案。

**第三问：10 阶对称矩阵只存下三角（行优先，B 下标从 0 开始），A[7][3] 在 B 的哪个位置？**

答：`k = 7×8/2 + 3 = 28 + 3 = 31`。

B 的总长度是 `10×11/2 = 55`，31 在范围内。

## 13. 小结

这一篇压成三句话：

```text
队列的价值在于约束：只准一头进一头出，换来"先来先服务"。
数组的价值在于算术：地址能算，所以随机访问是 O(1)。
压缩存储的价值在于"用公式换空间"，代价是丢掉随机访问。
```

三个必须记住的数字：

```text
循环队列（牺牲一个单元）容量 = MAXQSIZE - 1
对称矩阵元素个数 = n(n+1)/2
三对角矩阵元素个数 = 3n - 2
```

三个必须能默写的公式：

```text
元素个数  = (rear - front + MAXQSIZE) % MAXQSIZE
判满      = (rear + 1) % MAXQSIZE == front
对称矩阵  = i(i+1)/2 + j        （下三角，i >= j）
```
