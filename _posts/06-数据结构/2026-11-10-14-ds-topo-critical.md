> **读这篇之前，你只需要知道**：有向图就是边带箭头的图，箭头表示"从谁指向谁"；一个顶点的入度，是箭头指向它的边的条数；有向无环图（DAG）就是没有任何一条路径能绕回自己的有向图。
> **这篇讲什么**：当图里的边表示"谁必须先做"时，怎么排出一个合法的先后顺序，排不出来时怎么判断是哪里打了结；再给每个任务加上工期，算出整个工程最早几天完工、哪些任务一天都拖不起。
> **一个类比**：装修房子，水电没做完不能贴砖，贴砖没做完不能刷墙；把这些"不能"画成箭头，就得到一张有向图，排工期就是在这张图上算日子。

```text

```

现在辅导员问你：这七门课，给一个能从头读到尾的顺序。

要求只有一条：每门课开课时，它的先修课都已经读完。

随手排一个：

```text
C1 → C3 → C2 → C4 → C5 → C6 → C7
```

检查一下：C4 要 C2 和 C3，两者都在它前面；C6 要 C2 和 C4，都在前面。

合法。

再排一个：

```text
C3 → C1 → C5 → C2 → C4 → C6 → C7
```

也合法。

所以答案不止一个。

这就带出第一个问题：**合法的顺序有多少个，怎么系统地找一个？**

第二个问题更麻烦：

假设教务处在两张表里写了两条互相冲突的先修要求。

```text
C4 要求先修 C6，C6 又要求先修 C4
```

那就一门都开不了。

这时候不是"顺序排得不好"，是**根本排不出来**。

能不能在排之前就发现这一点？

这一篇就回答这两个问题，再往前推一步：

```text
如果每门课有学时，整个培养方案最短要几个学期？
哪些课一旦延期，整个方案就延期？
```

前两个问题叫**拓扑排序（topological sort）**。

后两个问题叫**关键路径（critical path）**。

它们共用同一张图，只是后者多了一个"权"。

## 1. 五个词先解释清楚

**1. 有向无环图（DAG，directed acyclic graph）**

边有方向，且不存在"顺着箭头走回自己"的环。

先修关系图必须是 DAG。

一旦有环，就没人能先修——这是死锁。

**2. AOV 网（activity on vertex）**

顶点表示活动，边表示活动之间的先后约束。

上面的选课表就是一张 AOV 网：顶点是课，边是"先修"。

AOV 网只关心**顺序**，不关心每门课要上多久。

**3. 拓扑序列（topological order）**

把 AOV 网的所有顶点排成一个线性序列，使得每条边 (u, v) 里的 u 都排在 v 前面。

一个 DAG 至少有一个拓扑序列。

有环的图一个都没有。

同一个 DAG 的拓扑序列通常不止一个——这是 408 的高频考点。

**4. AOE 网（activity on edge）**

边表示活动，顶点表示"事件"（一个活动集合的完成时刻），边上的权表示活动持续时间。

AOE 网里有两个特殊顶点：

```text
源点：入度为 0，表示工程开始
汇点：出度为 0，表示工程结束
```

一张规范的 AOE 网只有一个源点、一个汇点。

AOV 关心"谁先谁后"，AOE 关心"要花多少天"。

**5. 关键路径与最早/最迟时间**

**关键路径**：从源点到汇点的**最长**路径。

注意是"最长"，不是最短——因为工程要等最慢的那条线走完。

这条路径的长度就是整个工程的**最短工期**。

这句话听起来矛盾，其实是同一件事的两面：

```text
工程的最短完成时间 = 最长的那条路径的长度
```

因为所有并行的工作都得等，最慢的那条决定下限。

配套四个时间：

```text
ve(j)  事件 j 的最早发生时间   从源点往后正推
vl(j)  事件 j 的最迟发生时间   从汇点往前逆推
e(i)   活动 i 的最早开始时间   = 它的起点事件的 ve
l(i)   活动 i 的最迟开始时间   = 它的终点事件的 vl − 它的持续时间
```

以及一个差值：

```text
l(i) − e(i) = 这个活动的时间余量（松弛时间）
```

余量为 0 的活动，叫**关键活动**。

关键活动连起来的那条路径，就是关键路径。

一句话记：

```text
余量为 0 的，一天都拖不起；
余量大于 0 的，可以拖，但只能拖那么多。
```

## 2. 没有拓扑排序会怎样

如果没有拓扑排序，你手上只有"一堆先后约束"，没有"执行顺序"。

现实里这意味着：

```text
编译一个大项目，几万个文件互相依赖，make 不知道先编哪个。
装软件，A 依赖 B，B 依赖 C，装到一半发现 C 还没装。
课程表排不出来，学生选课系统天天报"先修冲突"。
```

人工排的麻烦在于，约束一多就看不出来。

七门课的约束，人脑还能凑。

七百个模块的约束，人脑会崩。

而且人工排有一个致命缺陷：**排不出来的时候，你不知道是自己笨，还是真的无解。**

拓扑排序顺手解决了这个：

```text
如果算法跑完，输出的顶点数少于总顶点数，
剩下的那些点就在环里，问题真的无解。
```

这一点比"排出一个顺序"更有价值。

因为它把"排不出来"从"感觉"变成了"结论"。

顺便纠正一个名字上的误会：拓扑排序并不是"排序"。

它不比较大小，也不产生递增序列，"排序"两个字在这里只是借用。

它做的是"给出一致的线性顺序"，和把 3、1、2 排成 1、2、3 是两码事。

## 3. 入度表法：逐轮表格

Kahn 在 1962 年给的办法，朴素到不需要证明：

```text
1. 找出所有入度为 0 的点，它们没有前置，可以先做。
2. 随便挑一个输出，把它删掉（连同它的出边）。
3. 被删掉的边指向的点，入度减 1；减到 0 的，进入待做队列。
4. 回到第 2 步，直到没有入度为 0 的点。
5. 如果输出的点数 < 总点数，说明有环。
```

为什么对？

因为入度为 0 意味着"没有任何前置"，此刻做它一定不违反任何约束。

做完把它删掉，约束就少了一批，剩下的图继续找入度 0 的点。

用开头那张选课表当例子，画成 AOV 网：

```text
              v1（C1）
             ╱        ╲
       v2（C2）        v3（C3）
        ╱    ╲           │
  v5（C5）    ╲           │
      │        ╲          ▼
      │         ────► v4（C4）
      │                  │
      └──────────────► v6（C6）
                         │
                        v7（C7）
```

（v2 有两条出边，分别指向 v4 和 v5；v3 指向 v4；v4 和 v5 都指向 v6。）

这张图里，v4 有两条入边（来自 v2 和 v3），v6 也有两条（来自 v4 和 v5）。

把它写成边表，方便后面逐条核对：

```text
编号   边            含义
e1    v1 → v2      C1 是 C2 的先修
e2    v1 → v3      C1 是 C3 的先修
e3    v2 → v4      C2 是 C4 的先修
e4    v3 → v4      C3 是 C4 的先修
e5    v2 → v5      C2 是 C5 的先修
e6    v4 → v6      C4 是 C6 的先修
e7    v5 → v6      C5 是 C6 的先修
e8    v6 → v7      C6 是 C7 的先修
```

八条边。

按边表数入度：

```text
顶点   入边        入度
v1     无           0
v2     e1           1
v3     e2           1
v4     e3、e4       2
v5     e5           1
v6     e6、e7       2
v7     e8           1
```

入度之和 = 0+1+1+2+1+2+1 = 8，等于边数。

这个等式永远成立：**每条边给终点贡献一个入度**。

手算时先验一次这个等式，能挡住大半的抄错。

现在开始跑。

**第 1 轮**：入度为 0 的只有 v1。

```text
输出 v1
删 v1→v2：v2 的入度 1 → 0，入队
删 v1→v3：v3 的入度 1 → 0，入队
待做：{v2, v3}
```

**第 2 轮**：从待做里取 v2。

```text
输出 v2
删 v2→v4：v4 的入度 2 → 1
删 v2→v5：v5 的入度 1 → 0，入队
待做：{v3, v5}
```

**第 3 轮**：取 v3。

```text
输出 v3
删 v3→v4：v4 的入度 1 → 0，入队
待做：{v5, v4}
```

**第 4 轮**：取 v5。

```text
输出 v5
删 v5→v6：v6 的入度 2 → 1
待做：{v4}
```

**第 5 轮**：取 v4。

```text
输出 v4
删 v4→v6：v6 的入度 1 → 0，入队
待做：{v6}
```

**第 6 轮**：取 v6。

```text
输出 v6
删 v6→v7：v7 的入度 1 → 0，入队
待做：{v7}
```

**第 7 轮**：取 v7，出度为 0，没有边可删。

待做空，输出 7 个点，等于总点数，无环。

得到的拓扑序列：

```text
v1, v2, v3, v5, v4, v6, v7
```

装成表：

| 轮次 | 输出 | 出队时的入度变化 | 待做集合 |
|---|---|---|---|
| 1 | v1 | v2: 1→0，v3: 1→0 | v2, v3 |
| 2 | v2 | v4: 2→1，v5: 1→0 | v3, v5 |
| 3 | v3 | v4: 1→0 | v5, v4 |
| 4 | v5 | v6: 2→1 | v4 |
| 5 | v4 | v6: 1→0 | v6 |
| 6 | v6 | v7: 1→0 | v7 |
| 7 | v7 | 无出边 | 空 |

注意第 3 轮和第 4 轮：待做集合里同时有 v5 和 v4，先取谁都行。

如果先取 v4，序列就变成：

```text
v1, v2, v3, v4, v5, v6, v7
```

两个都合法。

**待做集合用队列还是栈，会影响结果，但不影响合法性。**

用队列（先进先出）得到的是"按入队顺序"的序列。

用栈（后进先出）得到的是另一种。

这就是"拓扑序列不唯一"的机制来源。

**但有一种情况，序列是唯一的。**

如果整个过程中，待做集合的大小始终不超过 1，那么拓扑序列唯一。

换句话说：图里存在一条"贯穿所有顶点"的链，每个点都紧跟着前一个。

408 有一类题就是问"下列哪个图的拓扑序列唯一"。

判据可以用一句糙话：

```text
只要某一刻同时有两个点可以选，就不唯一。
```

## 4. DFS 法：退出次序倒过来

拓扑排序还有第二种做法，用深度优先搜索。

它只需要一行结论：

```text
对图做 DFS，记录每个顶点"搜索结束"的次序，
把这个次序倒过来，就是一个拓扑序列。
```

为什么？

DFS 结束一个顶点时，它的所有后继都已经结束。

所以"结束次序"里，后继一定排在前驱前面。

倒过来，前驱就在后继前面——正好是拓扑序列。

拿同一张图试，从 v1 出发，按编号小的先访问：

```text
DFS(v1)
  → DFS(v2)
      → DFS(v4)
          → DFS(v6)
              → DFS(v7)：无后继，结束。记 v7
              结束。记 v6
          结束。记 v4
      → DFS(v5)：v5 的后继 v6 已访问，结束。记 v5
      结束。记 v2
  → DFS(v3)：v3 的后继 v4 已访问，结束。记 v3
  结束。记 v1
```

结束次序：

```text
v7, v6, v4, v5, v2, v3, v1
```

倒过来：

```text
v1, v3, v2, v5, v4, v6, v7
```

这就成了一个拓扑序列（验一下：v3 在 v4 前 ✓，v2 在 v5 前 ✓，v4、v5 都在 v6 前 ✓）。

和 Kahn 得到的不一样，但都合法。

**这个方法的额外好处：判环。**

DFS 判环靠"三色标记"：

```text
白色：还没访问
灰色：正在访问（在当前的递归栈上）
黑色：访问完了
```

如果搜索时碰到一个**灰色**的邻居，说明从它出发又绕回了它自己，有环。

比 Kahn 的"数输出个数"更直接，而且能指出环在哪里。

**代价是递归。**

大图会爆栈，工程上要做成显式栈的迭代版本。

408 只需知道两种方法都能做，且 DFS 法得到的是"逆后序"。

还有一点要说明：DFS 法得到的序列，和"从哪个点开始"有关。

如果图里有多个入度为 0 的点（不连通），要对外层每个未访问的点都调一次 DFS：

```c
for (int i = 1; i <= n; i++)
    if (color[i] == 0) dfs(i);
```

所有 DFS 都结束后，`order` 数组才是完整的拓扑序列。

顺序不能反：要等所有 DFS 都跑完，再整体看逆后序，而不是每跑完一棵树就输出一段。

这也是"森林的逆后序"这个说法里"森林"两个字的来历。

## 5. C 代码：Kahn 与判环

```c
#include <stdio.h>
#include <string.h>

#define MAXV 100

int adj[MAXV][MAXV];   /* 邻接矩阵，1 表示有边 */
int indeg[MAXV];       /* 入度 */
int n;

/* 返回 1 表示无环并打印序列，返回 0 表示有环 */
int topo_kahn(void)
{
    int q[MAXV], head = 0, tail = 0;
    int order[MAXV], cnt = 0;

    for (int i = 1; i <= n; i++)
        if (indeg[i] == 0)
            q[tail++] = i;          /* 入度为 0 的先入队 */

    while (head < tail) {
        int u = q[head++];
        order[cnt++] = u;

        for (int v = 1; v <= n; v++) {
            if (adj[u][v]) {
                if (--indeg[v] == 0)
                    q[tail++] = v;  /* 减到 0 才入队 */
            }
        }
    }

    if (cnt < n) return 0;          /* 有点没输出，剩下的在环里 */

    for (int i = 0; i < cnt; i++)
        printf("%d%c", order[i], i + 1 == cnt ? '\n' : ' ');
    return 1;
}
```

三个细节。

**一是 `--indeg[v] == 0` 这个写法。**

先减再判，减到 0 才入队。

不能写成 `if (indeg[v] - 1 == 0)`——那样入度永远不真的减，会死循环。

**二是 `cnt < n` 判环。**

跑完之后还有顶点没输出，说明它们的入度永远降不到 0。

降不到 0 的唯一原因，是它们互相指着，形成一个环。

这个判据的漂亮之处在于：**它不需要额外空间，也不需要提前知道环长什么样。**

**三是队列还是栈。**

把 `q[tail++]` 换成栈（`q[--top]`），输出的序列会变，但合法性不变。

考试时按题干要求选；没要求就说明"答案不唯一"。

再看 DFS 法的判环版：

```c
int color[MAXV];        /* 0 白，1 灰，2 黑 */
int has_cycle = 0;
int order[MAXV], pos;

void dfs(int u)
{
    color[u] = 1;                    /* 进栈，染灰 */

    for (int v = 1; v <= n; v++) {
        if (!adj[u][v]) continue;
        if (color[v] == 1) {         /* 碰到灰色：有环 */
            has_cycle = 1;
        } else if (color[v] == 0) {
            dfs(v);
        }
    }

    color[u] = 2;                    /* 出栈，染黑 */
    order[--pos] = u;                /* 逆后序：从数组尾部往前放 */
}
```

`pos` 初值设为 `n`。

`order[--pos] = u` 的意思是"结束得越晚，放得越靠前"，一趟下来正好是逆后序。

不用再手动反转数组。

这两份代码，一份管"排队"，一份管"判环"。

考场上写哪个都行，但 Kahn 更容易在纸上手算，所以例题基本都用它。

## 6. 从 AOV 到 AOE：多出来的那个权

拓扑排序只回答"顺序"。

工程管理还要回答"要几天"。

于是给边加上权：顶点变成"事件"，边变成"活动"，权是工期。

这就是 AOE 网。

AOV 和 AOE 的对应关系，一张表说清：

```text
              AOV                     AOE
顶点的含义     活动本身                 事件（某个时刻）
边的含义       先后约束                 活动本身
权            没有                     活动的持续时间
关心的答案     执行顺序                 最短工期、关键活动
```

**从 AOV 转 AOE 时，最容易错的一步是"要不要加虚边"。**

规则是：一张规范的 AOE 网，必须满足

```text
1. 只有一个入度为 0 的顶点（源点）
2. 只有一个出度为 0 的顶点（汇点）
3. 任意两个活动之间，不能有"部分先后"的含糊关系
```

如果两条边从同一个事件出发、到同一个事件结束，它们会被误认为"完全并行"，这时要插一个**虚活动**（权为 0）来区分。

举一个具体的例子。

```text
活动 B 和 C 都要求 A 先完成。
活动 D 要求 B 完成（不要求 C）。
活动 E 要求 B 和 C 都完成。
```

"D 的前置集合是 {B}""E 的前置集合是 {B, C}"，这两句话是不同的状态。

如果直接从 B 和 C 各引一条边到 D，画出来的意思就变成"D 也要求 C"，错了。

这时插一个虚活动，把"B、C 都完成"单独变成一个事件，两种需求就分开了。

虚活动的工期是 0，所以它不影响任何 ve、vl 的计算——这是它唯一的好处，也是最容易忽略的地方。

408 的题一般给的图已经规范，不太考虚边，但概念要清楚。

下面用一个 7 事件、9 活动的 AOE 网，把最后四节算完。

```text
活动   起点   终点   工期
a1     v1     v2      3
a2     v1     v3      2
a3     v2     v4      3
a4     v2     v5      2
```

## 7. ve 正推：最早发生时间

ve(j) 的定义：事件 j 最早能在什么时候发生。

只有一条规则：

```text
ve(源点) = 0
ve(j) = max{ ve(i) + w(i, j) }   对所有指向 j 的边取最大
```

为什么取 **max**？

因为事件 j 要等**所有**前置活动都做完。

前置里最慢的那个决定它的最早时刻。

```text
取 max = 等最慢的那个
```

按拓扑序正推，一遍就够。

**ve(v1) = 0**

源点，没有前置。

**ve(v2) = ve(v1) + a1 = 0 + 3 = 3**

v2 只有一条入边。

**ve(v3) = ve(v1) + a2 = 0 + 2 = 2**

v3 也只有一条入边。

**ve(v4) = max( ve(v2) + a3 , ve(v3) + a5 )**

```text
= max( 3 + 3, 2 + 4 )
= max( 6, 6 )
= 6
```

两条路都是 6，撞在一起了。

这个"正好相等"是巧合，但很关键——它意味着两条路都是紧的。

**ve(v5) = ve(v2) + a4 = 3 + 2 = 5**

**ve(v6) = max( ve(v4) + a6 , ve(v5) + a7 )**

```text
= max( 6 + 3, 5 + 1 )
= max( 9, 6 )
= 9
```

走 v4 这一路更慢，等它。

**ve(v7) = max( ve(v5) + a8 , ve(v6) + a9 )**

```text
= max( 5 + 3, 9 + 2 )
= max( 8, 11 )
= 11
```

整个工程最短 11 天完工。

装成表：

| 事件 | ve | 是怎么算出来的 |
|---|---|---|
| v1 | 0 | 源点 |
| v2 | 3 | 0 + 3（经 a1） |
| v3 | 2 | 0 + 2（经 a2） |
| v4 | 6 | max(3+3, 2+4) = 6 |
| v5 | 5 | 3 + 2（经 a4） |
| v6 | 9 | max(6+3, 5+1) = 9 |
| v7 | 11 | max(5+3, 9+2) = 11 |

**正推的关键：必须按拓扑序算。**

算 ve(v4) 时要用到 v2 和 v3 的 ve。

如果先算 v4，两个前置都还是空的，结果必错。

所以 AOE 的题，第一步永远是"先把拓扑序排出来"。

这也解释了为什么这一篇要把拓扑排序放在前面——它不是独立的知识点，是 AOE 的前置工具。

再补一个直觉，帮你记住为什么一个取 max、一个取 min。

`ve` 是往前看：一个事件要发生，得等所有前置做完，所以取最慢的那个。

`vl` 是往后看：一个事件能推迟多久，取决于它后面有没有更紧的，所以取最紧的那个。

两个递推的方向和取值刚好相反，这不是巧合，是由"约束从哪边来"决定的。

## 8. vl 逆推：最迟发生时间与时间余量

vl(j) 的定义：在不推迟整个工程的前提下，事件 j 最迟能在什么时候发生。

规则也只有一条：

```text
vl(汇点) = ve(汇点)
vl(i) = min{ vl(j) − w(i, j) }   对所有从 i 出发的边取最小
```

为什么取 **min**？

因为事件 i 推迟，会同时推迟它后面**所有**的活动。

后面最紧的那条会先撑不住，所以要按最紧的算。

```text
取 min = 迁就最紧的那个
```

按**逆拓扑序**推，从汇点往回走。

**vl(v7) = ve(v7) = 11**

汇点不能推迟，一推迟整个工程就延期。

**vl(v6) = vl(v7) − a9 = 11 − 2 = 9**

**vl(v5) = min( vl(v7) − a8 , vl(v6) − a7 )**

```text
= min( 11 − 3, 9 − 1 )
= min( 8, 8 )
= 8
```

两条出边都给出 8。

**vl(v4) = vl(v6) − a6 = 9 − 3 = 6**

**vl(v3) = vl(v4) − a5 = 6 − 4 = 2**

**vl(v2) = min( vl(v4) − a3 , vl(v5) − a4 )**

```text
= min( 6 − 3, 8 − 2 )
= min( 3, 6 )
= 3
```

走 v4 那条更紧（3 天），所以 v2 最迟也是 3。

**vl(v1) = min( vl(v2) − a1 , vl(v3) − a2 )**

```text
= min( 3 − 3, 2 − 2 )
= min( 0, 0 )
= 0
```

源点的 vl 必须等于 0，这是验算点。

如果不等于 0，说明前面某一步算错了。

把 ve 和 vl 并排：

| 事件 | ve | vl | vl − ve |
|---|---|---|---|
| v1 | 0 | 0 | 0 |
| v2 | 3 | 3 | 0 |
| v3 | 2 | 2 | 0 |
| v4 | 6 | 6 | 0 |
| v5 | 5 | 8 | **3** |
| v6 | 9 | 9 | 0 |
| v7 | 11 | 11 | 0 |

只有 v5 有两个时间，差 3 天。

意思是：v5 这个事件，最早第 5 天到，最迟第 8 天到，中间有 3 天缓冲。

手算时最容易错的三处，先记下来：

```text
第一，正推时用了还没算出来的 ve（没按拓扑序）。
第二，逆推时把 min 写成了 max（出边多于一条时）。
第三，把"事件的时间"当成"活动的时间"，
     忘了 l(活动) 还要再减去工期。
```

第三处最隐蔽，因为减不减工期只差一个数，顺手就抄错了。

**注意：ve = vl 的事件，都在关键路径上。**

这张表里除了 v5，其余全是 ve = vl。

所以关键路径一定经过 v1、v2、v3、v4、v6、v7——但"经过"不等于"连成一条"，还要看活动。

这就到了下一步。

## 9. 活动的最早最迟时间

事件有了时间，活动的时间就好算了。

两条公式：

```text
e(i) = ve(活动的起点事件)
l(i) = vl(活动的终点事件) − 活动的工期
```

为什么这样？

活动的**最早**开始时间，取决于它的起点事件最早什么时候发生——起点到了，它就能开工。

活动的**最迟**开始时间，等于终点事件的最迟时间减去工期——再晚就拖累终点了。

逐个算：

**a1（v1→v2，3 天）**

```text
e = ve(v1) = 0
l = vl(v2) − 3 = 3 − 3 = 0
余量 = 0
```

**a2（v1→v3，2 天）**

```text
e = 0
l = vl(v3) − 2 = 2 − 2 = 0
余量 = 0
```

**a3（v2→v4，3 天）**

```text
e = ve(v2) = 3
l = vl(v4) − 3 = 6 − 3 = 3
余量 = 0
```

**a4（v2→v5，2 天）**

```text
e = 3
l = vl(v5) − 2 = 8 − 2 = 6
余量 = 3
```

**a5（v3→v4，4 天）**

```text
e = ve(v3) = 2
l = vl(v4) − 4 = 6 − 4 = 2
余量 = 0
```

**a6（v4→v6，3 天）**

```text
e = 6
l = vl(v6) − 3 = 9 − 3 = 6
余量 = 0
```

**a7（v5→v6，1 天）**

```text
e = ve(v5) = 5
l = vl(v6) − 1 = 9 − 1 = 8
余量 = 3
```

**a8（v5→v7，3 天）**

```text
e = 5
l = vl(v7) − 3 = 11 − 3 = 8
余量 = 3
```

**a9（v6→v7，2 天）**

```text
e = 9
l = vl(v7) − 2 = 11 − 2 = 9
余量 = 0
```

汇总：

| 活动 | 边 | 工期 | e | l | l − e | 是否关键 |
|---|---|---|---|---|---|---|
| a1 | v1→v2 | 3 | 0 | 0 | 0 | 是 |
| a2 | v1→v3 | 2 | 0 | 0 | 0 | 是 |
| a3 | v2→v4 | 3 | 3 | 3 | 0 | 是 |
| a4 | v2→v5 | 2 | 3 | 6 | **3** | 否 |
| a5 | v3→v4 | 4 | 2 | 2 | 0 | 是 |
| a6 | v4→v6 | 3 | 6 | 6 | 0 | 是 |
| a7 | v5→v6 | 1 | 5 | 8 | **3** | 否 |
| a8 | v5→v7 | 3 | 5 | 8 | **3** | 否 |
| a9 | v6→v7 | 2 | 9 | 9 | 0 | 是 |

关键活动：**a1、a2、a3、a5、a6、a9**。

非关键：**a4、a7、a8**，余量都是 3。

把关键活动连起来，得到两条路径：

```text
路径一：v1 ──a1(3)──► v2 ──a3(3)──► v4 ──a6(3)──► v6 ──a9(2)──► v7
        0          3          6          9          11

路径二：v1 ──a2(2)──► v3 ──a5(4)──► v4 ──a6(3)──► v6 ──a9(2)──► v7
        0          2            6          9          11
```

两条都是 11 天。

**这就是关键路径不唯一的样子。**

也解释了为什么 v4 的 ve 是 max(6, 6)——两条路同时到，谁也不等谁。

## 10. 两条关键路径：为什么只缩一天没用

这一节是 408 综合题最爱设的坑。

题目会问：

```text
"把 a1 缩短 1 天，工期能缩短几天？"
```

直觉答案：缩短 1 天，工期少 1 天。

正确答案：**0 天**。

为什么？

因为工期是**所有路径**里最长的那条。

a1 在路径一上，缩短它，路径一变成 10 天。

可路径二没变，还是 11 天。

工程还是得等 11 天。

所以：

```text
要缩短工期，必须同时缩短所有关键路径。
只缩一条，等于白干。
```

继续算：如果把 a1 和 a2 各缩短 1 天呢？

```text
路径一：2 + 3 + 3 + 2 = 10
路径二：1 + 4 + 3 + 2 = 10
```

工期变 10，成了。

**但这里还有一个坑。**

缩短之后，非关键活动的余量变了。

原本 a4 的余量是 3，现在 v5 的 ve 还是 5，vl 可能变成 7，余量 2。

如果继续缩短关键活动，某一天非关键活动会被"逼成"关键活动。

```text
缩短工期的过程，就是不断有新路径变成关键路径的过程。
```

所以这种题的标准解法是：

```text
1. 先把当前的关键路径全找出来。
2. 缩短之后，重新算 ve、vl。
3. 看新的关键路径是哪几条，再决定下一步缩哪里。
```

不能一步算到底。

另外还有两条规律，选择题常考：

```text
规律一：关键活动的持续时间缩短，工期不一定缩短（多条关键路径时）。
规律二：关键活动的持续时间延长，工期一定延长。
规律三：非关键活动的持续时间延长，只要不超过余量，工期不变。
规律四：非关键活动延长超过余量，它自己就变成关键活动，工期开始变长。
```

规律二特别好记：关键活动在最长路径上，它一变长，最长路径就更长。

**第五个反直觉的点：**

```text
关键路径是"最长"的路径，
但它决定的却是工程的"最短"完工时间。
最长与最短，在同一个句子里成立。
```

因为"最短完工"这个最优值，受制于"最长的一条链"。

这就是瓶颈的含义。

## 11. 真实系统里长什么样

这一篇的两个算法，在工程里出现得比想象中频繁。

**make 与编译顺序。**

一个 C 项目里，`.c` 依赖 `.h`，`.o` 依赖 `.c`，可执行文件依赖所有 `.o`。

这就是一张 AOV 网，make 每次构建都在上面跑一遍拓扑排序。

如果你把两个头文件互相 include，make 会报 "circular dependency dropped"——那就是它的判环输出。

**包管理器。**

apt、pip、npm 装一个包，要先装它的依赖。

依赖表就是 AOV 网，装包顺序就是拓扑序列。

真出环了（A 依赖 B 的 2.x，B 又依赖 A 的 1.x），现代包管理器会直接报"无法满足依赖"，而不是死循环——因为它先做了环检测。

要说明的是，真实的依赖解析比 AOV 复杂：它带版本约束，求的是满足约束的一组版本，本质上是 SAT 问题。

但"先把约束画成图，再看有没有环"这个骨架，就是拓扑排序。

**项目管理里的 PERT 与 CPM。**

这两个缩写指的是同一套东西：PERT 图就是 AOE 网，CPM 就是关键路径法。

工地上说的"关键线路"，就是这一篇算出来的关键路径。

项目经理画甘特图之前，先要算 ve、vl、余量，找出哪些工序一天都不能拖，把人和钱优先堆在那里。

"赶工"（crashing）这个词也来自这里：往关键活动上加人加钱，缩短它的工期，再回头看关键路径有没有换人。

换人了，说明原来那条已经不再是瓶颈，资源该挪走了。

## 12. 408 怎么考

拓扑排序和关键路径，题型很固定，四类。

**第一类：给 AOV 图，问哪个序列不是拓扑序列。**

不用把序列排出来，只需要**逐条检查边**。

```text
对每条边 (u, v)，看 u 在序列里是不是排在 v 前面。
只要有一条不满足，这个序列就不是。
```

比如给序列 `v1, v3, v4, v2, v5, v6, v7`。

检查边 v2→v4：v4 在位置 3，v2 在位置 4，v4 排在 v2 前面。

违反，不是拓扑序列。

这类题最快的做法是"盯住每一条边，找一个反例就停"。

**第二类：给图，问拓扑序列有几个 / 是否唯一。**

判据前面说过：

```text
任何时刻待做集合超过 1 个 → 不唯一
全程待做集合始终恰好 1 个 → 唯一
```

如果是问"一共有多少个"，就得真的去数。

小图可以画树：第一步有几种选法，每种选法之后又有几种。

```text
比如 v1 唯一，先输出 v1。
之后 v2、v3 都能选，分两支。
每支继续分……
叶子数就是序列总数。
```

**第三类：给 AOE 网，求关键路径和工期。**

标准流程四步：

```text
1. 排拓扑序（事件层面）。
2. 按拓扑序正推 ve，注意取 max。
3. 按逆拓扑序逆推 vl，注意取 min。
4. 对每个活动算 e、l，余量为 0 的在关键路径上。
```

验算三个点：

```text
vl(源点) 必须等于 0
ve(汇点) 必须等于 vl(汇点)
关键路径的总长必须等于 ve(汇点)
```

三个都对，基本就没算错。

**第四类：问"缩短某个活动能不能缩短工期"。**

前面第 10 节讲透了：看它是不是在**所有**关键路径上。

```text
在所有关键路径上都出现 → 缩短它，工期缩短
只在其中一条上出现     → 缩短它，工期不变
```

还有一问是"最多能缩短几天"。

答案是"缩短到它变成非关键活动为止"，或者"缩短到另一条路径变成关键路径为止"，取小的那个。

拿本文的图举例：a1 单独缩短，工期不变（因为路径二）。

那 a1 最多能缩几天还不浪费？

路径一变成 `(3−x) + 3 + 3 + 2`，路径二是 11。

要让路径一还等于 11，x 可以取到 0..? 路径一 = 11 − x，只要它 ≤ 11 就不影响工期。

所以缩多少都"不影响工期"——也就是全是白缩。

真正有用的是让**最大**的那条变短。

这类题最好画一张"两条路径并排"的图，一眼看出谁在卡。

再完整走一道自拟题，把四个步骤串一遍。

```text
五个事件，五条活动：
a1  v1→v2   2 天
a2  v1→v3   3 天
a3  v2→v4   4 天
a4  v3→v4   1 天
a5  v4→v5   2 天
```

第一步，拓扑序：v1, v2, v3, v4, v5。

第二步，正推 ve：

```text
ve(v1) = 0
ve(v2) = 0 + 2 = 2
ve(v3) = 0 + 3 = 3
ve(v4) = max(2 + 4, 3 + 1) = 6
ve(v5) = 6 + 2 = 8
```

第三步，逆推 vl：

```text
vl(v5) = 8
vl(v4) = 8 − 2 = 6
vl(v2) = 6 − 4 = 2
vl(v3) = 6 − 1 = 5
vl(v1) = min(2 − 2, 5 − 3) = 0
```

第四步，算每个活动的 e、l：

```text
a1：e=0，l=2−2=0    余量 0   关键
a2：e=0，l=5−3=2    余量 2
a3：e=2，l=6−4=2    余量 0   关键
a4：e=3，l=6−1=5    余量 2
a5：e=6，l=8−2=6    余量 0   关键
```

关键路径：v1 → v2 → v4 → v5，长度 8。

三个验算点：`vl(v1) = 0` ✓，`ve(v5) = vl(v5) = 8` ✓，关键路径长度 8 = ve(v5) ✓。

再看 a2：它走 v3 那条路，余量 2，拖两天没事。

但拖第三天，v4 的 ve 就从 6 变成 7，关键路径就换人了。

这就是余量的实际含义——它不是"随便拖"，是"拖到边界就变关键"。

## 13. 一页速查

```text
Kahn：
  入度为 0 的入队 → 出队输出 → 出边指向的点入度减 1 → 减到 0 入队
  输出个数 < n  →  有环

DFS：
  结束次序倒过来 = 拓扑序列
  碰到灰色邻居 = 有环

AOE：
  ve(源) = 0，ve(j) = max(ve(i) + w)     正推，取 max
  vl(汇) = ve(汇)，vl(i) = min(vl(j) − w) 逆推，取 min
  e(活动) = ve(起点)
  l(活动) = vl(终点) − 工期
  关键活动：l − e = 0

工期 = ve(汇点) = 最长路径长度
```

三句人话：

```text
拓扑排序回答"先做谁"，判环是它的副产品。
ve 取 max 是等最慢的前置，vl 取 min 是迁就最紧的后继。
关键路径是最长的路，决定最短的工期。
```

再记一个对照：

```text
AOV：点在活动上，边只表示先后，无权。
AOE：边在活动上，权是工期，点只是时刻。
```

手算模板，考场上照着填两行表：

```text
事件表： | 事件 | v1 | v2 | v3 | v4 | v5 | v6 | v7 |
         | ve   |    |    |    |    |    |    |    |
         | vl   |    |    |    |    |    |    |    |

活动表： | 活动 | 边 | 工期 | e | l | l−e |
```

先横着填完 ve 一整行（正推），再横着填完 vl 一整行（逆推），最后填活动表。

不要跳着填——跳着填是这类题失分最多的地方。

复杂度一栏，顺手记一下：

```text
Kahn：      O(V + E)，每点入队一次，每条边删一次
DFS 法：    O(V + E)
ve / vl：   O(V + E)，各扫一遍边
```

四个都是 O(V + E)，都不带 log。

因为整个流程里没有任何排序、没有任何查找——只有"减一"和"取最值"。

它们的代价在常数：要额外的入度数组、一个队列、两个时间数组。

### 自检三问

1. 一个 7 个顶点的 DAG，Kahn 跑完只输出了 5 个顶点，剩下 2 个顶点是什么状态？

   答不上来说明把"入度"理解成了静态属性。剩下的顶点入度永远降不到 0，因为它们互相指向，形成一个环；这 2 个顶点就在环里（或环的下游），所以无解。

2. ve 为什么取 max，vl 为什么取 min？能不能反过来？

   答不上来说明没抓住"等"和"迁就"这两个动作。ve 要等所有前置完成，最慢的说了算，所以取 max；vl 要保证所有后继都不被拖累，最紧的说了算，所以取 min。反过来算出来的是另一张图，不是这张。

3. 本文的 AOE 网里，a1 缩短 2 天，工期变成几天？为什么？

   答不上来说明没注意"关键路径有两条"。a1 只在路径一上，缩 2 天后路径一变 9 天，路径二仍是 11 天，工期不变。要缩短工期，必须同时缩 a1 和 a2（或缩两条路径共有的 a6、a9）。

## 14. 小结

回到那张选课表。

它有三个合法顺序，也有一个"如果教务处写错了就一门都开不了"的风险。

拓扑排序把这两件事一起解决了：给出顺序，并且在给不出顺序时告诉你"有环"。

这是它比"人工凑"强的地方。

再往前一步，给每门课加上学时，问题就从"排顺序"变成"排工期"。

答案从"一个序列"变成"一条最长路径"。

这一篇的四句话：

```text
拓扑排序的本质，是不断摘掉"没有前置"的点。
有环的判据，是摘不完。
AOE 的两个递推，一个取 max（等最慢），一个取 min（迁就最紧）。
关键路径是最长的路，所以它决定最短的工期。
```

还有一个容易被忽略的收获：

拓扑排序是"依赖管理"的通用工具。

make 编译、包管理器装依赖、Excel 公式重算、任务调度器排任务，底下都是这一套。
