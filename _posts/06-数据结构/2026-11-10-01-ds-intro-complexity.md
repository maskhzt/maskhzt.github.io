> **读这篇之前，你只需要知道**：变量是内存里一个有名字的格子，用来存一个值；循环是让一段代码重复执行若干次；函数是一段有名字、可以反复调用的代码。
> **这篇讲什么**：先把"数据""结构""操作"这三个词拆清楚，再告诉你怎样不靠秒表、只靠数次数，判断一段代码在数据变多时会慢成什么样。
> **一个类比**：一仓库货，可以按货架编号一排排摆（顺序），也可以每个箱子挂一张"下一个箱子在哪"的纸条（链式）；怎么摆决定了你取货、上货各自要花多少步。

先看一个老故事。

高斯十岁，老师让全班算 1 加到 100。

别的孩子从 1 开始，一个一个加。

高斯把数列首尾配对：

```text
1 + 100 = 101
2 + 99  = 101
...
50 + 51 = 101
```

一共 50 对，每对 101。

答案 5050，他几乎没动笔。

同样的结果，两种算法。

一种做 99 次加法，一种做 1 次乘法。

**这就是这门课真正关心的东西：不是"能不能算出来"，而是"要花多少步才算出来"。**

而"花多少步"，又取决于数据怎么存。

同样 100 万个名字，排成一排按位置取，一步到位；用纸条一个个串起来，得从头走。

存法换了，步数就换了。

这一篇要做的，是把这套朴素直觉，变成几个能写进答题纸的词：

```text
数据结构、逻辑结构、存储结构
抽象数据类型（ADT）
算法、时间复杂度、空间复杂度
```

先给一个总印象，后面逐节展开。

数据结构 = 数据 + 关系 + 操作 + 代价。

抽象数据类型 = 只规定"能做什么"，不规定"怎么做"。

复杂度 = 数据量翻倍时，步数大约翻几倍。

## 1. 没有"数据结构"这个词，会怎样

假设你要写一个通讯录。

一开始只有 100 个人，你用数组存，按编号排。

查人：从头翻，100 次以内。

插入新人：找到位置，把后面的人全部往后挪一格。

100 个人，最多挪 100 次，能忍。

三年后，通讯录有 10 万个人。

插入一个人，平均要挪 5 万次。

用户点一下"保存"，程序卡半秒。

你换了一台快一倍的电脑，卡顿只从半秒变成四分之一秒。

真正的问题不在电脑，在"存法"。

如果改成每个联系人挂一根"下一个是谁"的线，插入时只改两根线，不管通讯录多长，都是固定几步。

但代价来了：想找第 5 万个人，不能再"一步跳到"，得从头顺着线走 5 万步。

**这就是数据结构这门课的全部张力：没有一种存法让所有操作都便宜。**

所以你需要的不是"最好的结构"，而是一套词汇，能说清：

```text
这批数据之间是什么关系？
它被放在内存里的什么位置？
要在它上面做哪些操作？
每个操作要多少步？
```

这四个问题答完，选型就基本定了。

没有这套词汇，你只能凭感觉写，写完也不知道慢在哪。

## 2. 数据、数据元素、数据项：三个必须分清的词

这三个词看着像同义词，其实各指一层。

分不清它们，讨论"存什么"时就会把一条记录和一个字段混成一件事。

先看一个具体的东西：一张学生成绩表。

```text
学号      姓名    班级      总分
2024001   张三    计科 1 班   612
2024002   李四    计科 2 班   598
2024003   王五    计科 1 班   635
```

这张表里，每一行是一个整体。

"一行"就是数据元素。

"学号"这一格，是数据项。

"所有学生的总分"这一列，是另一个数据项。

把这三个词钉死：

**数据（data）**：所有能输入计算机、并被程序处理的符号的集合。

数字、文字、图像、声音都算。

**数据元素（data element）**：数据的基本单位，通常作为一个整体来处理。

上面的一行学生记录就是一个数据元素。

**数据项（data item）**：构成数据元素的、不可再分的最小单位。

学号、姓名、总分都是数据项。

**数据对象（data object）**：性质相同的数据元素的集合。

比如"全体学生"。

一个容易混的点：

数据元素不一定"很大"。

一个整数 5，也可以是一个数据元素。

一个学生记录，也可以是一个数据元素。

区别不在大小，在"你是不是把它当一个整体看"。

另一个容易混的点：

数据项是"不可再分"的，但这是相对于当前问题说的。

学号 2024001 里还能拆出"2024"和"001"，可在这个问题里没人关心，它就到此为止。

**定义"不可再分"的，是问题，不是数据本身。**

再补一个组合关系，408 选择题偶尔会考：

```text
数据项 → 组成 → 数据元素 → 组成 → 数据对象
```

一个学生记录（数据元素）由学号、姓名、总分（数据项）组成。

全体学生记录（数据对象）是若干数据元素的集合。

三者是"部分—整体"的层层包含关系，不是并列关系。

**标准说法只有两句：数据元素是数据的基本单位，数据项是构成数据元素的不可分割的最小单位。**

把"基本单位"和"最小单位"互换，就错了。

## 3. 逻辑结构：数据之间"看起来"的关系

如果不先确定元素之间的关系，你根本不知道该按什么方式组织它们。

现在把"存法"完全忘掉。

只问一件事：这些元素之间，谁挨着谁？

回答只有四种基本形状。

```text
集合：元素之间没有关系，只是"同属一个筐"。
线性：排成一排，每个元素最多一个前驱、一个后继。
树：一对多，一个上级管若干下级。
图：多对多，谁都能连谁。
```

先把"前驱"和"后继"这两个词说清。

前驱（predecessor）：排在你前面的那个元素。

后继（successor）：排在你后面的那个元素。

线性结构里，除了第一个没有前驱、最后一个没有后继，中间每个都恰好一个前驱、一个后继。

画出来：

```text
线性          树              图
a—b—c—d        A              A — B
              / \             | × |
             B   C            C — D
            / \
           D   E
```

**逻辑结构（logical structure）**：数据元素之间的逻辑关系，与它们在内存里怎么放无关。

这句话的重点是"无关"。

同一批学生，按学号排，是线性结构。

按"学院—专业—班级—学生"组织，是树结构。

按"谁和谁同宿舍"组织，是图结构。

数据没变，关系变了，逻辑结构就变了。

没有"逻辑结构"这个概念，会怎样？

你会把"数据"和"数据怎么摆"混成一件事。

比如老师说"用线性表存这些学生"，你立刻想到数组。

可线性表说的是"一对一"这个关系，数组只是它的一种实现。

换链表，它还是线性表。

**先把关系说清，再谈实现，这是本课程的第一条纪律。**

408 里，逻辑结构通常分四类：集合、线性、树、图。

有的教材把"树"和"图"合称"非线性结构"，说法不同，意思一样。

## 4. 存储结构：关系怎么落到内存上

图纸画得再好，不落到具体内存上，也只是一张图。

逻辑结构是图纸，存储结构是施工。

内存长这样：

```text
地址： 1000  1001  1002  1003  1004  1005
内容：  ?     ?     ?     ?     ?     ?
```

每个格子一个字节，格子有门牌号，叫地址（address）。

**存储结构（storage structure）**：逻辑结构在计算机里的表示，也叫物理结构。

四种基本做法。

**顺序存储**：把元素放在一段连续格子里，靠"算"找位置。

```text
┌────┬────┬────┬────┐
│ 10 │ 20 │ 30 │ 40 │
└────┴────┴────┴────┘
 1000 1004 1008 1012
```

找第 i 个：地址 = 起始地址 + (i−1) × 每个元素占的字节数。

一步除法加乘法，和 i 多大无关。

**链式存储**：元素分散放，每个元素额外存一个"下一个在哪"的地址。

```text
┌────┬──┐   ┌────┬──┐   ┌────┬──┐
│ 10 │──┼──►│ 20 │──┼──►│ 30 │╳ │
└────┴──┘   └────┴──┘   └────┴──┘
 1000        3000        2010
```

找第 i 个：从第一个开始，顺着地址走 i−1 步。

i 越大，走得越久。

**索引存储**：额外建一张目录表，先查目录再取货。

比如一本 1000 页的字典，每 10 页在书口贴一个字母标签。

找"W"开头的字，先看标签跳到 W 段，再在段内翻，不用从第 1 页翻起。

目录表本身也占空间，这是索引的代价。

**散列存储**：用一个函数把关键字直接算成地址。

这个函数叫哈希函数（hash function），也叫散列函数，"哈希"就是散列的音译。

比如学号 2024001，对 1000 取余得 1，就放在 1 号桶。

这里的"桶"，就是数组里存同一类元素的那个位置。

算一次就到位，不用比大小。

代价是不同关键字可能算出同一个地址，这叫冲突，后面的散列一篇专门讲。

后两种后面各有专篇，这里只要记住一句话：

```text
顺序靠"算"，链式靠"找"，索引靠"查表"，散列靠"算哈希"。
```

为什么同一个逻辑结构能有多种存储？

因为逻辑结构只规定"谁挨着谁"，没规定"挨着"必须体现在地址上。

数组用地址相邻表示"挨着"。

链表用指针指向表示"挨着"。

这就是"数组查询快、链表插入快"的根源，[02 篇](/posts/ds-sequential-list/)和[03 篇](/posts/ds-linked-list/)会各算一遍。

现在可以把"数据结构"正式定义一次。

**数据结构：相互之间存在一种或多种特定关系的数据元素的集合，包括逻辑结构、存储结构和数据的运算三部分。**

三者缺一不可。

只画关系图，不落到内存，代码写不出来。

只堆内存布局，不说关系，没法判断该用哪种查找。

定义了结构却不说能做什么运算，这个结构就没有用途。

所以后面每讲一个结构，都按同一个顺序：

```text
它表示什么关系（逻辑）
它在内存里怎么放（存储）
它支持哪些操作，每个操作多少步（运算与代价）
```

## 5. 抽象数据类型：只说能做什么

先设想一个糟糕的库。

你调用它的"入栈"函数，得先自己判断数组满没满，还得知道它内部数组多大、栈顶指针叫 `top` 还是 `t`。

某天作者把内部实现从数组换成链表，你的代码全编译不过。

问题出在：**实现细节漏到了使用者手里。**

抽象数据类型（abstract data type，ADT）就是来堵这个漏的。

**ADT：一个数学模型以及定义在该模型上的一组操作，只描述"能做什么"，不描述"怎么实现"。**

它由三部分组成：

```text
数据对象 D：这个类型里装的是什么东西。
数据关系 S：这些元素之间是什么关系。
基本操作 P：允许对它做哪些动作。
```

以线性表为例，写成 ADT 大概是这样：

```text
ADT List {
    数据对象：D = { a_i | a_i ∈ ElemSet, i = 1, 2, ..., n, n ≥ 0 }
    数据关系：R = { <a_{i-1}, a_i> | a_{i-1}, a_i ∈ D, i = 2, ..., n }
    基本操作：
        InitList(&L)            构造一个空表
        DestroyList(&L)         销毁表
        ListEmpty(L)            判空
        ListLength(L)           求长度
        GetElem(L, i, &e)       取第 i 个元素
        LocateElem(L, e)        找 e 的位置
        ListInsert(&L, i, e)    在第 i 个位置插入 e
        ListDelete(&L, i, &e)   删除第 i 个元素并用 e 带回
}
```

注意这里一个 `struct` 都没出现。

也没说第 i 个元素怎么找、插入要不要搬家。

**ADT 只签合同，不管施工。**

这和 C 语言里的"数据类型"是什么关系？

数据类型（data type）是"一组值的集合 + 定义在这组值上的一组操作"，比如 `int` 就是"整数 + 加减乘除"。

ADT 是用户自己定义的、更复杂的数据类型，强调"抽象"这一层。

所以你可以说：ADT 是一种数据类型，但它的定义里刻意抹掉了实现。

没有 ADT 会怎样？

每个用栈的人都要读一遍栈的源码，才能确认自己会不会踩到内部细节。

换一种实现，所有调用方跟着改。

**ADT 的价值不在代码里，在"换实现时调用方不用改"这句话里。**

C 语言没有 `class`，怎么表达 ADT？

用 `typedef struct` 藏住结构体，再提供一组函数当接口。

[02 篇](/posts/ds-sequential-list/)会给出完整写法，这里先看个骨架：

```c
/* 头文件里只暴露类型名和函数声明，不暴露结构体成员 */
typedef struct SeqList SeqList;   /* 不完整类型：使用者看不见内部 */

SeqList *ListCreate(int capacity);
int      ListInsert(SeqList *L, int i, int e);
int      ListDelete(SeqList *L, int i, int *e);
void     ListDestroy(SeqList *L);
```

结构体的真实定义只放在实现文件里：

```c
/* seqlist.c：只有这个文件知道内部长什么样 */
typedef int ElemType;    /* 元素类型，先当成 int */

struct SeqList {
    ElemType *data;      /* 连续存储区 */
    int       length;    /* 当前元素个数 */
    int       capacity;  /* 容量 */
};

/* 取第 i 个元素：ADT 里规定过，这里给出实现 */
int ListGet(SeqList *L, int i, int *e) {
    if (i < 1 || i > L->length)
        return 0;
    *e = L->data[i - 1];
    return 1;
}
```

使用者只能通过这四个函数操作表，内部是数组还是链表，他看不见。

这就是 C 语言版的 ADT。

抽象其实分两层。

第一层叫"数据抽象"：使用者不用知道数据在内存里怎么排。

第二层叫"过程抽象"：使用者不用知道函数内部怎么算。

两层合起来，才是"换实现不改调用方"。

反过来，如果头文件里直接写了 `struct { int data[100]; int length; }`，成员全暴露，那它就只是个结构体，不是 ADT。

**能改内部而不影响外部，是判断"抽象做没做到"的唯一标准。**

## 6. 算法：五个特性与四条标准

没有算法，数据结构只是一堆不会动的格子。

有了数据，有了存法，接下来是"怎么算"。

**算法（algorithm）**：对特定问题求解步骤的描述，是若干条指令的有限序列。

注意"有限"两个字，它是算法和程序的分界线。

算法有五个特性。

```text
有穷性：执行有限步之后结束，且每一步都在有限时间内完成。
确定性：每条指令含义明确，同样输入必得同样输出。
可行性：每一步都能用基本运算执行有限次实现。
输入：有零个或多个输入。
输出：有一个或多个输出。
```

最容易考的是"有穷性"。

一个操作系统的主循环 `while (1)`，是程序，不是算法。

因为它不满足有穷性。

但"程序 = 算法 + 数据结构"这个说法里的程序，指的是"解决某个具体问题的程序"，不是操作系统。

确定性也不好糊弄。

"取一个随机的数，如果它大于 0.5 就走左边"——这句话不是确定性的，因为没有规定随机数怎么来。

改成"取当前时间的毫秒数对 2 取余"，输入确定，结果就确定，这才算算法。

可行性说的是"每一步都能真正做到"。

"求出所有实数的和"听着像一句话，实际做不到，因为实数是无限的，没法在有限步内加完。

三个特性一起看，其实都在保证一件事：

```text
这个描述能在有限时间内，被一台机器无条件地执行完。
```

一个算法好不好，还有四条标准。

```text
正确性：对合法输入给出正确结果，对非法输入给出说明。
可读性：人看得懂，别为了省两行写成天书。
健壮性：输入不合法时，别崩，别输出垃圾。
效率与低存储：时间复杂度和空间复杂度都要低。
```

前三条是底线，第四条是这门课的主线。

408 选择题喜欢问："下面哪个不属于算法的特性？"

常见干扰项是"可读性""健壮性""高效性"——它们是好算法的标准，不是算法的必要条件。

**特性是"必须有"，标准是"最好有"，这两组词别混。**

## 7. 复杂度：为什么不用"秒"来衡量

现在到最关键的一步。

你说"这段代码跑 0.3 秒"，这句话信息量很小。

换台电脑，可能 0.05 秒。

数据从 1000 条变成 100 万条，可能 300 秒。

**用秒衡量，量出来的是"这台机器 + 这份数据 + 这个编译器"的混合结果，不是算法本身的性质。**

所以换个问法：

```text
当输入规模 n 变大时，基本操作的执行次数怎么涨？
```

这个"次数"，记作 T(n)。

时间复杂度（time complexity）就是 T(n) 的数量级。

大 O 记号的定义，用一句话说：

**存在正常数 C 和 n₀，使得当 n ≥ n₀ 时，T(n) ≤ C·f(n)，就记 T(n) = O(f(n))。**

翻译成人话：n 足够大以后，T(n) 长不快过 f(n) 的某个常数倍。

所以 O 记号干的事是"抓大头"：

```text
只留最高阶，丢掉系数和低阶项。
```

例：

```text
T(n) = 3n² + 5n + 7  →  O(n²)
```

为什么 5n 和 7 可以丢？

n = 1000 时，3n² = 3,000,000，5n = 5,000，7 可以忽略。

n 再大，5n 占比更小。

**低阶项不是不存在，是"在 n 足够大时不再决定增长趋势"。**

这也解释了大 O 的一个局限：它不管 n 小时的死活。

n = 10 时，3n² + 5n + 7 = 357，跟 n² 的 100 差了三倍多。

所以 408 有时会问"n 较小时哪个更快"，答案不一定按阶来。

计算题的标准三步，背下来能省很多时间。

```text
第一步：找基本操作（最内层、执行最频繁的那句）。
第二步：写出它执行次数的函数 T(n)。
第三步：只留最高阶，去掉系数与低阶项。
```

还有两个记号，408 选择题偶尔出现。

```text
Ω(f(n))：下界，T(n) 至少长这么快。
Θ(f(n))：紧确界，上下界同阶。
```

大 O 只承诺"不快于"，不承诺"一定这么快"。

所以严格说，O(n) 的算法也是 O(n²)，只是没人这么写。

平时说"这段代码是 O(n)"，约定俗成指的是"最紧的上界"。

没有复杂度会怎样？

你没法在写代码之前判断方案行不行。

产品经理说"用户量会涨到 100 万"，你只能等上线了再说。

有了复杂度，你扫一眼循环层数，就能估个大概。

## 8. 数基本操作：四段代码，四种数法

不会数基本操作，看到两层循环就写 O(n²)，会错得很稳定。

复杂度的计算不是背公式，是数数。

数数的第一步：**确定哪一句是"基本操作"**。

基本操作是执行次数最能代表算法工作量的那句，通常是内层循环里最费时的那句。

第二步：数它执行了多少次，写成 n 的式子。

第三步：抓大头。

看四段代码。

**第一段：一层循环。**

```c
int sum(int a[], int n) {
    int s = 0;                       /* 1 次 */
    for (int i = 0; i < n; i++)      /* 判断 n+1 次，自增 n 次 */
        s += a[i];                   /* n 次 */
    return s;                        /* 1 次 */
}
```

基本操作是 `s += a[i]`，执行 n 次。

T(n) = n，抓大头得 O(n)。

循环判断和自增大约再多 2n 次，仍是 n 的常数倍，丢掉。

**第二段：三角形循环。**

```c
int count = 0;
for (int i = 0; i < n; i++)
    for (int j = i; j < n; j++)
        count++;
```

内层从 i 跑到 n−1，跑了 n−i 次。

总数：

```text
n + (n−1) + (n−2) + ... + 1 = n(n+1)/2
```

代 n = 10：

```text
10 + 9 + ... + 1 = 55
```

代 n = 100：5050。

抓大头，n(n+1)/2 = n²/2 + n/2，得 O(n²)。

**注意那个 1/2。**

**它被丢掉了，但它是真实存在的。**

如果题目问"比较次数是多少"，答 n(n+1)/2；问"时间复杂度"，答 O(n²)。

**第三段：翻倍循环。**

```c
int i = 1, k = 0;
while (i < n) {
    i = i * 2;
    k++;
}
```

i 的取值是 1, 2, 4, 8, …，第 k 次之后 i = 2^k。

循环在 2^k ≥ n 时停。

所以 k = ⌈log₂ n⌉。

代 n = 8：

```text
i: 1 → 2 (k=1) → 4 (k=2) → 8 (k=3，此时 8 < 8 不成立，停)
k = 3 = log₂ 8
```

代 n = 1000：

```text
2^9 = 512 < 1000，k=9 后继续
2^10 = 1024 ≥ 1000，k=10 停
```

T(n) = O(log n)。

**这里省略了底数。** 因为 log₂ n 和 log₁₀ n 只差一个常数倍，大 O 里不区分。

写 O(log n) 就行，除非题目明确要"比较次数"。

**第四段：两层循环，但内层翻倍。**

```c
int f(int n) {
    int i = 1, s = 0;
    while (i <= n) {
        for (int j = 1; j <= i; j++)
            s += j;
        i = i * 2;
    }
    return s;
}
```

外面看着是双层，直觉会写 O(n²)。

数一遍：

i 取 1, 2, 4, …, 2^k，其中 2^k ≤ n。

内层分别跑 1, 2, 4, …, 2^k 次。

总数：

```text
1 + 2 + 4 + ... + 2^k = 2^(k+1) − 1
```

因为 2^k ≤ n < 2^(k+1)，所以总数 < 2n。

T(n) = O(n)。

代 n = 8：

```text
i = 1, 2, 4, 8
内层次数 = 1 + 2 + 4 + 8 = 15
2n − 1 = 15
```

**反直觉的点在这里：循环嵌套的层数不等于复杂度的阶。**

决定阶的是"总次数随 n 怎么涨"，不是"缩进了几层"。

还有一个规则要会用：加法取大。

```c
for (int i = 0; i < n; i++)
    a[i] = 0;                  /* n 次 */

for (int i = 0; i < n; i++)
    for (int j = 0; j < n; j++)
        b[i][j] = 0;           /* n² 次 */
```

两段先后执行，总次数 n + n²。

抓大头得 O(n²)，不是 O(n)。

如果是两层独立的循环，不是嵌套，就是相加不是相乘。

```c
for (int i = 0; i < n; i++) sum += a[i];
for (int j = 0; j < m; j++) sum += b[j];
```

这是 O(n + m)，不能写成 O(nm)。

**嵌套是乘法，并列是加法，这一条每年都有人错。**

## 9. 常见阶：从 O(1) 到 O(n!)

不知道常见阶的排序，就没法一眼判断一个方案能不能上线。

把常见的几档排一排。

| 阶 | 名称 | n = 10 | n = 1000 | 典型场景 |
|---|---|---|---|---|
| O(1) | 常数阶 | 1 | 1 | 数组按下标取值 |
| O(log n) | 对数阶 | 4 | 10 | 折半查找 |
| O(n) | 线性阶 | 10 | 1,000 | 遍历一遍 |
| O(n log n) | 线性对数阶 | 33 | 9,966 | 归并排序、堆排序 |
| O(n²) | 平方阶 | 100 | 1,000,000 | 冒泡、直接插入 |
| O(n³) | 立方阶 | 1,000 | 10⁹ | 朴素矩阵乘法 |
| O(2ⁿ) | 指数阶 | 1,024 | 约 10³⁰¹ | 枚举所有子集 |
| O(n!) | 阶乘阶 | 3,628,800 | 大到没法写 | 枚举所有排列 |

几个必须记住的对照。

n 翻倍时：

```text
O(1)     不变
O(log n) 只多 1 次
O(n)     翻倍
O(n log n) 略多于翻倍
O(n²)    翻四倍
O(2ⁿ)    平方级爆炸
```

n = 100 万时：

```text
O(log n) ≈ 20 次
O(n)     = 100 万次
O(n²)    = 1 万亿次
```

假设一次操作 1 纳秒：

```text
20 次        ≈ 0.00002 毫秒
100 万次     ≈ 1 毫秒
1 万亿次     ≈ 1000 秒，约 16.7 分钟
```

**这就是为什么"换个算法"比"换台电脑"有用得多。**

电脑快 10 倍，1 万亿次还是要 100 秒。

算法从 O(n²) 降到 O(n log n)，100 万条从 16.7 分钟变成 20 毫秒。

几个阶之间的大小关系，可以严格排出来。

```text
O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(n³) < O(2ⁿ) < O(n!)
```

证明思路很简单：看 n 趋近无穷时，后一项除以前一项的极限。

```text
log n / n → 0       所以 log n < n
n / (n log n) = 1/log n → 0   所以 n < n log n
n log n / n² = log n / n → 0  所以 n log n < n²
n² / 2ⁿ → 0          指数比多项式涨得快
```

**不用背证明，但要记住这个顺序，选择题经常让你排。**

还有两个容易踩的坑。

**坑一：O(1) 不是"只执行一次"。**

```c
int g(int a, int b, int c) {
    int x = a + b;
    int y = b + c;
    int z = x * y;
    return z;
}
```

执行了 3 次运算，但和 n 无关，仍是 O(1)。

哪怕写 100 条顺序语句，也是 O(1)。

**坑二：O 记号不区分常数倍。**

2n 和 100n 都是 O(n)。

但实际跑起来差 50 倍。

408 选择题里如果给两段 O(n) 代码问谁快，得看具体常数，不能只看阶。

## 10. 最好、最坏与平均：三种情况，一个算法

同一段代码，输入不同，执行次数可能差很远。

看顺序查找。

```c
int search(int a[], int n, int key) {
    for (int i = 0; i < n; i++)
        if (a[i] == key)
            return i;              /* 找到就返回 */
    return -1;                     /* 没找到 */
}
```

要找的 key 恰好在第一个：比较 1 次。

在最后一个：比较 n 次。

不在表里：比较 n 次。

所以有三种复杂度。

```text
最好情况：1 次            → O(1)
最坏情况：n 次            → O(n)
平均情况：要看 key 在哪、概率多大
```

平均情况怎么算？

假设 key 一定在表里，且出现在每个位置的概率相等，都是 1/n。

第 i 个位置要比较 i 次。

```text
ASL = (1/n) × (1 + 2 + ... + n)
    = (1/n) × n(n+1)/2
    = (n+1)/2
```

代 n = 10：平均 5.5 次。

代 n = 100：平均 50.5 次。

这个量在 408 里叫平均查找长度（average search length，ASL）。

**注意"等概率"这个前提。** 没有它，平均复杂度算不出来。

如果已知 80% 的查询都查前 10% 的元素，平均值会小很多。

没有"平均"这个概念会怎样？

你只测一组数据，可能刚好是最坏情况，就误判整个算法不行。

也可能刚好是最好的，上线才发现慢。

工程上通常关心最坏情况，因为它是"保证"。

408 选择题问"时间复杂度"时，默认指最坏情况，除非题目另说。

例外也要记：

```text
直接插入排序：最好 O(n)，最坏 O(n²)，平均 O(n²)
快速排序：最好 O(n log n)，最坏 O(n²)，平均 O(n log n)
```

**同一个算法，三种情况可以是三个不同的阶。**

答题时写清楚是哪种，比只写一个 O 更稳。

拿直接插入排序做对照。

```text
最好：原数组已经有序，每个元素只比较 1 次，不移动 → O(n)
最坏：原数组完全逆序，第 i 个元素要比较 i 次 → O(n²)
平均：随机排列，大约移动 n²/4 次 → O(n²)
```

代 n = 10：

```text
最好约 9 次比较
最坏 1+2+...+9 = 45 次比较
```

差了 5 倍。

n = 1000 时，最好约 999 次，最坏约 50 万次，差了 500 倍。

**所以"插入排序是 O(n²)"这句话不完整，它只在最坏和平均意义下成立。**

那为什么教材还这么写？

因为最坏情况才是性能保证。

用户不会保证给你的数据是有序的。

## 11. 空间复杂度：省时间往往要花空间

时间不是唯一的代价。

**空间复杂度（space complexity）**：算法在运行过程中临时占用的存储空间，记作 S(n)。

注意"临时"两个字。

输入数据本身占的空间不算。

只算为了运行算法额外开的那部分，叫辅助空间（auxiliary space）。

常见三档。

**O(1)：原地工作。**

```c
void reverse(int a[], int n) {
    for (int i = 0; i < n / 2; i++) {
        int t = a[i];
        a[i] = a[n - 1 - i];
        a[n - 1 - i] = t;
    }
}
```

只用了 i 和 t 两个变量，和 n 无关，S(n) = O(1)。

**O(n)：开了一个和 n 一样大的辅助数组。**

归并排序合并两段时，要开一个临时数组存结果。

n 个元素就要 n 个格子，S(n) = O(n)。

**O(n)：递归的调用栈。**

```c
int fact(int n) {
    if (n <= 1) return 1;
    return n * fact(n - 1);
}
```

递归深度 n，每层压一个栈帧（保存参数、返回地址、局部变量）。

S(n) = O(n)。

没有"空间复杂度"这个概念会怎样？

你写了个"用空间换时间"的算法，在服务器上跑得好好的，烧进单片机就内存溢出。

嵌入式和算法题里，经常会加一句"要求空间复杂度 O(1)"。

**这时候"开个哈希表"的解法就直接出局了。**

哈希表（散列表）：用哈希函数把关键字直接算成存储位置的表，后面的散列一篇专门讲。

时间与空间常常可以互换。

查表法把计算结果存起来，用空间换时间。

原地算法省空间，但可能要多跑几遍，用时间换空间。

408 一般只要求会算，不要求做复杂权衡。

## 12. 408 怎么考这一章

绪论在 408 里分值不高，但它是后面所有复杂度题的地基。

常见三种问法。

**问法一：给一段代码，问时间复杂度。**

例题（自拟）：

```c
int fun(int n) {
    int i = 0, s = 0;
    while (s < n) {
        i++;
        s = s + i;
    }
    return i;
}
```

数一下：s 的变化是 1, 1+2, 1+2+3, …，第 k 轮后 s = k(k+1)/2。

循环在 k(k+1)/2 ≥ n 时停。

解 k² ≈ 2n，得 k ≈ √(2n)。

所以 T(n) = O(√n)。

代 n = 10：

```text
k=1: s=1
k=2: s=3
k=3: s=6
k=4: s=10 ≥ 10，停
返回 4
```

√(2×10) ≈ 4.47，对得上。

这类题的关键是：**找出循环变量和被累加的量之间的关系，解出轮数。**

**问法二：给两段代码，问哪个增长更快。**

例题（自拟）：

```text
A: T₁(n) = n²              （插入排序，常数小）
B: T₂(n) = 50 × n log₂ n   （归并排序，常数大）
```

代 n = 10：

```text
A = 100
B = 50 × 10 × 3.32 ≈ 1660
A 更快
```

代 n = 1000：

```text
A = 1,000,000
B = 50 × 1000 × 9.97 ≈ 498,000
B 更快
```

**所以 n 小的时候，O(n²) 可能赢过 O(n log n)；n 足够大，阶低的必定赢。**

题目若问"渐近意义下哪个增长慢"，答 B；若问"n = 10 时哪个快"，答 A。

**不能只报阶，要代具体 n，这是复杂度题的第二个纪律。**

**问法三：给递归式，问复杂度。**

例题（自拟）：汉诺塔。

```c
void hanoi(int n, char a, char b, char c) {
    if (n == 1) { move(a, c); return; }
    hanoi(n - 1, a, c, b);
    move(a, c);
    hanoi(n - 1, b, a, c);
}
```

递推式：

```text
T(1) = 1
T(n) = 2T(n−1) + 1
```

展开：

```text
T(n) = 2T(n−1) + 1
     = 4T(n−2) + 3
     = 2^k T(n−k) + (2^k − 1)
     = 2^(n−1) × 1 + (2^(n−1) − 1)
     = 2ⁿ − 1
```

T(n) = O(2ⁿ)。

代 n = 10：1023 次。

代 n = 64：约 1.8 × 10¹⁹ 次，按每秒一亿次算，要 5700 多年。

**这就是为什么汉诺塔只能当智力题，不能当工程算法。**

**问法四：问空间复杂度。**

例题（自拟）：把单链表逆置（`LNode` 是单链表结点类型，[03 篇](/posts/ds-linked-list/)会给出完整定义）。

```c
LNode *reverse(LNode *head) {
    LNode *pre = NULL, *p = head, *q;
    while (p != NULL) {
        q = p->next;      /* 先记住下一个 */
        p->next = pre;    /* 掉头 */
        pre = p;          /* pre 前移 */
        p = q;            /* p 前移 */
    }
    return pre;
}
```

只用了 pre、p、q 三个指针，和链表长度无关。

时间 O(n)，空间 O(1)。

对比另一种写法：把每个结点复制进一个数组，再倒着接回去。

时间也是 O(n)，但空间 O(n)。

**同一道题，两种解法，空间差一个量级，这就是 408 加一句"要求空间 O(1)"的意义。**

四个例题覆盖了本章最常考的四种数法：

```text
循环：找轮数与 n 的关系
比较：代具体 n，别只看阶
递归：写递推式再展开
空间：只数辅助变量，不数输入
```

再看一道选择题（自拟）。

```text
下列关于算法的说法，正确的是：
A. 算法必须有一个或多个输入
B. 算法必须在有限步内结束
C. 算法的时间复杂度越低，实际运行一定越快
D. 程序就是算法
```

逐项拆：

```text
A 错。输入可以是零个，比如"输出 1 到 100"。
B 对。这是有穷性，算法与死循环程序的分界。
C 错。n 小或常数大时，低阶算法可能更慢。
D 错。程序可以不含算法，也可以不满足有穷性。
```

答案 B。

这种题不考计算，考的是"定义里的限定词"。

**复习时把"必须有""可以有零个""必须有限"这些词圈出来，比背整段定义有用。**

## 13. 容易混淆的七个点

集中收一遍。

```text
1. 逻辑结构 vs 存储结构
   逻辑结构说"谁挨着谁"，存储结构说"在内存里怎么摆"。
   线性表是逻辑结构，数组和链表是它的两种存储结构。

2. 数据元素 vs 数据项
   数据元素是"一行记录"，数据项是"记录里的一格"。
   数据元素可以只含一个数据项，但两者概念不同。

3. 数据结构 vs 数据类型 vs ADT
   数据结构 = 逻辑结构 + 存储结构 + 运算。
   数据类型 = 值的集合 + 操作，如 int。
   ADT = 只写"能做什么"的数据类型，隐藏实现。

4. 时间复杂度 vs 运行时间
   时间复杂度是增长趋势，运行时间是某台机器上的实测秒数。
   前者与机器无关，后者强相关。

5. O(1) vs 执行一次
   O(1) 指执行次数与 n 无关，可以是 1 次，也可以是 100 次。

6. 最坏 vs 平均
   最坏是上界，平均要概率假设。
   408 默认问最坏，平均查找长度默认等概率。

7. 算法的特性 vs 好算法的标准
   有穷、确定、可行、输入、输出是"必须有"。
   正确、可读、健壮、高效是"最好有"。
```

还有一个更隐蔽的：

```text
8. 空间复杂度不算输入
   S(n) 只算辅助空间。
   "把数组原地逆置"是 O(1)，不是 O(n)。
```

记这八个，选择题基本不会掉坑。

### 自检三问

2. 为什么一段执行 100 条语句的代码仍是 O(1)，而一段只有两层循环的代码却可能是 O(n)？决定阶的到底是什么？

## 14. 小结

把这一篇压成几句话。

```text
数据 = 符号集合
数据元素 = 一个整体（一行记录）
数据项 = 不可再分的最小单位（一格）
数据对象 = 同类数据元素的集合
```

逻辑结构四种：

```text
集合、线性、树、图
```

存储结构四种：

```text
顺序（靠算）、链式（靠找）、索引（查表）、散列（算哈希）
```

ADT 一句话：

```text
只说能做什么，不说怎么做；换实现，调用方不改。
```

算法五个特性：

```text
有穷、确定、可行、输入、输出
```

复杂度三句话：

```text
数基本操作，不掐秒表。
只留最高阶，丢掉系数。
最坏是保证，平均要假设。
```

必须记住的阶：

```text
O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(2ⁿ)
```
三个必算的量，从这一篇开始贯穿全系列：

```text
基本操作次数：这道题到底做了多少步
平均查找长度 ASL：找一个人平均要比较几次
空间复杂度：额外开了多少格子
```
