> **读这篇之前，你只需要知道**：树是"n 个点、n−1 条边、没有环、连通"的图；带权的边可以理解成"修这条路的造价"；并查集能在一堆元素里快速判断"这两个是不是已经连在一伙了"（09 篇）。
> **这篇讲什么**：给一张带权的连通图，挑出 n−1 条边把所有点连起来，让总造价最小，以及两种挑法（每次挑最便宜的、每次只挑挨着已建部分的）。
> **一个类比**：几个村子要通电，电线杆和电线按段收费；你要让每个村都通上电，又不能多拉一根线，于是每次都在"能让新村子接进来"的那些线里挑最便宜的一根。


六个城市，要修路让任意两个城市之间都能开车到达。

候选路段和造价：

```text
v1—v2  5    v1—v4  1    v2—v4  2
v2—v5  3    v3—v5  5    v3—v6  4
v4—v5  6    v5—v6  7    v2—v6  6
v1—v5  8
```

十条候选，六座城市。

全修要 47，明显浪费。

能不能只修五条？

能，因为"六座城市都能互相到达"这件事，只需要一棵树就够了。

树有 n−1 条边，六个点就是五条边。

**问题变成：从十条里挑五条，让图连通、没有环、总造价最小。**

答案的总造价是 15。

挑哪五条、按什么顺序挑，就是这一篇的全部内容。

## 1. n 个城市修路，最省钱的连法

先说没有"最小生成树"这个概念会怎样。

十条边挑五条，组合数是 C(10,5) = 252 种。

六座城市还能硬算，六十座城市就是 C(1770,59)，天文数字，枚举不了。

而且枚举出来还得逐个检查"连不连通""有没有环"，代价更大。

所以必须有一个"一步一步挑、每步都不后悔"的办法。

先把要求写清楚，三条：

```text
1. 连通：任意两个城市之间都要有路。
2. 无环：多一条环上的路，纯属浪费钱。
3. 边数最少：n 个点的连通无环图，恰好 n−1 条边。
```

前两条一合，就是"生成树"。

第三条保证不浪费。

第四条要求是"总造价最小"。

**四条一合，就是最小生成树（minimum spanning tree，MST）。**

注意"最小"修饰的是"总权值"，不是"每一条边都最小"。

MST 里完全可以有很贵的边，只要它是唯一能把某个点接进来的边。

这一点后面还会用反例强调一次。

**顺手证一个必考的小结论：n 个点的连通图，至少 n−1 条边。**

按连通关系把顶点分成若干块，块内互相可达，块间没有边。

如果整张图连通，那就只有一块，块数记作 `k = 1`。

每一块只要有边连起来，块内边数就不少于"块内点数 − 1"（可以归纳证明）。

把所有块加起来：

```text
边数 ≥ 总点数 − 块数 = n − k
```

连通时 `k = 1`，所以边数 ≥ `n − 1`。

**再看"多一条边会怎样"：n 个点、n 条边、连通，必然有环。**

因为 `n−1` 条边已经足够连通，多出来的那一条，两个端点之间早就有一条路径了，加上它正好闭成一个环。

**所以生成树的 n−1 条边，正好卡在"刚好连通"和"开始有环"之间。**

少一条就断，多一条就绕，这个临界点是整篇的出发点。

## 2. 最小模型：生成树、割、割性质

先说没有这三个词会怎样。

"为什么每次挑最便宜的边不会错"这个问题，光靠直觉答不了。

考场上问"这个算法为什么正确"，你需要一个能写下来的理由。

**生成树（spanning tree）**：连通图的生成树，是包含全部 n 个顶点、只有 n−1 条边的极小连通子图。

"极小"是指：少任何一条边就不连通了。

所以生成树里每条边都是桥（bridge），删掉它图就断。

**最小生成树**：所有生成树里，边权之和最小的那一棵。

记号上，`T` 是一棵生成树，`w(T)` 是它的总权值，MST 就是让 `w(T)` 最小的 `T`。

**割（cut）**：把顶点集分成两个不相交的非空部分 `S` 和 `V−S`。

```text
S = {v1, v4}
V − S = {v2, v3, v5, v6}
```

这个"分法"就叫一个割。

**横跨割的边（crossing edge）**：一个端点在 `S` 里、另一个端点在 `V−S` 里的边。

上面那个割，横跨的边有：

```text
v1—v2 (5)    一端在 S
v1—v5 (8)
v4—v2 (2)
v4—v5 (6)
```

四条。

**割性质（cut property）**：对任意一个割，横跨它的权值最小的那条边，一定属于某棵最小生成树。

如果那条边的权值是唯一的，它还属于**所有**最小生成树。

这条性质是 Prim 和 Kruskal 共同的正确性来源。

**为什么割性质成立？**

用反证法，两步。

第一步：任意一棵生成树，至少要有一条边横跨这个割。

因为树要把 `S` 里的点和 `V−S` 里的点连起来，不跨割就做不到。

第二步：假设某棵 MST 里横跨这个割的边是 `e'`，而横跨这个割的最小边是 `e`，且 `w(e) < w(e')`。

把 `e` 加进这棵树，会形成一个环。

这个环一定还有另一条横跨割的边（因为从 `S` 走到 `V−S` 再走回来，必然跨两次）。

而那另一条边就是 `e'` 一类的东西，把 `e'` 删掉，环就断了，树还是树。

新树的总权值 = 旧树 − `w(e')` + `w(e)` < 旧树。

矛盾，因为旧树已经是最小的。

**所以"横跨割的最小边"一定在 MST 里。**

这条证明很短，但它就是两种贪心算法的全部依据。

记住一句话：

```text
割性质：任何一刀切下去，最便宜的那根跨界边，一定可以要。
```

## 3. 走一遍：Kruskal 逐边选择

先说没有 Kruskal 会怎样。

如果按"从 v1 出发，一条一条往外接"，做出来的树可能被 v1 的位置绑死。

Kruskal 换了个视角：**把所有边排个队，从最便宜的开始，能要就要。**

人话版规则：

```text
1. 所有边按权值从小到大排序。
2. 依次看每一条边：
   如果它的两个端点还不连通，就要它；
   如果已经连通（会成环），就扔。
3. 要到 n−1 条边就停。
```

为什么"已经连通就要扔"？

因为两个端点已经能互相到达，再加这条边只会形成一个环，而环上的边对"连通"没有任何新贡献，纯浪费。

判断"是否已经连通"，正是并查集的活儿。

`find(u) == find(v)` 就扔，否则 `union(u, v)` 并选中它。

十条边排序：

```text
 1  v1—v4
 2  v2—v4
 3  v2—v5
 4  v3—v6
 5  v1—v2
 5  v3—v5
 6  v4—v5
 6  v2—v6
 7  v5—v6
 8  v1—v5
```

注意有两个 5、两个 6，排序时谁在前面不影响最终总权值。

按上面的顺序走一遍。

```text
第 1 条：v1—v4 (1)    v1、v4 不连通 → 选中
第 2 条：v2—v4 (2)    v2、v4 不连通 → 选中
第 3 条：v2—v5 (3)    v2、v5 不连通 → 选中
第 4 条：v3—v6 (4)    v3、v6 不连通 → 选中
第 5 条：v1—v2 (5)    v1、v2 已连通（v1—v4—v2）→ 扔掉
第 6 条：v3—v5 (5)    v3 在 {v3,v6}，v5 在 {v1,v2,v4,v5} → 不连通 → 选中
```

选到第 5 条边，`n−1 = 5` 满了，停。

选中的五条：

```text
v1—v4 (1)   v2—v4 (2)   v2—v5 (3)   v3—v6 (4)   v3—v5 (5)
总权值 = 1 + 2 + 3 + 4 + 5 = 15
```

画出来：

```text
    v1         v2         v3
     │        ╱  ╲        │
    1│      2╱    ╲3    4│
     │      ╱      ╲      │
    v4            v5 ──── v6
                   5
```

连成一棵树：`v4 — v1`，`v4 — v2`，`v2 — v5`，`v5 — v3`，`v3 — v6`。

六个点、五条边、无环、连通。

**第 5 条边为什么被扔掉？**

因为 `v1—v4—v2` 已经通了，再加 `v1—v2` 就多出一个三角形 `v1—v4—v2—v1`。

这个三角形花了 5 块钱，对"连通"零贡献。

**注意这里有个反直觉的点：**

```text
Kruskal 扔掉的边，权值（5）比它后面选中的边（4）还大，
但它被扔不是因为贵，而是因为"多余"。
```

如果那条 5 是 `v6—v3`（唯一能把 v6 接进来的边），再贵也得要。

## 4. 走一遍：Prim 从 v1 出发

先说没有 Prim 会怎样。

Kruskal 要先把所有边排序，e 很大时排序本身就很贵。

而且它每次都在"全局"找最便宜的边，可能同时在好几个互不相连的地方各长一棵小树。

Prim 换了个思路：**只维护一棵树，每次从"树里连到树外"的边中挑最便宜的。**

人话版规则：

```text
1. 随便选一个起点，放进集合 U。
2. 找出所有"一端在 U 里、一端不在 U 里"的边。
3. 挑其中权值最小的一条，把外面的那个点拉进 U。
4. 重复，直到 U 里装下所有点。
```

还是那六个城市，从 v1 出发。

**第 1 轮**：U = {v1}。

横跨的边：`v1—v2 (5)`、`v1—v4 (1)`、`v1—v5 (8)`。

最小是 1，选 `v1—v4`，把 v4 拉进来。

```text
U = {v1, v4}      累计权值 1
```

**第 2 轮**：U = {v1, v4}。

横跨的边：`v1—v2 (5)`、`v1—v5 (8)`、`v4—v2 (2)`、`v4—v5 (6)`。

最小是 2，选 `v4—v2`，把 v2 拉进来。

```text
U = {v1, v4, v2}   累计 1 + 2 = 3
```

**第 3 轮**：U = {v1, v4, v2}。

横跨的边：`v1—v5 (8)`、`v4—v5 (6)`、`v2—v5 (3)`、`v2—v6 (6)`。

最小是 3，选 `v2—v5`，把 v5 拉进来。

```text
U = {v1, v4, v2, v5}   累计 6
```

**第 4 轮**：U = {v1, v4, v2, v5}。

横跨的边：`v1—v5` 已经是内部边了；新增 `v5—v3 (5)`、`v5—v6 (7)`、`v2—v6 (6)`。

最小是 5，选 `v5—v3`，把 v3 拉进来。

```text
U = {v1, v4, v2, v5, v3}   累计 11
```

**第 5 轮**：U 里有五个点。

横跨的边：`v3—v6 (4)`、`v2—v6 (6)`、`v5—v6 (7)`。

最小是 4，选 `v3—v6`，把 v6 拉进来。

```text
U = 全部六个点   累计 15
```

结束。

Prim 选中的边：

```text
v1—v4 (1)   v2—v4 (2)   v2—v5 (3)   v3—v5 (5)   v3—v6 (4)
总权值 = 1 + 2 + 3 + 5 + 4 = 15
```

**和 Kruskal 选出的是同一组边，只是顺序不同：**

```text
Kruskal 的顺序：1, 2, 3, 4, 5
Prim    的顺序：1, 2, 3, 5, 4
```

第 4 条和第 5 条调了个个儿。

为什么会这样？

因为 Kruskal 是"全局排队"，权值 4 的边排在权值 5 的前面，它先看到就先选了。

Prim 是"围着当前这棵树找"，权值 4 的 `v3—v6` 在第 3 轮时 v3 还没进树，看不见它。

等 v3 进树了，已经选过 5 了。

**同一个权值，不同的挑法，不同的顺序，同一棵树。**

这个"殊途同归"不是巧合，割性质保证了两者都在做"安全选择"。

**再把 Prim 的起点换成 v6，验证一下"起点不影响总权值"。**

v6 的邻居：`v6—v2 (6)`、`v6—v3 (4)`、`v6—v5 (7)`。

```text
第 1 轮：U={v6}          最小 4，选 v6—v3，拉 v3 进来
第 2 轮：U={v6,v3}       候选 v3—v5(5)、v6—v2(6)、v6—v5(7)，最小 5，拉 v5
第 3 轮：U={v6,v3,v5}    候选 v5—v2(3)、v5—v4(6)、v6—v2(6)，
                         还有 v3 的边和 v5—v1(8)，最小 3，拉 v2
第 4 轮：U={v6,v3,v5,v2} 候选 v2—v4(2)、v2—v1(5)、v5—v4(6)、v5—v1(8)，
                         最小 2，拉 v4
第 5 轮：U 里有五个点     候选 v4—v1(1)、v2—v1(5)、v5—v1(8)，
                         最小 1，拉 v1
```

选中的边：

```text
v6—v3 (4)   v3—v5 (5)   v5—v2 (3)   v2—v4 (2)   v4—v1 (1)
总权值 = 4 + 5 + 3 + 2 + 1 = 15
```

**和从 v1 出发的结果一模一样，选中的五条边也一模一样。**

只有挑选的顺序变成了 `4, 5, 3, 2, 1`（从 v1 出发时是 `1, 2, 3, 5, 4`）。

这正好是"倒着挑"——因为 v6 那一侧边比较贵，从贵的这头开始，最后才挑到最便宜的 1。

**所以"从哪个点出发"只影响过程，不影响结论。**

考试如果问"Prim 从 v6 出发的第 3 条边是哪条"，那就是 `v5—v2 (3)`。

## 5. 拆开看之一：两种贪心为什么都对

先说没有这一节会怎样。

"每次挑最小"这句话听起来很危险。

现实中的贪心经常错：背包问题里，按"单位价值最高"贪心，就拿不到最优解。

为什么在生成树上就对了？

关键在"安全边"这个概念。

**安全边（safe edge）**：如果往当前已选的边集 `A` 里加一条边，加完仍然属于某棵 MST，这条边就叫安全的。

两个算法都在保证一件事：

```text
每一步选的边，都是安全边。
```

只要每一步都安全，选满 n−1 条时，得到的一定是某棵 MST。

**Kruskal 的安全性：**

它把边按权值排序，每次取"当前最小的、不会成环的边"。

把已选边集的连通分量看成若干个集合，任取其中一个集合 `S`，`V−S` 是其余部分。

这条边是横跨这个割的最小边（因为它已经是从小到大排的、之前更小的都没能连过去）。

按割性质，它安全。

**Prim 的安全性：**

`U` 就是那个 `S`。

它每次挑的就是"横跨 `(U, V−U)` 的最小边"。

按割性质，直接安全。

**所以两个算法的差别只在于"割怎么选"：**

```text
Prim  ：割固定在"已建的那棵树"和"其余"，一次只长一棵树。
Kruskal：割随着连通分量变，可能同时在好几处长树，最后拼起来。
```

**再看一个错误的贪心，体会一下"割"的重要。**

规则：每个顶点各自选"自己连出去最便宜的那条边"。

用我们的图算：

```text
v1 的最小边：v1—v4 (1)
v2 的最小边：v2—v4 (2)
v3 的最小边：v3—v6 (4)
v4 的最小边：v4—v1 (1)
v5 的最小边：v5—v2 (3)
v6 的最小边：v6—v3 (4)
```

选出来是 `v1—v4`、`v2—v4`、`v3—v6`，加上重复的 `v4—v1`、`v6—v3`。

去重之后只有三条边：`v1—v4`、`v2—v4`、`v3—v6`。

v5 和 v6 各自的小团体连不到一起，图不连通。

**失败的原因：每个人只顾自己，没有一个统一的"割"。**

贪心对不对，取决于"贪"的标准是不是跟全局目标一致。

生成树上，割性质保证了这种一致性；背包问题上没有，所以贪心失败。

## 6. 拆开看之二：复杂度，O(n²) 与 O(e log e)

先说没有这笔账会怎样。

两个算法都能算出正确答案，代码量也差不多。

但一个在稠密图上快 100 倍，另一个在稀疏图上快 100 倍。

选错了，程序在大图上就跑不完。

**Kruskal 的开销分两块：**

```text
1. 排序：e 条边排序，O(e log e)
2. 判环：每条边两次 find，并查集近似 O(1)，共 O(e α(e)) ≈ O(e)
```

合起来 `O(e log e)`，主项是排序。

所以 Kruskal 的复杂度**只跟边数有关，跟顶点数关系不大**。

边少的时候非常划算。

**Prim 的朴素实现：**

用邻接矩阵 + 一个 `lowcost[]` 数组，记"每个树外顶点到树内的最小边权"。

```text
每一轮：
  1. 在 lowcost 里扫一遍，找最小的（O(n)）
  2. 把这个顶点拉进 U
  3. 更新 lowcost：用新进来的点，刷新它所有邻居的最小值（O(n)）
共 n 轮，每轮 O(n) → O(n²)
```

`O(n²)` 跟边数完全无关。

稠密图（`e` 接近 `n²`）时，这已经是最优的量级了。

稀疏图（`e` 远小于 `n²`）时，就亏了：明明只有几千条边，却要扫 n² 次。

**Prim 的堆优化：**

把"树外顶点到树内的最小边权"放进小顶堆。

```text
每轮：弹堆顶 O(log n)，更新邻居时压新值 O(e log n)
总共：O(e log n)
```

**两者的比较：**

```text
Kruskal ：O(e log e)
Prim 堆 ：O(e log n)
Prim 朴素：O(n²)
```

`log e` 和 `log n` 只差常数级别，所以堆优化的 Prim 和 Kruskal 差不多。

真正拉开差距的是"朴素 Prim 的 n²"。

判断门槛：

```text
e 接近 n²（稠密）→ n² 和 e 同量级，Prim 朴素最好，还省了排序和并查集
e 远小于 n²（稀疏）→ e log e 远小于 n²，Kruskal 或堆 Prim 更好
```

给个具体数字：n = 1000。

```text
朴素 Prim：n² = 10⁶ 次
Kruskal ：e log e，若 e = 2000，则 2000 × 11 ≈ 2.2×10⁴ 次
```

稀疏图上 Kruskal 快 45 倍。

反过来，n = 1000、e = 499500（接近完全图）：

```text
朴素 Prim：10⁶ 次
Kruskal ：499500 × 19 ≈ 9.5×10⁶ 次
```

稠密图上朴素 Prim 快 9 倍。

**这就是"稠密用 Prim、稀疏用 Kruskal"的算术依据。**

顺带把空间也算一笔，考试偶尔会问。

```text
Prim 朴素：lowcost[n] + visited[n] + 矩阵 n²  → 空间 O(n²)（矩阵占大头）
Prim 堆  ：dist[n] + 堆最多 e 个元素          → 空间 O(n + e)
Kruskal  ：边数组 e 个 + 并查集 parent[n]     → 空间 O(n + e)
```

所以"空间换时间"在这里也成立：Prim 朴素省了排序和并查集，但吃掉了 n² 的矩阵。

如果图大到矩阵存不下，Prim 朴素版连初始化都做不到，只能上堆版或 Kruskal。

## 7. 拆开看之三：MST 不唯一，总权唯一

先说没有这一节会怎样。

选择题特别喜欢问"MST 唯一吗"。

答"唯一"或"不唯一"都不完整，得看条件。

**结论一：边权互不相同，MST 唯一。**

理由：割性质说"横跨割的最小边属于所有 MST"。

如果每刀切下去最小边都唯一，那每一步都没有第二种选法，树只能长成一个样子。

**结论二：有权值相同的边，MST 可能不唯一，但总权值一定相同。**

构造一个最简单的例子：

```text
三角形，三个点三条边，权值都是 1。
```

任取两条边都能连成生成树，总权值都是 2。

三棵不同的 MST，同一个总权。

**结论三：MST 不保证"任意两点间路径最短"。**

这是最容易错的一条。

**下面这几个例子值得自己动手试一遍：连着三个都打平，第四个才试出反例。**

这件事本身就在说明：MST 的路径经常恰好等于最短路径，所以很容易误以为它们永远一样。

看一个反例。

```text
     v1
   1/  \1
   v2   v3
    \  /
     v4
      1
      v5
```

边：`v1—v2 (1)`、`v1—v3 (1)`、`v2—v4 (1)`、`v3—v4 (1)`，再加 `v4—v5 (1)`。

MST 总权 = 4（五条边里挑四条）。

从 v1 到 v5，MST 里的路径是 `v1 → v2 → v4 → v5`，三条边，总权 3。

而原图里还有 `v1 → v3 → v4 → v5`，也是 3。

打平，看不出问题。

换一个能看出问题的：

```text
v1—v2 (1)
v2—v3 (1)
v1—v3 (100)
```

三角形，三条边。

MST 选 `v1—v2` 和 `v2—v3`，总权 2，不含那条 100。

从 v1 到 v3，MST 里的路径是 `v1 → v2 → v3`，权值 2。

而原图里还有直连的 `v1—v3`，权值 100，更贵。

还是没看出问题。

**真正的问题在"瓶颈"上。**

MST 保证的是：任意两点之间，MST 里那条路径的**最大边权**，是所有可能路径里最小的。

这叫最小瓶颈路（minimax path）。

但不保证**总权**最小。

举个例子：`v1—v2 (1)`、`v2—v3 (1)`、`v1—v3 (3)`。

MST 取前两条，v1 到 v3 的路径权值 2。

原图里直连的 `v1—v3` 权值 3，更贵。

要找"总权最小"，MST 恰好也对。

**那什么时候 MST 的路径不是最短路径？**

需要一条"边数多但每段都短"的绕路，比 MST 里那条路更省。

```text
v1—v2 (5)
v2—v3 (5)
v1—v4 (1)
v4—v5 (1)
v5—v3 (1)
```

MST：`v1—v4 (1)`、`v4—v5 (1)`、`v5—v3 (1)`、加上 `v1—v2 (5)` 或 `v2—v3 (5)`（二选一）。

假设选 `v1—v2 (5)`，MST 总权 = 1+1+1+5 = 8。

从 v1 到 v3，MST 里的路径是 `v1 → v4 → v5 → v3`，权值 3。

而原图里 `v1 → v2 → v3` 是 10，更贵。

还是没构造出来。

**说到底，MST 的路径经常恰好也是最短路径，但不是被保证的。**

要构造反例，需要"某条边在 MST 里，但它对某个点对来说绕了远路"。

经典构造：

```text
v1—v2 (1)
v1—v3 (2)
v2—v3 (2)
v3—v4 (3)
```

MST：`v1—v2 (1)`、`v1—v3 (2)`、`v3—v4 (3)`，总权 6。

从 v2 到 v4，MST 里的路径：`v2 → v1 → v3 → v4`，权值 1+2+3 = 6。

原图里另一条：`v2 → v3 → v4`，权值 2+3 = 5，更短。

**但 `v2—v3` 不在 MST 里。**

为什么？因为 `v1—v2` 和 `v1—v3` 已经把 v1、v2、v3 连通了，再加 `v2—v3` 会成环，而且它权值 2 比 `v1—v2` 的 1 大，Kruskal 会先选 1。

于是 v2 到 v4 的 MST 路径是 6，真正的最短路是 5。

**结论：MST 让"全网总造价最小"，不保证"任意两点间路径最短"。**

要求两点间最短，得用 13 篇的 Dijkstra。

这个区别，408 几乎每年都设一个坑。

## 8. 408 怎么考

先说没有这套题型归纳会怎样。

MST 的题几乎都是"过程题"：给图，写选边顺序，求总权值。

写错一条边，总权就错，后面全废。

常考的五类：

```text
类型一：给图，写出从某点出发的 Prim 选边顺序和总权值。
类型二：给图，写出 Kruskal 的选边顺序，问"第 k 条被选中的边"。
类型三：问 MST 是否唯一，或者"某条边一定在 MST 里吗"。
类型四：给一张不完全的图，问"总权值最小是多少"。
类型五：判断算法的复杂度与适用场景。
```

例题一（自拟）：还是那六个城市、十条边，问 Kruskal 算法中"第 5 条被检查的边"和"第 5 条被选中的边"分别是什么。

**先区分"检查"和"选中"。**

排序后第 5 条被检查的边是 `v1—v2 (5)`。

它被检查后被扔掉了，所以它不是"第 5 条被选中的"。

按选中顺序数：

```text
第 1 条选中：v1—v4 (1)
第 2 条选中：v2—v4 (2)
第 3 条选中：v2—v5 (3)
第 4 条选中：v3—v6 (4)
第 5 条选中：v3—v5 (5)
```

答案：第 5 条被检查的是 `v1—v2`，第 5 条被选中的是 `v3—v5`。

**这个"检查"和"选中"的区分，是这类题最大的坑。**

例题二（自拟）：若把 `v3—v5` 的权值从 5 改成 20，MST 的总权值是多少？

重新排序，`v3—v5` 排到最后。

前四条不变：`v1—v4 (1)`、`v2—v4 (2)`、`v2—v5 (3)`、`v3—v6 (4)`，此时 `{v1,v2,v4,v5}` 和 `{v3,v6}` 两组。

继续：

```text
v1—v2 (5)  同一组，扔
v4—v5 (6)  同一组，扔
v2—v6 (6)  跨组（v2 在组 A，v6 在组 B）→ 选中
```

选满 5 条：`1 + 2 + 3 + 4 + 6 = 16`。

所以总权值变成 16。

注意：原来的 `v3—v5 (5)` 变贵之后，系统换了一条更贵的 `v2—v6 (6)` 来连通两组。

**这说明 MST 会根据权值自动调整，不是"少一条就多一条"的简单替换。**

例题三（自拟）：判断"权值最大的边一定不在 MST 中"。

错。

如果那条边是桥（删掉它图就不连通），它必须出现在任何生成树里。

构造：

```text
v1—v2 (1)
v2—v3 (100)
```

三个点两条边，v2—v3 是唯一的通路，权值 100 是最大，但它必须在 MST 里。

MST 总权 = 101。

**正确的说法是：权值最大的边"不一定"在 MST 中，但如果它是桥，就一定在。**

三个高频陷阱：

```text
陷阱 1：把"检查顺序"当成"选中顺序"。Kruskal 会扔掉边。
陷阱 2：以为 Prim 必须从编号最小的点出发。起点可以任意，总权值一样。
陷阱 3：以为 MST 唯一。边权有重复时可能有多棵，但总权相同。
```

## 9. 写代码：Prim 与 Kruskal

先说没有代码落地会怎样。

手算六七个点还行，实际工程里几千个点，必须靠程序。

而且两个算法的边界条件（图不连通、有孤立点）不处理，结果会静默出错。

**Prim，邻接矩阵版。**

核心是 `lowcost[]`：记"每个树外顶点，连到树内的最小边权"。

```c
#define MAXV 100
#define INF  0x3f3f3f3f

/* 返回 MST 的总权值；图不连通时返回 -1 */
int Prim(MGraph *G, int start)
{
    int lowcost[MAXV];      /* 树外顶点到树内的最小边权 */
    int visited[MAXV];      /* 是否已进树 */
    int total = 0, cnt = 0;

    for (int i = 0; i < G->n; i++) {
        lowcost[i] = G->edge[start][i];   /* 初始只有起点在树里 */
        visited[i] = 0;
    }
    visited[start] = 1;
    cnt = 1;

    while (cnt < G->n) {
        int k = -1, minw = INF;
        for (int i = 0; i < G->n; i++)     /* 找树外最小的 lowcost */
            if (!visited[i] && lowcost[i] < minw) { minw = lowcost[i]; k = i; }
        if (k == -1) return -1;            /* 图不连通，走不到别的点 */
        visited[k] = 1;
        total += minw;
        cnt++;
        for (int i = 0; i < G->n; i++)     /* 用新进来的 k 刷新 */
            if (!visited[i] && G->edge[k][i] < lowcost[i])
                lowcost[i] = G->edge[k][i];
    }
    return total;
}
```

三处容易写错：

```text
1. lowcost 初始要用 start 那一行，不是全 INF。
2. 找最小值只能在"未进树"的点里找，漏了 visited 判断就会重复选。
3. 图不连通时 k 会一直是 -1，必须返回错误，不能硬加。
```

**Kruskal，边数组 + 并查集。**

```c
typedef struct { int u, v, w; } Edge;

int cmp(const void *a, const void *b)
{
    return ((Edge *)a)->w - ((Edge *)b)->w;
}

/* edges[0..m-1]，n 个顶点，返回 MST 总权值 */
int Kruskal(Edge edges[], int m, int n)
{
    int total = 0, picked = 0;
    Init(n);                       /* 并查集初始化：p[i] = i */
    qsort(edges, m, sizeof(Edge), cmp);   /* 按权值升序 */
    for (int i = 0; i < m && picked < n - 1; i++) {
        int ru = Find(edges[i].u), rv = Find(edges[i].v);
        if (ru == rv) continue;    /* 已成环，扔掉 */
        parent[ru] = rv;           /* 合并 */
        total += edges[i].w;
        picked++;
    }
    return (picked == n - 1) ? total : -1;   /* 选不够说明不连通 */
}
```

注意循环条件里的 `picked < n - 1`。

选满 n−1 条就可以立刻停，不用把剩下的边都检查完。

**这个提前终止，是 Kruskal 在稠密图上的一个重要常数优化。**

两类图各跑一次，对比很直观：

```text
图 A：n = 500，e = 600（稀疏）    Kruskal 排序 600 条，很快
图 B：n = 500，e = 100000（稠密） Kruskal 排序 10 万条，Prim 只扫 n² = 25 万次
```

图 B 里 Prim 更快。

## 10. 什么图用哪个

先说没有这个判断会怎样。

两个算法都对，随便挑一个也能出结果。

但考试问"为什么这题适合用 Kruskal"，答不上来就丢分；工程上选错，性能差一个量级。

一句话结论：

```text
稠密图 → Prim（朴素版，O(n²)）
稀疏图 → Kruskal（O(e log e)）
```

判据不是"感觉稠不稠"，而是比两个数：

```text
比较 n² 和 e log e
n² 小 → Prim
e log e 小 → Kruskal
```

再给三个具体场景。

**场景一：城市之间的高速公路网。**

几百个城市、几千条候选路段，`e ≪ n²`，稀疏。

用 Kruskal：排序几千条边，几乎瞬间。

**场景二：芯片内部的布线网。**

几万个引脚，每个引脚和周围一圈都要连，`e` 接近 `n` 的好几倍，仍不算 `n²`。

用 Kruskal 或堆 Prim 都行。

**场景三：完全图（每对点之间都有边）。**

`e = n(n−1)/2 ≈ n²/2`。

Kruskal 要排 `n²/2` 条边，光排序就 `O(n² log n)`，比 Prim 的 `O(n²)` 多一个 `log n`。

用 Prim。

**还有两个非性能因素：**

```text
Kruskal 需要"一次看到所有边"，图是流式给进来的就不好办；
Prim 只需要"当前树边界上的边"，可以边读边算。
```

所以"图太大、一次读不进内存"时，Prim 更有优势。

## 11. 容易混淆的五个点

**第一，MST 的"最小"是总权值最小，不是每条边都最小。**

MST 里可以有很贵的边，只要它是唯一的通路。

**第二，Prim 的起点不影响总权值。**

从 v1 出发和从 v6 出发，选出的边可能不同，但总权值一定一样。

因为两者都满足割性质，都是 MST。

**第三，Kruskal 的"扔边"不是"这条边太贵"。**

扔的原因是"两个端点已经连通，加了会成环"。

一条很贵的边，只要它连接两个还没通的组，照样要。

**第四，MST 不保证两点间路径最短。**

它保证的是"总造价最小"和"瓶颈边最小"，不是"任意两点间最短"。

**第五，图不连通时没有生成树，只有最小生成森林。**

每个连通分量各求一棵 MST，合起来就是森林。

代码上表现为"选不满 n−1 条边"。

## 12. 真实系统里长什么样

先说没有这一段会怎样。

MST 看起来是个纯教科书问题，其实它是一大堆实际问题的骨架。

**电网与光纤布线。**

这是 MST 最原始的来源。

几十个变电站、上千条可选线路，每条有造价，要求全连通且总造价最小。

实际工程当然还有别的约束（容量、可靠性、地理限制），但 MST 给出的是"理论下界"。

算一遍 MST，就知道"这个方案还能再省多少"。

**聚类：单链凝聚。**

把每个数据点看成一个顶点，两两之间的距离看成边权。

先求 MST，然后"把最长的几条边砍掉"。

砍掉 k 条最长的边，就得到 k+1 个簇。

为什么这么做有道理？

因为 MST 里剩下的边都是"最短的连接"，砍掉最长的，等于砍掉"最不像一伙"的连接。

这叫单链（single-linkage）聚类，是层次聚类里最省事的一种。

复杂度借用了 MST 的 `O(e log e)`。

**近似算法：TSP 的 2 倍近似。**

旅行商问题（TSP）是 NP 难的，没有多项式精确解。

但有一个经典近似：

```text
1. 求 MST。
2. 沿 MST 做一次 DFS，记下访问顺序。
3. 按这个顺序走，遇到走过的点就跳过（抄近路）。
```

得到的路线长度不超过最优解的 2 倍。

为什么？

因为 MST 的总权不超过最优 TSP 路线（去掉 TSP 环上一条边就是一棵生成树）。

而沿 MST 走两遍（每条边来回各一次）正好是 2 倍 MST，抄近路只会更短。

**所以 MST 是"用 2 倍代价换多项式时间"的那个 2 倍的来源。**

**分布式系统：最小生成树做广播。**

一个网络里要让所有节点收到同一条消息，最省带宽的做法是沿一棵生成树转发，每个节点只转发一次。

这棵树如果按链路代价选最小，就是 MST。

**现实中的分布式 MST 算法（如 GHS 算法）就是 Prim 的分布式版本**：每个节点只知道自己的邻居，靠互相发消息一点点把树拼出来。

**一个共同点：**

```text
凡是"用最少的代价把所有东西连起来"的问题，最后都会落到 MST 上。
```

### 自检三问

1. Kruskal 里那条 `v1—v2 (5)` 为什么被扔掉？它比后面选中的 `v3—v5 (5)` 差在哪？

   答不上来说明还在用"贵不贵"判断取舍。两条边的权值一样都是 5，区别在于 `v1` 和 `v2` 已经通过 `v1—v4—v2` 连通了，加它会成环；而 `v3` 和 `v5` 分属两个还没连通的组，加它能把两组接起来。扔的理由是"多余"，不是"贵"。

2. Prim 和 Kruskal 选出的边一样吗？顺序一样吗？为什么？

   答不上来说明没把"安全边"和"割"连起来。这个例子里选出的 5 条边完全相同，但顺序不同：Kruskal 是 1,2,3,4,5，Prim 是 1,2,3,5,4。因为 Kruskal 按全局权值排序，权值 4 的边排在 5 前面就先被看到；Prim 只看得见"当前树的边界"，权值 4 的 `v3—v6` 在 v3 进树之前根本不在候选里。两者都在选安全边，所以最终都是 MST。

3. 为什么稠密图用 Prim、稀疏图用 Kruskal？给一个能算的数字。

   答不上来说明没算过 `n²` 和 `e log e`。n = 1000、e = 2000 时，朴素 Prim 要 10⁶ 次，Kruskal 约 2000×11 = 2.2×10⁴ 次，Kruskal 快 45 倍；n = 1000、e = 499500 时，Prim 还是 10⁶ 次，Kruskal 要约 499500×19 ≈ 9.5×10⁶ 次，Prim 快 9 倍。判据就是比这两个数谁小。

## 13. 再练三题

三道题：一道两个算法对着做，一道判断，一道算复杂度。

**练习一：4 个点、4 条边的图，边为 `1—3 (1)`、`2—4 (2)`、`1—2 (3)`、`3—4 (4)`。分别用 Kruskal 和从 v1 出发的 Prim 求 MST。**

Kruskal：排序后是 `1—3 (1)`、`2—4 (2)`、`1—2 (3)`、`3—4 (4)`。

```text
1—3 (1)：1、3 不连通 → 选中
2—4 (2)：2、4 不连通 → 选中
1—2 (3)：{1,3} 和 {2,4} 还不通 → 选中
```

三条边选满（n−1 = 3），停。

总权值 = 1 + 2 + 3 = 6。

Prim 从 v1 出发：

```text
U={1}     候选：1—3(1)、1—2(3)              → 选 1—3(1)
U={1,3}   候选：1—2(3)、3—4(4)              → 选 1—2(3)
U={1,3,2} 候选：2—4(2)、3—4(4)              → 选 2—4(2)
```

总权值 = 1 + 3 + 2 = 6。

**选中的边完全一样，顺序不同：Kruskal 是 1、2、3，Prim 是 1、3、2。**

差别出在第三轮：Kruskal 按全局权值排，`2—4`（权 2）排在 `1—2`（权 3）前面；Prim 在 v2 还没进树时看不到 `2—4`，只能先选 `1—2`。

**练习二（判断对错）：**

```text
(1) 各边权互不相同的图，MST 唯一。
(2) MST 中任意两点间的路径，就是这两点间的无权重最短路。
(3) Kruskal 跳过的边，一定不在任何一棵 MST 里。
```

```text
(1) 对。割性质给出"横跨任意割的最小边唯一"，每一步都没有第二种选法。
(2) 错。第 7 节的反例：v1—v2(1)、v1—v3(2)、v2—v3(2)、v3—v4(3)，
    MST 里 v2 到 v4 走 v2→v1→v3→v4 权值 6，而原图 v2→v3→v4 只要 5。
(3) 错。等权的情况下，被跳过的边可能属于另一棵 MST。
    例如三角形三条边权都是 1，Kruskal 跳过第三条，
    但那第三条和另外两条中的任一条组合，都是合法的 MST。
```

**练习三：n = 2000、e = 5000 的稀疏图，粗算 Kruskal 与朴素 Prim 的操作次数。**

```text
Kruskal：排序 5000 条边，约 5000 × log₂5000 ≈ 5000 × 12.3 ≈ 6.2×10⁴ 次比较
         并查集部分约 2e 次 find，忽略常数
朴素 Prim：n² = 4×10⁶ 次
```

比例约 65 : 1，Kruskal 完胜。

把 e 换成 1999000（接近完全图）再算一次：

```text
Kruskal：2×10⁶ × 21 ≈ 4.2×10⁷
Prim   ：4×10⁶
```

这回 Prim 快 10 倍。

**同一张顶点表，换个边数，赢家就换了。**

顺手给一段"把 MST 的边打印出来"的代码，考试写综合题常要用：

```c
/* Prim 里选中 k 时，把边 (parent[k], k) 输出 */
int parent[MAXV];              /* parent[i] = i 是从哪个点被拉进树的 */

/* 在 Prim 的 while 循环里，找到 k 之后补两行： */
visited[k] = 1;
total += minw;
printf("选边 %d—%d，权 %d\n", parent[k], k, minw);
/* 更新 lowcost 时，顺便记下"是谁刷新的" */
if (!visited[i] && G->edge[k][i] < lowcost[i]) {
    lowcost[i] = G->edge[k][i];
    parent[i] = k;             /* 关键：记下这条边从哪来 */
}
```

`parent[]` 就是 MST 这棵树的父亲数组，和 BFS 树里的 `prev[]` 是一个套路。

**有了它，不光能算总权，还能把树画出来。**

## 14. 小结

回到开头的六个城市。

十条候选路，全修 47，只修五条是 15。

省下来的 32，来自"不修环上的路"。

MST 的全部内容，压成四句：

```text
连通、无环、n−1 条边，这是生成树。
总权值最小的那一棵，是最小生成树。
割性质：任何一刀切下去，最便宜的跨界边一定可以要。
Prim 守着树往外长，Kruskal 排好队挨个试。
```

复杂度上的取舍：

```text
稠密图 → Prim 朴素 O(n²)
稀疏图 → Kruskal O(e log e)
```

还有那个最容易被坑的结论：

```text
MST 让全网总造价最小，不保证两点之间最短路最短。
```

下一篇换个目标：不再问"怎么连最省"，而是问"从 A 到 B 怎么走最快"。

这两个问题的答案，经常不是同一棵树。

```text
数据结构系统讲解 13：最短路径：Dijkstra、Floyd、Bellman-Ford
```

那一篇会回答：

```text
边权有负数时，为什么 Dijkstra 会算错？
Floyd 的三重循环，为什么中间点必须放最外层？
五个点、十条边，手算一遍三条最短路径要多久？
```
