> **读这篇之前，你只需要知道**：队列是"先进先出"的表，从队尾进、从队头出；栈是"后进先出"的表，只在同一端进出；递归是函数自己调用自己，返回时按"最后进去的最先出来"的顺序退栈。
> **这篇讲什么**：拿到一张图，怎么从某个点出发，把所有能到的点都走一遍、每个点只走一次，以及"先走宽的"和"先走深的"两种走法各有什么本事。
> **一个类比**：走迷宫。BFS 像水漫灌——从入口开始，一圈一圈往外淹，先淹到的格子一定离入口最近；DFS 像一个人贴着右手边的墙一直走，走到死胡同才退回来换一条岔路。


一个网页上有五个链接，你点了其中一个，想看看能翻到多少页面。

写了个递归函数：顺着链接往下点，点过的再点一次也没关系。

运行结果：栈溢出。

为什么？

因为页面 A 链到 B，B 又链回 A。

函数 A 调 B，B 调 A，A 又调 B，永远退不出来。

**问题不在递归，在于"没有记住哪些页面已经看过"。**

加一个布尔数组，看过就标 1，进门先查这一位。

一行改动，程序从死循环变成正常结束。

```text
遍历 = 一个"我有没有来过"的标记 + 一条"接下来去哪"的路线。
```

标记保证"每个点只走一次"，路线决定"先走哪、后走哪"。

路线用队列，就是广度优先；路线用栈，就是深度优先。

两种走法，代码只差几行，本事完全不同。

## 1. 存好了，怎么"走过去"

先说没有遍历会怎样。

10 篇把图存进了内存，邻接矩阵也好、邻接表也好，那只是一堆数字。

存着不用，等于没存。

关于图的问题，绝大多数都要靠"走一遍"来回答：

```text
这个图连通吗？有几个连通分量？
从 A 到 F 有没有路？最短要几步？
图里有没有环？
哪些点从某个源点根本到不了？
```

这些问题，一个一个手推可以，顶点一多就不行了。

而"走一遍"这件事，本质上只有两个要求：

```text
第一，能到的都要到（完备性）。
第二，每个点只处理一次（终止性）。
```

第一条决定了"必须顺着边扩展"，第二条决定了"必须记下来过没有"。

**图的遍历（graph traversal）**：从某个顶点出发，沿着边访问图中所有可达的顶点，且每个顶点只访问一次。

注意"可达"两个字。

图不连通时，一次遍历只能走完一个连通分量。

要把整张图走完，得在外面套一层循环，挨个检查"还有谁没被访问过"。

## 2. 最小模型：一个标记数组 + 一个容器

先说没有"标记数组"会怎样。

开头那个死循环就是答案：A→B→A→B，永远走不完。

或者更隐蔽一点：程序不崩，但同一个点被处理了十次，结果全错。

标记数组是遍历的第一块基石。

```text
visited[n]：visited[i] = 1 表示顶点 i 已经访问过
```

第二块基石是一个容器，用来存"已经发现、但还没展开"的顶点。

```text
BFS 用队列（queue）：先进先出，先发现的先展开。
DFS 用栈（stack） ：后进先出，后发现的先展开。
```

于是两种遍历的骨架几乎一样：

```text
把起点放进容器，标记已访问
while (容器不空) {
    取出一个顶点 v
    对 v 的每个邻居 w {
        if (w 没访问过) { 标记 w；把 w 放进容器 }
    }
}
```

差别只在一句"取出一个顶点"：

```text
队列取出的是"最早进去的" → 一层一层往外扩 → BFS
栈取出的是"最近进去的"   → 一条道走到黑 → DFS
```

**这两行字的差别，就是这一篇的全部内容。**

有一处细节必须一开始就定下来：**标记是在"放入容器时"做，还是"取出时"做？**

答案是"放入时"。

如果等取出时才标记，同一个顶点可能被多个邻居各放一次，队列里出现重复，虽然结果还对，但会做无用功，甚至在某些图上把复杂度拖到 O(n·e)。

后面写代码时会再强调一次。

## 3. 走一遍：BFS 的队列变化

先说没有这一步走查会怎样。

BFS 的代码不到二十行，但"队列里到底有谁"这件事，光看代码想不清楚。

考场上要你写"BFS 序列"，凭感觉写，十有八九错在"某个点该不该入队"。

拿 10 篇那张 5 个顶点的无向图。

```text
顶点：1 2 3 4 5
边  ：(1,2) (1,4) (2,3) (2,5) (3,4) (3,5) (4,5)
```

邻接表按邻接点下标从小到大排：

```text
1 → 2 → 4
2 → 1 → 3 → 5
3 → 2 → 4 → 5
4 → 1 → 3 → 5
5 → 2 → 3 → 4
```

从 1 出发。

**第一步**：访问 1，标记 1，1 入队。

```text
输出：1
队列：[1]
```

**第二步**：1 出队，看它的邻居 2 和 4。

两个都没访问过，依次标记、入队。

```text
输出：1 2 4
队列：[2, 4]
```

**第三步**：2 出队，看它的邻居 1、3、5。

1 已访问，跳过；3 没访问，入队；5 没访问，入队。

```text
输出：1 2 4 3 5
队列：[4, 3, 5]
```

**第四步**：4 出队，邻居 1、3、5 全都访问过了。

```text
输出：1 2 4 3 5
队列：[3, 5]
```

**第五步**：3 出队，邻居 2、4、5 全都访问过了。

```text
队列：[5]
```

**第六步**：5 出队，邻居 2、3、4 全都访问过了。

```text
队列：[]
```

结束。

BFS 序列：

```text
1 → 2 → 4 → 3 → 5
```

再按"层"看一遍，会更清楚：

```text
第 0 层：1
第 1 层：2, 4      （1 的两个邻居）
第 2 层：3, 5      （2 的邻居里没访问过的：3、5）
```

**每一层到起点的边数，正好等于层号。**

1 到 1 是 0 步，1 到 2 是 1 步，1 到 3 是 2 步（1→2→3）。

这就是 BFS 能求最短路的根源，第 6 节展开。

还有一个容易忽略的点：**BFS 序列不是唯一的。**

如果把 1 的链表改成 `4 → 2`，序列就变成 `1 4 2 3 5`（这里 4 的邻居里 3、5 先入队）。

所以考题要么给定邻接表，要么给定"按编号从小到大"的约定。

没给约定又只给一个"标准答案"，那题本身就有问题。

## 4. 走一遍：DFS 的递归轨迹

先说没有这一步走查会怎样。

DFS 的代码比 BFS 还短，但"回溯到哪里、下一条边是哪条"最容易记错。

递归版的执行过程，等价于"沿着一条路走到底，走不动就退一步"。

还是那张图，还是从 1 出发，邻接顺序不变。

**第一步**：访问 1，从 1 的第一条边走向 2。

```text
输出：1
栈（调用栈）：[1]
```

**第二步**：访问 2，从 2 的第一条边走向 1。

1 已访问，跳过，看下一条 → 3。

```text
输出：1 2
栈：[1, 2]
```

**第三步**：访问 3，从 3 的第一条边走向 2。

2 已访问，跳过，看下一条 → 4。

```text
输出：1 2 3
栈：[1, 2, 3]
```

**第四步**：访问 4，从 4 的第一条边走向 1。

1 已访问，跳过；看下一条 → 3，已访问，跳过；看下一条 → 5。

```text
输出：1 2 3 4
栈：[1, 2, 3, 4]
```

**第五步**：访问 5，邻居 2、3、4 全都访问过了。

5 的邻居处理完，`dfs(5)` 返回，退回到 4。

```text
输出：1 2 3 4 5
栈：[1, 2, 3, 4]
```

**第六步**：回到 4，4 的邻居已经全部看完，`dfs(4)` 返回，退回到 3。

3 的邻居是 2、4、5，也已全部访问，`dfs(3)` 返回，退回到 2。

2 的邻居 1、3、5 全部访问，`dfs(2)` 返回，退回到 1。

1 的邻居是 2、4，都已访问，`dfs(1)` 返回。

```text
栈：[]
```

DFS 序列：

```text
1 → 2 → 3 → 4 → 5
```

和 BFS 的 `1 2 4 3 5` 一比，第 3、4 位换了位置。

为什么会换？

因为 BFS 是"把 1 的所有邻居 2、4 都先排进队"，而 DFS 是"抓住 2 就不放，一直钻到 5 才回头"。

**同一张图、同一个起点，路线不同，序列就不同。**

这也解释了为什么"给一个 BFS 序列，问图长什么样"这种题，答案一般不唯一。

## 5. 同一个图，为什么两个序列不同

先说没有这一节会怎样。

很多人以为 BFS 和 DFS 是"两个算法"，其实它们只差一个容器的取出规则。

把这点看透，很多题不用背。

把两种取法画在一起：

```text
容器是队列 [a, b, c]：
  取出 a → 得到 a，剩下 [b, c]     先进先出，最老的先展开

容器是栈 [a, b, c]（c 在栈顶）：
  取出 c → 得到 c，剩下 [a, b]     后进先出，最新的先展开
```

BFS 的"先进先出"造成一个滚雪球效应：

第 0 层的点先全部展开，它们的孩子（第 1 层）全部排到队尾；等第 0 层处理完，才开始处理第 1 层。

于是序列天然按"层"排列。

DFS 的"后进先出"造成一个钻探效应：

刚发现的点立刻被展开，它的孩子又立刻被展开，一层套一层，直到没有新点才回头。

于是序列天然是一条"深入到底再回退"的轨迹。

**再看一个更小的例子，把差别放大。**

```text
     1
   / | \
  2  3  4
  |
  5
```

从 1 出发。

BFS：1 → 2 → 3 → 4 → 5。

DFS（按 2、3、4 的顺序）：1 → 2 → 5 → 3 → 4。

```text
BFS 把"同一层的 2、3、4"挨在一起；
DFS 把"一条链上的 1、2、5"挨在一起。
```

**BFS 的序列反映"距离"，DFS 的序列反映"血缘"。**

这句话对做题很有用：

看到题目问"最短几步"，想 BFS；问"能不能走通""有没有环"，想 DFS。

## 6. 拆开看之一：BFS 为什么能求无权图最短路

先说没有这条性质会怎样。

求"从 A 到 F 最少走几条边"，最容易想到的办法是枚举所有路径，取最短。

路径的条数是指数级的，顶点一多就跑不动。

BFS 用一层一层的顺序，把这个指数问题变成线性问题。

理由只有一句话：

```text
BFS 是按"到起点的边数"从小到大访问顶点的。
```

严格说，是归纳法：

```text
第 0 层只有起点，距离 0，就是最小。
假设第 0 到第 k 层的距离都已经是最短的。
那么第 k+1 层的顶点，一定是从第 k 层某点走一条边得到的，
所以它的距离 ≤ k+1。
又因为它在第 k 层之前从没被访问过（否则早就进队了），
所以它的距离不可能 < k+1。
于是恰好等于 k+1。
```

结论：

```text
BFS 中，顶点第一次被访问时的层号 = 从起点到它的最少边数。
```

拿前面那张 5 点图核对：

```text
1 在第 0 层，距离 0
2、4 在第 1 层，距离 1（1→2、1→4）
3、5 在第 2 层，距离 2（1→2→3、1→2→5）
```

手查一下 1 到 5：`1→2→5` 是 2 步，`1→4→5` 也是 2 步，没有 1 步的路（1 和 5 之间没有边）。

对了。

**这条性质只在"无权图"或"边权全相等"时成立。**

边权不相等时，"步数最少"和"代价最小"不是一回事。

那时候要换成按边权扩展，也就是 Dijkstra（13 篇）。

这是 408 最爱设的一个坑：

```text
"BFS 能求最短路径" —— 对，但只在无权图上。
"BFS 能求最小代价路径" —— 错，那要靠 Dijkstra。
```

如果只需要"每个顶点到起点的边数"，BFS 时可以顺手记一个 `dist[]` 数组：

```c
dist[start] = 0;
/* 展开 v 的邻居 w 时 */
dist[w] = dist[v] + 1;
```

一行代码，最短路长度就全有了。

**如果还要把路径本身打印出来，再加一个 `prev[]` 数组。**

```c
int dist[MAXV], prev_[MAXV];

void BFS_Path(MGraph *G, int s)
{
    int queue[MAXV], front = 0, rear = 0;
    for (int i = 0; i < G->n; i++) {
        dist[i] = -1;
        prev_[i] = -1;
    }
    dist[s] = 0;
    queue[rear++] = s;
    while (front < rear) {
        int u = queue[front++];
        for (int w = 0; w < G->n; w++) {
            if (G->edge[u][w] && dist[w] == -1) {
                dist[w] = dist[u] + 1;
                prev_[w] = u;            /* 记住"我是从谁那儿发现你的" */
                queue[rear++] = w;
            }
        }
    }
}

/* 打印 s 到 t 的路径：从 t 顺着 prev 倒着走回 s，再反过来输出 */
void PrintPath(int s, int t)
{
    if (dist[t] == -1) { printf("不可达\n"); return; }
    int path[MAXV], k = 0;
    for (int v = t; v != -1; v = prev_[v]) path[k++] = v;
    for (int i = k - 1; i >= 0; i--) printf("%d%s", path[i], i ? " -> " : "\n");
}
```

`dist[]` 用 -1 表示"不可达"，比用 0 好，因为 0 是"起点自己"的合法距离。

`prev[]` 就是 BFS 树的父亲指针，把 `prev` 链倒过来读，就是一条最短路径。

**这里有个容易混的点：`prev[w] = u` 记的是"发现 w 的那个点"，不一定是的唯一路径。**

到 w 的最短路径可能不止一条，BFS 只保证挑到其中一条、而且长度最短。

要枚举所有最短路，那就得换算法了，408 不考。

## 7. 拆开看之二：不连通的图怎么办

先说没有这一层外层循环会怎样。

从 1 出发做一次 BFS，只走完了 1 所在的那个连通分量。

图里其他顶点，程序压根没碰，`visited` 里还是 0。

如果题目问"这个图有几个连通分量"，答案就错成 1。

解决办法是外面套一层循环：

```text
count = 0
for (v = 0; v < n; v++) {
    if (!visited[v]) {
        BFS(v);        /* 或者 DFS(v) */
        count++;       /* 又发现一个新的连通分量 */
    }
}
```

`count` 就是连通分量的个数。

**为什么这个办法一定对？**

因为每次 `BFS(v)` 会走完 v 所在的整个连通分量（能到的全都到了），并且只走这一个分量（走不到别处去）。

所以每调用一次，就恰好"吃掉"一个连通分量。

再看有向图，情况更微妙。

```text
顶点：1 2 3 4 5
弧  ：1→2  1→3  2→4  3→2  4→3     5 是孤立点
```

从 1 出发 BFS：

```text
第 0 层：1
第 1 层：2, 3
第 2 层：4      （2 的出边到 4；3 的出边到 2，已访问）
```

序列 `1 2 3 4`。

DFS 从 1 出发（邻接顺序按弧的输入顺序）：

```text
1 → 2 → 4 → 3
```

到 3 之后，3 的出边指向 2，已访问，退回。

所以 `1 2 4 3`。

外层循环继续扫，发现 5 没访问过，`BFS(5)` 只输出 `5`。

于是整张图走完是 `1 2 3 4 | 5`，有 2 个连通分量。

**注意有向图的"连通分量"要说清是哪种：**

```text
弱连通分量：把方向当无向看，能连通就行 —— 上面这个例子是 1 个
强连通分量：双向都能到达 —— 上面这个例子是 4 个（{1} {2,3,4} 视具体弧而定）
```

具体到 `1→2, 1→3, 2→4, 3→2, 4→3`：

2 能到 4、4 能到 3、3 能到 2，所以 `{2,3,4}` 互相可达，是一个强连通分量。

1 只能出不能进，`{1}` 自己一个。

5 自己一个。

所以强连通分量有 3 个。

**同一个图，"连通分量"数出 2，"强连通分量"数出 3，问法不同答案不同。**

**外层循环还能顺手回答两个问题。**

第一个：每个连通分量有多大？

```c
int compSize[MAXV], compId = 0;

for (int v = 0; v < n; v++) {
    if (!visited[v]) {
        int before = 0, after = 0;
        /* 先数一遍当前 visited 里有多少个 1 */
        for (int i = 0; i < n; i++) before += visited[i];
        BFS(v);
        for (int i = 0; i < n; i++) after += visited[i];
        compSize[compId++] = after - before;   /* 两次之差就是这一趟吃掉的点数 */
    }
}
```

第二个：两个顶点连不连通？

```text
从 a 出发做一次 BFS，看 visited[b] 是不是 1。
```

代价是一次完整的遍历，O(n+e)。

如果这类问题要问很多次（比如问十万对顶点），每次都重跑就太亏了。

一次性做法是：跑一次外层循环，给每个顶点记一个 `compId`。

```text
同一个 compId 的两个顶点，一定连通；不同的一定不连通。
```

这样一次 O(n+e) 预处理，之后每次查询 O(1)。

**这就是"并查集"在图上的一种等价用法**：9 篇的并查集做的正是同一件事，只不过它是"边一条条加进来、集合一个个合并"，而这里是"跑一次遍历、直接打标"。

图是静态的，用遍历打标更省；图是动态加边的，用并查集更省。

**同一件事，两种工具，看数据动不动。**

## 8. 复杂度：O(n²) 与 O(n+e) 是怎么数出来的

先说没有这笔账会怎样。

两种存法都能跑，代码一个字不用改（只要邻接矩阵和邻接表的接口一致）。

但一个 10⁵ 个顶点的图，矩阵版要 10¹⁰ 次操作，表版可能只要 10⁵ 次。

差了五个数量级，不是"慢一点"，是"跑不完"。

**先数邻接表。**

BFS 的循环体做了两件事：

```text
1. 每个顶点入队一次、出队一次      → 共 n 次
2. 每个顶点出队时，扫它的整条邻接链 → 共扫描 Σ deg(v) 个边结点
```

无向图里 `Σ deg(v) = 2e`，有向图里是 `e`。

所以总工作量：

```text
n + 2e（无向）  或  n + e（有向）
= O(n + e)
```

**再数邻接矩阵。**

顶点还是入队出队各一次，共 n 次。

但"扫邻居"这一步变了：矩阵没有链表，只能扫整行。

```text
扫第 v 行：n 个格子，不管 v 有几个邻居
```

n 个顶点各扫一行：

```text
n × n = n²
= O(n²)
```

**差别就在这里：**

```text
邻接表：只扫"真的存在的边"       → 工作量跟 e 走
邻接矩阵：不管有没有边，一格一格看 → 工作量跟 n² 走
```

用具体数字感受一下：n = 1000，e = 2000。

```text
邻接表：1000 + 2×2000 = 5000 次
邻接矩阵：1000 × 1000 = 10⁶ 次
```

差 200 倍。

再看空间：

```text
visited 数组：O(n)
队列/栈     ：最坏 O(n)（所有顶点同时在里面）
DFS 递归栈  ：最坏 O(n)（图退化成一条链时）
```

所以两种遍历的空间都是 O(n)，区别只在时间。

**一个常考的小计算：**

一个 n = 1000、e = 2000 的无向图，用邻接表做 BFS，一共访问多少个边结点？

答案是 `2e = 4000`。

如果题目问"每个顶点的平均度"，那是 `2e/n = 4`。

这两个数很容易混。

## 9. 408 怎么考

先说没有这套题型归纳会怎样。

遍历这一块的题，答案往往是"一串数字"，写错一个位置就全错，靠临场发挥风险太大。

常考的五类：

```text
类型一：给图（或邻接表/邻接矩阵），写出从某点出发的 BFS 或 DFS 序列。
类型二：给 BFS/DFS 序列，问"可能的图"或者"邻接表顺序"。
类型三：问复杂度，或者问"扫了多少个边结点"。
类型四：数连通分量、判断连通性。
类型五：画 BFS 树 / DFS 树，问树高、问某个点的父结点。
```

例题一（自拟）：无向图，顶点 1–6，边为 `(1,2) (1,3) (2,4) (3,4) (4,5) (5,6)`，各邻接表按编号升序，写出从 1 出发的 BFS 序列与 DFS 序列。

先把邻接表写全：

```text
1 → 2 → 3
2 → 1 → 4
3 → 1 → 4
4 → 2 → 3 → 5
5 → 4 → 6
6 → 5
```

BFS：

```text
起点 1 入队
出 1：邻居 2、3 入队        → 1 2 3
出 2：邻居 1 已访问，4 入队  → 1 2 3 4
出 3：邻居 1、4 都已访问
出 4：邻居 2、3 已访问，5 入队 → 1 2 3 4 5
出 5：邻居 4 已访问，6 入队   → 1 2 3 4 5 6
出 6：邻居 5 已访问
```

BFS 序列：`1 2 3 4 5 6`。

DFS：

```text
1 → 2（1 的第一条边）
2 → 1 已访问，转 4
4 → 2 已访问，转 3
3 → 1 已访问，4 已访问，退回 4
4 → 3 已访问，转 5
5 → 4 已访问，转 6
6 → 5 已访问，退回
```

DFS 序列：`1 2 4 3 5 6`。

这道题恰好显示了两者的差别：BFS 是 `1 2 3 4 5 6`，DFS 是 `1 2 4 3 5 6`。

第 3、4 位换了。

例题二（自拟）：上面那张图，BFS 树的树高是多少？从 1 到 6 的最短路径要几条边？

BFS 树的边是"发现新顶点时用的那条边"：

```text
1→2, 1→3, 2→4, 4→5, 5→6
```

树如下：

```text
      1
     / \
    2   3
    |
    4
    |
    5
    |
    6
```

树高（从根到最深叶子的边数）= 4。

从 1 到 6 的最短路径：`1→2→4→5→6`，4 条边。

**BFS 树的高度，就是所有顶点到根的最大最短距离。**

两者必然相等，这是可以互相验算的。

例题三（自拟）：一个 n = 500、e = 1200 的有向图，用邻接矩阵做 DFS，时间复杂度是多少？用邻接表呢？

```text
矩阵：O(n²) = 250000 次基本操作
邻接表：O(n + e) = 500 + 1200 = 1700 次
```

差 147 倍。

注意有向图的邻接表是 `n + e`，不是 `n + 2e`。

三个高频陷阱：

```text
陷阱 1：把 BFS 当作"能求最小权路径"。只有无权图才对。
陷阱 2：只调一次遍历就宣布图连通。漏了外层循环，连通分量会被低估。
陷阱 3：DFS 非递归版"出栈时才标记"，导致同一顶点重复入栈。
```

## 10. 写代码：BFS、DFS 递归、DFS 非递归

先说没有代码落地会怎样。

手算序列是一回事，写成能跑的代码是另一回事。

边界条件（空图、单点图、起点越界）不处理，程序在某个用例上就崩了。

BFS，用数组模拟队列：

```c
#define MAXV 100
int visited[MAXV];

/* 邻接矩阵版 BFS，从 v 出发 */
void BFS(MGraph *G, int v)
{
    int queue[MAXV], front = 0, rear = 0;
    printf("%d ", v);
    visited[v] = 1;              /* 入队前就标记 */
    queue[rear++] = v;           /* 入队 */
    while (front < rear) {
        int u = queue[front++];  /* 出队 */
        for (int w = 0; w < G->n; w++) {
            if (G->edge[u][w] && !visited[w]) {
                printf("%d ", w);
                visited[w] = 1;      /* 关键：标记在入队时 */
                queue[rear++] = w;
            }
        }
    }
}
```

如果把 `visited[w] = 1` 挪到出队之后，再看这一行，会发生什么？

同一层的两个顶点可能都发现同一个尚未标记的邻居，各放一次。

队列里就出现重复，虽然结果序列还对，但队列长度可能爆到 e 级别。

**所以标记必须和入队同步。**

DFS 递归版：

```c
void DFS(MGraph *G, int v)
{
    printf("%d ", v);
    visited[v] = 1;
    for (int w = 0; w < G->n; w++)
        if (G->edge[v][w] && !visited[w])
            DFS(G, w);
}
```

递归版的代码只有五行，和 BFS 的骨架几乎一样，只是"取下一个"变成了"立刻递归下去"。

递归栈的深度最坏是 n（图退化成一条链时）。

n = 10⁵ 时递归会爆栈，工程上要改成显式栈。

DFS 非递归版：

```c
void DFSNonRec(MGraph *G, int v)
{
    int stack[MAXV], top = -1;
    printf("%d ", v);
    visited[v] = 1;
    stack[++top] = v;                 /* 压栈时打印并标记 */
    while (top >= 0) {
        int u = stack[top];           /* 只看栈顶，先不弹 */
        int found = 0;
        for (int w = 0; w < G->n; w++) {
            if (G->edge[u][w] && !visited[w]) {
                printf("%d ", w);
                visited[w] = 1;
                stack[++top] = w;     /* 压入一个就跳出，模拟"立刻深入" */
                found = 1;
                break;
            }
        }
        if (!found) top--;            /* 没有新邻居了，才真正弹出，模拟"回溯" */
    }
}
```

这段代码有个要害：**栈顶元素不立刻弹，而是"找到一个新邻居就压栈并跳出循环"。**

如果写成"弹出 u，然后把 u 的所有邻居压栈"，得到的序列就不是 DFS 了，而是一种两者都不是的混合序。

为什么？

因为那样会把 u 的所有邻居同时压进去，然后先处理最后一个，处理完它的整棵子树，再回来处理倒数第二个。

表面上看也是"深入到底再回头"，但入栈的顺序和递归版相反，序列会反过来。

**要模拟递归，就必须"一次只深入一个"。**

一张表看清三个版本：

```text
BFS         队列，一层一层，序列按距离排
DFS 递归    调用栈，一条道走到黑，代码最短
DFS 非递归  显式栈，"找到新点就压栈并暂停"，模拟递归
```

## 11. 两种遍历的对比与选择

先说没有这个对比会怎样。

"什么时候用 BFS、什么时候用 DFS"是选择题里的高频问法。

答"都可以"不得分，答错方向也不得分。

按用途分：

```text
要"最少几步"           → BFS（仅限无权图）
要"能不能到达"         → 都行
要"数连通分量"         → 都行，加外层循环
要"判有向图有无环"     → DFS（用三色标记）
要"求拓扑序"           → DFS 或 BFS（入度法），14 篇讲
要"找一条路径"         → DFS 顺手
要"内存省"             → BFS 队列最坏 O(n)，DFS 递归也是 O(n)，打平
```

按图的特点分：

```text
图很宽（分支多、层数少）→ BFS 队列会很大，DFS 更省内存
图很深（层数多、分支少）→ DFS 递归会很深，BFS 更安全
```

按实现难度分：

```text
BFS：一个队列，不会写错
DFS：递归三行，但要小心爆栈；非递归要小心"弹出时机"
```

**空间上的差别，取决于图的形状，不是固定的一边赢。**

看两个极端。

星型图：中心点连 n−1 个叶子。

```text
       2   3   4
        \  |  /
    1 ——─ 中心 ——─ 5
        /  |  \
       6   7   8
```

从中心出发做 BFS：第 1 层就把 n−1 个叶子全部塞进队列。

```text
队列峰值：n−1
DFS 递归深度：2（中心 → 任意叶子 → 返回）
```

一条链：1 — 2 — 3 — … — n。

```text
队列峰值：1（每次只有一个点在里面）
DFS 递归深度：n（一口气钻到底）
```

**所以"BFS 更省内存"和"DFS 更省内存"都能被举出反例。**

正确的说法是：

```text
图很宽（分支多）→ BFS 队列大，DFS 深度小
图很深（链很长）→ BFS 队列小，DFS 深度大
```

408 的选择题如果问"哪个更省空间"，标准答案是"不一定，看图的形状"。

**DFS 判环的三色标记，值得单独说一句。**
```text
白色：还没访问
灰色：正在访问（在当前的递归路径上）
黑色：访问完了（它的所有后代都处理完了）
```

规则：DFS 时如果遇到一个**灰色**的邻居，说明找到了一个环。

因为灰色意味着"这个点还在当前这条路径上，我却从它后面又走回了它"。

遇到黑色邻居不算环，那只是走到了已经处理完的分支。

```c
int color[MAXV];   /* 0 白，1 灰，2 黑 */

int HasCycle(ALGraph *G, int u)
{
    color[u] = 1;                       /* 进门前涂灰 */
    for (ArcNode *p = G->vertices[u].firstarc; p; p = p->nextarc) {
        int w = p->adjvex;
        if (color[w] == 1) return 1;    /* 撞到灰色 → 有环 */
        if (color[w] == 0 && HasCycle(G, w)) return 1;
    }
    color[u] = 2;                       /* 出门后涂黑 */
    return 0;
}
```

**只有两种颜色的 DFS 判不了有向图的环。**

因为白色只区分"来过没来过"，分不清"还在路上"和"已经走完"。

无向图可以用"记录父结点"的简化版：遇到一个已访问且不是父结点的邻居，就是环。

有向图必须三色。

## 12. 走一遍：8 个顶点的图，两棵树

先说没有这个大例子会怎样。

前面两个例子都太小，BFS 和 DFS 的差别只体现为"中间两位换了个位置"。

换一个稍大的图，两者的树高会差出一倍，差别一眼就看出来。

无向图，8 个顶点，9 条边：

```text
边：(1,2) (1,5) (2,3) (2,6) (3,4) (4,8) (5,6) (6,7) (7,8)
```

邻接表按编号升序：

```text
1 → 2 → 5
2 → 1 → 3 → 6
3 → 2 → 4
4 → 3 → 8
5 → 1 → 6
6 → 2 → 5 → 7
7 → 6 → 8
8 → 4 → 7
```

验一下度数：`2+3+2+2+2+3+2+2 = 18 = 2×9`，对了。

**先做 BFS。**

```text
出 1：邻居 2、5 入队              序列：1 2 5
出 2：邻居 1 已访问，3、6 入队     序列：1 2 5 3 6
出 5：邻居 1、6 都已访问
出 3：邻居 2 已访问，4 入队        序列：1 2 5 3 6 4
出 6：邻居 2、5 已访问，7 入队     序列：1 2 5 3 6 4 7
出 4：邻居 3 已访问，8 入队        序列：1 2 5 3 6 4 7 8
出 7：邻居 6 已访问，8 已访问
出 8：邻居 4、7 都已访问
```

BFS 序列：`1 2 5 3 6 4 7 8`。

按层看：

```text
第 0 层：1
第 1 层：2, 5
第 2 层：3, 6      （2 的邻居 3、6）
第 3 层：4, 7      （3 的邻居 4；6 的邻居 7）
第 4 层：8         （4 的邻居 8）
```

BFS 树（用"发现新点时那条边"连起来）：

```text
        1
      /   \
     2     5
    / \
   3   6
   |   |
   4   7
   |
   8
```

从 1 到 8 的最短距离是 4 条边：`1-2-3-4-8`。

另一条同样长的走法是 `1-2-6-7-8`，也是 4 条边。

**再对同一个图做 DFS。**

```text
1 → 2
2 → 1 已访问，转 3
3 → 2 已访问，转 4
4 → 3 已访问，转 8
8 → 4 已访问，转 7
7 → 6（7 的邻居是 6、8，8 已访问）
6 → 2 已访问、5 未访问 → 5
5 → 1、6 都已访问，退回
```

DFS 序列：`1 2 3 4 8 7 6 5`。

DFS 树：

```text
1 - 2 - 3 - 4 - 8 - 7 - 6 - 5
```

一条链，7 条边，树高 7。

**放在一起看：**

```text
BFS 序列：1 2 5 3 6 4 7 8    树高 4
DFS 序列：1 2 3 4 8 7 6 5    树高 7
```

同一张图、同一个起点，一个树高 4，一个树高 7。

**BFS 树矮，因为它总是挑"离起点最近的那条路"。**

**DFS 树高，因为它一心往前钻，先撞到底再说。**

两个序列的最后一个顶点都不一样：BFS 最后到 8，DFS 最后到 5。

因为 BFS 是"8 在第 4 层，最后才轮到"，而 DFS 是"5 是整条链的末端，最后才退出"。

最后算一下这一趟的开销。

```text
顶点入队（入栈）次数：8 次
边结点扫描次数：2e = 18 次
合计：26 次

若用邻接矩阵：8 个顶点各扫一行 8 格 = 64 次
```

26 对 64，n 还小，差距不明显。

把 n 换成 10⁴、e 换成 2×10⁴：

```text
邻接表：10⁴ + 4×10⁴ = 5×10⁴ 次
邻接矩阵：10⁸ 次
```

2000 倍的差距。

**再把起点换成 5，看序列会怎么变。**

BFS 从 5 出发：

```text
出 5：邻居 1、6 入队          序列：5 1 6
出 1：邻居 2 入队             序列：5 1 6 2
出 6：邻居 2 已访问，7 入队    序列：5 1 6 2 7
出 2：邻居 3 入队             序列：5 1 6 2 7 3
出 7：邻居 8 入队             序列：5 1 6 2 7 3 8
出 3：邻居 4 入队             序列：5 1 6 2 7 3 8 4
出 8、出 4：都没有新邻居
```

BFS 序列：`5 1 6 2 7 3 8 4`。

DFS 从 5 出发：`5 → 1 → 2 → 3 → 4 → 8 → 7 → 6`。

和从 1 出发的两组序列完全不同。

**所以"BFS 序列"这四个字，必须配上"从哪个点出发、邻接表什么顺序"才唯一。**

考试里如果只写"求 BFS 序列"，一定要默认约定（通常是从编号最小的点出发、邻接点按编号升序）。

自己算的时候，先把这个约定写下来，再动笔。

## 13. 容易混淆的五个点

**第一，BFS 序列和"层次遍历"是一回事吗？**

对树来说是一回事，对图来说要小心。

树没有环，每个点只有一个父亲，所以层序天然唯一。

图有环，一个点可能被多个点"同时发现"，谁先发现它，取决于邻接表的顺序。

所以图的 BFS 序列依赖邻接顺序，树的层序不依赖。

**第二，DFS 序列唯一吗？**

不唯一。换起点、换邻接顺序，序列都会变。

考题如果只给一个图就问"DFS 序列"，标准答案通常默认"按编号升序"这个约定。

**第三，visited 数组要不要清零？**

一次遍历结束后必须清零，否则第二次遍历会认为"全都访问过了"，什么都不输出。

但如果外层循环是在同一次"数连通分量"里用的，就**不能**清零——那正是靠 `visited` 记住"这个分量吃过了"。

**第四，BFS 树和"最短路径树"是一回事吗？**

在无权图里是一回事。

在带权图里不是：BFS 树按边数最少，最短路径树按权值和最小，两者可以完全不同。

**第五，复杂度里的 n 和 e，到底哪个是主角？**

邻接表是 `O(n + e)`，矩阵是 `O(n²)`。

判断哪个更好，看 e 和 n² 谁大。

e 接近 n² 时，两者差不多（矩阵还省了指针开销）；e 远小于 n² 时，表完胜。

### 自检三问

1. 同一张 5 点图，为什么 BFS 给出 `1 2 4 3 5`，DFS 给出 `1 2 3 4 5`？

   答不上来说明还没把"容器取出规则"和"序列形状"连起来。BFS 用队列，先把 1 的两个邻居 2、4 都排进去，所以第 1 层是"2、4"整体；DFS 用栈（递归），抓住 2 就一直往里钻，2 的邻居 3 先进、3 的邻居 4 再进，于是 4 排在 3 后面而不是和 2 并列。

2. 遍历的复杂度，邻接表是 O(n+e)、邻接矩阵是 O(n²)，这个差别是怎么来的？

   答不上来说明没数清"扫邻居"这一步。邻接表里每个顶点出队时只扫自己那条链，所有链加起来是 2e（无向）或 e（有向），加上 n 次入队出队就是 O(n+e)；邻接矩阵没有链，只能扫整行 n 个格子，n 个顶点各扫一次就是 n²。

3. 为什么 BFS 能求无权图的最短路，却不能求带权图的最小代价？

   答不上来说明把"步数"和"代价"当成了同一个东西。BFS 按"边数"分层，第 k 层就是"恰好 k 条边能到"，这在无权图里就是最短；一旦边有权，"2 条边但权值和 100"可能比"3 条边但权值和 6"更贵，按层扩展就失去了意义，得改用按代价扩展的 Dijkstra。

## 14. 小结

回到开头那个死循环。

A 链到 B，B 链回 A，递归函数绕不出来。

加一个 `visited` 数组，进门先查、查到就返回，程序立刻正常。

**遍历的全部秘密，就是这一行标记。**

在这个基础上，换个容器就换一种走法：

```text
队列 → 一层一层 → BFS → 序列按距离排 → 能求无权最短路
栈   → 一条道走到黑 → DFS → 序列按血缘排 → 能判环、能求拓扑序
```

这一篇的六句话，值得抄下来：

```text
标记在入队（入栈）时做，不要在取出时做。
BFS 的第 k 层，就是到起点恰好 k 条边的点。
BFS 树的高度 = 最远点的最短距离。
不连通的图，要在外面套一层循环，每调一次吃掉一个连通分量。
邻接表 O(n+e)，邻接矩阵 O(n²)，差别在"扫不扫空格子"。
有向图判环必须三色，两色不够。
```
