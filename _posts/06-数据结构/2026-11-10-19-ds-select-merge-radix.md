> **读这篇之前，你只需要知道**：一棵完全二叉树可以按层序放进数组，第 i 个结点的左孩子在 2i、右孩子在 2i+1（下标从 1 开始）；"有序表"是已经从小到大排好的数组；一个十进制三位数由百位、十位、个位三个数字组成。
> **这篇讲什么**：三种不用"相邻比较交换"的排法——每次挑出最小的、把两段有序的合成一段、按每一位数字分桶再收回来。
> **一个类比**：一摞试卷要按分数排，可以每次抽出最低分放一摞（选择）；可以先把两摞各自排好的合起来（归并）；也可以先按个位分成十堆、按顺序叠好，再按十位分成十堆，再按百位分一次（基数）。

先看一个数。

排 100 万个元素，快排平均要做大约 2000 万次比较。

堆排序也是 2000 万次左右。

归并排序还是 2000 万次左右。

三者的比较次数几乎一样。

但实测下来，堆排序常常比快排慢两到三倍。

为什么？

因为它每次比较要跳到数组的另一处去取数：`a[2i]`、`a[2i+1]`。

跳跃访问，缓存不命中。

而快排是顺序扫过去的，缓存几乎全中。

这个例子说明一件事：

```text
比较次数只是账本上的一个数，
真正决定快慢的，还有"数据放在哪儿、怎么被访问"。
```

**这就是为什么背熟了复杂度表，还是答不对"哪个更快"的题。**

这一篇讲的三种排序，正好代表三条不同路线：

```text
选择类（含堆）：先找出最值，再放到该在的位置。
归并类：先让局部有序，再合并成大段有序。
基数类：根本不做关键字比较，按"位"分桶。
```

三条路线的复杂度分别是 O(n²)、O(n log n)、O(d(n+r))。

最后一条打破了"比较排序至少 n log n 次"的下界，值得单独看。

## 1. 从"每次挑出最小的"说起

这一节先问：如果只允许一个动作——"在剩下的人里找出最矮的"，能不能把队排好？

能，而且过程最简单。

```text
第一轮：在全体里找最小的，和第 1 个位置交换。
第二轮：在剩下 n−1 个里找最小的，和第 2 个位置交换。
…
第 n−1 轮：剩两个，找出小的，交换。结束。
```

这就是**简单选择排序（simple selection sort）**。

它的思路和插入排序正好相反。

插入排序是"拿到一个数，去找它该在的位置"。

选择排序是"确定一个位置，去找该放在这儿的数"。

前者移动的是元素，后者移动的是"目标位置"。

先把词定清楚。

**选择排序（selection sort）**：每一趟从待排区里选出关键字最小的元素，放到待排区的最前面。

**待排区**：还没排好的那一段，随着趟数增加不断缩短。

**有序区**：已经排好的那一段，每趟增加一个元素。

这个"有序区逐步扩大、待排区逐步缩小"的模式，是所有选择类排序的共同骨架。

堆排序也是这个骨架，只是它把"找最小值"从 O(n) 优化到了 O(log n)。

## 2. 简单选择排序：比较省不了，交换可以省

这一节的问题：选择排序的比较次数是 n(n−1)/2，和冒泡一样多，那它凭什么比冒泡快？

凭交换次数。

冒泡每发现一对逆序就换一次，最多换 n(n−1)/2 次。

选择排序每趟最多换一次，总共最多 n−1 次。

回到第 18 篇那笔账：交换一次是 3 次移动，记录大时极贵。

```text
冒泡：比较 n²/2 次，交换最多 n²/2 次 → 移动约 1.5n² 次
选择：比较 n²/2 次，交换最多 n−1 次  → 移动约 3n 次
```

n = 1000 时，冒泡移动 150 万次，选择移动 3000 次。

差了 500 倍。

所以在大记录场景下，简单选择排序比冒泡实用得多。

这也解释了一个历史事实：早期机器内存小、拷贝贵，"交换次数少"是很硬的优点。

代码：

```c
void select_sort(int a[], int n) {   /* a[0..n-1] */
    for (int i = 0; i < n - 1; i++) {
        int min = i;                       /* 假设 i 是最小 */
        for (int j = i + 1; j < n; j++)
            if (a[j] < a[min]) min = j;    /* 记下更小的下标 */
        if (min != i) {                    /* 一趟最多换一次 */
            int t = a[i]; a[i] = a[min]; a[min] = t;
        }
    }
}
```

`if (min != i)` 这一句可以省掉一次"自己和自己换"。

自己换看起来无害，其实是三次内存写。

数据量大时，这一句能省下不少。

但要注意：省掉它不影响正确性，也不影响稳定性判断。

简单选择排序现在很少单独用来排大规模数据，但它的思想到处都是。

"每轮挑一个最值放到边界上"，这个骨架只要换个"挑最值"的数据结构，就变成了堆排序。

再换个场景，就变成了最短路算法里"每次取距离最小的顶点"。

所以这一节真正要记的不是那几行代码，而是那句"确定一个位置，去找该放在这儿的数"。

它和插入排序的"拿到一个数，去找它该在的位置"，是同一枚硬币的两面。

选择排序还有一条容易被忽略的性质：**它的比较次数与初始序列完全无关**。

不管数据是已经有序、完全逆序，还是随机乱序，它都要比较 n(n−1)/2 次。

这让它成为少数"行为可预测"的排序，也让它在最好情况下依然很慢。

## 3. 简单选择排序逐趟走查

序列：`49, 38, 65, 97, 76, 13, 27, 49*`

```text
初始： 49  38  65  97  76  13  27  49*
```

第 1 趟，在全部 8 个里找最小：

```text
最小是 13（第 6 位），和第 1 位交换。
结果： 13 | 38  65  97  76  49  27  49*
```

第 2 趟，在 2 到 8 位里找最小：

```text
最小是 27（第 7 位），和第 2 位交换。
结果： 13  27 | 65  97  76  49  38  49*
```

第 3 趟，在 3 到 8 位里找最小：

```text
最小是 38（第 7 位），和第 3 位交换。
结果： 13  27  38 | 97  76  49  65  49*
```

第 4 趟：

```text
最小是 49（第 6 位），和第 4 位交换。
结果： 13  27  38  49 | 76  97  65  49*
```

第 5 趟：

```text
最小是 49*（第 8 位），和第 5 位交换。
结果： 13  27  38  49  49* | 97  65  76
```

第 6 趟：

```text
最小是 65（第 7 位），和第 6 位交换。
结果： 13  27  38  49  49*  65 | 97  76
```

第 7 趟：

```text
最小是 76（第 8 位），和第 7 位交换。
结果： 13  27  38  49  49*  65  76  97
```

排完。

比较次数：7+6+5+4+3+2+1 = 28 = n(n−1)/2。

交换次数：7 次，正好 n−1 次（每次都发生了交换）。

### 3.1 为什么它不稳定

看第 5 趟。

`49` 在第 4 位，`49*` 在第 8 位，此时待排区是 `76, 97, 65, 49*`。

最小的是 49*，它和第 5 位的 76 交换。

交换之后 `49*` 到了第 5 位，`49` 还在第 4 位。

这一次相对次序没变。

但换个数据就会变。

经典的例子是 `[2a, 2b, 1]`：

```text
第 1 趟：最小是 1（第 3 位），和第 1 位的 2a 交换。
结果： 1, 2b, 2a
```

2b 到了 2a 前面，次序反了。

**不稳定的根源是"跨越多个位置的一次交换"。**

被跳过的那一段里如果有相等元素，次序就可能被打乱。

冒泡只换相邻两个，所以稳定；选择一跳好几位，所以不稳定。

这条判断法在第 18 篇已经用过一次，对堆排序也成立。

## 4. 堆：为什么一棵树可以躺在数组里

这一节先问：简单选择排序每趟找最小要 O(n) 次比较，n 趟就是 O(n²)。

能不能让"找最小"变成 O(log n)？

能，前提是数据按一种特殊的方式组织起来。

**堆（heap）**：一棵完全二叉树，每个结点的关键字都不小于（或不大于）它的两个孩子。

这里有两个词要先解释。

**完全二叉树（complete binary tree）**：除了最后一层，每层都填满，最后一层的结点全部靠左连续排列。

这个"靠左连续"很关键，因为它保证树的形状是唯一的，节点之间没有空隙。

**大根堆（max-heap）**：每个结点都 ≥ 自己的孩子，所以根是全体最大的。

**小根堆（min-heap）**：每个结点都 ≤ 自己的孩子，所以根是全体最小的。

堆排序要用大根堆（要反复取最大值放到末尾）。

但要注意：**堆只保证"父 ≥ 子"，不保证"左 ≥ 右"。**

所以堆不是二叉排序树，中序遍历它得不到有序序列。

这是最容易混的一点。

顺带回答一个常被问的问题：为什么不用二叉排序树来排序？

因为二叉排序树的形态取决于插入顺序，插入有序数据时会退化成一条链，此时取最小值要 O(n)。

堆的形态被"完全二叉树"这个约束钉死了，不管数据怎么来，树高永远是 ⌊log₂ n⌋ + 1。

**"形态固定"才是堆能给出最坏 O(n log n) 保证的根本原因。**

这也解释了为什么堆适合做优先队列：插入和取最值都是"沿一条路径走树高"，与数据分布无关。

### 4.1 一棵树怎么躺进数组

堆的形状既然是"靠左连续"的完全二叉树，就可以按层序（从上到下、从左到右）依次放进数组。

因为形状固定，父子关系和下标之间就有了固定公式。

下标从 1 开始时最整齐：

```text
结点 i 的左孩子：2i
结点 i 的右孩子：2i + 1
结点 i 的父结点：⌊i / 2⌋
```

验证一下：i = 1 是根，左孩子 2、右孩子 3。

i = 2 的左孩子 4、右孩子 5。

i = 3 的左孩子 6、右孩子 7。

和层序排列完全对得上。

下标从 0 开始时，公式要挪一位：

```text
结点 i 的左孩子：2i + 1
结点 i 的右孩子：2i + 2
结点 i 的父结点：⌊(i − 1) / 2⌋
```

C 语言的数组从 0 开始，所以写代码时用这一组。

408 的教材习惯用 1 开始，答题时看清题目给的下标。

还有一条重要推论：**有 n 个结点的完全二叉树，叶子结点是后 ⌈n/2⌉ 个。**

等价地说，第一个叶子结点的下标是 ⌊n/2⌋ + 1（1 开始），或者说最后一个非叶结点是 ⌊n/2⌋。

这条推论在建堆时直接用到：只需要从 ⌊n/2⌋ 往前调整，后面的都是叶子，叶子本身就是合法的堆。

## 5. 向下调整与建堆

这一节的问题：如果根的某个孩子比根大，怎么修？

做法很朴素：把根和"较大的那个孩子"交换，然后继续检查被换下去的位置。

一直换到不用换为止。

**向下调整（sift down，也叫下沉）**：让一个结点沿着"较大的孩子"这条路一路往下换，直到它比两个孩子都大，或者沉到叶子。

为什么挑"较大的孩子"换？

因为换完之后，新的父结点要同时 ≥ 两个孩子。

如果跟较小的孩子换，那较大的孩子仍然比新父大，堆还是坏的。

这一步是堆排序所有正确性的基础，值得慢慢走一遍。

看一个具体例子。

数组 `[49, 97, 65, 49*, 76, 13, 27, 38]`，下标 1 到 8。

现在 1 号位是 49，它的孩子是 97（2 号）和 65（3 号）。

49 < 97，违反了大根堆。

调整过程：

```text
比较孩子：97 与 65，大的 97（2 号）。
49 < 97，交换 1 号和 2 号。
数组：97, 49, 65, 49*, 76, 13, 27, 38
继续看 2 号位：它的孩子是 49*（4 号）和 76（5 号）。
比较孩子：49* 与 76，大的 76（5 号）。
49 < 76，交换 2 号和 5 号。
数组：97, 76, 65, 49*, 49, 13, 27, 38
继续看 5 号位：它的孩子是 10、11 号，超出范围，是叶子，停。
```

调整完，整棵树合法了。

检查 2 号位：76 ≥ 49*（4 号）和 49（5 号），成立。

检查 1 号位：97 ≥ 76 和 65，成立。

一次调整走了 2 步，每步做 2 次比较（先比两个孩子，再和孩子比父）。

所以单次调整的比较次数最多是 2 × 树高 = 2⌈log₂ n⌉。

代码：

```c
/* 对 a[0..n-1] 中的结点 i 做向下调整，堆的规模是 n */
void sift_down(int a[], int i, int n) {
    while (1) {
        int l = 2 * i + 1;          /* 左孩子 */
        int r = 2 * i + 2;          /* 右孩子 */
        int big = i;                /* 假设自己是最大的 */
        if (l < n && a[l] > a[big]) big = l;
        if (r < n && a[r] > a[big]) big = r;
        if (big == i) break;        /* 自己最大，堆已合法 */
        int t = a[i]; a[i] = a[big]; a[big] = t;
        i = big;                    /* 继续往下沉 */
    }
}
```

`while (1)` 里的 `i = big` 是关键。

交换之后，原来的结点到了 `big` 位置，要继续从这个位置往下检查。

很多人只换一次就结束，遇到"下沉两层"的情况就错了。

### 5.1 建堆：从最后一个非叶结点往前

这里先问：随便给一个数组，怎么把它变成堆？

最直接的想法是从根开始，一个个调整。

但那样不行。

因为向下调整的前提是"它的左右子树已经是堆"，一上来子树都是乱的，调了也白调。

正确的顺序是从下往上。

```text
从最后一个非叶结点（下标 ⌊n/2⌋，1 开始）开始，往前逐个做向下调整。
一直做到根（1 号位）。
```

为什么这个顺序对？

因为叶子没有孩子，天生是合法的堆。

从最后一个非叶结点往前调，每次调整时，它的左右子树都已经在之前（或本来）是堆了。

于是"前提"就成立。

建堆的复杂度是 O(n)，不是 O(n log n)。

这一点很反直觉，值得算一下。

n 个结点，高度为 h 的结点大约有 n/2^(h+1) 个，每个最多下沉 h 层。

总代价是：

```text
Σ (n/2^(h+1)) × h  ≈  n × Σ (h/2^h)  ≈  n × 2  =  O(n)
```

级数 Σ h/2^h 收敛到 2，所以是线性。

直观地理解：**大部分结点在底层，下沉的距离很短；只有根下沉得远，但根只有一个。**

## 6. 建堆手算

数据：`49, 38, 65, 97, 76, 13, 27, 49*`，n = 8。

放进 1..8 号位，画成完全二叉树：

```text
              49 (1)
            /        \
        38 (2)       65 (3)
        /    \       /    \
    97 (4)  76(5) 13(6)  27(7)
    /
49*(8)
```

最后一个非叶结点是 ⌊8/2⌋ = 4 号（97）。从它开始往前。

**调整 4 号（97）**：

```text
孩子只有 8 号（49*）。
97 ≥ 49*，不用换。
```

**调整 3 号（65）**：

```text
孩子是 6 号（13）和 7 号（27）。
较大的孩子是 27（7 号）。
65 ≥ 27，不用换。
```

**调整 2 号（38）**：

```text
孩子是 4 号（97）和 5 号（76）。
较大的孩子是 97（4 号）。
38 < 97，交换 2 号和 4 号。
数组：49, 97, 65, 38, 76, 13, 27, 49*
继续看 4 号（38）：它的孩子是 8 号（49*）。
38 < 49*，交换 4 号和 8 号。
数组：49, 97, 65, 49*, 76, 13, 27, 38
4 号已经没有孩子（2×4 = 8 > 8？注意 8 号已被换走，8 号是叶子），停。
```

**调整 1 号（49）**：

```text
孩子是 2 号（97）和 3 号（65）。
较大的孩子是 97（2 号）。
49 < 97，交换 1 号和 2 号。
数组：97, 49, 65, 49*, 76, 13, 27, 38
继续看 2 号（49）：孩子是 4 号（49*）和 5 号（76）。
较大的孩子是 76（5 号）。
49 < 76，交换 2 号和 5 号。
数组：97, 76, 65, 49*, 49, 13, 27, 38
继续看 5 号（49）：孩子是 10、11 号，越界，停。
```

建堆完成：

```text
              97 (1)
            /        \
        76 (2)       65 (3)
        /    \       /    \
    49*(4)  49(5) 13(6)  27(7)
    /
38 (8)
```

验证三处：

```text
1 号 97 ≥ 76、65   ✓
2 号 76 ≥ 49*、49  ✓
3 号 65 ≥ 13、27   ✓
4 号 49* ≥ 38       ✓
```

结果：`97, 76, 65, 49*, 49, 13, 27, 38`。

总共做了 4 次向下调整（4、3、2、1 号），比较次数 2+2+4+4 = 12 次。

## 7. 堆排序逐趟走查

堆建好了，接下来怎么排序？

关键的一句话：

**大根堆的根，就是全体最大的元素。**

它该去的位置是数组末尾。

所以每一趟做两件事：

```text
① 把根和当前堆的最后一个元素交换。最大的元素就归位到末尾了。
② 堆的规模减 1（末尾那个已经排好，不再属于堆），对新的根做一次向下调整。
```

重复 n−1 趟。

还是那组数据，从建好的堆开始。

```text
开始： 97  76  65  49* 49  13  27 | 38
（竖线右边是已排好的部分，一开始是空的，最后一个 38 还在堆里）
```

**第 1 趟**：

```text
交换 1 号和 8 号：38 到根，97 归位。
数组：38  76  65  49*  49  13  27 | 97
堆规模变 7，调整 1 号（38）：
  孩子 76、65，大的 76 → 换 → 76  38  65  49*  49  13  27
  看 2 号（38）：孩子 49*、49，大的 49* → 换 → 76  49*  65  38  49  13  27
  看 4 号（38）：孩子是 8 号，超出规模 7，停。
结果：76  49*  65  38  49  13  27 | 97
```

**第 2 趟**：

```text
交换 1 号和 7 号：27 到根，76 归位。
数组：27  49*  65  38  49  13 | 76  97
堆规模 6，调整 1 号（27）：
  孩子 49*、65，大的 65 → 换 → 65  49*  27  38  49  13
  看 3 号（27）：孩子只有 6 号（13）→ 27 ≥ 13，停。
结果：65  49*  27  38  49  13 | 76  97
```

**第 3 趟**：

```text
交换 1 号和 6 号：13 到根，65 归位。
数组：13  49*  27  38  49 | 65  76  97
堆规模 5，调整 1 号（13）：
  孩子 49*、27，大的 49* → 换 → 49*  13  27  38  49
  看 2 号（13）：孩子 38、49，大的 49 → 换 → 49*  49  27  38  13
结果：49*  49  27  38  13 | 65  76  97
```

**第 4 趟**：

```text
交换 1 号和 5 号：13 到根，49* 归位。
数组：13  49  27  38 | 49*  65  76  97
堆规模 4，调整 1 号（13）：
  孩子 49、27，大的 49 → 换 → 49  13  27  38
  看 2 号（13）：孩子 38（4 号）→ 换 → 49  38  27  13
结果：49  38  27  13 | 49*  65  76  97
```

**第 5 趟**：

```text
交换 1 号和 4 号：13 到根，49 归位。
数组：13  38  27 | 49  49*  65  76  97
堆规模 3，调整 1 号（13）：
  孩子 38、27，大的 38 → 换 → 38  13  27
  看 2 号（13）：孩子是 4 号，超出规模 3，停。
结果：38  13  27 | 49  49*  65  76  97
```

**第 6 趟**：

```text
交换 1 号和 3 号：27 到根，38 归位。
数组：27  13 | 38  49  49*  65  76  97
堆规模 2，调整 1 号（27）：孩子 13，27 ≥ 13，不换。
结果：27  13 | 38  49  49*  65  76  97
```

**第 7 趟**：

```text
交换 1 号和 2 号：13 到根，27 归位。堆只剩 1 个元素，不用调整。
结果：13 | 27  38  49  49*  65  76  97
```

最终：`13, 27, 38, 49, 49*, 65, 76, 97`。

和前面几种算法排出来的结果一致。

三件事值得记。

第一，每趟都能确定一个元素的最终位置，而且是**最大值**。

所以堆排序是从后往前填的，和选择排序"从前往后填"正好相反，但本质一样。

第二，每趟的代价是 O(log n)：一次交换加一次向下调整，调整最多走树高。

n−1 趟，总代价 O(n log n)。

第三，初始建堆是 O(n)，比排序部分低一阶，所以整体还是 O(n log n)。

有人会问：要升序排列，为什么用大根堆而不是小根堆？

因为排序时元素是从后往前归位的，末尾放的是当前最大值。

用小根堆的话，堆顶是最小值，它该去的位置是数组开头，而开头已经被更小的值占了。

所以升序用大根堆、降序用小根堆，这是"归位方向"决定的，不是随便选的。

堆排序的关键性质：
```text
时间：最好、平均、最坏都是 O(n log n)。没有退化情况。
空间：O(1)，原地排序。
稳定：不稳定，因为根和末尾的交换是跨距离的。
```

最坏也是 O(n log n)，这是堆排序相对快排的最大优势。

所以需要"最坏情况保证"的场合，用它最稳。

代价是常数大、缓存不友好（父子结点在数组里隔得远）。

## 8. 归并：把两段有序的合成一段

这一节先问：如果两段数据各自已经有序，合成一段有序的需要几次比较？

只需要"各看一个，取小的"。

**归并（merge）**：把两个或多个有序表合并成一个有序表。

**二路归并（2-way merge）**：每次合并两段。

做法是设两个指针，各指向一段的头。

```text
比较两个指针指向的元素，把小的那个抄到结果里，指针后移。
某一段抄完了，把另一段剩下的整体接上。
```

关键性质：**每抄一个元素，最多做 1 次比较。**

所以合并两段总长 n 的数据，最多 n−1 次比较（最后一段会整体接上，不用再比）。

这就是归并排序能做到 O(n log n) 的原因。

如果合并是 O(n²)，总复杂度就上不去了。

还有一个更实际的原因：归并是少数能"在磁盘上做"的排序。

因为合并两段只需要顺序读、顺序写，从头扫到尾，不要求随机访问。

第 20 篇的外部排序正是靠这一点，把 100 GB 的文件切成很多段、各自排好、再一段段合并。

而快排、堆排必须随机访问数组中部的元素，磁盘上做一次随机读是毫秒级，完全不可行。

所以"归并排序要额外空间"这个缺点，在多路合并的场景里反而变成了优点。

举个具体例子。

```text
甲段：12  25  40
乙段：8   30  33
```

合并过程：

```text
比 12 和 8  → 取 8   （乙指针到 30）
比 12 和 30 → 取 12  （甲指针到 25）
比 25 和 30 → 取 25  （甲指针到 40）
比 40 和 30 → 取 30  （乙指针到 33）
比 40 和 33 → 取 33  （乙段空）
甲段剩下 40，整体接上。
结果：8  12  25  30  33  40
```

6 个元素，5 次比较。

注意最后一步"整体接上"没有再比较，这就是"最多 n−1 次"的来源。

代码：

```c
/* 合并 a[low..mid] 和 a[mid+1..high] 到临时数组 tmp，再抄回 a */
void merge(int a[], int tmp[], int low, int mid, int high) {
    int i = low, j = mid + 1, k = low;
    while (i <= mid && j <= high) {
        if (a[i] <= a[j]) tmp[k++] = a[i++];   /* 相等取左边，保证稳定 */
        else              tmp[k++] = a[j++];
    }
    while (i <= mid)  tmp[k++] = a[i++];       /* 甲段剩下的 */
    while (j <= high) tmp[k++] = a[j++];       /* 乙段剩下的 */
    for (k = low; k <= high; k++) a[k] = tmp[k];
}
```

`a[i] <= a[j]` 里的 `<=` 是稳定性的关键。

相等时取左边那段，左边那段的元素本来就在前面，所以相对次序保住了。

如果写成 `<`，相等时取右边，稳定性就没了。

## 9. 二路归并排序逐趟走查

这一节先问：一开始根本没有"两段有序"的数据，怎么开始归并？

答案是：把每个单元素看成一段有序表。

一个元素当然是有序的。

这就是递归的底。

**归并段（run）**：一段内部已经有序的数据。

归并排序的过程，就是让归并段的长度从 1 开始翻倍：1 → 2 → 4 → 8 → …，直到覆盖全长。

每一趟都要把所有相邻的两段合并。

还是那组数据：`49, 38, 65, 97, 76, 13, 27, 49*`

**初始**：8 个长度 1 的归并段。

```text
[49] [38] [65] [97] [76] [13] [27] [49*]
```

**第 1 趟**，两两合并，段长 1 → 2：

```text
[49] 和 [38] 合并 → [38, 49]        比较 1 次
[65] 和 [97] 合并 → [65, 97]        比较 1 次
[76] 和 [13] 合并 → [13, 76]        比较 1 次
[27] 和 [49*] 合并 → [27, 49*]      比较 1 次
结果：38  49  65  97  13  76  27  49*
```

**第 2 趟**，段长 2 → 4：

```text
[38, 49] 和 [65, 97] 合并：
  比 38 与 65 → 38；比 49 与 65 → 49；甲段空，接上 65、97。
  → [38, 49, 65, 97]               比较 2 次

[13, 76] 和 [27, 49*] 合并：
  比 13 与 27 → 13；比 76 与 27 → 27；比 76 与 49* → 49*；乙段空，接上 76。
  → [13, 27, 49*, 76]              比较 3 次

结果：38  49  65  97  13  27  49*  76
```

**第 3 趟**，段长 4 → 8：

```text
[38, 49, 65, 97] 和 [13, 27, 49*, 76] 合并：
  38 与 13 → 13
  38 与 27 → 27
  38 与 49* → 38
  49 与 49* → 49      （相等取左边，稳定）
  65 与 49* → 49*
  65 与 76 → 65
  97 与 76 → 76
  乙段空，接上 97
  → 13  27  38  49  49*  65  76  97    比较 7 次
```

排完。

把三趟的比较次数加起来：4 + 5 + 7 = 16 次。

对照一下：直接插入排序要 22 次，简单选择要 28 次。

归并排序的比较次数最少。

这正是 O(n log n) 的体现：8 个元素，⌈log₂ 8⌉ = 3 趟，每趟最多 n−1 = 7 次，上界 21 次。

实际 16 次，比上界小。

趟数公式要记牢：

```text
二路归并排序的趟数 = ⌈log₂ n⌉
```

n = 8 → 3 趟，n = 1000 → 10 趟，n = 100 万 → 20 趟。

每一趟都要把 n 个元素全部读写一遍，所以总时间 O(n log n)。

空间上需要 O(n) 的临时数组，这是归并排序唯一的短板。

递归写法：

```c
void msort(int a[], int tmp[], int low, int high) {
    if (low >= high) return;              /* 只剩一个元素，天然有序 */
    int mid = (low + high) / 2;
    msort(a, tmp, low, mid);              /* 左半排好 */
    msort(a, tmp, mid + 1, high);         /* 右半排好 */
    merge(a, tmp, low, mid, high);        /* 合并两段 */
}

void merge_sort(int a[], int n) {
    int *tmp = (int *)malloc(n * sizeof(int));
    if (tmp == NULL) return;
    msort(a, tmp, 0, n - 1);
    free(tmp);
}
```

注意 `tmp` 只在最外层申请一次，递归里反复用。

如果每次 `merge` 都 `malloc` 一遍，光申请释放的开销就能拖慢一倍。

归并排序的性质：

```text
时间：最好、平均、最坏都是 O(n log n)。
空间：O(n)，需要临时数组。
稳定：稳定，因为相等时取左边。
```

三个 O(n log n) 的排序里，只有归并是稳定的。

所以"要稳定 + 要最坏保证"的场合，它几乎是唯一选择。

## 10. 基数排序：不比较也能排

这一节先问一个更狠的问题：前面所有算法都在比较关键字，能不能一次都不比？

能，只要关键字是"可以按位拆开"的。

**基数排序（radix sort）**：把关键字看成若干个"位"，从最低位到最高位，每一位做一次"分配 + 收集"。

三个词要先说清。

**基数（radix）**：每一位有多少种取值。十进制数字的基数是 10（0 到 9）。

**分配（distribute）**：按当前位的值，把元素放进对应的桶。

**收集（collect）**：按桶号从小到大，把桶里的元素依次取出来，接成一串。

做法是：

```text
for 每一位（从个位到最高位）:
    按这一位的值，把所有元素分配到 10 个桶里
    按 0 到 9 的顺序，把 10 个桶收集回来
```

为什么从最低位开始？

因为每收集一次，元素就按"低位"有序了。

再按高一位分配时，同一个桶里的元素低位已经有序；收集时从 0 号桶到 9 号桶依次取，就得到"高位优先、低位次之"的顺序。

这个性质叫 **LSD（least significant digit first，最低位优先）**。

它成立的前提是：**分配和收集必须是稳定的**（同一个桶里，先进去的先出来）。

否则上一趟排好的低位顺序会被打乱。

所以"稳定性"在这里不是锦上添花，是算法正确性的必要条件。

### 10.1 三个两位数的小例子

先用小数据看清机制。

序列：`32, 13, 24, 51, 45`

**先按个位分配**：

```text
0 桶：空
1 桶：51
2 桶：32
3 桶：13
4 桶：24
5 桶：45
6-9 桶：空
```

收集（0 到 9）：`51, 32, 13, 24, 45`

**再按十位分配**：

```text
1 桶：13
2 桶：24
3 桶：32
4 桶：45
5 桶：51
```

收集：`13, 24, 32, 45, 51`

排好了。

整个过程中，没有做过一次"两个关键字谁大"的比较。

这就是基数排序最反直觉的地方：

```text
一个"排序"算法，可以完全不做比较。
```

它绕过了"比较排序至少 n log n 次"的下界，因为这个下界只约束"靠比较获取信息"的算法。

基数排序的信息来自"关键字本身的位"，不来自比较。

代价是它对关键字的形式有要求：必须能拆成固定个数的位，而且每一位的取值范围要小。

整数、定长字符串可以；浮点数、变长字符串要另外处理。


```text
n = 100 万，d = 4，r = 10
基数排序：4 × (100 万 + 10) ≈ 400 万次搬运
比较排序：100 万 × 20 = 2000 万次比较
```

这时基数排序快 5 倍左右。

而且它的"搬运"是顺序读写数组和桶，缓存非常友好。

### 11.1 实现上的两个坑

第一个坑：桶不能是 10 个链表。

教材上写"桶"很容易被理解成 10 条链，那样每次分配都要动态申请结点，开销极大。

真实实现用的是"计数 + 前缀和"：

```text
先数出每一位上每个值出现几次（count[10]）。
把 count 累加成前缀和，得到每个桶在结果数组里的起始位置。
再扫一遍原数组，按前缀和把元素放进结果数组的对应位置，同时把该桶的指针后移。
```

这样一趟分配收集就是两次线性扫描，不需要任何动态内存。

```c
/* 对非负整数做基数排序，d 是最大位数 */
void radix_sort(int a[], int n, int d) {
    int *out = (int *)malloc(n * sizeof(int));
    int count[10];
    int exp = 1;                       /* 当前处理的位权：1, 10, 100, … */
    for (int k = 0; k < d; k++) {
        for (int i = 0; i < 10; i++) count[i] = 0;
        for (int i = 0; i < n; i++) count[(a[i] / exp) % 10]++;   /* 数个数 */
        for (int i = 1; i < 10; i++) count[i] += count[i - 1];    /* 前缀和 */
        for (int i = n - 1; i >= 0; i--) {                        /* 从后往前，保证稳定 */
            int digit = (a[i] / exp) % 10;
            out[--count[digit]] = a[i];
        }
        for (int i = 0; i < n; i++) a[i] = out[i];                /* 抄回去 */
        exp *= 10;
    }
    free(out);
}
```

第二个坑就在这段代码里：**倒着扫原数组**。

`for (int i = n - 1; i >= 0; i--)` 是必须的。

因为前缀和给的是每个桶的"末尾位置"，倒着放，先进桶的元素会被放到后面，再被后进的挤到前面。

这样出来正好是原来的顺序。

如果正着扫，同一个桶里的元素顺序就反了，稳定性丢了，上一趟排好的低位顺序全乱。

**这一段是基数排序最容易写错的地方，也是唯一必须理解"为什么倒着扫"的地方。**

最后补两个工程上的限制。

第一，负数不能直接用这套代码。

`(a[i] / exp) % 10` 对负数会算出一个负余数（C 语言的取余向零取整），桶下标就成了负数，直接越界。

常见处理是把所有数先加上一个偏移量变成非负，或者把符号位单独拎出来当最高位处理。

第二，位数 d 必须事先知道。

对整数要先求最大值再算位数，对变长字符串要先扫一遍求最长长度。

这一步是 O(n)，不改变总复杂度，但很容易漏写。

## 12. 四种排序摆在一起

```text
              最好        平均        最坏        空间      稳定
简单选择      O(n²)       O(n²)       O(n²)      O(1)      否
堆排序        O(n log n)  O(n log n)  O(n log n) O(1)      否
归并排序      O(n log n)  O(n log n)  O(n log n) O(n)      是
基数排序      O(d(n+r))   O(d(n+r))   O(d(n+r))  O(n+r)    是
```

几点对照着说。

**简单选择排序的时间与初始序列无关。**

不管数据多乱、多整齐，比较次数永远是 n(n−1)/2。

这一点和折半插入一样，属于"不看输入脸色"的算法。

好处是行为可预测，坏处是最好情况也慢。

**堆排序是唯一"最坏也 O(n log n) 且空间 O(1)"的算法。**

需要最坏保证又要省内存时，只有它。

代价是不稳定、缓存不友好。

**归并排序是唯一"稳定且最坏 O(n log n)"的算法。**

代价是要 O(n) 额外空间。

外部排序几乎都用它（第 20 篇），就是因为这个组合。

**基数排序的时间与 n 是线性关系**，但要乘上位数 d。

d 取决于关键字的范围，不取决于 n。

所以关键字范围固定时（比如都是 32 位整数，d = 10 位十进制），它是 O(n) 的。

关键字范围随 n 增长时（比如关键字是 1 到 n² 的整数），d ≈ 2 log₁₀ n，退化成 O(n log n)。

**这解释了为什么基数排序"看起来是线性"，实际不一定。**

## 13. 408 怎么考

这一块的题型：

```text
① 给一个数组，画出建堆后的结果。
② 写出堆排序前几趟的结果。
③ 给出归并排序每趟的结果或比较次数。
④ 基数排序的每趟分配收集结果、时间空间复杂度。
⑤ 三种 O(n log n) 排序的对比（稳定性、空间、最坏情况）。
```

第一类最多。

口诀只有一句：

```text
从 ⌊n/2⌋ 号结点开始，往前逐个向下调整，每次和"较大的孩子"换。
```

看一道自拟的题。

题目：对 `5, 8, 3, 9, 7, 2` 建大根堆，写出结果。

n = 6，最后一个非叶结点是 ⌊6/2⌋ = 3 号。

```text
初始：5  8  3  9  7  2    （1..6 号）
```

调整 3 号（3）：

```text
孩子是 6 号（2）。3 ≥ 2，不换。
```

调整 2 号（8）：

```text
孩子是 4 号（9）、5 号（7）。大的 9。
8 < 9，交换 2 号和 4 号。
数组：5  9  3  8  7  2
看 4 号（8）：孩子是 8 号，越界，停。
```

调整 1 号（5）：

```text
孩子是 2 号（9）、3 号（3）。大的 9。
5 < 9，交换 1 号和 2 号。
数组：9  5  3  8  7  2
看 2 号（5）：孩子是 4 号（8）、5 号（7）。大的 8。
5 < 8，交换 2 号和 4 号。
数组：9  8  3  5  7  2
看 4 号（5）：孩子是 8 号，越界，停。
```

答案：`9, 8, 3, 5, 7, 2`。

验证：9 ≥ 8、3；8 ≥ 5、7；3 ≥ 2。

第二类考堆排序，注意"每趟之后数组长什么样"。

一个便于自查的办法：

```text
第 k 趟之后，数组末尾的 k 个元素一定是"最大的 k 个，且已经有序"。
如果不是，说明调整过程错了。

还有一个高频陷阱：题目给的数组下标从 0 开始。

这时最后一个非叶结点是 ⌊n/2⌋ − 1，不是 ⌊n/2⌋。

n = 6、下标 0 开始的数组，最后一个非叶结点是 2 号（对应 1 开始记法的 3 号）。

孩子下标也要换成 2i+1 和 2i+2。

只要有一处用错公式，整棵树就调错，而且错误答案看起来"很像对的"，很难自查出来。

所以提笔前先确认一句：**这道题的下标从 0 还是从 1 开始。**
```

第三类考归并，两个数要记：

```text
归并趟数 = ⌈log₂ n⌉
每趟比较次数 ≤ n − 1（n 是这一趟参与合并的元素总数）
```

自拟例题：n = 1000，二路归并排序需要几趟？总共最多比较多少次？

```text
趟数 = ⌈log₂ 1000⌉ = 10（因为 2⁹ = 512 < 1000 ≤ 1024 = 2¹⁰）
总比较次数 ≤ 10 × (1000 − 1) = 9990
```

第四类考基数排序，重点是空间复杂度 O(n + r) 和"稳定是必要条件"。

一个常见判断题：

```text
"基数排序不需要比较关键字，所以它的时间与关键字范围无关。"
```

错。

时间 O(d(n+r)) 里的 d 就是位数，位数取决于关键字范围。

范围越大，d 越大，时间越长。

## 14. 真实系统里长什么样

**堆：优先队列和定时器**

堆在工程里的主力用途不是排序，是**优先队列**（priority queue）。

```text
操作系统的定时器：把到期时间放进小根堆，每次取堆顶，就是最早到期的那个。
任务调度器：按优先级放堆里，每次取最高优先级的。
Dijkstra 算法：每次取当前距离最小的顶点，用小根堆。
```

这些场景只需要"取最小"和"插入"两个操作，不需要全排序。

用一个 n 个元素的小根堆，两个操作都是 O(log n)。

如果每次线性扫描找最小，Dijkstra 会从 O(E log V) 退化到 O(V²)。

Linux 内核的定时器早期用的是"时间轮"而不是堆，因为堆的常数还是偏大，而定时器的插入极频繁。

这是一个"理论最优不等于工程最优"的例子。

**归并：Timsort 与外部排序**

Python 的 `sorted()` 和 Java 的对象数组排序用的都是 Timsort。

它是归并排序的改良版，核心是找出数据里天然存在的有序段（run），再合并这些段。

```text
真实数据往往"局部有序"：日志按时间近似有序，数据库导出的数据按主键近似有序。
Timsort 先用插入排序把短的有序段延长，再用归并合并，最坏 O(n log n)，最好 O(n)。
```

这是"利用输入已有的有序性"的极致做法。

第 18 篇讲的希尔排序是另一种利用方式（利用"大致有序"），思路同源。

**基数排序：字符串与整数的批量排序**

基数排序在数据库和搜索引擎里用得很多：

```text
对定长字符串（比如 IP 地址、日期字符串）排序。
对整数键做桶排序的一层。
GPU 上的并行排序：基数排序特别适合并行，因为每一趟的分配是独立的。
```

它不适合通用场景，因为要求关键字能按位拆开且位数固定。

但在这个限定条件下，它比任何比较排序都快。

## 15. 小结

这一篇的三条路线，压成一句话：

```text
选择类靠"找最值"，归并类靠"合两段"，基数类靠"按位分桶再收回"。
```

三种排序的关键动作：

```text
建堆：从 ⌊n/2⌋ 往前，逐个向下调整，和较大的孩子换。
归并：两段各看一个，取小的；相等取左边（保稳定）。
基数：从低位到高位，每趟分配 + 收集，倒着扫原数组（保稳定）。
```

手算的三组结果：

```text
建堆：97 76 65 49* 49 13 27 38
堆排序七趟后：13 27 38 49 49* 65 76 97
归并三趟：
  第 1 趟 38 49 65 97 13 76 27 49*
  第 2 趟 38 49 65 97 13 27 49* 76
  第 3 趟 13 27 38 49 49* 65 76 97
基数三趟：
  个位后 930 063 083 184 505 278 008 109 589 269
  十位后 505 008 109 930 063 269 278 083 184 589
  百位后 008 063 083 109 184 269 278 505 589 930
```

一个反直觉的结论，放在最后：

```text
堆排序的最坏情况是 O(n log n)，比快排的 O(n²) 好；
但实测中堆排序常常比快排慢两三倍。
因为堆的父子结点在内存里隔得远，每次比较都是一次缓存不命中。
```

所以"复杂度更优"不等于"跑得更快"。

真实系统选排序算法时，看的往往是"最坏能不能接受"加上"缓存友不友好"。
