> **读这篇之前，你只需要知道**：指针是存"地址"的变量，地址就是内存格子的门牌号；结构体可以把几个不同类型的变量捆成一个整体；`malloc` 向系统要一块内存，`free` 把它还回去。
> **这篇讲什么**：不再要求数据挨着放，而是让每个元素自己记住"下一个在哪"，用改指针代替搬数据。
> **一个类比**：寻宝游戏，每张纸条上写着下一个线索藏在哪里；纸条可以散落在任何地方，你只能从第一张开始，顺着线索一张张找。

顺序表有一个绕不过去的痛点。

100 万条记录，在中间插一条，平均要挪 50 万条。

用户点一下"保存"，进度条转半秒。

你想了个办法：不挪了。

每个元素自己记一句"下一个在哪"。

插入时只改两根"线"，不管表有多长。

代价立刻出现：想找第 50 万个，没法再"算地址"了，只能从第一个开始，顺着线走 50 万步。

**这就是链表：用"找得慢"换"改得快"。**

这一篇要讲清四件事：

```text
一根线（单链表）怎么串、怎么插、怎么删
两根线（双链表）多换到了什么
首尾相连（循环链表）解决了什么
没有指针时，怎么用数组下标假装指针（静态链表）
```

先把"线"是什么说清。

## 1. 没有指针，链表就散了

先做思想实验。

你把 5 个整数分别写在 5 张纸上，放进 5 个抽屉。

抽屉编号是 3、17、42、8、91，毫无规律。

现在我问：第 2 个数是多少？

你不知道"第 2 个"指哪张纸。

除非每张纸上多写一句"下一个在 17 号抽屉"。

有了这句话，你才能从第 1 张开始，一张张走。

**这句话就是指针。**

指针（pointer）：一个变量，里面存的是另一个变量的地址。

地址（address）：内存里每个字节的门牌号。

在 C 里，`int *p` 表示 p 是一个指针，它存的是一个 int 的地址。

`*p` 表示"顺着这个地址，把那个 int 取出来"。

没有指针，元素之间就只能靠"物理上挨着"来体现顺序。

一挨着，插入就得搬家。

**链表放弃"挨着"，改用"记地址"，从而把"搬家"换成了"改地址"。**

在 C 里，"记地址"和"顺着地址取"各有一个符号。

```c
int x = 10;
int *p = &x;      /* & 取地址：p 里存的是 x 的地址 */
printf("%d", *p); /* * 解引用：顺着 p 找到 x，取出 10 */
```

`p` 是"门牌号"，`*p` 是"按门牌号进门拿东西"。

链表结点的 next 里存的，就是下一个结点的门牌号。

```text
结点 A 的 next = 3000  →  3000 号格子上住着结点 B
```

所以"遍历链表"这件事，本质是反复做两步：

```text
读当前结点的 next
跳到那个地址
```

没有"算"，只有"跳"。

**能算就能一步到位，只能跳就得一步步走，这是顺序表和链表最根本的分野。**

这笔交易划不划算，取决于你更常做哪种操作。

## 2. 结点：数据加一根线

如果结点只存数据，元素之间就断了联系。

链表里的每个元素，不能只存数据。

它还得存"下一个在哪"。

**结点（node）：链表中的一个元素，由数据域和指针域两部分组成。**

```text
数据域（data）：存元素本身的值。
指针域（next）：存下一个结点的地址。
```

画出来：

```text
┌──────┬──────┐
│ data │ next │──→ 下一个结点
└──────┴──────┘
```

C 里的定义：

```c
typedef int ElemType;

typedef struct LNode {
    ElemType      data;   /* 数据域 */
    struct LNode *next;   /* 指针域，指向同类型结点 */
} LNode, *LinkList;
```

这里有两个细节容易卡住。

**细节一：结构体里为什么写 `struct LNode *`，不写 `LNode *`？**

因为 typedef 还没生效。

在 `typedef struct LNode { ... } LNode;` 这行里，大括号内部还没有 `LNode` 这个别名。

只有 `struct LNode` 这个完整名字可以用。

**细节二：`LNode` 和 `LinkList` 有什么区别？**

`LNode` 强调"一个结点"。

`LinkList` 强调"一条链表"，本质是指向头结点的指针。

```c
LNode *p;      /* 一个结点指针 */
LinkList L;    /* 一条链表，等价于 LNode *L */
```

两者是同一种类型，只是语义不同。

考试写代码时用哪个都行，但读代码时要分清。

指针域的类型必须是"指向本结构体的指针"。

不能写 `int next`，因为地址是 64 位整数，和 int 宽度不一定一样。

不能写 `LNode next`，因为结构体会无限嵌套，大小无法确定。

只能写 `struct LNode *next`：存的是"另一个同样结构体的地址"，大小固定。

**指针让"结构体里放结构体"这种无限递归，变成了"结构体里放地址"这种有限大小。**

一个结点在内存里到底占多大？

```text
data：int，4 字节
next：指针，64 位系统上 8 字节
合计：12 字节，但通常按 8 字节对齐，实际占 16 字节
```

多出来的 4 字节叫填充（padding），是为了让 CPU 读得整齐。

对齐（alignment）：让数据的起始地址落在某个字节数的倍数上，CPU 一次就能读完，不用跨两个内存块。

所以存一个 int，链表要花 16 字节，顺序表只要 4 字节。

**链表的空间开销不只是"多一个指针"，还有对齐填充。**

存 100 万个 int：

```text
顺序表：约 4 MB
链表：  约 16 MB
```

差 4 倍。

这也是选型时要算的一笔账。

## 3. 单链表：一根线串到底

如果没有"最后一个指向 NULL"这条约定，遍历就停不下来。

**单链表（singly linked list）：每个结点只含一个指针域，指向它的直接后继。**

逻辑上相邻的两个元素，物理上不一定相邻。

它们的"相邻"由指针表示。

```text
head → [10|·] → [20|·] → [30|·] → [40|^]
```

`^` 表示空指针（NULL），意思是"后面没有了"。

最后一个结点的 next 必须是 NULL。

**这是遍历能停下来的唯一依据。**

如果最后一个结点的 next 指向了别处，遍历就停不下来。

如果它指向了前面的某个结点，就形成了环，遍历永远转圈。

头指针（head pointer）：指向链表第一个结点的指针。

整个链表靠它"抓住"。

丢了头指针，后面的结点就全找不回来了，内存也没法释放。

这就是链表最脆弱的地方：

```text
顺序表丢一个下标，还能重新算；
链表丢一个指针，整条链就断了。
```

遍历是链表最基本的动作。

```c
void PrintList(LinkList L) {
    LNode *p = L->next;          /* 从第一个元素开始，跳过头结点 */
    while (p != NULL) {
        printf("%d ", p->data);
        p = p->next;             /* 走到下一个 */
    }
    printf("\n");
}
```

循环条件必须是 `p != NULL`，不能写 `p->next != NULL`。

后者会漏掉最后一个结点。

循环体里 `p = p->next` 必须放在最后。

如果先移动再打印，第一个元素就被跳过了。

**链表的每个循环，都在处理"当前结点"和"下一个结点"这两个位置，写之前先想清楚 p 现在站在哪。**

单链表只能单向走。

想在打印完 1、2、3 之后再倒着打印，单链表做不到。

除非先递归到表尾，再在归的过程中打印：

```c
void PrintReverse(LNode *p) {
    if (p == NULL) return;
    PrintReverse(p->next);   /* 先走到表尾 */
    printf("%d ", p->data);  /* 回来时再打印 */
}
```

这用到了函数调用栈，空间 O(n)。

**"能倒着走"这件事，单链表要靠栈，双链表靠 prior，顺序表靠下标减一。**

三种结构，三种办法，代价各不相同。

## 4. 头结点：多挂一个空结点图什么

如果没有头结点，每次操作第一个位置都要特判。

单链表有两种写法。

一种头指针直接指向第一个元素结点。

另一种在第一个元素前面，再挂一个"不存数据"的结点。

这个结点叫头结点（dummy head / header node）。

```text
带头结点：
head → [ 空 |·] → [10|·] → [20|·] → NULL

不带头结点：
head → [10|·] → [20|·] → NULL
```

头结点的数据域可以空着，也可以存表长。

指针域指向第一个真正的元素。

多花一个结点的空间，换来三个统一。

**统一一：空表和非空表的操作一致。**

不带头结点时，空表是 `head == NULL`。

插入第一个元素，必须改 `head` 本身。

带头结点时，空表是 `head->next == NULL`。

插入第一个元素，改的是 `head->next`，和其他位置一样。

**统一二：第一个位置和其他位置的插入删除一致。**

不带头结点，在第一个位置插入要特判：

```c
if (i == 1) { 改 head } else { 找到前驱再改 }
```

带头结点，第一个位置也有前驱，就是头结点。

不用特判。

**统一三：头指针永远非空。**

不带头结点，空表时 `head` 是 NULL。

任何操作前都得先判 `head != NULL`。

带头结点，`head` 永远指向那个头结点，判空只看 `head->next`。

少一层判空，少一类崩溃。

408 的代码题默认带头结点，但题目会写明。

如果题目说不带头结点，插入第一个位置就要单独处理。

```c
/* 不带头结点：在第 1 个位置插入，必须改头指针本身 */
int InsertFirst(LinkList *L, ElemType e) {
    LNode *s = (LNode *)malloc(sizeof(LNode));
    if (s == NULL) return 0;

    s->data = e;
    s->next = *L;      /* 新结点指向原第一个 */
    *L = s;            /* 头指针改指新结点 */
    return 1;
}
```

注意参数是 `LinkList *L`，不是 `LinkList L`。

因为要修改"头指针本身"，必须把它的地址传进来。

如果写成 `LinkList L`，函数里改的是副本，外面的头指针没变。

**C 里"改一个变量的值"和"改一个变量指向的内容"，是两件完全不同的事。**

头结点把这件事变简单了：

有了头结点，头指针永远指向头结点，永远不用改。

所有插入删除改的都是某个结点的 next。

**一个空结点，换来了"头指针永不变"这个稳定性。**

## 5. 插入：两根指针，顺序错了就断链

如果插入的指针顺序写错，链会当场断掉。

先看最常见的操作：在结点 p 之后插入一个新结点 s。

初始状态：

```text
p → [b|·] → [c|·] → ...
```

目标：

```text
p → [b|·] → [s|·] → [c|·] → ...
```

只需要两步。

```c
s->next = p->next;   /* 第一步：s 先牵住 c */
p->next = s;         /* 第二步：b 再牵住 s */
```

画成图：

```text
第一步：s->next = p->next

p → [b|·] → [c|·]
        ↗
     [s|·]

第二步：p->next = s

p → [b|·] → [s|·] → [c|·]
```

顺序能不能换？

试试反过来：

```c
p->next = s;         /* 先让 b 指向 s */
s->next = p->next;   /* 再让 s 指向 p->next */
```

第一步之后，`p->next` 已经是 s 了。

第二步相当于 `s->next = s`。

s 指向自己，形成一个自环。

c 及后面全部丢失，再也找不回来。

**所以顺序必须是"先接后断"：先让新结点接上后继，再让前驱改指新结点。**

这个原则在单链表、双链表、甚至树的插入里都成立。

完整函数：

```c
/* 在结点 p 之后插入值为 e 的新结点，成功返回 1 */
int InsertAfter(LNode *p, ElemType e) {
    if (p == NULL) return 0;

    LNode *s = (LNode *)malloc(sizeof(LNode));
    if (s == NULL) return 0;      /* 内存分配失败 */

    s->data = e;
    s->next = p->next;            /* 先接后 */
    p->next = s;                  /* 后断前 */
    return 1;
}
```

如果要在第 i 个位置插入呢？

先找到第 i−1 个结点，再调用 `InsertAfter`。

找第 i−1 个是 O(n)。

**所以"链表插入 O(1)"这句话，省略了一个前提：你已经站在前驱结点上。**

完整操作仍是 O(n)。

这是一个必须说清、也最常被误解的点。

把"找前驱 + 插入"合起来的完整函数：

```c
/* 在第 i 个位置插入 e，i 从 1 开始 */
int ListInsert(LinkList L, int i, ElemType e) {
    if (i < 1) return 0;

    LNode *p = L;                    /* 头结点算第 0 个 */
    int j = 0;

    while (p != NULL && j < i - 1) { /* 找第 i-1 个 */
        p = p->next;
        j++;
    }
    if (p == NULL) return 0;         /* 前驱不存在 */

    LNode *s = (LNode *)malloc(sizeof(LNode));
    if (s == NULL) return 0;

    s->data = e;
    s->next = p->next;
    p->next = s;
    return 1;
}
```

走两个边界。

```text
i = 1：while 不执行，p 就是头结点。
       在头结点后插入，正是第 1 个位置。

i = n+1：while 走 n 步，p 停在最后一个结点。
       在它后面插入，正是表尾。
```

**有了头结点，i=1 和 i=n+1 都不用特判，走同一段代码。**

这就是第 4 节说的"统一"落到实处的样子。

还有一个方向问题。

单链表只有 next，没有 prior。

想在 p 之前插入，必须从头找到 p 的前驱，O(n)。

有一种取巧写法：

```text
在 p 之后插入 s，然后交换 p 和 s 的数据域。
```

这样逻辑上 s 跑到了 p 前面，但结点地址没变。

如果外部还持有 p 的地址，它指向的内容就变了，会出问题。

408 一般不考这种写法，知道有这回事即可。

## 6. 删除：先接后断，别忘了 free

如果删除时不先接住后继，后面的链就丢了。

删除 p 之后的结点 q。

```text
删除前：p → [b|·] → [q|·] → [c|·]
删除后：p → [b|·] → [c|·]
```

三步。

```c
q = p->next;         /* 记住要删的结点 */
p->next = q->next;   /* 让 b 直接指向 c */
free(q);             /* 把 q 还给系统 */
```

如果不 `free` 呢？

结点从链表里消失了，但内存还占着。

程序运行久了，内存越用越少，这叫内存泄漏（memory leak）。

在 408 代码题里，漏 `free` 一般不至于扣分，但这是坏习惯。

**更重要的是：`free` 之前一定要先保存 `q->next`。**

如果顺序写成：

```c
p->next = p->next->next;   /* 先接 */
free(p->next);             /* 错：删的是 c，不是 q */
```

这就删错了结点。

所以标准写法是先存 q，再接，最后 free q。

删除第 i 个结点，同样要先找第 i−1 个。

```c
/* 删除第 i 个结点，用 e 带回，i 从 1 开始 */
int ListDelete(LinkList L, int i, ElemType *e) {
    if (i < 1) return 0;          /* 位置非法 */

    LNode *p = L;                 /* 从头结点开始 */
    int j = 0;

    while (p != NULL && j < i - 1) {   /* 找第 i-1 个 */
        p = p->next;
        j++;
    }
    if (p == NULL || p->next == NULL)  /* 前驱不存在，或第 i 个不存在 */
        return 0;

    LNode *q = p->next;
    *e = q->data;
    p->next = q->next;
    free(q);
    return 1;
}
```

注意两个失败条件。

`p == NULL`：i−1 超过了表长，前驱根本不存在。

`p->next == NULL`：p 是最后一个结点，它后面没有结点可删。

**这两种情况要分开判，合并成一个会漏掉边界。**

走一遍删第一个结点。

```text
初始：head → [空] → [10] → [20] → NULL
i = 1：
  p = head（j=0，while 不执行）
  q = head->next = 10 号结点
  head->next = q->next = 20 号结点
  free(q)
结果：head → [空] → [20] → NULL
```

删表尾。

```text
初始：head → [空] → [10] → [20] → NULL
i = 2：
  p 走到 10 号结点（第 1 个）
  q = 20 号结点
  10 号->next = NULL
  free(q)
结果：head → [空] → [10] → NULL
```

两次都不用改 `head` 本身。

**头指针始终指着头结点，这是"稳定"带来的最大好处。**

再问一个常被考的问题：能不能 O(1) 删除"结点 p 本身"？

单链表不行。

因为删除 p 需要改 p 的前驱的 next，而单链表找不到前驱。

除非你从头走一遍，O(n)。

双链表可以，因为 p->prior 就在手边。

```c
p->prior->next = p->next;
if (p->next != NULL) p->next->prior = p->prior;
free(p);
```

**"删除某个结点"和"删除某个结点的后继"，在单链表里是两件难度完全不同的事。**

题目说"删除 p 结点"，先想清楚它给的是前驱还是 p 本身。

## 7. 按位查找：O(n) 的账要算清

单链表不能算地址，只能走。

```c
/* 返回第 i 个结点，i 从 1 开始；找不到返回 NULL */
LNode *GetElem(LinkList L, int i) {
    if (i < 0) return NULL;

    LNode *p = L;        /* 头结点算第 0 个 */
    int j = 0;

    while (p != NULL && j < i) {
        p = p->next;
        j++;
    }
    return p;
}
```

找第 i 个，要走 i 步。

平均走多少？

假设等概率查找每个位置，n 个位置：

```text
(1/n)(1 + 2 + ... + n) = (n+1)/2
```

n = 100 万时，平均走 50 万步。

和顺序表的 O(1) 比，差 50 万倍。

按值查找也一样。

```c
LNode *LocateElem(LinkList L, ElemType e) {
    LNode *p = L->next;
    while (p != NULL && p->data != e)
        p = p->next;
    return p;
}
```

最坏走 n 步，平均 (n+1)/2 步。

**所以链表的"查找"没有任何优势，它的优势全在"已知位置后的修改"。**

**反直觉的点在这里：链表插入是 O(1)，但"在链表里插入一个元素"仍然是 O(n)，因为找位置要走路。**

这两句话不矛盾。

```text
改指针：O(1)
走到那个位置：O(n)
合起来：O(n)
```

只有当你已经拿着前驱结点的指针时，插入才是真正的 O(1)。

这也是为什么链表常和"哈希表"配合：

哈希表负责 O(1) 找到位置，链表负责 O(1) 插入删除。

Java 的 `HashMap` 就是这么干的。

求表长也只能走一遍。

```c
int ListLength(LinkList L) {
    int len = 0;
    LNode *p = L->next;
    while (p != NULL) {
        len++;
        p = p->next;
    }
    return len;
}
```

时间 O(n)。

顺序表求长度是 O(1)，因为 `length` 就存在结构体里。

**链表要在每个结点上省一个"长度"字段，就得在每次求长度时付一遍遍历的代价。**

这是"空间换时间"的反向例子：省空间，费时间。

## 8. 建表：头插法与尾插法

如果建表时每次都从头找表尾，建一条 n 个结点的链会变成 O(n²)。

从数组建链表，有两种插法。

结果正好相反。

**头插法：每次插在头结点之后。**

```c
void CreateHead(LinkList *L, ElemType a[], int n) {
    *L = (LNode *)malloc(sizeof(LNode));   /* 头结点 */
    (*L)->next = NULL;

    for (int i = 0; i < n; i++) {
        LNode *s = (LNode *)malloc(sizeof(LNode));
        s->data = a[i];
        s->next = (*L)->next;              /* 新结点指向原第一个 */
        (*L)->next = s;                    /* 头结点指向新结点 */
    }
}
```

输入 `[1, 2, 3]`，得到 `head → 3 → 2 → 1`。

为什么反了？

因为每次新来的都插在最前面。

最后来的 3 排在了最前。

**头插法天然逆序，这是它的特点，不是 bug。**

**尾插法：每次插在表尾。**

```c
void CreateTail(LinkList *L, ElemType a[], int n) {
    *L = (LNode *)malloc(sizeof(LNode));
    (*L)->next = NULL;

    LNode *r = *L;                          /* r 始终指向表尾 */
    for (int i = 0; i < n; i++) {
        LNode *s = (LNode *)malloc(sizeof(LNode));
        s->data = a[i];
        s->next = NULL;
        r->next = s;
        r = s;                              /* 尾指针后移 */
    }
}
```

输入 `[1, 2, 3]`，得到 `head → 1 → 2 → 3`。

尾插法要多维护一个尾指针 r。

如果不维护，每次插表尾都要从头走到尾，建表变成 O(n²)。

**一个尾指针，把建表从 O(n²) 降到 O(n)，这是"用空间换时间"的最小例子。**

走一遍看结果。

```text
输入 a = [7, 8, 9]

头插法：
  插 7：head → 7
  插 8：head → 8 → 7
  插 9：head → 9 → 8 → 7

尾插法：
  插 7：head → 7
  插 8：head → 7 → 8
  插 9：head → 7 → 8 → 9
```

一个逆序，一个正序。

头插法还有一个用途：就地逆置。

把原链表从头到尾摘下结点，一个个头插到新表里，顺序就反了。

```c
/* 就地逆置：把结点逐个摘下，头插回头结点之后 */
void ReverseByHeadInsert(LinkList L) {
    LNode *p = L->next;
    L->next = NULL;              /* 结果表先清空 */

    while (p != NULL) {
        LNode *q = p->next;      /* 先存后继，否则断链 */
        p->next = L->next;       /* 头插：接到结果表最前 */
        L->next = p;
        p = q;
    }
}
```

走一遍 `1 → 2 → 3`：

```text
初始：L->next = NULL, p = 1
第 1 轮：q=2，1 插到最前，结果 1，p=2
第 2 轮：q=3，2 插到最前，结果 2 → 1，p=3
第 3 轮：q=NULL，3 插到最前，结果 3 → 2 → 1
```

和第 13 节的三指针法结果一样，写法更贴近"头插"这个动作。

**同一个逆置，两种思路：一种改 next 的方向，一种重新头插。**

考试写哪种都行。

第 13 节会给三指针版本。

## 9. 双链表：多一根线，换 O(1) 前驱

如果只有 next，想找前驱只能从头再来。

单链表只能往前走。

想访问前驱，得从头再走一遍。

**双链表（doubly linked list）：每个结点有两个指针，一个指后继，一个指前驱。**

```c
typedef struct DNode {
    ElemType       data;
    struct DNode  *prior;   /* 指向前驱 */
    struct DNode  *next;    /* 指向后继 */
} DNode, *DLinkList;
```

画出来：

```text
      ┌────────┬──────┬────────┐
  ⇄   │ prior  │ data │  next  │   ⇄
      └────────┴──────┴────────┘
```

多一个 prior，每个结点多占一个指针的空间。

换来的能力：已知 p，找 p 的前驱是 O(1)。

在 p 之后插入 s，要改四根指针。

```c
s->next = p->next;              /* 1. s 的后继指向 c */
if (p->next != NULL)
    p->next->prior = s;         /* 2. c 的前驱指向 s */
s->prior = p;                   /* 3. s 的前驱指向 p */
p->next = s;                    /* 4. p 的后继指向 s */
```

画图：

```text
插入前：p ⇄ c

第一步 s->next = p->next：
        p ⇄ c
        s → c

第二步 c->prior = s：
        p ⇄ c
        s ⇄ c

第三步 s->prior = p：
        p ⇄ s ⇄ c

第四步 p->next = s：
        p ⇄ s ⇄ c   （完成）
```

顺序有讲究。

第一步必须先把 p 原来的后继存进 s->next，否则后面改了 p->next 就找不到了。

第二步必须在 `p->next` 还指向 c 的时候做。

第三步和第四步顺序可以换。

**核心原则还是"先接后断"：先把新结点的两根线接好，再改老结点的线。**

删除 p 更简单，两根线一改：

```c
p->prior->next = p->next;       /* 前驱直接指向后继 */
if (p->next != NULL)
    p->next->prior = p->prior;  /* 后继直接指向前驱 */
free(p);
```

不用找前驱，因为 prior 就在手边。

**这就是双链表的价值：用空间换"往前找"的能力。**

边界要盯住：如果 p 是最后一个结点，`p->next` 是 NULL。

这时第二步 `p->next->prior = s` 会解引用空指针，程序崩。

所以代码里必须加 `if (p->next != NULL)`。

插入完成后，s 成了新的表尾，`s->next` 自动是 NULL。

删除时也一样。

如果 p 是表尾，`p->next` 是 NULL，只需改前驱的 next 和 p 的 prior，不用碰后继。

**双链表的每个操作，都要问一句"p 的左边或右边有没有结点"。**

这是它比单链表多出来的心智负担。

双链表的判空和单链表一样：

```c
head->next == NULL
```

只有循环双链表才变成 `head->next == head`。

四种组合要分清：

```text
单链表：一个 next
双链表：next + prior
循环单链表：next 成环，判空 head->next == head
循环双链表：next 和 prior 都成环
```

## 10. 循环链表：首尾相连

单链表的最后一个结点 next 是 NULL。

如果让它指回头结点，就成了循环链表（circular linked list）。

```text
head → [空|·] → [10|·] → [20|·] → [30|·]
         ↑                            │
         └────────────────────────────┘
```

好处：从任何一个结点出发，都能走遍全表。

不用回到头指针。

判空条件变了。

带头结点的循环链表为空：

```c
head->next == head
```

不是 `head->next == NULL`。

**这个判空条件最容易写错，考试前要单独记。**

循环链表最实用的技巧是"只存尾指针"。

设尾指针为 rear。

```text
rear->next            → 头结点
rear->next->next      → 第一个元素
rear                  → 最后一个元素
```

于是：

```text
在表头插入：O(1)
在表尾插入：O(1)
```

因为尾指针一步就能找到头，也能一步找到尾。

如果只存头指针，表尾插入还要走 n 步。

**一个尾指针，让"头尾都能 O(1) 插入"，这是循环链表最漂亮的用法。**

经典应用是约瑟夫环。

n 个人围成一圈，从第 1 个开始报数，报到 m 的人出圈，下一个人重新从 1 报。

用循环链表模拟，每次走 m−1 步，删一个结点，直到剩一个。

时间复杂度 O(nm)。

写出来大概是这样：

```c
/* n 个人围成一圈，报到 m 的出圈，返回最后剩下的编号，m ≥ 2 */
int Josephus(int n, int m) {
    /* 建一个带头结点的循环链表，编号 1..n */
    LNode *head = (LNode *)malloc(sizeof(LNode));
    head->data = 1;
    head->next = head;
    LNode *r = head;

    for (int i = 2; i <= n; i++) {
        LNode *s = (LNode *)malloc(sizeof(LNode));
        s->data = i;
        s->next = head;      /* 新结点先接回头 */
        r->next = s;         /* 前驱接上新结点 */
        r = s;
    }

    LNode *p = head;
    while (p->next != p) {   /* 只剩一个结点时停 */
        for (int i = 1; i < m - 1; i++)   /* 走到要删的前驱 */
            p = p->next;
        LNode *q = p->next;               /* 要出圈的人 */
        p->next = q->next;
        free(q);
        p = p->next;                      /* 从下一个人重新报数 */
    }
    return p->data;
}
```

这段代码有两个细节。

第一，建表时 `head->next = head`，一开始就成环。

第二，循环条件是 `p->next != p`，不是 `p != NULL`。

**循环链表没有 NULL，判断"到头了"只能靠"又回到了自己"。**

这也是它和单链表在写法上最大的区别。

循环链表还有一个常见用途：轮询。

操作系统让多个进程轮流用 CPU，一圈一圈转。

```text
进程 A → B → C → D → 回到 A
```

用循环链表存进程，一个"当前指针"顺着 next 走，走到尾自动回到头。

不需要"到表尾就重置"的特判。

```c
p = p->next;   /* 永远有下一个，不用判 NULL */
```

**"没有尽头"在这里不是缺陷，正是需求。**

## 11. 静态链表：用数组下标当指针

如果没有指针，链表是不是就写不了？

有些老语言没有指针。

有些场景不允许动态分配内存。

这时可以用数组模拟链表，叫静态链表（static linked list）。

思路：数组的每个元素是一个结点，next 不存地址，存"下一个元素的下标"。

```c
#define MAXSIZE 100

typedef struct {
    ElemType data;
    int      next;    /* 下一个结点的数组下标，不是地址 */
} SLinkList[MAXSIZE];
```

约定 0 号位置放头结点。

next = −1 表示表尾。

画出来：

```text
下标：   0      1      2      3      4
data： [空]   [10]   [30]   [20]   [  ]
next：   1      3      5      2     ...
```

这条链是：0 → 1 → 3 → 2 → ...，对应数据 10 → 20 → 30。

注意 2 号结点的 next 是 5，虽然 5 号还没用到，但它表示"后面接 5 号"。

这就是静态链表和数组的区别：

```text
数组：物理顺序就是逻辑顺序。
静态链表：物理顺序随便，靠 next 下标串出逻辑顺序。
```

插入时，找一个空位，改两个 next。

删除时，改一个 next，把空出来的位置记下来备用。

插入分三步。

```text
1. 找一个空闲下标 k。
2. 把新值写进 space[k].data。
3. 让 space[k].next = space[p].next，再让 space[p].next = k。
```

删除反过来。

```text
1. 找到被删结点的前驱 p。
2. 让 space[p].next = space[q].next。
3. 把 q 这个位置标记为空闲，留着下次用。
```

代一组数。

```text
下标：   0      1      2      3
data： [空]   [10]   [20]   [30]
next：   1      2      3     -1
```

在 10 后面插入 15，用 4 号空位：

```text
space[4].data = 15
space[4].next = space[1].next = 2
space[1].next = 4
结果：0 → 1 → 4 → 2 → 3 → -1，数据 10 → 15 → 20 → 30
```

没有搬任何元素，只改了两个整数。

**静态链表把"指针"换成了"数组下标"，把"地址"换成了"位置"，思路完全一样。**

**优点**：不用指针，不用连续搬移，适合容量固定的嵌入式场景。

**缺点**：容量写死，找下一个要"数组下标 → 结点"两次访存，比真指针慢。

408 考静态链表，通常只考"next 存的是下标"和"插入删除怎么改"。

画一张下标表，按图改数，比背代码快。

## 12. 顺序表 vs 链表：一张表说清

不比较，选型就只能凭感觉。

把两种存储放在一起比。

| 操作 | 顺序表 | 链表 |
|---|---|---|
| 按下标访问 | O(1) | O(n) |
| 按值查找 | O(n) | O(n) |
| 已知位置的插入 | O(n) | O(1) |
| 已知位置的删除 | O(n) | O(1) |
| 含"找位置"的插入删除 | O(n) | O(n) |
| 空间 | 连续，密度 1 | 分散，每结点多一个指针 |
| 缓存 | 友好 | 不友好 |
| 容量 | 固定或扩容搬家 | 随用随申请 |

读表要读三行。

第一行：顺序表赢在"按下标"。

第二行：平手。

按值查找两者都得一个个比。

第三行：链表赢在"已经站好位置"。

第四行最容易看错：含找位置的插入删除，两者都是 O(n)。

**链表并没有把插入删除变成 O(1)，它只是把"搬元素"换成了"改指针"。**

选型口诀：

```text
查得多、改得少 → 顺序表
改得多、查得少 → 链表
两头多、中间少 → 链表 + 尾指针
要按下标随机读 → 顺序表
```

还有一个工程因素：缓存。

顺序表连续访问，CPU 一次读一整块，命中率高。

链表每跳一次都可能缓存不命中。

同样是 O(n) 遍历，顺序表常常快 2 到 5 倍。

**复杂度相同，实际速度可能差几倍，这是选择题和工程题的区别。**

选型不只看复杂度，还要看访问模式。

```text
通讯录按姓名首字母分组，组内人数少、经常增删 → 链表
成绩表要按学号随机查、很少改 → 顺序表
浏览器的前进后退 → 双链表（要能往前）
操作系统的进程就绪队列 → 链表（频繁进出）
LRU 缓存 → 哈希表 + 双链表（查找 O(1)，移动 O(1)）
```

LRU 是"最近最少使用"的淘汰策略。

它需要两件事同时成立：

```text
O(1) 找到某个缓存项
O(1) 把某个缓存项移到"最近使用"的一端
```

哈希表负责第一件，双链表负责第二件。

**没有一种结构同时擅长这两件事，所以真实系统里常常是组合。**

408 只考单结构，但理解了"为什么组合"，选型题就不会选错。

## 13. 408 怎么考：反转、倒数第 k 个、判环

链表代码题是 408 的重灾区。

三个套路必须会。

**套路一：反转链表。**

三根指针，边走边掉头。

```c
/* 带头结点，就地逆置，返回头指针 */
LinkList Reverse(LinkList L) {
    LNode *pre = NULL;        /* 已反转部分的头 */
    LNode *p = L->next;       /* 当前待处理结点 */
    LNode *q;                 /* 暂存下一个 */

    while (p != NULL) {
        q = p->next;          /* 先记住下一个 */
        p->next = pre;        /* 当前结点掉头 */
        pre = p;              /* pre 前移 */
        p = q;                /* p 前移 */
    }
    L->next = pre;            /* 头结点接上新表头 */
    return L;
}
```

走一遍 `1 → 2 → 3`：

```text
初始：pre=NULL, p=1
第 1 轮：q=2, 1->next=NULL, pre=1, p=2
第 2 轮：q=3, 2->next=1,    pre=2, p=3
第 3 轮：q=NULL, 3->next=2, pre=3, p=NULL
结束：head → 3 → 2 → 1 → NULL
```

时间 O(n)，空间 O(1)。

**关键是 `q = p->next` 必须放在最前面，否则掉头之后找不到下一个。**

**套路二：找倒数第 k 个结点。**

双指针，快指针先走 k 步，然后两个一起走。

```c
/* 带头结点，找倒数第 k 个结点，找不到返回 NULL */
LNode *FindKthFromEnd(LinkList L, int k) {
    LNode *fast = L->next;
    LNode *slow = L->next;
    int cnt = 0;

    while (fast != NULL && cnt < k) {
        fast = fast->next;
        cnt++;
    }
    if (cnt < k) return NULL;    /* 表长不足 k */

    while (fast != NULL) {
        fast = fast->next;
        slow = slow->next;
    }
    return slow;
}
```

为什么对？

快指针先走 k 步，它和慢指针之间隔着 k 个结点。

当快指针走到 NULL（表尾后面），慢指针正好在倒数第 k 个。

走一遍 `1 → 2 → 3 → 4 → 5`，k = 2：

```text
fast 先走 2 步：到 3
然后同步走：
  fast=4, slow=2
  fast=5, slow=3
  fast=NULL, slow=4
返回 4，正是倒数第 2 个
```

时间 O(n)，空间 O(1)。

**这个套路还能解"找中间结点"：快指针走两步，慢指针走一步。**

**套路三：判环。**

快慢指针，快的每次走两步，慢的走一步。

有环必相遇。

```c
int HasCycle(LinkList L) {
    LNode *slow = L->next;
    LNode *fast = L->next;

    while (fast != NULL && fast->next != NULL) {
        slow = slow->next;
        fast = fast->next->next;
        if (slow == fast) return 1;
    }
    return 0;
}
```

为什么必相遇？

一旦两个指针都进了环，快指针相对慢指针每次多走 1 步。

环长有限，多走若干步后必然追上。

**如果快指针每次走 3 步呢？不一定相遇，可能永远跨过去。**

所以快慢指针的"快"必须是 2 倍，这是有讲究的。

三个套路覆盖了链表题的一大半。

写链表题有个固定流程，照做能少错一半。

```text
第一步：画图，标出 p、q、pre 各指哪。
第二步：想清楚改哪几根线，顺序是什么。
第三步：写边界，空表、表头、表尾各走一遍。
第四步：检查有没有断链、有没有漏 free。
```

还有两个常考的：

```text
合并两个有序链表：归并，谁小接谁，O(m+n)。
删除倒数第 k 个：先找倒数第 k+1 个，再删它的后继。
```

合并的代码值得完整看一遍。

```c
/* 合并两个带头结点的有序单链表，复用原结点，返回新表头 */
LinkList Merge(LinkList A, LinkList B) {
    LNode *pa = A->next;
    LNode *pb = B->next;
    LNode *r = A;                 /* r 指向结果表的表尾 */

    while (pa != NULL && pb != NULL) {
        if (pa->data <= pb->data) {
            r->next = pa;
            pa = pa->next;
        } else {
            r->next = pb;
            pb = pb->next;
        }
        r = r->next;
    }
    r->next = (pa != NULL) ? pa : pb;  /* 接上剩余的一段 */
    free(B);                           /* B 的头结点不再需要 */
    return A;
}
```

三个要点。

第一，`r` 始终指向结果表的最后一个结点，新结点接在它后面。

第二，循环结束后，把没走完的那条链整段接上，不用再逐个复制。

第三，复用的是原结点，没有新建结点，所以空间是 O(1)。

**归并两个有序链表，时间 O(m+n)，空间 O(1)，这是链表比顺序表强的地方。**

顺序表合并要开一个新数组，空间 O(m+n)。

## 14. 容易混淆的点

```text
1. 头指针 vs 头结点
   头指针是一个指针变量，指向第一个结点。
   头结点是一个真实的结点，不存数据，用来统一操作。
   头指针可以指向头结点，也可以直接指向第一个元素。

2. 指针 vs 指针域
   指针是一个变量，指针域是结点里存指针的那个成员。
   说"改指针"通常指改指针域的值。

3. 链表插入 O(1) 的前提
   前提是"已经站在前驱结点上"。
   找前驱仍是 O(n)，完整操作还是 O(n)。

4. 删除后要 free
   不 free 是内存泄漏。
   free 之前要先保存后继，否则找不到后面的链。

5. 单链表不能 O(1) 找前驱
   只有 next，没有 prior。
   要往前找，只能从头再来。

6. 循环链表的判空
   带头结点：head->next == head。
   不带头结点：head == NULL。

7. 静态链表的 next 是下标
   不是地址，不能直接当指针用。
   -1 常用来表示表尾。

8. 头插法建表是逆序的
   输入 1、2、3，得到 3、2、1。
   想要正序，用尾插法。
```

还有一个更隐蔽的：

```text
9. 链表结点的"逻辑相邻"不等于"物理相邻"
   逻辑相邻靠 next 维系，物理位置随意。
   所以改 next 就能改变逻辑顺序，不用搬数据。
```

## 15. 小结

把这一篇压成几句话。

```text
结点 = 数据域 + 指针域
单链表 = 一根 next 线
双链表 = next + prior 两根线
循环链表 = 尾巴指回头
静态链表 = 用数组下标当指针
```

头结点的三个统一：

```text
空表与非空表统一
首位置与其他位置统一
头指针永远非空
```

两个"先接后断"：

```text
插入：新结点先接后继，前驱再改指新结点
删除：先让前驱接住后继，再 free 被删结点
```

三个必须记住的复杂度：

```text
按位查找：O(n)
已知前驱的插入删除：O(1)
含找位置的插入删除：O(n)
```

顺序表按下标取是 O(1)，链表没有这个能力，这是它最大的短板。

四个容易混的判空：

```text
不带头结点的单链表：head == NULL
带头结点的单链表：  head->next == NULL
带头结点的循环单链表：head->next == head
带头结点的循环双链表：head->next == head
```

**判空条件取决于"头结点有没有"和"链有没有成环"，这两件事决定一切。**

三个套路：

```text
反转：三指针，先存后继再掉头
倒数第 k 个：快指针先走 k 步
判环：快慢指针，快的走两步
```

链表用"找得慢"换来了"改得快"。

可它还有一个问题没解决：

```text
如果我只想"后进先出"，既不需要随机访问，
也不需要遍历整条链，有没有更简单的结构？
```

有。

而且它简单到只需要一个"栈顶"指针。

```text
数据结构系统讲解 04：栈：后进先出的用处
```

那一篇会回答：

```text
为什么括号匹配非用栈不可？
中缀表达式怎么变成后缀？
递归和栈到底是什么关系？
出栈序列有多少种，哪些是不可能的？
```
