> **读这篇之前，你只需要知道**：内存是一排带编号的格子，每个格子有地址；一个变量占几个格子由类型决定，比如 `int` 通常占 4 个；地址可以加减，加 1 就是"往后挪一个格子"。
> **这篇讲什么**：把一排数据放进一段连续的格子里，说清为什么按下标取数只要一步，以及插一个、删一个平均要挪多少个。
> **一个类比**：电影院一排连号座位，第 1 号到第 10 号；你手里有 1 号座的门牌号，想找 7 号座，不用一个个问，直接用"1 号 + 6 个座位宽"算出来。

先看一段能跑、但会出事的代码。

```c
int a[10];
for (int i = 1; i <= 10; i++)
    a[i] = i * i;
```

看着很顺：10 个格子，循环 10 次。

可它写的是 `a[1]` 到 `a[10]`。

合法下标是 `a[0]` 到 `a[9]`。

`a[10]` 越界了。

越界那一格，可能是另一个变量，也可能是函数返回地址。

程序可能当场崩，也可能什么都不报，等你回家才发作。

**这不是"从 0 开始"这个约定在找麻烦，而是"第几个"和"偏移几个"这两件事被混成了一件。**

这一篇要把它们分开。

## 1. 没有"连续"这个前提，会怎样

先做个思想实验。

假设内存里的格子不按顺序给你，而是东一块西一块。

现在要存 5 个整数。

你想找第 3 个，怎么找？

没法算。

你不知道第 1 个在哪，也不知道第 3 个离第 1 个多远。

只能让每个元素额外记一句"下一个在哪"。

这就是[链表](/posts/ds-linked-list/)，03 篇的主题。

反过来，如果这 5 个元素必须挨着放：

```text
地址： 1000  1004  1008  1012  1016
内容： [10]  [20]  [30]  [40]  [50]
下标：  0     1     2     3     4
```

第 3 个在哪？

```text
1000 + 3 × 4 = 1012
```

一步算出来，不用问任何人。

**顺序表的一切优点和缺点，都来自"连续"这两个字。**

拿 100 万条记录比一下。

```text
顺序表：取第 50 万条 → 算一次地址，1 步
链表：  取第 50 万条 → 从第 1 个走 499999 步
```

差 50 万倍。

可如果要在第 50 万条后面插一条：

```text
顺序表：后面 50 万条全部后移 → 50 万步
链表：  改两根指针 → 2 步（前提是已经站在那个位置）
```

又反过来了。

**没有"最好"的结构，只有"对这个操作最便宜"的结构。**

优点：能算地址，所以随机访问快。

缺点：插入删除要保持连续，所以得搬家。

没有"连续"这个前提，这套算法全部作废。

所以顺序表不是"随便找块内存放进去"，它有一条硬约束：

```text
逻辑上相邻的两个元素，物理地址也必须相邻。
```

这条约束一旦成立，地址就能用公式算。

## 2. 线性表：先把逻辑关系定下来

如果连"一排"的规则都没定，讨论怎么存就是空谈。

在讲存储之前，先说清"一排"到底是什么意思。

**线性表（linear list）：n 个相同类型数据元素的有限序列。**

拆开看四个限定词。

```text
n 个：元素个数有限，n 叫表长。
相同类型：每个元素占一样大的空间，这样地址才好算。
有限：不能是无限序列。
序列：有先后次序，不是集合。
```

"序列"意味着每个元素有确定的位置。

除第一个外，每个元素有且只有一个前驱（predecessor，排在前面的那个）。

除最后一个外，每个元素有且只有一个后继（successor，排在后面的那个）。

n = 0 时叫空表（empty list）。

举几个线性表的例子。

```text
26 个英文字母：a, b, c, ..., z
一个班的成绩表：第 1 名、第 2 名、...
一列火车车厢：车头、1 号车厢、2 号车厢、...
```

它们都是"排成一排、有先后"。

反例也要看清。

```text
一个班的学生按"谁和谁同宿舍"组织 → 不是线性表，是图。
一个公司的组织架构 → 不是线性表，是树。
```

因为一个学生可以同时和好几个人同宿舍，前驱后继不唯一。

"相同类型"这个限定词也别漏。

如果一张表里既放整数又放字符串，每个元素占的空间不一样，地址就没法用统一公式算。

**顺序表能 O(1) 取数，前提是每个元素一样大。**

这也是为什么 C 的数组要求元素类型一致。

画出来：

```text
a1 → a2 → a3 → ... → an
```

注意这条链是"逻辑"的，不是"指针"的。

它只说明谁在谁前面，没说明在内存里怎么放。

线性表是逻辑结构。

顺序表和链表是它的两种存储结构。

**同一个线性表，可以存成数组，也可以存成链表，逻辑关系不变。**

408 喜欢在这里挖坑：

"线性表是顺序存储的"——错。

"顺序表是线性表的一种存储方式"——对。

线性表的基本操作，先列个清单，后面写代码时一个个对。

```text
InitList(&L)          初始化，构造空表
DestroyList(&L)       销毁
ListEmpty(L)          判空
ListLength(L)         求表长
GetElem(L, i, &e)     取第 i 个元素
LocateElem(L, e)      按值查找
PriorElem(L, e, &pre) 求前驱
NextElem(L, e, &next) 求后继
ListInsert(&L, i, e)  插入
ListDelete(&L, i, &e) 删除
```

顺序表和链表都要实现这十个操作。

区别只在"怎么实现"，不在"能做什么"。

这正是抽象数据类型（ADT）的意义，[01 篇](/posts/ds-intro-complexity/)给过定义。

## 3. 顺序表：把"一排"放进连续内存

如果不把元素按顺序放进连续内存，"算地址"这件事就无从谈起。

**顺序表（sequential list）：用一组地址连续的存储单元，依次存放线性表的各个元素。**

关键词是"依次"。

第 1 个元素放在起始位置。

第 2 个紧挨着它。

第 3 个再紧挨着第 2 个。

中间不许留空，不许插队。

```text
          base                       base + (n-1)*L
           ↓                          ↓
        ┌────┬────┬────┬─────┬────┐
data：  │ a1 │ a2 │ a3 │ ... │ an │
        └────┴────┴────┴─────┴────┘
下标：    0    1    2   ...   n-1
```

假设每个元素占 L 个字节。

整张表占 `n × L` 个字节，是一整块。

这块内存的起始地址，叫基地址（base address）。

**只要知道基地址、每个元素多大、下标是几，就能算出任意元素的地址。**

这句话是顺序表的全部秘密。

它带来一个能力：随机访问。

**随机访问（random access）：访问任意一个元素所花的时间都相同，与它的位置无关。**

注意"随机"不是"随便"。

它说的是"访问第 1 个和访问第 100 万个，代价一样"。

不是"每次访问的位置是随机的"。

这个术语在 408 选择题里经常被拿来玩文字游戏。

顺序表有三个直接后果，记住这三条，比背定义有用。

```text
1. 随机访问：按下标取元素 O(1)，因为地址能算。
2. 存储密度高：只存数据，不存指针，空间利用率接近 1。
3. 逻辑相邻 = 物理相邻：所以插入删除必须搬家，否则连续性被破坏。
```

第三条既是优点也是缺点。

优点：一次读一整块，缓存命中率高，实际跑起来比链表快。

缺点：中间插一个，后面全得挪。

**同一个"连续"，同时造出了 O(1) 的读和 O(n) 的写。**

"存储密度高"这句话，可以算出来。

存储密度 = 数据本身占的字节 ÷ 结点总共占的字节。

顺序表只有数据，没有额外指针：

```text
存储密度 = n × L ÷ (n × L) = 1
```

链表每个结点要多存一个 next 指针。

64 位系统上，一个 int 数据 4 字节，一个指针 8 字节：

```text
不算对齐填充：4 ÷ (4 + 8) ≈ 33%
算上对齐填充：4 ÷ 16 = 25%
```

三分之二到四分之三的空间，用来存"下一个在哪"。

数据越小，指针开销占比越高。

**这也是为什么存大量小整数时，顺序表通常更省内存。**

## 4. 地址计算：一步到位的真相

如果地址算不出来，"随机访问"就只是一句口号。

公式先给出来。

设第一个元素 `a[0]` 的地址是 `LOC(a[0])`，每个元素占 L 个字节。

```text
LOC(a[i]) = LOC(a[0]) + i × L
```

如果按教材的 1 起编号写：

```text
LOC(a_i) = LOC(a_1) + (i − 1) × L
```

两个公式算出来是同一个地址，只是下标起点不同。

代一组数。

```text
基地址 LOC(a[0]) = 1000
每个 int 占 L = 4 字节
求 a[3] 的地址
```

```text
LOC(a[3]) = 1000 + 3 × 4 = 1012
```

再验证一下物理意义。

```text
a[0] 占 1000–1003
a[1] 占 1004–1007
a[2] 占 1008–1011
a[3] 占 1012–1015
```

对得上。

再换一组参数，确认公式里每个量的单位。

```text
基地址 2000，元素是 double，每个占 L = 8 字节
求 a[4] 的地址
```

```text
LOC(a[4]) = 2000 + 4 × 8 = 2032
```

如果元素是字符，L = 1：

```text
基地址 2000，求 a[4]
LOC(a[4]) = 2000 + 4 × 1 = 2004
```

**公式里唯一会变的是 L。**

基地址由系统给，下标由你给，L 由类型决定。

三者一凑，地址就出来了。

这也解释了一个常被问的问题：

"数组名是什么？"

在 C 里，数组名在大多数表达式里会退化成"首元素地址"。

所以 `a` 的值就是 `LOC(a[0])`。

`a[i]` 就是"从 a 开始，跳过 i 个元素，取那一格"。

CPU 执行这条计算，只要一次乘法和一次加法。

乘法的两个数都是常数或已知量，和 n 无关。

所以取任意元素都是常数时间，O(1)。

**为什么不是 O(n)？因为它没有"找"。**

它直接算。

对比链表：想找第 3 个，必须从第 1 个开始，读一个指针走一步，走 3 步。

表越长，走的路一样长（对固定下标），但"走"这个动作本身是 O(i)。

所以数组按下标取是 O(1)，链表是 O(n)。

这个差别，是后面所有选型讨论的起点。

## 5. 为什么从 0 开始：三个理由

现在回答标题里的问题。

先排除一个常见误解：

"从 0 开始是为了省一次减法。"

这个说法不完全错，但不是根本原因。

现代编译器会把 `(i-1)*4` 优化成 `i*4-4`，一次减法几乎不要钱。

真正的原因有三层。

**理由一：下标就是偏移量。**

从 0 开始，`a[i]` 的地址是 `base + i × L`。

i 这个数，直接就是"跳过几个元素"。

```text
a[0] → 跳过 0 个
a[1] → 跳过 1 个
a[5] → 跳过 5 个
```

从 1 开始，公式变成 `base + (i−1) × L`。

每次访问都多一层"减 1"的翻译：你说"第 5 个"，机器得先想"那是偏移 4"。

多一层翻译，就多一个出错的机会。

看一段能直接跑的代码。

```c
#include <stdio.h>

int main(void) {
    int a[5] = {10, 20, 30, 40, 50};
    printf("%d\n", a[2]);        /* 30 */
    printf("%d\n", *(a + 2));    /* 30，完全等价 */
    return 0;
}
```

`a + 2` 不是"a 的值加 2 个字节"，是"往后跳 2 个 int"。

编译器会自动乘上 `sizeof(int)`。

所以 `*(a + 2)` 和 `a[2]` 指向同一格。

**下标 i 和指针偏移 i 是同一个数，这个等号只在 0 起编号时成立。**

**理由二：指针运算和下标运算能画等号。**

C 语言里这两句完全等价：

```c
a[i]      /* 下标 */
*(a + i)  /* 指针加偏移 */
```

这个等号成立的前提，就是 i 从 0 开始。

`a + 0` 指向第一个元素，`a + 1` 指向第二个。

如果下标从 1 开始，`a[1]` 对应 `*(a + 0)`，那 `a[i]` 就得写成 `*(a + i - 1)`。

指针算术立刻变丑，而且 `a + i` 不再等于第 i 个元素。

**理由三：半开区间让边界计算变简单。**

长度为 n 的数组，合法下标是 0 到 n−1。

写成区间是 `[0, n)`。

半开区间有个好性质：

```text
区间长度 = 右端 − 左端
```

`[0, n)` 的长度就是 n − 0 = n。

如果写成闭区间 `[1, n]`，长度是 n − 1 + 1，每次都要记得那个 +1。

循环条件也从 `i < n` 变成 `i <= n`。

`<` 和 `<=` 差一个等号，是无数越界 bug 的来源。

所以从 0 开始，本质是让"下标 = 偏移 = 区间左端"这三件事对齐。

对齐之后，地址公式、指针运算、循环边界三套规则长一个样。

**反直觉的点在这里：从 0 开始不是为了少算一次减法，而是为了让三套计数系统共用同一个数。**

那从 1 开始行不行？

行。

Fortran 的数组就从 1 开始，MATLAB 也是。

它们活得好好的，只是每次算地址要多减 1，循环边界要多想一下。

具体多出什么麻烦？

看这段 1 起编号风格的伪代码。

```text
for (i = 1; i <= n; i++)
    处理 a[i]
```

看起来自然："处理第 1 个到第 n 个"。

但底层地址是 `base + (i-1)*L`。

每次循环多一次减法。

更麻烦的是嵌套或区间操作。

```text
从第 i 个到第 j 个，共 j − i + 1 个
```

每次都要记得 +1。

换成 0 起、半开区间：

```text
从下标 i 到下标 j（不含 j），共 j − i 个
```

少一个 +1，就少一类错误。

**off-by-one（差一错误）是编程里最高频的 bug，从 0 开始是在源头减少它。**

408 考 C 风格，统一按 0 开始。

答题时如果题目明确写"第 i 个元素"，位置 i 通常从 1 数；写 `a[i]` 时，下标从 0 数。

**这两套编号同时存在，是初学者最容易翻车的地方。**

后面写代码，我会把"位置"和"下标"分开叫：

```text
位置 i：从 1 数，第 i 个元素
下标 j：从 0 数，j = i − 1
```

## 6. 插入：平均要搬多少个元素

不先算清一次插入要挪多少元素，你就不知道它为什么慢。

顺序表最贵的操作来了。

假设表里有 n 个元素，现在要在第 i 个位置插入一个新元素 e。

"第 i 个位置"指插入后 e 成为第 i 个。

原来第 i 个及之后的元素，都要往后挪一格。

```text
插入前：a1 a2 ... a(i-1) | a(i) ... an
插入后：a1 a2 ... a(i-1) | e | a(i) ... an
                          ↑
                     原来 i 及之后全后移
```

要挪多少个？

从 a_i 到 a_n，一共 n − i + 1 个。

代 n = 8，i = 3：

```text
挪 a3, a4, a5, a6, a7, a8
共 8 − 3 + 1 = 6 个
```

注意边界。

i = 1：插在最前面，n 个全挪。

i = n + 1：插在最后，一个都不用挪。

所以 i 的合法范围是 1 到 n+1。

现在算平均。

假设每个可插位置等概率，n+1 个位置各占 1/(n+1)。

平均移动次数：

```text
E = (1/(n+1)) × Σ(i=1 到 n+1) (n − i + 1)
```

把求和展开：

```text
i=1   → n
i=2   → n−1
...
i=n   → 1
i=n+1 → 0
```

求和：

```text
n + (n−1) + ... + 1 + 0 = n(n+1)/2
```

除以 n+1：

```text
E = n(n+1)/2 ÷ (n+1) = n/2
```

**结论：等概率插入，平均移动 n/2 个元素。**

代 n = 8：平均 4 个。

把每个位置的移动次数列全，检查一遍：

```text
i = 1 → 8 个
i = 2 → 7 个
i = 3 → 6 个
i = 4 → 5 个
i = 5 → 4 个
i = 6 → 3 个
i = 7 → 2 个
i = 8 → 1 个
i = 9 → 0 个（插在表尾）
```

加起来 36，除以 9 个位置，正好 4。

代 n = 100：平均 50 个。

代 n = 100 万：平均 50 万个。

再代一组不对称的数，练一下"公式里每个字母代什么"。

```text
n = 1000，i = 500
移动个数 = n − i + 1 = 1000 − 500 + 1 = 501
```

为什么是 501 而不是 500？

因为插入后 e 占第 500 个，原来的第 500 个变成第 501 个。

从原第 500 个到原第 1000 个，一共 501 个，全要后移。

**"插入位置 i"是插入后的位置，不是插入前的位置，这个 +1 就来自这里。**

这也解释了开头通讯录为什么卡。

时间复杂度 O(n)，因为最坏要挪 n 个。

注意"平均 n/2"和"最坏 n"是两回事。

408 问"平均移动次数"，答 n/2；问"最坏时间复杂度"，答 O(n)。

## 7. 删除：平均要搬多少个元素

如果以为删除比插入便宜，算一遍会发现两者只差半个元素。

删除是反方向。

删除第 i 个元素，原来第 i+1 到第 n 个，都要往前挪一格，把空位填上。

```text
删除前：a1 ... a(i-1) | a(i) | a(i+1) ... an
删除后：a1 ... a(i-1) | a(i+1) ... an
                       ↑
                  后面全部前移
```

要挪多少个？

从 a_(i+1) 到 a_n，一共 n − i 个。

代 n = 8，i = 3：

```text
挪 a4, a5, a6, a7, a8
共 8 − 3 = 5 个
```

边界：

i = 1：删第一个，后面 n−1 个全前移。

i = n：删最后一个，一个都不用挪。

所以 i 的合法范围是 1 到 n。

平均：

```text
E = (1/n) × Σ(i=1 到 n) (n − i)
```

展开：

```text
i=1   → n−1
i=2   → n−2
...
i=n−1 → 1
i=n   → 0
```

求和：

```text
(n−1) + (n−2) + ... + 1 + 0 = n(n−1)/2
```

除以 n：

```text
E = n(n−1)/2 ÷ n = (n−1)/2
```

**结论：等概率删除，平均移动 (n−1)/2 个元素。**

代 n = 8：平均 3.5 个。

列全检查：

```text
i = 1 → 7 个
i = 2 → 6 个
i = 3 → 5 个
i = 4 → 4 个
i = 5 → 3 个
i = 6 → 2 个
i = 7 → 1 个
i = 8 → 0 个（删表尾）
```

加起来 28，除以 8 个位置，正好 3.5。

代 n = 100：平均 49.5 个。

代 n = 100 万：平均约 50 万个。

为什么插入是 n/2，删除是 (n−1)/2？

因为插入有 n+1 个位置，删除只有 n 个位置。

插入多了一个"插在最后、不用挪"的位置，把平均值拉高了一点。

**这两个数 408 反复考，必须能自己推，不能只背。**

推导的关键只有三步：

```text
第一步：写出移动个数与 i 的关系。
第二步：对 i 从 1 到 n（或 n+1）求和。
第三步：除以位置个数。
```

## 8. 按值查找：不知道下标时，只能一个个比

如果不知道按值查找平均要比几次，就没法判断这个操作值不值得用。

按下标取是 O(1)。

可如果只知道"值"，不知道它在第几个呢？

只能从头比。

```c
int LocateElem(SqList L, ElemType e) {
    for (int i = 0; i < L.length; i++)
        if (L.data[i] == e)
            return i + 1;      /* 返回位置，从 1 数 */
    return 0;                  /* 0 表示没找到 */
}
```

这就是顺序查找（sequential search）。

比较次数取决于 e 在哪。

最好：第 1 个就是，比较 1 次。

最坏：在最后一个，或根本不在，比较 n 次。

平均：假设 e 一定在表里，且出现在每个位置等概率。

```text
ASL = (1/n)(1 + 2 + ... + n) = (n+1)/2
```

n = 10 时，平均比较 5.5 次。

n = 100 时，平均 50.5 次。

失败的情况呢？

如果 e 不在表里，循环要走满 n 次，最后返回 0。

所以：

```text
查找成功：平均 (n+1)/2 次
查找失败：平均 n 次
```

这也是为什么 408 的 ASL 题，一定要问清"成功"还是"失败"。

两个答案差一半。

**如果表是有序的，还有更快的办法。**

不用一个个比，每次比中间那个，一次砍掉一半。

这叫折半查找（binary search），复杂度 O(log n)。

n = 100 万时，顺序查找平均 50 万次，折半查找只要 20 次。

代价是"表必须有序"，而且中间插入删除仍要搬家。

折半查找的完整过程，后面查找基础一篇会拆开算。

顺序表这一篇只要记住：

```text
无序 → 只能顺序找，O(n)
有序 → 可以折半找，O(log n)
```

**"有序"这个额外条件，能把 O(n) 变成 O(log n)，这是后面很多优化的通用套路。**

再手算一遍 ASL，把求和写全。

n = 8，等概率查找成功：

```text
第 1 个找到：比较 1 次
第 2 个找到：比较 2 次
...
第 8 个找到：比较 8 次

总次数 = 1+2+3+4+5+6+7+8 = 36
ASL = 36 ÷ 8 = 4.5
```

公式 (n+1)/2 = 9/2 = 4.5，对得上。

注意这个 4.5 和插入的 4、删除的 3.5 不是一回事。

```text
插入：挪元素，平均 n/2 = 4
删除：挪元素，平均 (n−1)/2 = 3.5
查找：比大小，平均 (n+1)/2 = 4.5
```

**三个平均数长得像，来源完全不同，答题时别互相套。**

注意这个平均和插入删除的平均移动不一样。

插入是"挪元素"，查找是"比大小"。

两者都是 O(n)，但常数和公式不同。

**所以顺序表的能力画像是：按下标读极快，按值找很慢，中间插入删除很贵。**

一句话选型：

```text
读多、写少、主要按下标访问 → 顺序表
频繁在中间插入删除 → 链表
```

## 9. 用 C 写一个顺序表

没有能跑的代码，前面的公式都只是纸面推导。

先给结构体。

```c
#define MAXSIZE 100

typedef int ElemType;          /* 元素类型，先固定为 int */

typedef struct {
    ElemType data[MAXSIZE];    /* 连续存储区 */
    int      length;           /* 当前元素个数，不是容量 */
} SqList;
```

两个成员，一个数组，一个长度。

严格说，顺序表不等于数组。

数组是语言提供的一块连续空间，它只知道"有多大"，不知道"用了多少"。

顺序表在数组外面包了一层，多记一个 `length`，再把插入、删除、查找包成函数。

```text
数组：一块地
顺序表：一块地 + 一块写着"已用几格"的牌子 + 一套操作规矩
```

没有 `length`，你就分不清"第 100 格是有效数据"还是"从没写过的垃圾"。

**这也是为什么顺序表的插入删除必须维护 `length`，它才是"表"和"裸数组"的分界。**

注意 `length` 是"现在有几个"，不是"最多能放几个"。

最多能放几个由 `MAXSIZE` 决定，叫容量（capacity）。

这两个数在动态数组里会分开，固定数组里容易混。

初始化：

```c
void InitList(SqList *L) {
    L->length = 0;             /* 空表 */
}
```

插入：

```c
/* 在第 i 个位置插入 e，i 从 1 开始，范围 1..length+1 */
int ListInsert(SqList *L, int i, ElemType e) {
    if (i < 1 || i > L->length + 1)   /* 位置非法 */
        return 0;
    if (L->length >= MAXSIZE)         /* 表满 */
        return 0;

    for (int j = L->length; j >= i; j--)  /* 从后往前挪 */
        L->data[j] = L->data[j - 1];

    L->data[i - 1] = e;               /* 位置 i → 下标 i-1 */
    L->length++;
    return 1;
}
```

删除：

```c
/* 删除第 i 个元素，用 e 带回，i 范围 1..length */
int ListDelete(SqList *L, int i, ElemType *e) {
    if (i < 1 || i > L->length)
        return 0;

    *e = L->data[i - 1];

    for (int j = i; j < L->length; j++)   /* 从前往后挪 */
        L->data[j - 1] = L->data[j];

    L->length--;
    return 1;
}
```

取值和求长度：

```c
/* 取第 i 个元素，成功返回 1，失败返回 0 */
int GetElem(SqList L, int i, ElemType *e) {
    if (i < 1 || i > L.length)
        return 0;
    *e = L.data[i - 1];
    return 1;
}

int ListLength(SqList L) {
    return L.length;
}
```

`GetElem` 是 O(1) 的，因为直接算下标。

注意它按值传递 `SqList L`，不修改表，所以不用指针。

但这样会复制整个结构体。

100 个 int 加一个 length，约 404 字节。

调用频繁时，传指针更划算：

```c
int GetElem(const SqList *L, int i, ElemType *e);
```

`const` 表示"我只读，不改"。

这是 C 里表达"只读参数"的标准写法。

走一遍插入。

```text
初始：data = [10, 20, 30, 40, 50], length = 5
插入：位置 i = 2，值 e = 15
```

```text
j 从 5 到 2：
  j=5: data[5] = data[4] = 50
  j=4: data[4] = data[3] = 40
  j=3: data[3] = data[2] = 30
  j=2: data[2] = data[1] = 20
data[1] = 15
length = 6
结果：[10, 15, 20, 30, 40, 50]
```

挪了 4 个，正好是 n − i + 1 = 5 − 2 + 1 = 4。

再走一遍删除。

```text
初始：data = [10, 15, 20, 30, 40, 50], length = 6
删除：位置 i = 2
```

```text
*e = data[1] = 15
j 从 2 到 5：
  j=2: data[1] = data[2] = 20
  j=3: data[2] = data[3] = 30
  j=4: data[3] = data[4] = 40
  j=5: data[4] = data[5] = 50
length = 5
结果：[10, 20, 30, 40, 50]
```

挪了 4 个，正好是 n − i = 6 − 2 = 4。

把两次操作串起来跑一遍：

```c
int main(void) {
    SqList L;
    InitList(&L);

    for (int i = 1; i <= 5; i++)
        ListInsert(&L, i, i * 10);      /* 依次插 10,20,30,40,50 */

    ListInsert(&L, 2, 15);              /* 第 2 位插 15 */
    /* data: 10 15 20 30 40 50, length: 6 */

    ElemType e;
    ListDelete(&L, 2, &e);              /* 删第 2 位，e 带回 15 */
    /* data: 10 20 30 40 50, length: 5 */

    return 0;
}
```

这段代码里有两个容易忽略的点。

第一，`ListInsert(&L, i, i * 10)` 每次插在末尾，移动 0 次，是最快的情况。

第二，`ListDelete(&L, 2, &e)` 的第三个参数是 `&e`，因为函数要通过指针把删掉的值写回来。

**C 没有多返回值，要"带回"一个值，只能传指针。**

**注意 `j` 的边界和方向，这两处是手写代码最容易错的地方。**

## 10. 动态数组：固定容量装不下怎么办

`MAXSIZE = 100`，第 101 个元素就进不来。

真实程序里，容量通常不是写死的。

三个办法。

```text
办法一：开一个足够大的数组。浪费空间，且总有可能不够。
办法二：满了就重新开一块更大的，把老数据搬过去。
办法三：用链式存储，彻底不要"连续"这个前提。
```

办法二是动态数组（dynamic array），C++ 的 `vector`、Java 的 `ArrayList` 都是这么做的。

关键问题是：每次扩多大？

如果每次只扩 1 个，插入 n 个元素要搬：

```text
0 + 1 + 2 + ... + (n−1) = n(n−1)/2 次
```

均摊到每次插入，是 O(n)。

太贵。

如果每次容量翻倍：

```text
1, 2, 4, 8, ..., 2^k
```

总搬运次数：

```text
1 + 2 + 4 + ... + 2^k < 2^(k+1) ≤ 2n
```

均摊到 n 次插入，每次不到 2 次搬运。

**均摊（amortized）：把偶尔一次很贵的操作，摊到前面很多次便宜的操作上，算平均。**

翻倍的均摊代价是 O(1)。

单次最坏还是 O(n)，但连续 n 次的总代价是 O(n)。

C 里用 `malloc` 和 `realloc` 实现：

```c
typedef struct {
    ElemType *data;      /* 指向堆上的连续空间 */
    int       length;    /* 当前元素个数 */
    int       capacity;  /* 当前容量 */
} DynList;

int DynInsert(DynList *L, int i, ElemType e) {
    if (i < 1 || i > L->length + 1) return 0;

    if (L->length == L->capacity) {          /* 满了 */
        int newCap = L->capacity ? L->capacity * 2 : 1;
        ElemType *p = (ElemType *)realloc(
            L->data, (size_t)newCap * sizeof(ElemType));
        if (p == NULL) return 0;             /* 扩容失败 */
        L->data = p;
        L->capacity = newCap;
    }

    for (int j = L->length; j >= i; j--)
        L->data[j] = L->data[j - 1];

    L->data[i - 1] = e;
    L->length++;
    return 1;
}
```

`realloc` 可能原地扩，也可能另找一块再搬。

不管哪种，对使用者都是透明的。

`data` 指向的这块内存叫堆（heap）：程序运行时可以按需申请、手动释放的区域，和函数调用栈分开。

但有两件事必须自己处理。

第一，`realloc` 可能失败，返回 `NULL`。

失败时，原来的块还在，没有被释放。

所以不能直接写 `L->data = realloc(...)`。

一旦返回 `NULL`，`L->data` 被覆盖成空指针，原来的数据就再也找不到，这叫内存泄漏（memory leak）。

正确写法是先存到临时指针，检查后再赋值。

```c
ElemType *p = realloc(L->data, newCap * sizeof(ElemType));
if (p == NULL) return 0;   /* 原块还在，L->data 不动 */
L->data = p;
```

第二，动态分配的内存不会自动回收。

表不用了，要手动释放：

```c
void DestroyList(DynList *L) {
    free(L->data);
    L->data = NULL;
    L->length = 0;
    L->capacity = 0;
}
```

**申请和释放要配对，这是 C 程序员的肌肉记忆。**

408 一般不考内存泄漏，但写代码题时漏掉 `free` 不扣分，漏掉边界检查会扣。

408 一般考固定数组，但"扩容为什么是均摊 O(1)"偶尔出现在选择题里。

扩多少倍，工程上有讲究。

```text
每次扩 1 倍（翻倍）：均摊 O(1)，但最坏会浪费近一半空间。
每次扩 1.5 倍：均摊仍是 O(1)，空间浪费少一些，但重分配更频繁。
```

假设容量从 8 扩到 16。

翻倍后只用 9 个，浪费 7 格。

1.5 倍扩到 12，浪费 3 格。

可 1.5 倍扩到 12 之后，再用 4 个又满了，得再扩。

**这是"空间利用率"和"重分配次数"的权衡，没有唯一答案。**

C++ 的 `vector` 在 MSVC 里大约 1.5 倍，在 GCC 里 2 倍。

不管哪种，均摊复杂度都是 O(1)。

因为几何级数求和：

```text
1 + 1.5 + 2.25 + ... + 1.5^k < 3 × 1.5^k
```

总搬运量和最后一次扩容的规模同阶，比值是常数。

**只要扩容按"固定倍数"增长，均摊就是 O(1)；按"固定增量"增长，均摊就是 O(n)。**

这句话是扩容策略的核心，408 选择题可以直接用。

## 11. 顺序表的边界与常见错误

不把这些边界写清，代码跑通一次不代表对。

这一节收一遍手写代码时的高频错。

**错误一：位置和下标的范围搞混。**

```text
插入：位置 1..n+1，对应下标 0..n
删除：位置 1..n，  对应下标 0..n-1
```

插入可以插在"最后一个的后面"，所以位置能到 n+1。

删除只能删"存在的元素"，所以位置最多到 n。

**错误二：插入从前往后挪。**

```c
for (int j = i; j <= L->length; j++)
    L->data[j] = L->data[j - 1];   /* 错 */
```

这样 `data[i]` 先被覆盖，下一步再读它时，读到的已经是新值。

必须从后往前。

**错误三：删除从后往前挪。**

```c
for (int j = L->length - 1; j >= i; j--)
    L->data[j - 1] = L->data[j];   /* 错 */
```

这样后面的元素先往前盖，再处理前面的元素时，会把刚盖好的又盖一遍。

必须从前往后。

**错误四：以为 `length` 是容量。**

`length` 是元素个数。

容量是 `MAXSIZE` 或 `capacity`。

判断表满用 `length >= 容量`，不是 `length >= length`。

**错误五：函数传值。**

```c
void Insert(SqList L, int i, ElemType e);   /* 错，改的是副本 */
void Insert(SqList *L, int i, ElemType e);  /* 对，传地址 */
```

C 里结构体默认按值传递，函数里改 `L.length` 不影响外面。

**错误六：以为越界一定会报错。**

C 不做下标检查。

`a[10]` 写进去，可能改掉相邻变量，程序继续跑，结果全错。

这类 bug 最难查，因为错误现场和出错地点可能隔很远。

**错误七：扩容后还拿着旧指针。**

```c
ElemType *p = L->data;          /* 记住旧地址 */
ElemType *q = realloc(L->data, newCap * sizeof(ElemType));
/* 如果 realloc 另找了地方，p 就指向已释放的内存 */
p[0] = 1;                       /* 悬空指针，未定义行为 */
```

`realloc` 可能原地扩，也可能搬家。

搬了家，旧地址就作废。

这种指针叫悬空指针（dangling pointer）。

正确做法是只用 `realloc` 的返回值：

```c
ElemType *q = realloc(L->data, newCap * sizeof(ElemType));
if (q == NULL) { /* 处理失败 */ }
L->data = q;
```

**顺序表的所有优点，都建立在"不越界"这个前提上。**

越界一次，连续存储就从优点变成灾难。

## 12. 408 怎么考这一章

顺序表是 408 线性表部分的主力，五种题型。

**题型一：算平均移动次数。**

例题（自拟）：

```text
一个顺序表有 20 个元素，等概率地在任意位置插入一个元素，
平均需要移动多少个元素？删除一个元素呢？
```

套公式：

```text
插入：n/2 = 20/2 = 10
删除：(n−1)/2 = 19/2 = 9.5
```

答案：插入平均 10 个，删除平均 9.5 个。

如果题目问"最坏情况"：

```text
插入最坏：插在第 1 个位置，移动 n = 20 个
删除最坏：删第 1 个，移动 n−1 = 19 个
```

**题型二：原地删除所有值为 x 的元素。**

要求时间 O(n)，空间 O(1)。

例题（自拟）：

```text
顺序表 [3, 1, 3, 5, 3]，删除所有 3，结果 [1, 5]。
```

不能每删一个就整体前移，那样是 O(n²)。

用双指针。

```c
/* 返回删除后剩下的元素个数 */
int DelAllX(SqList *L, ElemType x) {
    int k = 0;                       /* 写指针：下一个保留元素放哪 */
    for (int i = 0; i < L->length; i++) {
        if (L->data[i] != x) {
            L->data[k] = L->data[i]; /* 保留，写到 k 位置 */
            k++;
        }
    }
    L->length = k;
    return k;
}
```

走一遍：

```text
i=0: data[0]=3 == x，跳过
i=1: data[1]=1 != x，data[0]=1，k=1
i=2: data[2]=3 == x，跳过
i=3: data[3]=5 != x，data[1]=5，k=2
i=4: data[4]=3 == x，跳过
length = 2
结果：[1, 5]
```

每个元素只读一次、最多写一次，O(n)。

只用了 i、k 两个变量，O(1)。

**这就是"双指针"的雏形：一个读，一个写，读的快，写的慢，天然把要删的跳过。**

**题型三：合并两个有序顺序表。**

```c
/* A、B 递增有序，合并到 C，C 的容量要够 */
void Merge(SqList A, SqList B, SqList *C) {
    int i = 0, j = 0, k = 0;

    while (i < A.length && j < B.length) {
        if (A.data[i] <= B.data[j])
            C->data[k++] = A.data[i++];   /* 取小的 */
        else
            C->data[k++] = B.data[j++];
    }
    while (i < A.length) C->data[k++] = A.data[i++];  /* A 剩余 */
    while (j < B.length) C->data[k++] = B.data[j++];  /* B 剩余 */

    C->length = k;
}
```

比较次数最多 m + n − 1 次。

时间 O(m+n)，空间 O(m+n)（因为要开新表）。

如果题目要求"就地合并"，顺序表做不到 O(1) 空间，得用链表。

**题型四：找两个等长有序序列的中位数。**

思路：各取一个指针，谁小谁后移，数到第 n 个就是中位数。

408 考过类似的题，本质是"归并到一半就停"。

先约定"中位数"取哪个。

两个长度都为 n 的升序表，合并后有 2n 个元素。

这里取第 n 小的那个，叫下中位数。

```c
/* A、B 长度都为 n，返回合并后的第 n 小元素 */
ElemType Median(SqList A, SqList B) {
    int i = 0, j = 0, k = 0;
    ElemType ans = 0;

    while (k < A.length) {              /* 只数到第 n 个 */
        if (i < A.length &&
            (j >= B.length || A.data[i] <= B.data[j]))
            ans = A.data[i++];
        else
            ans = B.data[j++];
        k++;
    }
    return ans;
}
```

走一遍：

```text
A = [1, 3, 5, 7]，B = [2, 4, 6, 8]，n = 4
第 1 小：A[0]=1
第 2 小：B[0]=2
第 3 小：A[1]=3
第 4 小：B[1]=4
k = 4 = n，停，返回 4
```

如果按"偶数个取中间两个的平均"，答案就是 (4+5)/2 = 4.5。

题目说清哪种，就按哪种答。

**这个解法不合并、不建新表，只数到第 n 个就停，所以空间 O(1)。**

**题型五：就地逆置。**

```c
void Reverse(SqList *L) {
    for (int i = 0; i < L->length / 2; i++) {
        ElemType t = L->data[i];
        L->data[i] = L->data[L->length - 1 - i];
        L->data[L->length - 1 - i] = t;
    }
}
```

走一遍 n = 5：

```text
[1, 2, 3, 4, 5]
i=0: 交换 data[0] 和 data[4] → [5, 2, 3, 4, 1]
i=1: 交换 data[1] 和 data[3] → [5, 4, 3, 2, 1]
i=2: 2 < 5/2=2 不成立，停
```

交换了 2 次，正好是 ⌊n/2⌋。

n = 6 时交换 3 次，最中间两个自己也交换一次，结果不变。

时间 O(n)，空间 O(1)。

**为什么循环条件是 `i < length/2` 而不是 `i <= length/2`？**

因为交换两次等于没换。

`<` 保证每对只换一次。

五个题型，前两个是必须拿下的。

## 13. 容易混淆的点

```text
1. 线性表 vs 顺序表
   线性表是逻辑结构，顺序表是存储结构。
   线性表还可以用链表存。

2. 位置 vs 下标
   位置从 1 数，下标从 0 数。
   位置 i 对应下标 i−1。

3. 长度 vs 容量
   length 是现在有几个，capacity 是最多能放几个。
   表满的判断用的是容量。

4. 随机访问 vs 随机查找
   随机访问指"任意下标访问都是 O(1)"。
   按值查找仍是 O(n)，两者不是一回事。

5. 平均移动 n/2 vs 最坏移动 n
   插入平均 n/2，最坏 n。
   删除平均 (n−1)/2，最坏 n−1。

6. 插入从后往前 vs 删除从前往后
   方向由"会不会覆盖还没搬的数据"决定，不是习惯。

7. 顺序表插入 O(n) vs 链表插入 O(1)
   链表插入 O(1) 的前提是"已经站在那个位置"。
   找位置本身仍是 O(n)，[03 篇](/posts/ds-linked-list/)会算清这笔账。
```

还有一条常被忽略的：

```text
8. 顺序表占的空间 = n × L，没有指针开销
   链表的每个结点要多存一个指针，空间效率更低。
   但链表不用一整块连续空间，这是它的优势。
```

还有一条工程上很重要、408 选择题偶尔会提的：

```text
9. 顺序表对缓存友好
   连续访问时，CPU 会把相邻数据一起读进缓存，一次读一整块。
   链表结点散落各处，每跳一次都可能缓存不命中。
```

所以同样是 O(n) 的遍历，顺序表往往比链表快好几倍。

缓存（cache）：CPU 内部一块比内存快很多的小容量存储，用来暂存最近用到的数据。

**复杂度相同，不代表实际速度相同，常数和内存访问模式也算账。**

## 14. 小结

把这一篇压成几句话。

```text
线性表 = 有限序列，逻辑上一对一
顺序表 = 用连续内存实现线性表
```

地址公式：

```text
LOC(a[i]) = LOC(a[0]) + i × L
```

从 0 开始的三个理由：

```text
下标就是偏移量
a[i] 等价于 *(a + i)
半开区间 [0, n) 的长度就是 n
```

三个关键数字：

```text
按下标访问：O(1)
插入平均移动：n/2
删除平均移动：(n−1)/2
```

按值查找：

```text
ASL = (n+1)/2（等概率成功）
最坏 n 次
```

一句话选型：

```text
读多写少、按下标访问多 → 顺序表
中间插入删除多 → 等 [03 篇](/posts/ds-linked-list/)的链表
```

顺序表的软肋，正是链表的强项：

```text
顺序表插入要搬半个表，因为它必须保持连续。
链表不用连续，所以插入只改两根指针。
```
